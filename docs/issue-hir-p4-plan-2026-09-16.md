### 1. 为什么不需要 C（缩小 P4 范围、只翻单文件）

C 的代价是**用户可见能力回退**（`pini run <目录>` 不再可用），且须走 spec §1.3 治理登记。启用它需要「收益 > 代价」，而实测不支持这一点：

1. **影响面小**：A 的实际影响 = **7 个测试用例**（0.55%）+ 包运行这一条用户路径。为一个 0.55% 的面去砍 P4 的范围，比例不成立。
2. **A 有明确且有限的实现路径**：缺的是「HIR 侧的包运行入口」，不是 lowering、不是节点语义 —— 单文件路径已跑通，包路径是**装配层**的缺口。
3. **B 已排除 ⇒ A 是唯一选项**：不留回落、又不缩小范围，则 A 必做。此时 C 只是「A 做不动时的退路」。
4. **C 会制造新的不一致**：单文件走 HIR、包走 AST，等于两个默认引擎 —— 比现在的「一个开关 + 一条拒绝」更难解释给用户。

⇒ **排 A，不排 C。** 仅当 A 开工后实测发现其依赖面超出「装配层」（例如需要改动 lowering 或跨模块符号解析）时，才回来启用 C，并届时重估。

## 4. 判据（每批都必须跑的三条，缺一不可）

1. **AST 下的全量回归**（现状基线，防回归）。
2. **`PINI_INTERP_ENGINE=hir` 下的全量回归** —— **必跑**。本计划之所以存在，就是因为这条此前没人跑。
3. **全量探针 + 与冻结件逐夹具对账**（Δ 全 0，且**逐夹具判定变化数**必须报出来，不能只报槽位数）。

> ⚠️ 三条都要报**分层读数**，不能合并成一个数 —— 合并后的数对「某层失效」结构性失明。

## 5. 止损点

1. 任一批的 HIR 回归失败数**超过开工前** ⇒ 停，判是批内引入还是既有面被揭开。
2. P4-1 开工后若发现它**不止是装配层**（需改 lowering / 跨模块符号）⇒ **停，回来启用 C 并重估**。
3. P4-6（R1/R2）若发现保 `await`/`wait` 的代价是重写 CPS ⇒ **停，上报裁决**，不在批内自行决定保或弃。
4. 单批回归 >5 失败且 >1 小时无收敛（沿用 `ADR-031` §4 口径）。
