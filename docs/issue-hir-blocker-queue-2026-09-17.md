### `D-G3c-1` — `detach` 要不要新节点（`G-3c` 勘测新出，2026-09-17）

**这是什么**：`detach <expr>`（求值得到一个 `Future` 值，把它从父任务**剪枝**、不参与父返回时的自动取消）
在 HIR 里**没有落点** —— `HIRStmt` **16 case 无 `detach`**，契约 §3 同样只列 16 条，
§4 预留位**只剩 `char` 一条**（`§4.2` 已随 `join` 兑现作废）
⇒ **新增即契约 61 → 62**，须走**第 2 次** `spec §1.3`（第 1 次是 `ADR-040`）。

**为什么现在要决定**：`G-3c` 的夹具面里有 **3 条**首缺口正是
`statement 'detach' is not yet lowered to HIR`；而 `D-P4-26` 给 `G-3c` 立的硬停条件是
「**迁移若须改动契约那 60 个节点 ⇒ 停下先走 `spec §1.3`**」—— 这条**恰在硬停条件上**。

**选项与代价**：
- **① 新增 `HIRStmt.detach` 节点**：代价 = 契约 **61 → 62** + 走一次 `spec §1.3`
  + 三锚点（`llvm` / `printer` / `interp-hir`）同步认领 + 下游引用「61」的文字跟改
  （`docs/spec/hir-contract.md` §0.4 至少一处，否则下一位读者会拿旧基数核验）。
- **② 降成既有形状**（求值 + 调 `Future` 的一个方法，即走 `call` 的按名形状）：
  代价 = 零治理成本，但须**登记**「`detach` 走 `call` 形状」这一实现约定。

**我的建议**：**②**。与 §2 裁 `join` 取 ① 是**同一把尺、相反结论**：
`join` 要在求值点**挂起整个求值栈**（保存续体、释放 OS 线程），不是「调用」能承载的；
而 `detach` **不挂起** —— AST 侧就是一行 `fut.detachFromParent()`
（`Sources/PiniCore/Interpreter/SuspendEvaluator.swift:627`），正落在裁 `join` 时**自己认可**的那类先例里
（`argv` / `moduleRoot` / `Array.append`：**同步、有副作用但无控制流**）。
⇒ 两个节点**性质不同**，同一把尺得出相反结论，**不是**两处判据打架。

详见 `docs/issue-hir-p4-gamma-g3-plan-2026-09-17.md` §12.3。

**这是什么**：勘测发现 **`suspendMode` 的生产面是 `false`** ——
`Sources/` **零赋值点**（`Sources/PiniCore/Interpreter/Interpreter.swift:42` 是声明且默认 `false`），
**8 处赋值全在 `Tests/`** ⇒ **现行发布语义 = 阻塞 join**（`GCDScheduler` + 真线程），
那 890 行 CPS 求值器（`Sources/PiniCore/Interpreter/SuspendEvaluator.swift`）
**只在测试翻开关时才被执行**。

据此建议把 `G-3c` 切成两批：

| 批 | 内容 | 判据 |
|---|---|---|
| **`G-3c-1`** | 异步管道 + **阻塞** join（含 `HIRFunction` 异步标记 · 执行器 spawn 面 · `join` 降载 · `Future` 值层内建与方法 · `detach`） | **59 条**首缺口归零；⚠️ 与前两批**不同形态**：这批**应当真转绿**（阻塞语义**就是**发布语义） |
| **`G-3c-2`** ⛔ **已取消（2026-09-17，`ADR-043` / 缺口 `G66`；本行为取消前的登记留痕）** | 真挂起 CPS（890 行镜像 + driver 路由改 **depth** 制 + `HIRExecutor` 四状态改 `ThreadLocal`） | `SuspendRuntimeTests` 15 条 + `CPSDifferentialTests` 14 条**改指 HIR 后逐字节一致** ⇒ **与 `G-3d` 天然合流** |

**为什么现在要决定**：不切则按 §3 原表单批做，两条代价**一次性承担** ——
① **访问面**：另立文件则 `HIRExecutor` 的 `private` 成员（`evaluate` / `execute` / `executeStatements` /
`pushDeferScope` / `currentEnv` …）须放宽为 `internal`，或把 CPS 写进同一文件使
`HIRExecutor.swift` 由 **2177** 行涨到约 **3100** 行；
② **高风险拖累可交付**：真挂起（跨线程上下文还原）一旦卡住，阻塞面（可判据、可交付）一起被搁置。

**选项与代价**：**① 切**（建议）／**② 不切**（按 §3 原表，一次性承担上述两条）。

**我的建议**：**①**。理由同 §3.1 给 `G-3a` / `G-3b` 单列的那条 —— **风险不同类**；
且 `G-3c-1` 的全部改动**都在 `HIRExecutor.swift` 文件内**（异步臂加在 `case .call`、join 加在 `case .join`），
**零访问面代价**。

详见 `docs/issue-hir-p4-gamma-g3-plan-2026-09-17.md` §12.2。

## 4. 明确**不排**（规模守护）

- **不逐条修那 64 条红**。它们按簇处置（`31 并发` 归 `G-3`；`33 其余` 归 `G-2R` 式的簇批），
  且**分类表必须重测**——规划件那张「16 结构性 + 13 口径」是按红数 72 的时点写的，现读数 64。
- **不启动 LLVM 并发运行时**（除非 `D3` 改判）。
- **不把 `G-3a` 剥离出来的下一层缺口当新缺陷立案** —— `joinAll` / `joinWithin` / `isCancel` 三个内建仍无降载规则，
  但它们是 `G-3` 的**计划内分层**（实测 `'ok'` 17 → 50 · `'err'` 0 → 8，合计 +41 ⇒ 归因闭合），归 `G-3b` / `G-3c`。
- ⚠️ **包通道自 `A1`（2026-09-17）起判红，且这是读数不是事故** —— 两处分歧**各有主人**
  （`demo3/app` 归在册的 `import` 符号单，`examples/ffi_module` 归新立的 vendored-FFI 单）。
  ⇒ **不要**把它读成「该入口坏了」，更**不要**为了让那一行变绿去修分歧（`charter.md` D2）。
- ⚠️ **探针的根集不含并发簇**（2026-09-17 实测：7 个并发目录的夹具在探针 6 根里 **0 条**）⇒
  凡以「探针零位移」为 `G-3*` 各批判据者，**必须同时给第二条判据**（本格用「首缺口归零 + 变异反证 + 全量集合相等」），
  否则该判据对该面**没有区分力**。
- **不在本件里顺手改 LLVM 行为**（`run-llvm` 退出码 · 警告转发 · `argv` 的面 · 字典 `.get` 的 IR）。
- **不把 `P4-5`**（字符串字节语义格 / 取址格）**拉回前置** —— 已裁决为翻转后语义债。
- **不把 `P0d`（Char 类型落地）与紧随其后的「字符字面量 `'c'`」拉进 `LR-4` 的任何一批** ——
  两者**已裁（`ADR-033`）但不在** `P0 → P0b → P1 → P2 → P3 → P4` 的顺序硬约束链内
  （2026-09-17 核：全 `docs/` 无延后裁决），且属**语言面**而非「HIR 统合」。
  ⚠️ **但须记账**：`docs/spec/hir-contract.md` §4 的两个预留位（`char` 节点 · `.join` 挂起语义）里，
