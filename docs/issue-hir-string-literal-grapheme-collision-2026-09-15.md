# Issue：同字形、不同码点序列的两个字符串字面量被合并（后者被换成前者的字节）

- **状态**：**Open（2026-09-15 立案；新发现，登记不修）**
- **发现来源**：P3 拆格 G3 前置的「`arrayJoin` 非 ASCII 补测」（用户裁定「先补非 ASCII 测试再移出 B 组」）
  期间**伴生发现**。⚠️ **与本节点无关**：把 `join` 完全去掉后仍复现。
- **关联**：`docs/spec/adr/adr-019-unicode-char-model.md`（D1 grapheme 模型，**权威依据**）；
  `docs/spec/adr/adr-034-hir-contract.md`（B 组字符语义族，**本项为其同根因族的新成员**）；
  `docs/issue-hir-string-slice-byte-based-2026-09-11.md`（字节当字符用，同族但对象不同）；
  `docs/spec/hir-contract.md` §2.40 / §2.9（`interpString` 属 C 组，**已裁「纯组装」**）。

## 现象（三通道实测，2026-09-15）

最小复现（**不含任何 `join`**，故与 §2.40 无涉）：

```
main|func() -> ():
    print("é")             ; 源字节 c3 a9        —— 预组合，单码点
    print("e" + U+0301)    ; 源字节 65 cc 81      —— 拆开，两码点
    return
```

| 通道 | 输出字节 | 判定 |
|---|---|---|
| `interp-ast` | `c3a9 0a` `65cc 81 0a` | ✅ 各自保留原样 |
| `interp-hir` | `c3a9 0a` `65cc 81 0a` | ✅ 各自保留原样 |
| **`llvm-hir`** | `c3a9 0a` **`c3a9 0a`** | ❌ **第二个字面量被换成第一个的字节** |

## 触发的三条判据（逐条实测，非推断）

| # | 条件 | 实测 |
|---|---|---|
| **1** | 两个字面量**规范化后同字形** | ✅ 是触发条件。反例：预组合 `á` 与拆开 `é`（字形不同）⇒ **无碰撞、三臂一致** |
| **2** | 两者的**码点序列不同** | ✅ 是触发条件（同字节的重复字面量本来无害） |
| **3** | **哪个被换掉** = 后出现者被换成**先出现者**的字节 | ✅ 双向实测：预组合在前 ⇒ 后者变预组合；拆开在前 ⇒ 后者变拆开（**方向随书写顺序反转**） |

**可复现性**：同一命令重跑，输出逐字节相同。**与 `join`、与接收者形态均无关**（去掉 `join` 亦复现）。

## 性质

- **不是翻转阻塞**：现有语料不含该形态（同字形不同码点的两个字面量），故不进阻塞清单。
- **但翻转后是用户可见缺陷**：解释器输出正确字节，LLVM 侧**静默改写了字符串内容** ——
  属「翻转把可跑程序变坏」这一类（与 `issue-hir-string-slice-byte-based-2026-09-11.md` 同类）。
- ⚠️ **静默性**：`llvm-hir` 的 rc = 0、stderr 为空 ⇒ 现有判据**看不到**它，
  除非专门构造该形态的语料（本单**暂不入语料**，理由见下）。

## 未定位（**如实声明，不冒充已根因**）

- 差异必然在 **HIR → IR 发射路径及其后**（因为 `interp-hir` 执行同一份 HIR 时输出正确）。
- 疑点在**字符串常量的归并键**：若键取「规范化后字形」而非「原始字节」，则同字形者会共用同一份存储。
  ⚠️ **本单未读码定位，以上仅为假设**，不得当作结论引用。
- 需先回答一个**语言层问题**才谈得上修：**「同字形、不同码点」的两个字面量，
  在语言里是否应被视为同一个字符串？** 若答案为「否」（按字节/码点身份），则当前行为是缺陷；
  若答案为「是」（按字素身份），则缺陷在**另一侧**（解释器未规范化）。
  ⇒ 该问题**须走 spec §1.3**（提议 → 影响评估 → 登记 → 落地 → 证据登记），**不得由实现先定**。

## 为什么不入语料（本单的处置口径）

**按 D1/D2「只登记不修」+ 规模控制**：本形态一旦入语料，探针会多出一项阻塞/差异读点，
**与该族（B 组字符语义）的既有读数混在一起**，将来分不清是谁的。
⇒ 待本条被裁并进入实施时，再入语料，并**配一次变异轮次**证明该语料真能捕获它。

## 建议处置（不含实施）

1. **先裁语言层问题**（上节末段），再定「修哪一侧」。
2. 若定为缺陷：定位 IR 侧字符串常量的归并键，改为按**原始字节**（或按裁决结果）区分。
3. 补语料 + 变异反证（同批做），对象 = `interpString` / 字符串字面量发射，**不是** `arrayJoin`。

## 交叉引用

- 本单是 P3 拆格字符串线的**伴生产物**；`arrayJoin` 移出 B 组（用户 2026-09-15 裁定）**不因本单改变**
  —— 两者对象不同：`arrayJoin` = `§2.40`，本单 = 字符串字面量发射。
