# 把内联的 Pini 源码从 Swift 测试中抽离

- 状态：**方案已定；试点 1/102 文件完成，分批实施待续推**（2026-08-31 立项，2026-09-02 复核）。
- **顺序约束（2026-09-02 补充）**：本工单的抽离**必须先于**测试目录分组。抽离批次清单以
  `.swift` 文件为键，若先分组则 102 个路径全变、清单作废重算，且新增的 819 个 `.pini` 需二次搬迁。
  相关台账见 `docs/issue-test-example-hygiene-2026-09-02.md`。
- 动因（用户判断）：Pini 源码内联在 Swift 测试字符串里**本身就是错误的写法，极其危险**——
  已多次出现「源码含 `|` 却阻塞于 EOF」这类问题，其根因之一就是内联字符串对换行、缩进、
  转义的处理不受 Pini 自身约束。抽离后，问题从「内联字符串问题」变成「`.pini` 文件问题」，
  可以用文件级的工具与门禁处理。
- 附带收益：H-4（A8 选项 B：带执行块的函数以 `:` 开块）转强制时，需要改的 862 处函数签名
  目前嵌在 Swift 源码里，与 Swift 自身的闭包语法**文本同形**（都含 `-> (`），脚本无法安全
  区分，因而无法自动迁移。抽离之后它变成**纯 `.pini` 文件迁移**，可以用 H-4 已验证的
  箭头锚点规则安全处理。

## 裁决（用户拍板，2026-08-31）

1. **路径机制**：`#filePath` 推导同目录（**不改 Package.swift**）。SPM `Resources` +
   `Bundle.module` 作为备选，仅在 `#filePath` 方案受阻时启用。
2. **fileName**：**继续传原假名**（`"test.pini"` 等）。位置敏感断言依赖诊断文本里的文件名，
   换真实路径会破坏那 3 个文件；抽离的收益来自内容外置，与 fileName 无关。
3. **4 处 Swift 插值**：**先逐个判定意图再动**。它们是路径注入（`\(path)`），需要动态值；
   建议改为「文件里写占位符 + 加载后替换」，或作为例外保留内联——实施前逐处确认。
4. **测试助手统一（补 check）**：**留作独立批次**。借机统一会暴露「harness 不跑 checker」
   一类真缺陷并转红（G-P8 教训），必须单独一批、按 D9 如实记录，不混进抽离批次。

## 命名与路径规则

- 目录：`<测试文件名去扩展名>/`，与 `.swift` 文件同级（如 `Tests/PiniTests/IOTests/`）。
- 文件：`<测试函数名>.pini`；同函数第 2 块起加序号 `<func>_2.pini`、`_3`……
- 函数外块（共享常量 / 辅助函数内的块）：`<_常量名>.pini`，下划线前缀以区别于函数块；
  同目录重名追加序号。
- 唯一性：以「文件 + 名字」为键校验，抽取脚本须断言路径两两不同（本次 819 块 → 819 路径）。
- 加载助手：新增 `loadSource(_ name: String, #filePath)`——从调用点所在目录读取；
  **fileName 仍传原假名**，源码内容改用文件内容。

## 保真校验（不可省略）

抽离的唯一风险是**静默改变测试语义**。因此：

1. 抽取时对每个块记录 `sha256[:16]`、字节数、是否以换行结尾、是否含 Swift 插值
   （`/tmp/pini_extract/manifest.json` 是本次基线）。
2. 抽离落地后重算哈希并与基线比对——**任何一处不同即视为失败并回滚**。
3. 缩进按 Swift 多行字符串规则剥离（剥离量 = 非空行最小前导空白，保留相对缩进），
   因为 Pini 缩进敏感。
4. 尾部换行逐字节保留（本次 819 块全部以换行结尾，落地后仍须全部以换行结尾）。

## 风险

- **静默语义变更**：哈希基线是唯一防线，不可跳过。
- **规模**：819 块 / 102 文件，必须分批，禁止一次全量替换。
- **与 H-4 的耦合**：抽离完成后再执行冒号强制迁移，顺序不可颠倒（先文件化，后规则化）。
