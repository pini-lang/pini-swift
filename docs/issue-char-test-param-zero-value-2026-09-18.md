# Issue：`Char` 在测试参数注入里没有零值

- 状态：**Open（登记不修）** —— 2026-09-18 由格 `P0d` 的 `C` 阶段立案；**未决策前不动源码**（当前已按 `.null` 显式登记，见下）。
- 层级：**宿主级**（实现面缺口，非语言面裁决）。
- 发现来源：`P0d` 的 `A` 阶段扩散点清点 —— 该站点被 `A` 判为「16 处扩散点里最危险的一处」。
- 关联：`docs/issue-p0d-char-landing-plan-2026-09-18.md` §11.1 · `ADR-033` · 源码 `Sources/PiniCore/Run/ProgramRunner.swift`（`zeroValue(forTestParam:)`）

## 问题

`ProgramRunner.zeroValue(forTestParam:)` 为 `|test` 函数的**参数注入**提供零值。
它按 `HIRType` 分派，既有映射是：

| 类型 | 零值 | 依据 |
|---|---|---|
| `i8`/`u8`/`i32`/`i64`/`u64` | `.int(0)` | 自然零 |
| `f64` | `.float(0)` | 自然零 |
| `boolean` | `.bool(false)` | 自然零 |
| `string` | `.string("")` | **空串是合法的 `String`** |
| `char` | **?** | ⛔ **不存在「空字符」** |

⇒ `Char` 是**唯一没有零值的标量**：它的不变式是「**恰含 1 个字素**」，
而「0 个字素」不构成合法值。函数末尾的 `default: return .null` 会把 `Char`
**静默**吸收成 `null`。

⚠️ **危害面比单个站点大**：该函数是**两台引擎共用**的零值源，
其注释明文要求「两引擎必须一致，否则测试的通过与否会变成引擎差异」。
⇒ 一个错的零值会**同时**污染两条通道，而两通道的一致性判据**看不见**它
（两侧同错 ⇒ 逐字节相同 ⇒ 判据绿）。

## 实测（2026-09-18）

- 该函数对未知类型返回 `.null` —— **实测确认**（读源码，`default: return .null`）。
- 触发面真实存在：`Char` 落地后，`|test` 函数**可以**声明 `Char` 参数，
  而参数注入是 `pini test` 的既定行为（`G41`）。
- **本格处置**：把 `.char` 写成**显式 arm**（仍返回 `.null`），
  使该选择**可见**而非被 `default` 吸收；**未**发明一个零值。理由见下「为何不顺手定」。

## 三个候选（未裁）

| 选项 | 做什么 | 代价 |
|---|---|---|
| **A · 注入 `.char("")`** | 给一个退化值 | ⛔ **制造不变式违例**：`""` 不是「恰含 1 个字素」⇒ 把一个类型系统宣称不可能的值放进引擎 |
| **B · 维持 `.null` 并明文登记**（**当前**） | 显式 arm + 本工单 | 用户代码在测试里拿到 `null` 而声明是 `Char` ⇒ **类型与值不符**，但**不制造非法值** |
| **C · 让 `|test` 禁止 `Char` 参数** | 静态拒绝该形态 | 属语言面裁决（须走 `spec §1.3`），且 `Char` 本应可自由作参数 |

## 我的建议

**B 暂留，C 待语言面裁决。** 理由：

1. **A 不可接受** —— 它让运行时**主动**产出违反不变式的值，而 `ADR-033 D1` 明确
   「不变式由类型系统承担」；运行时代替类型系统破例，会把该不变式降级为口头约定。
2. **B 的代价是「值不合法」而不是「值被伪造」**，且它**已经**是现状（非本格引入）
   ⇒ 不构成阻塞，符合「登记不修」。
3. **C 才是干净的终局**，但它需要先回答「没有零值的标量该不该可作测试参数」
   —— 那是语言面问题，须走 `spec §1.3`，**不在本工单范围内**。

## 不做范围

- **不**在本工单内改 `ProgramRunner` 的行为（除已落的显式 arm）。
- **不**改 `|test` 的参数注入契约。
- **不**动 `ADR-033`。
