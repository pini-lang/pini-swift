## 背景：解释器的两条标签规则（本格已对齐的部分）

标签（分量名）在解释器里只在两处补写，均已由引擎同址复刻并验证：

| 规则 | 解释器落点 | 引擎落点 | 状态 |
|---|---|---|---|
| ① 显式 `return` 出口 | `Interpreter.applyReturnLabels`（`executeFunctionBody` 内） | `HIRExecutor.call` 的 `returnSignal` 路径，喂入声明返回类型 | ✅ 本格 F1 修 |
| ② 带元组注解的绑定 | `Interpreter.applyTypeAnnotationLabels`（`varDecl` 内） | `HIRExecutor` 的 `allocVar` 臂 + 降载侧 `HIRLowerer.slotType` | ✅ 本格 F2 修 |

实测（七夹具、手写三臂比对器）：`rE1`/`rE2`/`rE4`/`rE5`/`rE6`/`rE7`/`rE8` 中除下列残留外
三臂一致；`rE3`（隐式尾表达式）的 ast/hir 已一致，llvm 因上一条工单而分叉。

## §1 位置式注解盖住具名值：引擎与 ast/llvm 两臂都分叉（潜伏）

```
除余|func(a: I32, b: I32,) -> (商: I32, 余: I32,):
    return (a / b, a % b)

main|func() -> ():
    let t: (I32, I32,) = 除余(17, 5)
    print(t)
    return
```

| 臂 | 输出 |
|---|---|
| ast | `[3, 2]` |
| llvm | `[3, 2]` |
| **hir** | **`[商: 3, 余: 2]`** |

**性质**：解释器的规则②是**语法**规则——只要写了元组注解就整体改写标签（`(I32, I32,)`
的标签表是 `[nil, nil]`，于是把值身上已有的名字**洗掉**）；llvm 臂标签取自**静态类型**，
注解未命名故打印无名。引擎的 `slotType` 判据是「声明是否比初始化器的类型多说了一个名字」，
本例两者相当，故判定「无需改写」。

**为什么值得单独登记**：这是本格唯一一处「解释器与 llvm 两臂一致、只有引擎分叉」的形状，
与其余案件的分叉方向相反。**实测：73 个差分夹具 + 全量探针语料中不存在该形状**（已核：
唯一的位置式元组注解是 `testBackfillTrailingCommaSevenForms.pini` 的
`let t: (I32, F64,) = (1, 2.5,)`，其初始化器本身也无标签 ⇒ 无差异）。

**精确修法（二选一，均超出「最低代码改动」）**：

- (a) 在 `allocVar` 上记录「源码写了元组注解」这一位（节点面变更 ⇒ 契约/打印/发射/契约检查
  连带）；或
- (b) 在引擎里加 `HIRExpr → HIRType` 访问器，把判据改成「声明的标签 ≠ 初始化表达式的类型标签」
  （约 40 个 case 的机械分派，且引入第二处类型真相）。

**本格未取**：两者都比现值大，而该形状在语料中不可达；等该形状真实出现（或与 §3 的标签
语义一并裁决）再定。

## §2 泛型方法特化丢具名返回标签

`TypeEnvironment.defineGenericStruct(methods:)` 的 methods 形参是元组类型
`[(name: String, params: [TypeAnnotation], returns: [TypeAnnotation])]`，**没有** `returnLabels`
字段，故具名返回标签经泛型**方法**特化后丢失（泛型**函数**特化点同缺，模板
`GenericFunctionTemplate` 无标签来源）。两处均已在源码就地注明「Recorded, not fixed」。

影响：`T.method(...)` 返回具名元组时，调用点拿不到分量名。当前语料无该形状（泛型夹具无具名返回）。

## §3 待裁（spec 级）：具名返回类型的**隐式**尾表达式是否带分量名？

同一个具名返回签名，两条返回路径的标签行为不同：

- 显式 `return (a / b, a % b)` → 解释器补写 `["商", "余"]`（规则①）；
- 隐式尾表达式 `(a / b, a % b)` → 解释器**原样返回末值**，不补写（实测 ast 打 `[3, 2]`）。

llvm 臂的渲染由**静态类型**驱动，故同一程序在 llvm 上会打出名字——两臂对「具名返回函数
的隐式出口是否携带声明名」持不同模型。本格让引擎**跟随冻结参照（ast）**，即隐式路径不补写；
`HIRLowerer.slotType` 的注释与引擎判据都以此为据。

**该问题现在不可裁**：上一条工单里隐式返回的值本身是错的（拿的是返回槽残留），
标签无从谈起。**前置 = 先修值，再裁标签**。
