# 测试基建：`SuspendRuntimeTests` 偶发 SIGSEGV（崩溃的类读成通过）

> 状态：**Open**（2026-09-16 立案；**只登记不修**）
> 发现于：`G-2` 基线与 `G-2b`/`G-2c` 读数对账时的**不一致**。
> 相邻但**不同对象**：`docs/issue-test-harness-sigpipe-on-failure-paths-2026-09-16.md`
> （那份是**终止信号**吞掉其后所有类；这份是**进程崩溃**把该类读成通过）。

## 1. 现象（实测，同一棵树 `0f12a56`，同一命令）

命令：`TMPDIR=/tmp swift test --filter PiniTests.SuspendRuntimeTests`

| 运行 | 退出码 | 实际执行的方法数 | 输出 |
|---|---:|---:|---|
| `G-2` 基线（第 1 次）| 1 | **3 / 15** | `xctest … exited with unexpected signal code 11`；死在 `testCancelSleepingChildInSuspendMode` |
| `G-2c`（第 2 次）| 0 | 15 / 15 | 全过（4.086s）|
| `G-2b`（第 3 次）| 0 | 15 / 15 | 全过 |

⇒ **同一份代码、同一条命令，一次崩溃、两次通过** ⇒ 非确定性。

⚠️ **本单的实际危害不是崩溃本身，而是读数口径**：
崩溃的类**在解析器眼里没有「失败行」** ⇒ 一个只看「退出码 / 有无解析到失败」的判据
会把它读成**通过**（本单立案时，基线里那 13 个**从未运行**的方法是**零信息**的）。

## 2. 定位（实测范围内的结论，不外推）

- 崩在 `testCancelSleepingChildInSuspendMode`（第 3 个方法），信号 11。
- 该类属「挂起/并发**内部 API**」面（`P4-β` 的四分类 B 类），直接驱动
  `Interpreter` 的挂起运行时（`SuspendEvaluator` / 调度器 / Future / 取消）。
- ⚠️ **未定位到具体代码行**：本单只登记「它是非确定性的」与「它影响读数」，
  不把「疑似栈溢出」这类猜测写成根因。定位需要单独一轮（含 `lldb` / 线程转储）。

## 3. 对 `P4-γ` 判据的影响（必须记账）

1. **本批每一个「130 类逐类单跑」的读数都受此上限约束**：
   崩溃出现在哪个类是随机的，故某一次读数可能**少算**该类的失败数。
2. `G-3`（`R1` 并发迁移）会**大幅改动**这一类代码 ⇒ 若不去根因，
   「迁移前 / 迁移后」的对比里会混入一个**非确定性**分量。
3. `G-6`（删走查）会删掉 `SuspendEvaluator` ⇒ 本类会从「B 类」变成「无处可跑」。
   ⇒ **在 `G-3` 裁决 `R1/R2` 之前，本单应先有一个可复现的最小输入**，否则无法判断
   「崩溃是挂起运行时自己的缺陷，还是测试用法的缺陷」。

## 4. 处置建议（不预设，供后续）

| 选项 | 代价 |
|---|---|
| A 先做最小复现（同一方法重复 N 次 / 关闭并发看是否复现）| 中；产出「确定性 vs 并发相关」的判断，是本单其余选项的前提 |
| B 在测试基建里**检测崩溃**（rc≠0 且无解析失败 ⇒ 记为 `DID_NOT_RUN` 并失败）| 小；能立刻止住「读成通过」，但会引入新的红（诚实红）|
| C 与 `G-3` 合并处置 | 若 `G-3` 选 `R2`（退役并发），本类随之退役，问题消失（但代价是能力回退）|

⚠️ **建议 A 先于 C**：`G-3` 的 `R1/R2` 裁决需要「并发面现在到底多健康」的**可信**读数，
而本单正是那个读数的污染源。
