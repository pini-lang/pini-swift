## 5. ⚠️ 过程失误与可疑读数（如实登记）

**① 我自己引入过一个错读数**：`three-edge-union.py` 首版把 `Executed` 汇总行**求和**，
而 XCTest 在嵌套层级各打印一条 ⇒ **89 被读成 267**。已改为只取最后一条（最外层总计），并在注释里写明原因。

**② 一次「形状合法但错的判据」被当场抓住**：第 9 条首版断言按**行**切分 LLVM 输出，
而 `testDiffLexical` 的字符串里含**真实换行** ⇒ 一个元素被劈成两行 ⇒ 报出一处**假分歧**。
改为**逐字节**比较（`ast.map { $0 + "\n" }.joined()`，因为 `outputSink` 默认即 `print(line)`）。
⚠️ 这正是台账 §5 纪律 2 的形态：**对照落在了表示差异上，不是通道差异**。

**③ 构建设置会让整张表变成「形状合法的假红」**：`swift build --product pini` **不产出
`libPiniRuntime.dylib`** ⇒ 探针 LLVM 臂全线 `Symbols not found -> HARNESS_DEPENDENT`。
修法 = 不带 `--product` 建全部产品。

**④ 环境判据（`BUILDING.md` ADR-031 约束 6）**：`lli` 不在工具 shell 默认 PATH 上，
**不得**据此判「工具不存在」；本批测量一律带 `PINI_LLVM_BIN=/opt/homebrew/opt/llvm/bin`。

**⑤ 可疑读数（不替它编解释）**：全量探针本批约 **35 秒**，而既有读数记 **6m31s / 11m49s**
（单目录 85 夹具那次 1m27s）。**判定分布与基线逐项吻合**，故倾向机器冷热差异，但**未证实** ⇒ 标注待复核。
