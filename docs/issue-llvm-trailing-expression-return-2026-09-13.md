# Issue：尾表达式返回在 LLVM 通道不成立（发射器丢弃非 void 函数的末表达式值）

- 状态：**Open（2026-09-13 立案；LR-4 P2a G2 勘测发现，未裁决处置方向）**
- 发现渠道：G2 元组族证伪期间，为「具名返回 + 尾表达式」造最小夹具时三臂读数分叉，
  顺标量变体一并测量后确认与标签无关。
- 归属：代码生成面（`IREmitter` 的函数体出口），非标签模型面、非引擎面。
- 关联：`docs/issue-tuple-label-binding-rule-2026-09-13.md`（同批发现的标签残留；
  **其 §3 以本单修复为前提**）。

## 现象（实测，2026-09-13 现跑）

三臂定义：`ast` = 解释器（冻结参照，`PINI_INTERP_ENGINE=ast`）；
`hir` = HIR 引擎（`PINI_INTERP_ENGINE=hir`）；`llvm` = `pini run-llvm`。

| 夹具 | 被测函数 | ast | hir | llvm |
|---|---|---|---|---|
| `v3-scalar` | `bump(a: I32, b: I32,) -> (I32,):` 体为 `a + b`；`print(bump(12, 2))` | `14` | `14` | **`12`** |
| `v5-value-used` | 同上；`let v = bump(12, 2)` → `print(v * 2)` | `28` | `28` | **`24`** |
| `v6-no-params` | `seven() -> (I32,):` 体为 `7`；`print(seven())` | `7` | `7` | **`1`** |
| `v1-named-tuple` | `除余(a: I32, b: I32,) -> (商: I32, 余: I32,):` 体为 `(a / b, a % b)`；直接 `print(除余(12, 2))` | `[6, 0]` | `[6, 0]` | **`[商: 12, 余: 2]`** |
| `v2-positional-tuple` | 同上，返回写作 `((I32, I32,),)` | `[6, 0]` | `[6, 0]` | **`[12, 2]`** |
| `v4-one-slot` | `-> (I32,):` 体为 `(a / b,)` | `[6]` | `[6]` | **`12`** |

读法：`12` = 参数 `a`；无参时得 `1`。即**调用方拿到的是返回槽里的残留内容，不是末表达式的值**。
三个变体都 `rc=0`、stdout 正常成形 ⇒ **静默错误结果**，非抛出。

夹具已复核在基线重复（`Sources/` 暂存回退后重建）：`v3` 得 `14 / 14 / 12`，
`v1` 的 llvm 列得 `[12, 2]`——**逐字相同** ⇒ 本缺陷先于 LR-4 P2a G2 存在。

## 根因（源码级，已定位）

`Sources/PiniCore/CodeGen/IREmitter.swift` 的函数体语句分派里，表达式语句是**丢弃**的
（全文仅此一处 `exprStmt`）：

```
case .exprStmt(let expr):
    _ = emitExpr(expr)
```

发射器没有任何「非 void 函数跑出末尾时把末表达式写进返回槽」的规则：函数体执行完直接走到
尾声，返回槽保持未被写入的状态。

对照三处**都实现了**该规则：

- 解释器 `Interpreter.executeFunctionBody` → `lastValue`（本条的语义权威来源）；
- HIR 引擎 `HIRExecutor.executeStatements` → `lastValue`，并在
  `HIRExecutorTests.testFallingOffTheEndReturnsTheLastExpressionValue` 上以 ast↔hir 臂钉住；
- 类型检查器接受该形状（`v*` 全部 `typeErrors == 0`）。

⇒ 这是**两条 HIR 后端对同一条已实现规则的分歧**，不是语言边界。

## 为何语料没抓到（覆盖缺口）

73 个差分夹具 + 全量探针语料里**没有**「非 void 函数以尾表达式返回」的形状：

- 名字最接近的 `testDiffNoTrailingReturn.pini` 内容是
  `main|func() -> (): let x: I32 = 9; print(x)`——void 入口且无显式 `return`，
  与该形状无关（名字里的 "NoTrailingReturn" 指的是「无末尾 return 语句」的另一件事）；
- 名内其他函数一律写显式 `return`，故该路径从未在 llvm 臂被执行过。

⇒ 缺口类型属手册 §4 的**覆盖盲区类**（路径从未被比对），非「判据假绿」。

## 影响（未逐项量化）

HIR 是当前唯一代码生成路径（M6b 翻转已完成），故凡「函数以尾表达式返回值」的程序，
在 llvm 通道上算错。严重度取决于该写法在真实语料中的占比——**修前应先测爆炸半径**
（本单未测：仅确认最小形状必错）。

## 建议处置方向（未裁决）

1. 发射器补规则：非 void 函数体的**末表达式语句**其结果写入返回槽（与 `returnStmt` 同址），
   并区分「中间表达式语句（丢弃）」与「末尾表达式语句（返回）」——注意必须复刻解释器
   「只有**语句位置**的末表达式算返回；`if` / 循环体内的末表达式不算」的边界。
2. 补差分夹具（非 void + 尾表达式，含标量与元组、含参/无参），使该路径进入 llvm 臂语料。
3. 与 P2a G1（控制流格）的边界关系需确认：该规则涉及块出口判定，可能应并入 G1 而非单列。

## 不做范围

本格（P2a G2 元组族）不修：本单不在 G2 计划面内，且修它需要发射器新增出口规则 +
新增语料，属独立工作单元。启动需点名。
