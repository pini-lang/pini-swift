# Issue：`stringSplit` 的分隔符语义未裁 —— LLVM 侧按**字符集**切分、空分隔符无守卫

- 状态：**Open（2026-09-15 立案；登记不修）** —— 待 spec §1.3 裁决「分隔符是**子串**还是**字符集**」
  以及「空分隔符语义」之后方可实施；**未决策前不动源码**。
- 发现来源：`stringSplit` 格（LR-4，P2b 之后 / P3 之前的**实现对齐**格）执行期间的伴生发现 ——
  该格只消费契约 §2.39 的**空 token** 一项，本单两处偏离在**同一节点**上、但**不在该格范围内**。
- 关联：`docs/spec/hir-contract.md`（条目 39 与 §6 A 组行，语义权威）；
  `docs/issue-hir-string-slice-byte-based-2026-09-11.md`（B 组字符语义，**明文排除 `split`**）；
  `docs/issue-interpreter-hir-gap-audit-2026-09-12.md`（P0 审计，line 113 曾记本节点为「C strtok 两趟」）；
  `docs/issue-diagnostic-channel-parity-2026-09-12.md`（判据类缺陷，本单实测的两面失明机制另挂该单）。

## 性质

- **不是翻转阻塞**：本节点三臂都能跑完（`rc=0`），分歧只在**输出内容**上；且现有夹具
  在**探针判据**下观测不到该分歧（见末节「判据可观测性」），故不进 `FLIP BLOCKERS` 计数。
- **是翻转后的用户可见缺陷**：同一程序在「解释器」与「LLVM 后端」下产出**不同的数组**，
  且差异发生在**单字符分隔符之外**的所有情形上 —— 用户写的多字符分隔符在 LLVM 侧被**当作字符集**。
- **与 `stringSplit` 格的关系**：该格按契约 §2.39 A4 只裁了**空 token**（`"a,,b"` → 2 段）。
  本单两处**超出该裁决范围**，属**新发现的既有缺陷**，不是该格未做完的部分。
  ⇒ 立本单**不违反** P2 计划 §10.4 的「不给 `stringSplit` 格另立工单」—— 那条禁止的是给
  **同一个对象**造第二个状态源；本单的对象是**另一件事**（分隔符语义裁决），有独立待裁项与独立根因。

## 现象（三通道实测，2026-09-15）

探针语料（`/tmp/ss-delim2.pini`，scratch，非语料夹具）：
`"abc".split("")` · `"a:b".split("::")` · `"a::b".split("::")` · `"a..b..c".split("..")` ·
`"x::y".split("::")` · `"ab".split("abc")` · `"ab".split("ab")`。
命令：`pini run`（`PINI_INTERP_ENGINE=ast` / `=hir`）与 `pini run-llvm`。

| 输入 | `interp-ast` | `interp-hir` | `llvm-hir` | 判定 |
|---|---|---|---|---|
| `"abc".split("")` | `[a, b, c]` **3** | `[a, b, c]` **3** | `[abc]` **1** | ⚠️ **分歧** |
| `"a:b".split("::")` | `[a:b]` **1** | `[a:b]` **1** | `[a, b]` **2** | ⚠️ **分歧** |
| `"a::b".split("::")` | `[a, b]` 2 | `[a, b]` 2 | `[a, b]` 2 | 一致（**巧合**） |
| `"a..b..c".split("..")` | `[a, b, c]` 3 | `[a, b, c]` 3 | `[a, b, c]` 3 | 一致（**巧合**） |
| `"x::y".split("::")` | `[x, y]` 2 | `[x, y]` 2 | `[x, y]` 2 | 一致（**巧合**） |
| `"ab".split("abc")` | `[ab]` **1** | `[ab]` **1** | `[]` **0** | ⚠️ **分歧** |
| `"ab".split("ab")` | `[]` 0 | `[]` 0 | `[]` 0 | 一致（**巧合**） |

三臂 `rc` 全为 `0`，无 error / warning。**两个解释器臂在全部七例上逐字节一致**
⇒ 偏离方唯一、且是 **LLVM 侧**；对齐目标无歧义。

⚠️ **「巧合一致」是本节的关键认识**：多字符分隔符的**多数**用例恰好重合，因为
`strtok` 的字符集语义在「被分隔串里每个组成字符都单独成界」时与子串语义**同结果**。
⇒ 这解释了为什么该缺陷长期未被发现（**分歧只在特定输入组合上显形**），
也说明**不能用「几个常用用例一致」推断两侧语义相同**。

## 根因（符号级）

`Sources/PiniCore/CodeGen/IREmitter.swift` → `emitStringSplit(source:delim:type:)`：

- 两趟 `@strtok`（先计数、再填充），源串拷进 `alloca i8, i64 1024` 缓冲区；
- `strtok` 的第二参数是 **C 字符串形式的字符集合**，不是子串。⇒ **根因 A**：分隔符被按**字符集**解释。
  表现：`"a:b".split("::")` ⇒ `::` 退化为集合 `{':'}` ⇒ 2 段；
  `"ab".split("abc")` ⇒ `{a,b,c}` 覆盖整串 ⇒ **0 段**。
- **无空分隔符守卫**：`strtok(s, "")` 把整串作为**单个** token 返回 ⇒ **根因 B**：
  表现 `"abc".split("")` ⇒ 1 段。

对照（两侧均已实现的镜像源）：`Sources/PiniCore/Common/StdlibPini.swift` 的 `split`（下沉 Pini 实现，
AST 通道）与 `Sources/PiniCore/Interpreter/HIRExecutor.swift` 的 `case .stringSplit`（HIR 通道）
**都在 `m == 0` 时逐字素切分**，且都按**子串**匹配（逐字符比较 `sep[j]`）。
两者的存在使本单的「偏离方 = LLVM 侧」有据可依。

## 为什么不在本格顺手修（两条拒绝理由）

1. **契约与实现冲突时的纪律**：改用户可见行为属**止损范畴**，须先确认该语义的**对齐载体格**已在册。
   本两处**既无裁决、也无在册对齐格** ⇒ 按治理顺序先立本单、后走 spec §1.3。
2. **本单需要的是「裁决」而不是「修复」**：`strtok` 的字符集语义是否**可接受**是一个语言层问题 ——
   「分隔符是子串」是**新的语义承诺**（会改变既有 LLVM 行为），必须经
   提议 → 影响评估 → 登记 → 落地 → 证据（spec §1.3），不能由实现在代码里单方面宣布。

## 建议处置（A / B 两路线，待裁）

### 处置项 1：分隔符 = 子串 还是 字符集

- **A（推荐）：裁为「子串」**，LLVM 侧重写 `emitStringSplit` 为逐字符比较的子串匹配（镜像
  `StdlibPini.split` 的 `while i < n / while j < m` 结构），**弃用 `strtok`**。
  - 代价：需处理 1024 字节缓冲上限之外的动态长度（现实现已有一条**未被本单覆盖**的长度上限风险，
    见「未覆盖面」）；工作量中等。
  - 收益：三臂语义同一；与两个解释器臂的既有行为一致；`strtok` 的全局状态（非可重入）一并去除。
- **B：裁为「字符集」**，改两个解释器臂对齐 `strtok`。
  - 代价：**两侧**都要改（不止 LLVM 侧），且 `..` 这类「多字符分隔符」在文档层面会变成
    「等价于 `..` 集合」的**反直觉**语义；还要解释 `"ab".split("abc")` → 0 段。
  - 判定：与 `stringConcat` / `stringContains` 等节点已裁的**子串**语义家族不一致。

### 处置项 2：空分隔符语义

现状 = 两个解释器臂「逐字素切分」（`"abc".split("")` → 3 段），LLVM 侧 1 段。
候选：**(a) 逐字素（与两侧现有实现一致，推荐）** · (b) 判为非法输入、fail-loud ·
(c) 整串单元素（现 LLVM 行为）。
⇒ 本项**偏向已有二对一的既成事实 + `ADR-019 D1` 字素模型**，但**仍须正式登记**后才算裁齐。

## 未覆盖面（本单**已知**但未测，避免留假账）

- **1024 字节缓冲**：`emitStringSplit` 的 `alloca i8, i64 1024` 与 `@memcpy` 在源串 ≥ 1024 字节时
  的形态**本单未测**（未构造长串语料）。它属**同一函数**的实现约束，实施处置项 1 时必须一并评估。
- **`strtok` 的全局状态**：`strtok` 非可重入（静态内部指针）。本单只测顺序单次调用；
  **嵌套 / 重入场景未测**（当前语言是否可达该场景亦未核）。
- **分隔符含多字节 UTF-8**（如 `"、".split("，")`）：本单未测。按 `strtok` 的**逐字节**字符集语义，
  预计偏离形态与 ASCII 多字符一致，但**未实测不作断言**。
