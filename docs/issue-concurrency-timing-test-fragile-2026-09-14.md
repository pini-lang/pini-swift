# Issue：`testConcurrentTasksOverlapInTime` 的墙钟断言在全量并行负载下脆弱

- 状态：**Open（2026-09-14 立案；LR-4 P2b G7 收口连带发现，不阻塞本格）**
- 发现渠道：G7（字符串与内建）**全量回归的第一次运行**。该次 1260 份测试中**唯一的失败**是本项，
  即它把一次「实现完成、4 个断言待更新」的回归读数**搅成 5 个失败**，需要逐条归因才能分辨
  ——**这就是立案的理由**：脆弱断言的成本不在它自己红不红，而在它**污染别人的读数**。
- 归属：**测试稳定性**（非语言语义、非 HIR、非 LLVM）。
- 关联：`docs/issue-interpreter-hir-p2-plan-2026-09-13.md` §8.7（本单的来源格实录）。

## 现象

`Tests/PiniTests/ConcurrencyTests/ConcurrencyTests.swift:151`：

```
XCTAssertLessThan(..., 0.11, "两个并发任务应重叠执行（墙钟 < 110ms），实测 \(elapsed)s 表明疑似串行")
```

判据是**绝对墙钟**（110 ms），实测 **0.11201703548431396 s** ⇒ 失败。

## 实测读数（三次，同一台机器同一天）

| # | 命令 | 结果 |
|---|---|---|
| 1 | `swift test`（全量，G7 收口第一次） | **1 failure**：本项，实测 `0.11201703548431396` s（阈值 0.11） |
| 2 | `swift test --filter ConcurrencyTests` | **35 tests / 0 failures**（单独跑全绿） |
| 3 | `swift test`（全量，G7 收口最终） | **1263 tests / 0 failures** ⇒ **未复现** |

## 判定

- 余量只有 **2 ms**（0.112 vs 0.110），而断言的是**墙钟重叠** —— 在**全量套件**下测试进程数变多、
  调度与机器负载都在动，2 ms 的余量不足以稳定。
- 读数 2 与 3 说明它**不是稳定失败**（不是真串行），是**负载敏感的抖动**。
- ⇒ 因此**与 G7 无关**（G7 只改 `HIRExecutor.swift` 与测试表，不碰并发运行时）。
