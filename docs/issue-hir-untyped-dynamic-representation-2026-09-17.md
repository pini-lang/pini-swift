## 0. 一句话

四个看起来无关的缺陷（`var xs = []` / `var ys = []; ys.append("b")` / `[Any]` 标注 / 无标注形参）
是**同一件事**：**静态层没有「类型未定 / 动态」这个表示** —— 一切类型位必须在降载期当场解成一个具体类型，
而语言表面允许「先写下来、后由用法决定」。⇒ 修这个表，而不是四次修表下的四个洞。

## 1. 四个形态（全部实测，2026-09-17，HEAD `1438887`）

### 形态 1 · 无标注空数组：`var xs = []` 的元素类型落成 `i32`

```pini
main|func() -> ():
    var xs = []
    xs = xs.append(Shape.circle(r= 3,))
    print(len(xs))
    return
```

**实测**（两条独立用例，两个不同枚举，同一形状）：

```
HIR lowering error at 3:19: type mismatch: enumeration(name: "Shape") is not i32
HIR lowering error at 3:19: type mismatch: enumeration(name: "Other") is not i32
```

```sh
swift test --filter "PiniTests.CrossFileRuntimeTests/testCrossFileQualifiedEnumCaseConstruction|PiniTests.CrossFileRuntimeTests/testCrossFileAmbiguousCaseAllowsQualified" 2>&1 | grep "error:"
```

⇒ 空数组字面量**没有元素类型来源**，降载期给它一个**默认具体类型**（实测症状是 `i32`），
而语言表面允许「由后续 `append` 决定」。⇒ 二者冲突。

### 形态 2 · 无标注累积器：同一件事的「非空起步」版

```pini
main|func() -> ():
    var zs: [Any] = [1, "a"]
    var ys = []
    ys = ys.append(1)
    ys = ys.append("b")
    print(zs,)
    print(ys,)
    return
```

AST 侧实测输出（**两行都对**）：

```
[1, a]
[1, b]
```

HIR 侧实测（⚠️ **注意它死在哪**）：

```
HIR lowering error at 3:5: variable 'zs' has non-scalar annotation '(non-scalar)'
```

⇒ ⚠️ **本形态的首缺口被形态 4 遮蔽**：`zs: [Any]` 的标注先被拒，`ys` 的问题还没轮到暴露。
**这是 `P4-1a` 记录的「首缺口遮蔽」在本工单内的实例** —— 判据须按「剥掉形态 4 后再看」取，
不能按本夹具当前的红因归因给形态 2。**本件如实登记这一层遮蔽**，不把它算成形态 2 的证据。

### 形态 3 · 「由调用点决定」的无标注形参（**已部分处置**）

`G-2R` 交付「**无标注形参跨文件传参**」（4 条交付之一），`docs/issue-hir-p4-gamma-batches-2026-09-16.md`
记其 CLI 面实测可用（单文件两引擎都输出 `hi`）。
⇒ 本形态的**函数参数位**已有处置；**但**它当时被判为与形态 1/2 **同源**（同一根因：「类型由用法定的位」）。
⇒ 本件**不重复立案**，只登记「同源关系」：**修好表示层之后，这一支也应当自洽**，
否则说明当初的处置是**位点特判**而非表级修正。

### 形态 4 · 通配类型标注 `[Any]` 在降载层不被接受（**本件新发现，此前未立档**）

```
variable 'zs' has non-scalar annotation '(non-scalar)'
```

⇒ `[Any]` 在**前端类型检查器**是通过的（AST 侧该程序跑通并输出两行），
但在**降载层**被当作「非标量标注」拒绝。
⇒ 这是「**动态 / 通配类型**」这一族在**降载层的表示缺失**，与形态 1/2 同一张表的另一侧。

## 2. 同源论证（为什么必须合并立项，而不是四张工单）

| 形态 | 类型位在哪 | 类型从哪来（语言表面） | 静态层的反应 |
|---|---|---|---|
| 1 无标注空数组 | 变量声明 + 元素 | **由后续用法** | 给一个默认具体类型（`i32`）⇒ 与用法冲突 |
| 2 无标注累积器 | 变量声明 + 元素 | **由后续用法** | 同上（被形态 4 遮蔽） |
| 3 无标注形参 | 形参 | **由调用点** | `G-2R` 已部分处置 |
| 4 `[Any]` 标注 | 标注位 | **由作者显式写「任意」** | 降载层无此表示 ⇒ 拒 |

**共同结构**：语言的类型表里**只有「具体类型」与「已解出的泛型实参」**，没有
「**尚未定 / 由用法定 / 任意**」这一档。⇒ 凡语言表面允许「后置决定」的位置，
静态层只能**猜一个具体类型**（形态 1/2）或**拒**（形态 4）。

**⇒ 这是表级缺口，不是四处实现疏漏**。分四次修，会得到四套「就地打补丁」的处置，
且**第五个同类形态出现时仍会漏**（形态 4 就是本件新发现的一个——它一直存在，只是没人归口）。

## 4. 处置方向（三选项，**未裁**；本件只登记不修）

- **① 类型表加「未定 / 动态」一档**（提案 → 影响评估 → `spec §1.3` → 落地 → 证据）。
  代价 = **语言级变更**，涉 `TypeAnnotation` / `HIRType` / `Value` 三处表示 + 契约 §1（**类型层 20 case**）
  + 类型检查器与降载层的求值规则；收益 = 一次修到表上，第五个同类形态不会再漏。
  ⚠️ 若采纳，**契约计数会变** ⇒ 与 `G-3` 的硬停同款流程（`spec §1.3`）。

- **② 只在降载层「就地放宽」四处**（形态 1/2 给元素类型一个「待定」占位、形态 4 放行非标量标注）。
  代价 = 四处特判、无表示层支撑；收益 = 不动契约、不动类型表、当批可落地。
  ⚠️ 风险 = **`call` 条目偏差那一族的老路**（实现约定无登记处）⇒ 必须在契约里写明占位语义。

- **③ 不做，登记为已知缺口**（在 `docs/spec/pini-spec-v0.md` §3 缺口登记里立 G 号）。
  代价 = 3 条用例长期红 + 用户可见的「空数组不能装非 `i32`」；收益 = 零风险。

**建议**：**③ 先行、② 视 `G-3`/`G-6` 的排期再定、① 留到自举之后**。
理由：它**不阻塞翻转**（3 条红，且不在 `G-3`/`G-4`/`G-5` 的验收面内）；
而 ① 是语言级变更、代价与 `G-3` 同级，**在翻转前引入第二个语言级变更会同时抬高两条线的风险**。
