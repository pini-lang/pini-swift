## 1. 发现（实测，2026-09-13，宿主 HEAD 7204846，`.build/debug/pini` 与 `/tmp/pini-build/debug/pini` 双产物一致）

同一「字符串未闭合」类输入，`pini tokens` 行为**分叉**：

| # | 输入 | rc | 输出 | 契约判定 |
|---|---|---|---|---|
| **H1** | `var x : String = "abc\`（反斜杠后**紧跟 EOF**） | **1** | `Error: Lexer Error [E1-002] … unterminated string literal` | ❌ **违反** |
| **H2** | `var x : String = "a\(b`（插值体未闭合，行尾终止） | **1** | 同上（位置指向 `2:1`） | ❌ **违反** |
| C1 | `var x : String = "abc`（行尾终止） | 0 | `string "abc"` | ✅ 合规 |
| C2 | `var x : String = "abc\` + 换行 | 0 | `string "abc\` + 换行 | ✅ 合规 |
| C3 | `var x : Int = 1 @ 2` | 0 | `at @` | ✅ 合规 |
| C4 | `/* unclosed` | 0 | `slash` `star` | ✅ 合规 |
| C5 | `0x` / `0b` / `1e` / `1.2.3` / `0xZZ` | 0 | 全部回退，无抛错 | ✅ 合规 |

**契约原文（ADR-021 D1，转引自 `docs/issue-lexer-gap-closure-2026-08-29.md` §2）**：
「词法器永不失败……**字符串行尾/EOF 隐式终止**」。

## 2. 根因（代码级；符号定位为准，行号仅作软定位，spec §1.4）

`Sources/PiniCore/Lexer/Lexer.swift` 全文**仅 6 处 `throw`**（539 / 545 / 580 / 639 / 674 / 679）。
其中落在「**字符串扫描的 EOF 边界**」的共 **2 条路径**：

1. **`:580`** —— 常规字符串路径：`guard let esc = currentChar else { throw LexerError.unterminatedString(loc) }`
   （反斜杠之后直接 EOF）⇒ **H1**。
2. **`:622-681` `scanInterpolationExpression()`** —— 函数体内 **3 处** throw：
   `:639`（内层字符串反斜杠后 EOF）· **`:674`（遇换行且 depth > 0）** · `:679`（循环退出即 EOF 且 depth > 0）⇒ **H2**。

> ⚠️ **订正一条既有记录**：2026-09-13 L5 日志记该函数「`throw unterminatedString`（**4 处**）」——
> 源码实测为 **3 处**（`:639`/`:674`/`:679`）。上文已订正。

### 2.1 关键结构发现（本单的诊断价值所在）

同一条 ADR-021 纪律，在**相邻代码**上分叉：

- **常规路径 `:571-576` 明文落地了它**，注释直引 ADR-021：

  ```swift
  while let char = currentChar, char != "\"" {
      if char == "\n" {
          // ADR-021：宽松词法——字符串在行尾隐式终止（换行不消费，
          // 版面处理照常），不再抛 unterminatedString
          break
      }
  ```

- **插值路径 `:673-675` 同一情形却是 throw**：

  ```swift
  if char == "\n" {
      throw LexerError.unterminatedString(currentLocation)
  }
  ```

⇒ 结论：**不是「没人想到」，而是同一纪律在一条分支上落地、在相邻分支上漏了**。
⇒ 这也解释了既有门禁为何全程未报（见 §3）。

### 2.2 未违反项（并列登记，避免把 ADR-021 读成「普遍失效」）

`:539` / `:545` 的 `LexerError.invalidCharacter`（畸形浮点 / 整数）在实测输入上**不可达** ——
C5 全部 rc=0 且按 ADR-021 D1 回退（畸形进制/指数回退 `int 0`/`int 1` + 标识符）。
⇒ **本单不主张**这两个 throw 点是违规；它们是**登记在案的死面或另一条件专有**，超出本单范围。

## 3. 为何未被任何判据测量（盲区三重）

1. **语料零覆盖**：`examples/selfhost/examples/lex_corpus.pini`（123 行）仅 **1 处**插值用例
   （`:93` = `var msg = "hi \(语)!"`）且**闭合**；**零未闭合用例**。⇒ 该分歧从未进入对拍面。
   （注：L5 日志曾把该路径写成 `examples/lex_corpus.pini`，实际路径见上。）
2. **门禁口径所限**：L0 `diff_tokens` 对拍的是**双侧都能产出 token 的输入**；一侧直接抛错 ⇒
   该输入**根本不在对拍集合内**，「两侧一致」与「从未测量」不可区分。
3. **退出码语义混淆**：`tokens` 在**多数**词法错误上 rc=0（C1–C5），**仅 H1/H2 两处** rc=1。
   ⇒ 「rc=0 即合规」不能当判据；反之「rc≠0」也不能直接读成 I/O 错误。

> ⚠️ **订正一条既有断言**：2026-09-13 L5 日志写「`tokens` 对**词法错误恒 exit 0**、仅 I/O 错误才非零」。
> 本单实测证明该断言**过度概括** —— C1–C5 成立，H1/H2 是**反例**。改为：「`tokens` 对**多数**词法错误 rc=0，
> 例外 = 字符串扫描的 EOF 边界两处（H1/H2）」。

## 4. 附带登记：E1 域不在诊断权威映射内

- `docs/spec/diagnostic-codes.md` §E1 明文列有 `E1-001 非法字符` / `E1-002 未闭合字符串` / `E1-003 缩进错误`。
- 但 `Sources/PiniCore/Resources/Diagnostics.en.toml` 实测 **70 段**，域分布 =
  `E2×23 · E3×11 · E4×14 · E5×15 · E6×5 · E7×2`，**零 `[E1-*]`**。
- ⇒ E1 消息由 `Sources/PiniCore/Common/ErrorFormatter.swift`（`:164`
  `case .unterminatedString: return "unterminated string literal"`）**硬编码兜底**渲染。
- ⇒ **E1 整域绕过权威映射**：spec 说有码 → 映射里没有 → 渲染走硬编码，**三者不同源**（E2 与 E1 冲突，E2 胜）。
- **与 §1 的关系**：**独立可修**（补 toml 段 + formatter 改走映射即可），与 H1/H2 的修复**不耦合**；
  故不合并为一处修复、只登记于此。

## 5. 修复面与一个**待裁**（本单不代裁）

### 5.1 低风险侧（可直接做）
- **`:580`（H1）**：`guard … else { throw }` → 「EOF 处隐式终止」，与 `:575` 的 `break` 同语义，落回字符串 token。
- **§4 的 E1 映射补齐**。

### 5.2 须先裁（契约级）
H2 的插值路径若照 `:575` 那样「隐式终止」，会**产生语义歧义**：`"a\(b` 在行尾终止时，
插值体 `b` 是一个**不完整表达式**。三条路线：

| 路线 | 做法 | 代价 / 判据 |
|---|---|---|
| **A（本单倾向）** | 整个字面量**降级为普通 `string` token**（保留源文本；插值体**不作为表达式求值**）⇒ 把判断推给解析/语义阶段 | 与 ADR-021 D1 的**自述理由**一致（「错误报告是解析/语义阶段职责；标识符落在不合适的位置自然被拒」）。代价 = 词法层不再承诺 `\(` 必为插值 |
| B | 隐式补 `)` 并产出 `interpolatedString` | **造出语义上不存在的表达式** ⇒ 触 ADR-024 D9 精神（伪造绿）。不推荐 |
| C | 保留 throw，但为插值路径在 **ADR-021 里开一处显式例外** | 需改 ADR（契约级，走 spec §1.3）；且把「词法器永不失败」降格为「多数情况不失败」 |

⇒ **倾向 A，但须用户裁决**：三条路线都改变**可观察行为**（错误类别或 token 类别）
⇒ 按 spec §1.3 走「提议 → 影响评估 → 登记（§3 缺口 + ADR）→ 落地 → 证据登记」。

## 6. 语料为何**本单不落**（关键，勿误读为遗漏）

把 H1/H2 的未闭合用例加进 `examples/selfhost/examples/lex_corpus.pini` 会**立刻使 L0 对拍转红**
（宿主 rc=1 ⇒ host 侧输出残缺）。而 `docs/issue-selfhost-probe-plan-2026-09-13.md` §6.1 的
**门禁红窗口红名单机制尚未获裁** ⇒ 现在落语料 = 要么违 ADR-024 D9（伪造绿），
要么开一个**未获授权的红窗口**。

⇒ **语料随本单修复一起落**；或**先裁红窗口机制**再落。二者取其一，**不得静默跳过**。
