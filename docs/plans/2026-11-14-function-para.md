# Pini 调用点实参标签方案

## 一、问题

Pini 当前调用点实参标签是**可选糖**：

```
创建("张三", 42,)              ; 全位置，合法
创建(名称 = "张三", 年龄 = 42,) ; 标签，合法
```

`call-arg ::= [IDENT '='] expression` 中 `[IDENT '=']` 可选，且没有强制标准。  
结果：**调用点普遍退化为纯位置传值**，导致：

- 多参数同类型不可辨：`设置(10, 20,)`
- 布尔参数不可辨：`配置(true, false,)`
- 默认参数与位置实参混用易错位
- 重构改形参顺序时，调用点静默错位

## 二、方案：把 `_` 前缀规则延伸到参数位

核心读法：

> **默认表面 = 调用点必须写标签；`_名` = 退出默认表面，调用点可不写标签。**

### 声明与调用形态

```
创建(_名称: String, 年龄: I32 = 0,) -> 用户:
    ...

创建("张三", 年龄 = 42,)      ; _名称 不写标签；年龄 必须写
创建("张三",)                 ; 年龄 省略，用默认
```

```
距离(_a: 点, _b: 点,) -> F64:
    ...
距离(点A, 点B,)               ; 纯位置，声明点显式退出
```

### 规则表

| 参数声明 | 调用点 |
|---|---|
| `_名: T` | 不写标签，按位置 |
| `名: T` | **必须写标签** `名 = 值` |
| `名: T = 默认` | 省略时用默认；显式给实参时**必须写** `名 = 值` |

## 三、与现有 `_` 语义的一致性

§4.10 已把 `_` 定为“退出默认表面”，现有位置：

| 位置 | `_` 含义 |
|---|---|
| 声明位 `_名称` | private |
| 文件 `_名称.pini` | internal |
| 目录 `_名称/` | package |
| 导出表 `_C = 符号` | 抑制导出 |
| 导入表 `_B = "路径"` | 注入导入 |
| 模式位 `case _:` | 通配 |

新增：

| 位置 | `_` 含义 |
|---|---|
| 参数位 `_名` | 调用点不写标签 |

**不新增关键字、不新增记号，复用同一条“退出默认表面”语义。**

## 四、解决的问题

| 问题 | 现状 | 方案后 |
|---|---|---|
| 标签可选导致全位置传值 | 调用点自由选择，无记录 | 默认强制标签；省标签须在声明点显式 `_`，有记录、可审查 |
| 多参数同类型不可辨 | `设置(10, 20,)` | `设置(宽 = 10, 高 = 20,)` |
| 布尔参数不可辨 | `配置(true, false,)` | `配置(启用 = true, 严格 = false,)` |
| 默认参数位置错位 | `创建("张三", 42,)` 靠位置猜 | 显式给默认参数必须写标签，省略即用默认 |
| 重构改形参顺序静默错位 | 位置实参不报错 | 非 `_` 参数必须标签，可读性提升 |

**关键改进：把“是否写标签”的决定权从调用点移到声明点。声明点写一次、可审查；调用点写多次、不可审查。**

## 五、实施计划

### 5.1 现状读数

| 项 | 读数 |
|---|---|
| `.pini` 文件 | 245 个：`bootstrap` 106、`examples` 70、`Tests` 65、`bench` 3、`Sources` 1 |
| 自举声明（`func` / `self` / `own`） | 944 个：零形参 97、单形参 342、多形参 505，合计 1888 个形参 |
| 调已声明函数的处数 | 约 3523 处：单形参调用 1225、多形参调用 2210、零形参调用 88 |
| 点号方法调用 | 约 2259 处，多数是内建方法（豁免面，真实数由普查给出） |
| 宿主测试内嵌 Pini | 81 个 Swift 文件、624 处函数声明 |

三处现状要先说清：

- 宿主（`Sources/`，`.build/debug/pini` 用的那一套）**不支持参数默认值**，`名: T = 默认` 在解析期就报错；自举语法包能解析默认值。规则的判定不依赖默认值是否存在，但规范里“显式给默认参数要写标签”这一行在宿主暂时测不到。
- 宿主对 `别名.成员(...)` 的跨包限定调用按**不透明**处理（只查实参表达式，不查签名）；裸名导入的跨包调用正常解析。所以限定调用这一形暂不判。
- 宿主 `pini check <目录>` 走的是首错即停的通道，整包收错要先补一条收集模式，否则普查读数会偏小。

### 5.2 规则口径

**标签面**：一张函数声明里，哪些形参在调用点必须写标签、哪些按位置。下文一律用这个词。

| 构造 | 判不判 | 依据 |
|---|---|---|
| 自由函数调用 | 判 | 声明的标签面 |
| 方法调用（`\|self` / `\|own`） | 判 | 方法声明的标签面 |
| 特征方法调用 | 判 | 特征声明是契约，实现必须同规 |
| 内建函数与方法 | 不判 | 签名表不带标签面，保持位置式 |
| 外部函数块 | 不判 | C ABI 没有标签位 |
| 枚举具名构造 | 不判 | 现状是位置式（E4-014），本批不改 |
| 函数值调用 | 不判 | 函数类型里没有形参名 |
| 跨包限定调用 `别名.名(...)` | 暂不判 | 宿主当前不解析；随接口产物接入 |

**绑定名**：`_` 是形参名字的首字符，不是可摘的标记。声明写 `_名`，体内引用、改名与检索一律写 `_名`；`_名` 与 `名` 因此是两个不同的形参，可同处一张参数表。

**对位**：标签按名字对位、允许乱序；位置实参只填空着的 `_` 形参，按声明序进行；`f(a = 1, 2,)` 合法，当且仅当 `2` 落到的那个形参已退出标签面。

**默认值与取用参数**：省略即用默认（取用位由默认实例填充），这两条沿用；显式给值时必须写标签，与普通形参同一条规则，不另设判据。

**特征同规**：实现方法的标签面（哪些形参写了 `_`）必须与特征声明逐位一致，不一致按 E4-008 报“签名不符”。

**诊断码**：缺标签 E4-036、`_` 形参收到标签 E4-037、重复标签 E4-038；未知标签维持 E4-009。四个码在宿主与自举两侧同码同义。

### 5.3 分阶段

| 阶段 | 交付 | 判据 |
|---|---|---|
| **规则落地** | 宿主按 5.2 判定，默认严格（不设开关） | 新增 14 项宿主测试绿；语料未迁完前严格检查预期红 |
| **错误普查** | `check --report=tsv` 输出违规清单；按声明与按文件两张汇总表 | 清单行数与检查器报错总数一致；抽 20 条人工核对 |
| **批量改码** | 分档迁移：单形参声明加 `_`，多形参调用补标签 | 严格检查归零；三通道测试全绿；格式门禁全绿 |
| **自举同规** | 自举 `call.pini` / `parser.pini` 同一套判据 | 语义包两通道全绿；新增 8 项测试 |
| **语料收口** | 迁 `examples` 与宿主测试语料；规范三处更新 | 全仓严格检查归零；示例门禁不缩水 |

**规则落地**的具体改动面：

- 语法树：`Parameter.name` 原样保留源码写法，标签面由名字推出（`takesLabel = !name.hasPrefix("_")`），不另存字段，故名字与标签面不会各记一份而彼此不符；打印器与签名序列化直接写名字。
- 签名：`FunctionSignature` 增形参标签面（名字、是否要标签、声明位置）；自由函数、泛型函数、结构/对象/扩展/特征/本型方法、泛型方法的注册点都填，内建与外部函数留空即豁免。
- 类型哨兵与参数标记分开判：类型位的 `_` 表示“未标注”，名字位的 `_` 表示“退出标签面”，两者不能混用同一条判据。
- 对位：`validateCallArguments` 改成“标签先对名、位置再填空位”，同时补重复标签判据与四条错误；`using` 省略式与变参的既有判据保留。
- 诊断：两张码表加 E4-036 / E4-037 / E4-038，重跑 `bootstrap/tools/gen-diagnostics-table.py` 更新自举码表。
- 判定入口：不设开关，`check`、`test`、`build` 一视同仁；`check` 只多一个临时 `--report=tsv` 供普查用，目录模式补 `checkCollecting(package:)` 一次收全。
- 测试：规则表逐行、`_` 退出、显式默认值、取用位、方法、特征、乱序、重复、未知、内建与外部函数豁免、函数值豁免。

**错误普查**的 TSV 字段：`文件 行 列 码 被调 形参 形参下标 声明文件 声明行`。带声明位置是为了按声明聚合，也是为了改声明时精确落点。工作区根不能直接 check（根清单是工作区形态，不是包清单），普查按 8 个包逐个跑。

**批量改码**的脚本放 `tools/arg-label-migrate.py`，属临时脚手架，收口后删除。档位是分档：单形参声明加 `_`，多形参调用补标签。两条改写规则：声明处按形参序插 `_`（`using` 前缀之后）；调用处按 TSV 的行列在实参起点插 `名 = `，同一行多处从右往左应用。每轮改完立即严格复查，仍有错的文件回滚并列人工清单。

**自举同规**的注意点：自举侧没有开关，必须先完成源码迁移再落这条，否则自举自检先红；`call_test` 与 `container_test` 里按位置构造的既有夹具要同步改。

**语料收口**的难点在宿主测试内嵌 Pini：556 处声明在 75 个文件的多行块里，68 处在 18 个文件的单行串或普通代码里。多行块按去缩进后的行列映射回字面量，脚本可改；单行串逐条人工改。没有开关，语料不迁完就不能提交，这一步与批量改码同批完成。

### 5.4 风险与边界

1. **接口产物必须带标签面**：装配面的接口文本要把“形参名 + 是否要标签”列进去，否则自举侧永远判不了跨包调用。
2. **全局名字映射**：宿主现在按函数名存形参表，跨包同名会把标签面串味。本仓当前 841 个函数名零重名，但迁移时应顺手改成按声明身份存。
3. **大 diff 与并行批次**：默认严格意味着迁移完成前分支一直是红的，不能分段提交；单独分支、一次性合并，迁移期间不并行改 `.pini`，否则脚本的落点会漂。
4. **列号口径**：宿主按字符计列，脚本按码位切串，中文语料一致；含组合附加符号的语料先列出来人工处理。
5. **宿主默认参数缺口**：本批不实现，规范里那一行在宿主保持“不可测”，单列为后续缺口。
6. **目录检查首错即停**：普查与门禁都必须走收集模式，否则会把“只报了一条”当成“只有一条”。
7. **枚举构造两处口径打架**：规范把 `E(x = 1)` 列进 `=` 的用法，宿主的 E4-014 却按“位置式”拒收。本批不裁决，维持实现现状，把冲突记进回执。
8. **既有诊断路径会动**：`validateCallArguments` 从按位置对位改成按标签对位，参数个数与类型诊断落到哪个实参会变。既有测试若断言了旧文案或旧码，按新判据逐条核对后再改，不静默放宽。

### 5.5 三项裁定

| 项 | 裁定 | 落地口径 |
|---|---|---|
| **迁移档位** | 分档 | 单形参声明加 `_`；多形参调用补标签；方法调用同规 |
| **开关形态** | 直接默认严格，不留过渡开关 | 判据不挂开关；`--report=tsv` 只作迁移脚手架，迁完删除 |
| **适用面** | 全形纳入 | 自由函数、方法、特征都判；内建、外部函数、枚举构造、函数值豁免；跨包限定暂缓 |

三项合起来的效果：多形参的调用点必须一次迁完，分支在迁移期间是红的；单形参调用保持位置式，退出记录在声明点的 `_` 上。

### 5.6 不做的事

- 宿主参数默认值的实现（另一件事，不混进本批）。
- 枚举构造具名化（现状位置式，规则不覆盖）。
- 跨包限定调用的签名解析（随接口产物）。
- 未知标签改用新码（E4-009 继续用，文案本身后续再理）。

### 5.7 验收口径

- 严格检查：8 个包、`examples`、`Tests` 语料逐项归零，读数写进回执。
- 测试：宿主全量（含 81 个内嵌语料文件）、工作区解释器与原生通道、`semantics` 两通道。
- 门禁：注释、格式、文档链接、诊断表一致性、内建清单、IR 契约。
- 构建：`pini build bootstrap` 后产物输出保持 `workspace-ok 3 true`。
- 筹划载体：自举计划只加一行指针指向本件，批次表不复制两份。

### 5.8 交付回执
