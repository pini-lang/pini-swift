# 引用计数进解释器

## 目标与边界

给解释器补上对象的生命周期：计数、`deinit` 调用点、弱引用与无主引用的存活判定，以及字段私有性
在运行期的可访问性检查。执行表的 `deinit` 一例由「保留差异」转「通过」，`E5-010` 发出。

边界：不改 ARC 的语言面语义（计数规则以参考件内存模型章为准）；不实现 `asyncDeinit` 的真实调度——
它与结构化作用域退出两侧都没有，本件只登记，不硬造。运行时段的计数实现也不在此件，在 **运行时 C 化**。

## 缺口与读数

| 项 | 现状 | 取数入口 |
|---|---|---|
| `deinit` 执行 | 保留差异：解释器无计数，析构不触发 | `tests/parity/execution-disposition.tsv` |
| `E5-010` | 保留差异：解释器不判类型私有字段的可访问性 | `tests/parity/diagnostics.tsv` |
| 弱引用解引用 | 目标释放后未置空即读到悬垂 | `examples/lazyref.pini` 邻近夹具 |
| 析构形状检查 | 已交付：`deinit` 挂错类型/带形参/异步在声明处拦下 | `packages/semantics/src/api/lifecycle.pini` |
| `asyncDeinit` | 两侧都没有，保留差异 | `docs/spec/pini-reference.md` 内存模型章 |

## 批次

### 一、对象计数

对象值在解释器里改成带计数的箱：赋值加一、离开作用域减一、归零调 `deinit` 再释放。值语义的
struct 与容器不受影响，仍按拷贝走。

判据：`examples/deinit.pini` 输出「体」后跟「析构」；同一对象析构只调一次。

### 二、弱引用与无主引用

弱引用在目标释放后读取得 `nil`；无主引用不查存活，但目标已释放时读它是未定义——解释器要给稳定行为，
不能读到随机内存。

判据：弱引用目标释放后读取得 `nil`；无主引用的悬垂读按既定诊断报，不崩。

### 三、字段私有性

`type-private` 字段的可访问性在运行期判一次：调用点所属类型与被访问字段的宿主类型不一致即报 `E5-010`。
检查层已能判的，运行期不重复报，避免同一处出两条。

判据：`E5-010` 发出；正例（类型自身方法内访问）不报；差异表删该行。

## 风险与裁定

| 风险 | 处置 |
|---|---|
| 计数与值语义混用导致双重释放 | 只有 `.object` 与句柄类值走计数；struct、容器、元组保持拷贝语义 |
| 循环引用永不归零 | 参考件已有环检测章节；本件先做计数，环检测按该章另排 |
| `deinit` 里再改自身字段 | 参考件规定析构体不归还 self；解释器要在调用点拦，不在析构体内兜底 |
| 计数开销拖慢解释通道 | 与 **解释通道提速** 的读数一起看；单项变慢不算回归，全量耗时算 |
