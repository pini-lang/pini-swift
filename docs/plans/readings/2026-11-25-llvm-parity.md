# llvm 通道全文对账读数

本件是交付证据，不是筹划载体：通道面要回答的问题、收口次序与判据写在
`docs/plans/2026-11-12-self-hosting-plan.md` 的 **通道面** 一节，这里只存量出差集时的实测读数与探针。

注意 读数易腐。它们绑定当次的机器、工具链与源码规模；实现一变即失去可比性，引用时只可作
「当时差多少」的依据，不可当作验收判据。

## 环境

| 项 | 值 |
|---|---|
| 机器 | macOS 27.2.1，arm64 |
| 宿主编译器 | `.build/release/pini`，Apple Swift 6.4.2 |
| 自举编译器 | `bootstrap/.build/release/bin/pini-bootstrap`，首代产物 |
| LLVM 工具 | Homebrew clang 23.1.5 |
| 被测输入 | `examples/` 下 65 个单文件程序；目录形态与 bench 不在本次面内 |
| 测量脚本 | `bootstrap/tools/llvm-parity.py`，只读测量，产物落构建目录 |

两侧用同一条命令：`pini emit <绝对路径> -o <产物>`。给绝对路径是必须的——自举按程序基准解析
相对输出路径，相对写法会落到包目录下。

## 方法与口径

全文逐行比无意义：函数顺序、前导声明与所有权写法一起变，行级比对会把每一行都记成差异。故先把两侧
文本规范化到可比形状，再用阶梯读数看「哪一类差异被抹掉之后，函数体才相同」：

- 去注释、去指针类型拼写（`i8*` 与 `ptr`）、局部名与基本块标签按首现重编号、串常量按首现重编号；
- 槽分配（`alloca`）提到函数体表头并按类型排序；
- 函数按名排序后再比：宿主自身的函数顺序两跑就不同，排序才能稳定地量函数体差；
- 阶梯四级：**体全同**（规范化后逐行相同）→ **去归还**（删归还调用，并清掉只喂给它的装载与取址）
  → **去跳板**（抹掉 `Lx: br label Ly` 空跳板）→ **同指令集**（只比指令多重集，不比顺序）。

前导（声明 + 全局）与函数体分两笔计：两侧的前导策略本就不同，混在一起看会盖掉函数体的差。

## 差异分类

十五类。前六类在前导与函数集层，后九类在函数体层。「影响行为」列的判断依据是：该类若被抹平，
两侧产物是否产生同一可观测结果；标「否」的类只改文本。

| 类 | 证据 | 量 | 影响行为 |
|---|---|---|---|
| 头部注释 | 宿主 `; Pini LLVM IR` 一行；自举 `; pini llvm module` 与 target 行两行 | 每例 1/2 行 | 否 |
| 前导声明 | 宿主固定列全运行时段符号（hello 就有 63 条 `declare`），自举只列用到的 12–27 条 | 累计宿主持有、自举未声明 3,322 条 | 否 |
| 类型定义 | 宿主发 `%bk_array` / `%bk_dict` / `%bk_set`，有并发时另发 `%struct.调度器`；自举不发 | 每例 0–4 行 | 否 |
| 程序基与收尾 | 宿主 `main` 首调 `bk_set_program_base`、尾调 `bk_runtime_cleanup`，并带 `@.pini_program_base` 全局；自举两者都无 | 每例 3 处 | 否（相对路径解析另计） |
| 串表编号 | 宿主预留 `@.str0` 作空串占位，其后串名整体后移一位；自举从 `@.str0` 起编 | 每例全体串名位移 | 否 |
| 聚合格式串 | 自举固定发 10 条（`fmt_space`、`fmt_lbracket`、`fmt_colon` 等）；宿主按需，hello 一条不发 | 每例 10 条全局 | 否 |
| 函数顺序 | 宿主把标准库成员排在前、`main` 居中、给定块物化在尾；自举 `main` 首 | 65/65 例顺序不同 | 否 |
| 预置给定块 | 宿主每例恒发 `收下__调度器`、`选择下一个任务__调度器`，另有 9 例发 `__given_init__调度器`；自举无此声明 | 每例 2–3 个函数 | 非用户可达 |
| 胶水与物化命名 | 宿主 `__release_enum.形状` / `__release_struct.计数器`；自举 `__release_box_1` 一类数字名。给定块宿主 `__given_init__X`，自举 `__given_make__X` | 124 个函数名不同 | 否（跨侧链接不可解析） |
| 泛型实例拼写 | 宿主 `身份_I32`、`取_盒_String`；自举 `身份__I32`、`取_盒$String` | 每处实例一名 | 否（同上） |
| 入口与环境箱 | 自举每函数发 `entry:` 标签与 `%ebox = alloca [8 x i8], align 8`；宿主都不发 | 每函数 2 行 | 否 |
| 槽分配与缩进 | 宿主先把全部槽 `alloca` 完再写 `store`，缩进一格；自举逐个 `alloca` + `store`，缩进两格 | 每函数槽数行 | 否 |
| 所有权与归还 | 自举在出口释放形参与接收者；宿主不释放形参、只释放自有中间值。同一 `io` 示例：`bk_str_release` 宿主 19 次、自举 101 次，`bk_str_retain` 两侧各约 27 次 | 1,237 个函数 | 两侧各自自洽，目标文件不可混链 |
| 分支结构 | 自举给 `if` 补 `if.else.0: br label %if.end.0` 跳板；宿主直连 `if.end` | 846 个函数 | 否 |
| 指令选择 | 串前缀比较：宿主取长度前缀 + `memcmp`，自举调 `strcmp`；`sqrt` 宿主走 `llvm.sqrt.f64`，自举有走 `bk_*` 的路径；句柄释放宿主用 `__release_*` 胶水，自举另有 `bk_handle_release` | 546 个函数 | 否 |

## 行为等价抽查

把两侧发射的 `.ll` 各自用 `clang` 链接同一份 release 运行时段库后运行，抽查四例：

| 示例 | 宿主退出码 | 自举退出码 | 输出 |
|---|---|---|---|
| `hello` | 0 | 0 | 逐字节相同 |
| `io` | 0 | 0 | 逐字节相同 |
| `access` | 0 | 0 | 逐字节相同 |
| `collections` | 0 | 0 | 逐字节相同 |

结论：十五类差异是文本与策略差，不是这些示例上的行为差。抽查不覆盖全部示例，也不构成行为等价判据。

## 宿主自身的非确定性

同一输入连发五次，宿主的 `.ll` 五次哈希各不相同；函数集合稳定（33 个），变的是顺序：
第 21 个函数在 `rotate_I32` 与 `any_I32` 之间摇摆，指向泛型实例表的字典遍历。自举侧三次发射哈希相同。

这一条直接改判据：**全文逐字节相同在宿主修复函数顺序之前不是可稳定判定的目标**——两侧还没比，
宿主自己两跑就不等。

## 结论

- 全文差的绝大多数不是格式，是发射策略：所有权约定（1,237 个函数）、槽与求值顺序（998）、
  指令选择（546）、分支跳板（846）。这四类都在 `backend-llvm` 的发射主体里，不在打印层。
- 命名与集合差（声明 3,322 条、函数 124 个、全局 200 个）可以靠两侧统一策略收掉，但要先裁定
  「以谁为准」：宿主的前导是全集，自举是按需，收口等于让一侧改成另一侧的哲学。
- 移植成本落在既有的 `llvm` 通道上，而不是新增一条通道。与 **C 头通道**、**JSON 通道** 相比，
  后两者只新增实现、不动既有通道；本条的收口面是一个能跑、能过门禁的既有发射器的重写。
- 因此通道面的次序应改：`llvm` 全文对照不当第一条。可先做 C 头与 JSON，或把 llvm 全文登记为
  保留差异，只保留「同输入两跑逐字节相同」（这一条自举已满足，宿主未满足）。

若仍要收口，最小可行子集按「先可对齐面、后语义策略」排：头部、前导、命名、顺序、缩进、
入口标签与环境箱这六类先做，它们不改产物行为；所有权、槽序、跳板、指令选择四类随后，
它们要动发射器的调度与调用约定，且必须先修宿主的函数顺序。

## 已知限制

- 规范化把串常量按首现重编号，串表编号差已单列成类，不在函数体残差里重复计。
- 「差行数」受函数排序影响，只作量级看：排序后 164,031 行落在差异块里，接近结构区全量。
- 输入是 65 个单文件示例；目录形态、bench 语料与全工作区不在本次面内。
- 行为抽查四例，不是全量；未抽查的示例仍可能有真行为差。
- 两侧都只测 release 构建；debug 构建的读数不具可比性。
