# 解释器接 C 变参与句柄

## 目标与边界

让解释通道能直接调用外部 C 函数，包括变参与字符串句柄两种形态，执行表七例由「保留差异」转「通过」。

边界：不改 C 头的翻译面（`pini bind` 已交付）；不改 `|c` 导出面。本件只补解释器侧的符号解析与调用 ABI。
真正的动态链接仍由 LLVM 通道承担，解释通道是进程内解析同一份映像。

## 缺口与读数

| 项 | 现状 | 取数入口 |
|---|---|---|
| 执行表七例 | 全部「保留差异」：外部调用只在 LLVM 通道成立，解释器不解析进程映像 | `tests/parity/execution-disposition.tsv` |
| `E5-019` | 变参只在 LLVM 通道可调用 | `tests/parity/diagnostics.tsv` |
| `E5-020` | 句柄只由运行时段持有 | 同上 |
| `E7-006` | 外部变参的通道提示，随执行线 | 同上 |
| `E7-007` | 外部函数用字符串句柄的通道提示 | 同上 |
| 解释器侧 | `foreignDataAddresses` 只覆盖数据符号，函数符号无解析路径 | `Sources/PiniHost/Interpreter/IRExecutor.swift` |

七例：`ffi`、`ffi-handle`、`ffi-handwritten`、`ffi-string-callback`、`ffi-varargs-handle`、
`ffi_generated`、`ffi_module`。

## 批次

### 一、函数符号解析

进程内取符号：`dlsym` 等价的运行时段入口，按 `[名称|foreign]` 登记的名字解析。解析不到要报
「符号缺失」而不是给空指针——空指针会让错误推迟到调用点，堆栈里看不出是谁没绑上。

判据：`ffi` 与 `ffi-handwritten` 两例在解释通道通过。

### 二、调用 ABI 与变参

按形参类型编组调用：标量直传、指针传槽地址、结构化参数按 C ABI 展开。变参要按 `va_list` 等价路径传入，
不能用定参数组冒充。

判据：`ffi-varargs-handle` 在解释通道通过；`E5-019`、`E7-006` 两条处置改「通过」后删行。

### 三、字符串句柄与回调

字符串句柄由运行时段持有：解释器不能把 Swift 字符串的内部缓冲交给 C。回调要把顶层自由函数包成 C 可调
函数指针。

判据：`ffi-handle`、`ffi-string-callback`、`ffi_generated`、`ffi_module` 四例通过；
`E5-020`、`E7-007` 处置改「通过」后删行。

## 风险与裁定

| 风险 | 处置 |
|---|---|
| 解释通道调 C 与 LLVM 通道结果不一致 | 同一夹具两侧输出逐字节比；不一致判红，不做「解释器可以宽松」的裁定 |
| 变参 ABI 在 arm64 与 x86_64 上不同 | 判据只在两种三元组各跑一次，读数分别记录，不互相替代 |
| 把 `&变量` 槽指针传给 C | 已由 `ptrArg` 拒绝；本件不改这条，槽指针没有真实地址 |
| 回调生命周期超出作用域 | 回调对象按运行时段持有，不随调用点释放；释放时机由调用方声明，不猜 |
