# Pini 自举终态架构与实施计划

## 目标与边界

目标是用当前语言实现一个新的 Pini 编译器，使它能够编译自身，并在连续自产之间达到确定性不动点。

代际口径：首代自产指用宿主编译出的第一份 Pini 编译器，次代自产指首代编译自身所得，三代自产
依此类推。下文只用这三个词指代具体产物。

下一代自产指自产编译器自己读 `build.pini`、出构建计划、装载计划登记的生成模块、发射，再由脚本
调外部 `clang` 链接，产出可运行的下一代。判据：自产 `build` 退出 0 且产物可运行；两代文本逐字节
相同；构建后 `git status --porcelain` 无新文件。浮点字面量与标准库装配属于「能编译真实用户程序」
的完整性项，不作下一代自产的门槛。

自举验收必须同时满足：

- 编译器源码全部由 Pini 书写；脚本只负责构建编排、进程调用与产物比较，不承载编译逻辑。
- 工作区、包清单、依赖图、源码装载、语法、语义、IR 和 LLVM 文本发射均由自举实现。
- 首代自产能编译完整工作区并得到次代自产，次代自产能够运行。
- 次代自产与三代自产对同一输入生成相同的确定性 LLVM 文本。
- 合法与非法语料均以语言参考、IR 契约和手写期望为判据，不以宿主输出代替规范。

下列事项不阻塞自举验收：

- 用 Pini 重写运行时。当前 `PiniRuntime` 继续经 C ABI 复用，运行时替换单独立项。
- 用 Pini 启动 `clang`。构建脚本负责调用外部 LLVM 工具，进程原语只在替换完整 CLI 时补。
- 让自举构建过程执行 `pini bind`：翻译器已由 `bind` 提供，自举构建仍只按计划消费生成物。
- 在自举侧求值手写块的 `|macro`。宏值要 C 预处理器，自举不启动 clang；求值结果随构建计划带出，没有计划条目的宏按能力缺口报出，不静默当成缺符号。
- 自举侧实现 `|c` 导出面与共享库产物。编译器自身不发布 C 面，语法层只保留解析，语义与发射等有消费方再立批次。
- 远程包下载、包仓库、LSP、调试器、REPL、embedded 后端和完整工具链替换。
- 为追求宿主 LLVM 文本一致而引入与规范无关的约定。

本地多包工作区、包可见性、外部符号的包级可见性和依赖构建不是可选扩展，而是本计划的编译器基础能力。

## 筹划载体

所有架构决定、实施批次、验收判据、风险和后续调整只在本件内维护，不另立专题计划件。各批次的实际代码、测试夹具、构建产物与验证日志属于交付证据，不属于新的筹划载体。

读数口径：件内的测试项数、耗时与吞吐数字都是易腐记录，只回答「当时差多少」，不承担长期参考价值。机器、构型或测试集一变，须整组重取，不拿旧数字补新差；需要长期基线时按 **解析吞吐与栈深** 的测量口径另立读数件，并同样标明易腐。实施批次的记录只记「做了什么、判据是什么、边界与教训」，逐批累计的读数已按此口径删去，只保留改变过判断的那几处量级；要读数时由 `driver lower` 与各门禁重取。

外部 C 互操作的语言面语义归 `docs/spec/pini-reference.md` 与 `docs/spec/c-interop-design.md`；本件只承载自举侧的批次、判据与风险。三个来源的分工、构建期生成、符号裁决与链接口径按这两份文件执行，本件不复述。

工作区奠基之后立即打通测试函数闭环。后续包不得等到功能完成后再补测试，统一按“先写失败测试、确认红、最小实现、确认绿、重构并复跑”的循环推进。

## 当前缺口

自举闭环已成立：十七个包全量检查、降载、发射零缺口，两代文本逐字节相同，全量测试由自产产物自己
跑通。构建脚本面三段（解析、计划落盘、生成模块装载）均已交付，`build` 能读 `build.pini`、出计划、
把计划登记的生成模块并入编译单元，计划另带宿主写入的宏与跳过两张结果表；
**宏常量的构建期求值与降级** 已交付，未求值的 `|macro` 只在读点报；外部声明发射与门禁接线
也已接通——次代跑同一套 `test-gate.sh`，生成模块夹具与三类定向诊断由此由自产产物执行，
两代计划文本逐字节相同。

标准库成员与函数两种形态均已交付：`pini-bootstrap/stdlib` 是独立源码包，驱动在工作区级装配一份，
默认开；装配源按路径升序、入口 `core.pini` 先，`algorithms.pini` 的泛型自由函数同批并入；编译器
自身构建带 `--no-stdlib`，不反向 import 它。泛型函数只做自由函数与调用点显式类型实参，按实参
单态化。浮点字面量已接通，取值走运行时的 strtod 口径，发射按宿主的常量文本口径出文本。

判据以「自产 `build` 退出 0、产物可运行、两代文本与计划文本相同」为准；增量缓存与工具演进不属这条线。

## 自举路线

各语言的自举路线按「种子、阶梯、版本窗口、门禁」四件事归纳如下。细节随版本变化，引用时以各项目
官方构建文档为准；本件只取对 Pini 有约束力的条规。

| 项目 | 种子 | 阶梯 | 版本窗口 | 可借的条规 |
|---|---|---|---|---|
| Rust | beta 预编译 rustc | stage0 → stage1 → stage2；stage3 验同结果 | 不用未进 beta 的特性 | 种子随版本滚动；stage3 只验同结果 |
| Go | Go N-2（取偶）工具链 | 一次替换，无中间语言 | N 需 N-2 取偶：1.20 需 1.17，1.24 需 1.22 | 版本窗口写成公式，写进文档 |
| Swift | Swift 工具链，主分支起必需 | level-0 编译器与库 → level-1 → 自编译 | 6.2 为最后一个可无 Swift 宿主自举的版本 | hosttools 快；bootstrap 不依赖宿主 |
| GHC | 用户安装的 GHC | stage0 → stage1 → stage2，stage3 冒烟 | 需 GHC N-1 | stage3 只作冒烟，不作交付 |
| Zig | C 编译器或预编译 Zig | `bootstrap.c` → zig2 → stage3 → stage4 | 依赖最近一次可用的自建编译器 | 无 LLVM 路径只需一个 C 编译器 |
| Nim | csources（C 版编译器） | C 源 → `bin/nim` → `koch boot` | 种子随版本重新生成（`koch csource`） | 种子可刷新，不冻死 |
| Roslyn | 上一版 C# 编译器 | 自建编译器再编自身 | 每次变更即验 | bootstrap 正确性进 CI，失败可诊断 |
| Crystal | 上一版 Crystal | stage0 → stage1 → stage2 | 同大版本 2 年或 8 个小版本 | 向前兼容窗口写进发布政策 |

据此取五条方针：

- **单一源码树**：编译器源码只有 `pini-bootstrap/` 一份，宿主只作种子，不维护第二套编译器。Pini 已满足。
- **固定种子矩阵**：宿主提交、运行时库构建配置、LLVM 与 clang、Unicode 数据、目标三元组逐项登记；
  改任一项即整组重取读数、重跑全量，不拿旧读数补新差。
- **代际阶梯与同结果**：首代 → 次代 → 三代，发射文本逐字节相同；每代跑同一套测试，报告逐字节相同。
- **版本窗口**：自产源码只使用「当前种子与上一代自产都认识」的构造；首个发布版起保留两代升级窗口。
- **变更即自举**：提交前三秒自检；合并前单包 bootstrap；发版前全量；种子变更后必跑全量。

不采纳两条路线：从 hex0 一类最小种子重建整条链，Pini 的信任根是 Swift 工具链与 release 运行时库，
重写宿主不在线内；另写一套独立实现做交叉校验，保留「宿主发射与首代发射逐字节相同」作弱化版即可，
它是同一语言的两个实现产同一文本，足以发现代码生成漂移，不足以对抗信任根被替换。

## 架构原则

- **先定终态，再切批次**：任何功能直接进入最终归属包，不先放进总包再迁移。
- **包边界由编译器执行**：公开接口、包可见性和依赖方向必须由构建系统检查，不靠命名习惯或审查记忆。
- **接口与实现分离**：跨包只暴露值、类型、函数和错误契约；内部数据结构、遍历顺序和发射细节不得泄漏。
- **单向依赖**：基础包不认识编译器，语义不认识后端，后端不反向读取 AST，驱动是唯一编译器装配点。
- **无空壳包**：尚未实现的功能不建立占位 API；创建包时必须交付真实能力和测试，但目录规划从第一批就固定。
- **生成物即构建产物**：翻译结果落构建目录并由计划登记；源码树不出现生成文件，装载面只认计划里的路径。
- **中间形态不改终态边界**：早期可以整图一次性构建，后期再改增量构建；两种形态都使用同一包结构和公开接口。

根 `pini.toml` 是工作区清单，不是把全部源码装在一起的包清单。它登记成员包、构建 profile、共享 LLVM 与运行时配置，以及测试目标。工作区语法是待实现的构建能力，实施时先进入构建规范，不能由脚本私下解释一套未登记格式。

### 包内统一形态

每个生产包使用同一结构：

```text
packages/<包名>/
  pini.toml
  src/
    api/
    _internal/
  tests/
```

- `api/` 是包间契约，只放公开类型、公开入口和导出声明。
- `_internal/` 是包内实现，其他包不可见；包内测试可以贴近实现，跨包测试只准走 `api/`。
- `tests/` 是测试 target，不进入普通库产物。工作区需要明确库、可执行文件和测试三类 target，不能用排除目录的临时技巧代替。
- 包清单显式列出本地依赖；未声明依赖的包即使源码可见，也不得被引用。

### 各包职责与允许依赖

| 包 | 职责 | 允许依赖 |
|---|---|---|
| `support` | 字节缓冲、切片、源码文本、区间、符号驻留、确定性容器、通用结果与错误 | 无包内依赖，只依赖语言与运行时基础 |
| `unicode` | UTF-8、标量分类、NFC、混淆骨架、Unicode 数据表 | `support` |
| `diagnostics` | 诊断码、严重级、源码位置、标签、修复建议、渲染 | `support` |
| `syntax` | 记号、AST、词法、语法、源码打印所需的语法信息 | `support`、`unicode`、`diagnostics` |
| `semantics` | 作用域、符号、类型、声明注册、可见性、外部符号裁决、类型检查、类型布局 | `support`、`unicode`、`syntax`、`module-loader` |
| `ir` | IR 节点、降载、份额、布局消费、外部符号节点、结构校验 | `support`、`syntax`、`semantics`、`module-loader`、`unicode` |
| `backend-kit` | 后端接口、能力声明、目标描述、发射结果与后端注册接缝 | `semantics`、`ir` |
| `backend-llvm` | LLVM 类型映射、文本发射、复制与释放胶水、外部符号发射、目标产物 | `semantics`、`unicode`、`ir`、`backend-kit` |
| `backend-dump` | 结构转储后端，只读模块、按固定节序出文本，作模块自足的见证 | `semantics`、`ir`、`backend-kit` |
| `runtime-api` | 运行时段符号、C ABI 声明、句柄与桥接能力清单 | 无包内依赖，只依赖语言与运行时段符号 |
| `package` | 工作区与包清单、`[ffi]` 库绑定与头文件集合、target、依赖图、构建脚本步骤与计划、拓扑排序、产物身份 | `unicode`、`syntax` |
| `module-loader` | 从构建计划读取源码（含计划登记的生成模块）、规范化和解析，形成语法层编译单元 | `unicode`、`diagnostics`、`syntax`、`package` |
| `hostproc` | 进程族封装与工具链定位，编译命令调外部工具的唯一点 | 无包内依赖，只依赖语言与运行时段符号 |
| `driver` | 编译器库入口与 CLI，装配装载、检查、降载、测试执行、后端和输出 | 上述编译链各包、`hostproc` 与 `testkit`，禁止反向被依赖 |
| `testkit` | 测试发现、筛选、顺序、执行器接口、结果报告、夹具协议与确定性乱序测试 | `support`、`ir` |

依赖图必须保持无环。`package` 只为取构建脚本写法读语法树，不建符号表也不做类型检查，`module-loader` 不做类型检查，`semantics` 不读文件，`ir` 不调用 LLVM，`backend-llvm` 不解析源码，`driver` 不拥有各层内部规则。

依赖列即当前允许集，增删依赖与改本表同批。三处与真实调用路径不一致，登记为待收窄：
`semantics` 只从 `module-loader` 取编译单元与包模型类型，其清单仍声明 `package`，这条由无调用点的
`registerWorkspace` 带入；`backend-kit` 声明 `semantics` 而源码未取其中任何符号；`runtime-api`
没有入边，运行时段符号名仍由 `backend-llvm` 自带，接线后它才进依赖图。

### 标准库、工具与测试的位置

- `pini-bootstrap/stdlib/` 是独立源码包，由驱动按语言规则装配到用户模块；编译器各包不得通过反向 import 获取它。
- `tooling/formatter` 只依赖 `syntax`、`support`、`diagnostics`，不得为了复用 CLI 而依赖 `driver`。
- `tooling/language-server` 可以依赖 `syntax`、`semantics`、`module-loader`，不得依赖 LLVM。
- `tooling/debugger` 通过独立调试接缝消费源码映射，不进入编译主依赖链。
- `runtime/abi/` 保存 C 侧契约与链接元数据；Pini 侧声明只归 `runtime-api`，避免两套符号清单漂移。
- `tests/architecture/` 检查包依赖、公开接口和禁止引用。
- `tests/integration/` 覆盖多包构建、缓存、增量重编和诊断。
- `tests/conformance/` 保存语言正负语料与手写期望。
- `tests/selfhost/` 保存自洽、不动点和确定性验证协议。
- `tools/` 只保存构建与测试编排，不放任何生产编译逻辑。

新增后端只新增实现 `backend-kit` 的包，并在驱动注册；不得把目标判断散落到 IR 或语义层。新增工具只进入 `tooling/`，不得把命令实现堆回 `driver`。

## 工作区与构建契约

### 包接口产物

每个库包在逻辑上生成三类产物：

- **导出接口**：公开声明名、函数签名（参数名与类型、返回类型）、类型布局所需信息、依赖声明与包名。泛型实例化所需语义信息随类型面补面接入，依赖版本待包版本模型落地。
- **编译产物**：供链接或整图发射使用的 IR 与目标产物。
- **构建身份**：包源码、构建脚本与生成物、公开接口、依赖接口、语言配置和后端配置的内容摘要。

公开接口变化必须使下游失效；仅 `_internal/` 变化时不得要求下游重解析或重检查。早期尚未实现增量缓存时也必须按同一身份规则判断哪些步骤需要执行，不能靠时间戳猜测正确性。

第一批只落记录与判据：接口文本逐包写成 `.build/<profile>/packages/<包>/interface.api.txt`，工作区记录写成 `<根>/.build/<profile>/interfaces.toml`，记录按包名排序、只存摘要与根相对路径。第二批把记录升为构建身份：接口条目多记本包源码摘要，产物条目多记输入指纹；`interfaces` 与 `emit --packages` 按拓扑序逐包比摘要，命中就不重算公开面、不重发 IR。公开面变化只波及直接下游，接口文本未变则再下一层复用。跳过重解析与重检查的实际调度仍留给后续批次。

第三批把同一套身份规则接到宿主：宿主 `build` 写 `interfaces.host.toml`（与自产记录同形、文件名区分、`path` 指向 `interface.txt`），宿主 `check` 认工作区根并按记录判 E3-021；两侧记录不互读。接口文本各自形态，逐字节对齐留待类型面进入接口文本。

第四批把并行与远程缓存放在语言外的两层：`plan --waves` 按依赖深度出波次，外部步骤逐波并行调 `emit --packages --package=<包>`；`emit` 另收 `--cache-dir=<目录>`，按输入指纹读写 `<目录>/<指纹>/<包>.ll`，目录可挂网络盘或随流水线搬迁，跨机器复用因此不需要新协议。语言层没有进程与网络内建，驱动不做调度，这一批只把「按内容复用」做成可搬迁的目录。

### 构建形态演进

- 初期允许工作区整图装载、整图检查、整图发射，但包间仍只能读取导出接口。
- 随后增加按拓扑序的包产物和接口缓存，不改变包目录、调用方或依赖声明。
- 最后增加并行构建与远程缓存；它们都不属于自举验收前置。
- 终态：宿主发起的 `build` 仍是整图构建，自产 `build` 只出计划与指纹，翻译归外部步骤，发射归
  `emit`，链接归脚本；计划是构建形态的接口，根相对、无时间戳、跨机器逐字节相同。
- 任何阶段都禁止跨包读取 `_internal/`，禁止通过“先把源码并入同包”绕过可见性。

### 构建脚本与生成模块

`build.pini` 是声明文件，不是可执行脚本：每个 `[名称|given]` 块读成一条翻译步，块名即步骤名，字段固定为 头文件、包含路径与定义。声明式不是风格取舍，是“配置纯净”的现成形态——语言还没有计划对象的构造面，执行式配置要先补一个配置期内置与语义入口。

构建分两段：配置期只登记并产出计划，执行期才翻译、发射、链接。

- 计划是纯数据：`<根>/.build/<profile>/plan.toml` 记包根、脚本哈希、每条步骤的头文件与产物路径、输入指纹，以及两张结果表——`[[macro]]` 记包、名、状态与值或未求值理由，`[[skip]]` 记生成面跳过的宏与理由。
- 生成物落 `<根>/.build/<profile>/packages/<包>/generated/<步骤名>.pini`，归声明它的包；步骤名须是合法的路径分量且在包内唯一。
- 单一装载入口：计划缺失、脚本哈希不符、产物缺失各报一条指向 `pini build` 的诊断，不静默跳过。
- 路径白名单：只接受以 `.build` 组件开头且登记在计划里的产物路径，其余一律拒绝。
- 确定性：同一输入两次构建的计划与生成物逐字节相同；指纹含头文件与整棵包含树、包含路径、宏定义、翻译器版本与目标平台。
- 跨包共用同一头文件时各翻一份：正确性不受影响，多花的是翻译时间；去重的前提是落点与包名解耦。

注意 计划是数据不是代码：`check`、`run`、`test` 只读计划，绝不执行 `build.pini`。脚本写坏只影响 `build`，不会让整个仓库的检查一起红。

### 架构硬门

工作区构建器直接依据依赖图执行以下判据：

- 未声明依赖、反向依赖、跨包内部引用、循环依赖均为构建错误。
- 包公开接口与导出接口产物必须一致，接口变化必须触发对应下游重建。
- 同一包不能同时以源码路径和另一种包身份进入同一张图。
- 构建、测试和自举三代链共用同一依赖图，不允许脚本另排一套包顺序。
- 生成物路径越出 `.build` 前缀，或未登记在计划里，均为装载错误；构建只写构建目录，不写源码树。

## 文本模型

采用**字节编译内核**，严格分开三个文本域：

| 文本域 | 用途 | 禁止事项 |
|---|---|---|
| UTF-8 字节 | 源码保存、ASCII 记号、关键字、区间、LLVM 文本 | 不得把字节下标当用户字符下标 |
| Unicode 标量 | UTF-8 校验、标识符分类、转义解码、规范化 | 不得把标量序号当字节偏移 |
| 字素簇 | 现有用户层 `Char` 与 `String` 行为 | 不得用于词法游标和源区间 |

核心类型按最终包归属：

- `support.ByteBuffer`：持有完整 UTF-8 字节，不支持隐式字素解释。
- `support.ByteSlice`：保存缓冲区身份、起点和长度，切片不复制。
- `support.SourceText`：持有规范化后的源码、文件名和逐行起点表；`Span` 一律是字节区间。
- `support.ByteBuilder`：线性追加 ASCII 与 UTF-8 字节，供诊断和 LLVM 发射使用。
- `unicode.UnicodeText`：包装需要标量分类或规范化的小段文本，不进入扫描热路径。

当前语言只需补两类内部桥接能力：把 `String` 的完整 UTF-8 内容复制成字节数组，以及把字节数组经 UTF-8 校验后组成 `String`。桥接经现有 C ABI 运行时实现并登记到 `docs/spec/runtime-abi.md`，不暴露指针算术，不改变用户层字符串语义。

词法器不得使用 `split`、`replace` 或字素下标扫描源码。标识符和字面量先记字节区间，确实需要内容时才切片；记号默认携带 `Span` 与符号编号，不携带整段复制文本。

## 标识符身份与混淆

采用**原始拼写保留、规范化负责身份、混淆分析负责诊断**的三轨模型：

- 原始拼写永远保留在 AST、符号声明和诊断中，不改写用户源码。
- 符号查找键使用 NFC 规范化结果；同一作用域内，原始拼写不同但 NFC 相同的声明按同一符号冲突处理。
- 规范化只在标识符上进行，不规范化整个源文件，字符串字面量和注释内容不受影响。
- Unicode 版本必须固定，字符类别、规范化与混淆表由受控数据生成 Pini 表并纳入版本控制；构建和运行不得依赖宿主操作系统的 Unicode 版本。
- 混淆骨架只用于安全诊断，绝不用于符号查找，避免把视觉相似误当成语言等价。

混淆策略不按“非 ASCII 一律危险”处理，中文标识符仍是正式能力：

- 对拉丁、西里尔、希腊等高风险混写给出错误；常用脚本与中文的合理组合不因混写这一因素被拒。
- 对同作用域内混淆骨架相同的标识符给出警告，并同时展示原始拼写和转义后的码点序列。
- 全角字母数字、数学字母数字、兼容等价拼写至少给出警告；是否提升为错误由语料门禁验证后固定。
- 标识符中的零宽字符、双向控制字符和不可见格式字符直接拒绝；注释与字符串中的双向控制字符给出明确警告。
- 无效 UTF-8、BOM 和 NUL 在装载期响亮拒绝。CRLF 归一化发生在词法之前，所有区间统一指向归一化后的 `SourceText`。

NFC 会改变符号身份，属于语言面决定。实施前先修订 `docs/spec/pini-reference.md`，宿主和自举同批对齐；若暂不采纳 NFC，则只能把规范等价冲突降为警告，不能暗中在自举符号表里做另一种查找语义。

## 受限源码约定

受限只约束编译器自身的写法，不压缩终态包结构，也不缩小编译器最终必须接受的用户语言：

- 使用结构体、枚举、数组、字典、函数、`match`、循环、`Result` 和显式类型标注。
- 泛型只保留容器与必要算法所需形式，避免把高阶类型推断扩散到编译器源码。
- 不使用结构化并发、`LazyRef`、弱引用与无主引用；外部声明只收标量、指针、`String` 形参与 `StringHandle`，不碰按值聚合。
- 本地多包、公开接口和包可见性属于必用能力，不得列入“以后再支持”。
- 公共声明显式写参数与返回类型，不依赖宿主推断细节。
- 不用字典遍历顺序决定输出。文件、声明、符号、诊断、类型布局和 LLVM 定义都显式排序。
- 不用宿主字符串优化、文件系统顺序或哈希种子作为正确性的前提。

用户语言覆盖按规范逐项回填，并为每个新增构造补正负语料。

## 实施批次

已交付批次按「交付 / 判据 / 边界」三段记；尚未开工的批次另标「待办」，保留完整计划。已交付部分
按主题归并：前端的各面记在 **语法包贯通** 至 **装配面**，后端的各面记在 **契约与节点池** 至
**自举闭环与验收**；未开工的完整性项与自产门禁收在 **下一代自产**。

### 工作区奠基

清单模型收 `[workspace]`、`[lib]`、`[[bin]]`、`[[test]]`，`WorkspaceBuilder` 统一出依赖图、拓扑计划、target 源码集与产物路径。`pini-bootstrap/` 立三包，多文件 import 与嵌套 `_internal` 可见性按祖先目录算，测试 target 与生产源码隔离；门禁覆盖拓扑序与真实产物执行。

判据：两个库包加一个可执行包按拓扑序构建，跨包公开调用成功；未声明依赖、内部引用、循环依赖与接口漂移均被拒绝；测试源码与非法夹具不进入普通库产物。

边界：仍是整图降载与链接，独立库链接、接口缓存与 `|test` 执行闭环留后续批次。

### 测试函数闭环

目标是在大规模实现语言特性之前，用一条最小但完整的垂直链路打通测试函数：`|test` 声明进 `syntax`、`semantics`、`ir` 与 `backend-llvm`，`testkit` 管发现、筛选、确定性顺序、执行器接口与结果报告，`driver` 提供最小入口并复用同一工作区依赖图，不为测试另排构建顺序。

后续各包统一按下列循环推进：

```text
写公开行为测试 → 运行并确认失败 → 最小实现 → 运行并确认通过 → 重构 → 全量复跑
```

跨包行为只准通过公开 API 测试，修复缺陷先补能复现的失败测试，增加能力先写判别式与至少一条反例。

判据：一个通过用例、一个失败用例与一个多测试文件验证发现顺序、报告、失败后继续执行与退出状态；撤掉断言失败处理或测试注册时门禁必须转红；筛选、乱序与重复运行不改变结果，三条输出通道均有手写期望。

边界：收不到 `|test` 与筛选零命中一律非零退出；测试体以工作区根为进程目录，`moduleRoot()` 仍答所属包根；工作区级原生聚合未接线，TDD 循环暂由解释器通道承担。

### 基础包落地

`support` 出 `ByteBuffer`、`ByteSlice`、`ByteBuilder`、`SourceText` 与 `StringTable`，覆盖字节缓冲、无拷贝切片、源行表、字节构建器与符号首次出现定序；同批修 LLVM 的 U8/I8/I64/U64 数组元素 ABI、U8 打印零扩展与无符号谓词，注释与格式门禁的扫描根加入 `bootstrap`。

`unicode` 固定 Unicode 15.1.0：解码六类错误保留出错前的标量、编码往返一致，分类表按分段判定字母、数字与空白，规范化与混淆骨架用「池 + 打包下标」；同批修三个宿主缺口（隐式导入只注名字、泛型数组元素类型、数组 ABI），词法转义改按簇首标量识别，修掉 `\t` 后接组合符被粘成一簇的缺陷。

`diagnostics` 出五个类型与 99 条码表，位置映射按 Unicode 标量计列，落在多字节中间时回退到标量起点；确定性由文件、锚点起终点、码、消息逐级比较保证；同批修宿主「成员访问只对 identifier 接收者递归」的缺陷，`f(x).字段` 的实参不再逃过检查。

判据：覆盖 ASCII、中文、组合字符、全角、数学字母、高风险混写、零宽字符、双向控制、非法 UTF-8、BOM、NUL 与 CRLF；每个扫描例核对消费字节数，不允许结果正确但游标错位；三个包都能独立构建和测试，不 import 任何上层编译器包。

边界：`as` 未实现，字节换算由 `temp` 前缀临时内建承担，正式字节文本面落地时整组移除。

### 语法包贯通

`syntax` 分记号、关键字、词法、AST、解析五面：词法按字节推进，缩进栈只在行首比较，括号内抑制换行；AST 用四个节点池加子节点下标，字段稳定，不依赖反射或动态分派。类别判定一律比类别码，不比枚举相等；语法诊断继承码表。

判据：合法夹具得到预期结构，非法夹具得到预期诊断码与源码位置；畸形输入必须终止，未闭合插值、缩进错乱与括号失衡均有超时判据；`syntax` 测试不依赖语义、IR 与驱动。

边界：自解析用例读本包五个源文件并核对零诊断；插值段与控制流糖留待补面。

### 语义与装载分工

语义与装载两层从零建立，按能力拆九个直接落入终态包的子批次：标识符身份、清单面、装载面、注册面、类型面、表达式面、语句面、布局面、装配面。依赖顺序为标识符身份 → 清单面 → 装载面 → 注册面 → 类型面 → 表达式面与语句面（共用类型池与作用域链）→ 布局面（与类型面可并行）→ 装配面。每个子批次先写公开行为测试、确认红，再最小实现。

判据纪律：只认语言参考、IR 契约与手写期望；宿主输出可用于定位差异，不作门禁判据。

决定：查找键归语义层（`support` 只存原始拼写，NFC 键由语义层以字节序列自持）；类型判定归语义层（语义产出类型表与解析表，IR 只映射类型池下标，不重跑检查规则）；构建身份先用结构化文本（摘要算法留给增量批次）；布局以槽为单位（字节尺寸、对齐与偏移归 `backend-kit` 目标描述）。

#### 标识符身份

参考件补符号身份五段：查找键取 NFC，原始拼写全程保留在语法树、声明与诊断里，混淆骨架只用于诊断、不参与查找；全角与数学字母、兼容等价拼写至少告警；零宽、双向控制与不可见格式字符在标识符位拒绝、在注释与字符串位只告警。宿主与自举同批改为 NFC 键，共用一份正负语料；词法增三条错码，零宽、双向控制、起始 BOM 与簇内变体选择符一律拒绝，Unicode 数据门禁改为比对登记摘要。

判据：同一作用域内 NFC 与 NFD 两种写法按同一符号冲突处理且都显示原始拼写；中文标识符、组合字符、全角与数学字母的判定与规范一致；骨架相同的标识符只告警，不触发查找失败；组合附加符号可作续字符、不得作首字符。

边界：自举侧的字符串告警只覆盖字面段；续字符只认四个组合标记区块，混写只认拉丁、西里尔与希腊三个脚本。

#### 清单面

`package` 拆 `toml`、`manifest`、`build_script`、`plan` 四层；清单按平表、点分子表、数组表、内联数组与引号感知注释收集，形状非法即报清单错误，不静默取默认值。工作区、包与 target 三个模型，成员、包名、target 名与入口的校验在生成计划之前完成。拓扑序按包名升序深度优先，依赖同样升序，用具名帧而非递归，成环报完整链条。

判据：自举工作区根清单解析出全部成员与固定拓扑序，重复执行逐字相同；重复包名、越界成员、非法入口、重名 target、成环依赖各报专用错误并带具体包名与 target 名；构建计划按包给出 target、源码集与三类产物路径。

同时修宿主 `IRType.typeAnnotation` 对名义类型返 nil 导致局部类型串味的缺陷。

边界：符号链接与 `[resources]` 等字段留后续。

#### 装载面

`module-loader` 从构建计划取 target 源码集：递归扫描，点前缀目录整棵跳过，嵌套清单下的源码不进父包，清单声明的排除项按前缀判；按 UTF-8 字节序读取后去重排序，结果与文件系统返回顺序无关。装载期一次性规范化：非法 UTF-8、起始 BOM 与 NUL 直接拒绝，CRLF 归一为 LF，此后所有区间指向同一份源文本。

判据：同一 target 换文件系统顺序，诊断序列与树结构逐字相同；七类装载错误各有类别名，位置指向出错字节；装载只读源文本与语法树，不 import 语义、IR 与驱动。

源文本判定走字节步进，BOM、逐标量合法性与 NUL 一次判完，不用字符串层判 NUL。

边界：全量解析基线超出 CI 时间预算，未完成，判据分层见 **解析吞吐与栈深**。

#### 注册面

语义包建符号表与作用域栈，名字经 NFC 键驻留，符号记种类、可见性与定义位置；结构、对象、枚举、扩展、函数与测试、变量、导入块与导入项、字段、参数、变体各类声明各自注册。可见性按 `_` 前缀在符号、文件名、目录链三级收紧，包级索引据此回答跨文件可见性。

判据：自举既有包注册零错误；换文件顺序后符号表内容与冲突诊断的排列逐字相同；重声明、类型成员同名、别名相撞、跨文件重名各报专用错误，位置指向声明头；`_` 前缀在三个层级上的收紧效果各自可判。

同时修 `Ast.items` 漏收类型与导入块、`loadPackage` 按 target 合并两处缺陷。

边界：扩展块同名按后声明者覆盖；枚举项与顶层同处一个名字空间的边界留到类型面。

#### 类型面

类型池按形状驻留，下标相等即类型相等；标量、指针、结构、对象、枚举、元组、集合、可选、结果、函数与泛型实例各成一类，递归结构用下标表达。六类标注（具名、泛型实参、可选、指针、元组、函数）按节点类别分流，具名类型按声明类别分结构、对象与枚举。等价按结构逐位，可赋值只放行同族拓宽、字符与字符串的成对关系与单向包装；字段环分自引用与成环两类。

判据：标注语料的规范化文本与手写期望逐字相同；等价与可赋值的正负表逐条通过，反向用例必须为假；泛型实参个数与约束不匹配报专用错误；递归类型、自引用结构与未声明类型各自报专用错误；规范化文本在两次不同遍历顺序下相同。

边界：用户泛型实例按显式实参单态化，符号名为函数名加实参拼写，重复实参只发一次；约束求解与实参推断未进解析面；`[T,]`、`{K: V,}`、`{T,}` 与 `^T` 的类型语法未进解析面；编译器源码只用容器的泛型实参。

#### 表达式面

覆盖全部表达式节点：字面量、插值、标识符、成员、下标、切片、调用（含具名实参与默认值）、一元、二元、元组、数组、字典、集合、真值、空值、函数字面量与前置点用例；匹配模式、分支绑定与穷尽性同批。产出名字解析表与表达式类型表，按单元与节点下标对齐，供降载直接消费；语法形状助手（`if` 臂、`match` 臂、调用实参的只读访问器）进 `syntax`，语义层不按子节点奇偶猜结构。

子批次按依赖顺序：作用域链（函数、块、循环与匹配臂四类帧，参数、自身、局部、循环变量与模式绑定五类局部，槽位在函数内单调）；解析表（建一次、检查期二分，覆盖完整且无悬空）；字面量判定（期望传播到标注、实参、返回与容器元素，整数缺省 `I32`、浮点 `F64`、`nil` 必须有望）；成员判定（字段、自身方法、本型方法、元组序号与标签、枚举项、`Array`、`String` 与 `Dictionary` 内建成员）；调用判定（位置与标签实参、默认值、函数值间接调用、内建签名表）；运算判定（一元、二元、短路、比较与位运算，数值提升，`Char` 到 `String`）；容器与索引（元素统一、下标读、切片开放边界与 `len`）；匹配模式（枚举、可选与裸值，绑定作用域与穷尽性）；字面量补面（函数字面量的参数作用域、返回类型与捕获表）；吞吐基线（`checkExpr` 在 `syntax` 包上记录单遍耗时与峰值内存）。

判据：正负语料逐条通过，诊断码与标签区间与手写期望一致；解析表与类型表覆盖完整，每个标识符、成员与调用目标恰一条记录且指向真实声明，不留 `-1` 空洞；全表达式语料在 `syntax`、`support` 与 `semantics` 三个真实包上零诊断；同一输入两次检查的解析表与类型表逐字节相同。

注意 标签实参在语法树里复用二元节点加名字区间，必须按父节点识别，不进入二元判定。

边界：多处宿主偏宽（`len(1)`、`a[1.5]`、`!1`、集合下标）按参考件收紧；`writeResolve` 原地写入，调用方须按唯一所有权使用。

#### 语句面

覆盖函数体、变量与解构、赋值与十一类复合赋值、条件、循环与 `step`、遍历、匹配、返回、跳出、继续、通过、延迟；语句层作用域、循环变量与模式绑定的生命周期同批。函数帧由声明播种，标注作期望起点，条件按 `Bool` 判，臂帧逐位绑定。语句检查复用表达式面的解析表与作用域链，不另建一套名字解析。

判据：正负语料逐条通过，控制流诊断位置指向关键字或条件；跳出与继续在循环外、返回在函数外各报专用错误；同块重复声明被拒、跨块遮蔽放行；函数体缺失返回路径报专用错误。

边界：复合条件读不到类型即放过；参考件的双字段遍历与 IR 契约不符，按契约与宿主实现走；错误码沿用既有条目、不加新码，成员与下标目标的类型由调用方写入。

#### 布局面

形态表按池序取名义类型成形：结构、对象取字段，枚举取用例与载荷，条目恒按类型下标升序；槽布局以纯函数折叠，字段从第 4 槽起。对象头四格、`Result` 三槽、`Optional` 两槽，语义层不出现尺寸、对齐与偏移。

判据：布局表对既有包的手写期望逐项相同，含空结构、单字段、嵌套结构与两用例枚举；字段顺序变化必须改变布局；同一输入两次布局逐项相同；语义层源码不出现字节尺寸、对齐或字节偏移的字面量与计算。

边界：形态表只收顶层名义类型，泛型实例与内嵌组合待补面；位置载荷的形参不绑类型，布局里那一格留 -1。

#### 装配面

导出接口文本由公开声明名、函数签名与槽布局合成，接口变化使下游失效；跨包可见性按「目标包 + 名字」查，`api/` 内公开声明可跨包引用，`_internal/` 一律不可见，未声明的依赖即使源码可见也拒绝。驱动把清单、装载、注册、类型与检查按同一张包图串成 `checkWorkspace` 的检查装配，诊断统一排序后渲染。

判据：抽样工作区（两库包加一可执行包）零诊断、退出码为零；跨包公开调用成功，目标包无名、跨包遮蔽与各级收紧各有正负语料；换包图顺序诊断序列逐字相同；删除内部实现后接口文本不变，改签名、槽数或字段序即变。

测试接线：`semantics` 与 `module-loader` 的原生测试随各自子批次进入 CI，与既有六个包的门禁同形。

边界：检查入口在自举产物里跑不动全工作区，端到端归吞吐批次；接口文本未落盘，漂移判定由调用方带记录进来；`package` 的测试待原生通道补齐文件读取后接入，不用跳过冒充通过。

### 语言面：调用点实参标签

形参名在声明点写一次、在调用点写多次，故标签与否只在声明点决定：形参名不带头者，调用点必须写标签；`_名` 退出标签面，按位置传，`_` 仍是名字的一部分。自由函数、方法与特征同规；内建、外部函数、枚举构造与函数值调用豁免；跨包限定调用随接口产物接入。缺标签 `E4-036`、退面形参收到标签 `E4-037`、重复标签 `E4-038`，宿主与自举同码同义。

判据：八个包、三个示例包与既有示例、bench 语料在严格检查下归零；宿主全量、工作区解释器通道、语义与语法两通道全绿，门禁不缩水；不设过渡开关，`check`、`test`、`build` 同一判据。

边界：迁移为约五百处单形参声明补 `_`、约九千五百处调用点补标签；跨包限定调用当时不判，等接口文本；宿主参数默认值未实现。

### 语法补面

语法树的缺口不并入其他批次的检查面，单列本批，并前移到 **装配面** 收尾之前：后续各层都指望「工作区级零诊断」作基线，缺口存在时这条判据只能抽样；补面之后判据面才完整，全量执行仍受吞吐批次约束。

现况按词法与语法两处实物核对后可钉成一句：宿主已实现的构造远多于自举。特征声明与特征体、导出块、给定块、外部块、结构泛型头、内嵌组合、`实现` 行、`try` 表达式、`unsafe` 前缀、`unroll` 展开器、标签控制流、插值段子表达式、`=>` 箭头，以及 `[T,]`、`{T,}`、`{K: V,}`、`^T`、`?T` 五类类型写法，宿主侧都有对应物；`as` 转换的五层实现也在宿主侧贯通。故本批全部是追平宿主，判据可以拿宿主做结构对照，两侧都缺的构造为零。

依据可逐条复核：自举关键字表按当前词表收满，解析器只按类别引用其中一部分；未按类别分派的词里，
`try`、`await`、`wait`、`unsafe`、`detach`、`capture`、`unroll`、`export` 是缺口，`enum` 与 `object` 只在修饰符位按标识符文本比对，不按类别分派。宿主侧定义在 `Sources/PiniSyntax` 的关键字表与 `Parser.swift` 的四个解析函数，自举侧在 `pini-bootstrap/packages/syntax/src/api` 的四个类别池与解析器引用集。

交付覆盖：转换（`as` 中缀、目标类型解析、与数值提升的分工）、类型写法（五类类型位写法与行首声明分派互不干扰）、错误处理（`try` 的语句位单行、语句位块与表达式位三形态，`^右值` 脱糖为 `try 右值 else err: return err`）、声明块（特征声明与特征体、特征扩展、导出块、给定块、外部块与三个符号修饰）、声明头（类型参数的声明位置、内嵌组合行、`实现` 行）、语句（标签控制流、`capture`、`unroll`、`defer` 相邻单行）、前缀（`unsafe` 表达式）、异步（`=>` 声明与函数字面量、`await` / `wait` 前缀、`detach` 语句）、字面（插值段内子表达式、字典条目类型位 `{键: 类型 = 值,}`）。

子批次顺序：转换面、类型写法面、错误处理面、声明块面、声明头面、语句补面、异步面、字面补面。`^` 在类型位是结果糖、在右值位是解包糖，两条判据必须同批；声明块五类共用一张块头分派表，一次改完再逐类落语料；声明头三处都改声明体的读取循环，合并以免三次改同一段；异步面列末位，不阻塞自举，也允许单独切出。

判据：正负语料逐条通过，诊断码与标签区间按手写期望；差分语料只比语法树结构与区间，不比诊断措辞；每条新增构造由同一份语料同时驱动宿主与自举，任一侧缺失即判失败；未进本批的构造仍在解析期报语法错误并至少前进一条记号。

决定：追平不重裁（宿主已有构造按实现追平，发现与规范不一致时登记差异，差异本身不改本批范围）；`as` 以规范为判据，条款没写的部分就地补写，结论进规范；「一次返回多个值」归 **降载面**，「跨包引用限定枚举值」与「跨包同名顶层函数」归 **装配面**。

边界：`syntax` 原生通道的自解析跑不完，归吞吐批次；字典条目的类型标注只进语法树，判型待接线。

### 外部面

宿主已把 C 互操作做成生成、手写、封装三个来源，三条汇成一张包级符号表，库绑定退到 `[ffi].libs`，块名只是标签。自举侧补齐同一形态。

交付覆盖：`[名称|foreign]` 块（条目只有一形 `名{|标志}: 类型`，标志为 `readonly`、`macro`、`varargs`；块内函数自动 `unsafe`，块名不参与查找、重名不构成冲突）；`[ffi]` 六字段（`abi`、`search_paths`、`libs`、`headers`、`include_paths`、`defines`，`libs` 与 `search_paths` 进构建计划）；包级外部符号表（一处声明处处可用，声明处一次裁决：同名同型合并、异型报错、与本地符号或导出名同名报错）；判型（类型白名单、回调只收顶层自由函数、变参固定前缀与尾实参提升、`String` 借出、`StringHandle` 与 `fromCString` 取回、数据符号读写与 `readonly` 拒写）；解析顺序（运行时 shim、`[ffi].libs` 预加载、进程映像三层，未命中在注册期报错）；`runtime-api` 建包，按 `docs/spec/runtime-abi.md` 逐条声明可经外部块可达的符号。

子批次按依赖顺序：清单字段、块与条目、符号裁决、判型面、运行时段包、解析顺序。

判据：`runtime-api` 在自举工作区零诊断；同名同型合并、同名异型、与本地符号或导出名同名、非 C 名各有负例，位置指向第二次声明并带首次声明文件；`pini bind` 的生成文本原样进自举解析零诊断；同一语料在两侧得到同一组符号与同一张计划文本；解析顺序三层各有判据。

边界：调用点判型随 **装配面** 接线；手写 `|macro` 求值归构建期，见 **宏常量的构建期求值与降级**；`StringHandle` 与变参只在 LLVM 通道成立。

### 构建脚本面

`build.pini` 只声明翻译步，不执行构建：`[名称|given]` 块读成一条翻译步，块名即步骤名，字段固定为头文件、包含路径与定义。声明式不是风格取舍：语言还没有计划对象的构造面，执行式配置要先补一个配置期内置与语义入口。块体走语法包的树，不另写一套文本扫描——同一份语法两处实现必然分叉。配置期只登记并产出计划，执行期才翻译、发射、链接。计划是纯数据，落 `<根>/.build/<profile>/plan.toml`，记包根、脚本哈希、每条步骤的头文件与产物路径、输入指纹，以及宿主写入的两张结果表；生成物落 `generated/<步骤名>.pini`，归声明它的包，步骤名须是合法路径分量且在包内唯一；源码树不出现生成文件。

注意 计划是数据不是代码：`check`、`run`、`test` 只读计划，绝不执行 `build.pini`。

交付：`package` 读给定块成步骤，计划带根相对产物路径，`plan` 打印、`build` 补输入指纹并落
`plan.toml`；自举 `build` 另把旧计划的两张结果表原样搬到新计划末尾——值由宿主算，自举只搬；
`module-loader` 读计划并入生成模块，缺计划、计划过期、产物缺失各报一条指向 `build`
的诊断。夹具与判据见 **下一代自产**。

边界：不翻译——生成文本由 `pini bind` 产出，两侧同形；生成模块归属按装载分组判，不再靠路径前缀；
自举不启动 C 编译器，结果表只搬不算。

### 宏常量的构建期求值与降级

`|macro` 条目的值只能由 C 预处理器给出，求值因此落在宿主侧：每个条目一行探针，一次 `cc -E -P`
展开后按标记读回，另用一趟 `-dM` 判对象式、函数式与头里有没有；`check`、`run`、`build` 各自
求一遍，只有 `build` 把结果写进计划。自举不启动 C 编译器，只按计划读值；缺计划条目与缺头文件
分开报，读者分得清「配置没给」与「计划没带」。

求不出值的条目不阻断声明：缺头文件、头里没有、函数式宏、展开不可解析、值越界、缺计划六种理由
记在声明上，读到它才报 `E4-044`——主标签落在读点，文案带声明位置与展开原文（截断 160 字符）。
未使用即零诊断，`check` 通过时补一行提示，不进诊断流、退出码仍为 0。分界是「能静态判定的当场
报，依赖头文件与环境的才降级」：`|macro` 的类型不是七个 C 标量之一报 `E4-045`，C 预处理器不可
用仍当场失败。

计划因此多两张结果表：`[[macro]]` 记包、名、状态与声明类型，有值写 `value`，未求值写
`reason` 与 `detail`；`[[skip]]` 记生成面被跳过的宏与理由。宿主 `build` 在翻译后写入这两张表，
自举 `build` 原样搬运——值归宿主，自举只搬家。查找按「包 + 名」，两包各自声明同名宏时各取本
包的值，不按计划次序抢第一条。

降载把有值宏直接出字面量，不产生存储、不产生 `external global`；未求值的留作读点能力缺口，
供 `check` 覆盖不到的通道兜底。生成面另有分工：`pini bind` 跳过的宏名写进计划，用户直接写下这
个名字报 `E4-046` 并附 shim 配方，同一名字不再叠一条未定义名；跳过名按包归属，邻包的同名标识
符仍报 `E3-001`。

判据：未使用的失败宏 `check` 退出 0、`run` 正常；读到它报一条 `E4-044`，位置落在读点；`&宏`
只报 `E4-001`「没有地址可取」，不叠 `E4-044`；`|macro: *U8` 在两侧都报 `E4-045`；`errno` 配
`<errno.h>` 时报 `E4-044` 并附展开原文 `(*__error())`；双包同名宏各取本包的值；同包重复声明在
计划里只留一行；同一输入两次 `build` 的计划逐字节相同。

边界：结果表只由宿主写入，自举 `build` 搬运而不重算；两代 `plan` 比对的是配置期计划，结果表不
在其中——搬运由 `package` 的单元测试与 `build` 前后的计划文本共同核对。宿主不读计划，宏值照旧
当场求；单文件通道没有清单，宏按缺头文件降级。

### 解析吞吐与栈深

自举解析器在原生通道跑不完自己的语料：单个 `parser.pini` 自解析记 5 分 36 秒，五个源文件合计越过命令上限被终止，解释器通道却全量通过。差距不来自语义，最可疑的是按值往返的复制路径：原生通道的数组追加在存储被共享时逐元素堆分配深拷，解释器侧是宿主数组的整块写时复制，常数差出量级。这条以阶梯读数为准，代码形状只是待验假设。

测量口径：只认原生通道，解释器读数作对照进过程记录、不参与判据；输入取 `parser.pini`、`scan.pini`、`nfc_tables.pini` 与 1k / 2k / 4k / 8k 行合成阶梯；单次耗时取同进程重复次数的差商，每档五次取中位数、首跑丢弃，同档两次中位数差超过一成即作废；读数按毫秒、字节每秒、记号每秒三列给出；记录写机器、LLVM 版本、构型与优化级别。

基线取法：先在未改动的代码上取一组读数，改造后同法复测、两列并列；全文件跑不完时用截断阶梯（前八分之一、四分之一、二分之一）按耗时随规模的指数拟合定位复杂度，绝对量另有全工作区一档直接实测，不按平方和外推；栈深与时间分开量，取最大递归层数与触发它的结构。

改造落在：记号瘦身（段表移出记号进段池，记号退成定长记录）、归一守卫（只在文本含 CR 时走 `replace`，避开逐字切片与拼串的平方代价）、句柄登记（活动句柄表按对象身份索引，登记与摘除常数时间）、关键字表（入口建一次随状态传递，按宽度剪枝直接比字节）。两条判定不做：状态就地（按值往返的只是六个数组句柄，不是数组内容）、节点瘦身（根因是句柄表线性摘除，改常数时间后带数组字段的节点与纯标量节点同阶）。

判据：输入翻倍，解析耗时不超过二点四倍，净耗时低于底噪一成的档不参与判定；全工作区 130 个文件、约 2.4 MB 的装载加解析在原生通道不超过三十秒；双通道 539 项读数逐项不变，全量解析零诊断的抽样集合不缩小，同一输入两次解析的语法树摘要与诊断序列逐字节相同；`parser.pini` 与 `nfc_tables.pini` 在默认线程栈上不溢出且最大递归深度进过程记录；把句柄登记改回线性查找，线性度与绝对量必须同时转红。

结果：全文件自解析降到亚秒级，全工作区装载加解析进入二十秒级，栈深每层约 2 KB、实文件最深约 30 KB，六条验收齐。

风险与控制：

| 风险 | 控制 |
|---|---|
| 为提速改语义或跳过判据 | 双通道读数与全量零诊断作为等价门禁，读数变化即停 |
| 就地推进后读到旧快照 | 同一输入两次解析逐字节相同；关键结构加写后读用例 |
| 优化落在错误热点 | 先取阶梯读数定指数，再改；每项改造单独复测，不合并取数 |
| 需要运行时扩容入口 | 先登记 `docs/spec/runtime-abi.md` 再动，不私加符号 |
| 栈深被调参掩盖 | 最大递归深度与触发结构写进过程记录 |

边界：缩进深度影响词法耗时一处未定位，嵌套泛型实参写法待补面；改造只动形状不动语义，双通道与全量零诊断是唯一等价证据。

### 解释器自解析搁置

工作区测试聚合强制走解释器通道，`syntax` 的 `自解析` 一项独占这段耗时的四成上下。同一用例在原生通道已由逐包门禁覆盖，且覆盖更严——它把发射与运行一并验证。故解释器那一份在 CI 里停跑，判据由原生承担，直到解释器具备 JIT 一类加速能力再复核。

依据是去重，不是取舍：该用例在流水线里本就被跑两遍，去掉的是一直较慢的那一遍，判据本身不减少。读数（macOS 27.2.1 arm64、Swift 6.4.2、clang 23.1.5、debug）：工作区全量解释器 543 项 156.34 秒，其中 `自解析` 68.74 秒，同口径装配底噪 9.41 秒；同一项原生 5.17 秒（发射与链接 4.7 秒，运行 0.47 秒）；`syntax` 全包原生 91 项 5.54 秒。

流水线步数在同一区间由 15 增至 25，新增的十步里八步是逐包原生测试，工作区测试仍是单步里最重的一项。这一条只削单步内最贵的一段，不动编排结构；真要压总时长，得从原生聚合与逐包门禁的合并上取，那是另一笔。

落地：测试执行的收窄面加 `--skip`，与 `--filter` 对称、可重复、先筛后跳；工作区路径下每个名字必须至少命中一条测试，否则按框架错退出，筛空或被全部跳过都不算通过，报告留一句「--skip 全数排除」；模块路径的单模块测试只做排除、不校验命中。

边界：停跑只在 CI，本地默认仍执行解释器那一份，它承担解释器与原生分叉的早期信号；恢复条件是解释器落地 JIT 一类加速、耗时降到与原生同量级。工作区级原生聚合是根治路径，但要逐包发射并聚合，不进本批。

### 契约与节点池

IR 是单层中间表示：节点单池加类别码分段，子节点用池下标；IR 类型池独立于语义类型池，降载入口
一次建映射。节点结构共用七个字段（`kind`、`typeId`、`op`、`intValue` / `floatValue`、`text`、
`kids`），一套遍历、一套校验与一套契约对照即可覆盖全部节点，不必为每族写一遍。

契约基线是二十五类、六十二个表达式节点与十八个语句节点，共八十条。契约表由节点声明生成并随
源码提交，`tools/ir-contract-check.py` 在契约、节点池与三个后端锚点之间三方核验，不解析
Markdown；新增节点与契约同批改，否则自检先红。

判据：IR 校验双向报告「有节点无契约」与「有契约无实现」；语义与 IR 不含 LLVM 名称、指令与目标
布局判断；一个只做结构转储的第二后端不改公共接口即可接入。

边界：整图降载、整图发射，不做按包产物与增量缓存；字段与用例只存声明序下标，名字退为诊断与
发射拼写。份额只分四类、求值效果只分三类，标量与外部指针不参与，判定归语义层；字节宽度与对齐
只在 `backend-kit` 的目标描述里算一次。`future`、`cFunction`、`lazyRef`、`stringHandle` 四类 IR
类型由降载点就地造，语义池没有对应类别。

### 降载面

降载入口 `lowerWorkspace(world)` 一次吃完世界、类型表、表达式类型表、形态表、槽布局与外部符号
表，出一份模块；函数表顺序由拓扑序、包内声明序与表达式池序共同决定，不依赖字典插入序。

调用与赋值是第一批大头：方法符号按「方法名 + 类型」出，`|self` 与 `|own` 各一套，实例方法形参
表首位补接收者；带标签实参按形参声明序归位，省略默认值与取用位的调用报缺口，不按零值补齐；
复合赋值降成「读—算—写」三节，局部、字段与下标各一条写路。

字面量与声明：字符串去引号按转义表还原后驻留文本池，不逐段解码；数组元素保序，空字面量按标注
定型；带标注声明把类型写回模式节点，初值窄于标注时包一层显式转换；零参构造、内建调用、别名调用
与下标读各留类型后备。

语句小项同批收口：`elif` 脱糖、跳出与继续带深度、`as` 发转换节点、`nil` 发可选构造、多参
`print` 发对应节点；插值改为段表随编译单元进降载，不到降载期重扫字面。

匹配是另一类：`match` 降成「主体落临时局部 + 标签比较 + 载荷绑定 + `if` 链」，枚举、`Optional`
与 `Result` 的判别式走 `enumTagGet`、关联值走 `enumPayloadGet`；未命中补陷阱，裸值未命中静默
落到匹配之后。契约基线因此定为六十加十八。

推导与期望：名字表按函数建一张，`self` 与参数先入表，方法体走完即弃；推导按函数、按语句序遍历，
先推初值再登记名字；`for` 与 `unroll` 的模式变量按容器分量定型；语句序走完再按池序传播一遍，
兜住字段初值、处理器体与函数字面量体。期望下推的来源三条——声明标注、实参位、返回位与容器元素
位；用例归属「期望优先、唯一候选兜底」；标签实参按名对位传期望，位置对不上宁可不传；变参尾与
回调位不传期望。

裸名收紧：值位的枚举用例只认限定写法与 `.用例`，裸名只在 `match` 模式位合法；用例倒排表只按
用例名建键、所有者记枚举名；驱动的 `cases` 子命令只列位置，不改写源码。

缺口按原因分类报：族未声明、类别码未接、该换写法、本引擎还不会，四类不拼同一后缀，也不静默写
零值。过渡机制已撤：`fallbackIrType` 的下标分支删除，下标类型由推导表给出；当前源码已无十八个
内建成员旁路，保留的
`upper`/`lower`/`trimLeft`/`trimRight` 是语言基元，不属该旁路。

### 模块自足与结构校验

模块要能只凭自己发射：类型声明表（形态表折成声明表，字段与用例保持声明序，类型下标换成 IR 池
下标）、槽表（转述语义槽布局与两个基准常量）、位置面（函数携带逐语句源内偏移，条目序即语句
创建序）、归还面（节点带 `adopt` 与 `releaseOld`，份额按类型给类别、按节点给求值效果）、外部
函数表、文本池与错误表。字段位只存声明序槽位，名字退为降载期的查找键。

结构校验在后端读模块之前走一遍：十条规则从函数体入口走可达集，违约报专用码与源位置；新增节点
同批补规则与阴性夹具。

`backend-dump` 是见证而不是产品：按固定节序输出类型池、声明表、槽表、函数体与错误表，两遍逐
字节相同才算接缝过关；它不发射目标码，也不参与运行。

判据：手搭模块给每个类别码各装一个节点，转储逐类印名，行数等于节点数加六节表头；全量两遍转储
逐字节相同；工作区测试与逐包原生测试全过。

边界：位置只记语句，合成节点共用所在语句的偏移；校验只走可达集，失败函数留下的孤儿节点不参与；
转储暂不列外部函数表；语句节点的类型位常为 -1，读时按行首 `stmt` / `expr` 分辨。

### 后端接缝与能力族

后端记成「名字 + 输出档次 + 能力族表 + 入口码」，驱动按入口码分派，不引入函数指针。
`backend-kit` 分三段：后端记录、目标描述（字节宽度与对齐、符号拼写、变参实参提升，字节口径只此
一处）与注册表。新后端等于新包加注册一行，能力族与宿主同形，另加控制流一档收语句节点。

依赖方向照 **各包职责与允许依赖** 的表：`semantics → ir → backend-kit → backend-llvm`，`driver`
依赖编译链各包并作唯一装配点。`ir` 不认识 LLVM，`backend-kit` 不认具体后端。接缝四段各给各的：
语义给类型下标、声明序与槽位；`ir` 给只读模块视图；`backend-kit` 给目标描述与族表；后端给文本
与失败项。谁都不回头重判上游已经定下的类型、布局与份额。

能力族当前十四族全声明，八十条里降载可达与发射接通分开计量：
降载可达（源码写法能产出该节点）、发射接通（节点有分派分支）、族已声明（缺口文案分「族未声明」与
「类别码 N 未接」）；三条同时成立才算用户可达。`pini-bootstrap/tools/capability-reach.py` 逐节点给出
三列并汇总到族，`--check` 判「接通即声明、声明即至少接一条」，已进 `test-gate.sh`。

判据：越出能力声明的节点必须报错；转储后端可以对全部族表态支持，但产出档次单列；族表与节点
可达在普查里逐条对齐。

边界：能力族是声明不是实现；只做结构转储的后端不拿族表冒充可执行；后端不做类型、布局与份额的
再判定。

### LLVM 发射面

发射入口吃「后端记录 + 目标描述 + 模块」，目标描述由调用方给，发射器只读不入模块；发射结果带
缺口表，按条累积、按类别去重，失败位与缺口数同源。未接类别按能力族报缺口，不产占位指令。

起步面取「能过 LLVM 校验、能链接执行、值算得对」的最小集：整数与浮点常量、字符串常量、变量
读写、算术与比较、模块内与外部调用、条件分支、循环、返回、表达式语句、打印与断言。随后按主题
补齐：

- 指针与外部数据：`load` / `store` 专属路径，`&x` 在检查与推导各补一条，外部数据出
  `external global`。
- 整份与可接住读写：走契约节点，撤掉 `readFile` 的内建行。
- 闭包与惰性引用：函数字面量落 `closureLiteral`，发射 `{ ptr, ptr }` 与 `@__closure_<n>`；
  `LazyRef` 走 `pini_lazyref_create` / `pini_lazyref_value`。
- 并发：`=>` 调用方拿 `Future<T>`，`await` 与 `wait` 同降成 `join`，`detach` 降成剪枝语句。
- 默认实例：`[名|given]` 与结构同权降成名义类型，模块为每个给定块出初始化函数，取用点走
  `pini_given_get`。
- 内建名：`len` 与 `Array.append` 不按名字直呼运行时符号，先查「内建名 + 接收者类别码 → 符号
  + 搬参形状」的表；`len` 在降载面出容器长度节点，`append` 先落装箱台再调运行时。
- 外部声明：`[名称|foreign]` 的条目登记进模块外部函数表，发射按表出 `declare`，变参尾留省略
  号，调用点按 C 拼写直呼。

文本与胶水：文本池引用语义承载，驻留从池尾倒着扫；类型表按单元记绑定起点，`typeOf` 越界答 -1；
复制、释放与 ARC 胶水按份额动作出，闭包环境与测试跑器同批接。

判据：产物过 `llvm-as`、经 `clang` 链接执行，读数与手算一致；每个 IR 节点同时有文本形状判据与
运行行为判据；相同输入重复发射逐字节相同，文件顺序与字典插入顺序不影响结果；四份夹具
（`llvm-family`、`llvm-lazyref`、`llvm-task`、`llvm-given`）与宿主逐行相同；声明文本的定参与
变参各有一条单测。

边界：外部函数只收标量、指针、`String` 与 `StringHandle` 形参，回调与按值聚合报缺口；变参只收
固定前缀加尾实参提升；指针只收标量元素，聚合值指针与指针算术未实现；无体函数不发声明，留在
缺口表；测试助手跨包重名一律加包前缀；浮点待办，见 **下一代自产**。

### 装配、确定性与吞吐

装配链固定为 plan → load → world → fill → shapes → layouts → lower → validate，一条命令一条链；
`check`、`build`、`plan`、`lower`、`dump`、`emit`、`test`、`cases` 只是同一链的不同停点。诊断
非空即不发射。

确定性是硬约束：同一输入两跑，函数表、缺口数与诊断序列逐字相同；所有对外产物显式排序，字典
插入顺序不决定输出，另加乱序输入对照。

吞吐按主题记结论，不记逐批读数：

- 标识符几乎全 ASCII，键计算先走 ASCII 快路径、再退完整 NFC，装配段降到原来的三分之一上下。
- 编译单元带字节视图，装载时转一次，消掉各调用点重复转换整段文本的开销。
- Unicode 四张生成表改「定宽数据串 + 通用二分」，生成源码由两万余行降到百行量级，查表不解码
  整串。
- 解释器自追加改消费路径：识别「右值是接收者加一个元素且目标同处」，先求元素、取走槽里的数组、
  就地追加再写回；判不成唯一引用时退回复制。
- 文本池独立成池、引用语义承载、驻留从池尾倒扫；类型表按单元绑定起点，先跳再扫。
- 试过并回退：声明查类型改二分、类型池比较换整数码、`clang -O2` 重编整图——后者只快百分之四，
  说明瓶颈不在机器码。

判据：四项产物读数（函数表、缺口数、诊断序列、发射文本）与改动前逐项相同；语料二十六例全过；
全量测试全绿；`test-gate.sh` 钉住「stage 1 止于装载」「默认路径跑到校验」；运行时段只按 release
构建，rpath 指向 release 目录，缺库即报错，不回退 debug。

边界：填表仍是最大单段，它是十二万个表达式逐个推导的累积，没有可摘的单点；类型解析阶段的游标
仍走线性；采样显示剩余时间分散在运行时库的固定开销上；未采样前不做代码生成侧优化。

### 自举闭环与验收

构建链固定为「当前宿主 → 首代自产 → 次代自产 → 三代自产」。验收分两层，不互相替代：

- **自洽**：首代自产编译完整多包工作区得到次代自产；次代自产能编译规范语料并通过全部行为测试。
- **不动点**：次代自产与三代自产分别编译同一工作区，所得 LLVM 文本逐字节相同。

`|test` 贯通语法、语义与降载；测试函数里的断言失败只写消息位与失败位并立刻返回，后续测试照跑，
非测试路径仍是陷阱。`testkit` 管发现、筛选、定序与报告；`backend-llvm` 加测试发射入口，跳过
非测试 `main`、合成跑器与进程入口；驱动 `test` 子命令支持 `--filter`、`--skip` 与 `--list`。
发射期另设重名定义门禁：同名有体函数拒发并指出后一处。

语料每例一个自带清单的极小工作区，期望写在用例清单里，来源是语言参考与诊断表；两条通道各跑
一遍，按「码 + 区间」比对，措辞不进判据；两侧各加一个只读的结构化诊断开关。已知差异记进
`pini-bootstrap/tests/conformance/divergence-baseline.tsv`，只许缩小，某条转为一致时门禁反红提示
删行。

判据：两代发射文本逐字节相同；两代可执行文件各自跑同一套测试，报告逐字节相同；全部包逐个
`check` 通过；语料二十六例八类（合法、非法、Unicode 三、路径、诊断、包构建、C 互操作、
确定性）全过且基线清空；构建时间、峰值内存与产物大小建立基线，阈值后设，不预编数字。

边界：崩溃类测试（越界、显式陷阱）仍终止整轮，进程级隔离留待真出现此类用例；只比首条诊断，
一侧多报的后续诊断不入判据；位置约定取「主标签落在最小可指结构」，规范未写死的按此裁定，裁定
不了的进基线；全量自举只在本地或发版前跑，流水线只跑三秒自检；门禁分级见 **下一代自产**。

### 门禁接线

门禁分级里「提交前」一层此前只验首代产物：`test-gate.sh` 写死首代路径，`selfhost.sh` 也只跑整图
发射与语料，于是生成模块装载、`build` 落盘与三类定向诊断这三段判据从未由次代执行过。接线不动
判据，只把入口参数化，并把次代接进自洽链。

交付：`test-gate.sh` 取 `PINI_BOOTSTRAP_BIN`，缺省仍取首代产物；`selfhost.sh` 在链接次代之后
依次跑四段——两代门禁报告、两代计划文本、净化 `PATH` 下的次代 `build` 与构建前后 `git status`
快照、两代语料报告与发射文本。

判据：自洽链退出 0；次代 `build` 输出 `build-ok 0 0`；构建前后 `git status --porcelain` 逐字节
相同；两代门禁报告、计划文本、语料报告、发射文本各自逐字节相同。读数：链全长 2 分 52 秒，门禁
单遍 2 至 3 秒。

边界：门禁报告只比「通过」一行，不比过程输出；`build` 的步骤级落盘与装载由生成模块夹具承担，
净化 `PATH` 只用于证明次代不靠宿主二进制。`plan` 与 `build` 的工作区参数须给绝对路径——相对
路径按程序基准解析，工作区清单会读成不存在。

### 浮点字面量

浮点此前只有语法与节点：`irFloatConst` 在契约与节点池里（`floatValue: F64`），后端已按节点类型
切换浮点指令，打印走 `pini_double_to_string`；缺的是降载分支与常量发射。卡点是编译器自身取不到
运行时段符号——解释器通道只认语言内建，`[名称|foreign]` 的 `pini_` 符号在 `pini` 进程里不可见——
故取值与位模式两个入口登记为零调用点，只由自举在编译期调用。

交付：`runtime-abi` 增 `pini_parse_double`（strtod 口径）与 `pini_double_bits`（IEEE-754 位模式），
解释器侧同批加两条 shim；降载把拼写解析成值填 `floatValue`，整型标注按截断折成整数常量；发射按
宿主的 `doubleLiteral` 口径出文本——零与指数写法走位模式十六进制，其余用最短往返十进制。顺带补
不安全前缀的降载：它此前是缺口，含 `unsafe` 的函数会被整段丢掉。

判据：夹具 `fixtures/llvm-float` 四条读数与宿主逐行相同（18.75 / 3.75 / 0.30000000000000004 /
1e-05）；`test-gate.sh` 增一条「浮点常量按位模式发射」；全量测试 673 项、降载 2684 函数零缺口、
`emit-ok 14 339951`；自洽两代文本 12,999,009 字节相同。

边界：只接十进制拼写；溢出到无穷的写法（`1e999`）未单列诊断。F32 不在 IR 宽度内，仍走内建。

### 标准库成员形态

交付：`pini-bootstrap/stdlib` 作为独立源码包，由驱动在工作区级装配一份，默认开；编译器自身构建用
`--no-stdlib`，编译器包不反向 import 它。十八个成员（trim、startsWith、endsWith、replace、repeat、
padLeft、padRight、lastIndexOf、isEmpty、count、stripPrefix、stripSuffix、ensurePrefix、ensureSuffix、
reversed、capitalized、center、truncate）可从用户模块直接调用；`upper`/`lower`/`trimLeft`/`trimRight`
是语言基元，不属标准库装配面。宿主发行副本与 `pini-bootstrap/stdlib` 由宿主测试逐字节比对。

判据：全量测试 693 项由自产产物跑通，十四包检查、降载、发射零缺口；单包夹具默认装配后
`trim`/`upper` 端到端输出正确；语料二十九例通过、基线为零；自洽链两代门禁、计划文本、发射文本
逐字节相同。

边界：装配源是整份标准库目录，`core.pini` 排在 `algorithms.pini` 之前，两份以换行拼接后进
同一个 `<stdlib>` 单元；`stdlib` 不参与编译器自身构建，避免改标准库触发编译器重建。

## 下一代自产

目标：自产编译器自己读 `build.pini`、出构建计划、装载计划登记的生成模块、发射，脚本只调外部
`clang` 链接，产出可运行的下一代。不变量三条：编译器源码只有一份；每代产物由前一代编译；两代
发射文本逐字节相同。

门槛判据：自产 `build` 在 PATH 无宿主 `pini` 时退出 0，产物可运行；两代发射文本与两代计划文本
逐字节相同；两代测试报告逐字节相同；构建后 `git status --porcelain` 无新文件。

已交付的能力件五段：

- **外部声明发射**：`IrModule` 带外部函数表，条目为名字、返回类型、形参类型与变参标志；降载把
  `[名称|foreign]` 的条目登记进表，手写块与生成块同形；发射按表出 `declare`，变参尾留省略号；
  调用点按 C 拼写直呼，不按内部编码。`IrExternData` 只管数据符号，两表同形不合并。
- **构建脚本面**：`package` 解析 `build.pini` 的给定块，不把配置块交给语义层当类型声明；计划带
  步骤与根相对产物路径，`plan` 打印、`build` 落盘；`module-loader` 读计划并入生成模块，只认以
  `.build` 组件开头且与脚本步骤对得上的产物。计划与宿主同一份 TOML 形状：`[plan]` 记版本与
  翻译器标签，`[[package]]` 记包根与脚本哈希，`[[step]]` 记头文件、包含路径、定义、产物与输入
  指纹；哈希走 SHA-256。夹具 `fixtures/build-script` 与 `fixtures/generated-load` 覆盖计划形状、
  生成模块装载与三类定向诊断。
- **宏常量的构建期求值与降级**：宿主 `pini build` 在翻译后求值 `|macro`，把结果写进计划的
  `[[macro]]` 与 `[[skip]]` 两张结果表；自举 `build` 原样搬运这两张表，不启动 C 编译器。
  `module-loader` 按「包 + 名」查宏，并把与单元同序的包名表带进降载帧；有值宏降成字面量、
  不产生外部符号，未求值与缺计划在读点报 `E4-044`，生成面跳过的宏名报 `E4-046`。计划两张表的
  解析与整段搬运由 `package` 的单元测试钉住。
- **门禁接线**：`test-gate.sh` 认 `PINI_BOOTSTRAP_BIN`，缺省仍取首代产物；`selfhost.sh` 链接次代
  之后，以两代各跑同一套门禁并比报告，两代各 `plan` 同一构建脚本夹具比计划文本，另在净化 `PATH`
  下跑次代 `build`，比对构建前后的 `git status --porcelain`。生成模块夹具、`build` 落盘与三类
  定向诊断因此由次代自产执行。
- **浮点字面量**：`runtime-abi` 增 `pini_parse_double` 与 `pini_double_bits` 两个入口，解释器同批加
  两条 shim；降载把拼写解析成值填 `floatValue`，发射按宿主的常量文本口径出文本；顺带补上不安全
  前缀的降载（此前含 `unsafe` 的函数会被整段丢掉）。夹具 `fixtures/llvm-float` 四条读数与宿主
  逐行相同。

本线待办已清空。**标准库函数形态**已交付：`algorithms.pini` 的二十六个泛型自由函数随装配源

### 推进次序与裁定

次序按「先后清空哪条总判据、后动哪份契约」排，不按上面七段的列举顺序。前置三项
（**差异普查**、入口与对照夹具、只读命令）已交付，余下是：

**判据清账** → **通道面** → **命令面** → **内存模型** → **工具面**；**解释执行** 暂缓，不进当前次序

注意 实际次序已偏离这一行：**命令面** 与 **内存模型** 先落了，**通道面** 先交付 `json` 一条，
余 `c` 一列十四行「无」；`llvm` 全文对照已量，读数见 `docs/plans/readings/2026-11-25-llvm-parity.md`，
处置排在 `c` 这条新通道之后。它不阻塞工具面，但总判据收线前必须回来。

**判据清账** 打头：三条总判据里有两条（程序表清空、诊断表差集为空）不依赖任何新契约，现在就能
开工，且它们是权重最大的两项；命令面的 `compile`、`run-llvm`、`test-llvm` 是纯新增，不改善任何
一例失败。**通道面** 紧随其后，同为对照法、不改契约：`llvm` 两侧产物的全文差要先量出来，才谈得
上逐条收口。**命令面** 排在第三，因为它的前置是进程原语——不可逆的 ABI 扩张，晚定不使任何已交付
项返工，早定却先占住手。**解释执行** 从零长执行器但不改契约，暂缓的理由见本节裁定。
**内存模型** 提前到 **命令面** 之后：它的当前差集只剩自举侧三处（析构调用点、E4-040 发码点、
COW 写时分裂的验收），都不经执行器，宿主两条通道已落地，对照物是参考件 7.7 与示例 golden。
`asyncDeinit` 与结构化作用域退出的调度留作保留差异：它要运行时段的延迟释放队列与调度入口，
借执行器省不掉这块，跳过执行器后代价只会更明确。**工具面** 仍留末位。

五处裁定：

- **进程原语进 ABI**：`compile`、`run-llvm`、`test-llvm` 在宿主侧都经 `Process()` 起 `clang` 或
  `lli`，自举侧没有任何进程入口。补 `pini_process_*` 进运行时，符号先登记
  `docs/spec/runtime-abi.md` 再进实现，第 2 节合计数与 `tools/runtime-abi-check.py` 同批更新。这三条命令因此进本线，不作保留差异。
- **`test` 走解释通道**：`test` 与 `test-llvm` 同形——收集、执行、报告，差别只在执行通道；
  `test` 走进程内的树遍历求值器，`test-llvm` 发射原生程序再跑。起进程因此只发生在 `compile`、
  `run-llvm` 与 `test-llvm` 三条命令，`build` 只出计划。自举侧当前「`test` 只发射」是过渡形态，
  随 **解释执行** 收口，不留作终态。不提前钉这条，`test` 会先长成「发射加起进程跑」的第二个
  编排器，等求值器落地还要再拆一次。
- **解释执行先做 `run`**：树遍历求值器与 `run` 同批交付，运行期错误按 E5 段发码；`repl`、`debug`、
  `dap` 三条要标准输入，而运行时段还没有读标准输入的通道，三条因此记「随执行线」，退出条件是
  该通道落地。`test` 走解释通道这条仍推迟：`test` 仍是「只发射」，过渡形态保留到求值器接管测试。
- **`embedded_min` 留差异**：宿主侧也只是最小集。该通道按保留差异登记，不进总判据的归零项；
  运行器随 **解释执行** 一起做，不单独立项；该段已暂缓，运行器随之挂起。
- **工具面只做最小集**：格式化的幂等往返、头翻译的两次生成一致、语言服务与调试各一份脚本化会话
  夹具即为上限；协议版本与能力集落后不阻塞收线。

### 差异普查

### 判据清账

两份对照读数先清，再谈新增命令。程序表的失败例按三类归因：**缺符号**（作用域里没有那个名字）、
**缺判定**（类型、成员、标签面的规则没接）、**缺语法构造**（解析期就断）。归因表落
`pini-bootstrap/tests/parity/`，与既有四张表同址同纪律。

诊断表的缺码按 **差异普查** 的依据列分类：参考件有条款的先补，只属宿主实现的不补，依据不明的
转 **待核** 并写明缺哪一条款。补的是发码点，不是码表——登记数与宿主全集已一致。

补齐前先查宿主有没有构造点，不能只看码表有登记。按错误枚举的构造点普查：`E2-004`、`E2-010` 与
`E2-013`–`E2-024` 这十四码原本在宿主解析器里一处也没有抛出，只活在码表与错误枚举里。这十四码已按
**两侧同批补抛出点** 收口：宿主 `Parser.swift` 与自举 `parser.pini` 同批加站点，除 `E2-004` 外各配
一例语料。`E2-004` 的判定已就位（缩进块读到文件末尾仍未见反缩进），但词法在文件末尾会补齐 DEDENT，

### 通道面

`c` 与 `json` 已交付；余 `embedded_min` 一条，按裁定保留差异。`dump` 是文本结构转储，与 `json`

- **`llvm` 全文对照**（已量，排后）：差分十五类，函数体层的四类是所有权约定、槽与求值顺序、
  分支跳板与指令选择，覆盖一千三百二十五个共同函数里的一千一百七十个；命名与集合差另占前导
  二千九百六十四行与一百二十四个函数。另测出宿主自身的函数顺序两跑不同，全文逐字节相同在宿主
  修复前不是可稳定判定的目标。收口等于重写既有发射器的调度与调用约定，故排到 `c` 之后；
  若只为收线，可登记为保留差异，判据退到「自举同输入两跑逐字节相同」。
- **C 头通道**（已交付）：输入 IR，按导出表出结构声明、函数原型与两个生命周期符号；布局断言
  让错位在 C 编译期就红。与构建脚本面里的头文件翻译方向相反，不共用实现。错误码表未建模，
  本后端不发；门禁按两跑逐字节相同与 clang 可读两段判，通道表 c 列十四格转「有」。
- **JSON 通道**（已交付）：`backend-json` 按宿主 `json` 后端的字段名与出现次序出单行文本。顶层为
  `backend`、`output`、`layout`（头槽数、结果槽数、可选槽数、标签槽）、`types`（名义类型名，声明序）、
  `enums`（枚举名，声明序）与 `functions`；函数条目为 `name`、`params`（逐项 `name` 与 `type`）、
  `returnType`、`async`、`test` 与 `body`；语句体按先序平铺，条目为 `kind`（契约名）、`depth`

  注意 `detail` 是自由文本，两侧键集不同：宿主写语句专属字段，自举写类型、操作码、文本池下标、
  子节点数与份额动作。比对只认 `kind` 与 `depth`，不比 `detail`；类型拼写走 `irTypeText`，不照抄
  宿主那套反射形态（它把模块名连同 `Optional(...)`、`Set([])` 一起印进了输出）。
  判据：`backends --tsv` 出现 json 列且十四族全声明；同一模块两跑逐字节相同；示例全量产出的文本
  可被 JSON 解析器读入；通道表 json 行转「有」。接通列记该族契约节点数 —— 这条后端不按类别码
  分派，只按通用字段印，没有会漏的分支；它与 `llvm` 列的口径不同，读表时按列注理解。
- **字节码通道**：宿主侧也是最小集；先对齐族矩阵，运行器随 **解释执行** 一起做。

判据：`backends --tsv` 的共同通道逐格相同（自举另有 `dump`，宿主另有 `embedded_min`）；每条通道

### 内存模型

实测差集已清零：`E4-040` 的发码点、释放胶水的 `deinit__` 调用点与 `deinit` 的 self 借出三处

登记为保留差异。展开、值语义拷贝、释放胶水、弱引用、无主引用与导出面已收口，记在下面各条。

按可验证性排序：

- **展开**：`unroll` 在类型检查前按表的行克隆语句，纯前端；与宿主 `expand` 同一套语义。已交付：
  `examples/unroll.pini` 两代编译运行输出逐行相同，且与宿主一致；四类诊断的码与位置同宿主逐位相同
  （夹具 `check-unroll`、`check-unroll-bad`）；程序表该例由「语义」转「通过」。命令已随 **工具面** 的
  **搭车** 解锁，命令表转「有」：展开按树重打，注释不进产物，产物可过 `check`。

  缺口；门禁、711 项测试、自洽链全绿，发射文本 14,013,124 字节。
- **值语义拷贝**：结构体在四个存储点（绑定 · 赋值 · 字段写 · 返回）拷出独立箱，容器元素仍按箱共享，
  与宿主的 `IRType.adoption` 同一判据；拷贝胶水 `__copy_box_*` 逐字段搬值，结构体字段递归、对象与枚举
  与容器留份、串留份。判据：`let 副本 = 原` 后改副本字段不回写原处，两侧输出 1/1/99；嵌套结构体
  3/4；返回值 7/8；形参共享 500。
- **箱的生命周期**：释放胶水先减计数，归零才清扫字段并 `free` 箱体；值语义箱归族码 3（名义箱），
  槽、形参、字段、数组元素四处都要还。数组元素按聚合标签登记一对成员钩子，销毁与分裂时逐格留份/归还。
  读数：715 项测试；自洽链 4 分 54 秒，发射文本 16,436,146 字节；次代发射自身的常驻内存 1.65 GB
  （此前 12.9 GB）、耗时 113 秒（此前 206 秒），与首代的 1.27 GB / 110 秒同阶。
- **份额判据收口**：细分码只对计数族有值，其余族答 0，而 0 又等于「不动作」，按它判份额会静默漏掉
  整族。现在细分码改成下划线名字不出包，跨包只认四族类别与 `irRetainFamilyOf` 的族码（0 不动作 ·
  1 串 · 2 容器 · 3 名义箱）。判据：同一程序的发射文本逐字节相同；716 项测试、自洽链 4 分 52 秒、
  16 条夹具、普查三表全绿。
- **循环内声明**：同一条声明在循环里会重复执行，落槽前先还上一轮的值；首轮槽已在入口清零，还空值是
  空操作。不还则每轮泄一箱，次代发射自身时涨到 GB 级。
- **匹配主语**：`match` 的主语先落临时槽再逐支复读，这一格也要填接收动作；漏填则主语被槽与真持有者
  各还一次，箱释放后仍被读写，堆在后续分配处才崩。
- **份额入账**：求值造出的新份额按「是否握份额」入账，不按细分码判；值语义箱的细分码是 0，按细分码判
  会让它的临时值从不入账，落槽时又留一份，每处多留一份计数。
- **池残留**：节点池只追加，被替换掉的子树仍留在池里；退役把它们换成空语句与空字面量，语义层的
  全池扫描对它们是空操作，功能风险由此闭合。不走「语义层按可达性只查活节点」：遍历要枚举全部入口，
  漏一个入口就把活节点判死、连诊断一起漏掉，失败方向比现状危险；而自举源码里 `unroll` 用量为零，
  收益当前为零。判据：`退役节点是空壳` 一条用例钉住「死节点的名字区间、kids 与处理器块都不带」。
- **导出面**（已交付）：语义层新增导出面检查——条目右端限本单元的自由函数或给定块，方法、泛型、
  异步、`|test`、`main` 与多返回值一律拒，C 名转写后相撞、落进 C 保留区或与外部符号同名各报一条；
  名字转写归 `support`，语义与降载共用一份。`ir` 的模块带导出表（C 名已转写），`backend-llvm` 按表
  出 C 入口、给定块取址与两个生命周期符号：`^T` 走状态码加出参，空载荷只剩状态码，借出的串在入口
  复制、调用一返回就放。判据：`emit` 后 `clang -shared` 链接，符号表含各 C 名与 `<块>_init` /
  `<块>_shutdown`；C 侧调用读数与手算一致；门禁新增符号表段与一条方法导出的负例。边界：头文件通道仍
  归 **通道面**；`|c` 的错误码表与 `strerror` 未做；`build --shared` 已随 **命令面** 交付。
- **生命周期**（已交付）：`deinit|self()` 只挂在对象类型上，零形参、零返回、每类型至多一个，
  形状不合格报 E4-040。宿主的释放胶水在计数归零后先调它再清扫字段；解释侧的计数本来就是宿主逐份
  记的（与「引用复制 +1、丢弃 −1」同构），归零后把字段交割给释放队列，引擎在语句边界与帧收尾迭代
  执行 `deinit__<类型>`，即参考件 7.1 那条延迟释放队列。自举侧三处同批：语义层的
  `checkLifecycleShapes` 五条判据挂进检查装配；释放胶水的 sweep 首条插 `deinit__` 调用，按函数表
  命中才插；`deinit` 的 self 按借出处理——出口不登记、调用点不移交，两端成对。判据：五类非法形状
  各报一条且位置指向声明头；`examples/deinit.pini` 两通道与 golden 逐行相同；门禁两条示例比 golden。
  边界：同一作用域里多个对象的析构次序两通道不保证一致（绑定表是字典，没有声明序）。
  `asyncDeinit|self() => ()` 同样静默：语法层认 `|self` 与 `=>`，它按普通异步方法注册并发射，
  永不作为析构被触发。它与结构化作用域退出的调度未做，登记为保留差异：运行时段没有延迟释放队列与
  调度入口，补它等于在 C 侧重造执行器的一段；参考件 7.7 的调度表可推判据，本段不动它。
- **尾表达式与丢弃值**（已交付）：值返回的函数体、方法体、闭包体，末句是普通表达式语句时它就是返回值；
  表达式语句的值没人读时，语句尾当场归还它那份份额。判据是两通道逐字节同读数，且发射文本里那条归还
  紧跟造值调用。出口不完整（有路径既没 `return` 也不以交值表达式收尾）报 `E4-041`；`if` 分支与
  `match` 覆盖面的判据见参考件 6.6。
- **引用种类**：`weak`、`unowned`。旁表入口若不在 `runtime-abi` 里就补条目，只加入口不改运行时
  语义。`weak` 已交付，见 **弱引用**；`unowned` 已交付，见 **无主引用**。

#### 克隆约定

- **下标映射**：克隆函数返回新下标，装配父节点时当场取用返回值；不走「先记源下标、事后按表回填」。
  池没有引用身份，事后回填在第一轮因新旧下标恰好重合而看不出错，第二轮偏移即把新语句挂回旧节点。
- **kids 分派**：语句节点的 `kids` 混放两类池下标，按类别码与位置分派。块、`defer` 的体、`if` 的
  分支体、`while` 与 `for` 的体与步进、`match` 的分支体、`unroll` 的体走语句克隆，其余位置走
  表达式克隆；表达式节点的 `kids` 全是表达式池，`body` 是 `try` 的处理器块，走语句克隆，`typeId`
  指向类型池，克隆时共享原值。
- **克隆身份**：克隆必须新建节点并逐字段填，不复用源节点；名义类型的赋值共享同一个箱，改副本会写回
  池里的源节点，表现为第二轮读到第一轮的克隆结果。
- **位置**：克隆节点复制源节点的 `start` 与 `end`；模式名换成分量字面量时用字面量自己的区间。
  诊断码与位置以宿主为参照，逐位比对。
- **重名**：体顶层不许声明局部变量，任何位置不许与模式名同名，违者报 `E3-016`。这条是能力边界不是
  缺陷：与 Rust 让两轮局部变量互不互通同效，只是表达为拒绝而不是隔离。

### 弱引用

`weak` 进关键字表（34 → 35，中文词表补「弱引用」），文法按前缀表达式收；操作数限对象，结果
`WeakRef<T>`，`.value` 读成 `Optional<T>`。宿主与自举两侧的语法、语义、解释器 / LLVM 同批打通，
非对象操作数报 `E4-042`。

运行时段增 `pini_weak_create` / `pini_weak_value` / `pini_weak_destroy` 三个入口：创建只在对象头装上旁表
指针，不碰强计数；对象归零时把旁表标死，此后取值答空。IR 增 `weakRef` 类型与
`weakRefConstruct` / `weakRefValue` 两节点（码 59 / 60），匹配主语用完即弃另增 `releaseVar`
（码 118），契约基线由七十五条升到七十八条。

判据：语料 `weak-ref-lifecycle` 两通道各跑一遍——存活时 `some` 带载荷，强引用换掉后 `nil`；
`runtime-abi` 的「清单数 = 导出数」由 124 升到 127；全量 724 项、语料三十例、自洽链四项不变。

边界：弱引用旁表随对象或进程存活，不在 `pini_weak_destroy` 回收；宿主解释器用 Swift 弱引用承载，
两侧都不比对旁表布局。

### 无主引用

`UnownedRef(对象)` 是类型构造器而不是前缀关键字：实参在 unsafe 上下文里写，结果类型
`UnownedRef<T>`；解引用、调用与字段读写同批纳入 unsafe 门禁，读、写、调用三类判定穿过同一处
成员检查，非对象操作数报 `E4-043`。宿主与自举两侧的语法、语义、解释器 / LLVM 同批打通。

运行时段不增入口：无主引用不记账、不登记旁表，表示就是对象指针（IR 拼写 `ptr`）。IR 增
`unownedRef` 类型与 `unownedRefConstruct` / `unownedRefValue` 两节点（码 61 / 62），字段读与
方法调用在降载期插入一次解引用。契约基线因此是二十五类、六十二个表达式节点与十八个语句节点，
共八十条。

判据：语料 `unowned-ref-no-retain` 两通道各跑一遍——读、写、调用三路都作用到目标；比较按目标身份，
同一目标的两份句柄相等、不同目标不等；随后换掉强引用，同伴弱引用读成 `nil`，证明无主引用没有留份。
`runtime-abi` 维持 127 不变；全量七百二十八项、语料三十一例、自洽链四项同批成立。

边界：对象销毁后再解引用是未定义行为，两条通道都不补偿（解释器按 Swift 的 `unowned` 规则停住，
LLVM 通道直接读悬垂指针）。

### 解释执行

**暂缓**，不进当前次序，裁定见 **推进次序与裁定**。宿主有 `run` 与 `repl`，自举没有。这是唯一一段
从零长出执行器的工作，也是唯一不共享 LLVM 通道的段。

分两步：先做与装配链共用世界与类型表的树遍历求值器（`check` 与 `run` 共用同一份世界，避免两套
语义），再做 REPL 的增量求值与补全；生成模块装载与计划读取沿用现有链路。

判据：同一程序两通道输出逐字节相同——宿主 `run` 与 `run-llvm` 已有这个口径，照搬；`examples/` 全部
程序两通道同输出。

注意 解释器不进编译器自身构建路径：自举编译器由 LLVM 通道产出，解释执行是对用户程序的第二条通道，
不能反过来成为编译器的依赖。

保留差异、仅宿主实现、设计预留，补齐项清零；执行表每个示例有处置，处置取通过、补齐、
随执行线、保留差异，处置写通过而实际变红即拒生成。

处置是机械判据：三张静态表由 `tools/parity.py` 生成，缺行即拒绝生成；程序表与执行表要跑
示例，只在 `--full` 下重取。保留差异与随执行线必须在来源表写明理由与退出条件，退出条件
不成立前不重开该码。人工来源是 `command-disposition.tsv`、`diagnostic-basis.tsv`、
`diagnostic-disposition.tsv` 与 `execution-disposition.tsv`。

自举独有的命令不要求宿主补齐，也不计入归零项：`plan`、`lower`、`dump`、`cases`、`interfaces`
是自举侧的内部通道，按表内理由登记即可。

边界：

- 运行时仍经 C ABI 复用，不重写；`weak` 若需旁表，只加入口。
- 不以宿主输出回填语言判据：产物结构按 `docs/spec/ir-contract.md` 的字段比，宿主快照只作回归护栏。
- 新能力不进编译器源码，直到自洽链能编过——沿用 **风险与控制** 的前代编译门禁。
- **工具面** 允许长期留差异：`lsp`、`dap` 的协议版本与能力集可能一直落后，登记在表里即可，不阻塞
  其它段。
- 并行、远程缓存与逐包产物不进本线：它们已在 **构建形态演进收尾：分波计划与共享缓存（已交付）**
  落地。

## 宿主迁移评估

问题是：何时把 Swift 宿主移出构建链，改用「Pini 编译器 + C 运行时」。今天两条实现并存——`Sources/`
171 个文件、约 5.9 万行，含解释执行、语言服务、调试适配、REPL 与 C 头翻译；`pini-bootstrap/` 的 `src` 层
150 个文件、约 4.7 万行，另有 92 个测试文件、约 1.4 万行。实现规模已接近（宿主约多两成），差不在行数，
在命令、通道、诊断三张表与执行路径。

判据六条，按硬度排：

- **命令面**：`commands.tsv` 每格有处置；余四条「无」是 `lsp`、`debug`、`dap`、`repl`，`help` 与
  `run` 已交付。
- **通道面**：`channels.tsv` 的「无」清零——`c` 十四条已接，余 `embedded_min` 的未保留格。
- **诊断面**：二十七条缺码按处置清零——十七条随执行线、六条保留差异、三条仅宿主实现、
  一条设计预留；七条补齐项（`E2-025`、`E4-027`、`E6-005`、`E7-003`、`E7-004`、`E7-005`、`E7-008`）
  已交付，表内转「一致」。E5 那十五条需解释执行先落地。
- **执行路径**：`run` 要有不依赖宿主的执行方式。现已由自举求值器执行，不再走宿主解释器；
  `test` 只发射、`run-llvm` 经 `lli` 执行，两条路保持原样。
- **种子**：首代二进制可复现取得并登记摘要。今天种子就是宿主构建；没有登记过的二进制，移出宿主
  等于让「哪份产物可信」无人回答。
- **版本窗口**：两代升级窗口生效后才冻结种子；版本串已是 0.56.0，宿主的 `Version.swift` 与自举的
  `inspect.pini` 同值，改号要两处同批。

结论：编译器侧接近，执行面刚起步，工具侧未到，运行时段是另一笔。

- 已成熟：自洽链四项逐字节相同（门禁报告、计划文本、语料报告、发射文本）；程序表六十八例全通过；
  命令行对照三十七条用例退出码全部相同，三十五条首条诊断相同，十二条全文逐字节相同。
- 未成熟：  `repl`、`debug`、`dap` 三条仍未接；执行表六十九例里四十五例跑不完，缺口按
  `execution-disposition.tsv` 分随执行线与保留差异；C 互操作的生成侧只到 `bind`；
  诊断面缺三十五条，非法程序可能报不出专用码。
- 运行时段另计：`PiniRuntime` 现有 3,856 行 Swift、133 条 C ABI 符号；C 化要重写字符串、容器、
  引用计数与并发，并重验解释与 LLVM 两条通道。它不阻塞编译器迁移，但「零 Swift」要等它。

分四段推进，每段可独立验收：

- **默认发布**：自产产物作默认 `pini`，宿主降为开发期种子。判据是自洽链与全量测试都由自产产物
  跑通——这一条现已成立，缺的只是把「默认」写进发布物。
- **差集清零**：命令、通道、诊断三张表按处置收线——补齐项清零，保留差异写明退出条件；`bind` 已交付，JSON 读取器落在 `support`。
- **冻结种子**：登记各平台首代二进制与内容摘要，宿主移出构建链。判据是净化 `PATH` 下从零构建成功，
  且两代文本仍逐字节相同。
- **运行时 C 化**：独立立项，判据是 ABI 133 条符号等价、两条通道行为一致。

注意 迁移换的是信任根，不是实现：从「Swift 工具链 + release 运行时段」换成「冻结的 Pini 种子」。
未登记种子摘要就移出宿主，等于把最该有判据的一步留成口头约定。

## 导入形态整顿

**现状**：`pini-bootstrap/` 二百三十四个源文件里一百四十四个带导入块，条目三百零九条；二百九十九条是
注入式（`_别名 = "路径"`），十条是限定式。路径按文件层级写死：`src/api` 下二百零一条写 `../../../`，
`tests` 下一百零八条写 `../../`。注入式把目标包的公开符号倒进本文件裸名空间，调用点看不出名字来自
哪一层；`semantics/src/api/register.pini` 的 `package` 是限定式却从未使用，这类死导入也无人发现。

**规模**（估算，不是编译器读数）：按「外来公开名在本文件出现的次数」估，跨包裸名引用约六千处，
覆盖一百三十九个文件。把名字按声明种类切开，类型声明名与值名约六比四（六千五百八十四对三千九百
四十八，与上一条同源、未去局部同名）。头部几条边：`backend-llvm → ir` 约一千四百七十、
`semantics → syntax` 约八百七十、`backend-llvm → semantics` 约八百、`ir → semantics` 约四百一十、
`semantics → module-loader` 约四百。注意 这是名字匹配的估算，局部同名与字段名会带来偏差；准确值由
自举检查器逐包给出——它一次报全，宿主只报每个文件的首条。

**目标**：跨包名字带别名前缀，来源在阅读时可见；注入形态在编译器自身源码里收敛为零（语言保留该
能力，标准库与用户包照用）。导入右端维持路径写法，不引入包名或前缀。

**三步**：

- **类型位前缀**（前置，已交付）：类型注解原只认裸名——宿主对 `p: 别名.类型` 报解析错，自举对同一
  输入段错误退出。两通道已各补解析、打印、判型与接口文本，并加跨包夹具：同一夹具两通道 `check`
  都过，`fmt` 逐字节相同，`别名.类型<T>` 判解析错。这一步与整顿解耦——它补的是 §4.2「非 `_` 别名
  必须限定」在类型位落不了地的缺口，即使整顿不做也留用。
- **逐包翻转**：一批一个包，自底向上：`unicode` → `diagnostics` → `syntax` → `package` →
  `module-loader` → `semantics` → `ir` → `backend-kit` → `backend-llvm` → `backend-dump` →
  `testkit` → `driver`；`support`、`runtime-api`、`hostproc` 无导入，跳过。每批四步：`_别名`
  改成 `别名` → 自举 `check --diagnostics-tsv` 收该包全部未定义名 → 脚本按行·列定位，查该文件
  导入包的公开名，唯一即改写 `别名.名`，不唯一列人工 → 复跑至零诊断。判据：该包零诊断、宿主
  `check` 绿、`fmt --check` 零输出；每三批加跑全量测试，收尾两代文本逐字节相同。
- **收口**：门禁加一条，编译器源码的导入块不得出现 `_` 别名；零命中即通过。语言面不动。

**搁置**（本轮结论）：整顿暂时搁置，**工具面** 之后重评。两处卡点，一层比一层深：

- **名字面**：文件可见面没按导入路径算出来。`knownName` 先查全工作区顶层表，注入表只作补充，
  于是「导入与否」不影响判定；宿主相反，同一夹具（`y` 限定导入 `z`，裸调 `z` 的 `add`）报 E3-001，
  自举放行。
- **符号表**：登记按包平铺，不循导入路径生成；导入块只登记别名，不产出符号。文件级的符号面因此
  得另行计算——这才是 **可见名** 补丁治不了根的地方。

试点已证后果：`diagnostics` 翻转四条导入后，自举检查一条错也不报；**逐包翻转** 的收错一步没有
信号。离线估算也顶不上——按名字匹配会把 `append`、`sleep`、`filter` 这类内建名与局部名算成跨包
引用，抽样误报过半。重评时先回答「符号表按什么路径产」，再谈逐包翻转的收错办法。

**已交付并保留**：类型位前缀（`别名.类型` 的解析、打印与按末段判等，两通道同规则）；参考件
§4.2 措辞（导入侧不筛选、公开与否归导出侧、右端为模块根目录）。

**已定**：

- 导入右端维持路径，参考件 §4.2 只把「谁决定可见性」写明：导入侧不筛选，公开与否归导出侧。
- 测试目录与 `src/api` 同批翻转，一个包的导入块一次清完，检查不重复跑。

**排序**：搁置中，重评排在 **工具面** 之后。重评前不动包源码；这一改触及全部包，恢复时仍宜独占
窗口，不与 **外部面** 同批。

**风险与控制**（重评后适用）：

| 风险 | 控制 |
|---|---|
| 改写误伤局部同名、字段名、注释与字符串 | 只按诊断给出的行·列改名，不做文本替换 |
| 跨包同名符号选错归属 | 五类类型名与十二个值名跨包同名（`float`、`isOK`、`count` 等）；脚本列候选，唯一归属才自动改 |
| 改写混进语义改动 | `fmt --check` 零输出；两代文本逐字节相同 |
| 六千处一次性 diff 无法评审 | 按包分批，每批独立提交与验收 |
| 限定后行宽超限 | 先量触发比例，再定别名是否缩短 |

注意 自举检查器当前不是零基线：六条「注入名与本文件名字相撞」，局部变量 `all` 与 `filter` 撞上
注入名，宿主不报这些。翻转后它们自然消失，试点按这个基线读。另注意 自举一次检查七十到一百一十秒，
宿主一秒半；每批只跑自举一次，迭代靠它一次给全。

注意 `module-loader` 被导入七十七次，根子是 `CompilationUnit` 与 `MemberWorld` 几乎每个包都用。
限定之后这两类会到处以 `module_loader.` 开头，来源清楚了，但「这两个类型该不该住在这一层」是另一件
事，不在本整顿内裁定。

| 风险 | 控制 |
|---|---|
| 为赶进度重新合并成总包 | 工作区硬门直接拒绝未声明依赖和内部引用；每批复核包图 |

| 未实现构造被静默写成零值 | 降载和发射 fail-loud，结构校验与行为测试同时存在 |
| 输出顺序导致不动点漂移 | 所有对外产物显式排序，并加入乱序输入对照 |
| 宿主和自举的标识符语义分叉 | 规范先改、同批落地、共享语料；查找键只用 NFC，原始拼写不进比较 |
| 语义与降载各写一遍类型判定 | 类型判定只在语义层，IR 只做类型池下标到 `IRType` 的映射；后端不重算布局 |
| 检查面缺口被跳过（fail-open） | 全部表达式节点进检查面；语法未表达的构造在语法补面明列，遇到即报错 |
| 槽布局与字节布局两处维护 | 语义层只出槽布局；字节口径单归 `backend-kit` 目标描述 |
| 临时内建扩散成永久语言面 | 只准 `temp` 前缀，逐条登记退出条件；正式能力落地时整组移除 |
| 生成物落进源码树，或源码树里的文件冒充生成物 | 只写 `.build`；装载面只认计划登记且以 `.build` 组件开头的路径 |
| 自产产物与宿主的结构体复制语义分叉，嵌套表被共享改写 | 实例世界逐字段另立新表，不依赖结构体复制隔离；自洽链覆盖泛型实例 |
| 计划与源码不一致（脚本改过没重建） | 计划记脚本哈希与输入指纹；`check` 只验哈希与产物存在，重翻归 `build` |
| 接口记录与源码不同步，下游拿旧接口通过检查 | `check` 按整份接口文本比记录，本包或依赖变化即报 E3-021；记录只由 `interfaces` 重写 |
| 宿主接口文本只有公开名，签名变化不触发接口漂移 | 签名变化由类型检查在下游调用点报 E4；接口文本扩签名随类型面接入，不提前造第二套签名渲染 |
| 逐包切分把跨包定义漏进别包，链接期报重定义 | 本包名单按函数源文件首段归包，非本包只出声明；自检逐包编译后再合并链接 |
| 缓存只按本包源码判命中，依赖接口变了仍发旧产物 | 输入指纹含依赖接口摘要；接口未变的下游才复用，公开面变化沿依赖传播一层 |
| 共享缓存按指纹取文件，被污染的缓存会被当成正确产物 | 缓存键含源码摘要、依赖接口摘要与发射身份；写入只发生在新发射后，发布前整批重建复核 |
| 外部符号同名异型被后写者覆盖 | 声明处一次裁决：签名与标志全同才合并，异型报错并指回首次声明 |
| 生成物用了自举解析器不认识的写法 | 映射规则只写在参考件与夹具；生成文本原样进自举解析，零诊断是判据 |
| 族声明与节点可达脱节，声明成了空头承诺 | 能力普查三列并排，`--check` 判「接通即声明、声明即至少接一条」 |
| 节点可降载而发射未接（或反之）被当成「已支持」 | 缺口文案分「族未声明」与「类别码 N 未接」；普查表逐节点核对 |
| 运行时段回退 debug 构建，门禁慢五倍却仍全绿 | 定位函数只认 release，缺库即报错不回退；rpath 与构建步各留一处可复核 |
| 跨通道诊断差异被当成噪声长期挂着 | 基线只许缩小，转为一致即反红；新差异必须先写进已知缺口再登记 |
| 语料把未实现的能力当成判据松动 | 期望只从规范推；未实现记缺口进基线，不放宽判据，也不拿某一侧输出回填 |
| 标准库让位跨包生效，邻居包声明同名项会摘掉本包的库函数 | 夹具 `stdlib-claims-workspace` 钉并集口径（两侧都必须拒绝）；码随名字解析口径而异：宿主按包解析得未定义，自举按工作区解析得实参个数不符 |
| 泛型实例的未定来源只认有正面证据的两类 | 名字不存在报 E3-002，实参落到非类型声明报 E3-003；未知类型名全仓没有判据，宿主只在下游报成类型不匹配、自举放过 |
| 提速改动改变产物 | 每批先比四项产物读数与语料，读数不符即回退 |
| 分段读数被当成通过 | `test-gate.sh` 钉住 stage 1 止于装载、默认路径跑到校验 |
| 自举测试全量进 CI 拖长合并与流水线 | 全量只作交付判据，在本地或发版前跑；流水线只跑三秒自检 |
| 测试助手跨包重名，发射时静默取首个定义 | 同名有体定义在发射期拒发并指出后一处；测试助手一律加包前缀 |
| 宿主升级后首代文本变化，旧读数冒充新结论 | 种子矩阵改一项即整组重取；全量失败先比文本再查代码 |
| 新增语言特性渗进编译器源码，旧自产编不过 | 自洽链本身就是前代编译门禁；首个发布版起扩为两代窗口 |
| 链接参数受库目录顺序影响 | `[ffi].libs` 按清单序拼；夹具固定一组库顺序 |
| 差异普查的程序表要跑全部示例，进常驻门禁会拖慢每次提交 | 只作交付判据；三张静态表走源扫与宿主矩阵，进门禁 |
| 普查表与源码脱节，缺口被静默忽略 | `parity.py --check` 在门禁里过三张静态表，过期即红并指出重取命令 |
