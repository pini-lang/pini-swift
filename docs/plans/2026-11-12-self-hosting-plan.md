# Pini 自举终态架构与实施计划

## 目标与边界

目标是用当前语言实现一个新的 Pini 编译器，使它能够编译自身，并在连续自产之间达到确定性不动点。

自举验收必须同时满足：

- 编译器源码全部由 Pini 书写；脚本只负责构建编排、进程调用与产物比较，不承载编译逻辑。
- 工作区、包清单、依赖图、源码装载、语法、语义、IR 和 LLVM 文本发射均由自举实现。
- 首代自产能编译完整工作区并得到次代自产，次代自产能够运行。
- 次代自产与三代自产对同一输入生成相同的确定性 LLVM 文本。
- 合法与非法语料均以语言参考、IR 契约和手写期望为判据，不以宿主输出代替规范。

下列事项不阻塞自举验收：

- 用 Pini 重写运行时。当前 `PiniRuntime` 继续经 C ABI 复用，运行时替换单独立项。
- 用 Pini 启动 `clang`。构建脚本负责调用外部 LLVM 工具，进程原语只在替换完整 CLI 时补。
- 远程包下载、包仓库、LSP、调试器、REPL、embedded 后端和完整工具链替换。
- 为追求宿主 LLVM 文本一致而引入与规范无关的约定。

本地多包工作区、包可见性和依赖构建不是可选扩展，而是本计划的编译器基础能力。

## 筹划载体

所有架构决定、实施批次、验收判据、风险和后续调整只在本件内维护，不另立专题计划件。各批次的实际代码、测试夹具、构建产物与验证日志属于交付证据，不属于新的筹划载体。

工作区奠基之后立即打通测试函数闭环。后续包不得等到功能完成后再补测试，统一按“先写失败测试、确认红、最小实现、确认绿、重构并复跑”的循环推进。

## 现况缺口

当前宿主已经提供可复用的种子、C ABI 运行时、LLVM 工具链、语言参考、IR 契约和测试门禁。自举真正缺少的是以下底座：

- **工作区与包构建**：需要让多个独立包按公开接口协作，而不是把源码放进一个总包后依赖目录约定维持分层。
- **文本底座**：用户层 `String` 的长度、下标和切片按字素工作；编译器需要稳定的 UTF-8 字节区间、标量解码和线性扫描。
- **符号身份**：规范给出了标识符的 Unicode 字符类别，但没有完整规定规范化、等价拼写和混淆冲突。
- **稳定装配面**：需要明确哪些类型属于包间契约，哪些只是包内实现；后续增量构建、格式化、语言服务和新增后端都依赖这一分界。

## 架构原则

- **先定终态，再切批次**：任何功能直接进入最终归属包，不先放进总包再迁移。
- **包边界由编译器执行**：公开接口、包可见性和依赖方向必须由构建系统检查，不靠命名习惯或审查记忆。
- **接口与实现分离**：跨包只暴露值、类型、函数和错误契约；内部数据结构、遍历顺序和发射细节不得泄漏。
- **单向依赖**：基础包不认识编译器，语义不认识后端，后端不反向读取 AST，驱动是唯一编译器装配点。
- **无空壳包**：尚未实现的功能不建立占位 API；创建包时必须交付真实能力和测试，但目录规划从第一批就固定。
- **中间形态不改终态边界**：早期可以整图一次性构建，后期再改增量构建；两种形态都使用同一包结构和公开接口。

## 终态目录

```text
bootstrap/

  packages/
    support/
    unicode/
    diagnostics/
    syntax/
    semantics/
    ir/
    backend-kit/
    backend-llvm/
    runtime-api/
    package/
    module-loader/
    driver/
    testkit/
  stdlib/
    pini.toml
    src/
  tooling/
    formatter/
    language-server/
    debugger/
  tests/
    architecture/
    integration/
    conformance/
    selfhost/
  runtime/
    abi/
  tools/
  .build/
```

根 `pini.toml` 是工作区清单，不是把全部源码装在一起的包清单。它登记成员包、构建 profile、共享 LLVM 与运行时配置，以及测试目标。工作区语法是待实现的构建能力，实施时先进入构建规范，不能由脚本私下解释一套未登记格式。

### 包内统一形态

每个生产包使用同一结构：

```text
packages/<包名>/
  pini.toml
  src/
    api/
    _internal/
  tests/
```

- `api/` 是包间契约，只放公开类型、公开入口和导出声明。
- `_internal/` 是包内实现，其他包不可见；包内测试可以贴近实现，跨包测试只准走 `api/`。
- `tests/` 是测试 target，不进入普通库产物。工作区需要明确库、可执行文件和测试三类 target，不能用排除目录的临时技巧代替。
- 包清单显式列出本地依赖；未声明依赖的包即使源码可见，也不得被引用。

### 各包职责与允许依赖

| 包 | 职责 | 允许依赖 |
|---|---|---|
| `support` | 字节缓冲、切片、源码文本、区间、符号驻留、确定性容器、通用结果与错误 | 无包内依赖，只依赖语言与运行时基础 |
| `unicode` | UTF-8、标量分类、NFC、混淆骨架、Unicode 数据表 | `support` |
| `diagnostics` | 诊断码、严重级、源码位置、标签、修复建议、渲染 | `support` |
| `syntax` | 记号、AST、词法、语法、源码打印所需的语法信息 | `support`、`unicode`、`diagnostics` |
| `semantics` | 作用域、符号、类型、声明注册、可见性、类型检查、类型布局 | `support`、`syntax`、`diagnostics` |
| `ir` | IR 节点、降载、份额、布局消费、结构校验 | `support`、`semantics`、`diagnostics` |
| `backend-kit` | 后端接口、能力声明、目标描述、发射结果与后端注册接缝 | `support`、`ir`、`diagnostics` |
| `backend-llvm` | LLVM 类型映射、文本发射、复制与释放胶水、目标产物 | `support`、`backend-kit`、`runtime-api` |
| `runtime-api` | 运行时段符号、C ABI 声明、句柄与桥接能力清单 | `support` |
| `package` | 工作区与包清单、target、依赖图、拓扑排序、构建计划和产物身份 | `support`、`diagnostics` |
| `module-loader` | 从构建计划读取源码、规范化和解析，形成语法层编译单元 | `support`、`package`、`syntax`、`diagnostics` |
| `driver` | 编译器库入口与 CLI，装配装载、检查、降载、测试执行、后端和输出 | 上述编译链各包与 `testkit`，禁止反向被依赖 |
| `testkit` | 测试发现、筛选、顺序、执行器接口、结果报告、夹具协议与确定性乱序测试 | `support`、`syntax`、`ir`、`diagnostics` |

依赖图必须保持无环。`package` 不认识 AST，`module-loader` 不做类型检查，`semantics` 不读文件，`ir` 不调用 LLVM，`backend-llvm` 不解析源码，`driver` 不拥有各层内部规则。

### 标准库、工具与测试的位置

- `stdlib/` 是独立源码包，由驱动按语言规则装配到用户模块；编译器各包不得通过反向 import 获取它。
- `tooling/formatter` 只依赖 `syntax`、`support`、`diagnostics`，不得为了复用 CLI 而依赖 `driver`。
- `tooling/language-server` 可以依赖 `syntax`、`semantics`、`module-loader`，不得依赖 LLVM。
- `tooling/debugger` 通过独立调试接缝消费源码映射，不进入编译主依赖链。
- `runtime/abi/` 保存 C 侧契约与链接元数据；Pini 侧声明只归 `runtime-api`，避免两套符号清单漂移。
- `tests/architecture/` 检查包依赖、公开接口和禁止引用。
- `tests/integration/` 覆盖多包构建、缓存、增量重编和诊断。
- `tests/conformance/` 保存语言正负语料与手写期望。
- `tests/selfhost/` 保存自洽、不动点和确定性验证协议。
- `tools/` 只保存构建与测试编排，不放任何生产编译逻辑。

新增后端只新增实现 `backend-kit` 的包，并在驱动注册；不得把目标判断散落到 IR 或语义层。新增工具只进入 `tooling/`，不得把命令实现堆回 `driver`。

## 工作区与构建契约

### 包接口产物

每个库包在逻辑上生成三类产物：

- **导出接口**：公开声明、类型布局所需信息、泛型实例化所需语义信息和依赖版本。
- **编译产物**：供链接或整图发射使用的 IR 与目标产物。
- **构建身份**：包源码、公开接口、依赖接口、语言配置和后端配置的内容摘要。

公开接口变化必须使下游失效；仅 `_internal/` 变化时不得要求下游重解析或重检查。早期尚未实现增量缓存时也必须按同一身份规则判断哪些步骤需要执行，不能靠时间戳猜测正确性。

### 构建形态演进

- 初期允许工作区整图装载、整图检查、整图发射，但包间仍只能读取导出接口。
- 随后增加按拓扑序的包产物和接口缓存，不改变包目录、调用方或依赖声明。
- 最后增加并行构建与远程缓存；它们都不属于自举验收前置。
- 任何阶段都禁止跨包读取 `_internal/`，禁止通过“先把源码并入同包”绕过可见性。

### 架构硬门

工作区构建器直接依据依赖图执行以下判据：

- 未声明依赖、反向依赖、跨包内部引用、循环依赖均为构建错误。
- 包公开接口与导出接口产物必须一致，接口变化必须触发对应下游重建。
- 同一包不能同时以源码路径和另一种包身份进入同一张图。
- 构建、测试和自举三代链共用同一依赖图，不允许脚本另排一套包顺序。

## 文本模型

采用**字节编译内核**，严格分开三个文本域：

| 文本域 | 用途 | 禁止事项 |
|---|---|---|
| UTF-8 字节 | 源码保存、ASCII 记号、关键字、区间、LLVM 文本 | 不得把字节下标当用户字符下标 |
| Unicode 标量 | UTF-8 校验、标识符分类、转义解码、规范化 | 不得把标量序号当字节偏移 |
| 字素簇 | 现有用户层 `Char` 与 `String` 行为 | 不得用于词法游标和源区间 |

核心类型按最终包归属：

- `support.ByteBuffer`：持有完整 UTF-8 字节，不支持隐式字素解释。
- `support.ByteSlice`：保存缓冲区身份、起点和长度，切片不复制。
- `support.SourceText`：持有规范化后的源码、文件名和逐行起点表；`Span` 一律是字节区间。
- `support.ByteBuilder`：线性追加 ASCII 与 UTF-8 字节，供诊断和 LLVM 发射使用。
- `unicode.UnicodeText`：包装需要标量分类或规范化的小段文本，不进入扫描热路径。

当前语言只需补两类内部桥接能力：把 `String` 的完整 UTF-8 内容复制成字节数组，以及把字节数组经 UTF-8 校验后组成 `String`。桥接经现有 C ABI 运行时实现并登记到 `docs/spec/runtime-abi.md`，不暴露指针算术，不改变用户层字符串语义。

词法器不得使用 `split`、`replace` 或字素下标扫描源码。标识符和字面量先记字节区间，确实需要内容时才切片；记号默认携带 `Span` 与符号编号，不携带整段复制文本。

## 标识符身份与混淆

采用**原始拼写保留、规范化负责身份、混淆分析负责诊断**的三轨模型：

- 原始拼写永远保留在 AST、符号声明和诊断中，不改写用户源码。
- 符号查找键使用 NFC 规范化结果；同一作用域内，原始拼写不同但 NFC 相同的声明按同一符号冲突处理。
- 规范化只在标识符上进行，不规范化整个源文件，字符串字面量和注释内容不受影响。
- Unicode 版本必须固定，字符类别、规范化与混淆表由受控数据生成 Pini 表并纳入版本控制；构建和运行不得依赖宿主操作系统的 Unicode 版本。
- 混淆骨架只用于安全诊断，绝不用于符号查找，避免把视觉相似误当成语言等价。

混淆策略不按“非 ASCII 一律危险”处理，中文标识符仍是正式能力：

- 对拉丁、西里尔、希腊等高风险混写给出错误；常用脚本与中文的合理组合不因混写这一因素被拒。
- 对同作用域内混淆骨架相同的标识符给出警告，并同时展示原始拼写和转义后的码点序列。
- 全角字母数字、数学字母数字、兼容等价拼写至少给出警告；是否提升为错误由语料门禁验证后固定。
- 标识符中的零宽字符、双向控制字符和不可见格式字符直接拒绝；注释与字符串中的双向控制字符给出明确警告。
- 无效 UTF-8、BOM 和 NUL 在装载期响亮拒绝。CRLF 归一化发生在词法之前，所有区间统一指向归一化后的 `SourceText`。

NFC 会改变符号身份，属于语言面决定。实施前先修订 `docs/spec/pini-reference.md`，宿主和自举同批对齐；若暂不采纳 NFC，则只能把规范等价冲突降为警告，不能暗中在自举符号表里做另一种查找语义。

## 受限源码约定

受限只约束编译器自身的写法，不压缩终态包结构，也不缩小编译器最终必须接受的用户语言：

- 使用结构体、枚举、数组、字典、函数、`match`、循环、`Result` 和显式类型标注。
- 泛型只保留容器与必要算法所需形式，避免把高阶类型推断扩散到编译器源码。
- 不使用结构化并发、`LazyRef`、弱引用、无主引用和复杂 FFI 聚合布局。
- 本地多包、公开接口和包可见性属于必用能力，不得列入“以后再支持”。
- 公共声明显式写参数与返回类型，不依赖宿主推断细节。
- 不用字典遍历顺序决定输出。文件、声明、符号、诊断、类型布局和 LLVM 定义都显式排序。
- 不用宿主字符串优化、文件系统顺序或哈希种子作为正确性的前提。

用户语言覆盖按规范逐项回填，并为每个新增构造补正负语料。

## 实施批次

### 工作区奠基

交付：

- 在工作区与包构建规范中定义根清单、成员包、target、依赖图、导出接口和产物身份。
- 种子侧支持本地多包构建；自举 `package` 先实现工作区根探测，构建计划语义随后续批次在该包内扩展。
- 建立最终目录规范、包内 `api/_internal` 边界、测试 target 和架构硬门。
- 钉定标识符规范与字节转换 ABI。

验收：

- 两个最小库包和一个可执行包能按拓扑序构建，跨包公开调用成功。
- 未声明依赖、内部引用、循环依赖和接口漂移均被拒绝。
- 测试源码与非法夹具不会进入普通库产物。
- 不建立总包，不用脚本硬编码包顺序。

交付回执：

- 根 `[workspace]`、`[lib]`、`[[bin]]`、`[[test]]` 已进入当前清单模型；`WorkspaceBuilder` 统一生成依赖图、拓扑计划、target 源码集与产物路径。
- 普通 `build` 在工作区根上生成包接口、LLVM IR 和原生可执行文件，单包行为保持类型检查；CI 增加工作区构建与产物运行门禁。
- `bootstrap/` 已建立 `support`、`package`、`driver` 三个真实包。`support` 与 `package` 提供最小公开能力，`package.hasWorkspace` 承接 Pini 侧根清单探测，`driver` 验证跨包公开调用。
- 多文件 import 已按文件登记，嵌套 `_internal` 的可见性按全部祖先目录计算；测试 target 与普通生产源码已隔离。
- 自动判据覆盖拓扑顺序、循环依赖、产物重名、未声明依赖、跨包内部引用、多文件导入、清单字段保留、测试隔离和真实产物执行。专项套件现有 9 项测试。
- 完整 CI 已验证通过，包含工作区构建与运行、格式、示例、差分探针和 685 项测试（101 个套件）。
- 当前仍是整图降载与链接，未宣称独立库链接或增量缓存；完整 Pini 侧构建计划、接口缓存和 `|test` 执行闭环按下列批次继续。

### 测试函数闭环

目标是在大规模实现语言特性之前，用一条最小但完整的垂直链路打通 Pini 测试函数。该链路直接落入终态包，不另建一次性测试编译器或旁路测试框架。

交付：

- `syntax` 支持 `|test` 声明与断言所需的最终 AST 形态，不引入新的测试 DSL。
- `semantics` 注册测试函数，检查断言语句的条件与消息类型，并保留测试来源信息。
- `ir` 携带测试元数据与断言节点，测试入口和普通函数入口保持明确分界。
- `backend-llvm` 先实现测试函数、断言、报告和退出状态所需的最小发射面，失败不能静默变成成功。
- `testkit` 提供测试发现、筛选、确定性顺序、执行器接口和统一结果报告；执行器由驱动装配，不让测试框架反向依赖 CLI。
- `driver` 提供最小测试入口，复用同一工作区依赖图和包可见性，不为测试另排构建顺序。

后续所有包执行同一 TDD 循环：

```text
写公开行为测试 → 运行并确认失败 → 最小实现 → 运行并确认通过 → 重构 → 全量复跑
```

### 语义与装载分工

本批从零建立语义与装载两层。为使每一步都有可读的红绿判据，按能力拆成九个子批次，全部直接落入终态包，不建一次性旁路。每个子批次按既有循环推进：先写公开行为测试、确认红，再最小实现转绿，实施后在其节内补交付回执。

依赖顺序：标识符身份先立规范与查找键，其后是清单面、装载面、注册面、类型面；表达式面与语句面共用类型面产出的类型池；布局面只消费类型面；装配面把其余各面接成一条链。类型面与布局面之间没有相互前置，可以并行。

判据纪律：验收只认语言参考、IR 契约与手写期望。宿主输出可以用来定位差异，但不得作为门禁判据 —— 诊断消息的措辞与位置粒度会随实现漂移，把宿主文本当期望，门禁测到的就是无关差异。

三条本批决定：

- **查找键归语义层**：`support` 的符号驻留只保存原始拼写；依赖方向不允许 `support` 反向认识 `unicode`，故 NFC 键由语义层的符号表以字节序列自持。规范化的输入是标识符在源内的区间，不是整份源码。
- **语义层不出定型结果**：IR 契约规定类型在降载之后定型、后端不得再推一次。语义层对外只提供类型模型、布局与名字解析表；逐节点类型判定留在 IR 层，否则同一套规则会在两层各写一遍并逐渐分歧。
- **身份先用结构化文本**：构建身份由成员与 target、入口、源码相对路径与字节数、接口文本拼成可比较的文本。摘要算法留给增量批次替换，调用方不变。

- 混写按脚本分组：拉丁、西里尔、希腊之间的高风险混写报错；中文与常用脚本的合理组合不因混写被拒。

验收：

- 同一作用域内 NFC 与 NFD 的两种写法按同一符号冲突处理，渲染时都显示原始拼写。
- 中文标识符、组合字符、全角字母与数学字母各自的判定与规范一致。
- 零宽字符与双向控制字符在标识符位被拒、在注释与字符串位只告警。
- 混淆骨架相同的标识符给出警告，不触发查找失败。
- 组合附加符号可作续字符、不得作首字符，宿主与自举判定一致。

交付回执：

- 语言参考的标识符一节已补五段：符号身份、原始拼写、不可见字符、混淆、混写。条款只写用户可见行为，数据来源留在实现侧。
- 词法层新增 E1-004 至 E1-006：零宽字符、双向控制字符、起始 BOM 与字素簇内的变体选择符一律拒绝，消息带码点；组合附加符号作首字符单列一条，可续写但不能起头；拉丁、西里尔与希腊之间的混写同样报错，中文与拉丁的组合不受此限。反引号转义走同一套判据。

- 数据只有一份来源：生成器把混淆与脚本文件复制进各自的包资源并登记摘要，`--check` 校验 8 份文件，两份副本漂移时门禁先红。宿主与自举读的是同两个文件。
- 新增宿主 26 项测试、自举 11 项测试；全量 728 项通过，自举工作区 112 项通过，解释器与原生通道读数相同。

- 已知边界：自举侧的字符串告警只覆盖字面段；`\0` 之后的字节不再成为字面段，故那一段不参与告警（宿主按逐字符扫描覆盖它）。两处判定集合仍是同一张 Bidi_Control 表。
- 已知边界：续字符只认四个组合标记区块，区块外的间距组合标记（Mc）仍不作续字符；混写只认拉丁、西里尔与希腊三个高风险脚本，其余脚本的形近关系只走混淆告警、不升级为错误。两条都是可扩展的同一张表。

交付：

- `package` 实现清单两级收集：平表、点分子表、数组表、内联数组与引号感知注释；形状非法时按清单错误报出，不静默取默认值。
- 工作区、包与 target 三个模型落地；成员、包名、target 名与入口的校验全部在生成构建计划之前完成。

- 构建计划按包给出 target、源码集与产物路径；产物路径在 profile 下确定，判定不读时间戳。

验收：

- 自举工作区根清单解析出全部成员与固定拓扑序，重复执行结果逐字相同。
- 重复包名、越界成员、非法入口、重名 target、成环依赖各自报专用错误，错误里带具体包名与 target 名。
- 成员未声明 target 时被拒绝，不退化成一个隐式包。

交付回执：

- `package` 拆成四层：`toml` 做两级收集（平表、点分、数组表、内联数组、引号感知注释），形状非法逐行记账不中断；`manifest` 建工作区、包与 target 三个模型，三类 target 按清单顺序展开；`plan` 做成员规范化、跨包查重、拓扑序与产物路径；`errors` 收十八类清单错误，路径与细节随错误走。

- 构建计划按包给 target、源码根与三类产物路径：库与可执行取 `src`，测试目标取入口目录；`profile` 只改变产物目录，判定不读时间戳。
- `hasWorkspace` 从子串匹配改成解析表头：注释里的 `[workspace]` 不再误判。
- 判据：自举根清单装配出六包与固定序（support → diagnostics → package → driver → unicode → syntax），成员声明顺序不影响结果，两次装配文本逐字相同；越界、重复、缺 target、入口非法、成环、产物重名各自报专用错误。
- 读数：自举工作区 130 项通过（`package` 由 1 项增至 19 项）；宿主全量 729 项，11 个既有已知问题。

#### 装载面

交付：

- `module-loader` 从构建计划取 target 的源码集：递归扫描，点前缀目录整棵跳过，嵌套清单下的源码不进父包，清单声明的排除项生效。

- 装载期一次性规范化：非法 UTF-8、起始 BOM 与 NUL 直接拒绝；CRLF 归一为 LF，此后所有区间指向同一份源文本。

验收：

- 全量自解析基线先行：装载自举全部包的源码，诊断集合为空。基线若出现解析缺口，先补语法包，不把缺口写进装载面的通过条件。
- 同一 target 的源码以不同文件系统顺序给出时，编译单元的诊断序列与树结构逐字相同。
- 非法 UTF-8、BOM 与 NUL 各有专用诊断码，位置指向出错字节。
- 装载只读源文本与语法树，不 import 语义、IR 与驱动。

交付回执：

- 新包 `module-loader` 落三层：`api/source` 判源文本、`api/unit` 建编译单元、`api/load` 出源集与单元；`_internal/walk` 管扫描规则，`_internal/sort` 管字节序。
- 扫描规则做成纯函数：点前缀条目整棵跳过、`_` 前缀照常收、只认 `.pini` 后缀、子目录自带 `pini.toml` 即整棵让给嵌套包、清单的 `[build] exclude` 按包根相对路径判前缀。测试直接喂名字与布尔，不造目录树。
- 收集与装载分成两层：`collectTarget`/`collectPackage`/`collectWorkspace` 只碰文件系统并按路径去重排序，`loadTarget`/`loadPackage`/`loadWorkspace` 在其上解析。同一文件被库与测试两个 target 各收一次时只留一份。

- 对自举工作区跑检查零诊断，退出码为零。
- 跨包公开调用成功，跨包遮蔽与各级可见性收紧各有正负语料。
- 跨包引用内部实现、引用未声明依赖、接口漂移各自报专用错误。
- 同一工作区在包图顺序变化时，诊断序列逐字相同。
- 删除某包的内部实现细节后，该包接口文本不变，下游不因接口变化被判失效。
- 每个子批次的原生测试进入 CI，与前六个包的门禁同形。

### IR 与后端接缝

交付：

- `ir` 的节点、降载、份额、布局消费和结构校验。
- `backend-kit` 的后端接口、能力声明、目标描述和统一发射结果。
- 所有未支持节点显式报出能力缺口，不用零值占位伪装实现。

验收：

- IR 校验双向报告“有节点无契约”和“有契约无实现”。
- 语义与 IR 不包含 LLVM 名称、指令或目标布局判断。
- 一个最小第二后端可只实现 `backend-kit` 接入，不修改语义和 IR 公共接口。

### LLVM 与驱动装配

交付：

- `backend-llvm` 以 `ByteBuilder` 发射类型、声明、函数体、复制与释放胶水。
- `runtime-api` 与 C 侧符号清单一致，经现有运行时完成链接和执行。
- `module-loader`、语义、IR、后端在 `driver` 中装配；CLI 只是驱动库入口的薄包装。
- `stdlib` 由驱动按语言规则装配到用户模块，编译器包不反向依赖它。

验收：

- 发射产物通过 LLVM 校验、链接和执行。
- 每个 IR 节点同时有文本形状判据与运行行为判据。
- 相同输入重复发射逐字节相同，文件顺序与字典插入顺序变化不影响结果。
- `runtime-abi` 检查、后端能力检查和包依赖检查全部进入常态门禁。

### 自洽验收

构建链固定为：

```text
当前宿主 → 首代自产 → 次代自产 → 三代自产
```

验收分为两层，不互相替代：

- **自洽**：首代自产编译完整多包工作区得到次代自产；次代自产能编译规范语料并通过全部行为测试。
- **不动点**：次代自产与三代自产分别编译同一工作区，所得 LLVM 文本逐字节相同；两代可执行文件通过同一套测试。

另需验证：

- 全量规范语料包含合法、非法、Unicode 安全、路径、诊断、包构建和确定性用例。
- 自举门禁进入 `ci/entrypoint.sh`，宿主 ABI、包语义或语言语义变化时必须复跑。
- 记录各代构建时间、峰值内存和产物大小；先建立基线，再设置回归阈值，不预编性能数字。

### 增量与工具演进

自洽之后沿既定包边界增强，不做二次架构迁移：

- `package` 增加接口缓存、增量重编与并行构建，调用方不变。
- `testkit` 在既有测试函数闭环上扩展夹具协议、差分和确定性乱序测试，不另建第二套测试框架。
- 若需要自举 CLI 自己调用 `clang`，再设计语言级进程原语与非零退出。
- formatter、语言服务和调试器进入各自的 `tooling` 包，不扩张驱动职责。
- 新后端只实现 `backend-kit`，运行时替换只改变 `runtime-api` 背后的实现。

## 风险与控制

| 风险 | 控制 |
|---|---|
| 为赶进度重新合并成总包 | 工作区硬门直接拒绝未声明依赖和内部引用；每批复核包图 |
| 包接口泄漏内部布局 | 导出接口只含必要声明，接口快照和跨包测试共同检查 |
| 整图构建固化为永久形态 | 产物身份从第一批定义，后续只替换 `package` 的调度与缓存 |
| 字节、标量、字素下标混用 | 不同封装类型，公共接口禁止裸整数跨域传递 |
| Unicode 数据膨胀与平台漂移 | 固定版本、生成有序表、构建期不联网 |
| 混淆规则误伤中文或合法混写 | 骨架只诊断不查找，高风险集合由真实语料钉定 |
| 未实现构造被静默写成零值 | 降载和发射 fail-loud，结构校验与行为测试同时存在 |
| 输出顺序导致不动点漂移 | 所有对外产物显式排序，并加入乱序输入对照 |
| 宿主和自举的标识符语义分叉 | 规范先改、同批落地、共享语料；查找键只用 NFC，原始拼写不进比较 |
| 语法树缺口被静默降级 | 语义层只检查语法树里存在的节点；缺的构造在计划里明列并归语法补面，遇到即报语法错误，不发明节点 |
| 语义与降载各写一遍类型判定 | 类型判定只在降载期，语义层对外只有类型模型、布局与解析表 |
| 临时内建扩散成永久语言面 | 只准 `temp` 前缀，逐条登记退出条件；正式能力落地时整组移除 |
| 规范承诺的构造未实现（`as` 转换） | 编译器源码只用已实现入口；补 `as` 前由 `tempByteToInt` / `tempIntToByte` 承担 |
| 枚举项与顶层声明同处一个全局名字空间 | 降载期按裸名解析 case；跨包重名报歧义，注册面暂只判顶层与成员，枚举项的重名留给类型面统一登记 |
| 解析吞吐不足以支撑全量自解析基线 | 判据分层：收集层覆盖全量，解析零诊断抽样；吞吐本身单列为性能项，不用「减少判据」冒充完成 |

## 开工入口

**工作区奠基**、**测试函数闭环**、**`support` 首批能力**、**`unicode` 解码分类**、**`unicode` 规范化与骨架**、**`diagnostics` 诊断模型**与 **`syntax` 语法层**均已交付：分别以拓扑构建与包边界、工作区级红绿判据、字节缓冲与源行表、UTF-8 解码与标量分类、NFC 与混淆骨架、诊断模型与确定性渲染、字节级词法与递归下降解析的双通道测试为证据。

**标识符身份**、**清单面**、**装载面** 与 **注册面** 已交付：分别以规范条款与词法判据、TOML 收集与构建计划、源集收集与编译单元、符号表与四类冲突判据为证据。下一批从 **类型面** 开工：类型池与下标身份、六类标注解析、等价与可赋值关系、规范化文本。其后是 **表达式面** 与 **语句面** 补全检查并产出名字解析表，**布局面** 给出尺寸与偏移，最后 **装配面** 把整条链接到工作区根上。跨包只消费导出接口，跨文件信息在语义层统一装配；`syntax` 的节点池与类别码是这一层的输入。每项能力先写公开行为测试、确认红，再最小实现转绿。

语法树尚未表达的构造不进入本批检查面，单列语法补面批次：特征声明、导出块、给定块、外部块、`unsafe`、`as` 转换、`try` 与异步表达式、插值括号内的子表达式、遍历步长、标签控制流，以及宿主侧中文词表入口。代码层另有三处写法在自举里不可用，同步归入该批次：一次返回多个值、跨包引用限定枚举值、跨包名相同的顶层函数。`as` 转换在补齐之前仍由临时数值桥承担。
