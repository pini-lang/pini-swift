# Pini 自举终态架构与实施计划

## 目标与边界

目标是用当前语言实现一个新的 Pini 编译器，使它能够编译自身，并在连续自产之间达到确定性不动点。

自举验收必须同时满足：

- 编译器源码全部由 Pini 书写；脚本只负责构建编排、进程调用与产物比较，不承载编译逻辑。
- 工作区、包清单、依赖图、源码装载、语法、语义、IR 和 LLVM 文本发射均由自举实现。
- 首代自产能编译完整工作区并得到次代自产，次代自产能够运行。
- 次代自产与三代自产对同一输入生成相同的确定性 LLVM 文本。
- 合法与非法语料均以语言参考、IR 契约和手写期望为判据，不以宿主输出代替规范。

下列事项不阻塞自举验收：

- 用 Pini 重写运行时。当前 `PiniRuntime` 继续经 C ABI 复用，运行时替换单独立项。
- 用 Pini 启动 `clang`。构建脚本负责调用外部 LLVM 工具，进程原语只在替换完整 CLI 时补。
- 用 Pini 重写 C 头文件翻译器，或让自举驱动器执行 `pini bind`。翻译器是宿主工具，自举只按计划消费生成物。
- 在自举侧求值手写块的 `|macro`。宏值要 C 预处理器，自举不启动 clang；求值结果随构建计划带出，没有计划条目的宏按能力缺口报出，不静默当成缺符号。
- 自举侧实现 `|c` 导出面与共享库产物。编译器自身不发布 C 面，语法层只保留解析，语义与发射等有消费方再立批次。
- 远程包下载、包仓库、LSP、调试器、REPL、embedded 后端和完整工具链替换。
- 为追求宿主 LLVM 文本一致而引入与规范无关的约定。

本地多包工作区、包可见性、外部符号的包级可见性和依赖构建不是可选扩展，而是本计划的编译器基础能力。

## 筹划载体

所有架构决定、实施批次、验收判据、风险和后续调整只在本件内维护，不另立专题计划件。各批次的实际代码、测试夹具、构建产物与验证日志属于交付证据，不属于新的筹划载体。

读数口径：件内的测试项数、耗时与吞吐数字都是易腐记录，只回答「当时差多少」，不承担长期参考价值。机器、构型或测试集一变，须整组重取，不拿旧数字补新差；需要长期基线时按 **解析吞吐与栈深** 的测量口径另立读数件，并同样标明易腐。实施批次的回执只记「做了什么、判据是什么、边界与教训」，逐批累计的读数已按此口径删去，只保留改变过判断的那几处量级；要读数时由 `driver lower` 与各门禁重取。

外部 C 互操作的语言面语义归 `docs/spec/pini-reference.md` 与 `docs/spec/c-interop-design.md`；本件只承载自举侧的批次、判据与风险。三个来源的分工、构建期生成、符号裁决与链接口径按这两份文件执行，本件不复述。

工作区奠基之后立即打通测试函数闭环。后续包不得等到功能完成后再补测试，统一按“先写失败测试、确认红、最小实现、确认绿、重构并复跑”的循环推进。

## 现况缺口

当前宿主已经提供可复用的种子、C ABI 运行时、LLVM 工具链、语言参考、IR 契约和测试门禁。自举真正缺少的是以下底座：

- **工作区与包构建**：需要让多个独立包按公开接口协作，而不是把源码放进一个总包后依赖目录约定维持分层。
- **文本底座**：用户层 `String` 的长度、下标和切片按字素工作；编译器需要稳定的 UTF-8 字节区间、标量解码和线性扫描。
- **符号身份**：规范给出了标识符的 Unicode 字符类别，但没有完整规定规范化、等价拼写和混淆冲突。
- **稳定装配面**：需要明确哪些类型属于包间契约，哪些只是包内实现；后续增量构建、格式化、语言服务和新增后端都依赖这一分界。
- **外部符号与构建脚本**：宿主已把 C 头文件翻成外部块、把 `build.pini` 折成构建计划，并让外部符号在包级可见；自举侧没有 `[名称|foreign]` 块，没有 `[ffi]` 清单，也没有生成模块的装载面。

## 架构原则

- **先定终态，再切批次**：任何功能直接进入最终归属包，不先放进总包再迁移。
- **包边界由编译器执行**：公开接口、包可见性和依赖方向必须由构建系统检查，不靠命名习惯或审查记忆。
- **接口与实现分离**：跨包只暴露值、类型、函数和错误契约；内部数据结构、遍历顺序和发射细节不得泄漏。
- **单向依赖**：基础包不认识编译器，语义不认识后端，后端不反向读取 AST，驱动是唯一编译器装配点。
- **无空壳包**：尚未实现的功能不建立占位 API；创建包时必须交付真实能力和测试，但目录规划从第一批就固定。
- **生成物即构建产物**：翻译结果落构建目录并由计划登记；源码树不出现生成文件，装载面只认计划里的路径。
- **中间形态不改终态边界**：早期可以整图一次性构建，后期再改增量构建；两种形态都使用同一包结构和公开接口。

## 终态目录

```text
bootstrap/
  pini.toml
  packages/
    support/
    unicode/
    diagnostics/
    syntax/
    semantics/
    ir/
    backend-kit/
    backend-llvm/
    runtime-api/
    package/
    module-loader/
    driver/
    testkit/
  stdlib/
    pini.toml
    src/
  tooling/
    formatter/
    language-server/
    debugger/
  tests/
    architecture/
    integration/
    conformance/
    selfhost/
  runtime/
    abi/
  tools/
  .build/
```

根 `pini.toml` 是工作区清单，不是把全部源码装在一起的包清单。它登记成员包、构建 profile、共享 LLVM 与运行时配置，以及测试目标。工作区语法是待实现的构建能力，实施时先进入构建规范，不能由脚本私下解释一套未登记格式。

### 包内统一形态

每个生产包使用同一结构：

```text
packages/<包名>/
  pini.toml
  src/
    api/
    _internal/
  tests/
```

- `api/` 是包间契约，只放公开类型、公开入口和导出声明。
- `_internal/` 是包内实现，其他包不可见；包内测试可以贴近实现，跨包测试只准走 `api/`。
- `tests/` 是测试 target，不进入普通库产物。工作区需要明确库、可执行文件和测试三类 target，不能用排除目录的临时技巧代替。
- 包清单显式列出本地依赖；未声明依赖的包即使源码可见，也不得被引用。

### 各包职责与允许依赖

| 包 | 职责 | 允许依赖 |
|---|---|---|
| `support` | 字节缓冲、切片、源码文本、区间、符号驻留、确定性容器、通用结果与错误 | 无包内依赖，只依赖语言与运行时基础 |
| `unicode` | UTF-8、标量分类、NFC、混淆骨架、Unicode 数据表 | `support` |
| `diagnostics` | 诊断码、严重级、源码位置、标签、修复建议、渲染 | `support` |
| `syntax` | 记号、AST、词法、语法、源码打印所需的语法信息 | `support`、`unicode`、`diagnostics` |
| `semantics` | 作用域、符号、类型、声明注册、可见性、外部符号裁决、类型检查、类型布局 | `support`、`syntax`、`diagnostics` |
| `ir` | IR 节点、降载、份额、布局消费、外部符号节点、结构校验 | `support`、`syntax`、`semantics`、`diagnostics`、`module-loader`、`unicode` |
| `backend-kit` | 后端接口、能力声明、目标描述、发射结果与后端注册接缝 | `support`、`ir`、`diagnostics` |
| `backend-llvm` | LLVM 类型映射、文本发射、复制与释放胶水、外部符号发射、目标产物 | `support`、`backend-kit`、`runtime-api` |
| `runtime-api` | 运行时段符号、C ABI 声明、句柄与桥接能力清单 | `support` |
| `package` | 工作区与包清单、`[ffi]` 库绑定与头文件集合、target、依赖图、构建脚本步骤与计划、拓扑排序、产物身份 | `support`、`diagnostics` |
| `module-loader` | 从构建计划读取源码（含计划登记的生成模块）、规范化和解析，形成语法层编译单元 | `support`、`package`、`syntax`、`diagnostics` |
| `driver` | 编译器库入口与 CLI，装配装载、检查、降载、测试执行、后端和输出 | 上述编译链各包与 `testkit`，禁止反向被依赖 |
| `testkit` | 测试发现、筛选、顺序、执行器接口、结果报告、夹具协议与确定性乱序测试 | `support`、`syntax`、`ir`、`diagnostics` |

依赖图必须保持无环。`package` 不认识 AST，`module-loader` 不做类型检查，`semantics` 不读文件，`ir` 不调用 LLVM，`backend-llvm` 不解析源码，`driver` 不拥有各层内部规则。

### 标准库、工具与测试的位置

- `stdlib/` 是独立源码包，由驱动按语言规则装配到用户模块；编译器各包不得通过反向 import 获取它。
- `tooling/formatter` 只依赖 `syntax`、`support`、`diagnostics`，不得为了复用 CLI 而依赖 `driver`。
- `tooling/language-server` 可以依赖 `syntax`、`semantics`、`module-loader`，不得依赖 LLVM。
- `tooling/debugger` 通过独立调试接缝消费源码映射，不进入编译主依赖链。
- `runtime/abi/` 保存 C 侧契约与链接元数据；Pini 侧声明只归 `runtime-api`，避免两套符号清单漂移。
- `tests/architecture/` 检查包依赖、公开接口和禁止引用。
- `tests/integration/` 覆盖多包构建、缓存、增量重编和诊断。
- `tests/conformance/` 保存语言正负语料与手写期望。
- `tests/selfhost/` 保存自洽、不动点和确定性验证协议。
- `tools/` 只保存构建与测试编排，不放任何生产编译逻辑。

新增后端只新增实现 `backend-kit` 的包，并在驱动注册；不得把目标判断散落到 IR 或语义层。新增工具只进入 `tooling/`，不得把命令实现堆回 `driver`。

## 工作区与构建契约

### 包接口产物

每个库包在逻辑上生成三类产物：

- **导出接口**：公开声明名、函数签名（参数名与类型、返回类型）、类型布局所需信息、依赖声明与包名。泛型实例化所需语义信息随类型面补面接入，依赖版本待包版本模型落地。
- **编译产物**：供链接或整图发射使用的 IR 与目标产物。
- **构建身份**：包源码、构建脚本与生成物、公开接口、依赖接口、语言配置和后端配置的内容摘要。

公开接口变化必须使下游失效；仅 `_internal/` 变化时不得要求下游重解析或重检查。早期尚未实现增量缓存时也必须按同一身份规则判断哪些步骤需要执行，不能靠时间戳猜测正确性。

### 构建形态演进

- 初期允许工作区整图装载、整图检查、整图发射，但包间仍只能读取导出接口。
- 随后增加按拓扑序的包产物和接口缓存，不改变包目录、调用方或依赖声明。
- 最后增加并行构建与远程缓存；它们都不属于自举验收前置。
- 任何阶段都禁止跨包读取 `_internal/`，禁止通过“先把源码并入同包”绕过可见性。

### 构建脚本与生成模块

`build.pini` 是声明文件，不是可执行脚本：每个 `[名称|given]` 块读成一条翻译步，块名即步骤名，字段固定为 头文件、包含路径与定义。声明式不是风格取舍，是“配置纯净”的现成形态——语言还没有计划对象的构造面，执行式配置要先补一个配置期内置与语义入口。

构建分两段：配置期只登记并产出计划，执行期才翻译、发射、链接。

- 计划是纯数据：`<根>/.build/<profile>/plan.toml` 记包根、脚本哈希、每条步骤的头文件与产物路径、输入指纹，以及 `|macro` 条目的求值结果。
- 生成物落 `<根>/.build/<profile>/packages/<包>/generated/<步骤名>.pini`，归声明它的包；步骤名须是合法的路径分量且在包内唯一。
- 单一装载入口：计划缺失、脚本哈希不符、产物缺失各报一条指向 `pini build` 的诊断，不静默跳过。
- 路径白名单：只接受以 `.build` 组件开头且登记在计划里的产物路径，其余一律拒绝。
- 确定性：同一输入两次构建的计划与生成物逐字节相同；指纹含头文件与整棵包含树、包含路径、宏定义、翻译器版本与目标平台。
- 跨包共用同一头文件时各翻一份：正确性不受影响，多花的是翻译时间；去重的前提是落点与包名解耦。

注意 计划是数据不是代码：`check`、`run`、`test` 只读计划，绝不执行 `build.pini`。脚本写坏只影响 `build`，不会让整个仓库的检查一起红。

### 架构硬门

工作区构建器直接依据依赖图执行以下判据：

- 未声明依赖、反向依赖、跨包内部引用、循环依赖均为构建错误。
- 包公开接口与导出接口产物必须一致，接口变化必须触发对应下游重建。
- 同一包不能同时以源码路径和另一种包身份进入同一张图。
- 构建、测试和自举三代链共用同一依赖图，不允许脚本另排一套包顺序。
- 生成物路径越出 `.build` 前缀，或未登记在计划里，均为装载错误；构建只写构建目录，不写源码树。

## 文本模型

采用**字节编译内核**，严格分开三个文本域：

| 文本域 | 用途 | 禁止事项 |
|---|---|---|
| UTF-8 字节 | 源码保存、ASCII 记号、关键字、区间、LLVM 文本 | 不得把字节下标当用户字符下标 |
| Unicode 标量 | UTF-8 校验、标识符分类、转义解码、规范化 | 不得把标量序号当字节偏移 |
| 字素簇 | 现有用户层 `Char` 与 `String` 行为 | 不得用于词法游标和源区间 |

核心类型按最终包归属：

- `support.ByteBuffer`：持有完整 UTF-8 字节，不支持隐式字素解释。
- `support.ByteSlice`：保存缓冲区身份、起点和长度，切片不复制。
- `support.SourceText`：持有规范化后的源码、文件名和逐行起点表；`Span` 一律是字节区间。
- `support.ByteBuilder`：线性追加 ASCII 与 UTF-8 字节，供诊断和 LLVM 发射使用。
- `unicode.UnicodeText`：包装需要标量分类或规范化的小段文本，不进入扫描热路径。

当前语言只需补两类内部桥接能力：把 `String` 的完整 UTF-8 内容复制成字节数组，以及把字节数组经 UTF-8 校验后组成 `String`。桥接经现有 C ABI 运行时实现并登记到 `docs/spec/runtime-abi.md`，不暴露指针算术，不改变用户层字符串语义。

词法器不得使用 `split`、`replace` 或字素下标扫描源码。标识符和字面量先记字节区间，确实需要内容时才切片；记号默认携带 `Span` 与符号编号，不携带整段复制文本。

## 标识符身份与混淆

采用**原始拼写保留、规范化负责身份、混淆分析负责诊断**的三轨模型：

- 原始拼写永远保留在 AST、符号声明和诊断中，不改写用户源码。
- 符号查找键使用 NFC 规范化结果；同一作用域内，原始拼写不同但 NFC 相同的声明按同一符号冲突处理。
- 规范化只在标识符上进行，不规范化整个源文件，字符串字面量和注释内容不受影响。
- Unicode 版本必须固定，字符类别、规范化与混淆表由受控数据生成 Pini 表并纳入版本控制；构建和运行不得依赖宿主操作系统的 Unicode 版本。
- 混淆骨架只用于安全诊断，绝不用于符号查找，避免把视觉相似误当成语言等价。

混淆策略不按“非 ASCII 一律危险”处理，中文标识符仍是正式能力：

- 对拉丁、西里尔、希腊等高风险混写给出错误；常用脚本与中文的合理组合不因混写这一因素被拒。
- 对同作用域内混淆骨架相同的标识符给出警告，并同时展示原始拼写和转义后的码点序列。
- 全角字母数字、数学字母数字、兼容等价拼写至少给出警告；是否提升为错误由语料门禁验证后固定。
- 标识符中的零宽字符、双向控制字符和不可见格式字符直接拒绝；注释与字符串中的双向控制字符给出明确警告。
- 无效 UTF-8、BOM 和 NUL 在装载期响亮拒绝。CRLF 归一化发生在词法之前，所有区间统一指向归一化后的 `SourceText`。

NFC 会改变符号身份，属于语言面决定。实施前先修订 `docs/spec/pini-reference.md`，宿主和自举同批对齐；若暂不采纳 NFC，则只能把规范等价冲突降为警告，不能暗中在自举符号表里做另一种查找语义。

## 受限源码约定

受限只约束编译器自身的写法，不压缩终态包结构，也不缩小编译器最终必须接受的用户语言：

- 使用结构体、枚举、数组、字典、函数、`match`、循环、`Result` 和显式类型标注。
- 泛型只保留容器与必要算法所需形式，避免把高阶类型推断扩散到编译器源码。
- 不使用结构化并发、`LazyRef`、弱引用与无主引用；外部声明只收标量、指针、`String` 形参与 `StringHandle`，不碰按值聚合。
- 本地多包、公开接口和包可见性属于必用能力，不得列入“以后再支持”。
- 公共声明显式写参数与返回类型，不依赖宿主推断细节。
- 不用字典遍历顺序决定输出。文件、声明、符号、诊断、类型布局和 LLVM 定义都显式排序。
- 不用宿主字符串优化、文件系统顺序或哈希种子作为正确性的前提。

用户语言覆盖按规范逐项回填，并为每个新增构造补正负语料。

## 实施批次

### 工作区奠基

交付：

- 在工作区与包构建规范中定义根清单、成员包、target、依赖图、导出接口和产物身份。
- 种子侧支持本地多包构建；自举 `package` 先实现工作区根探测，构建计划语义随后续批次在该包内扩展。
- 建立最终目录规范、包内 `api/_internal` 边界、测试 target 和架构硬门。
- 钉定标识符规范与字节转换 ABI。

验收：

- 两个最小库包和一个可执行包能按拓扑序构建，跨包公开调用成功。
- 未声明依赖、内部引用、循环依赖和接口漂移均被拒绝。
- 测试源码与非法夹具不会进入普通库产物。
- 不建立总包，不用脚本硬编码包顺序。

交付回执：

- 清单模型收 `[workspace]`/`[lib]`/`[[bin]]`/`[[test]]`，`WorkspaceBuilder` 统一出依赖图、拓扑计划、target 源码集与产物路径。
- `bootstrap/` 立三包；多文件 import 与嵌套 `_internal` 可见性按祖先目录算，测试 target 与生产源码隔离；门禁覆盖拓扑序与真实产物执行。
- 边界：仍是整图降载与链接，独立库链接、接口缓存与 `|test` 执行闭环留后续批次。


### 测试函数闭环

目标是在大规模实现语言特性之前，用一条最小但完整的垂直链路打通 Pini 测试函数。该链路直接落入终态包，不另建一次性测试编译器或旁路测试框架。

交付：

- `syntax` 支持 `|test` 声明与断言所需的最终 AST 形态，不引入新的测试 DSL。
- `semantics` 注册测试函数，检查断言语句的条件与消息类型，并保留测试来源信息。
- `ir` 携带测试元数据与断言节点，测试入口和普通函数入口保持明确分界。
- `backend-llvm` 先实现测试函数、断言、报告和退出状态所需的最小发射面，失败不能静默变成成功。
- `testkit` 提供测试发现、筛选、确定性顺序、执行器接口和统一结果报告；执行器由驱动装配，不让测试框架反向依赖 CLI。
- `driver` 提供最小测试入口，复用同一工作区依赖图和包可见性，不为测试另排构建顺序。

后续所有包执行同一 TDD 循环：

```text
写公开行为测试 → 运行并确认失败 → 最小实现 → 运行并确认通过 → 重构 → 全量复跑
```

包内实现细节可以补内部测试，跨包行为只准通过公开 API 测试。修复缺陷时先加入能复现缺陷的失败测试；增加能力时先写判别式与至少一条反例，不接受只验证实现能够执行的冒烟测试。

验收：

- 一个通过用例、一个失败用例和一个包含多个测试的文件能够验证发现顺序、报告、后续测试继续执行及最终退出状态。
- 故意撤掉断言失败处理或测试注册时，门禁必须转红，证明不存在假通过。
- 测试筛选、测试乱序输入和重复运行不改变结果；标准输出、标准错误与退出状态均有手写期望。
- 后续 `support`、`unicode`、`diagnostics` 的首批测试由这条链执行，TDD 循环不依赖尚未实现的其他语言特性。

交付回执：

- 工作区测试链接通：`WorkspaceTestRunner` 按包拓扑序与 `[[test]]` 出现序展开，逐 target 过门禁后收集 `|test`；`pini test` 支持 `--filter`。
- 空跑不能读成通过：收不到 `|test` 与筛选零命中一律非零退出；测试体以工作区根为进程目录，`moduleRoot()` 仍答所属包根。
- 专项测试钉住通过、失败、筛选、空 target 与拓扑序；工作区级原生聚合未接线，暂由解释器通道承担 TDD 循环。


### 基础包落地

交付：

- `support` 的字节缓冲、无拷贝切片、源码行表、字节构建器、符号驻留和确定性容器。
- `unicode` 的 UTF-8、标量分类、NFC、混淆骨架和可复现数据表。
- `diagnostics` 的诊断模型、位置映射和纯数据渲染接口。

验收：

- 覆盖 ASCII、中文、组合字符、全角、数学字母、高风险混写、零宽字符、双向控制、非法 UTF-8、BOM、NUL、CRLF。
- 每个扫描例核对消费字节数，不允许结果正确但游标错位。
- 大输入扫描和发射不出现逐字切片或反复整串复制。
- 三个包都能独立构建和测试，不 import 任何上层编译器包。

交付回执（support）：

- `ByteBuffer`/`ByteSlice`/`ByteBuilder`/`SourceText`/`StringTable` 落地，覆盖字节缓冲、切片、构建器、源行表与符号首次出现定序。
- 同批修 LLVM 的 U8/I8/I64/U64 数组元素 ABI、U8 打印零扩展与无符号谓词；注释与格式门禁扫描根加入 `bootstrap`。
- 边界：`as` 转换未实现，字节换算由 `temp` 前缀临时内建承担，正式字节文本面落地时整组移除。


交付回执（unicode）：

- 生成器与数据版本钉在 Unicode 15.1.0；解码六类错误保留出错前的标量，编码与之往返，分类表按分段判定答字母/数字/空白。
- 规范化与骨架同批：表用「池 + 打包下标」，字节进出；同批修三个宿主缺口（隐式导入只注名字、泛型数组元素类型、数组 ABI）。
- 边界：`as` 仍由临时数值桥承担；词法转义改按簇首标量识别，修掉 `\t` 后接组合符被粘成一簇的缺陷。


交付回执（diagnostics）：

- 五个类型与 99 条码表随包提交，码表由主机资源生成；位置映射按 Unicode 标量计列，落在多字节中间时回退到标量起点。
- 确定性由全序保证：文件、锚点起终点、码、消息逐级比较；渲染头行形状固定，找不到源文本时退化为无位置头行。
- 同批修宿主「成员访问只对 identifier 接收者递归」的缺陷，`f(x).字段` 的实参不再逃过检查；本包只承载模型与渲染。


### 语法包贯通

交付：

- `syntax` 的记号、AST、词法、递归下降解析器和语法层源码信息。
- 缩进、括号、块声明、字符串插值和运算符优先级按语言参考实现。
- AST 使用显式节点枚举与稳定字段，不依赖反射、动态分派或宿主类型身份。

验收：

- 合法夹具得到预期结构，非法夹具得到预期诊断码和源码位置。
- 畸形输入必须终止；未闭合插值、缩进错乱和括号失衡均有超时判据。
- 诊断展示原始拼写，安全诊断能展示码点。
- `syntax` 测试不依赖语义、IR 或驱动。

交付回执（syntax）：

- 包分记号、关键字、词法、AST、解析五面：词法按字节推进、缩进栈只在行首比较、括号内抑制换行；AST 用四个节点池加子节点下标。
- 类别判定一律比类别码，不用枚举相等 —— 两通道的 `==` 都不可用；语法诊断继承码表；Unicode 数据门禁改为比对登记摘要。
- 自解析用例读本包五个源文件并核对零诊断；同批修格式化器把 CRLF 当一簇转义的宿主缺陷；插值段与控制流糖留待补面。


### 语义与装载分工

本批从零建立语义与装载两层。为使每一步都有可读的红绿判据，按能力拆成九个子批次，全部直接落入终态包，不建一次性旁路。每个子批次按既有循环推进：先写公开行为测试、确认红，再最小实现转绿，实施后在其节内补交付回执。

依赖顺序：标识符身份先立规范与查找键，其后是清单面、装载面、注册面、类型面；表达式面与语句面共用类型面产出的类型池，语句面复用表达式面的作用域链与解析表；布局面消费类型面与形态表；装配面把其余各面接成一条链。类型面与布局面之间没有相互前置，可以并行。

判据纪律：验收只认语言参考、IR 契约与手写期望。宿主输出可以用来定位差异，但不得作为门禁判据 —— 诊断消息的措辞与位置粒度会随实现漂移，把宿主文本当期望，门禁测到的就是无关差异。

本批决定（表达式面开工前复核：两条保持、一条调整、一条新增）：

- **查找键归语义层**：`support` 的符号驻留只保存原始拼写；依赖方向不允许 `support` 反向认识 `unicode`，故 NFC 键由语义层的符号表以字节序列自持。规范化的输入是标识符在源内的区间，不是整份源码。
- **类型判定归语义层，IR 只做类型映射**：原条「语义层不出定型结果」按字面会把成员、实参与运算判定推到 IR，表达式面在语义层无法验收，同一套规则也要写两遍。现改为：语义层产出 Pini 类型表（表达式节点 → 类型池下标）与名字解析表；IR 只把类型池下标映射成 `IRType` 并决定资源动作，不重跑检查规则。原条保留在此作追溯，不再作为实现依据。
- **身份先用结构化文本**：构建身份由成员与 target、入口、源码相对路径与字节数、接口文本拼成可比较的文本。摘要算法留给增量批次替换，调用方不变。
- **布局以槽为单位**：语义层只给槽布局（对象头四格、字段槽位、枚举标签与载荷槽、`Result` 三槽、`Optional` 两槽）；字节尺寸、对齐与字节偏移归 `backend-kit` 的目标描述，布局段只带槽位与字段序，签名另成一段。原「尺寸、对齐与字段偏移」中的字节口径据此收窄。

#### 标识符身份

交付：

- 语言参考的标识符一节补四类条款：符号查找键取 NFC 规范化结果；原始拼写全程保留在语法树、声明与诊断里；混淆骨架只用于诊断、不参与查找；全角字母数字、数学字母数字与兼容等价拼写至少告警。
- 不可见字符策略落地：标识符中的零宽字符、双向控制字符与不可见格式字符直接拒绝；注释与字符串中的双向控制字符给出警告。
- 宿主符号表与自举符号表同批改为 NFC 查找键，共用一份正负语料。
- 混写按脚本分组：拉丁、西里尔、希腊之间的高风险混写报错；中文与常用脚本的合理组合不因混写被拒。

验收：

- 同一作用域内 NFC 与 NFD 的两种写法按同一符号冲突处理，渲染时都显示原始拼写。
- 中文标识符、组合字符、全角字母与数学字母各自的判定与规范一致。
- 零宽字符与双向控制字符在标识符位被拒、在注释与字符串位只告警。
- 混淆骨架相同的标识符给出警告，不触发查找失败。
- 组合附加符号可作续字符、不得作首字符，宿主与自举判定一致。

交付回执：

- 参考件补符号身份、原始拼写、不可见字符、混淆与混写五段；词法增三条错码，零宽、双向控制、起始 BOM 与簇内变体选择符一律拒绝。
- NFC 查找键两侧就位，组合附加符号对齐 Swift 与 UAX31；混淆告警与混写判定按三个高风险脚本落地，数据只有一份来源并登记摘要。
- 边界：自举侧的字符串告警只覆盖字面段；续字符只认四个组合标记区块，混写只认拉丁、西里尔与希腊三个脚本。


#### 清单面

交付：

- `package` 实现清单两级收集：平表、点分子表、数组表、内联数组与引号感知注释；形状非法时按清单错误报出，不静默取默认值。
- 工作区、包与 target 三个模型落地；成员、包名、target 名与入口的校验全部在生成构建计划之前完成。
- 依赖图从成员的声明依赖生成，拓扑序按包名定序；成环时报出完整链条。
- 构建计划按包给出 target、源码集与产物路径；产物路径在 profile 下确定，判定不读时间戳。

验收：

- 自举工作区根清单解析出全部成员与固定拓扑序，重复执行结果逐字相同。
- 重复包名、越界成员、非法入口、重名 target、成环依赖各自报专用错误，错误里带具体包名与 target 名。
- 成员未声明 target 时被拒绝，不退化成一个隐式包。
- 构建脚本不参与包排序，计划完全由清单与依赖图决定。

交付回执：

- `package` 拆四层（`toml`/`manifest`/`plan`/`layout`）；校验分两段：包内规则在解析期，跨包规则在装配期。
- 拓扑序按包名升序深度优先、依赖同样升序，用具名帧而非递归；构建计划按包给 target、源码根与三类产物路径，`profile` 只改目录。
- 顺带修宿主 `IRType.typeAnnotation` 对名义类型返 nil 导致局部类型串味的缺陷；符号链接与 `[resources]` 等字段留后续。


#### 装载面

交付：

- `module-loader` 从构建计划取 target 的源码集：递归扫描，点前缀目录整棵跳过，嵌套清单下的源码不进父包，清单声明的排除项生效。
- 目标源码按 UTF-8 字节序排序后读取，结果与文件系统返回顺序无关。
- 装载期一次性规范化：非法 UTF-8、起始 BOM 与 NUL 直接拒绝；CRLF 归一为 LF，此后所有区间指向同一份源文本。
- 解析结果与词法问题一起构成编译单元：源文本、相对路径、语法树与诊断各自可分。

验收：

- 全量自解析基线先行：装载自举全部包的源码，诊断集合为空。基线若出现解析缺口，先补语法包，不把缺口写进装载面的通过条件。
- 同一 target 的源码以不同文件系统顺序给出时，编译单元的诊断序列与树结构逐字相同。
- 非法 UTF-8、BOM 与 NUL 各有专用诊断码，位置指向出错字节。
- 装载只读源文本与语法树，不 import 语义、IR 与驱动。

交付回执：

- 三层公开面（源文本、编译单元、装载）落地；扫描规则做成纯函数：点前缀跳过、`_` 前缀照收、嵌套包让路、排除项按前缀判。
- 收集与装载分层、按路径去重排序；源文本判定走字节步进（BOM、逐标量合法性、NUL 一次判完），不用字符串层判 NUL。
- 七类装载错误各有类别名；全量解析基线超出 CI 时间预算，未完成，判据分层见吞吐批次。


#### 注册面

交付：

- 语义包建立符号表与作用域栈：名字经 NFC 键驻留，符号记录种类、可见性与定义位置。
- 结构、对象、枚举、扩展、函数与测试声明、变量、导入块与导入项、字段、参数、变体各类声明的注册。
- 冲突判定：同作用域重声明、类型成员同名、导入别名与本地符号相撞、跨文件同名顶级声明。
- 可见性按 `_` 前缀四级推导，包级索引据此回答跨文件可见性。

验收：

- 自举既有包注册零错误。
- 同一包以不同文件顺序注册，符号表内容与冲突诊断的排列逐字相同。
- 重声明、类型成员同名、别名相撞、跨文件重名各自报专用错误，位置指向声明头。
- `_` 前缀在符号、文件名、目录三个层级上的收紧效果各自可判。
- 注册只读语法树与源文本，不做类型判断。

交付回执：

- 四处公开面落地：符号与可见性、三层存放与判重、声明遍历注册、错误面；判等与查找只用 NFC 字节键，原始拼写只随诊断带出。
- 四类冲突各有类别名，扩展块同名按后声明者覆盖；可见性按符号、文件名、目录链三级收紧，工作区注册按拓扑序逐包追加。
- 顺带修 `Ast.items` 漏收类型与导入块、`loadPackage` 按 target 合并两处缺陷；枚举项与顶层同处一个名字空间的边界留到类型面。


#### 类型面

交付：

- 类型池与下标身份：标量、指针、结构、对象、枚举、元组、集合、可选、结果、函数与泛型实例各成一类，递归结构用下标表达。
- 具名、泛型实参、可选、指针、元组与函数六类类型标注的解析。

验收：

### 语法补面

语法树的缺口不并入其他批次的检查面，单列本批，并前移到 **装配面** 收尾之前。理由是后续各层都指望「工作区级零诊断」作基线，缺口存在时这条判据只能抽样；补面之后判据面才完整，全量执行仍受吞吐批次约束。

本批的现况与原先记载不同，按词法与语法两处实物核对后可钉成一句：**宿主已实现的构造远多于自举**。本批列出的构造在宿主的记号表、AST 与解析器里都有对应物 —— 特征声明与特征体、导出块、给定块、外部块、结构泛型头、内嵌组合、`实现` 行、`try` 表达式、`unsafe` 前缀、`unroll` 展开器、标签控制流、插值段子表达式、`=>` 箭头，以及 `[T,]`、`{T,}`、`{K: V,}`、`^T` 四类类型写法；`as` 转换的五层实现也在宿主侧贯通。因此本批全部是 **自举追平宿主**，判据可以拿宿主做结构对照，两侧都缺的构造为零。

这个事实同时改写风险面：追平类是「按既有实现补齐加差分判据」，不涉及语言面重新裁量；`as` 的期望仍按参考件的条款写，宿主实现只作结构对照，不当判据。

依据可以逐条复核：自举关键字表收满 34 个词条，而解析器只按类别引用其中二十四个。差额十个里，`try`、`await`、`wait`、`unsafe`、`detach`、`capture`、`unroll`、`export` 是缺口；`enum` 与 `object` 只在修饰符位按标识符文本比对，不按类别分派，不算缺口。宿主侧对应的定义在 `Sources/PiniSyntax` 的关键字表，以及 `Parser.swift` 的 `parseTraitDecl`、`parseStructDecl`、`parseDefer`、`parseTypeAnnotation`；自举侧的现状在 `bootstrap/packages/syntax/src/api` 的四个类别池与解析器引用集。这条判据只比「词条有没有被解析器消费」，不依赖任何一方的诊断措辞。

交付：

- 转换：`as` 的中缀形态、目标类型解析、与数值提升的分工，宿主与自举同码同义。
- 类型写法：`[T,]`、`{T,}`、`{K: V,}`、`^T` 四种类型位写法，以及它们与行首声明分派的互不干扰。
- 错误处理：`try` 的语句位单行、语句位块与表达式位三形态，`^右值` 解包糖脱糖为 `try 右值 else err: return err`。
- 声明块：特征声明与特征体、特征扩展块、导出块、给定块、外部块与外部符号的三个修饰。给定块同时是 `build.pini` 的读取入口，字段初值即翻译步参数。
- 声明头：类型参数的声明位置、内嵌组合行、`实现` 行。
- 语句：标签控制流（`标签|if`、`标签|while`、`标签|for` 与 `break 标签` / `continue 标签`）、`capture`、`unroll`、`defer` 相邻单行形式。
- 前缀：`unsafe` 表达式。外部调用一律要求它，故与外部块同一份语料验收。
- 异步：`=>` 函数声明与函数字面量、`await` / `wait` 前缀、`detach` 语句。
- 字面：插值段内的子表达式、字典条目类型位 `{键: 类型 = 值,}`。

子批次按依赖顺序：

- **转换面**：先落 `as`。它是 `tempUtf8Bytes` / `tempByteToInt` / `tempIntToByte` 三条临时内建的正式替代；宿主侧五层已贯通，自举侧照此追平。参考件的显式转换条款已给出三条约束——仅数值类型之间、指针转换须在 `unsafe` 上下文、窄化按截断——照此实现即可；条款若有歧义（跨族转换、溢出表现）就地补写，不另立设计。正负语料两侧同批，它同时是第一条按宿主结构逐层对照的三通道判据。
- **类型写法面**：四类类型写法。行首的 `[` `{` 归声明分派、类型位的同一记号归容器，两条判据分开写，不复用行首规则。
- **错误处理面**：`try` 三形态与 `^` 解包。`^` 在类型位是结果糖、在右值位是解包糖，两条判据必须同批，否则同一记号会在两处给出不一致的接受面。
- **声明块面**：特征声明、特征扩展、导出块、给定块与外部块共用一张块头分派表，一次改完再逐类落语料；`unsafe` 前缀同批，外部调用离不开它。
- **声明头面**：类型参数声明、内嵌组合行、`实现` 行。三者都改声明体的读取循环，合并以免三次改同一段。
- **语句补面**：标签控制流、`capture`、`unroll`、`defer` 单行。标签同时进语句分派与跳出定向两处；`capture` 进函数字面量体；`unroll` 与既有展开语义对齐。
- **异步面**：`=>` 与 `await` / `wait` / `detach`。受限源码约定禁止结构化并发，自举源码不用这几项，故列末位，不阻塞自举，也允许单独切出。
- **字面补面**：插值段子表达式与字典条目类型位。前置是表达式池能装段内节点，故排在其余各面接回检查之后。

验收：

- 正负语料逐条通过，诊断码与标签区间按手写期望；差分语料只比语法树结构与区间，不比诊断措辞。
- 自举对能完成解析的全部源文件零诊断；`unicode` 的生成表仍按抽样，解析吞吐是独立缺口，不在本批消化，也不拿抽样冒充全量。
- 每条新增构造都由同一份语料同时驱动宿主与自举，任一侧缺失即判失败；不再出现「自举支持而宿主无法复核」这类只能单向验证的登记。
- 未进本批的构造仍在解析期报语法错误并至少前进一条记号，不得静默产出空节点或退化为零值。
- 语法层测试不依赖语义、IR 与驱动，`syntax` 包既有判据不缩水。

决定（本批开工前记录）：

- **追平不重裁**：宿主已有的构造按宿主实现追平，不重新讨论语义；发现宿主与规范不一致时按规范登记差异，差异本身不改本批范围。
- **异步面末位**：受限源码约定禁止结构化并发，自举不依赖它；排在末位可与下一批并行或单独切出。
- **`as` 以规范为判据**：宿主已有五层实现可作结构对照，期望仍按参考件的显式转换条款写；条款没写的部分（跨族转换、溢出表现）就地补写，补写结论进规范不进计划。
- **三处代码层限制不归本批**：「一次返回多个值」属 **IR 与后端接缝**，「跨包引用限定枚举值」与「跨包同名顶层函数」属 **装配面**。它们不是语法树缺口，混入本批会让判据错位。
- **原清单两处按实况订正**：「遍历步长」在两侧解析器均已实现（`while` 与 `for` 之后的 `step` 块），不再单列；「宿主侧中文词表入口」属宿主配置面，不属语法树缺口，归 **语言面** 回填。

交付回执：

- 八个子面逐面追平宿主：转换、类型写法、错误处理、声明块与声明头、语句、异步与字面；`as` 按上下文关键字处理，目标类型落节点。
- 各面取证在专项测试；顶层裸变量不在参考件形态表内，行首一律报 E2-005。
- 边界：`syntax` 原生通道的自解析跑不完，归吞吐批次；字典条目的类型标注只进语法树，判型待接线。


### 外部面

宿主已把 C 互操作做成三个来源：生成、手写、封装。三条汇成一张包级符号表，库绑定退到 `[ffi].libs`，块名只是标签。自举侧停在更早的形态：`|foreign` 只作函数修饰，`[名称|foreign]` 块、`[ffi]` 清单与包级裁决都不存在。

本批只做阻塞自举的部分。头文件翻译与生成模块的装载归 **构建脚本面**；本批只把生成文本当夹具，不实现翻译。外部调用的发射归 **IR 与后端接缝** 与 **LLVM 与驱动装配**。

交付：

- `[名称|foreign]` 块：条目只有一形 `名{|标志}: 类型`，标志为 `readonly`、`macro`、`varargs`；类型是函数即外部函数，其余为数据符号；块内函数自动 `unsafe`；块名不参与查找，重名不构成冲突。
- `[ffi]` 清单六字段：`abi`、`search_paths`、`libs`、`headers`、`include_paths`、`defines`；`libs` 与 `search_paths` 进构建计划，块名与库名脱钩。
- 包级外部符号表：一个文件声明、另一个文件直接用；声明处一次裁决，同名同型合并、异型报错、与本地符号或导出名同名报错、条目名非 C 标识符报错；外部符号一律包级可见，不受 `_` 前缀收紧。
- 判型：类型白名单、回调形参只收顶层自由函数、变参固定前缀与尾实参提升、`String` 借出、`StringHandle` 与 `fromCString` 取回、数据符号读写与 `readonly` 拒写；`|macro` 的值从计划读，无计划条目报能力缺口。
- 解析顺序：运行时 shim 白名单、`[ffi].libs` 预加载、进程映像；未命中在注册期报错，不延到调用点。
- `runtime-api` 建包：按 `docs/spec/runtime-abi.md` 的清单声明可经外部块可达的符号，其余走内建；链接口径随构建计划。它是外部面的第一个真实消费者，不是占位包。

子批次按依赖顺序：

- **清单字段**：`[ffi]` 六字段进清单模型与计划；未知字段按形状保留，不静默取默认值。
- **块与条目**：`[名称|foreign]` 块进语法树与注册面（依赖语法补面的声明块面）；`unsafe` 前缀同批。
- **符号裁决**：包级外部符号表、合并规则、全部冲突判据与解析顺序。
- **判型面**：白名单与五条边界，正负语料各一组；`StringHandle` 作为不透明具名类型进类型池，只在 FFI 面与 `|c` 条目内成立。
- **运行时段包**：`runtime-api` 按 `docs/spec/runtime-abi.md` 逐条声明可经外部块可达的符号；它是本面的端到端判据，声明错一条就在检查期报。

验收：

- `runtime-api` 在自举工作区里零诊断；外部调用（`unsafe` 前缀）、`[ffi]` 清单与外部块在同一份夹具里各有一条正例。
- 同名同型合并、同名异型、与本地符号同名、与导出名同名、非 C 名各有负例，位置指向第二次声明，消息带首次声明所在文件。
- `pini bind` 对夹具头文件的生成文本原样进自举解析，零诊断；生成文本逐字节钉死的那份夹具同时是自举的输入。
- 同一份外部块语料在宿主与自举上得到同一组符号与同一张计划文本；块名重名不改变查找结果。
- 解析顺序三层各有判据：命中 shim 不查符号、命中预加载库不落到进程映像、三层都未命中在注册期报错。

交付回执：

- 宿主侧落地外部声明的三个来源、冲突裁决与链接口径；参考件 9.4 改写，两份文档不再出现文件级作用域。
- 自举侧开面六处：清单字段、块与条目、符号裁决、判型白名单与五条边界、运行时段包、解析顺序。
- 边界：调用点判型随 **装配面** 接线；手写 `|macro` 求值归构建期，`StringHandle` 与变参只在 LLVM 通道成立。


### 构建脚本面

`build.pini` 只声明翻译步，不执行构建。配置期读声明产计划，执行期按计划翻译、发射、链接；生成物落构建目录、归声明它的包，源码树不出现生成文件。

本面不阻塞自举验收：`bootstrap` 没有 `build.pini`，自洽链不需要它。它阻塞的是用自举编译器构建带 C 生成面的用户工作区，故排在外部面之后，可与 IR 批次并行或后置。

交付：

- `package` 的步骤模型与计划：步骤名、头文件、包含路径、定义、产物路径与 `|macro` 求值结果；步骤名须是合法路径分量且在包内唯一；计划记包根、脚本哈希与输入指纹。
- `build.pini` 的读取归驱动：驱动经 `syntax` 取给定块，块到步的映射与计划归 `package`，故 `package` 仍不认识 AST，只认步骤记录。备选是让 `package` 依赖 `syntax` 自行解析，代价是清单层开始认识程序结构，不取。
- `module-loader` 单一装载入口：按计划取生成单元，归包按计划登记的包名，不按路径前缀；计划缺失、脚本哈希不符、产物缺失各报定向诊断。
- 确定性：两次构建的计划与生成物逐字节相同；指纹含头文件与整棵包含树、包含路径、宏定义、翻译器版本与目标平台。
- 失败面：`build.pini` 写坏只影响 `build`；`check`、`run`、`test` 读计划，不执行脚本。

验收：

- `pini build --print-plan` 在无 clang 的机器上打出计划文本，且配置期不执行翻译。
- 构建后 `git status --porcelain` 无新文件；删掉生成目录后检查报“先 build”，紧接着 `build` 能重建。
- 改头文件只重翻受影响的目标；两次构建逐字节相同。
- 生成单元与源码单元在计划里同源：同一包的两类单元在注册面看到同一个包名。
- 脚本写坏、步骤重名、产物缺失、计划过期各有专用诊断，不静默跳过。

决定：

- **声明式配置**：语言没有“计划对象 + 方法调用”的构造面，执行式配置要先补配置期内置与语义入口；声明式同样满足配置纯净与计划即数据，代价是字段名固定。
- **生成物归声明包**：`import` 写路径，独立模块要同时开三个口子——给 `.build` 里的目录补清单、让 import 能表达构建期才存在的模块、给该模块在依赖解析里开例外；并入声明包后包内即用，不需要 import 这一跳。
- **驱动解析、包建计划**：见交付第二条，边界比“让清单层认识 AST”更窄。

交付回执：

- 宿主侧 `BuildScript`、`BuildPlan`、`BuildLayout`、`BuildRunner` 与 `GeneratedModules` 落地，由专项套件取证。
- 边界：自举侧未开面；跨包共用生成物不去重；`pini bind` 不属自举，生成文本由宿主工具产出。


### 解析吞吐与栈深

自举解析器在原生通道跑不完自己的语料：单个 `parser.pini` 自解析记 5 分 36 秒，五个源文件合计越过命令上限被终止，解释器通道却全量通过。差距不来自语义，最可疑的是按值往返的复制路径：原生通道的数组追加在存储被共享时逐元素堆分配深拷，解释器侧是宿主数组的整块写时复制，常数差出量级。这条以阶梯读数为准，代码形状只是待验假设。全工作区零诊断、增量构建与不动点都排在这条后面。

本批不改语言面、不改语义判据、不动运行时 ABI。若读数指向运行时深拷的常量因子，先出结论再定归属，不并入本批。

测量口径：

- 通道只认原生通道；解释器读数作对照入回执，不参与判据。
- 输入取三类真实文件：`parser.pini`（代码最密，5 分 36 秒那条用例的输入）、`scan.pini`（中等代码）、`nfc_tables.pini`（最大单文件）；另加一组合成阶梯，同一模板重复产出 1k / 2k / 4k / 8k 行，名字带序号以免重名干扰。
- 单次耗时取同进程重复次数的差商：跑一次与跑四次各测墙钟，差值除以三，启动、JIT 与读文件因此抵消。语言目前没有时钟内建，本批不为测量新增 ABI 符号。
- 每档五次取中位数，首跑丢弃；同一档两次测量中位数差超过一成时该档作废，先查环境再取数。
- 读数按毫秒、字节每秒、记号每秒三列同时给出；记号数取解析结果里的真实值，不按字节估算。
- 回执记机器、LLVM 版本、构型与优化级别，缺一项则该组读数不进判据。

基线取法：

- 先在未改动的代码上取一组读数，记为改造前基线；改造后同法复测，两列并列。
- 全文件跑不完时用截断阶梯：同一文件取前八分之一、四分之一、二分之一，按耗时随规模的指数拟合定位复杂度。绝对量另有全工作区一档直接实测，不按平方和外推。
- 栈深与时间分开量：取最大递归层数与触发它的结构，不以「跑过去了」代替读数。

交付：

- 测量脚本：生成临时测量模块，逐档以 `--filter` 调原生通道，按次数取中位数，不含编译逻辑，落 `bootstrap/tools`。
- **记号瘦身**：段表移出记号、进词法结果的段池，记号只留基址与段数，退成定长记录。
- **归一守卫**：词法入口只在文本含 CR 时才走 `replace` 做 CRLF 归一。`replace` 是逐字切片再逐字拼串的标准库函数，代价随长度平方增长，无 CR 的源必须绕开。
- **句柄登记**：运行时活动句柄表按对象身份索引，登记与摘除都是常数时间。原实现是列表加线性查找，表长等于活跃容器数，于是「每个元素各带一个容器」的追加按表长退化。
- **关键字表**：词法的关键字词表在入口建一次并随状态传递，比对按宽度先行剪枝、直接比字节，不再为每个标识符重建词表并逐词物化。
- **容量预留判定**：只出结论与归属。运行时没有公开的扩容入口，需要时单列运行时批次，不在语法包私加符号。

判定：**状态就地** 不做。按值往返复制的只是六个数组句柄，不是数组内容；就地推进与原形状的阶梯读数没有差别，改动只增加表面积，故保留原形状。

判定：**节点瘦身** 不做。节点表追加的代价取决于元素里有没有容器字段，而根因是句柄表的线性摘除；登记表改成常数时间后，带数组字段的节点与纯标量节点同阶，改节点形状不再有收益。

验收：

- 线性度：输入翻倍，解析耗时不超过二点四倍；净耗时低于底噪一成的档不参与判定，改由合成语料补齐。这一条判复杂度，与机器快慢无关。
- 绝对量：全工作区 130 个文件、约 2.4 MB 的装载加解析，在原生通道单进程内不超过三十秒。依据是现有 CI 门禁单次已在分钟级，解析须成为其中的小项。
- 等价：双通道 539 项读数逐项不变，全量解析零诊断的抽样集合不缩小，同一输入两次解析的语法树摘要与诊断序列逐字节相同。
- 可复现：按上述口径两次独立测量，同一档中位数差不超过一成。
- 栈深：`parser.pini` 与 `nfc_tables.pini` 在默认线程栈上不溢出，且最大递归深度入回执。
- 反例：把 **句柄登记** 改回列表加线性查找，线性度与绝对量必须同时转红，证明判据测的是登记表的复杂度而不是机器抖动。

注意 三条：改造只动形状不动语义，双通道与全量零诊断是唯一等价证据；就地推进后若某处仍持旧快照，会读旧值而不报错，故「两次解析逐字节相同」必须进判据；栈深不许用调大线程栈掩盖，先量深度再定对策。

风险与控制：

| 风险 | 控制 |
|---|---|
| 为提速改语义或跳过判据 | 双通道读数与全量零诊断作为等价门禁，读数变化即停 |
| 就地推进后读到旧快照 | 同一输入两次解析逐字节相同；关键结构加写后读用例 |
| 优化落在错误热点 | 先取阶梯读数定指数，再改；每项改造单独复测，不合并取数 |
| 需要运行时扩容入口 | 先登记 `docs/spec/runtime-abi.md` 再动，本批不私加符号 |
| 栈深被调参掩盖 | 最大递归深度与触发结构写进回执 |

交付回执：

- 基线显示解析耗时按规模呈二次方、词法占八成五；逐字节二分把二次方压到记号携带段表与词法入口的 `replace` 归一两处。
- 四处改造（记号瘦身、归一守卫、句柄登记按对象身份索引、关键字表入口建一次）后三项判据齐，反例改回线性查找即同时转红。
- 判定不做「状态就地」与「节点瘦身」；附带发现缩进深度影响词法耗时（未定位），嵌套泛型实参写法待补面。


### 解释器自解析搁置

工作区测试聚合强制走解释器通道，`syntax` 的 `自解析` 一项独占这段耗时的四成上下。同一用例在原生通道已由逐包门禁覆盖，且覆盖更严——它把发射与运行一并验证。故解释器那一份在 CI 里停跑，判据由原生承担，直到解释器具备 JIT 一类加速能力再复核。

读数（macOS 27.2.1 arm64、Apple Swift 6.4.2、Homebrew clang 23.1.5、debug 构型）。这一组是易腐记录，只用于本次取舍，不承担长期参考价值；机器、命令与原始输出另存 [解释器自解析跳过的读数](readings/2026-11-16-interpreter-selfparse-skip.md)：

| 口径 | 项数 | 耗时 |
|---|---|---|
| 工作区全量走解释器 | 543 | 156.34 秒 |
| 其中 `自解析` 一项（含一次工作区装配） | 1 | 68.74 秒 |
| 同口径的装配底噪（一条轻用例） | 1 | 9.41 秒 |
| 同一项走原生 | 1 | 5.17 秒（发射与链接 4.7 秒，运行 0.47 秒） |
| `syntax` 全包走原生 | 91 | 5.54 秒 |
| 工作区全量带 `--skip 自解析` | 542 | 94.81 秒 |

停跑的依据是去重，不是取舍：该用例在流水线里本就被跑两遍，一遍解释器、一遍原生；去掉的是一直较慢的那一遍，判据本身不减少。工作区上下文对它也没有额外意义——它只读本包源文件，不涉跨包装配。

流水线步数在同一区间由 15 增至 25，新增的十步里八步是逐包原生测试，工作区测试仍是单步里最重的一项。这一条只削单步内最贵的一段，不动编排结构；真要压总时长，得从原生聚合与逐包门禁的合并上取，那是另一笔。

落地：测试执行的收窄面加了 `--skip`，与 `--filter` 对称，可重复、先筛后跳；CI 的工作区测试门禁已带上它，其余门禁不动。未加语言面修饰、未改测试源码：为一个用例撑开语法修饰符，代价与收益不成比例。工作区级原生测试聚合是这条的根治路径，但它要逐包发射并聚合，不进本批。

跳过规则自身也有判据：工作区路径下，`--skip` 的每个名字必须至少命中一条测试，否则按框架错退出；筛选命中又被跳空同样不算通过；整个 target 被跳过时报告留一句「--skip 全数排除」，空结果不冒充「没有测试」。模块路径的单模块测试只做排除、不校验命中——那里没有统一的收集面，校验得另读一遍声明表。零命中要等全部 target 收集完才能判定，故参数写错会先付一次执行时间再红；换来的是正常路径上不额外扫一遍源码树。

注意 停跑的边界是 CI，不是语言。本地默认仍执行解释器那一份——它承担解释器与原生行为分叉的早期信号，一分钟的本地代价可以接受，每次流水线重复付一遍不可以。

恢复条件：解释器落地 JIT 一类加速、`自解析` 的解释耗时降到与原生同量级时，去掉 `--skip` 并同批复测。本条只改 CI 编排与筛选面，不动任何验收判据，也不改测试收集规则。

### IR 与后端接缝

交付：

- `ir` 的节点、降载、份额、布局消费和结构校验，含外部函数调用、外部数据符号与宏常量的节点。
- `backend-kit` 的后端接口、能力声明、目标描述和统一发射结果。
- 所有未支持节点显式报出能力缺口，不用零值占位伪装实现。
- 外部符号节点带来源标签：手写块与生成块同形，来源只影响诊断措辞，不影响降载。

验收：

- IR 校验双向报告“有节点无契约”和“有契约无实现”。
- 语义与 IR 不包含 LLVM 名称、指令或目标布局判断。
- 一个最小第二后端可只实现 `backend-kit` 接入，不修改语义和 IR 公共接口。

决定（本批开工前记录）：

- **节点单池**：自举语言无继承、无动态分派，访问者写不出来；节点按 AST 四池的先例并成一池，类别码分段（表达式一段、语句一段），子节点用池下标，遍历一律按类别码分派。族只作能力声明与契约对照的单位，不落成池的切分。
- **后端用注册表加入口码**：特征只作约束、不作类型，协议对象不存在；一个后端记成「名字 + 输出档次 + 能力族表 + 入口码」，驱动按入口码分派，不引入函数指针。
- **IR 类型池独立于语义类型池**：语义池十二类有效类别（另有无效标记）、IR 池二十三类，不是同一集合；降载入口一次建映射，IR 内部不回查语义池。映射不上的类别报降载错误，不留空下标。
- **字段与用例只存声明序下标**：`fieldGet` 的字段位、`enumConstruct` 的用例位都写形态表里的序号；名字进字符串池只供诊断与发射拼写，后端不按名字查布局。
- **节点清单随源码提交**：契约正文与宿主节点枚举实测都是五十六个表达式节点加十七个语句节点，共七十三条；清单表由工具按契约生成，与 unicode 数据表、诊断码表同规，双向检查落在清单表与节点池的对照上，不解析 Markdown。契约 §0.4 写作「55 + 17 = 72」，与本批实测不符，订正与否另案，本批以实测为准。
- **整图降载、整图发射**：本批不做按包产物与增量缓存，与 **构建形态演进** 的初期形态一致；包边界仍由接口文本约束。

| 接缝 | 上游给 | 下游要 | 不变量 |
|---|---|---|---|
| 语义到 ir | 类型池、表达式类型表、解析表、形态表、槽布局、局部槽位、外部符号表 | 类型下标、字段与用例的声明序、槽位 | IR 不回查语义池 |

- `ir` 建包：类型池按形状驻留、七十三项节点类别码分段、单池七字段、族码表与宿主能力族同序。
- 判据：八项测试两通道全过；工作区成员由九增至十，新增 `ir` 原生与契约一致性门禁。
- 契约条目数实测七十三，与 §0.4 的「55 + 17 = 72」不符，以实测为准另案订正；降载入口与份额判定未做。


交付回执（降载入口）：

- `lowerWorkspace` 落地：吃世界与各张表，按单元序与声明序出函数表，参数类型走语义绑定表；类型映射一次建表。
- 缺口纪律：语句体未降载，有体函数各报一条 `E6-004` 并留空体，空体数与缺口数对照，静默吞体即红。
- 边界：方法名未 mangle，同名方法在函数表里会撞；`ir` 的允许依赖补入 `syntax`。


交付回执（语句体）：

- 语句体接通：帧、表达式、语句三面按「帧 → 表达式 → 语句 → 入口」分工；控制流节点加 `tail` 分两段序列。
- 失败即整函数留空，错误表分函数级与类型级两栏；类型后备按运算符形状取，待推导表补局部类型后删除。
- 未完成：方法调用、标签实参、复合赋值、`for`/`match`/`defer`/`try`、标注声明与各类字面量；孤儿节点靠后端从体入口遍历规避。


### 降载吞吐

降载入口接通后，全工作区降载在原生通道需两分半。分段读数把耗时按装配链切开：装载、注册、类型、建世界四段占九成，降载本身只占一成。故本批的边界不是「让降载更快」，而是把每段成本摆出来，先修确定是浪费的那一处。

测量口径：

- 通道只认原生通道，输入取自举工作区全量。
- 计时取外部墙钟，单次跑；分段靠临时裁掉后段再测，差值即该段成本。
- 读数易腐：单元数、函数数或机器一变即整组重取，不拿旧数字补新差。

分段读数（改造前）把一整轮切成五段：装载与解析、注册、类型解析与建世界四段合计占九成，降载只占一成。瓶颈因此在装配链，本批先修其中确定是浪费的一处。

交付：

- `ownerTypeOf` 复用调用方已转好的字节视图：原实现每方法重转整单元文本，单元越大越亏。
- 驱动 `lower` 子命令：装配后直接降载并打印函数数与缺口数，作为端到端入口与测量面。

验收：

- 同一输入两次运行，函数数与缺口数逐字相同。
- 优化只动字节视图的来源，不改变任何降载结果。
- 判据不拿耗时作准：耗时只作读数，函数数与缺口数才是等价证据。

交付回执：

- 改动等价：函数数与缺口数逐字不变，工作区与各门禁通过；对照实验（声明查类型换二分）无可测差异，已回退。
- 边界：只削掉确定浪费的一处，端到端大头仍在装配链；装配吞吐是否单列批次，待下一批读数决定。


### 装配吞吐

**降载吞吐** 的分段读数把两分半里的一成归给降载，其余归给装配：装载、注册、类型解析与建世界。本批接手这四段，判据与测量口径同前，不重复。

已排除的嫌疑：

| 嫌疑 | 做法 | 读数 | 结论 |
|---|---|---|---|
| 声明查类型走线性扫描 | 二分加排序，端到端对比 | 2:24.41 → 2:24.77（同源码应为 2:24.20 上下） | 无可测差异，回退 |

对照实验的两条纪律，记在这里免得下次再踩：

- **比读数必须同源码**：二分那版同时新增了四个函数，函数表由 1915 变 1919；若不先认出这四行，会把「源码变了」读成「降载结果变了」。
- **错误用法也要测**：二分不排序会漏项，但耗时与排序版几乎相同，说明 `typeOf` 本身不贵 —— 贵的是别处。

后续嫌疑，按调用量排：

- 符号注册的 `containsKey` 线性查重，逐声明扫一遍。除非它可见地拖慢注册段，暂不动。
- `makeMemberWorld` 的两张索引，计划说建表归并一次，但取用侧是否仍线性待查。

类型池那条嫌疑已随整数码一起排除：比较方式换掉后端到端不动，说明查找次数与池长都不足以成瓶颈。

验收：

- 同一输入两次运行，函数表与诊断序列逐字相同；耗时只作读数，不作判据。
- 每项改造单独复测，不合并取数；读数变化超过一成才认。
- 端到端降到一分钟以内时回来复测，看瓶颈是否转移。

交付回执：

- 整数码无可测收益（改动保留但不记收益），索引未做；真正瓶颈是键计算 —— 每个标识符都走完整 NFC，而标识符几乎全 ASCII。
- ASCII 快路径砍掉规范化后，端到端降到原来的三分之一上下；分段复测推翻「类型解析是大头」的旧判断，符号查重不再值得动。
- 教训：连续两处猜错都因缺分段数据；这次靠「键在每处都被算一次」的静态线索定位。


### Unicode 表瘦身

**降载吞吐** 的分段读数把耗时的四分之三归给四个生成文件，本批把它们由「判定函数」改成「数据串加通用二分」：原来每次编译都在重编同一棵判定树。

先证伪过一条路：把池改成单一所有者、原地追加。四组基准（裸数组、值类型过一层、值类型过三层、真实节点池）在高次追加上都是线性，解释不了三万八千个节点的降载要两百余秒。改动未落地。这是第三次用静态推理代替读数，记在这里。

表的形态：

- 记录是定宽十六进制文本，按码点升序；码点字段 6 位，值字段按表定宽。
- 区间表答「最后一个起点不超过码点的值」，精确表与成对表答命中值，未命中一律 -1。
- 查表在 `table_search.pini`：按记录偏移直接读字段，不解码整串，也不建中间容器。
- 数据仍随源码提交，构建与运行不读宿主数据；版本声明与摘要门禁不变。

热路径的字节视图：

- `unicodeClassOf` 原来逐次转换 11KB 表，而词法逐标量调用它；转换按字节装箱，代价远高于查表本身。
- 词法状态携带一份分类表视图，整段只转一次，逐标量走 `startsIdentifierIn` 与 `continuesIdentifierIn`。
- NFC 与混淆骨架各自在入口转一次，`...In` 变体收视图；分解、组合类、组合三张表不再按标量重复转换。

交付回执：

- 四个生成文件由判定函数改成数据串加通用二分，生成源码由两万余行降到百行量级，数据串是主体。
- 全工作区降载由十余分钟降到四分半上下，宿主全量构建由近三十秒降到十九秒上下；等价与数据门禁通过。
- 装配段没有回到改造前水平，原因由 **装配段诊断** 给出。


### 装配段诊断

当前基线接受为起点；本批不改变它，只回答装配段那七十秒的来处。

分段读数把一整轮切成六段，表达式推导一段独占七成六，装载、注册、类型解析、建世界与降载五段合计不足四分之一 —— 装配段那七十秒只是推导段之外的次大头。

推导段不是某个函数慢，是同一件事做了很多遍。逐单元读数没有单点热点：表达式最多的文件耗时十七秒，而只有它四分之一表达式的文件却要十二秒。每表达式一到五毫秒，与节点数不成比例。

采样（主线程 3,824 个样本）：

- 把单元文本转成字节数组占四成九。
- 释放这些临时数组占一成六。
- 推导自身占一成四。

来源是 `tempUtf8Bytes(unit.text)`：目前有十几处独立调用点，分布在成员、调用、表达式检查、形态、标注、边界、控制流、模式与外部类型各模块。每个调用点各自转换整个单元文本，字节视图没有沿调用链传下去。转换按字节逐个写入数组，常数很大；单元文本越长，其中每个表达式越贵。

一条已经接了一半的线：语句检查的 `StoreCheck.bytes` 有缓存字段，但两个调用点只读不写，缓存永远是空的。

两条改法：

- **单元带视图**：`CompilationUnit` 加一个字节字段，装载时填一次，各调用点改读字段。改动面是一个结构与十几处调用点；收益按采样上限约六成。
- **参数传视图**：给各函数加字节参数并逐层传。改动面更深，且新函数漏传一处就退回原样。

推荐 **单元带视图**，理由是它漏不掉：字段随单元走，不存在「忘记传」这种失误模式。

交付回执：

- `CompilationUnit` 增加字节字段，装载时填一次，`unitBytes` 作唯一入口；语义层十八个文件三十三处改读单元视图。
- 推导段耗时减半，端到端由四分钟级降到两分半以内；装载段因多转一次略增。
- 等价：工作区、`module-loader`、`semantics` 与 `ir` 两通道全过；注释与格式门禁通过。


### 降载覆盖面

**IR 与后端接缝** 的降载只接住了标识符、二元、一元、调用、成员读与下标读，方法体几乎全落缺口。本批按调用量补三处：方法调用、带标签实参、复合赋值，判据是缺口分类读数与节点形状。

交付：

- **方法调用** 两端同名：`|self` 方法与调用点同批按 `方法__类型` 出符号，`|own` 方法按 `own__方法__类型`；实例方法形参表首位补 `self`，调用点把接收者作首实参，本型方法不带接收者。
- **标签归位**：实参按形参声明序归位，标签按名对位、位置实参填剩余的不收标签位；省略默认值或取用位的调用报缺口，不按零值补齐。
- **读改写**：复合赋值降成「读—算—写」三节，局部、字段与下标三类目标各有一条写路；普通赋值的字段与下标目标同批接上。
- **帧播种**：语义层播种的自身与形参照抄进局部帧，形参赋值不再被当成非局部目标。
- **类型后备**：推导表不覆盖 `self.字段` 与调用结果时，字段类型查字段声明、调用结果查被调声明的返回类型，两处都缺才报缺口。
- 语义包补三个按名查找入口（`lookupTopByName`、`lookupMemberByName`、`lookupImportByName`），包外调用方不必自持名字键格式。
- 驱动 `lower` 增缺口归纳：按原因归并计数，函数名前缀不进归类。

验收：

- 缺口读数按分类下降，每一类都能在驱动输出里读到原因与成员名。
- 方法符号名与形参表、标签归位后的实参序、三类赋值目标的节点形状各有测试钉住。
- 双通道读数不变：同一批用例在解释器与原生两条通道上全过。

交付回执：

- 方法调用、带标签实参、复合赋值接通，缺口由过半函数降到三成上下并首次可按原因分读；函数表增 44 条，同名方法不再互撞。
- 六项测试钉住方法名编码、标签归位与三类写路；`driver` 的缺口夹具改用内联源码。
- 边界：标准库成员仍报成员被调；复合赋值接收者只收标识符；默认值与取用位的调用报缺口。


决定：

- **符号名两侧同规**：方法名与形参表在声明侧与调用侧各算一遍，靠同一份编码规则对齐，不引入符号表二次索引。非 ASCII 名按 `_u` 加四位大写十六进制编码，与宿主同一规则。
- **缺口带名字**：成员被调的缺口写清成员名，下一批可直接按名字分流。
- **依赖补记**：`ir` 的允许依赖补 `unicode`（符号名编码）与 `module-loader`（编译单元与测试造单元）—— 两者此前以隐式类型名可见，本批改为显式声明。

注意 本批只改降载面、语义包的三个查找入口与驱动输出，不改语言语义，不动 IR 契约的节点形状。

### 声明定型与字面量降载

**降载覆盖面** 之后，函数体仍大面积留空：字符串与数组字面量一遇即整函数失败，`var x: T = ...` 无条件报缺口。本批补字面量降载与声明定型，判据是缺口分类读数与节点形状。

交付：

- **带标注声明** 接通：标注类型由语义层写在声明模式节点上，降载只做映射；初值窄于标注时包一层显式转换，无初值的声明只带标注。
- **字符串字面量**：去首尾引号按转义表还原，`\0` 之后的内容全部丢弃；值驻留文本池，不做逐段解码（转义切开的序列会变替换字符）。
- **数组字面量**：元素保序，类型取推导表；空字面量在带标注声明里按标注定型，这是唯一能给空数组定元素类型的位置。
- **零参构造**：`T()` 按名字与对象位查类型池里的名义条目，产出构造节点；查不到即缺口，不在降载期新增池条目（新条目传不回模块池）。
- **内建调用**：包级符号表查不到的名字回落内建表，返回类型按形状映射；`print` 不走这条，它有专属节点。
- **别名调用**：`别名.函数` 的解析前移到降接收者之前 —— 别名不是值，先降它必然失败。
- **下标读类型后备**：容器类型的分量即元素类型；此前只覆盖成员与调用，下标读全落空。
- 语义包新增 `fillDeclaredTypes`（推导后按标注覆盖模式节点类型）与 `resolveAnnotationIn`（复用类型游标，不为每条声明重建类型世界）；`TypeMap` 补 `charId`。
- 缺口摘要增两处：表达式类型未定带类别名、每类缺口带一个样本文件与偏移。

验收：

- 缺口按分类下降，字符串与数组两类不再出现在缺口表里。
- 类别分派、转义还原、空数组定型、零参构造、内建返回类型各有测试钉住。

交付回执：

- 带标注声明、字符串与数组字面量、零参构造、内建调用接通，字符串与数组两类缺口消失，头号一桶变成标识符。
- 五项测试钉住类别分派与定型；`driver` 缺口夹具改用 `for` 语句；端到端变慢，按纪律先记账不猜归属。
- 边界：名字表只给字面量初值的局部登记类型；标准库未装配；`fallbackIrType` 的下标分支属过渡机制。


已知边界：

- **标识符 413 条**是当前头号缺口：推导期的名字表只给「字面量初值」的局部登记类型（`noteVariable`），`let a = f(x)` 这类局部不入表，其下游的标识符、成员读、下标读一并落空。修在推导面，属独立一批。
- 标准库成员（`append` 217、`split`、`substring`、`indexOf`、`contains`、`startsWith`）仍报成员被调，标准库未装配进自举工作区。
- 带实参的构造、枚举用例、插值字符串、`for`/`match`/`defer`/`try` 语句均未降载，各自对应的缺口数见回执。
- `fallbackIrType` 的下标读分支与成员、调用分支同属过渡机制，待推导表补面后一并删除。
- 零参构造只查既有池条目：某名义类型若从未在任何签名里出现过，其构造调用仍报缺口。

注意 本批改降载面与语义包的填表面，不改语言语义，不动 IR 契约的节点形状。

### 推导期名字表

**声明定型与字面量降载** 之后，标识符 413、成员读 126、数组字面量 112 三桶同源：推导期的名字表只收参数、带标注声明与「初值是字面量」的局部，`let a = f(x)` 这类既不入表，其下游的标识符、成员读、下标读一并落空。

成因不止一处：名字表按**整个单元**建一张，`out`（415 处）与 `i`（414 处）这类高频局部名必然同名异型而被标歧义，名字一旦歧义就整局失效。故本批同时改分组与登记时机。

交付：

- **函数级名字表**：每个函数一张，`self` 与参数先入表（`self` 按所属类型的池下标入表），方法体走完即弃，跨函数不再互相干扰。
- **语句序增量**：推导驱动从「按表达式池扁平顺序」改为「按函数、按语句序遍历」；变量声明先推初值，再按标注或初值类型登记名字，后面的语句立刻可用。
- **声明类型写回**：带标注的声明在遍历时把标注类型写回模式节点，降载读模式节点即可取声明类型；`fillDeclaredTypes` 退为兜底，跳过已写槽位，不再重复解标注。
- **模式变量入表**：`for` / `unroll` 的模式变量按容器分量定型并入表，此前它们根本不进名字表。
- **兜底扫描**：语句序走完后再按池序扫一遍未定型节点，用空名字表只做「由已定型处向外传播」。字段初值、处理器体、函数字面量体挂在语句树之外，靠这一遍兜住；漏推因此不会拉低覆盖面。
- 驱动 `lower` 增 `types-ok` 读数（全工作区已定型槽数），用于比对推理面改动前后的覆盖面。
- 类型缺口的细节在标识符上另带拼写 —— 分不出名字就分不出批。

验收：

- 五项判据先钉红再转绿：初值非字面量的局部及其下标读可推、两个函数各自的同名局部各推各的、`self.字段` 可推、循环模式变量可推、一个除「被调名与循环模式」外全定型的样例。
- 已定型槽数不得下降；缺口按分类下降。

交付回执：

- 名字表按函数分组并在语句序里增量登记，已定型槽数涨四成；`self`、参数、标注与循环模式变量都进表，兜底扫描防漏推。
- 目标未达（缺口未压到八百以下）：判据把名字表当唯一上游 —— 那批标识符缺口全是枚举项作值，另属三个机制。
- 决定两遍而非一遍、线性表不嵌套、`self` 入表；端到端略增。


决定：

- **两遍而非一遍**：语句序负责「登记后可用」，兜底负责「不因漏推而少了覆盖面」。漏推是这套改法唯一的真风险，用兜底把它降级成「少推」而不是「推错」。
- **线性表，不做块级嵌套表**：同一函数内后声明的异型同名把该名字从此标歧义，宁可不推。块级作用域表能更准，但要连推导与降载两处一起改，不在本批。
- **`self` 进表**：方法调用与字段读写都从接收者类型出发，`self` 不入表则整条链断在第一步。

已知边界：

- 枚举项作值未推：裸名引用枚举项要按项名反查枚举，名称空间与歧义口径未定，独立一批。
- `match` 模式绑定、函数字面量参数不进名字表；前者缺枚举载荷类型，后者要有独立的函数帧。
- 标准库成员（`append`、`split`、`contains`、`substring`、`indexOf`、`slice`）仍报成员被调，标准库未装配进自举工作区。

注意 本批只改推导面（`semantics` 的 `expr_infer`）与驱动的读数输出，不改语言语义，不动 IR 契约。

### 用例写法与降载

**推导期名字表** 之后仍有 442 条标识符缺口。逐名核对后确认：它们全部是值位裸名引用的枚举用例（`irTypeTag(irArrayType)` 的实参那一类），不是变量 —— 名字表这条上游已闭合，缺的是另一条路。

**草稿口径**（`docs/Pini草稿.md`）：用例作值只有两种写法 —— 限定 `枚举.用例` 与前导点 `.用例`（Optional 的 `.some(值)`、Result 的 `.ok(值)` 即后者）；裸名只出现在 `match` 的模式位。语法层早已把两种写法分成 `exprCase` 与 `exprIdentifier` 两个类别，前导点的报错文案直接写「枚举项名」。故裸名用例不成立，按草稿应改写。

判据一句话：**用例是枚举这一类型的成员，推断必须知道用例的类型**；前导点只是把枚举名写成糖。

交付：

- **用例倒排**：`SymbolIndex` 增 `CaseSlot` 表，只按用例名建键，所有者记枚举名；`caseCandidateCount` 与 `caseCandidateOwner` 给出候选数与候选枚举，`uniqueCaseOwner` 恰一个才答 —— 歧义不猜。
- **前导点定型**：推导面对 `exprCase` 按唯一候选枚举定型；零个或多个候选留未写。
- **前导点降载**：`enumCaseTag` 按枚举体声明序数 tag（0 起，与宿主同一口径，不按符号表下标）；`lowerCaseValue` 发 `irEnumConstruct`，文本是用例名、`op` 是 tag。
- **裸名报错**：`lowerIdentifier` 名字表未命中但命中用例表时，报「裸名用例 X 须写成 .X（候选枚举 N 个）」，推动改写；不改写成前导点即留空体。
- **写法需改与能力缺口分开**：新增 `missNeed`，不拼「尚未降载」后缀 —— 「该换写法」与「本引擎还不会」不是同一类缺口。
- **收集通道**：驱动增 `cases` 子命令，逐单元扫表达式池列出裸名用例位置（文件:偏移:用例名），不降载。降载缺口按函数首错报，一个函数里有多处裸名时拿不到完整清单，故需要这条只扫通道。

验收：

- 前导点用例、裸名报错、同名歧义各有测试钉住节点形状与报错文案。
- 缺口分类里不再出现「枚举用例」一桶；裸名用例按用例名成列，可直接作改写清单。

交付回执：

- 用例倒排、前导点定型、`irEnumConstruct` 降载、裸名报错与 `cases` 收集通道接通；缺口小幅下降。
- 裸名故意不支持：草稿只认前导点与限定两种写法，报缺口推动改写，不给裸名修第二条路。
- 边界：收集清单一千二百余处待改写，`float`/`integer`/`string` 三名须逐处判身份；语句类别与标准库成员仍缺。


决定：

- **裸名故意不支持**：宿主有一路 `lowerBareEnumCase` 兼容裸名，草稿没有。自举按草稿收紧，报缺口推动改写，不给裸名修第二条路。
- **先唯一候选、后期望类型**：宿主的两级规则是「期望类型优先、唯一候选兜底」，本批只做兜底一级 —— 自举 553 个用例名零跨枚举重名，兜底即可全绿。期望类型下推是下一批，它要动整条推导链的形参表。
- **`cases` 判据用文件级名字面**：同名局部会让人漏报（保守方向，不误报）。要精确到作用域得在收集通道里重跑一遍名字表，收益不抵成本。

已知边界：

- 裸名用例尚未改写，其中 `float`、`integer`、`string` 三个名字同时被用作变量或参数，改写时不能机械加点，要逐处判身份。
- 前导点用例缺上下文时不报「需要类型标注」而是「候选枚举 0/多个」，期望类型下推落地后再补这条话术。
- 标准库成员（`append` 243、`contains`、`split`、`substring`）仍报成员被调，标准库未装配。
- 语句类别（`for` / `match` / `defer` / `try`）77 处未降载。

注意 本批不改语言语义（用例写法由草稿定），不改 IR 契约（`irEnumConstruct` 早已在节点表里），源码一处未改写。

### 期望类型下推

**用例写法与降载** 只做了「唯一候选兜底」这一级。兜底在零重名的语料上够用，但它不是主路：用例是枚举的成员，归属应由**上下文给出的期望类型**决定，唯一候选只是没有上下文时的退路。本批把期望接进推导链。

交付：

- **推导链带期望**：`inferNode` 增 `expected: Expectation` 参数，`inferAtNode` 同步；`inferKids` 与兜底扫描显式传「无期望」，期望不会从无关位置漏进来。
- **三条来源**：变量声明的标注（先解标注，再拿它作期望推初值）、函数返回类型（`WalkState` 增 `returnType`，`return` 语句按它推值）、实参位（按被调形参的声明类型逐位推）。
- **用例归属两级**：`caseOwnerFor` 先看期望类型是不是声明了该用例的枚举，不成立才退回唯一候选 —— 与宿主 `TypeChecker` 的两级规则同款。
- **期望只认同类**：`enumNameOfType` 判类型池条目是否枚举类别，非枚举的期望不参与归属。

验收：

- 三条判据各自造「两个枚举各有一个同名用例」的样例 —— 此唯一候选不成立，只能由期望通过。标注位、实参位、返回位各一条，先关掉期望分支验红（3 条全红），再恢复验绿。
- `semantics` 新增三条测试。

交付回执：

- `inferNode` 带期望，标注、返回与实参三处来源；用例归属改为「期望优先、唯一兜底」，与宿主两级规则同款。
- 缺口未降是预期：零重名语料下唯一候选早已全覆盖，本批收益是语义主干与重名场景。
- 边界：标签实参位不吃期望；字段初值与容器元素位的期望未接。


决定：

- **两级而非一级**：期望优先、唯一候选兜底。去掉兜底会让无标注的 `.用例` 全部报错，而草稿的写法清单里并没有要求每处都写类型；保留兜底与宿主同构。
- **标签实参不传期望**：位置对不上会把用例定成错误的枚举，错定比不定更糟。有标签的调用退回唯一候选，标签对位留作后续。
- **期望只走「值」位**：字段初值与容器元素位未接，它们的期望来自声明而非语句，要另一套入口。

已知边界：

- 标签实参位（`名 = 值`）不吃期望。
- 字段初值、数组/字典元素位的期望未接。
- 前导点用例「有期望但期望里没有这个用例」时仍报「候选枚举 N 个」，没有细分为「该枚举没有这个用例」。

注意 本批不改语言语义，不改 IR 契约，源码一处未改写。

### 用例源码改写

**期望类型下推**折的是语义面，源码里那批裸名用例一处未动；本批把它们改成前导点写法。判据只有一条：用例是枚举的成员，值位必须写前导点 `.用例` 或限定 `枚举.用例`，裸名只在 `match` 模式位合法。源码里统一改写前导点。

交付：

- **两条清单通道**：
  - 驱动 `cases` 按**名字**排除文件级可裸引用名。同一文件里既有 `case X:` 模式又有值位 `X` 时，整名的值位会被一并藏掉 —— 它第一遍报的处数只是下限。
  - 第二遍按**位置**判：从枚举声明取用例名全集，逐 token 排除成员位（前一字符是 `.`）、模式行（`case … :` 冒号之前）、声明位（`let` / `var` / `for` 之后，后随 `:` 或 `(` 的）与调用位；本文件另有同名绑定或声明的整名排除。上一遍漏掉的那批由此补出。
- **改写手法**：清单带 UTF-8 字节偏移（同一行有中文时字符偏移与字节偏移不等），逐点插入一个句点，同文件内从后往前插避免位移；插入前回验该偏移的拼写与名字逐字节相等、前一字节不是标识符延续字符。差异按「只许插点」核：逐行多出的只有句点，合计一千八百余处。

验收：

- `workspace-ok 10 true`：整车检查（装载、注册、类型、跨包对账、函数体）零诊断。
- `pini build bootstrap` 退出 0：十个包的 `.ll` 与 `pini-bootstrap` 产物齐出；十个包逐包 `check` 全过。
- 宿主全量测试通过（既有已知问题不变）。
- 位置判据复算：候选值位 0 处 / 0 文件。
- 格式门禁与注释门禁通过。
- 覆盖面：缺口由四位数降到七百上下，已定型槽同步上升；「裸名用例」一桶从缺口表里消失。

发现：

- **块头不是表达式**：`[string|foreign]` 的块名与 `TokenKind.string` 同名，位置判据把块头当值位改成 `[.string|foreign]`，解析当场报 `expected token identifier`。块头行（`[名|…]`）、枚举块头（`[名]`）与块内用例行都必须整行排除。
- **清单口径**：名字级判据给出的是下限，真实值位裸名比它多出四成有余；名字级清单不能再当全集用。
- **宿主侧缺一口**：语义分析器判前导点用例只查本单元登记的用例名集，枚举声明在别的文件时一律报「undefined variable '.用例'」。跨文件引用的用例全部撞上，`build` 在 unicode 第一处即停。补 `packageDeclaresCase`：按包级符号索引查，种类为用例且对引用文件可见才放行 —— 与类型检查器 `parentEnums` 的包级口径对齐。这是本批唯一的宿主改动。

已知边界：

- 位置判据对「本文件另声明了同名局部或形参」的名字整名放弃，宁可漏报：这类名字的值位身份靠名字判不了。
- 限定写法 `枚举.用例` 的降载面本轮未验，源码统一走前导点。
- 跨行书写的 `match` 模式会被按行判据漏判；本轮语料没有跨行模式，改写后两条清单通道双 0。

注意 本批不改语言语义，不改 IR 契约；改动只增句点，逐行核过。

### 降载耗时的消费式追加

**背景**：全量降载端到端二十余分钟，远超同规模原生编译器。三包工作区的分段读数把耗时切开：装载、建世界与推导各占小块，降载段独占七成；降载段里前十五个单元合计一秒，第十六个单元独占五十秒 —— 它是九十八 KB 的生成数据文件，内容是两个巨型字符串字面量。

**根因**：数组追加是整表复制。解释器里 `append` 的内建实现就是「旧数组拼一个元素」，每次调用复制全部元素；`stringLiteralText` 又逐字节累计字面量，于是九万余字节的字面量要付约四十八亿次元素复制，与那一单元独占的五十秒吻合。微基准把「自追加」与「纯循环」并列：纯循环随规模线性，自追加每翻一倍规模耗时近四倍，二次方成立。

**方案**：执行器在赋值处识别自追加形态 —— 右值是「接收者加一个元素」的追加调用，且接收者与赋值目标同一处（同名局部，或同一 字段）。识别到就先求元素，再把槽里的数组取出、清槽、就地追加、写回。槽位清空后存储只剩一个引用，就地增长成立，追加摊还 O(1)；判不成唯一引用时退回复制，与改动前同价，语义不变。

**交付**：

- 环境对象增「取走」入口：按赋值同一套作用域查找与可变性检查交出旧值，并把槽位置空；不可变绑定照旧抛错。
- 执行器两处赋值点位接消费路径：局部槽与字段槽。求值次序保持元素先、接收者后，与既有「右值先于接收者」一致。
- 判据不拿耗时作准：消费路径每命中一次记一笔，测试断言一千次自追加至少命中九百次；语义判据由既有宿主测试与工作区两通道承担。

**交付回执**：

- 环境对象增取走入口；执行器在局部槽与字段槽两处接消费路径，字段位先让出再追加（第一版漏了这一步，唯一性判不出来）。
- 节点池改引用语义承载，独立成 `node_pool.pini`：池在各函数间传同一份存储，追加就地增长；三十个追加调用点一处未动。
- 消费命中计数落在运行时段，测试读它证明快路真在跑。

**验收**：

- 宿主全量测试与工作区测试链全过（既有已知问题不变）。
- 消费路径四条判据全绿：变量自追加、字段自追加各命中不少于九成，值语义与求值次序各一条。
- 注释、格式与文档链接门禁通过；`ir` 包测试与十个包逐个 `check` 全过。
- 单元级判据：自追加与经函数传入的池追加都由二次方转为线性，同规模耗时降一到两个数量级。

一处分歧待办：格式化器把 `[名|object]` 输出成 `{名}`，而 `{名}` 紧跟另一类型声明时解析不过（报「类型体内禁止函数声明」）。本轮把池单独成文件、以 `{名}` 开头绕开；解析器与格式化器这一处不一致应单独订正。

**已知边界**：

- 池这条二次方已由引用语义承载解决，不再依赖唯一性判定；文本池仍是值语义数组，追加与逐条扫描未动。
- 全量读数尝试过一次：release 通道跑到十九分半仍未出结果，已停止 —— 跑得完这件事仍未获证实。第三处开销起初判在文本池与名字索引的键计算，见 **文本池与类型表索引**：改后三包只降一成不到，六包仍不收敛，剩余在解释器逐节点开销。
- 只认接收者与目标同一处：接收者是表达式时（形如先调再取字段）不消费，否则接收者会被求值两次、多跑副作用。
- 消费路径只在解释器通道生效；原生通道的数组追加本来就有唯一引用判定，两腿语义一致、实现不同。

注意 本批不改语言语义、不改 IR 契约；改动落在宿主执行器、环境对象、运行时段，外加一条宿主测试。

### 文本池与类型表索引

**降载耗时的消费式追加** 之后，全量仍在十九分钟上不收敛；采样把热点指到按字节哈希与字典查找，而不是值复制。本批按此补两处索引：文本池改引用语义承载，类型绑定按单元分段。

交付：

- **文本池**：`IrTextPool` 独立成 `text_pool.pini`，引用语义承载，各函数传同一份存储，追加走字段清槽后的就地增长；驻留从池尾倒着扫，重名多在近处，命中即返。
- **类型表**：`TypeTable` 增每单元的绑定起点，`typeOf` 先跳到该单元首条再顺序扫、越过单元即止；起点在 `resolvePackage` 里扫一遍绑定即得。
- 两条判据：文本驻留的同内容复用与新内容追加；第二个单元里的声明查得到类型。

验收：

- `ir` 二十五项、`semantics` 三百四十五项测试全过；十个包逐个 `check` 通过。
- 三包工作区降载由 38.4 秒降到 35.3 秒：文本池 −4%，类型表再 −4%。
- 六包工作区仍越过八分钟未出结果，已终止 —— 第三处开销未消。

交付回执：

- 文本池改引用语义并倒扫驻留，类型表按单元分段；两处都只改查找与追加方式，不改降载结果。
- 三包读数只降一成不到，六包仍不收敛：大头不在键计算，而在解释器逐节点开销 —— 采样里 retain/release 与字符串哈希各占一成上下。
- 边界：`IrModule.texts` 仍是值语义数组；`typeOf` 仍按 (单元, 声明) 键，单元号悬空答 -1。

注意 本批不改语言语义、不改 IR 契约；改动落在 `ir` 的文本池与 `semantics` 的类型表，外加两条测试。

### LLVM 与驱动装配

交付：

- `backend-llvm` 以 `ByteBuilder` 发射类型、声明、函数体、复制与释放胶水。
- 外部符号的声明与调用、变参尾实参提升、回调地址、`String` 借出与 `fromCString` 取回按参考件发射；链接参数从计划里的 `[ffi].libs` 与 `search_paths` 拼出。
- `runtime-api` 与 C 侧符号清单一致，经现有运行时完成链接和执行。
- `module-loader`、语义、IR、后端在 `driver` 中装配；CLI 只是驱动库入口的薄包装。
- 驱动读计划与生成模块，按单一入口装载；不执行 `build.pini`。
- `stdlib` 由驱动按语言规则装配到用户模块，编译器包不反向依赖它。

验收：

- 发射产物通过 LLVM 校验、链接和执行。
- 每个 IR 节点同时有文本形状判据与运行行为判据。
- 相同输入重复发射逐字节相同，文件顺序与字典插入顺序变化不影响结果。
- `runtime-abi` 检查、后端能力检查和包依赖检查全部进入常态门禁。

### 自洽验收

构建链固定为：

```text
当前宿主 → 首代自产 → 次代自产 → 三代自产
```

验收分为两层，不互相替代：

- **自洽**：首代自产编译完整多包工作区得到次代自产；次代自产能编译规范语料并通过全部行为测试。
- **不动点**：次代自产与三代自产分别编译同一工作区，所得 LLVM 文本逐字节相同；两代可执行文件通过同一套测试。

另需验证：

- 全量规范语料包含合法、非法、Unicode 安全、路径、诊断、包构建、C 互操作（手写外部块）和确定性用例。
- 带 `build.pini` 的生成面不进自洽语料：它由构建脚本面单独验收，不拿自洽验收替它背书。
- 自举门禁进入 `ci/entrypoint.sh`，宿主 ABI、包语义或语言语义变化时必须复跑。
- 记录各代构建时间、峰值内存和产物大小；先建立基线，再设置回归阈值，不预编性能数字。

### 增量与工具演进

自洽之后沿既定包边界增强，不做二次架构迁移：

- `package` 增加接口缓存、增量重编与并行构建，调用方不变。
- `testkit` 在既有测试函数闭环上扩展夹具协议、差分和确定性乱序测试，不另建第二套测试框架。
- 若需要自举 CLI 自己调用 `clang`，再设计语言级进程原语与非零退出。
- formatter、语言服务和调试器进入各自的 `tooling` 包，不扩张驱动职责。
- 新后端只实现 `backend-kit`，运行时替换只改变 `runtime-api` 背后的实现。

## 风险与控制

| 风险 | 控制 |
|---|---|
| 为赶进度重新合并成总包 | 工作区硬门直接拒绝未声明依赖和内部引用；每批复核包图 |
| 包接口泄漏内部布局 | 导出接口只含必要声明，接口快照和跨包测试共同检查 |
| 整图构建固化为永久形态 | 产物身份从第一批定义，后续只替换 `package` 的调度与缓存 |
| 字节、标量、字素下标混用 | 不同封装类型，公共接口禁止裸整数跨域传递 |
| Unicode 数据膨胀与平台漂移 | 固定版本、生成有序表、构建期不联网 |
| 混淆规则误伤中文或合法混写 | 骨架只诊断不查找，高风险集合由真实语料钉定 |
| 未实现构造被静默写成零值 | 降载和发射 fail-loud，结构校验与行为测试同时存在 |
| 输出顺序导致不动点漂移 | 所有对外产物显式排序，并加入乱序输入对照 |
| 宿主和自举的标识符语义分叉 | 规范先改、同批落地、共享语料；查找键只用 NFC，原始拼写不进比较 |
| 语法树缺口被静默降级 | 语义层只检查语法树里存在的节点；缺的构造在计划里明列并归语法补面，遇到即报语法错误，不发明节点 |
| 自举与宿主的语法面差距被当成设计缺口 | 先逐条核对宿主实现，追平类只补实现不重裁语义；只有两侧都缺的构造才进规范讨论 |
| 语义与降载各写一遍类型判定 | 类型判定只在语义层，IR 只做类型池下标到 `IRType` 的映射；后端不重算布局 |
| 检查期线性查找拖垮吞吐 | 注册后建符号索引与声明索引；解析表与类型表按节点下标对齐；先测 `syntax` 包再扩全量 |
| 检查面缺口被跳过（fail-open） | 全部表达式节点进检查面；语法未表达的构造在语法补面明列，遇到即报错，不静默通过 |
| 槽布局与字节布局两处维护 | 语义层只出槽布局；字节口径单归 `backend-kit` 目标描述，接口产物只带槽位与字段序 |
| 临时内建扩散成永久语言面 | 只准 `temp` 前缀，逐条登记退出条件；正式能力落地时整组移除 |
| 两侧实现不同面，编译器源码用了只有一侧认识的构造 | 编译器源码只用两侧同面的构造；`as` 已两侧同面，字节换算仍走 `temp` 桥，替换随检查面接线 |
| 枚举项与顶层声明同处一个全局名字空间 | 降载期按裸名解析 case；跨包重名报歧义，注册面暂只判顶层与成员，枚举项的重名留给类型面统一登记 |
| 解析吞吐不足以支撑全量自解析基线 | 判据分层：收集层覆盖全量，解析零诊断抽样；吞吐本身单列为性能项，不用「减少判据」冒充完成 |
| 生成物落进源码树，或源码树里的文件冒充生成物 | 只写 `.build`；装载面只认计划登记且以 `.build` 组件开头的路径；构建后 `git status --porcelain` 必须无新文件 |
| 计划与源码不一致（脚本改过没重建） | 计划记脚本哈希与输入指纹；`check` 只验哈希与产物存在，重翻归 `build` |
| 外部符号同名异型被后写者覆盖 | 声明处一次裁决：签名与标志全同才合并，异型报错并指回首次声明 |
| 块名被当成库名，换通道换一套库 | 块名只是标签；库绑定只从 `[ffi].libs` 进计划，LLVM 拼 `-l`、解释器预加载同一清单 |
| 生成物用了自举解析器不认识的写法 | 映射规则只写在参考件与夹具；生成文本原样进自举解析，零诊断是判据 |
| 手写 `\|macro` 让自举依赖 C 预处理器 | 承载已定：求值结果随计划带出，检查期只读计划；无计划条目报能力缺口，不静默当缺符号 |
| 名义类型未进类型池时构造调用报缺口 | 降载期不新增池条目；缺口里写清类型名，靠补签名覆盖或回填池解决 |
| 推导期名字表只认字面量初值，局部类型大面积缺失 | 已闭合：函数级名字表 + 语句序增量（见该节）；兜底扫描防漏推 |
| 裸名用例清单按名字排除，同文件里有同名模式时值位被漏报 | 已闭合：值位裸名统一改前导点；清单按位置判，块头、模式行与声明位整行排除，名字级清单不当全集 |
| 前导点用例只按唯一候选定型，无期望类型下推 | 已闭合：期望优先、唯一兜底两级（见该节） |
| 标签实参位不吃期望，重名用例在该位仍报缺口 | 位置对不上会错定枚举，错定比不定更糟；标签对位留作后续 |
| 推导驱动改成语句序遍历后漏推，覆盖面反而下降 | 语句序之后按池序兜底扫一遍，未定型节点由已定型处向外传播 |
| 复合赋值把接收者求值两次 | 接收者只收标识符，其余形态报缺口；不用临时槽位伪造一次求值 |
| 方法符号名两侧算得不一致，调用点找不到声明 | 声明侧与调用侧共用同一份编码规则，名字与形参表各一条测试钉住 |
| 解释器自解析在 CI 停跑后丢掉一处通道覆盖 | 原生逐包门禁同批覆盖该用例，且多验发射与运行；停跑只在 CI 编排层，本地仍跑；恢复条件写在批内 |
