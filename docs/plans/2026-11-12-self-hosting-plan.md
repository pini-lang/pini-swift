# Pini 自举终态架构与实施计划

## 目标与边界

目标是用当前语言实现一个新的 Pini 编译器，使它能够编译自身，并在连续自产之间达到确定性不动点。

代际口径：首代自产指用宿主编译出的第一份 Pini 编译器，次代自产指首代编译自身所得，三代自产
依此类推。下文只用这三个词指代具体产物。

下一代自产指自产编译器自己读 `build.pini`、出构建计划、装载计划登记的生成模块、发射，再由脚本
调外部 `clang` 链接，产出可运行的下一代。判据：自产 `build` 退出 0 且产物可运行；两代文本逐字节
相同；构建后 `git status --porcelain` 无新文件。

自举验收必须同时满足：

- 编译器源码全部由 Pini 书写；脚本只负责构建编排、进程调用与产物比较，不承载编译逻辑。
- 工作区、包清单、依赖图、源码装载、语法、语义、IR 和 LLVM 文本发射均由自举实现。
- 首代自产能编译完整工作区并得到次代自产，次代自产能够运行。
- 次代自产与三代自产对同一输入生成相同的确定性 LLVM 文本。
- 合法与非法语料均以语言参考、IR 契约和手写期望为判据，不以宿主输出代替规范。

下列事项不阻塞自举验收：用 Pini 重写运行时，`PiniRuntime` 继续经 C ABI 复用；用 Pini 启动
`clang`，进程原语只在替换完整 CLI 时补；远程包下载、包仓库、LSP、调试器、REPL、embedded 后端
与完整工具链替换。为追求宿主 LLVM 文本一致而引入与规范无关的约定，同样不在线内。

本地多包工作区、包可见性、外部符号的包级可见性和依赖构建不是可选扩展，而是本计划的编译器基础能力。

## 筹划载体

所有架构决定、实施批次、验收判据、风险和后续调整只在本件内维护，不另立专题计划件。各批次的实际
代码、测试夹具、构建产物与验证日志属于交付证据，不属于新的筹划载体。

已交付批次按主题归并到 **已交付能力** 一章，只保留「现在是什么」与仍生效的约束；逐批的过程、读数
与教训不再随本件保留，取舍现场由提交记录回答。未开工项、保留差异与未收项按原样留在本件。

读数分两类，处置相反。**判据读数** 指缺口数——几例未收、几码未补、几格无：真源是
`pini-bootstrap/tests/parity/` 下由 `pini-bootstrap/tools/parity.py` 生成的四张表与手工维护的五张
来源表，正文不复述，要用时按表读，复述一遍就等于立了第二份真源。**参考读数** 指规模、耗时与体积：
只回答「当时差多少」，不承担长期参考价值，机器、构型或测试集一变须整组重取，不拿旧数字补新差；
需要长期基线时按 **解析吞吐与栈深** 的测量口径另立读数件，并同样标明易腐。描述当前状态的句子提到
读数时必须同时给出取数入口（表名或命令），只写数字不写入口按缺陷处理。

外部 C 互操作的语言面语义归 `docs/spec/pini-reference.md` 与 `docs/spec/c-interop-design.md`；本件只
承载自举侧的批次、判据与风险。三个来源的分工、构建期生成、符号裁决与链接口径按这两份文件执行，
本件不复述。

工作区奠基之后立即打通测试函数闭环。后续包不得等到功能完成后再补测试，统一按“先写失败测试、确认红、
最小实现、确认绿、重构并复跑”的循环推进。

## 自举路线

各语言的自举路线按「种子、阶梯、版本窗口、门禁」四件事归纳如下。细节随版本变化，引用时以各项目
官方构建文档为准；本件只取对 Pini 有约束力的条规。

| 项目 | 种子 | 阶梯 | 版本窗口 | 可借的条规 |
|---|---|---|---|---|
| Rust | beta 预编译 rustc | stage0 → stage1 → stage2；stage3 验同结果 | 不用未进 beta 的特性 | 种子随版本滚动；stage3 只验同结果 |
| Go | Go N-2（取偶）工具链 | 一次替换，无中间语言 | N 需 N-2 取偶：1.20 需 1.17，1.24 需 1.22 | 版本窗口写成公式，写进文档 |
| Swift | Swift 工具链，主分支起必需 | level-0 编译器与库 → level-1 → 自编译 | 6.2 为最后一个可无 Swift 宿主自举的版本 | hosttools 快；bootstrap 不依赖宿主 |
| GHC | 用户安装的 GHC | stage0 → stage1 → stage2，stage3 冒烟 | 需 GHC N-1 | stage3 只作冒烟，不作交付 |
| Zig | C 编译器或预编译 Zig | `bootstrap.c` → zig2 → stage3 → stage4 | 依赖最近一次可用的自建编译器 | 无 LLVM 路径只需一个 C 编译器 |
| Nim | csources（C 版编译器） | C 源 → `bin/nim` → `koch boot` | 种子随版本重新生成（`koch csource`） | 种子可刷新，不冻死 |
| Roslyn | 上一版 C# 编译器 | 自建编译器再编自身 | 每次变更即验 | bootstrap 正确性进 CI，失败可诊断 |
| Crystal | 上一版 Crystal | stage0 → stage1 → stage2 | 同大版本 2 年或 8 个小版本 | 向前兼容窗口写进发布政策 |

据此取五条方针：

- **单一源码树**：编译器源码只有 `pini-bootstrap/` 一份，宿主只作种子，不维护第二套编译器。
- **固定种子矩阵**：宿主提交、运行时库构建配置、LLVM 与 clang、Unicode 数据、目标三元组逐项登记；
  改任一项即整组重取读数、重跑全量，不拿旧读数补新差。
- **代际阶梯与同结果**：首代 → 次代 → 三代，发射文本逐字节相同；每代跑同一套测试，报告逐字节相同。
- **版本窗口**：自产源码只使用「当前种子与上一代自产都认识」的构造；首个发布版起保留两代升级窗口。
- **变更即自举**：提交前三秒自检；合并前单包 bootstrap；发版前全量；种子变更后必跑全量。

不采纳两条路线：从 hex0 一类最小种子重建整条链，Pini 的信任根是 Swift 工具链与 release 运行时库，
重写宿主不在线内；另写一套独立实现做交叉校验，保留「宿主发射与首代发射逐字节相同」作弱化版即可，
它是同一语言的两个实现产同一文本，足以发现代码生成漂移，不足以对抗信任根被替换。

## 架构原则

- **先定终态，再切批次**：任何功能直接进入最终归属包，不先放进总包再迁移。
- **包边界由编译器执行**：公开接口、包可见性和依赖方向必须由构建系统检查，不靠命名习惯或审查记忆。
- **接口与实现分离**：跨包只暴露值、类型、函数和错误契约；内部数据结构、遍历顺序和发射细节不得泄漏。
- **单向依赖**：基础包不认识编译器，语义不认识后端，后端不反向读取 AST，驱动是唯一编译器装配点。
- **无空壳包**：尚未实现的功能不建立占位 API；创建包时必须交付真实能力和测试，但目录规划从第一批就固定。
- **生成物即构建产物**：翻译结果落构建目录并由计划登记；源码树不出现生成文件，装载面只认计划里的路径。
- **中间形态不改终态边界**：早期可以整图一次性构建，后期再改增量构建；两种形态都使用同一包结构和公开接口。

根 `pini.toml` 是工作区清单，不是把全部源码装在一起的包清单。它登记成员包、构建 profile、共享 LLVM
与运行时配置，以及测试目标。工作区语法是待实现的构建能力，实施时先进入构建规范，不能由脚本私下解释
一套未登记格式。

### 包内统一形态

每个生产包使用同一结构：

```text
packages/<包名>/
  pini.toml
  src/
    api/
    _internal/
  tests/
```

- `api/` 是包间契约，只放公开类型、公开入口和导出声明。
- `_internal/` 是包内实现，其他包不可见；包内测试可以贴近实现，跨包测试只准走 `api/`。
- `tests/` 是测试 target，不进入普通库产物。工作区需要明确库、可执行文件和测试三类 target，不能用
  排除目录的临时技巧代替。
- 包清单显式列出本地依赖；未声明依赖的包即使源码可见，也不得被引用。

### 各包职责与允许依赖

| 包 | 职责 | 允许依赖 |
|---|---|---|
| `support` | 字节缓冲、切片、源码文本、区间、符号驻留、确定性容器、通用结果与错误 | 无包内依赖，只依赖语言与运行时基础 |
| `unicode` | UTF-8、标量分类、NFC、混淆骨架、Unicode 数据表 | `support` |
| `diagnostics` | 诊断码、严重级、源码位置、标签、修复建议、渲染 | `support` |
| `syntax` | 记号、AST、词法、语法、源码打印所需的语法信息 | `support`、`unicode`、`diagnostics` |
| `semantics` | 作用域、符号、类型、声明注册、可见性、外部符号裁决、类型检查、类型布局 | `support`、`unicode`、`syntax`、`module-loader` |
| `ir` | IR 节点、降载、份额、布局消费、外部符号节点、结构校验 | `support`、`syntax`、`semantics`、`module-loader`、`unicode` |
| `backend-kit` | 后端接口、能力声明、目标描述、发射结果与后端注册接缝 | `semantics`、`ir` |
| `backend-llvm` | LLVM 类型映射、文本发射、复制与释放胶水、外部符号发射、目标产物 | `semantics`、`unicode`、`ir`、`backend-kit` |
| `backend-dump` | 结构转储后端，只读模块、按固定节序出文本，作模块自足的见证 | `semantics`、`ir`、`backend-kit` |
| `backend-c` | C 头通道：按导出表出结构声明、函数原型与两个生命周期符号，布局断言让错位在 C 编译期就红 | `support`、`semantics`、`ir`、`backend-kit` |
| `backend-json` | JSON 通道：按宿主字段名与出现次序出单行文本 | `semantics`、`ir`、`backend-kit` |
| `runtime-api` | 运行时段符号、C ABI 声明、句柄与桥接能力清单 | 无包内依赖，只依赖语言与运行时段符号 |
| `package` | 工作区与包清单、`[ffi]` 库绑定与头文件集合、target、依赖图、构建脚本步骤与计划、拓扑排序、产物身份 | `unicode`、`syntax` |
| `module-loader` | 从构建计划读取源码（含计划登记的生成模块）、规范化和解析，形成语法层编译单元 | `unicode`、`diagnostics`、`syntax`、`package` |
| `hostproc` | 进程族封装与工具链定位，编译命令调外部工具的唯一点 | 无包内依赖，只依赖语言与运行时段符号 |
| `evaluator` | 树遍历求值器：`run`、`test --interpret`、`repl` 与 `debug` 的执行通道，不读类型表 | `support`、`unicode`、`syntax`、`module-loader` |
| `driver` | 编译器库入口与 CLI，装配装载、检查、降载、测试执行、后端和输出 | 上述编译链各包、`evaluator`、`hostproc` 与 `testkit`，禁止反向被依赖 |
| `testkit` | 测试发现、筛选、顺序、执行器接口、结果报告、夹具协议与确定性乱序测试 | `support`、`ir` |

依赖图必须保持无环。`package` 只为取构建脚本写法读语法树，不建符号表也不做类型检查，`module-loader`
不做类型检查，`semantics` 不读文件，`ir` 不调用 LLVM，`backend-llvm` 不解析源码，`driver` 不拥有各层
内部规则。

依赖列即当前允许集，增删依赖与改本表同批。三处与真实调用路径不一致，登记为待收窄：
`semantics` 只从 `module-loader` 取编译单元与包模型类型，其清单仍声明 `package`，这条由无调用点的
`registerWorkspace` 带入；`backend-kit` 声明 `semantics` 而源码未取其中任何符号；`runtime-api`
没有入边，运行时段符号名仍由 `backend-llvm` 自带，接线后它才进依赖图。

### 标准库、工具与测试的位置

- `pini-bootstrap/stdlib/` 是独立源码包，由驱动按语言规则装配到用户模块；编译器各包不得通过反向
  import 获取它。
- `tooling/formatter` 只依赖 `syntax`、`support`、`diagnostics`，不得为了复用 CLI 而依赖 `driver`。
- `tooling/language-server` 可以依赖 `syntax`、`semantics`、`module-loader`，不得依赖 LLVM。
- `tooling/debugger` 通过独立调试接缝消费源码映射，不进入编译主依赖链。
- `runtime/abi/` 保存 C 侧契约与链接元数据；Pini 侧声明只归 `runtime-api`，避免两套符号清单漂移。
- `tests/architecture/` 检查包依赖、公开接口和禁止引用。
- `tests/integration/` 覆盖多包构建、缓存、增量重编和诊断。
- `tests/conformance/` 保存语言正负语料与手写期望。
- `tests/selfhost/` 保存自洽、不动点和确定性验证协议。
- `tools/` 只保存构建与测试编排，不放任何生产编译逻辑。

新增后端只新增实现 `backend-kit` 的包，并在驱动注册；不得把目标判断散落到 IR 或语义层。新增工具
只进入 `tooling/`，不得把命令实现堆回 `driver`。

## 工作区与构建契约

### 包接口产物

每个库包在逻辑上生成三类产物：

- **导出接口**：公开声明名、函数签名（参数名与类型、返回类型）、类型布局所需信息、依赖声明与包名。
  泛型实例化所需语义信息随类型面补面接入。
- **编译产物**：供链接或整图发射使用的 IR 与目标产物。
- **构建身份**：包源码、构建脚本与生成物、公开接口、依赖接口、语言配置和后端配置的内容摘要。

记录形状固定：接口文本逐包写 `.build/<profile>/packages/<包>/interface.api.txt`，工作区记录写
`<根>/.build/<profile>/interfaces.toml`，产物记录写 `artifacts.toml`；记录版本 2，按包名排序、只存
摘要与根相对路径，接口条目另记本包源码摘要，产物条目另记输入指纹（源码摘要、发射身份与依赖接口
摘要合一）。

判据只认内容不认时间戳：命中即不重算公开面、不重发 IR；公开面变化只波及直接下游，接口文本未变则
再下一层复用。宿主写同形的 `interfaces.host.toml`，与自产记录文件名区分、`path` 指向
`interface.txt`，两侧记录不互读；接口文本各自形态，逐字节对齐留待类型面进入接口文本。

并行与远程缓存放在语言外的两层：`plan --waves` 按依赖深度出波次，外部步骤逐波并行调
`emit --packages --package=<包>`；`--cache-dir=<目录>` 按输入指纹读写 `<目录>/<指纹>/<包>.ll`，
目录可挂网络盘或随流水线搬迁。语言层没有进程与网络内建，驱动不做调度。

### 构建形态演进

- 初期允许工作区整图装载、整图检查、整图发射，但包间仍只能读取导出接口。
- 随后增加按拓扑序的包产物和接口缓存，不改变包目录、调用方或依赖声明。
- 最后增加并行构建与远程缓存；它们都不属于自举验收前置。
- 终态：宿主发起的 `build` 仍是整图构建，自产 `build` 只出计划与指纹，翻译归外部步骤，发射归
  `emit`，链接归脚本；计划是构建形态的接口，根相对、无时间戳、跨机器逐字节相同。
- 任何阶段都禁止跨包读取 `_internal/`，禁止通过“先把源码并入同包”绕过可见性。

### 构建脚本与生成模块

`build.pini` 是声明文件，不是可执行脚本：每个 `[名称|given]` 块读成一条翻译步，块名即步骤名，字段
固定为 头文件、包含路径与定义。声明式不是风格取舍，是“配置纯净”的现成形态——语言还没有计划对象的
构造面，执行式配置要先补一个配置期内置与语义入口。

构建分两段：配置期只登记并产出计划，执行期才翻译、发射、链接。

- 计划是纯数据：`<根>/.build/<profile>/plan.toml` 记包根、脚本哈希、每条步骤的头文件与产物路径、
  输入指纹，以及两张结果表——`[[macro]]` 记包、名、状态与值或未求值理由，`[[skip]]` 记生成面跳过
  的宏与理由。
- 生成物落 `<根>/.build/<profile>/packages/<包>/generated/<步骤名>.pini`，归声明它的包；步骤名须是
  合法的路径分量且在包内唯一。
- 单一装载入口：计划缺失、脚本哈希不符、产物缺失各报一条指向 `pini build` 的诊断，不静默跳过。
- 路径白名单：只接受以 `.build` 组件开头且登记在计划里的产物路径，其余一律拒绝。
- 确定性：同一输入两次构建的计划与生成物逐字节相同；指纹含头文件与整棵包含树、包含路径、宏定义、
  翻译器版本与目标平台。
- 跨包共用同一头文件时各翻一份：正确性不受影响，多花的是翻译时间；去重的前提是落点与包名解耦。

注意 计划是数据不是代码：`check`、`run`、`test` 只读计划，绝不执行 `build.pini`。脚本写坏只影响
`build`，不会让整个仓库的检查一起红。

### 架构硬门

工作区构建器直接依据依赖图执行以下判据：

- 未声明依赖、反向依赖、跨包内部引用、循环依赖均为构建错误。
- 包公开接口与导出接口产物必须一致，接口变化必须触发对应下游重建。
- 同一包不能同时以源码路径和另一种包身份进入同一张图。
- 构建、测试和自举三代链共用同一依赖图，不允许脚本另排一套包顺序。
- 生成物路径越出 `.build` 前缀，或未登记在计划里，均为装载错误；构建只写构建目录，不写源码树。

## 文本模型

采用**字节编译内核**，严格分开三个文本域：

| 文本域 | 用途 | 禁止事项 |
|---|---|---|
| UTF-8 字节 | 源码保存、ASCII 记号、关键字、区间、LLVM 文本 | 不得把字节下标当用户字符下标 |
| Unicode 标量 | UTF-8 校验、标识符分类、转义解码、规范化 | 不得把标量序号当字节偏移 |
| 字素簇 | 现有用户层 `Char` 与 `String` 行为 | 不得用于词法游标和源区间 |

核心类型按最终包归属：

- `support.ByteBuffer`：持有完整 UTF-8 字节，不支持隐式字素解释。
- `support.ByteSlice`：保存缓冲区身份、起点和长度，切片不复制。
- `support.SourceText`：持有规范化后的源码、文件名和逐行起点表；`Span` 一律是字节区间。
- `support.ByteBuilder`：线性追加 ASCII 与 UTF-8 字节，供诊断和 LLVM 发射使用。
- `unicode.UnicodeText`：包装需要标量分类或规范化的小段文本，不进入扫描热路径。

当前语言只需补两类内部桥接能力：把 `String` 的完整 UTF-8 内容复制成字节数组，以及把字节数组经
UTF-8 校验后组成 `String`。桥接经现有 C ABI 运行时实现并登记到 `docs/spec/runtime-abi.md`，不暴露
指针算术，不改变用户层字符串语义。

词法器不得使用 `split`、`replace` 或字素下标扫描源码。标识符和字面量先记字节区间，确实需要内容时
才切片；记号默认携带 `Span` 与符号编号，不携带整段复制文本。

## 标识符身份与混淆

采用**原始拼写保留、规范化负责身份、混淆分析负责诊断**的三轨模型：

- 原始拼写永远保留在 AST、符号声明和诊断中，不改写用户源码。
- 符号查找键使用 NFC 规范化结果；同一作用域内，原始拼写不同但 NFC 相同的声明按同一符号冲突处理。
- 规范化只在标识符上进行，不规范化整个源文件，字符串字面量和注释内容不受影响。
- Unicode 版本必须固定，字符类别、规范化与混淆表由受控数据生成 Pini 表并纳入版本控制；构建和运行
  不得依赖宿主操作系统的 Unicode 版本。
- 混淆骨架只用于安全诊断，绝不用于符号查找，避免把视觉相似误当成语言等价。

混淆策略不按“非 ASCII 一律危险”处理，中文标识符仍是正式能力：

- 对拉丁、西里尔、希腊等高风险混写给出错误；常用脚本与中文的合理组合不因混写这一因素被拒。
- 对同作用域内混淆骨架相同的标识符给出警告，并同时展示原始拼写和转义后的码点序列。
- 全角字母数字、数学字母数字、兼容等价拼写至少给出警告；是否提升为错误由语料门禁验证后固定。
- 标识符中的零宽字符、双向控制字符和不可见格式字符直接拒绝；注释与字符串中的双向控制字符给出
  明确警告。
- 无效 UTF-8、BOM 和 NUL 在装载期响亮拒绝。CRLF 归一化发生在词法之前，所有区间统一指向归一化后的
  `SourceText`。

NFC 会改变符号身份，属于语言面决定。实施前先修订 `docs/spec/pini-reference.md`，宿主和自举同批对齐；
若暂不采纳 NFC，则只能把规范等价冲突降为警告，不能暗中在自举符号表里做另一种查找语义。

## 受限源码约定

受限只约束编译器自身的写法，不压缩终态包结构，也不缩小编译器最终必须接受的用户语言：

- 使用结构体、枚举、数组、字典、函数、`match`、循环、`Result` 和显式类型标注。
- 泛型只保留容器与必要算法所需形式，避免把高阶类型推断扩散到编译器源码。
- 不使用结构化并发、`LazyRef`、弱引用与无主引用；外部声明只收标量、指针、`String` 形参与
  `StringHandle`，不碰按值聚合。
- 本地多包、公开接口和包可见性属于必用能力，不得列入“以后再支持”。
- 公共声明显式写参数与返回类型，不依赖宿主推断细节。
- 不用字典遍历顺序决定输出。文件、声明、符号、诊断、类型布局和 LLVM 定义都显式排序。
- 不用宿主字符串优化、文件系统顺序或哈希种子作为正确性的前提。
- 不写「块内 `var 名: Array<T> = []` 与元组返回同现」的声明：宿主对此判型错位，空名单由函数给。

用户语言覆盖按规范逐项回填，并为每个新增构造补正负语料。

### 解释器自解析搁置

解释器通道里 `自解析` 一项占去四成耗时，而同一用例在原生通道已由逐包门禁覆盖，且覆盖更严——它把
发射与运行一并验证。故 CI 停跑解释器那一份，本地默认仍执行，它承担解释器与原生分叉的早期信号；
恢复条件是可度量判据：该项在解释通道不高于原生同项的五倍，达不到就继续停跑。原始读数见
`docs/plans/readings/2026-11-16-interpreter-selfparse-skip.md`。

### 仍生效的四条约束

装配链与停点：plan → load → world → fill → shapes → layouts → lower → validate，一条命令一条链；
`check`、`build`、`plan`、`lower`、`dump`、`emit`、`test`、`cases` 只是同一链的不同停点，诊断非空
即不发射。

身份与缓存：三类产物各记摘要；命中判据只看内容摘要，不看时间戳；缓存写入只发生在新发射之后，发布
前仍要整批重建复核。

份额与所有权：份额只认四族类别码（0 不动作 · 1 串 · 2 容器 · 3 名义箱）；值语义箱在四个存储点拷出
独立箱；空箱归还走旁路；循环内重复声明先还上一轮；匹配主语落槽后要填接收动作。

后端与契约：字节宽度与对齐只在 `backend-kit` 的目标描述里算一次；整数常量按 I64 全宽出文本；IR 不
出现 LLVM 名称、指令与目标布局判断。

## 总判据与处置口径

四条总判据，按处置判，不按「看起来能跑」判：

- **程序表**清空：`examples/` 每个程序过 `check`、`lower`、`emit` 三条腿。
- **命令表与通道表**每一格有处置，补齐项清零。
- **诊断表**每条缺码有依据与处置，补齐项清零。
- **执行表**每个示例有处置，写「通过」而实际变红即拒生成。

处置是机械判据：三张静态表由 `pini-bootstrap/tools/parity.py` 生成，缺行、陈旧行与非法取值都拒绝
生成；程序表与执行表要跑示例，只在 `--full` 下重取。处置词表取六种之一——补齐、自举内部通道、
随执行线、保留差异、仅宿主实现、设计预留；保留差异与随执行线必须在来源表写明理由与退出条件，退出
条件不成立前不重开该项。人工来源是 `pini-bootstrap/tests/parity/` 下的五张 `.tsv`。

自举独有的命令不要求宿主补齐，也不计入归零项：`plan`、`lower`、`dump`、`cases`、`interfaces` 按表内
理由登记即可。

边界：运行时仍经 C ABI 复用，不重写；扩运行时段先登记 `docs/spec/runtime-abi.md` 再进实现，合计数与
`tools/runtime-abi-check.py` 同批更新。不以宿主输出回填语言判据，产物结构按 `docs/spec/ir-contract.md`
的字段比，宿主快照只作回归护栏；宿主已知偏宽处（`len(1)` 之类）不得按「仅宿主实现」补进自举。新能力
不进编译器源码，直到自洽链能编过；工具面允许长期留差异。

## 解释通道提速（待办）

**热函数编译** 未交付；**环境归位** 的存储形态已落地，余 `test --interpret` 的 `E5-005` 越界（改造前既有）。
本节保留完整判据；目标是 **追平原生**（把解释通道追到原生同量级），两段都收之后再评估是否达标。

解释通道的耗时随输入平方增长，不是常数因子慢。根因在块求值：每进入一个块就新开一层环境，退出不回退；
循环体每轮涨一层，环境表单调增长。赋值回写走整表写时复制，单次代价随环境表长度线性上升，于是总代价
随轮数平方上升。这条与 **解析吞吐与栈深** 对原生通道的诊断同源（共享存储深拷），但解释器侧表现为整表
复制，不是逐元素深拷。

**环境归位**：环境表改引用语义，块退出回退到进入时的水位，赋值不再整表复制；控制流旗标、返回位与
错误态仍按值走，只有绑定表共享。判据：扣除装载底噪后两万次循环不高于一秒；输入翻倍耗时不超过
二点四倍；`test --interpret` 的五包原生测试全绿，且单包耗时不随用例数超线性增长。边界：只改存储形态，
不改求值次序与错误传播；两通道报告逐字节对照是等价证据。这一批是 **热函数编译** 与交互三命令共同的
启动条件。

**热函数编译**：按函数归集步数，越过阈值后把该函数单独发射成动态库并装载，调用点改经跳转槽。槽表放在
运行时段，求值器调用前查槽，槽空照常解释，装载成功后把地址写进槽。路线取子进程加跳转表：
`emitPartition` 已能按函数名单出 IR，`clang -shared` 出动态库，`dlopen` 载入，运行时段只多一条写槽的
符号。不把函数指针引进语言面——槽的签名是固定的 C 形状，不经过 Pini 函数类型。注意 写槽符号要进运行
时段，与读行入口的符号增补同属一次扩容，两批不能并行改 ABI 文档与三处计数。

首批范围收在纯标量：形参与返回都是 `I32`、`I64`、`F64` 或 `Bool`，无闭包、无容器、无 `|self`、无
`defer`。热循环正好是这个形状，边界不需要装箱转换，这一批即可验收；其余函数留解释通道，不做部分编译。

判据：同一热函数两通道输出相同；单函数耗时降到解释通道的百分之五以下；编译、链接或装载失败只让该函数
永久留在解释通道，不改退出码与报告。边界：类型定义在编译期已定，装载后没有重载需求；旧库不卸载，同一
函数按源摘要只编一次并设次数上限；两个平台各验一次，不以一处读数外推。注意 这一条不保证「与原生同量
级」：边界仍有调用与转换的固定开销，只对单次调用内迭代足够多的函数成立；交互式命令的延迟由
**环境归位** 承担。

## 宿主迁移评估

问题是：何时把 Swift 宿主移出构建链，改用「Pini 编译器 + C 运行时」。今天两条实现并存——宿主含
解释执行、语言服务、调试适配、REPL 与 C 头翻译，自举侧含编译链与求值器；差不在行数，在命令、通道、
诊断三张表与执行路径。

判据六条，按硬度排：

- **命令面**：`commands.tsv` 每格有处置；余两条「无」是 `dap`、`lsp`，均按保留差异登记。
- **通道面**：`channels.tsv` 的「无」清零——`c` 已接，余 `embedded_min` 的未保留格。
- **诊断面**：缺码按处置清零，补齐项已交付；其余按保留差异、随执行线、仅宿主实现、设计预留登记。
- **执行路径**：`run` 要有不依赖宿主的执行方式，现由自举求值器执行；`test` 走解释通道，`run-llvm`
  经 `lli` 执行。
- **种子**：首代二进制可复现取得并登记摘要。没有登记过的二进制，移出宿主等于让「哪份产物可信」无人
  回答。
- **版本窗口**：两代升级窗口生效后才冻结种子；版本串宿主与自举同值，改号要两处同批。

结论：编译器侧接近，执行面刚起步，工具侧未到，运行时段是另一笔。

- 已成熟：自洽链四项逐字节相同；程序表清零；命令行的退出码、首条诊断与归一全文三种签名逐条登记在
  `cli.tsv`。
- 未成熟：`dap`、`lsp` 两条未接，均按保留差异登记；执行表按 `execution-disposition.tsv` 分随执行线
  与保留差异；C 互操作的生成侧只到 `bind`；诊断面仍有缺码，非法程序可能报不出专用码。
- 运行时段另计：`PiniRuntime` 仍是 Swift 实现，C 化要重写字符串、容器、引用计数与并发，并重验两条
  通道。它不阻塞编译器迁移，但「零 Swift」要等它。

分四段推进，每段可独立验收：**默认发布**、**差集清零**、**冻结种子**、**运行时 C 化**。前两段已交付，
安装、打包与 CI 入口同批改齐；冻结种子的 `linux-amd64` 行由 `release.yml` 构建后回传摘要，未到手前不写
占位行——占位行会让「已登记」变成没人核对的声明。运行时 C 化独立立项，判据是
`docs/spec/runtime-abi.md` 登记的符号全数等价、两条通道行为一致。

注意 迁移换的是信任根，不是实现：从「Swift 工具链 + release 运行时段」换成「冻结的 Pini 种子」。未登记
种子摘要就移出宿主，等于把最该有判据的一步留成口头约定。

## 导入形态整顿（搁置）

现状：编译器源码的导入块以注入式为主（`_别名 = "路径"`），路径按文件层级写死，调用点看不出名字来自
哪一层；限定式也在用，但存在写死却从未使用的死导入，无人发现。目标是把跨包名字带上别名前缀，注入形态
在编译器自身源码里收敛为零——语言保留该能力，标准库与用户包照用。

三步，第一步与整顿解耦，已交付并保留：

- **类型位前缀**：类型注解认 `别名.类型`，两通道各补解析、打印、判型与接口文本；`别名.类型<T>` 报
  解析错。这一步补的是参考件 §4.2「非 `_` 别名必须限定」在类型位落不了地的缺口。
- **逐包翻转**：一批一个包，自底向上；每批四步：`_别名` 改 `别名` → 自举 `check --diagnostics-tsv`
  收全部未定义名 → 按行·列定位并唯一改写 → 复跑至零诊断。
- **收口**：门禁加一条，编译器源码的导入块不得出现 `_` 别名。

搁置的两个卡点，一层比一层深：

- **名字面**：文件可见面没按导入路径算出来。`knownName` 先查全工作区顶层表，注入表只作补充，于是
  「导入与否」不影响判定；宿主相反。
- **符号表**：登记按包平铺、不循导入路径生成；导入块只登记别名，不产出符号。文件级符号面因此得另行
  计算——这才是「可见名」补丁治不了根的地方。

试点已证后果：一个包翻转四条导入后，自举检查一条错也不报，收错一步没有信号；离线估算也顶不上，按名字
匹配会把内建名与局部名算成跨包引用，抽样误报过半。

已定：导入右端维持路径，参考件只写明「导入侧不筛选，公开与否归导出侧」；测试目录与 `src/api` 同批
翻转，一个包的导入块一次清完。重评排在 **工具面** 之后，重评前不动包源码；重评时先回答「符号表按什么
路径产」，再谈逐包翻转的收错办法。

## 风险与控制

| 风险 | 控制 |
|---|---|
| 为赶进度重新合并成总包 | 架构硬门拒绝未声明依赖与内部引用；每批复核包图 |
| 包接口泄漏内部布局 | 导出接口只含必要声明；接口快照与跨包测试共同检查 |
| 字节、标量、字素下标混用 | 不同封装类型，公共接口禁止裸整数跨域传递 |
| Unicode 数据膨胀与平台漂移 | 固定版本、生成有序表、构建期不联网 |
| 混淆规则误伤中文或合法混写 | 骨架只诊断不查找，高风险集合由真实语料钉定 |
| 未实现构造被静默写成零值 | 降载与发射 fail-loud，结构校验与行为测试同时存在 |
| 输出顺序导致不动点漂移 | 对外产物显式排序，并加入乱序输入对照 |
| 宿主与自举的标识符语义分叉 | 规范先改、同批落地、共享语料；查找键只用 NFC，原始拼写不进比较 |
| 语义与降载各写一遍类型判定 | 类型判定只在语义层；后端不重算布局 |
| 检查面缺口被跳过（fail-open） | 全部表达式节点进检查面；语法未表达的构造明列，遇到即报错 |
| 槽布局与字节布局两处维护 | 语义层只出槽布局；字节口径单归 `backend-kit` 目标描述 |
| 临时内建扩散成永久语言面 | 只准 `temp` 前缀，逐条登记退出条件 |
| 生成物落进源码树，或源码树里的文件冒充生成物 | 只写 `.build`；装载面只认计划登记且以 `.build` 组件开头的路径 |
| 计划与源码不一致（脚本改过没重建） | 计划记脚本哈希与输入指纹；`check` 只验哈希与产物存在，重翻归 `build` |
| 接口记录与源码不同步，下游拿旧接口通过检查 | `check` 按整份接口文本比记录，本包或依赖变化即报 E3-021；记录只由 `interfaces` 重写 |
| 逐包切分把跨包定义漏进别包，链接期报重定义 | 本包名单按函数源文件首段归包，非本包只出声明；自检逐包编译后再合并链接 |
| 共享缓存按指纹取文件，被污染的缓存被当成正确产物 | 缓存键含源码摘要、依赖接口摘要与发射身份；写入只发生在新发射后，发布前整批重建复核 |
| 外部符号同名异型被后写者覆盖 | 声明处一次裁决：签名与标志全同才合并，异型报错并指回首次声明 |
| 族声明与节点可达脱节，声明成了空头承诺 | 能力普查三列并排，`--check` 判「接通即声明、声明即至少接一条」 |
| 跨通道诊断差异被当成噪声长期挂着 | 基线只许缩小，转为一致即反红；新差异必须先写进已知缺口再登记 |
| 对照夹具把旧产物的行为钉成期望 | 两侧产物都要求新于源码，落后即拒跑；重取只走 `--bless` |
| 提速改动改变产物 | 每批先比四项产物读数与语料，读数不符即回退 |
| 种子升级后旧读数冒充新结论 | 种子矩阵改一项即整组重取；全量失败先比文本再查代码 |
| 新增语言特性渗进编译器源码，旧自产编不过 | 自洽链本身就是前代编译门禁；首个发布版起扩为两代窗口 |
| 导入整顿改写误伤局部同名与字段名 | 只按诊断给出的行·列改名，不做文本替换；`fmt --check` 零输出；按包分批提交与验收 |
