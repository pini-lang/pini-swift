# C 错误通道调研

**问题**：`^T` 导出到 C 只交状态码 `0/1`。调用方知道失败了，不知道失败原因。本次调研回答：错误能不能作为数据过边界；若能，以什么形态、要动哪一层。

## 判据

「错误即数据」在本项目不是口号：参考手册 §8.4 把错误定义为 `Error` / `CancelError` 名义类型的值，经 `Result` 显式传播，不在调用栈上抛异常。落到 C 边界，同一条原则拆成三条可判定的要求：

| 判据 | 含义 | 反例 |
|---|---|---|
| 回传 | 错误随本次调用的返回值或出参回到调用点 | 事后调 `last_error()` 查询 |
| 所有权 | 谁持有、活多久、谁释放，调用方不必猜 | 交出一个指向被调函数栈帧的地址 |
| 并发 | 两个会话同时失败互不覆盖 | 进程级单槽 |

另有工程判据：**ABI 面积** —— 每个导出函数多几个参数、返回形态是否整体变形。

## 现状

### 错误值是进程期自持的堆盒

`Error("msg")` 在 IR 里唤的是 `bk_error_create`，得到一个 `i64` 句柄（`Sources/PiniIR/IR/IRLowerer.swift:3535`）。运行时把消息 `strdup` 进一个盒子，用 `passRetained` 交出去，之后不再释放（`Sources/PiniRuntime/PiniRuntime.swift:1790`、`:1801`）。

读侧是两个纯函数，都只吃那个字：

| 读法 | 落点 | 行为 |
|---|---|---|
| `e.message` | `bk_error_message` | 返回盒内 C 串；文档写明「指针在对象存活期（= 进程期）内稳定」 |
| `isCancel(e)` | `bk_error_is_cancel` | 读盒上的标志位 |

所以错误在运行时**已经**是数据：两种类型、独立所有权、可并发读取、消息可任意拼接（运行时已经复制了一份）。C 边界缺的不是表示，是导出面没把那个字交出去。

注意 —— 上一版把「同一函数再调一次，旧 Result 读到新消息」当作悬垂证据。那个复现写错了：handler 里先 `return`，程序根本没走到第二次读。重做后旧 Result 仍读到「第一次」，解释器与 LLVM 一致。盒子是自持的，不悬垂。

### 错误槽的合法值域没有约束

`Result<T, E>` 的 E 在类型层不参与定形（`Sources/PiniIR/IR/IRNode.swift:29` 明说这一点；`TypeChecker` 让 `err` 成员的类型直接等于 E）。于是 `err(42)` 能过检查，运行到 `e.message` 时 42 被当作地址解引用 —— 实测 LLVM 直接崩溃。

这是错误槽唯一的真实缺陷：不是悬垂，是**谁都能往那个字里塞东西，读侧却假定它一定是盒**。任何 C 通道都建在这个假定上，所以值域得先收。

## 先例

| 先例 | 形态 | 错误在哪 |
|---|---|---|
| Zig | `!T` 错误联合 + `@errorName(e)` | 错误是返回值的一部分；名字是静态表的纯投影 |
| Win32 | `HRESULT` + `FormatMessage` | 码即数据；文案是码的纯函数 |
| Rust FFI | `#[repr(C)]` 结果结构体或出参 | 错误值走数据，调用方拥有 |
| Swift | `throws` → `NSError**` 出参 | 错误对象所有权转给调用方，要 release |
| POSIX | `errno` | 环境状态，非数据；本调研判为反例 |

可借两条：Zig 的「码是数据、文案是投影」，Rust 的「结构体返回、零隐藏状态」。Swift 的出参形态多一层所有权转移，只在必须转移对象所有权时才值得 —— 这里不需要，盒子本来就归库所有。

## 候选

### 码表

```c
int32_t calc_div(int32_t a, int32_t b, int32_t* out);
const char* calc_strerror(int32_t code);   /* 纯函数，静态串 */
```

错误值就是码；文案由库的表投影。零分配、并发安全、ABI 只多一个纯函数。
代价：码要有语义来源。语言层没有错误分类，只能取 `0/1/2`（成功/失败/取消）或由编译器按消息字面量编号。

### 状态结构

```c
typedef struct { int32_t code; const char* message; } calc_status_t;  /* 0 成功 1 失败 2 取消 */
calc_status_t calc_div(int32_t a, int32_t b, int32_t* out);
```

每次调用都带回码与消息，无隐藏状态、零分配 —— 盒子已经在了，导出桩只是把 `bk_error_message` 的返回值填进去。
代价：`^T` 导出的返回形态整体变形，现有 C 调用方要改。

### 缓冲出参

```c
int32_t calc_div(int32_t a, int32_t b, int32_t* out, char* err, size_t cap);
```

任意消息（含拼接），调用方给缓冲，生命周期归调用方。
代价：每个 `^T` 函数加两个参数；调用方每次都要备缓冲，即便成功。消息本来就有稳定指针，这条多做了一次复制。

### 错误句柄

```c
calc_error_t* calc_div(int32_t a, int32_t b, int32_t* out);  /* NULL = 成功 */
const char* calc_error_message(const calc_error_t*);
bool calc_error_is_cancel(const calc_error_t*);
void calc_error_release(calc_error_t*);
```

错误是拥有型数据，可保存、可比较、可跨调用；`isCancel` 一起过边界。
代价：四五个新符号，外加一条 release 契约（盒子现在不释放，交出去就得定谁来释放）。

### 旁路槽

```c
int32_t calc_div(int32_t a, int32_t b, int32_t* out);
const char* calc_last_error(void);   /* 线程局部，下一次失败覆盖 */
```

ABI 面积最小。
代价：违反回传与并发两条判据，错误会被下一次调用覆盖。**不采用。**

## 对照

语义维度：

| 候选 | 回传 | 所有权 | 并发 | 取消可辨 | 消息来源 |
|---|---|---|---|---|---|
| 码表 | 是 | 无对象 | 安全 | 码等于 2 | 静态表 |
| 状态结构 | 是 | 库持有，进程期 | 安全 | 码等于 2 | 任意 |
| 缓冲出参 | 是 | 调用方 | 安全 | 另加一个出参 | 任意 |
| 错误句柄 | 是 | 调用方 release | 安全 | 访问器 | 任意 |
| 旁路槽 | 否 | 不确定 | 不安全 | 另查一次 | 任意 |

工程维度：

| 候选 | 新增分配 | 调用方负担 | ABI 破坏 | 新增符号 | 需改语言层 |
|---|---|---|---|---|---|
| 码表 | 无 | 无 | 否 | 1 | 码的来源要定 |
| 状态结构 | 无 | 无 | 是（改返回形态） | 0 | 值域约束 |
| 缓冲出参 | 无 | 每次备缓冲 | 是（每函数 +2 参） | 0 | 值域约束 |
| 错误句柄 | 无（盒子已在） | 必须 release | 是（改返回形态） | 4–5 | 值域约束 |
| 旁路槽 | 无 | 无 | 否 | 1 | 无 |

## 推荐

**表示层不用重写，先收值域，再做边界。**

1. **值域**：把 `err(...)` 的载荷限定为 `Error` / `CancelError`。不收，任何通道都可能在第一个非盒载荷上崩；收的代价是要改 `IRNode` 里「E 不受约束」那条注释与参考手册 §11.1 的表述。
2. **边界**：取状态结构。导出桩在失败分支读 tag、调 `bk_error_message` 与 `bk_error_is_cancel`，填进 `{code, message}` 返回。零分配、无隐藏状态，消息任意（运行时已复制自持），正好是「错误即数据」在 C 上的直译。
3. **不做**旁路槽；句柄形态留到真有「保存错误、稍后再读」的调用方。

注意 —— 状态结构唯一的真实成本是 ABI：`^T` 导出从 `int32_t` 变 `calc_status_t`，现有 C 调用方要跟着改。这是破坏性变更，得一次性切换。

## 分步

| 步骤 | 内容 | 验收 |
|---|---|---|
| 值域 | 类型层限定 `err(...)` 载荷为 `Error` / `CancelError` | `err(42)` 报类型错；全量绿 |
| 边界 | 导出桩读 tag 与两个访问器；`IRExportFunction` 增状态结构形态；头文件出 `calc_status_t` 与三态常量 | C 调用方拿到两种不同消息，能区分失败与取消 |
| 可选 | `calc_strerror` 静态表；错误句柄形态 | 由真实调用方需求触发，不预做 |

## 待决

**E 要不要收紧？** 收紧：错误槽的读侧假定成立，`e.message` 不再可能崩；代价是改语言层「E 不受约束」的既有选择，参考手册要同步。

**签名变形可接受吗？** `^T` 导出从 `int32_t` 变 `calc_status_t`，现有 C 调用方要改，属于破坏性 ABI 变更，需一次性切换或版本化。
