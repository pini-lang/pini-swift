# C 错误通道调研

**问题**：`^T` 导出到 C 只交状态码 `0/1`。调用方知道失败了，不知道失败原因。本次调研回答：错误能不能作为数据过边界；若能，以什么形态、要动哪一层。

## 判据

「错误即数据」在本项目不是口号：参考手册 §8.4 把错误定义为 `Error` / `CancelError` 名义类型的值，经 `Result` 显式传播，不在调用栈上抛异常。落到 C 边界，同一条原则拆成三条可判定的要求：

| 判据 | 含义 | 反例 |
|---|---|---|
| 回传 | 错误随本次调用的返回值或出参回到调用点 | 事后调 `last_error()` 查询 |
| 所有权 | 谁持有、活多久、谁释放，调用方不必猜 | 交出一个指向被调函数栈帧的地址 |
| 并发 | 两个会话同时失败互不覆盖 | 进程级单槽 |

另有工程判据一条：**ABI 面积** —— 每个导出函数多几个参数、返回形态是否整体变形。

## 现状

### 错误在语言层是数据

`Error` 与 `CancelError` 都是名义类型，各带一个 `message: String`；`isCancel` 区分二者（参考手册 §8.4）。`try ... else e:` 把错误值绑给 `e`，`e.message` 可读。

### 在 IR 层是一个字

`Result<T>` 的 LLVM 形态是 `{ i64, T, i64 }`：只带 ok 载荷，错误槽擦成机器字（`Sources/PiniIR/IR/IRNode.swift:81`）。构造时 `.resultConstruct` 把错误载荷 `widenToWord` 后写进第三个槽（`Sources/PiniBackendLLVM/CodeGen/IREmitter.swift:2402`）。`try` 把那个字原样存进局部槽（同文件 `1869`），读 `e.message` 时再按指针还原。

### 那个字指向已返回的栈帧

`Error` 是值布局结构体，IR 里按栈指针携带（`IRNode.swift:44`）。`err(Error(m))` 构造的结构体在**被调函数的帧**里，widened 后写进 Result 的是它的地址。

实测（`run-llvm`）：

```pini
坏(m: String,) -> (^I32,):
    return err(Error(m))

main|func() -> (I32,):
    let r = 坏("第一次")
    let q = 坏("第二次")      ; 复用同一帧
    try r else e:
        print(e.message)     ; 打印出「第二次」
```

旧 Result 里的消息被下一次调用覆盖。这不是 FFI 的边界问题：Pini 侧把 Result 存起来、再调用同一个函数，`e.message` 就会读到别人的消息。**现状是悬垂指针，不是取舍。**

### 导出桩只读标签

导出桩取 tag、比对 0、成功时写 ok 出参，失败分支直接丢弃载荷（`IREmitter.swift:3247`）。所以 C 侧拿到的 `1` 后面没有任何数据。

注意 —— 缺的不是一个访问器。即便在 C 侧加 `last_error()`，它能拿回的也只是那个已失效的地址。**先修表示，再谈通道。**

## 先例

| 先例 | 形态 | 错误在哪 |
|---|---|---|
| Zig | `!T` 错误联合 + `@errorName(e)` | 错误是返回值的一部分；名字是静态表的纯投影 |
| Win32 | `HRESULT` + `FormatMessage` | 码即数据；文案是码的纯函数 |
| Rust FFI | `#[repr(C)]` 结果结构体或出参 | 错误值走数据，调用方拥有 |
| Swift | `throws` → `NSError**` 出参 | 错误对象所有权转给调用方，要 release |
| POSIX | `errno` | 环境状态，非数据；本调研判为反例 |

可借两条：Zig 的「码是数据、文案是投影」，Rust 的「结构体返回、零隐藏状态」。Swift 的出参形态多一层所有权转移，只在必须传非字面量消息时才值得。

## 候选

### 码表

```c
int32_t calc_div(int32_t a, int32_t b, int32_t* out);
const char* calc_strerror(int32_t code);   /* 纯函数，静态串 */
```

错误值就是码，文案由库的表投影。零分配、并发安全、ABI 只多一个纯函数。
代价：码要有语义来源。语言层没有错误分类，码只能由编译器按消息字面量编号，或由库作者在导出面声明（新语法）。

### 状态结构

```c
typedef struct { int32_t code; const char* message; } calc_status_t;  /* 0 成功 1 失败 2 取消 */
calc_status_t calc_div(int32_t a, int32_t b, int32_t* out);
```

每次调用都带回码与消息，无隐藏状态、零分配。`message` 指向静态串，生命周期与库相同。
代价：`^T` 导出的返回形态整体变形，现有 C 调用方要改；消息须是字面量。

### 缓冲出参

```c
int32_t calc_div(int32_t a, int32_t b, int32_t* out, char* err, size_t cap);
```

任意消息（含拼接），调用方给缓冲，生命周期归调用方。
代价：每个 `^T` 函数加两个参数；调用方每次都要备缓冲，即便成功。

### 错误句柄

```c
calc_error_t* calc_div(int32_t a, int32_t b, int32_t* out);  /* NULL = 成功 */
const char* calc_error_message(const calc_error_t*);
bool calc_error_is_cancel(const calc_error_t*);
void calc_error_release(calc_error_t*);
```

错误是拥有型数据，可保存、可比较、可跨调用；`isCancel` 一起过边界。
代价：堆分配、ARC 桥接、四个新符号；调用方必须记得 release。

### 旁路槽

```c
int32_t calc_div(int32_t a, int32_t b, int32_t* out);
const char* calc_last_error(void);   /* 线程局部，下一次失败覆盖 */
```

ABI 面积最小。
代价：违反回传与并发两条判据，错误会被下一次调用覆盖。**不采用。**

## 对照

| 候选 | 回传 | 所有权 | 并发 | ABI 面积 | 消息来源 |
|---|---|---|---|---|---|
| 码表 | 是 | 无对象 | 安全 | 一个纯函数 | 静态表 |
| 状态结构 | 是 | 静态串 | 安全 | 改返回形态 | 字面量 |
| 缓冲出参 | 是 | 调用方 | 安全 | 每函数 +2 参 | 任意 |
| 错误句柄 | 是 | 调用方 release | 安全 | 改返回形态 +4 符号 | 任意 |
| 旁路槽 | 否 | 不确定 | 不安全 | 一个纯函数 | 任意 |

## 推荐

**先修表示层，再选边界形态。** 五种候选没有一种能在当前表示上成立：错误字指向已返回的帧，任何通道都只能搬一个失效地址。

表示层的最小改法：错误槽从「指向 Error 结构体的字」换成「消息指针 + 取消位」。即 `{ i64 tag, T, i8* message }`，tag `0` 成功 / `1` 失败 / `2` 取消。形状不变，变的是第三槽的含义，以及构造时直接写消息指针而不是结构体地址。

- `isCancel` 由 tag 承载，不必额外带类型；
- 消息串的生命周期必须写死：字面量指向静态区，拼接消息复制进库级缓冲或明确「不释放」；
- 顺带修掉 Pini 侧那个悬垂：`let r = 坏(); 坏(); try r else e` 不再读到别人的消息。

边界形态建议取**状态结构**：错误随调用回传、零分配、无隐藏状态，是「错误即数据」在 C 上的直译。

```c
typedef struct { int32_t code; const char* message; } calc_status_t;  /* 0 成功 1 失败 2 取消 */
calc_status_t calc_div(int32_t a, int32_t b, int32_t* out);
```

注意 —— 这条路把「消息必须是字面量」变成硬约束：`err(Error("前缀" + 变量))` 无法保证生命周期，导出期要么拒绝，要么降级成通用文案。这是需要点头的取舍。

若要任意消息，再升级到**错误句柄**。缓冲出参与旁路槽都不建议：前者把负担摊到每个调用点，后者违背判据。

## 分步

| 步骤 | 内容 | 验收 |
|---|---|---|
| 表示层 | 错误槽改「消息指针 + 取消位」；`resultConstruct` 直接写消息；`try` 按 tag 绑定；解释器与两个后端同步 | 全量绿；上面那段复现打印「第一次」；`e.message` 两条路径同值 |
| 边界 | 导出桩读 tag 与消息指针；`IRExportFunction` 增状态结构形态；头文件出 `calc_status_t` 与三态常量 | C 调用方拿到两种不同消息，能区分失败与取消 |
| 约束 | 导出期拒绝非字面量错误消息 | 负例：拼接消息被拒，消息点名导出条目 |
| 可选 | `calc_strerror` 静态表；错误句柄形态 | 由真实调用方需求触发，不预做 |

## 待决

**消息限字面量？** 限：状态结构成立，零分配、生命周期清楚，代价是拼接消息用不了。不限：只能走错误句柄，堆分配加 release 契约。

**码要几态？** 建议 `0/1/2`（成功 / 失败 / 取消），与 `isCancel` 对齐。分类码需要在导出面声明，属于新语法，不建议现在做。

**签名变形可接受吗？** `^T` 导出从 `int32_t` 变 `calc_status_t`，现有 C 调用方要改；这是破坏性 ABI 变更，需一次性切换或版本化。
