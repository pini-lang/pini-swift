# 计划：拼写保留与版面还原

- 性质：实现计划。不改语言语义，语义以 pini-reference-v0.md 为准。
- 范围：`pini fmt` 的四条保留——字面量原拼写、每个缩进块的原宽度、单行块形、集合的跨行决定。
- 出处：`docs/plans/打印器与有界展开.md` 的后续。那条计划把打印器钉成「AST → 源码」的唯一实现，
  本件不改这个前提，只把源位置用起来。
- 状态：阶段「旁路」已完成，其余未开工。判据与读数见 §8。

## 0. 已裁四项

| 主题词 | 裁决 | 依据 |
|---|---|---|
| 保留范围 | 只做值与版面两层；语法层等价写法（尾逗号、类型糖、对象块双写、顶格与缩进体）不救 | 每救一项都要往 AST 塞一个纯表现字段，代价与收益不成比例 |
| 缩进粒度 | 每个缩进块各取自身首行的空格数，默认四格 | 词法只校验退格落点，同一深度内必然等宽，故块宽可精确还原；合成块无源行，退四格 |
| 保留载体 | 一份 `PrintHints`，不给 AST 加关联值 | 字面量三个分支在 Sources 与 Tests 里合计一百余处绑定，改签名要全仓跟改 |
| 打印器去留 | 不引入 token 打印路径 | `expand` 产物没有 token；且 token 打印默认保留一切，与本表首行冲突 |

注意 曾议过照 gofmt 上 token 流重写。gofmt 的保真不来自 token：它靠 AST 节点带 `FileSet` 位置、
`BasicLit.Value` 存原文、注释进 `ast.File.Comments`。位置与原文进树，与本件的旁路表是同一件事的
两种实现；换实现只会多出第二份版面文法，而 `expand` 仍要 AST 打印器。

## 1. 现状

| 事实 | 位置 |
|---|---|
| 字面量只存值不存原文：三处进制分支算完即丢 | `Lexer.numberLiteral`（455 行起） |
| 打印器按值重写：`integerLiteral` 直接 `"\(value)"` | `Printer.expr` |
| 缩进一律层级乘四 | `Printer.SourceWriter.line` |
| 词法知道每行宽度却只喂缩进栈，不留表 | `Lexer.countLeadingWhitespace`（201 行） |
| 括号内不计数，跨行在 token 流里不留痕 | `Lexer.tokenize` 的 `suppressesLayout` 分支 |
| 行内块形在解析时并入块，打印时无差别展开 | `Printer.write(statement:)` 的 `ifStatement` 分支 |
| `expand` 走无源模式 | `FmtCommand.runExpandCommand` 调 `Printer.print(module:)` |

**为什么现在做**：`examples/lexical.pini` 在洗牌 8c53b80 里被掏空。该文件自称演示数值进制与
科学计数，六处写法却全被归一：

| 写法 | 洗牌前 | 现在 |
|---|---|---|
| 十六进制 | `var h = 0xFF` | `var h = 255` |
| 二进制 | `var b = 0b1010` | `var b = 10` |
| 八进制 | `var o = 0o17` | `var o = 15` |
| 科学计数 | `1.5e3` / `2e-2` / `3.0E+2` | `1500.0` / `0.02` / `300.0` |

值不变，`golden/` 不变，示例门禁四腿全绿，所以没有任何一条判据会报。示例仍在讲进制，代码里
一处进制也没有了。

## 2. 一份 hints，两条推断

```
PrintHints {
    spellings: [(line, column, text)]   // 字面量原文，含进制前缀与指数写法
    indents:   [line: Int]              // 源码行 → 前导空格数
}
```

另两条不建表，用 AST 上已有的行号推断：

| 保留项 | 推断 |
|---|---|
| 单行块形 | 体首句与块头同源行 |
| 集合跨行 | 任一元素与首元素不同行 |

理由是同一件事：两者都只问「作者有没有在这里断开」这一比特，行号已经在节点上；建表等于把 AST
已有的东西再抄一份，还多一处会与 AST 不一致的副本。

`FrontEnd.Scan` 现在带回 `CommentTable`，按同一条路加 `hints`。`fmt` 传，`expand` 传空。

接口保持三个重载，既有签名不动，测试与调用点免改：

```
Printer.print(module:)
Printer.print(module:comments:)
Printer.print(module:comments:hints:)
```

注意 键取位置不取节点身份。展开器复制的节点沿用原位置，于是副本与原件的拼写、缩进自动一致；
查不到即走默认，合成节点不需要额外分支。

## 3. 拼写

词法在十进制、十六进制、二进制、八进制、浮点五处登记原文，打印器查表命中就用原文。

未命中走值输出，覆盖两类节点：常量折叠的产物、展开器按表行造出的副本。前者没有源行，后者有源行
且表里本来就有对应写法。

字符串不纳入本增量：插值段与转义重排交织，保留原文等于跳过重排，收益低于数字，且会与
`quote` 的转义规则打架。要做得先定「插值段与字面段如何分段还原」，单独立判据。

判据：探针文件写 `0xFF`、`0b1010`、`0o17`、`1.5e3`、`2e-2`、`3.0E+2`，格式化后逐字节不变。

## 4. 缩进

规则：缩进块的输出列 = 父块输出列 + 本块首行源宽度 − 父块首行源宽度；无源行时 +4。

做法：

- 词法每遇一行代码，登记 `indents[loc.line] = countLeadingWhitespace()`。括号内的续行不登记，
  它们不是缩进块。
- `SourceWriter` 的 `depth: Int` 换成 `column: Int`，同时记一份 `sourceColumn: Int`；写嵌套体时
  按上式推子列。顶层两个列都从零起。
- `Line.depth` 改 `Line.column`；`CommentAnchoring` 的 `Slot.depth` 与 `indent(depth)` 一并改成列。
  判「块内还是块尾」仍比源列，落位用输出列。
- 顶格块体不是缩进块：体列等于块头列，体内方法的体再按上式推。

判据：构造 2 空格、3 空格、8 空格三种探针，以及外层 2 内层 6 的混合探针，格式化后逐字节不变。

注意 词法允许非等距缩进（只校验退格落在栈上某个宽度），所以「每文件一个单位」不够。混合宽度的
文件是合法的，必须按块取。

## 5. 单行块形

触发：`if` / `elif` 分支体只有一条语句、该语句是表达式语句，且其源行号等于分支头行号。

输出：`if 条件: 表达式`，行内一条。

限制：

- 行内体只接受表达式语句。解析器的单行体分支只调 `parseExpression`（`Parser.parseControlBlock`），
  声明、`return`、赋值写在同一行解析不回，故这三类即使同源行也退回块形。
- 只认 `if` 与 `elif`。`else`、`while`、`for` 的单行写法不在此列，仍按块形输出。
- 退回块形时该体按「无源行」处理，取四格——这些体的首句与块头同行，差值为零，套公式会印出与
  块头同列的体，解析器读不回块。

判据：单行 `if c: print(1)` 格式化后仍是一行；同样内容的块形写法格式化后仍换行；两者二次打印
逐字节相同。

注意 这条与「不折行」不冲突。折行是打印器在无源行时自己选断点；这里是作者已经选好，打印器照着走。

## 6. 集合跨行

触发：数组、字典、集合、元组四个字面量的元素不全在同一行。

输出形状：每个元素独占一行；元素列 = 父列 + 4（该元素有源行时取其源列）；末元素带逗号；
收尾括号回到字面量首列。

限制：

- 只认这四种字面量。调用实参、参数表、类型实参不在其列——那属调用面与声明面，跨行会与
  「多语句函数字面量作实参」的收尾规则纠缠，另立判据再动。
- 空集合恒单行。
- 元素内部若还有跨行集合，各自独立判。

判据：多行字典格式化后仍是多行、元素顺序不变、二次打印逐字节相同；单行集合不被拆开。

注意 保留的是「断不断」，不是「怎么断」。作者把四个元素挤在两行的写法会被规整成四行各一，
这是选定的规范形，不是还原原文。要连原始断点一起还原，就得逐 token 记列，回到 token 打印那条路。

## 7. 判据

前三条沿用既有的往返判据，第四条把四类保留逐项断言：

| 腿 | 形式 | 说明 |
|---|---|---|
| 幂等 | `P(A(P(A(s)))) = P(A(s))` | 逐字节 |
| 等价 | `A(P(m)) ≡ m` | 位置除外 |
| 注释守恒 | 注释文本序列一致 | 注释不在树里 |
| 保留 | 拼写原文、块首行宽、单行形、跨行决定 | 四类各一组探针 |

注意 保留腿不能写成整文件相等：排版本来就要改行号与空行。它只能逐项断言。上一轮掏空
`lexical.pini` 时，往返与幂等两条全过——保留是独立判据，不是前两条的推论。

## 9. 风险

**唯一规范形退化为「每文件一种字节」。** `--check` 仍可判——判的是「该文件是否等于它自己的
规范形」，不是「是否等于全仓统一形」。代价有两处：两份语义等价但宽度或断行不同的文件不再能
逐字节比；跨分支合并时这些差异会进 diff。这是保留换来的，不是缺陷。

**注释锚回跟着改坐标系。** 现有实现用层号，改列后 `depth(of:)` 的返回语义变了。宽度为四时输出
不变，所以改错不会有测试直接报——只有 2 空格与 8 空格的探针能暴露，且探针必须带块尾注释。

**缩进表按源行号索引，展开后指向原文件。** `expand` 输出里合成行取四格，与原样复制的行混排时
可能不齐。这是无源模式的固有降级，写进文档即可；不要给合成行编造宽度。

**跨行的规范形是选出来的，不是还原的。** 两位作者两种挤法会收敛成同一种。这条要在文档里说清，
否则会被当成「保留了还走样」的缺陷。

**单行体退回块形时差值为零。** 体首句与块头同行意味着缩进差为零，直接套公式会印出与块头同列的体，
解析器读不回块。`else`、`while`、`for` 的单行写法和同行 `return` 全会走到这条，必须显式退回四格；
探针要覆盖「写成一行、但按规则退回块形」这一格。

## 10. 不做

- 不做语法层等价写法的保留：尾逗号、类型糖（`[T]` 与 `Array<T>`）、对象块双写、顶格与缩进体。
- 不保留字符串原拼写与插值分段。
- 不做调用实参、参数表、类型实参的跨行保留。
- 不做按列宽折行，也不做行内对齐。
- 不做 token 打印路径，不做局部区间格式化。
