# 计划：打印器与有界展开

- 性质：实现计划。不改语言语义，语义以 pini-reference-v0.md 为准。
- 范围：`pini fmt` 的打印内核与 `unroll` 的有界展开。两件合成一份计划，因为它们共用同一条
  「AST ↔ 源码」映射：打印器是这条映射的唯一实现，展开器是它的第二个用户。
- 状态：六个阶段（收拢、打印核心、注释锚点、展开器、两个入口、门禁）全部完成，判据见 §6。
  本件只写做法与判据，不写排期。

## 2. 为什么合成一件

### 2.1 交点一：同一条往返判据

打印器定义的是 `AST → 源码`。它的正确性只能用反方向验证：把输出重新解析，看是否得到同一棵树。

展开器产出的是**没有源文本的 AST**。它的正确性也只能用同一条判据验证：展开产物打印出来、
重新解析、与展开后的树相等。

两条判据是同一句话。先写哪个都得写这条，所以描述一次。

### 2.2 交点二：打印器必须支持「无源文本」

如果打印器按「读源码、重排空白」写，它永远打印不了展开产物——那些节点没有对应的源行。

所以打印器从第一天就必须是「从 AST 完整重建源码」，而不是「改写文本」。这个决定是展开器逼出来的，
晚做就得重写。计划把它钉在第一阶段。

### 2.3 交点三：注释在两处的行为不同

注释不在 AST 里（见现状表）。打印器必须靠旁路表把注释锚回去。

- `pini fmt`：AST 来自原文件，注释表齐备，完整还原。
- `pini expand`：AST 来自展开器，**展开出的副本没有源行**，注释表里查不到。
  规则是「合成节点不携带注释」，而不是复制或丢弃整份表的注释。

同一条打印路径要能吃两种输入，这也是合成一件的理由。

## 3. 共同判据：往返

记 `P` 为打印器，`A` 为「解析 + 常量折叠」。

| 性质 | 形式 | 说明 |
|---|---|---|
| 幂等 | `P(A(P(A(s)))) = P(A(s))` | 打印两次与打印一次逐字节相同 |
| 等价 | `A(P(m)) ≡ m` | 重新解析得到的 AST 与打印前逐节点相等，`SourceLocation` 除外 |
| 注释守恒 | 输出的注释序列与输入一致 | 不能用 AST 判，注释不在树里 |

注意 第三条是独立判据。前两条同时成立时，注释仍可能被整段吞掉而无人发现。

注意 等价按「位置除外」判：排版本来就要改行号与列号，把 `SourceLocation` 计入相等则往返判据恒假。
`Module` 的 `Equatable` 含位置，故验收走逐节点比对并跳过位置字段，不走 `==`。

## 4. 打印器

### 4.1 输入形态

```
print(module: Module, comments: CommentTable) -> String
```

`CommentTable` 是 `[(line: Int, column: Int, text: String, ownLine: Bool)]`，由词法旁路产出。
传空表即「无源文本模式」：没有注释要插，与「源文件没有注释」在打印器看来是同一件事。

### 4.2 注释锚点

词法不动 token 流，只在跳过注释时往旁路表追加一条。打印器每写一行就登记生成它的节点位置，
注释按位置先后插进这份行序——不重新解析原文本，也不靠空白猜结构。

| 形态 | 判据 | 落点 |
|---|---|---|
| 块内 | 存在后一处锚点，且注释层不深于它 | 插在它之前，缩进取那行的层 |
| 块尾 | 注释层深于后一处锚点，或其后已无锚点 | 插在前一处锚点之后，按注释层缩进 |
| 行尾 | `ownLine` 为假 | 挂同源行最后一个锚点行末，与代码隔一个空格 |

注释层 = 从前一处锚点向后找第一处「列号不深于注释」的锚点，取它所在的层。这一条把「块首注释挂
子块」与「块尾注释挂本块」并成同一判据：往下走时后一处锚点更深，注释跟着它进块；平走或上走时
注释层不浅于后一处锚点，退回块尾。

注意 三条规则只在 `CommentAnchoring` 一处实现，打印器的各语法分支不参与。十种边界形态写成
`CommentAnchorTests` 的逐字节用例：空块、单语句块、块首、块尾、块尾紧接 `else`、连续退两层、
文件末尾、连续整行、`case` 前、顶层声明之间。语料里块尾注释一处也没有，只跑语料查不出这条规则。

### 4.3 能力边界：不折行、不对齐

版面上只做三件事：缩进、空行、行内空白归一。行内空白一律一个空格，不做列对齐；版面决策不看列宽。

折行的边界比「行敏感」三个字细：布局抑制的判据是「栈顶为普通括号」（`Lexer.swift:105`），此时
行尾不发 newline（`Lexer.swift:80`）、行首不触缩进栈（`Lexer.swift:46`）。括号内换行语义中性，
括号外一行就是一个 NEWLINE 记号，折了即改语义。

三个禁区即使将来放开折行也不能碰：块携带括号（`(func …)` 布局照常）、`<` `>` 不参与括号深度
（泛型实参必须单行）、括号外。

注意 第一版一律不折，含集合字面量。语料最长代码行九十字、无一行超过一百二十字，折行零收益；
而折点选择是幂等性最容易破的地方。放开时单独立判据，先定折点算法再动打印器。

### 4.4 缩进与空行

| 项 | 规则 |
|---|---|
| 缩进单位 | 每级四个空格，严格逐级递增；只作用于缩进块（函数体、控制流子块） |
| 顶格块体 | 与块头同列，不缩进；体内成员的缩进从该列起按级递增 |
| 集合字面量 | 一律单行，元素间一个空格；不因长度拆行 |
| 顶层声明 | 相邻声明之间空一行 |
| 块内空行 | 不保留原空行，只按上述规则产生 |
| 行尾空白 | 一律删除 |

注意 顶格块体不是「零级缩进」，是与块头同列的另一种对齐基准：`(计数器)` 的体从第零列起，
体内方法体再缩进一级。

注意 两处写出规则由解析器的读法逼出来，不是风格：泛型闭合的 `>` 前一位仍是 `>` 时补一个空格
（否则 `>>` 被词法并成右移，泛型在此断掉）；多语句函数字面量作实参时，包围结构的收尾另起一行
回到语句缩进（否则 `)` 黏在最后一条语句尾巴上）。

### 4.5 判据

- `examples/` 全部示例往返成立：`A(P(A(源))) ≡ A(源)`。
- 全部示例二次打印稳定：`P(A(P(A(源))))` 与 `P(A(源))` 逐字节相同。
- 注释守恒：示例源码里注释的文本序列，与打印结果一致；打印结果再打一次仍逐字节相同。
- 打印结果重新跑 `pini run`，`golden/` 输出不变。

读数：语料 93 个源文件（示例全集、语法夹具接受态、bench）加 12 个构造片段，等价、幂等、版面三条全过。
注释腿另计 379 条注释全数守恒，二次打印逐字节相同；九个边界形态见 §4.2。
运行等价由「折叠后 AST 逐节点相等」蕴含，示例门禁四腿无回归；`pini run` 直跑打印结果的那条腿随
`fmt` 入口落到 §6 的门禁阶段。

注意 「注释守恒」与「注释不漂移」是两条：只查文本序列时，整段注释挪进另一个块也照样通过。
位置这条由二次打印逐字节相同 + 边界形态的逐字节期望共同兜住。

## 5. 展开器

### 5.1 语法

```
unroll (码, 名) in [(1, "开始"), (2, "进行"), (3, "结束")]:
    登记(码, 名)
```

- `unroll` 进 `PiniSyntax/Lexer/Token.swift` 的 `Keyword`，规范 §2.6 关键字表同批改为三十五个。
  已核对 `examples/`、`Tests/`、`docs/` 零处使用该标识符，无源兼容风险。
- 无 `step`、无控制流标签：它是代码生成构造，不是循环。
- 表只认**直接写在原地的字面量集合**：数组字面量，元素为标量字面量或元组字面量。
  不认 `let` 绑定的名字——那需要局部常量环境，留到第二版。
- 每轮不是独立的 Block 节点：语言没有裸块语法，多一个 `Block` 就打不出来、也回读不回来。
  各轮语句直接铺进外层语句列表，因此体顶层**不得声明局部变量**（跨轮必然重名），
  声明写进体内的嵌套块则没问题——那层块本来就每轮各一份。

### 5.2 算法

全部在 AST 上，解析之后、类型检查之前。

1. 求值表：只接受数组字面量；元素是整数 / 浮点 / 布尔 / 字符串字面量（负数按「负号 + 数字」认），
   或由它们构成的元组。
2. 校验：元素分量数等于模式长度；元素数在一到二百五十六之间。
3. 逐个绑定：模式名映射到该元素的字面量值；`_` 占位不绑定。
4. 克隆体并替换：只替换表达式位的标识符。
5. 禁区：声明名、`MatchPattern` 的用例名、`x.名字` 的成员名、类型标注、控制流标签，一律不替换；
   模式名作赋值目标直接报错——替换成字面量后没有可赋的东西，留着又会静默落到外层同名变量上。
6. 预检同名：体内任何层级不得声明与模式同名的变量；体顶层不得声明任何局部变量（§5.1 末条）。
7. 递归：先展开外层，再对每份副本递归处理内层 `unroll`；函数字面量与 `try … else` 处理器里的
   `unroll` 一并展开，遍历覆盖全部表达式分支。

注意 第六步挡的是静默错值。Nim 的社区 `unroll` 出过同类事故：每轮复用同一个符号，
`1+1、2+1、3+1` 算成 `2+2+2`，结果正确性丢失而编译通过。

### 5.3 诊断

码落在语义域 E3-014 至 E3-018，不落在 E7。规范 §11.4 的域段表写明 E7 是**警告**域，
本组诊断是致命错误；E7-008 起的号会把这层含义搅乱，且码一经分配不复用。

| 码 | 触发 |
|---|---|
| E3-014 | 表不是字面量集合（含元素不是标量） |
| E3-015 | 某行分量数与模式长度不符 |
| E3-016 | 体内出现模式名（声明／赋值）或体顶层声明局部量 |
| E3-017 | 表为空 |
| E3-018 | 展开份数超过二百五十六 |

注意 展开后多份副本共用同一 `location`，类型检查报错会重复多次。去重落在两个收集入口
（`SemanticAnalyzer.analyzeCollecting` / `TypeChecker.checkCollecting`），键取整条诊断的渲染形：
位置相同而内容不同的仍各留一份。

### 5.4 判据

- 展开产物不含 `unrollStatement` 节点（打印前遍历一次，计数为零）。
- 展开产物可被打印器打印，且 `A(P(展开树)) ≡ 展开树`。
- 解释器与 LLVM 两条通道对同一份 `unroll` 程序输出一致。

读数：`UnrollExpanderTests` 十二条全过——展开、嵌套、函数字面量体内、五条诊断各一、嵌套块不误报、
双通道一致；`examples/unroll.pini` 进示例门禁四腿（check / run / run-llvm / golden）。

## 6. 落地顺序

每阶段的门禁是下一阶段的前提，不跳阶段。

**阶段「收拢」**（已完成）：抽 `FrontEnd`，内含常量折叠与展开占位；六个入口各一处调用。

- 判据：六处调用点各一；`Sources/` 内 `Parser(tokens:` 只余 `FrontEnd` 与解析器内部子解析；
  `foldConstants` 只被 `FrontEnd.passes` 调用；`pini run` 与 `pini parse` 对同一文件的 AST 描述一致。
- 读数：`pini parse` 对 `2 + 3 * 4` 打印 `int: 14`，`pini run` 输出 14，两条通道同一次折叠；
  示例门禁四腿无回归。

**阶段「打印核心」**（已完成）：`Module → String`，覆盖全部语法；注释不参与打印。

- 判据：全部示例往返等价与二次打印稳定两条同时成立；`pini run` 输出与 `golden/` 一致。
- 读数：`PrinterRoundTripTests` 两腿全过——92 个源文件的等价与幂等，12 个构造片段的补充覆盖；
  示例门禁 check 57 · run 53（1 已知失败）· run-llvm 54 · golden 52（2 豁免）· 回归 0。

**阶段「注释锚点」**（已完成）：词法旁路表 + 三条锚回规则。

- 判据：注释守恒成立；二次打印仍稳定（注释不漂移、不重复）。
- 读数：379 条注释全数守恒；92 个源文件加 10 个边界形态二次打印逐字节相同。块尾与文件末尾两类在
  语料里各零处，只能靠构造形态覆盖。

**阶段「展开器」**（已完成）：`UnrollExpander` + 五条诊断。

- 判据：5.4 三条全过；新增示例进 `examples-gate.py` 三腿。
- 读数：530 个测试 / 77 套全过；示例门禁 check 58 · run 54（1 已知失败）· run-llvm 55 · golden 53
  （2 豁免）· 回归 0；六个门禁全通过。

**阶段「两个入口」**（已完成）：`pini fmt` 与 `pini expand` 共用打印器；`expand` 传空注释表。

- `fmt` 只到语法（`FrontEnd.syntaxOnly`）：折叠与展开都改写程序，打印跑过 pass 的树就不再是同一份
  程序的另一种排版。
- `fmt <路径>...` 默认打印到 stdout；`-w` 原地写回，只写有变化的文件并保留权限位；`--check` 只列
  需要格式化的路径，有则退出 1。路径可为文件或目录，目录递归取 `.pini`、跳过隐藏项与 `.build`。
- `expand <file.pini>` 打印跑完 pass 清单的树，注释不进产物；常量折叠同在这条清单里，故字面量运算
  以结果出现。import 块头由文件名派生，输出改名落盘要自行改块头。
- 解析失败一律报错退出，不跳过；「跳过失败」会把真错误静默成通过。
- 判据：`pini expand x.pini` 的输出直接喂给 `pini run`，行为与 `pini run x.pini` 一致。
- 读数：`FmtCommandTests` 八条全过——语法模式不折叠不展开、语料 93 个文件逐字节不动点、CLI 六条
  行为（stdout、`--check`、`-w`、目录递归、expand 跑通、参数冲突）。顶层示例 55 个，格式化前后各跑
  一次：54 个可跑且输出一致，`ffi-v2-llvm.pini` 本就跑不起来，`concurrency.pini` 的差异只是并发
  打印顺序，原文件连跑三次自身也不一致。

**阶段「门禁」**（已完成）：规范形成为提交与集成的硬条件。

- `tools/fmt-gate.py` 扫 `examples/`、`Tests/`、`bench/` 的全部 `.pini`（现 131 个），跑一次
  `pini fmt --check`。产物须存在且不早于源码，否则按环境失败（退出 2），不算通过。
- `tools/fmt-exempt.tsv` 三列「路径 · 类别 · 原因」。`unparseable` 六件解析拒绝夹具，没有规范形；
  `variant` 八件以非规范写法为被测对象的语法标本（七个尾逗号、一个多行字典）。两类都受检：
  前者须仍解析失败，后者须仍可解析且仍不是规范形；任一不成立即判过期，门禁红。
- 计划原写「九件拒绝态夹具不可解析」，实测只有六件：`testSemanticRejects…` 与两件
  `testTypeCheckerRejects…` 解析得动，属语义 / 类型拒绝，照常格式化并受检。
- 洗牌 80 个文件（+308 / −418 行）。改动不止空白：AST 不保留 `[T]` / `?T` / `{K: V}` 的原拼写，
  统一成 `Array<T>` / `Optional<T>` / `Dictionary<K, V>`；尾逗号按打印器规范统一（声明参数补、
  调用实参去）。语义未变：`swift test` 538 条与示例门禁四腿洗牌前后一致，`golden/` 零差异。
  洗牌前修掉三处会写坏语料的缺陷：实参与字典项的 `名= 值` 缺空格、扩展块头丢泛型参数
  （补进 `ExtensionDecl.genericParams`）、注释段落之间的空行被吃掉（注释门禁随即变红）。
- `ci/entrypoint.sh` 在构建之后加一步；`hooks/pre-commit` 在身份与注释之后追加同一条。
- 洗牌提交的哈希登记进 `.git-blame-ignore-revs`。

注意 禁止「解析失败即跳过」。那会把真错误静默成通过，与「跳过不等于通过」是同一条纪律。

## 7. 风险

**注释锚点决定成败。** 三条规则若在块边界上不自洽，幂等性会被打破，而破坏方式通常是
「第二次打印时注释跑到了下一行」，肉眼很难在六十多个示例里发现。九种边界形态已固化成
`CommentAnchorTests` 的逐字节用例（§4.2），语料本身覆盖不到块尾与文件末尾两类。

**行内函数字面量里的注释没有锚点。** 多语句函数字面量与 `try … else` 处理器由独立写出行再拼回
一行，其体内各行不登记锚点，落在那里的注释会退到语句层。语料里没有这种写法；真出现时先确认
退到哪一层是否可接受，再决定要不要给内联块单开一条锚点通道。

注意 注释缩进一律按落点重算，源文件里手工缩进的注释会被拉回所属块的层级。这是格式化器的本职，
不是漂移；判据是二次打印不再变化。

**打印器会暴露 AST 的信息缺失。** 若某处语法在 AST 里不可区分（例如原写法与等价写法折叠成同一棵树），
往返等价仍成立，但风格会被统一。这属可接受，但要记录哪些写法会被改动。

**语法标本不能规范化。** 尾逗号与多行字典不在 AST 里，打印器只能输出规范形；对
`testParserAcceptsTrailingCommaIn*` 这类夹具跑格式化，等于删掉它们唯一被测的写法。故这类文件按
`variant` 豁免，受检条件是「仍可解析且仍不是规范形」，而不是一律跳过。

**展开器的收益面窄。** 它只能替代语句级重复。这是调研得出的结论，不是实现缺陷；
计划不为它扩张语法。

**首次洗牌不可逐行审。** 一百二十余个源文件一次重排，人工逐行看一眼不现实。判据只能靠工具：
洗牌提交只动空白，`golden/` 输出全等，`pini run` 两条通道行为不变。

## 8. 不做

- 不做按列宽折行：语句级折行改语义，集合字面量折行引入阈值。第一版没有任何依赖列宽的决策。
- 不做行内对齐：行内空白一律一个空格。
- 不做 `match` 的 `case` 臂生成：`case` 标签是模式不是语句，且表里放不下函数值。
- 不做声明生成：需要放弃每轮独立作用域，且要回答「新名字从哪来」，本语言无反射。
- 不认命名表：留第二版。
- 不做 `--check` 之外的配置项：格式化器一旦可配，往返判据就不再是唯一。
- 不做编译期校验规范形：格式不是语义，`pini run` 接受任意合法布局。
