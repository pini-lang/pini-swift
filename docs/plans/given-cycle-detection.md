# 给定块物化环检测 · 实施计划

状态：已落地，四条验收判据全过；射程二期扩到间接环，三期含方法体。

## 1. 目标与验收

`pini check` 能报出「给定块物化环」，以警告形式输出、退出码仍为 0。

环的成因：某个给定块的字段初值要求物化它自己。**射程含间接环** —— 字段初值经普通函数或方法绕回来、
甚至穿过几层才取用到自己的，都报。边表由两类边合成：取用边与调用边（§3.1）。射程与呈现见 §4.4 / §3.7。

验收判据四条，缺一不算完成：

| 判据 | 内容 |
|---|---|
| 环可见 | 最小环文件在 `pini check` 下打印警告并给出环路径，退出码 0 |
| 零噪声 | 无环文件不因本特性多出任何诊断行；只有警告的文件按 §3.5 的形态输出（警告 + 检查通过） |
| 无回归 | 示例门禁 55 个文件全绿，无新增警告 |
| 有判据 | 全量测试绿，新增测试不少于 5 条 |

## 2. 现状

### 2.1 环导致崩溃且无提示

最小环语料：给定块的字段初值调用一个函数，该函数的 `using` 形参又指向这个给定块。

```
[甲块|given]
    值: I32 = 读甲()

读甲|func(using 甲: 甲块,) -> (I32,):
    return 甲.值
```

实测读数：`pini check` 通过（退出码 0），`pini run` 被信号 10 杀死（栈溢出），无任何诊断输出。

注意 环检测的价值在于把一次进程信号变成一句可定位的话，不是让这个程序能跑。

### 2.2 依赖图缺给定块这个节点

现有的依赖表只遍历函数，键是函数名。给定块声明在降载时只检查字段初值是否齐全，随后跳过，不生成函数。

它的字段初值确实会降载，但发生在一个临时上下文里（`IRLowerer.swift:1713`，`functionName` 为 `<field-default:名称>`）。取用记录写进这个上下文，函数返回类型声明时集合被丢弃。

因此 `IRModule.swift:132` 那句「引用面 = 函数体里的取用点 + 给定块字段初值里的引用」与实现不符，后者从未进图。补图（§3.1）落的正是这一条。

### 2.3 降载开销不是障碍

`emit`（含降载与发射）减去 `check` 的耗时差，debug 构建三次取中位数：最大 16.3ms，最小 3.5ms；`check` 本身 6–7ms。空降载不含发射，还要更低。

`build` 只是 `check` 的别名，没有「只编译不执行」的命令，故用 `emit` 作上界。

### 2.4 取用点记在调用方

`using` 形参的实参由编译器在**调用点**插入，所以「A 的初值调用 f，f 的 `using` 形参指向 B」这条链，
边直接是 A → B，长在 A 的字段初值降载上下文里 —— 窄射程靠这一条就够，不必补调用边。

注意 它只在「f 自己有 `using` 形参」时成立。f **体内**才取用 B 时，取用点记在 f 身上，A 那侧空无一物
⇒ A → B 不出现，环断开。补法不是在 A 上再记一条，而是把「A → f」这条调用边也放进图（§3.1）。

## 3. 方案

六项，按补图 → 检测 → 告警 → 退出码 → 接入 → 文档的顺序落地。前五项各自独立可验证。

### 3.1 补图

1. `lowerNominal`（`IRLowerer.swift:1696`）加一个 `inout DependencyEdges` 出口，在给定块分支把临时上下文的
   取用集合与调用集合写出去，键用给定块名。
2. 出口只在 `lower(module:)`（`270`）组装边表时并入；`lower(package:)`（`205`）转发到前者，自动获得。
3. 只收给定块的边。结构体与对象块的字段初值取用发生在构造时，不是载入时，进同一张图会误报。
4. 调用边在这些位置记：普通调用、泛型特化、模块限定、成员调用、trait 默认方法。闭包体内的调用并入
   外层函数（同一个 `functionName`）。方法体同时并入两张表 —— 它既接受边也产出边（§3.7）。

补图做完，图是完整的物化依赖图，但不产生任何警告，与窄射程时期等价，可单独验证。

### 3.2 检测

新增纯函数：输入是边表，输出是环路径列表（如 `甲块 → 乙块 → 甲块`）。不依赖编译器状态，可直接喂图做单元测试。落点 `PiniIR/IR/GivenCycle.swift`，入口 `GivenCycleDetector.cycles(in:)`。

边表已是有向边，方向即「物化谁需要谁」，无需额外的方向字段。补了调用边之后函数也有入边，可以入环，
故多两条判据：环里至少有一个给定块（否则是普通递归，那是运行时栈的事），起点旋转到环里最小的给定块
（否则告警按起点取声明位置会落空）。

注意 三色遍历每条回边报一条环，故「有环必报」，但不保证报出同一强连通分量里的所有简单环。告警要的是一条能定位的路径，不是环的清单。

### 3.3 告警

新增警告 `givenCycle`，归警告段 `E7`，码位取 `E7-003`。中文与英文模板各一条，文案带环路径。

`SemanticWarning`（`PiniSemantics/Semantic/SemanticWarning.swift`）是现成的警告通道：严重级别为警告、不阻断、命令行走标准错误输出。

注意 模板里的 suggestion 当前显示不出来：`SemanticWarning.suggestion` 恒为 nil，`ErrorFormatter.formatDiagnostic` 只给 E3 三码查资源模板。E7-001/002 同样如此，本条与它们保持一致；要让建议真的出现，得在格式化入口加一条（与 did-you-mean 同款），属后置。

### 3.4 接入

三个 check 入口各接一步空降载，取两张边表合成一张图后调检测：

| 入口 | 位置 | 形态 |
|---|---|---|
| 单文件收集式 | `main.swift:1116` | 单文件降载 |
| 模块目录 | `main.swift:1488` | 整包降载 |
| 无清单目录 | 逐文件走单文件入口 | 自动获得 |

两处均已持有 `checker`，可直接取 `checker.typeInference`。降载前须设 `persistAcrossScopesForCodegen = true`，与 run / emit 同款。

接入时的两条细节：

- 降载传 `requiresMain: false`。check 不要求程序有入口，用默认值会让「无 main 的库文件」整类拿不到环检测。
- 位置按环起点（旋转后的最小给定块）回 AST 的 `GivenDecl.location` 取 —— 边表里只有名字。给定块名单
  取自声明面而非边表：图上函数名与块名混在一起，值面已分不出谁是谁。取不到位置（预置块不在声明表里）
  就跳过这条。

### 3.5 退出码

`runCheckCommand` 今天把语义警告与错误混在一个数组里，只看空不空就定退出码 ⇒ 一个只有警告的文件
`pini check` 返回 1，而同一文件放进含清单的目录返回 0。环检测的输出是警告，判据一要求退出码 0，
所以这条口径要先在单文件路径上统一。

改法：`checkSingleFileDiagnostics` 的返回值多带一位「是否含阻断性诊断」，三个调用点改判这一位；
输出顺序与文案一字不动，只有退出码与「检查通过」那行会变。

### 3.6 文档

参考文档 §4.11 补一段「环检测」：说明是警告、不阻断，给出环的成因，并写明射程的边界（§4.4）。

### 3.7 可读名

方法在 IR 里叫 `mangle(方法名)__mangle(类型名)`，而告警是给人看的。`IRFunction` 因此多一个
`displayName`：只有方法填它（`类型.方法`），顶层函数留空表示与 `name` 同名。`IRModule.displayNames`
汇总成一张表，CLI 构造警告时把路径逐项翻过去。

注意 环的身份仍用 IR 名 —— 去重与旋转都在身份上做，翻名只发生在呈现那一刻。拆 `__` 还原是行不通的：
标识符允许 `_`，`a__b` 是合法方法名，分隔点无法从串上确定。

## 4. 取舍

### 4.1 空降载抛错：不显示错误，静默跳过

`check` 今天不看降载层错误。把那些错误显示出来会收窄 check 的通过面，昨天还绿的代码今天变红，是破坏性变更。

注意 代价是明确的：一个文件若含有其他降载错误，环检测对它不生效。这条边界要写进代码注释，不假装它不存在。

### 4.2 按输入形态分别处理

单文件走单文件降载，模块目录走整包降载，无清单目录逐文件。跨文件环只可能在同一模块内出现；无清单目录下每个文件本就是独立程序，不存在跨文件环。

### 4.3 警告不阻断

环导致的是必然崩溃，警告之后 `pini run` 仍会崩。这一点不靠文档掩饰，靠文案说清。

### 4.4 射程：不再有结构边界

三期把方法体入了图：方法不再只从 `functions` 之外旁观，它既接受边（成员调用记调用边），也产出边
（方法体的取用与调用并入两张表）。图因此是一张完整的「谁依赖谁」，环可以穿过任意多层的函数与方法。

名字的可读性单独解决（§3.7）：路径身份仍是 mangle 过的 `方法__类型`，呈现时按 `displayName` 翻回
`类型.方法`。两个面各管各的，谁也不将就谁。

| 项 | 内容 | 规模 |
|---|---|---|
| 补图 | 出口 + 并入两张边表 | 约 90 行，5 处传参 |
| 检测 | 纯函数 + 单元测试 | 约 70 行，12 条用例 |
| 告警 | 类型 + 码位 + 中英模板 | 约 60 行，2 条用例 |
| 退出码 | 返回值带阻断位 + 三个调用点 | 约 20 行，2 条判据 |
| 接入 | 三个入口接空降载 | 约 60 行，2 条判据 |
| 文档 | §4.11 补段 | 约 10 行 |
| 收口 | 全量测试 + 示例四腿 + 注释门禁 | 跑一次 |

合计约 350 行代码、10 行文档、9 条判据。性能代价：`check` 每文件增 3–16ms。

补图必须单独跑一次全量测试再进检测 —— 它改的是三个类型共用的降载函数。

二期（间接环）在已落地的基础上加三类边各一条记录点与一次合并，检测器只改判据与旋转，不动遍历骨架。

## 6. 风险

**签名波及**：补图改 `lowerNominal` 的签名，它同时服务结构体、对象块、给定块三处。改错会让前两者的字段默认值降载出问题。示例门禁与全量测试是这条的主要判据。

**可达性误报**：若某条边实际不会在物化时触发（取用点在永不被调用的分支里，或包在从不调用的闭包里），检测会报一个跑不出来的环。倾向照报：静态检测不判可达性，误报的代价是一条可忽略的警告，漏报的代价是崩溃。

**可读名缺失**：`displayName` 目前只有方法这一路填。将来若有别的降载路径产出 mangle 名却不填它，
告警会原样打印 mangle 串 —— 不报错，只是难读。§3.7 的用例钉住了方法这一路。

**退出码放宽**：只有警告的文件从退出码 1 变 0，今日依赖「有警告就红」的用法会变绿。放宽与「警告不阻断」的既有约定一致，属纠偏而非破坏，但调用方需要知情。

## 7. 不做的事

不给 `check` 增加「显示降载层错误」的能力。那是「check 盲区」的整体议题，属单独立项，不由这个特性顺带完成。

不实现环的自动修复或阻断。语言允许写环，工具只负责指出来。
