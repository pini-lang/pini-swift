# 解释通道提速

## 目标与边界

把 `pini test . --interpret` 从「跑不到终点」做到可日常使用，并让**热函数编译** 落地：按函数归集步数，
越过阈值后把该函数单独发射成动态库，调用点改经跳转槽。

完成判据有两条并列：全量套件能在可接受时间内跑到终点并给出报告；热函数编译的调用点真的走动态库，
不是「代码里有个开关」。

边界：不改求值次序与错误传播；不改两侧逐字节对照的判据。热函数编译不追求与 LLVM 全程序发射同形，
只要求同一份源码经热替换后输出不变。

## 缺口与读数

| 项 | 现状 | 取数入口 |
|---|---|---|
| 全量套件 | 五百八十秒未到终点（无报告） | `pini test . --interpret` |
| 单包成本 | 十二例耗二分三十五秒 | `pini test . --interpret --target support` |
| 成本落点 | 在整树装配，不在用例数：用例从十到四百，耗时同量级 | 上两行之比 |
| `E5-005` 越界 | 未定位：要先跑到报错用例，而全量不收敛 | `pini test . --interpret` |
| 热函数编译 | 零代码痕迹：全仓搜 `hotFunc`/`jumpSlot` 无命中 | `packages/` 源码 |
| 逃逸闭包 | 已改报 `E5-011`；要真可用须让环境层按引用存活 | `packages/evaluator/src/api/machine.pini` 的 `envAlive` |

## 批次

### 一、装配分段量算

在解释通道的装配段打点，把 parse、语义检查、降载、求值四段耗时分别读出。装入成本看不见，
后面每一步都无法判断是否有效。

判据：`pini test . --interpret --target support` 打印分段读数，且各段之和不超总耗时。

### 二、按需装配

只装配被选中目标及其依赖闭包，不再整树装配。这是把全量拉进可跑区间的关键一步：`--target` 现在
只影响选择面，装配面照旧。

判据：全量套件跑到终点并给出报告；同一目标的分段装配量低于全树，且报告与整树装配逐字节相同。

### 三、`E5-005` 越界定位与修

全量能跑完后按报错用例定位。台账记它是改造前既有，说明与存储形态改造无关，先复现再判归属。

判据：解释通道全量零 `E5-005`；该用例同时在发射通道通过。

### 四、热函数编译

四段：按函数归集步数、`clang -shared` 出行生动态库、`dlopen` 装载、调用点改经跳转槽。槽表与
运行时段符号扩容须同批改，ABI 文档的符号计数随之一致。

判据：自产 `build` 退出 0 且产物可运行；两代文本逐字节相同；构建后 `git status --porcelain` 无新文件；
热替换后同一程序的输出与未替换时相同（取数：同一夹具两次运行的输出比对）。

## 风险与裁定

| 风险 | 处置 |
|---|---|
| 环境层按引用存活与「块退出缩表」判据相抵 | 逃逸闭包要真可用必须付这份代价；先做按需装配，再评估是否值得放开 |
| 热函数编译要动 `PiniRuntime` 符号面 | 与 **运行时 C 化** 交叉，两件排期须错开或合并评审 |
| 提速改动改变产物 | 每批先比四项产物读数与语料，读数不符即回退 |
| 按需装配引入装配次序差异 | 报告逐字节对照是等价证据，不一致即判红，不做「差异可接受」的裁定 |
