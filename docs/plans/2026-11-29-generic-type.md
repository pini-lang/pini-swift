# 泛型类型面

## 目标与边界

让泛型类型声明（`箱<T>` 这一形）与它在调用点的单态化落地，扩展块以泛型实例为目标时能正确归并；
归并不了的目标报 `E6-006`。

边界：不做运行时类型擦除、不做字典传递——参考件已定为编译期单态化。本件只补「类型」这一面，
泛型函数已交付的部分不动。约束求解若与单态化冲突，先按参考件的「显式类型实参替换」办，不引入推断。

## 缺口与读数

| 项 | 现状 | 取数入口 |
|---|---|---|
| 泛型类型声明 | 缺：解析只覆盖泛型函数（`映射<T, U>`）与泛型自由函数调用 | `packages/syntax/src/api/parser.pini` |
| 实例化 | 缺：`GenericInstance` 只带函数实例，无类型实例 | `packages/semantics/src/api/generic.pini` |
| 扩展目标归并 | `E6-006` 保留差异：依赖泛型类型声明 | `tests/parity/diagnostics.tsv` |
| 规范依据 | `Box<I32>` 与 `Box<String>` 是两个具体类型 | `docs/spec/pini-reference.md` §3.11 |
| 现有回归 | 泛型自由函数与容器泛型成员已交付 | `examples/generic.pini`、`generic-func.pini` |

## 批次

### 一、泛型类型声明

解析 `名<T,>(...)` 形式的类型声明（struct / object / enum 三种宿主），形参进模板的类型表。
声明本身不生成实例，只登记模板。

判据：三种宿主的泛型类型都能声明并 `check` 通过；非泛型声明行为不变。

### 二、类型实例化

`箱<I32>` 与 `箱<String>` 各成一份具体类型：各自的字段表、方法表、IR 类型名。同名不同实参不复用。
实例按「模板 + 实参文本」做键，键相同才复用。

判据：`箱<I32>` 与 `箱<String>` 各自可构造、可读字段；两者类型不互认（互赋报类型不符）。

### 三、扩展目标归并

扩展块写成 `{{箱<I32>}}` 时按实例归并；写成 `{{箱}}` 而模板有未绑定形参时报 `E6-006`，
消息带上目标文本与缺的实参。归并顺序按模板声明序，不按扫描序。

判据：`E6-006` 发出；带全实参的扩展块归并到实例；差异表删该行。

## 风险与裁定

| 风险 | 处置 |
|---|---|
| 实例爆炸（同形参换名字就多一份） | 键取实参文本而非声明位置；同文本复用一份 |
| 泛型类型与泛型函数共用 `GenericInstance` 时字段打架 | 类型实例另立一张表，不复用函数实例的键空间 |
| 扩展块归并到模板而非实例 | 归并判据只认实例表；模板上的扩展块按 `E6-006` 拒 |
| 单态化后 IR 类型名过长 | 类型名按实例键编码，长度不设上限；截断会让两个实例撞名 |
