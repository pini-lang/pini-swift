# `|macro` 求值失败降级设计

Zig 的 translate-c 把翻不出来的宏写成 `pub const X = @compileError("...")`：名字还在，值没有，用到才报。
本设计把同一形态搬到 Pini，且不引入 `@`、不引入任何新语法。

## 结论

| 项 | 裁定 |
|---|---|
| 降级状态的载体 | 符号表与构建计划，源码里没有占位写法 |
| 报错时机 | 用到才报；未使用即零诊断 |
| 分界 | 声明自身写错当场报，环境与头文件导致未求值才降级 |
| 可见性 | `check` 通过时打印一行提示，不静默 |
| 自举 | 求值结果与理由随计划带出，自举侧不启动 C 编译器 |

## 为什么不需要 `@compileError` 的对应物

Zig 需要它，是因为 translate-c 的产物是 Zig 源码：一条宏翻不出来，必须能在源码里写成一个表达式值，才能让使用点报错。Pini 的 `|macro` 条目本来就只有名字与类型，值从不出现在源码里——它由构建期求值产生，存在符号表与构建计划里。于是「没有值」天然就是符号表的一种状态，不需要任何表达式形态。

| Zig | Pini | 差别 |
|---|---|---|
| `pub const X = @compileError("…")` | 同名条目仍在符号表，状态为未求值 | Pini 源码里没有占位写法 |
| 产物是可读源码 | 产物是声明文本加构建计划 | 值的通道在计划里，不在文本里 |
| 错误文本由翻译器写死 | 理由由求值器给出，带展开原文 | 同一份源码换头文件，理由可以不同 |

注意 —— 这不是省掉一个内置，是两种产物的差别。把状态塞进声明文本，会顺带开出「用户可以手写一条求值失败」的后门；而 `|macro` 的全部价值是「值来自头文件」，后门一开这条链路就断了，与「块内写值」被拒是同一个理由。

## 方案对照

方案「状态入表」（本设计）

- 语法零改动，`ForeignSymbol.knownFlags` 不动。
- 失败理由走 `ForeignConstantFailure`，由求值器产出、语义层消费。
- 接口文本不动：外部符号是包级可见，不进接口；未求值状态因此不出包。

方案「生成物占位」

- 需要新写法（如 `名|macro|unresolved: 类型` 或值位内置 `unresolved("…")`）。
- 代价：封闭标志白名单开洞、解析器与生成器同改、用户可伪造求值失败、接口文本要扩。
- 收益仅是「生成的产物里看得见」，而这已由 `pini bind` 的跳过报告与 `check` 的提示行覆盖。

选「状态入表」。

## 状态模型

```swift
/// 宏常量的求值结局：有值进 IR，没值只留理由。
/// 未求值不是错误本身，只有在被读到时才转成诊断。
public enum ForeignConstantFailure: Equatable, Sendable {
    case noHeaders
    case notDefined
    case functionLike
    case unparsable(text: String, detail: String)
    case outOfRange(value: String, type: String)
    case missingPlan
}

/// 一次求值的两路产出：值给降载，失败给语义层。
public struct ForeignMacroEvaluation: Sendable {
    public var values: [IRForeignConstant]
    public var failures: [String: ForeignConstantFailure]
}
```

`ForeignConstantFailure` 进语义层，只依赖语法与位置，不碰 IR；`ForeignMacroEvaluation` 留在宿主层，把两路产出拼在一起。

理由六种，来源与处置各不相同：

| 理由 | 谁判 | 降级 | 诊断里的说法 |
|---|---|---|---|
| `noHeaders` | 求值器前置 | 是 | 包里 `[ffi].headers` 为空；单文件模式没有 `pini.toml` |
| `notDefined` | `cc -E -dM` 宏表 | 是 | 头文件里没有名为 X 的宏 |
| `functionLike` | `cc -E -dM` 宏表 | 是 | 它是函数式宏，Pini 不展开宏，要调用请写 shim |
| `unparsable` | 常量表达式解析 | 是 | 展开后是 `…`，不是常量表达式：… |
| `outOfRange` | 按声明类型收敛 | 是 | 值放不进声明的类型 |
| `missingPlan` | 自举装载器 | 是 | 本机构建计划里没有它的求值结果，跑 `pini build` |

两类失败不降级，仍在声明处或求值入口当场报：

| 失败 | 谁判 | 为什么不当场报不行 |
|---|---|---|
| `\|macro` 的类型不是标量 | 语义层声明期 | 与头文件无关，写法本身不成立；放行等于允许一条永远没有值的声明 |
| C 预处理器不可用或执行失败 | 求值器 | 是构建环境故障，不是某条宏的属性；降级会把整机配置问题变成沉默 |

原则一句：**能静态判定的错误当场报，依赖头文件与环境的结局才降级。** 越界看似声明写窄了，但值来自头文件，换一版头就可能成立，故归降级。

## 判定「用到」

| 位置 | 处置 |
|---|---|
| 读值：赋值右值、实参、运算、返回、条件 | 报 E4-044 |
| 取址 `&宏` | 走既有「没有地址可取」，不叠加 E4-044 |
| 写 `store(&宏, …)`、`宏 = 1` | 走既有只读与取址禁令，不叠加 |
| 类型位、块名、成员名 | 与宏常量无关 |
| `unsafe` 门禁 | 不变：宏是常量，读它不需要 `unsafe` |

实现落在 `TypeChecker.checkExpression` 的标识符前置段：那里已有「外部数据符号需要 unsafe」的门禁，未求值判定放在它之前，命中即报并提前返回。宏本来就不需要 unsafe，两条门禁不会互相遮蔽。

取址要短路：`.addressOf` 今天对操作数递归调用 `checkExpression`，裸标识符不需要这趟递归。跳过之后，`&宏` 只剩既有那条地址错误，不会一表达式两诊断。

级联边界：未求值表达式的类型仍按声明类型给出，下游可能多出一条衍生诊断（如 `宏.字段`）。不做级联抑制——那要把「这个表达式没有值」一路传遍推断层，代价与收益不成比例；诊断按首条根因读即可。

## 诊断

新增三码，接在 E4-043 之后。

```toml
[E4-044]
message = "宏常量 '{name}' 在这里取不到值：{reason}"
suggestion = "值只能来自 C 头文件：补 `[ffi].headers`，或写一个 shim 函数；确定不用就删掉这条声明"

[E4-045]
message = "`|macro` 的类型必须是标量：'{name}' 声明为 '{type}'"
suggestion = "改成 I8 / U8 / I32 / I64 / U64 / F64 / Bool 之一；C 的字符串与结构宏不进常量面"
```

诊断协议只带单点位置，没有次标签；声明位置折进 `{reason}` 文案（`…（声明在 文件:行）`），主标签仍在读点。加一套次标签要改格式化器、LSP 与协议报文，收益不抵这笔改动。每次使用各报一条：一处一改，合并反而让人找不到位置。

三个实例：

```
error[E4-044]: 宏常量 'errno' 在这里取不到值：它是函数式宏，Pini 不展开宏
  --> src/api/errno.pini:12:9
   |
 4 | errno|macro: I32
   | ^^^^^ 声明在这里
12 |     let 码 = errno
   |             ^^^^^ 用到才报
   = 要调用它，在 C 侧写 shim：pini_errno: () -> (*I32)

error[E4-044]: 宏常量 'EOF' 在这里取不到值：包里 [ffi].headers 为空
error[E4-044]: 宏常量 'SDL_UINT64_C' 在这里取不到值：头文件里没有名为 SDL_UINT64_C 的宏
```

`reason` 由语义层按 `ForeignConstantFailure` 渲染，与 E4-028 的 `{reason}` 同一条路。展开原文截断到 160 字符，超出以 `…` 收尾，保证诊断与计划逐字节确定。

提示行：`check` 通过且存在未求值时打印一行，按名字排序，不阻断。

```
注意 3 条宏常量未求值：EOF、SDL_UINT64_C、errno。用到时才报错。
```

注意 —— 这一行是刻意偏离 Zig 的地方。Zig 的降级在 `zig translate-c` 的产物里可见，`@cImport` 本身不说话；Pini 没有生成物可读，若连提示也不打，就退回 Swift 那种静默跳过。提示行不进诊断流，退出码仍为 0。

## 行为变化

| 场景 | 现状 | 本设计 |
|---|---|---|
| 声明了失败宏但没用 | `check` 失败，退出 1 | `check` 通过，一行提示，退出 0 |
| 用了失败宏 | 声明或求值阶段一条 `Error`，不给使用点 | 使用点 E4-044，次标签指回声明 |
| 宏类型非标量 | 求值器抛「须为标量」 | 声明处 E4-045，与头文件无关 |
| C 编译器缺失 | 抛 `compilerFailed` | 不变，仍当场报 |
| 降载期缺值 | 逐声明预检直接抛 | 预检删除，缺值不进 IR；读点留兜底 |

## 流水线

现状：解析 → 语义 → 类型检查 → 求值（一抛即退出）。
新序：解析 → 语义 → 求值（产出值与失败两路）→ 类型检查（带失败表）→ 降载（只收值）。

求值必须前移：使用点诊断要在表达式检查时就能读到失败表。求值只依赖声明与清单，不依赖类型，前移不改任何判据。语义分析有错时直接跳过求值，省一次工具链调用。单文件通道按 `.default` 配置求值，恒得 `noHeaders`，不启动工具链，「单文件不用工具链」的故事不变。

改动面：

| 文件 | 落点 | 改动 |
|---|---|---|
| `PiniHost/FFI/ForeignMacroEvaluator.swift` | `ForeignMacroError` / `evaluate` | 失败枚举迁到语义层；返回值改 `ForeignMacroEvaluation`；只对工具链故障抛错 |
| 同上 | 新增宏表一趟 | 一次 `cc -E -dM` 判对象式与函数式、判名字是否存在；`-dM` 不可用时退回只探针 |
| `PiniSemantics/Type/TypeChecker.swift` | `check(module:)` / `check(package:)` / `checkCollecting(…)` | 新增失败表入参，必填，测试显式传空；漏传即静默放行，故不给默认值 |
| 同上 | 外部块声明期 | `\|macro` 标量校验（E4-045）与声明位置表 |
| 同上 | `checkExpression` 标识符前置 | 未求值判定与 E4-044 |
| 同上 | `.addressOf` 分支 | 裸标识符不递归，避免叠加诊断 |
| `PiniSemantics/Type/TypeError.swift` | 枚举 | 三例：未求值、类型非标量、生成面未翻译 |
| `PiniSemantics/Common/Diagnostic.swift` | 码表与位置 | 三例登记 |
| `PiniHost/Diagnostics/ErrorFormatter.swift` | 兜底文案 | 三例 |
| `PiniHost/LSP/DiagnosticPublisher.swift` | 位置 | 三例 |
| `PiniSemantics/Resources/Diagnostics.zh/en.toml` | 资源 | E4-044 / E4-045（E4-046 第二批） |
| `PiniIR/IR/IRLowerer.swift` | 两处声明期预检 | 缺值改为跳过，不再逐条抛错 |
| 同上 | 标识符读点 | 名字是已声明宏却不在常量表时给明确兜底，替换「未定义变量」 |
| `PiniCLI/main.swift` | 十处求值调用 | 收敛到一个入口，取 `.values` 与 `.failures`；`check` 前移求值并打提示行 |

降载那两处预检是必须动的：它们今天要求「每条 `|macro` 都有值」，与降级直接冲突；留着就等于未使用也照样失败。

## 构建计划

计划是自举侧唯一的值来源。宏段平铺成 `[[macro]]`，按包与名索引，有值与未求值同形。

```toml
# 宏段：state 区分有值与未求值；值与原文只存字符串。
[[macro]]
package = "libc"
name = "EOF"
state = "value"
type = "I32"
value = "-1"

[[macro]]
package = "libc"
name = "getc"
state = "unresolved"
type = "I32"
reason = "functionLike"
```

写成平表而不是嵌进 `[[step]]`：MiniTOML 只认平表与内联数组，嵌表要两代解析器同扩，而平表携带的信息一样（包名、名、状态、理由）。跳过段同理：

```toml
[[skip]]
package = "libc"
step = "stdio"
name = "getc"
reason = "函数式宏要实参才能展开，不能取成常量；要用请写 C shim"
```

跳过段只收宏：静态函数、typedef、枚举的跳过项没有「已知但未翻译」的语义，混进来会让 `E4-046` 指错方向。

三条确定性约束不变：

- 只存求值器自己生成的 `reason` 与 `detail`，不存 C 编译器的 stderr——那里面有临时目录，逐字节相同会被打破。
- 浮点按最短往返十进制写，读取侧按声明类型解析；整数不经浮点中转。
- 失败理由属结果段，不进输入指纹；同一输入两次构建的计划仍逐字节相同。

写入时机：`pini build` 翻译完成后按包重解析源码，求值全部 `|macro`，再写宏段；`check` / `run` 只读计划，不写。自举 `build` 不启动 C 编译器，把旧计划里的宏段与跳过段原文搬回新计划，因此自产构建不会把宿主算好的值抹掉。

旧计划兼容：计划没有宏段时，自举侧把每条声明当作 `missingPlan`，不猜值。宿主侧不读计划，行为不受影响。

自举侧不启动 C 编译器，`missingPlan` 是它唯一的「没有值」来源，与宿主侧的 `noHeaders` 分开报，读者能分清「配置没给」与「计划没带」。

## 生成面

第一批不动：`pini bind` 仍只生成本头文件里能展成数值的对象式宏，函数式宏进跳过报告，理由改成 shim 配方。

第二批把跳过表带进计划，补 E4-046：

- 计划每条宏跳过项记 `package / step / name / reason`，落成平表 `[[skip]]`。
- 装载器把跳过名挂在包上（`Package.unavailableNames`），只在名字解析失败时使用，不产生符号、不参与类型。
- 未定义名的报告先查这张表，命中即 E4-046，附 shim 配方；未命中仍是 E3-001（值位）与 E3-002（调用位）。

```toml
[E4-046]
message = "'{name}' 是 C 头文件里的宏，`pini bind` 没有翻译它：{reason}"
suggestion = "函数式宏要写成 C shim 再声明为外部函数；Pini 侧不展开宏"
```

发码点在名字解析（`SemanticError.untranslatedForeignMacro`），码仍取 E4：它与 E4-044 / E4-045 同属 C 面，读者按 FFI 一族读。码域按「读者读到哪一族」划，不按「哪个类抛的」划。

注意 —— 只有宏跳过项进这张表。静态函数、typedef、枚举即使被跳过也不登记：它们不是「本该有值却没有」，登记了会让未定义名报错指向错误的修法。

不把函数式宏编个类型塞进生成物：类型是编的，读者会当成真的，而它连返回值都没有。

## 判据

| 用例 | 期望 |
|---|---|
| 声明失败宏、未使用 | `check` 退出 0，一行提示；`run` 正常 |
| 使用失败宏 | E4-044 一条，主标签在使用点，理由含声明位置与展开原文 |
| 同一声明两处使用 | 两条 E4-044，各指一处 |
| `&宏` | 只有「没有地址可取」一条 |
| `store(&宏, …)` | 只有写侧禁令或地址禁令一条 |
| `\|macro` 类型为 `*U8` | E4-045，在声明处，与头文件无关 |
| `[ffi].headers` 为空且使用 | E4-044，reason 指向缺头文件 |
| 头文件里没有该名字 | E4-044，reason 为「头文件里没有」，不是解析错 |
| 函数式宏 | E4-044，reason 为函数式，附 shim 配方 |
| C 编译器不可用 | 当场报，退出 1，不进失败表 |
| 自举通道缺计划条目 | 自举 `check` 报 E4-044，reason 为缺计划；`lower` / `emit` 另报能力缺口 |
| 生成面函数式宏 | 使用处 E4-046，未使用零诊断 |
| 计划缺宏段 | 自举按 `missingPlan` 报，不猜值 |
| 自举 `build` | 旧计划的宏段与跳过段逐字节保留 |
| 两次 `check` | 诊断序列与提示行逐字节相同 |
| 既有语料 | 未使用失败宏者零新增诊断；原期望为失败者按新表改写 |

门禁：宿主全量、工作区解释器通道、逐包原生门禁与自洽链四项照旧；语料基线只允许「由失败改为通过加提示」这一种变化，逐条登记。

## 落地顺序

第一批，宿主闭环：

1. 失败枚举进语义层，求值结果类型留宿主层，求值器改用 `-dM` 判形。
2. 类型检查各入口收失败表；声明期标量校验；读点诊断；取址短路。
3. 诊断三处登记与资源文案。
4. 降载两处预检改为跳过。
5. CLI 求值前移、提示行、十处调用收敛。
6. 语料与期望输出改写，门禁复跑。

第二批，自举与生成面：

1. 计划宏段与跳过段；自举装载器读宏段，`missingPlan` 单独文案。
2. 自举检查面补 E4-044 / E4-045（非标量声明）与 E4-046（生成面跳过名）。
3. 自举工作区零诊断与自洽链复跑。

两批各自可独立验收；第一批不依赖计划形状，第二批不改宿主判据。

第一批已落地：宿主 11 项单测、工作区 756 项、semantics 原生 378 项全绿；`check bootstrap` 零诊断。

第二批已落地：计划宏段与跳过段、`pini build` 写入、自举读取与降载、自举检查面 E4-044 / E4-045 / E4-046。自举 `build` 搬运结果段；缺计划与缺头文件分开报。E4-044 / E4-045 / E4-046 三码在两侧都已发码，诊断普查不再留缺。规范两处已按新行为订正：`docs/spec/c-interop-design.md` 的「求值路径」与 `errno` 段、`docs/spec/pini-reference.md` 的 `[ffi]` 段。

## 已定

1. 未使用且未求值的条目不加声明级警告：提示行已点名，再加警告会让头文件多的模块长期带噪。
2. 展开原文截断 160 字符，超出以 `…` 收尾。
3. en 诊断里的 `{reason}` 仍是中文：与 E4-028 同一笔既有债，不在本设计内解决。
4. 计划的结果段用平表 `[[macro]]` / `[[skip]]`，不嵌进 `[[step]]`：MiniTOML 只认平表，嵌表要两代解析器同扩而信息量相同。
