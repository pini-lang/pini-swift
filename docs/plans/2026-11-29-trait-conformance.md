# 特征一致性

## 目标与边界

补齐特征声明的两条判据：声明实现某个特征却没提供全部抽象方法报 `E4-007`；提供了但签名不符报 `E4-008`。
两条都在语义层判，按声明处的位置报。

边界：特征只作约束、不作类型，本件不改这条定位；不做特征方法的动态派发。`错误` 特征的实现判定已存在
（导出面用来校验 `Result` 的错误位），本件把它扩成通用规则，不另立第二套。

## 缺口与读数

| 项 | 现状 | 取数入口 |
|---|---|---|
| `E4-007` | 保留差异：特征一致性检查未进自举语义层 | `tests/parity/diagnostics.tsv` |
| `E4-008` | 保留差异：方法签名比对随一致性检查一起做 | 同上 |
| 现有能力 | 只认 `错误` 特征的实现行（`implementsOf` + 文本匹配），不比对方法集 | `packages/semantics/src/api/export_surface.pini` |
| 特征声明 | 解析与登记已有：特征作为具名类型进符号表 | `packages/semantics/src/api/register.pini` |

## 批次

### 一、抽象方法集采集

从特征声明收集抽象方法：名字、形参数、形参类型、返回位。特征里的具名默认方法不进集合，只作继承。

判据：对 `docs/spec/pini-reference.md` 特征章的两个示例，采集结果与手写期望一致（用 `dump` 或接口面取）。

### 二、`E4-007` 缺方法

类型声明 `实现: 某特征` 后，逐个比对抽象方法；缺一个报一条，位置指向类型声明头。多个特征分别判，
同一方法被两个特征要求时只报缺它的那个。

判据：`E4-007` 发出；补上方法后不报；差异表删该行。

### 三、`E4-008` 签名不符

方法名对上但形参数、类型或返回位不一致时报 `E4-008`，并把差异写进消息（缺哪个形参、哪个类型不符）。
不按「能调用就算实现」放行——特征只作约束，约束要对齐到签名。

判据：`E4-008` 发出；签名改正后不报；差异表删该行。

## 风险与裁定

| 风险 | 处置 |
|---|---|
| 判据过严拒掉合法实现（如形参名不同） | 形参名不进签名；只比个数、类型、返回位 |
| 与 `错误` 特征的既有判定重复报 | `错误` 特征走同一套规则后删掉文本匹配那条，不保留两条路径 |
| 跨模块实现时方法集取不到 | 按包边界先取导出接口，接口缺失按边界错误报，不静默跳过 |
| 特征默认方法被误判为缺失 | 默认方法属特征自身，只要求实现方提供抽象方法 |
