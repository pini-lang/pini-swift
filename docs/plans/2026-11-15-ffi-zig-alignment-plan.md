# Pini FFI：头文件翻译、build.pini 接线与零散面

## 目标与边界

按 Zig 0.17 的三分法重排 Pini 的 FFI 供给：头文件是事实来源，构建脚本把声明翻译成模块，头文件给不了的零散要求由手写载体承接。

| 层 | Zig 0.17 | Pini 对应 |
|---|---|---|
| 事实来源 | 头文件由 translate-c 处理 | 头文件由翻译器处理，clang 为准 |
| 装配 | `build.zig` 调 translate-c 包，产出模块（构建步的 `addTranslateC` 在 0.17 已弃用） | `build.pini` 声明翻译步，产出 Pini 模块 |
| 零散补充 | 源文件里的 `extern` 声明 | foreign 块、given 块方法、内建 |

边界：

- 本期不定义完整构建脚本。`build.pini` 只落 FFI 翻译步所需的最小面；目标图、依赖、并行、缓存仍归 `pini.toml` 与 `pini build`。但执行形态从第一期就按两段式设计，因为后补会把「加翻译步」从动作改成登记，调用方全要改。
- 生成物不进源码树。翻译结果是构建产物，落构建目录；要求源码树里出现生成文件的方案不在候选之列。
- 不把 C 结构体按值搬进来。翻译器只产出 Pini 的 ABI 面能承接的部分，其余跳过并出报告，由零散面手写承接。
- 导出面（`[文件名|export]` 的 `|c` 条目）不动。
- 不做 C++ / Rust 互操作，不做别名机制。

## 参照基线

Zig 0.17（2026-10，写作时的最新版）的三条：头文件由工具处理；`build.zig` 把翻译结果装配成模块，源码侧 `@import("c")`；头文件给不了的零散声明写在源文件里。

注意 版本敏感：`@cImport` 在 0.16 弃用、0.17 移除，翻译改由独立包在构建期完成。0.16 及更早的资料会把「语言内建读头文件」当成标准做法，与本计划的前提相反。

Zig 的「零散补充」那条正是 Pini 的零散面：手写 `extern` 声明。Pini 多两个载体（given 块方法、内建），因为 Pini 的 ABI 面比 Zig 窄——没有 `extern struct`，不透明句柄只能靠封装层补类型。

## 现况与缺口

| 事实 | 现状 | 对三分法的影响 |
|---|---|---|
| 头文件只服务宏常量 | `[ffi].headers` 加 `cc -E -P` 探针，读回数值宏 | 缺「声明翻译」这半条，函数与数据符号读不进来 |
| 没有构建脚本 | 构建是 `pini build` 按 `pini.toml` 的 target 走整图 | 翻译步没有落点 |
| 符号是文件私有 | 一个文件声明 `atoi`，另一个文件调用报 `E3-002` | 生成模块必然在独立文件里，今天放进去就不可用 |
| 块名是库键 | 解释器按块名 `dlopen`，`libc` 是保留名 | 生成块只能按头文件命名，`lib<stdio.h>` 无从加载 |
| 成员是类型形 | 函数类型不带参数名 | 生成物不需要参数名；手写面需要，但不是阻塞项 |
| 同名异型不裁决 | 后注册者覆盖前者，错误落在调用点 | 生成模块与手写块会大面积同名，必须先立裁决 |

注意 「符号是文件私有」与「块名是库键」不是「顺便修一下」：不先修，头文件面根本接不上。这也是上一版计划把作用域排在语法前面的同一个理由，只是这次它从「缺陷修复」升级成「前置条件」。

## 终态形状

```
include/stdio.h ──clang──► 声明清单（内部文本，非语言面）
                              │
                   build.pini 声明翻译步
                              │
     .build/<profile>/packages/<包>/generated/stdio.pini   [stdio|foreign]
                              │
                    模块图（与其他 .pini 同规）
```

三个来源的分工：

| 需求 | 载体 | 例子 |
|---|---|---|
| 头文件里读得到，且类型在白名单内 | 生成模块 | `malloc`、`free`、`strlen`、`EOF` |
| 头文件里读得到，但类型超出 Pini 的 ABI 面 | 手写 foreign 块 + 包装函数 | `stat`（按值结构体）、返回函数指针的工厂 |
| 头文件里读不到，或平台名不同 | 手写 foreign 块（可分平台文件） | `__stdoutp`、shim、变参包装 |
| 不透明句柄要带类型与状态 | given 块方法 | `[文件\|given]` 持 `_句柄: *U8`，方法包 `fopen` / `fread` |
| 边界转换 | 内建 | `fromCString`、`toCString`、字符串句柄 |

外框不是新语法：`[stdio|foreign]` 就是今天的块，`[文件|given]` 就是今天的给定块。

## 翻译面

**输入**：头文件路径、包含路径、宏定义。与 Zig 的 translate-c 入口同参。

**两段拆分**：C 语义段由 clang 出结论（类型宽度、变参、typedef 解析、目标平台），映射段把结论写成 Pini 声明。本期两段都在宿主的翻译器里。中期若用 Pini 重写翻译器，改的是执行器侧的步实现，`build.pini` 仍只声明步——配置期不做实际工作这条不能破。

**映射规则**：

| C | Pini | 说明 |
|---|---|---|
| 整数与浮点 | 按 clang 给出的实际宽度 | 不按类型名猜：`long` 在 LP64 是 8 字节，在 LLP64 是 4 字节 |
| `const char*` 形参 | `String` | 借出，只在本次调用期有效 |
| `char*` 形参 | `*U8` | 可写缓冲，不能借出成 `String` |
| `char*` 返回 | `*U8` | 要 Pini 串就配 `fromCString` |
| 数组形参 | `*T` | 退化为指针，C 的形参本就如此 |
| `_Bool` | `Bool` | 回调签名里含 `Bool` 仍由既有判据拒 |
| 变参 | `\|varargs` | 固定前缀照写 |
| 函数指针形参 | 回调类型 `(A, B,) -> (C,)` | 实参写顶层自由函数名；回调里 `const char*` 也是 `*U8` |
| 记录指针 | `*U8` | 块头注明「指针一律 `*U8`」，原拼写由来源头文件负责 |
| 数值宏 | `\|macro` | 值不由翻译器内联，仍走 `cc -E` 求值 |
| 枚举常量 | 本期跳过 | 枚举不是宏，`cc -E` 展不开；要生成得先有模块级常量声明 |

**跳过**：按值结构体与联合、返回函数指针、裸 `char` 标量、位域、函数式宏、枚举常量。跳过项进报告，报告是构建产物的一部分，不是控制台噪声。

**确定性**：按 AST 的声明次序（即包含树的出现次序）排，不按 clang 的遍历顺序；同名重复声明保留第一处并记一条跳过。同一输入两次生成逐字节相同。确定性不是为了让 diff 好看，是让缓存键稳定、让两次构建可比较。

**生成文件的头**：只写事实——来源头文件、clang 版本、翻译步参数、跳过条数与「不许手改」。

**落地形态**：`pini bind <header> [-I <dir>]... [-D <name>]... [--block <name>] [-o <path>]`。三条实现口径：

- AST 取 clang 的 JSON，并**关掉内建预声明**（`-fno-builtin`）。开着它们，头文件里的 `strlen` 会被并进 clang 的预声明，类型变成 `__size_t` 这种只有 clang 认识的拼写。
- 宽度取 clang 的 `__SIZEOF_*` 预定义宏，不从类型名推。`typedef` 名靠 AST 里的 typedef 表展开（`__size_t` → `unsigned long`），递归有深度上限，只防环。
- 范围与 Zig 同口径：一个头文件的翻译结果 = 它整棵包含树的声明面。只认被声明的那一个头文件，`stdio.h` 这种只做转发的头会翻出空块。

注意 回调形参不映射成 `String`：C 传的是裸字节，Pini 串是带头的堆对象，既有判据本来就不让 `String` 进回调签名。翻译器在这里按「非形参位」映射，`const char*` 得到 `*U8`。

## 构建面

`build.pini` 不是「一边执行一边构建」的脚本，而是「产出一份计划」的配置器。这不是风格选择，是 Zig 用 0.17 一整轮重构换来的结论。

形状（已落地）：

```
; build.pini —— 每个给定块是一条翻译步，块名即步骤名
[stdio|given]
    头文件: String = "include/stdio.h"
    包含路径: [String,] = ["include",]
    定义: [String,] = ["_GNU_SOURCE",]
```

`build.pini` 是**声明文件，不是可执行脚本**：构建系统解析它、读块与字段初值，从不执行它。契约与执行式配置相同——**配置期只登记，不执行**，也不写输出路径；翻译发生在执行期，配置期的产出是一张可打印、可比较的计划。

为什么不做成可执行脚本：语言今天没有「计划对象 + 方法调用」的构造面，执行式配置要先补一个配置期内置函数与语义层入口，而它换来的纯净性，声明式本来就有。代价是字段名固定为 头文件 / 包含路径 / 定义，多一个字段就要改读取器。等语言有了对象与方法调用，可以再评估是否换成脚本；计划这份数据接口不必跟着变。

六条考量，逐条落成决定：

| 考量 | Zig 0.17 的做法 | Pini 的决定 |
|---|---|---|
| 构建脚本是可执行程序 | 配置器跑 `build.zig` 产图，执行器跑图 | `build.pini` 只产计划，执行器跑计划 |
| 配置可缓存 | 图序列化成二进制配置，输入不变即跳过配置 | 计划是纯数据；第一期先能打印与比较，缓存留接口 |
| 配置必须纯 | 探测 PATH、读未声明文件即「缓存投毒」，配置作废 | 配置期不查 clang、不读环境；工具查找放到执行期 |
| 参数透传 | `addPassthruArgs`：脚本看不见 run 参数，换改参数不重配 | 同规：脚本看不出的输入，不计入配置签名 |
| 构建图是工具接口 | 序列化配置加 `--listen=-` 的构建服务器协议；ZLS 在 0.17 不可用，两边仍在补协议 | `pini build --print-plan` 打文本计划；协议留到有工具消费方时 |
| 输出路径不硬编码 | 生成物在缓存里，路径按步骤哈希分配，安装前缀由用户定 | 生成物落构建目录，路径由构建系统按包与目标生成；源码树不出现生成物 |

注意 生成物不入库，源码树里就看不出这次翻译产出了哪些符号。审查单位因此从「生成文件」换成「翻译步声明」：翻了哪个头文件、带哪些包含路径与宏定义、跳过了什么。跳过报告要在构建日志里读全，需要时用 `pini bind --print` 把生成文本打出来。

落地细节：

- 生成物落点：`<工作区或包根>/.build/<profile>/packages/<包名>/generated/<步骤名>.pini`，与 `target.irPath` 同级。步骤名即文件名，故步骤名必须是合法路径分量且唯一。`.build/` 已在忽略表里，构建不写源码树。
- 计划落点：`<工作区或包根>/.build/<profile>/plan.toml`，记包根、`build.pini` 哈希、每条翻译步的头文件与产物路径、输入指纹。`build.pini` 只在 `pini build` 里读；其余命令读计划。
- 装载面：`check` / `run` / `test` / 调试与工作区构建都经 `GeneratedModules.attach` 取生成模块。计划缺失、脚本哈希不符、产物缺失各报一条「先跑 `pini build`」的定向诊断，不静默跳过。`.build` 路径只在这一处拼，各命令不得自行拼目录。
- 缓存键：`clang -E -dD -P` 的输出（含整棵包含树与全部宏定义）、目标宽度、翻译器版本。只取声明文本漏宏改动，只取头文件字节漏被包含文件。
- 生成物归属：并入声明它的包，不另造模块身份（见下节）。
- 头文件集合归一：翻译步声明的头文件与宏定义并入宏求值的输入，`[ffi].headers` 仍可另写；两边取并集，而 `[ffi].defines` 是为这条归一补的字段。
- 库绑定：生成模块不写库名，链接与加载都读 `[ffi].libs`。
- 落地形态：宿主侧新增翻译器，先以 `pini bind` 子命令暴露；`build.pini` 的翻译步调到同一个入口，手工重生成与构建期重生成走同一条代码路径。
- `pini build` 内部分两段：先配置（跑 `build.pini` 产计划），再执行（翻译、发射、链接）。计划可打印、可比较，后续再谈缓存。

注意 计划是数据，不是代码：`check` 等命令读它，绝不执行 `build.pini`。这样脚本写坏只影响 `pini build`，不会让整个仓库的检查一起红。

注意 `check` 不跑翻译器，但要 clang 的场合没变——声明了 `|macro` 的包仍走 `cc -E`。一个读计划，一个求宏值，别混。

注意 生成物路径由构建系统生成、记在计划里，装载器因此会读到包目录之外的路径。白名单只有一条：路径以 `.build` 组件开头且已登记在计划里；其余一律拒绝。

### 生成物归属

Zig 的生成物没有「归某个包所有」这一层，归属拆成三样：

| 层 | Zig 的做法 |
|---|---|
| 物理 | 文件落 `.zig-cache/o/<步骤哈希>/`，路径只含哈希；包目录里从不出现生成物 |
| 逻辑 | 模块在装配处注册：`b.addModule("box2d", .{ .root_source_file = translator.output_file })`；源码侧 `@import("box2d")` 不含路径 |
| 生产者 | 0.17 起翻译器本身是普通依赖包（`b.dependency("translate_c")`），谁声明翻译步谁产；早期写法里也可由生产包建模块、依赖方 `bar_dep.module("c_api")` 取用 |

于是「归谁」是一条规则：**产物归声明翻译步的那个包，消费方按装配期给的名字引用**。名字与目录无关，同一份生成物既能被本包多处 import，也能经依赖图交给别的包。

Pini 缺的是第二层。`import 别名 = 包路径` 写的是路径，模块根必须有 `pini.toml`；采用依赖通道的清单上，`pini build` 还查 require 与 import 的集合一致。生成物要做成独立模块，得同时开三个口子：给 `.build` 里的目录补清单、让 import 能表达构建期才存在的模块、给该模块在 MVS 里开例外。

结论：并入声明它的包。这不是省事——Pini 的包内符号在前置面之后本就跨文件可见，生成文件进门即用，不需要 import 这一跳。

注意 跨包共用同一头文件，Zig 的解法是上游包导出模块，不是两个包各翻一份。Pini 要走到那一步，前提是 import 能按名绑定；本期不做，代价是两个包各翻一份计划条目，正确性不受影响，多花的是翻译时间。去重的前提是落点与包名解耦，那属于构建缓存落地之后的事。

生成物不入库，CI 改用三道判据：

- 同一输入连续两次 `pini build`，生成物与计划逐字节相同。
- 构建后 `git status --porcelain` 不出现新文件，证明生成物没落到源码树。
- 删掉生成目录后 `pini check` 必须报「先跑 build」而不是静默通过；紧接着 `pini build` 能重建。

## 零散面

三个载体的边界要写死，否则同一件事会同时出现在三处。

- **foreign 块**：头文件给不了的符号。规则不变——名即符号、块内自动不安全、调用点要 `unsafe`。新增一条：**生成模块与手写块同名同型时合并，异型时报错**，不允许后写者覆盖。
- **given 块方法**：不透明句柄的封装。字段存 `*U8`，方法包外部调用。选给定块而不是对象块，因为导出面只认给定块——`|c` 的右端只收自由函数与给定块，给定块发布成 C 结构体视图；它同时是 `using` 默认实例的载体。限制照旧：字段须有初值，物化按需。
- **内建**：`fromCString` 取回、`toCString` 借出、字符串句柄。本期不新增内建；若翻译面发现某类转换出现三次以上，再议提升为内建。

块名只作标签：重名不构成冲突，符号才是裁决单位。这是库绑定归一之后的直接结果——块名不再承担库名职责，就没有理由再要求它唯一。

## 前置面

两件事必须在翻译面之前落地，它们是生成模块能用的前提。

- **作用域归位**：外部符号登记进模块符号表，跨文件可见；一个文件声明、另一个文件使用是主用例。六条冲突各有一条负例：同名同型合并、同名异型报错、与本地函数同名报错、与类型同名报错、与导出名同名报错、非 C 标识符报错。
- **库绑定归一**：块名不再是解释器的加载键，改由 `[ffi].libs` 预加载加进程映像查找；`libc` 保留名消失。

成员形状不进前置面：生成物是机器写的，参数名对它无意义；手写面若需要，可在作用域批里顺带做（函数条目改签名形），不做就继续用行尾注释。

## 实施批次

### 前置面

作用域与库绑定一次改完，理由见上。

验收：跨文件用例；六条冲突负例；单文件示例两通道同结果（`run-llvm` 只收单文件，模块目录走解释器）；`[ffi].libs` 为空时 libc 符号仍可解析；缺库与缺符号各一条负例；`tools/diagnostics-parity-check.py` 与自举码表生成门禁绿。

### 翻译面

clang 取声明、映射成 Pini、跳过报告、确定性。

验收：一个只含标量、指针、变参与数值宏的夹具头文件，生成文本逐字节钉死；含结构体与函数式宏的夹具，跳过报告逐条对得上；同一输入两次生成逐字节相同；`swift test` 与 IR 契约门禁绿。

### 构建面

配置与执行两段、`build.pini` 的最小面、计划可打印、生成物落构建目录、装载面登记、缓存键、头文件集合归一。

已落地：`BuildScript` / `BuildPlan` / `BuildLayout` / `BuildRunner` / `GeneratedModules`，取证在 `BuildSurfaceTests`（十条：步骤读取、缺省、三类坏脚本、计划纯数据、成员布局、`--print-plan` 不落盘、build→check→run 全链、缺产物、过期脚本、复用与重翻）。

四处口径单独记明：

- **`build.pini` 是声明文件，不是可执行脚本**。每个 `[名称|given]` 块读成一条翻译步：块名即步骤名，字段初值即参数。语言今天没有「计划对象 + 方法调用」的构造面，执行式配置要先补一个配置期内置函数与语义层入口；而契约（配置纯净、计划是数据、只有 build 跑脚本）用声明式已经满足，代价只是字段名固定为 头文件 / 包含路径 / 定义。
- **计划只在有翻译步时落盘**。没有构建面的包不该多出一个空文件；反过来，`build.pini` 被删掉而旧计划还在时，重跑 build 会写一份空计划把过期状态清掉。
- **输入指纹取 `clang -E -dD -P` 的输出**。只取声明文本不够：`#define LIMIT 512` 不写进预处理输出，改宏值或删宏都不会让指纹变化。`-dD` 把宏定义一并展开，改动才进键。
- **`check` 只验两件事：脚本哈希与产物存在**。它不碰 clang，因此头文件变了 `check` 不会察觉——这由 `pini build` 的指纹负责；`check` 要拦的是「压根没构建」与「脚本改过没重建」这两种会让生成模块与源码对不上的情况。

## 已否决：解散

上一版建议取消块、改成逐条顶层声明，理由是「符号要进模块符号表，最稳的办法是让它本来就是普通声明」。三分法下这条理由不再成立：块不是与生成模块竞争的形态，它就是生成物的容器——一个头文件一个块，正好是一张可审查的清单。逐条声明会让生成物变成几十行散落的顶层声明，清单消失，库分组也消失。

记录保留，因为后续若有人重提「取消块」，要先回答：生成物用什么形状承载。

## 不采纳与缓办

| 项 | 为什么不 | 什么信号再启动 |
|---|---|---|
| 取消 foreign 块 | 见「已否决：解散」 | 不启动 |
| 生成物做成独立模块 | Zig 靠装配期绑名支撑；Pini 的 import 写路径，独立模块要开三个口子 | import 能按名绑定，且两个包共用同一头文件的翻译开销可测 |
| 别名机制 | 名即符号是「不遮蔽」的前提；平台名差由手写块吸收 | 同一符号要在两个平台写两个名字，且 shim 不可行 |
| 按值结构体 | 要 ABI 分类（寄存器 / 栈 / HFA），两条通道都得跟上；翻译面只做白名单 | 出现必须按值传结构体的库且无法用指针绕开 |
| 语言内建读头文件 | Zig 0.17 已把这条路走完并退回构建期；语言面只放声明 | 不启动 |
| 函数式宏 | 要展开与求值，等价于在 Pini 里写一遍 C 预处理器 | 出现只有宏能给、且无替代符号的 API |
| 成员参数名 | 生成物不需要；手写面可用行尾注释 | 手写块条目多到读不动 |

## 风险与控制

| 风险 | 控制 |
|---|---|
| 翻译器按类型名猜宽度，换平台即错 | 宽度只取 clang 的目标信息；夹具里放 `long` 与 `size_t` 各一条 |
| 生成物不在评审视野，翻错了也看不见 | 跳过报告进构建日志；`pini bind --print` 可打全文；夹具把头文件的生成文本逐字节钉死 |
| 跳过策略太松，生成物里混进半可用的声明 | 白名单外一律跳过并列原因；报告进构建产物 |
| 生成模块与手写块同名异型互相覆盖 | 前置面先把裁决做实，翻译面只在前置面之后开工 |
| `check` 与 `build` 对生成物的判据分叉 | `check` 只读、`build` 只写；CI 用 `build` 后比对工作区 |
| 翻译器与自举解析器两边各写一套映射 | 映射规则只写在计划与测试夹具里；自举侧按同一份夹具验收 |
| 头文件集合两处维护 | 构建面把头文件归一，宏求值从翻译步继承 |
| 配置期探测工具，计划不可复用 | 配置期只登记，工具查找在执行期；`--print-plan` 必须能在没有 clang 的机器上打出计划 |
| 生成物路径越过 `.build` 前缀，变成任意路径写入 | 计划只接受工作区 `.build` 下的输出路径；装载器拒绝其余前缀 |
| 缓存键漏掉翻译器版本，升级后沿用旧产物 | 键含翻译器版本与目标三元组；升级翻译器后强制 miss |
| 生成物缺失被当成「没有外部符号」静默通过 | 计划里登记了翻译步却没有产物，报定向诊断（要求先 build），不静默跳过 |
| `build.pini` 写坏，把全仓检查一起拖红 | 只有 `pini build` 读脚本；`check` / `run` / `test` 只读计划数据 |

## 决策登记

| 决策 | 状态 | 理由 | 代价 |
|---|---|---|---|
| 采用三分法：头文件、构建翻译、零散面 | 已定 | 与 Zig 0.17 同构 | 需要新建翻译器与 `build.pini` 最小面 |
| 构建脚本两段式：配置产计划、执行跑计划 | 已定 | 脚本与执行混在一起，缓存与工具接口都无从谈起 | 多一层计划对象与执行器 |
| `build.pini` 用声明块而非可执行脚本 | 已定 | 语言还没有计划对象的构造面；声明式同样满足「配置纯净、计划是数据」 | 字段名固定，扩参数要改读取器 |
| 配置期不做工具探测 | 已定 | 探测即污染配置缓存，计划不可复用 | clang 查找推迟到执行期 |
| 生成物落构建目录，不进源码树 | 已定 | 与 Zig 同路；缓存键保证不陈旧 | 源码树看不到生成声明，审查改看翻译步声明 |
| 计划是数据，只有 `pini build` 执行脚本 | 已定 | 脚本写坏只影响 build，不会被 check / run 连带 | 其他命令多一步「先 build」 |
| 生成物并入本包，暂不做独立模块 | 已定 | Zig 里生成物归声明翻译步的包，消费方靠装配期绑名；Pini 的 import 写路径，独立模块要开三个口子 | 两个包不能共用同一份生成声明 |
| 翻译范围只做白名单，其余跳过出报告 | 已定 | Pini 的 ABI 面接不住结构体与函数指针返回 | 手写面仍需承接一部分符号 |
| 块名不再是库键，库绑定归 `[ffi].libs` | 随前置面成立 | 生成块按头文件命名，无法充当库名 | 解释器换一套库解析 |
| 取消 foreign 块 | 已否决 | 见「已否决：解散」 | 无 |
| 成员参数名 | 缓办 | 生成物不需要 | 手写面靠行尾注释 |

## 三条裁决

开工前的三条待决项已裁定，理由与代价记在「决策登记」里；这里只留会影响后续写法的部分。

- **生成物归属**：并入声明它的包。跨包共用不共享产物，两个包各翻一份；等 import 能按名绑定、且翻译开销可测时再谈独立模块。
- **生成模块可见性**：只认计划。`check` / `run` / `test` 遇缺失报「先跑 `pini build`」，不执行 `build.pini`；代价是第一次检查前要先 build 一次。
- **翻译范围**：严出白名单。结构体、函数指针返回、位域、函数式宏、枚举常量一律跳过并进报告；手写面承接这部分，等出现绕不开的库再扩。
