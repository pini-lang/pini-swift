# HIR 判据缺口台账（CG 表）

- 状态：**在册（Open 清单）** —— **只登记不修**。落件 = **P3-G2（2026-09-15）**。
- 对象：LR-4 **判据面**（三层判据的器械与纪律）的缺口，**不是产品缺陷**。
  产品缺陷走工单，本件只收「判据看不见 / 判据说了不算 / 判据写不出账」这一类。
- **单源**：与工单**不重复登记** —— 已有户口者只给指针（依据 = P2 细目 §10.4 的
  「同一件事不要有两个状态源」）。本件是**唯一**登记处，条目 ID 前缀 **`CG-`**（criteria gap），
  与 `E-*`（证据）/ `D-P2-*`（决策）/ `J*`（验收判据）/ `M*`（变异轮次）/ `G-P*`（宿主 gap）**不同族**。
- 引用本件的两处「并入」指针已改指本件：主计划 §13（G6 重放批末）· P2 细目 §8.4 末。

## 0. 为什么需要本件

P3 的三层判据里：第 1 层（执行等值）与第 2 层（规范一致性）**已有器械**（探针 + `hir-contract-check.py`），

**从未收敛**，于是「哪些判据缺口在册」这个问句**没有单一答案**。
本件把 13 条收敛成一张表，并如实标注**每条是已处置、待处置、登记不修，还是需裁决**。

## 3. 本项处置的 7 条：实测依据（全部现跑，2026-09-15）

**CG-01 / CG-02（G1）**：规则 6 纳入 `a_out` 后实测 —— 真实盲区**只有 2 例**
（`testBareCaseAmbiguousExpectedTypeViaLLI` / `testDotCaseAmbiguousExpectedTypeViaLLI`：
参照臂 `rc=1`、两实臂各输出 `42`）⇒ 新槽位 `CHANGE_REFERENCE` 承接。
⚠️ **这订正了此前的估计**：曾把这 2 例与 20 例 `GAP_HIR_ENGINE` 绑在一起；实测证明
**成因不同** —— 20 例是 **stderr 形状**的 tie-break 失配（CG-05），2 例才是 **stdout 不含参照臂**。

**CG-05（G1）**：20/20 夹具逐字复验 —— 三臂 `rc=0`、三臂 stdout 逐字节相同、
`E7-001` 在**冻结参照臂上同样出现**、LLVM 臂静默 ⇒ 与 HIR 实现无关。
收窄形态 = **旧槽位拆成两个**：奇偶（两边都响、LLVM 静默，来自共享前端）判**非阻塞观察**
（`WARN_CHANNEL_ASYMMETRY`、按错误码聚合），**只有真不对称**才留在 `GAP_HIR_ENGINE`。
⇒ `FLIP BLOCKERS 27 → 11`（7 真 + 4 明示接受的假阳性）。

**CG-06（G1）**：`h_rc != 0` 提为规则 5 后，4 个负向测试夹具从 `OK_HARNESS` 归入 `GAP_EXEC`
（变异 M4 捕获：规则序回退 ⇒ 4 夹具 `GAP_EXEC → OK_HARNESS`，带 `[BLOCKER-RESOLVED]` 标记）。
代价（用户明示接受）：这 4 个是**假阻塞** —— 三臂均如实报错，`run-llvm` 报 `rc=0`
仅因其**忽略 `lli` 退出码**。⇒ 口径必须**按两个度量读**：「集合内假阳性」20 → 4、
「集合总数」27 → 11，**两者不可互相抵消陈述**。
⇒ **该代价的处置已落地**（2026-09-16，P4-0）：4 个负向测试**移出阻塞集**，由新非阻塞槽位
`WARN_LLVM_RC_UNPROPAGATED` 承接（门 = **参照臂非零 ∧ LLVM 臂 stderr 非空**）；
`FLIP BLOCKERS 11 → 0`。`run-llvm` 依裁决**未修**，其「丢弃 `lli` 退出码」另立工单
（`docs/issue-run-llvm-discards-lli-exit-status-2026-09-16.md`，登记不修）。
⚠️ 上行两个数（27 / 11）是 **P3-G1 时点**的读数，**不是现值**；现值见元仓
`.workbuddy/state-readings.json`（本件不镜像读数）。

**CG-07（G2）**：探针新增 `--out`（**默认值保持 `/tmp/hir-parity-sweep.tsv` 不变**）。
改动动机是实测事故：G1 的变异反证与基线 sweep **共用**该固定路径 ⇒ 冻结件曾被变异件残留污染

**CG-04（G2）**：写入本件 §5（认知纪律）—— 它没有代码可改，**能改的只有「读法」**。

**CG-08（G2 补记）**：理由由「零语料行使」升级为**架构层不可构造** —— 本格读码实测：
`HIRExecutor` **没有非致命告警通道**（诊断仅有 `noLocation` 占位与 `RuntimeError`，

⇒ 「HIR 臂告警（`rc=0`）而参照臂静默」这一形态**在该架构下无法构造**。

**保留**（G1 已裁：删了会让该真缺口类一并失明），继续标注 `UNEXERCISED`，**不宣称有判别力**。

**CG-13（2026-09-15，附属批；用户裁决 + 走 spec §1.3 落地）**：`arrayJoin` **移出 B 组 ⇒ B 组 5 项**（`§2.22` / `§2.23` / `§2.36` / `§2.37` / `§2.38`）。执行前提是用户裁定的**先补非 ASCII 测试**：

## 5. 纪律条款（供各格开工自检；无代码可改，只能改读法）

1. **覆盖面的判据是「通道对」，不是「套件名」**（CG-04）。`HIRDifferentialTests` 这个名字会让人
   以为「HIR 已被差分覆盖」，而它比的是 `ast ⇄ llvm 管线`、**不经过 HIR 解释器**。
   ⇒ 问「这个面覆盖了吗」时，必须答**覆盖了哪一对通道**；`llvm⇄hir` 与 `hir⇄ast`
   由**另外两个器械**承担。
2. **对照必须与变异面正交**（CG-09/10 的同族教训，源自 `slice` 反例）：`slice` 看似是
   纯容器对照，实则**同一内建方法两通道走不同路线**（AST 走 Pini 标准库、HIR 走原生 `.sliceCall`），
   于是它成了「第二个可观测者」—— 红不是因为对照失效，而是因为**对照恰好在变异面上**。
   ⇒ 对照要选**不触碰**被变异族（match / optional / try / 字面量 / 内建）的纯算术 parity 用例。
3. **「跑过某个子集」不能升级为「知道该面的覆盖面」**（CG-04 的过程留档）：该结论起初据子集
   误判为「XCTest 面对 HIR 缺口全失明」，跑全量当场推翻。

每条**连跑三次**读数稳定 ⇒ 不是闪断。

**符号级根因**（为什么只有后者是 `rc=0`）：`Sources/PiniCLI/main.swift` 的 `case "run-llvm"`
**直接把参数当文件读**（`readFile(args[2])`，**无目录分支**）⇒ 目录走 `catch` → `exit(1)`；
而 `runLLICommand` **内部**的 `waitUntilExit()` 丢弃 `terminationStatus` ⇒ lli 真跑起来但程序崩溃时，
命令仍返回 `0`。**两条路径在代码上是不同位置，性质相反**：

| 路径 | 表现 | 性质 | 归谁 |
|---|---|---|---|
| `readFile` 失败（目录 / 打不开） | 显式报错 + **`rc=1`** | **显式失败** —— 脚本看得见，**不是判据缺陷** | `docs/issue-hir-package-run-unsupported-2026-09-16.md`（能力缺口） |
| `runLLICommand` 之后（程序自己崩） | lli 的 stderr 有真报错，命令却 **`rc=0`** | **假绿** —— 脚本看不见 | `docs/issue-run-llvm-discards-lli-exit-status-2026-09-16.md` |

⇒ 「`run-llvm` 不接受目录」与「`rc=0` 掩盖」是**两件事**，此前被并排写进同一张表，
读者会顺理成章读成「目录输入也静默」。**本批不替那次读错编解释**，只给出可复现的现测与符号级根因。
