# Pini 特性索引（Feature Index）

> **本件是什么**：`docs/spec/pini-reference-v0.md` 的**派生视图** —— 把参考件里散落在 13 章、约 100 节
> 中的**语言特性**收成一张可引用、可探讨的**编号表**。
>
> ⛔ **本件不是权威**：特性是否存在、其语义为何，**一律以参考件为准**；两者冲突时以参考件为准。
> 本件的职责只有三件：① 给每条特性一个**稳定编号**；② 把出处**逐条指回参考件的节**（可机械核对）；
> ③ 为「离全量覆盖还有多远」这类探讨提供一个**共同的名录底座**（在此之前该问题只能报近似值）。
>
> **形态先例**：与 `diagnostic-codes.md` 同型 —— 人类可读的**派生视图**，低权威、迟维护。
>
> **维护纪律**：
> - 参考件新增/删除一节 ⇒ 本件**同批**跟一行（否则派生物腐坏）；
> - ⛔ **本件不记会漂的读数**：现况列只到**受控词表**（见本件 0.3 节），不写条数、行数、器械道数；
> - 「现况」列是**一次标定**，权威读数在别处（指针见本件 0.3 节）⇒ 读到它时先核日期。

## 0. 读法（三分钟）

### 0.1 收什么

**收**：参考件里的**语言特性** —— 语言提供的**构造**（语法形态 + 语义）与**能力**（后端、运行时、工具链）。

**⛔ 不收**（另见本件 14 节）：文档约定 · 术语表 · 性质与依据 · 稳定性标记的含义 · 治理流程 ·
后端名册的**状态**（名册本身作为一条特性收，各后端的状态不收）· 已退役的实现形态 ·
未采纳的意图产生式 · 纯读数。

### 0.2 列的含义

| 列 | 含义 |
|---|---|
| **#** | 稳定编号（`F001` 起，只增不改；删条留洞，⛔ 不回收） |
| **特性** | 该行对应的语言构造 / 能力。⚠️⭐ **它是中文描述，⛔ 不是标识符来源** —— 见本件 0.4 节 |
| **出处** | 参考件的**章·节**（`§x.y`），可机械核对 |
| **稳定性** | **抄**参考件的标记（`Provisional` / `Experimental`；无标记 ⇒ 记 `—`） |
| **编译链落点** | ⭐ 该特性**在哪一层**被兑现（值域见下表） |
| **自举现况** | 自举 MVP 切片对该特性的覆盖（值域见下表，⚠️ 快照） |

### 0.3 ⭐ 两列的受控词表

**编译链落点**（决定「这条要不要自举实现」）：

| 值 | 含义 |
|---|---|
| **前端** | 只需解析 / 语义 / 类型检查兑现 —— ⛔ **不产生 IR，不进产物**，因此与发射器无关 |
| **降→发** | 需要降载（源码 → IR）+ 发射（IR → `.ll`） |
| **降→发+RT** | 在前者基础上还需**运行时段**（`bk_*` 符号） |
| **分析** | 在 **IR 上做的分析**（ARC 插入 / 单态化 / COW / 逃逸 / SCC 等） |
| **宿主** | 由编译器驱动或工具链兑现（模块系统 / 依赖解析 / 诊断码），**不进产物** |
| **后端** | 后端面本身（名册 / 字节码 / WASM / 新后端），与语言构造正交 |

**自举现况**（⚠️ 快照，标定日 **2026-10-04**）：

| 值 | 含义 |
|---|---|
| **内** | 该特性在自举 MVP 切片内（契约 §1.3 的 40 节点口径） |
| **划** | 明确划出（规划件 §1.3 / 自举仓 `src/IR/ir.pini` 件头两处一致的划出面） |
| **部分** | 部分在内（如标量类型族：切片只含其中一部分） |
| **—** | 不涉（该特性落在前端 / 宿主 / 后端面，⛔ 本表不对它记现况） |

⚠️⭐ **现况列的权威读数不在本件**：条数几何、面册状态、销账进展一律现查 ——
发射覆盖面见自举仓 `tools/` 的四本册（单文件面 / 整包面 / 对齐腿两本）；特性差距见
`docs/spec/issue/selfhost-gap-ledger-2026-09-30.md`；路线与销账条件见
`docs/spec/issue/plan-selfhost-llvm-backend-2026-10-01.md`。本列**只作名录**，⛔ 不作判据。

### 0.4 ⛔⭐ 标识符纪律：本表的中文「特性」列**不是**标识符来源

**为什么单列一节（2026-10-04 · 用户提出）**：本表的「特性」列是为**人读**写的中文描述。
若实现时**照它造标识符**，会产出**违反自举仓规范**的代码 —— 而 ⚠️⭐ **这种违规不会报错**。

**实测事实（2026-10-04 · 自举仓 `src/` 全体 `*.pini`）**：

| 面 | 总数 | **含中文标识符** |
|---|---|---|
| 函数 / 方法定义（`名\|func(…)` / `名\|self(…)`） | **1689** | **0** |
| 类型定义（`[名]` / `(名)` / `{名}`） | **230** | **0** |
| 方括号类型声明（契约承载节点） | **131** | **0** |

⇒ 中文在自举仓源码里的出现面**只有两处**：**注释**（5424 行）与**字符串字面量 / `print`**（214 行）。
⇒ 事实规范 = **仓自身源码一律用英文标识符**（`IRExprList` · `irLowerEntry` · `ivExecCall`）。

⚠️⭐ **它为什么是陷阱（三条叠加）**：

1. **语言层允许中文标识符** —— 参考件 §2.5：首字符 `\p{L}`（Unicode 字母）⇒ 中文**合法**；
2. ⇒ **照中文名写，编译器一声不吭**（`check` 绿、`run` 也绿）—— 违规**没有任何器械会拦**；
3. ⚠️ **该纪律今天是「事实规范」而非「成文条款」**：规范件里检索「命名 / 标识符 / 英文」
   只命中**标识符的语法规则**与**文件命名**，**没有一条规定仓源码该用什么语言的标识符**
   （⛔ 这条是**证据**，不是本件的裁断 —— 要不要把它升格为成文规范属待裁项）。

**正确取法**：需要标识符时，以 **IR 契约件的条目名** / **参考件里的英文形态**为准。
本表**已给出反引号英文名的有 40 条**（如 `` `capture` `` · `` `print` `` · `` `I32` ``）——
它们是**示范**，⛔ 不是「其余 152 条缺信息」。

⚠️ **一处必须说清的边界**：本表 192 条里有 **127 条完全没有英文名**，而这是**正常的** ——
本表按「**特性**」立条，而特性多是**机制或性质**（「源文件与编码」·「缩进栈与三类块」·
「运算符优先级九层」），它们**本来就没有对应的标识符**。⇒ ⛔ **别读成本表缺信息**，
也⛔ **别为凑整齐而替它们编造英文名**（那会造出**不存在于任何权威载体**上的名字）。

**另有层级命名纪律**（⛔ 不在本表，在各层的件头注释里）：本仓各层共用一张符号表且
**不支持重载** ⇒ 层内一律带前缀避冲突（如类型层 `ty` 前缀 · 诊断层 `type` 前缀），
保留词另有避让（`scope` 是块标签保留词 ⇒ 作用域帧一律用 `frame`）。
⚠️ **取用时读该层的件头**，⛔ 不要按本表推断命名。

⚠️ **本表不给条数**：`自举现况` 与分组计数都是**会漂的量**，按本件 0 节的维护纪律只留名录；

- ⛔ **本件不记读数**：现况列只到受控词表，条数与进展现查（本件 0.3 节给了指针）。
- ⛔ **本件不代裁**：本件 15 节各项须另行点名。
- ⛔⭐ **本件的中文「特性」列不是标识符来源**（见本件 0.4 节）——
  照它造标识符会**违反自举仓的英文标识符纪律**，而该违规**没有任何器械会拦**。
- ⚠️ **本件的完成标准**：F001–F192 与参考件**双向可核** —— 每条能指回一个节，每个节的语言特性至少有一条；
  若参考件新增一节而本件无对应行 ⇒ **本件已腐坏**，须同批跟行。
- ⚠️ **编号按写入序**，不按节序重排（§12.7 那批为补录项）⇒ 引用时以**编号**为准，⛔ 别按号推章节。
