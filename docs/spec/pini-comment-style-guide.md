# Pini 注释风格指南（Comment Style Guide）

> **性质**：项目**强制工程标准**，受 spec v0 §7「注释规范」治理（spec 给权威摘要与 DoD，本文给细则、样例、lint 与迁移批次）。与 `test-refactoring-principles.md`（测试规范，受 spec §6 治理）**协和共存**，不替代其「意图 / 推进性 / 驳回性」三要素要求。
>
> **事实源层级**（继承 spec v0）：spec v0 ＞ 本指南 ＞ 代码注释。注释与 spec 冲突时以 spec 为准。
>
> **来源依据**：本指南不新增立场，只把 spec 两条既有治理原则操作化——① 行号=软证据、符号名+语义为权威；② 跨文件章节号「见到即缩减」。

---

## 0. 动机：两个空间的寿命不对称（核心论点）

| 空间 | 演进速率 | 维护负担 |
|---|---|---|
| **代码注释** | 持久、慢维护——代码改了，注释常被忘改 → 漂移 / 腐化 | 高（散落全文，难批量审） |
| **外部引用** | 半持久、快演进——spec 段落、ADR、issue、PR、CHANGELOG、行号都在动 | 低（集中治理、带版本） |

**推论**：注释里「指向外部」的耦合必然腐化——外部快变、注释慢变，引用迟早过期。

**因此本指南的总纲**：
- **原因与来源（why / source）** 进**受版本化治理的外部文档**（ADR / issue / CHANGELOG / spec），不在注释里叙述。
- **代码注释**只保留两样东西：① **自包含**的行为 / 不变量陈述（用代码自身词汇）；② 必要时的**一个符号型稳定 ID 指针**（单行）。

**「稳定」的判定标准**：ID 是否随文件编辑 / 重命名 / 章节重排而漂移。

| 指针形态 | 稳定性 | 判定 |
|---|---|---|
| `ADR-015` / `G43` / `E5-016` / `issue-2026-08-27` | 语义键，不随编辑漂移 | ✅ 可用 |
| `spec §2.7` / `roadmap §3` | 章节号随对方文件演进重排 | ❌ 禁用（spec §0 缩减原则） |
| `docs/xxx.md` / `Parser.swift:2237` | 文件可改名/删除，行号必移 | ❌ 禁用（spec §1.4） |

这与 spec「行号=软证据；权威判定键=符号名+语义」及「跨文件章节缩减」完全同源——spec 管「证据判定」，本指南管「注释写法」。

## 1. 注释可以写什么（允许）

1. **自包含的「做什么」**：用代码自身词汇（符号名、类型、前置 / 后置条件）说明**非显然**行为。读注释不需跳转外部。
2. **不变量 / 契约**：本段代码必须满足的约束。例：`*T 元素须为标量或纯值结构体（与 C-ABI 对齐）`。
3. **符号型稳定 ID 指针**（单行，最多一句）：`ADR-015` / `issue-2026-08-27` / `G43` / `E5-006`。
4. **测试「意图」首行注释**：测试规范强制要求，保留且鼓励（见 §5）。

## 2. 注释不要写什么（禁止 / 劝阻）

- ❌ **行号**：`Parser.swift:2237`、`cstring.pini:42` 之类。spec 已定行号=软证据；代码注释写行号必腐。要定位用**符号名**。
- ❌ **跨文件章节号**：`spec §2.7`、`roadmap §3` 之类。章节号随对方文件演进重排 → 悬空引用。按 spec 缩减原则改为符号型 ID（`ADR-015` / `G43`）或粗粒度主题词（「见 spec FFI 与 unsafe 主题」）。
- ❌ **文件路径 / 文档名快照**：`docs/xxx.md`。文件可改名或删除——本仓库已实证：注释中 3 个文档名引用已成死链。
- ❌ **版本号叙事**：「v0.48.0 起改为…」「ADR-014 逆转 ADR-013」——那是 CHANGELOG / ADR 的内容。注释只述**现况**，外加当前有效的 ADR ID。
- ❌ **大段摘抄 spec / 草稿**：spec 是事实源，复制即双份维护、必分歧。
- ❌ **易变 URL / 裸 PR 号**：除非该 PR 本身是受治理的稳定记录（罕见）。
- ❌ **实现流水账**：「本函数依次做了 X、Y、Z」式——用符号名指向即可，注释不是目录。

## 3. 如何合法引用外部（确有必要时限此写法）

- 只用**符号型稳定 ID**：不用行号 / 章节号 / 路径 / URL。
- 格式建议（单行）：
  - `// 见 ADR-015（FFI & unsafe）`
  - `// G43：foreign 声明块语义边界`
  - `// issue-2026-08-27 P1：foreign 输出可观测性`
  - 需指 spec 时：`// 见 spec「FFI 与 unsafe」主题`（主题词，非章节号）
- 若理由复杂：把理由写进对应 ADR / issue，**注释只留 ID**；读者按需追到受治理文档。

## 4. 注释分级（tier）

| 层级 | 语法 | 允许内容 | 约束 |
|---|---|---|---|
| **公开契约注释** | Swift `///`、Pini `#` | 行为契约、不变量；必要时符号型 ID | 不用章节号 / 行号 / 路径；不复制 spec 段落 |
| **实现注释** | Swift `//`、Pini `;` | 本地非显然决策、不变量 | 自包含；必要时单行 ID 指针 |
| **TODO / FIXME** | `// TODO:` | 待办 | **必须带稳定追踪 ID**（issue / ADR），禁止裸 `TODO` |

## 5. 与测试规范协和（mapping）

`test-refactoring-principles.md` 的三要素保持不变，本指南与其映射如下：

- **意图注释（每条测试首行）** = 本指南「自包含行为陈述」在测试代码上的具体实例 → **保留并鼓励**。一句话说清「验证什么行为」即可，不额外嵌入行号 / 章节号 / 代码片段。
- **推进性 / 驳回性注释**中若提到错误码，用稳定码 `E#-###`，不用行号。
- 测试里引用外部决策（如「为何此边界被拒」）同样走 §3：单行 `// 见 ADR-014`，理由在 ADR。

二者不冲突：测试规范要求「写意图」，本指南要求「意图之外不叙事、不引易变外部」——互补。

## 6. 正反样例

### ❌ 坏味道（叙事 + 行号 + 外部摘抄，当前真实存在）

```pini
; ════════════════════════════════════════════════════════════════
; ffi_module — FFI & unsafe 完整模块示例（ADR-015 / ADR-017，spec §2.7）
;
; 本文件与 pini.toml 同处 examples/ffi_module/。演示「配置外部接口
; + 以最小不安全范围调用」的完整链路（我们在 v0.48.2~v0.48.3 把 shim
; 白名单和 dlsym 动态加载先后落地，见 CHANGELOG 对应段落）。
;
; 类型坑（实验确定）：load 返回动态 Any；只有在非 unsafe 上下文用
; `unsafe load(p)` 才能收回具体标量（见 Interpreter.swift:1369 附近
; 的实现）。assert 内比较只接受 I32（U64 在 FileLoader.swift:32 解析
; 时…）。puts 直写真实 stdout（绕过 outputSink，见 Interpreter.swift:650）。
; ════════════════════════════════════════════════════════════════
```

问题：①大段叙事会随 CHANGELOG / ADR 改写而腐；②三处行号必过期；③摘抄 spec/实现细节成双份维护。

### ✅ 好味道（自包含 + 单行 ID 指针）

```pini
; ffi_module — FFI & unsafe 示例（配置点 + 最小不安全范围调用）。
; 设计依据见 ADR-015 / ADR-017（G43）。
; 不变量：foreign 符号文件级作用域；load 仅在非 unsafe 上下文收回具体类型；
;         *T 元素须标量（C 兼容）；foreign 输出不经 outputSink。
```

改进：行为 / 不变量自包含陈述（不跳转也懂）；外部只留符号型稳定 ID；零行号、零章节号、零叙事。

### 9.3 硬约束（不可违反）

1. **零语义变更**：只改注释，禁止顺手改代码、重命名符号、调整格式。每批 `git diff` 应只含注释行。
2. **每批独立验证**：`swift build --disable-sandbox` + `swift test --disable-sandbox`（本机必须带 `--disable-sandbox`）。基线 994 + 44 = 0 失败。
3. **文档注释不降信息量**：删外部叙事时，若该叙事含唯一的行为约束，须先把约束改写为自包含陈述再删——**不允许净删除信息**。
4. **示例注释同规**：`examples/*.pini` 与 `Sources/` 同规，因示例是用户第一读物。
5. **顺序不可跳**：Phase 0 未完成前不动 V1 相关注释（否则 ID 仍悬空，白改）。
