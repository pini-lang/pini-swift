# Pini 注释风格指南（Comment Style Guide）

> **性质**：项目**强制工程标准**，受语言规范的「注释规范」治理（规范给权威摘要与 DoD，本文给细则、样例、lint 与迁移批次）。与**测试规范**（受语言规范的「测试规范」治理）**协和共存**，不替代其「意图 / 推进性 / 驳回性」三要素要求。
>
> **事实源层级**（继承语言规范）：语言规范 ＞ 本指南 ＞ 代码注释。注释与规范冲突时以规范为准。
>
> **适用面**：**注释**（源码内的 `//` `///` `;` `#`）与**长效文档**（决策记录、规范、指南、参考）**同规** ——
> 二者同属「持久、慢维护」空间，故「指向快变外部」的耦合在两边都以同样方式腐化。细则见 §10。
> ⛔ **不适用**：变更记录（版本叙事就是它的内容）· 提案与落地计划（工作件，指向过程材料是本职）· 规范与参考（权威源，互引是职责）。
>
> **来源依据**：本指南不新增立场，只把语言规范的两条既有治理原则操作化 ——
> ① 行号 = 软证据、符号名 + 语义为权威；② 跨文件章节号「见到即缩减」。
> §10 是同一条「寿命不对称」律的**第二个落点**，同样非新增立场。

---

## 0. 动机：两个空间的寿命不对称（核心论点）

| 空间 | 演进速率 | 维护负担 |
|---|---|---|
| **代码注释** | 持久、慢维护——代码改了，注释常被忘改 → 漂移 / 腐化 | 高（散落全文，难批量审） |
| **外部引用** | 半持久、快演进——spec 段落、ADR、issue、PR、CHANGELOG、行号都在动 | 低（集中治理、带版本） |

**推论**：注释里「指向外部」的耦合必然腐化——外部快变、注释慢变，引用迟早过期。

**因此本指南的总纲**：
- **原因与来源（why / source）** 进**受版本化治理的外部文档**（ADR / issue / CHANGELOG / spec），不在注释里叙述。
- **代码注释**只保留两样东西：① **自包含**的行为 / 不变量陈述（用代码自身词汇）；② 必要时的**一个符号型稳定 ID 指针**（单行）。

**「稳定」的判定标准**：ID 是否随文件编辑 / 重命名 / 章节重排而漂移。

| 指针形态 | 稳定性 | 判定 |
|---|---|---|
| `FFI 子系统` / `G43` / `E5-016` / `issue-2026-08-27` | 语义键，不随编辑漂移 | ✅ 可用 |
| `spec §2.7` / `roadmap §3` | 章节号随对方文件演进重排 | ❌ 禁用（spec §0 缩减原则） |
| `docs/xxx.md` / `Parser.swift:2237` | 文件可改名/删除，行号必移 | ❌ 禁用（spec §1.4） |

这与 spec「行号=软证据；权威判定键=符号名+语义」及「跨文件章节缩减」完全同源——spec 管「证据判定」，本指南管「注释写法」。

## 1. 注释可以写什么（允许）

1. **自包含的「做什么」**：用代码自身词汇（符号名、类型、前置 / 后置条件）说明**非显然**行为。读注释不需跳转外部。
2. **不变量 / 契约**：本段代码必须满足的约束。例：`*T 元素须为标量或纯值结构体（与 C-ABI 对齐）`。
3. **符号型稳定 ID 指针**（单行，最多一句）：`FFI 子系统` / `issue-2026-08-27` / `G43` / `E5-006`。
4. **测试「意图」首行注释**：测试规范强制要求，保留且鼓励（见 §5）。

## 2. 注释不要写什么（禁止 / 劝阻）

- ❌ **行号**：`Parser.swift:2237`、`cstring.pini:42` 之类。spec 已定行号=软证据；代码注释写行号必腐。要定位用**符号名**。
- ❌ **跨文件章节号**：`spec §2.7`、`roadmap §3` 之类。章节号随对方文件演进重排 → 悬空引用。按 spec 缩减原则改为符号型 ID（`FFI 子系统` / `G43`）或粗粒度主题词（「见 spec FFI 与 unsafe 主题」）。
- ❌ **文件路径 / 文档名快照**：`docs/xxx.md`。文件可改名或删除——本仓库已实证：注释中 3 个文档名引用已成死链。
- ❌ **版本号叙事**：「v0.48.0 起改为…」「标签语法反转 逆转 块标签语法（已撤销）」——那是 CHANGELOG / ADR 的内容。注释只述**现况**，外加当前有效的 ADR ID。
- ❌ **大段摘抄 spec / 草稿**：spec 是事实源，复制即双份维护、必分歧。
- ❌ **易变 URL / 裸 PR 号**：除非该 PR 本身是受治理的稳定记录（罕见）。
- ❌ **实现流水账**：「本函数依次做了 X、Y、Z」式——用符号名指向即可，注释不是目录。

## 3. 如何合法引用外部（确有必要时限此写法）

- 只用**符号型稳定 ID**：不用行号 / 章节号 / 路径 / URL。
- 格式建议（单行）：
  - `// 见 FFI 子系统（FFI & unsafe）`
  - `// G43：foreign 声明块语义边界`
  - `// issue-2026-08-27 P1：foreign 输出可观测性`
  - 需指 spec 时：`// 见 spec「FFI 与 unsafe」主题`（主题词，非章节号）
- 若理由复杂：把理由写进对应 ADR / issue，**注释只留 ID**；读者按需追到受治理文档。

## 4. 注释分级（tier）

| 层级 | 语法 | 允许内容 | 约束 |
|---|---|---|---|
| **公开契约注释** | Swift `///`、Pini `#` | 行为契约、不变量；必要时符号型 ID | 不用章节号 / 行号 / 路径；不复制 spec 段落 |
| **实现注释** | Swift `//`、Pini `;` | 本地非显然决策、不变量 | 自包含；必要时单行 ID 指针 |
| **TODO / FIXME** | `// TODO:` | 待办 | **必须带稳定追踪 ID**（issue / ADR），禁止裸 `TODO` |

## 5. 与测试规范协和（mapping）

**测试规范**的三要素保持不变，本指南与其映射如下：

- **意图注释（每条测试首行）** = 本指南「自包含行为陈述」在测试代码上的具体实例 → **保留并鼓励**。一句话说清「验证什么行为」即可，不额外嵌入行号 / 章节号 / 代码片段。
- **推进性 / 驳回性注释**中若提到错误码，用稳定码 `E#-###`，不用行号。
- 测试里引用外部决策（如「为何此边界被拒」）同样走 §3：单行 `// 见 标签语法反转`，理由在 ADR。

二者不冲突：测试规范要求「写意图」，本指南要求「意图之外不叙事、不引易变外部」——互补。

## 6. 正反样例

### ❌ 坏味道（叙事 + 行号 + 外部摘抄，当前真实存在）

```pini
; ════════════════════════════════════════════════════════════════
; ffi_module — FFI & unsafe 完整模块示例（FFI 子系统 / 解释器 dlsym 加载，spec §2.7）
;
; 本文件与 pini.toml 同处 examples/ffi_module/。演示「配置外部接口
; + 以最小不安全范围调用」的完整链路（我们在 v0.48.2~v0.48.3 把 shim
; 白名单和 dlsym 动态加载先后落地，见 CHANGELOG 对应段落）。
;
; 类型坑（实验确定）：load 返回动态 Any；只有在非 unsafe 上下文用
; `unsafe load(p)` 才能收回具体标量（见 Interpreter.swift:1369 附近
; 的实现）。assert 内比较只接受 I32（U64 在 FileLoader.swift:32 解析
; 时…）。puts 直写真实 stdout（绕过 outputSink，见 Interpreter.swift:650）。
; ════════════════════════════════════════════════════════════════
```

问题：①大段叙事会随 CHANGELOG / ADR 改写而腐；②三处行号必过期；③摘抄 spec/实现细节成双份维护。

### ✅ 好味道（自包含 + 单行 ID 指针）

```pini
; ffi_module — FFI & unsafe 示例（配置点 + 最小不安全范围调用）。
; 设计依据见 FFI 子系统 / 解释器 dlsym 加载（G43）。
; 不变量：foreign 符号文件级作用域；load 仅在非 unsafe 上下文收回具体类型；
;         *T 元素须标量（C 兼容）；foreign 输出不经 outputSink。
```

改进：行为 / 不变量自包含陈述（不跳转也懂）；外部只留符号型稳定 ID；零行号、零章节号、零叙事。

## 7. 机械检查（CI lint 规则集）

| 规则 | 检测正则（ripgrep） | 判定 | 现状实测 |
|---|---|---|---|
| L1 行号禁止 | `(//\|///\|;\|#).*\.(swift\|pini)?:[0-9]+` | 违规 | **0 命中**（已清） |
| L2 跨文件章节号 | `^\s*(//\|///\|;\|#).*(spec\|roadmap\|草稿) §[0-9A-Z]` | 违规 | **0 命中**（已清，2026-08-27 治理收口；见 §9.4 盲区） |
| L3 文档名快照 | `^\s*(//\|///\|;\|#).*[A-Za-z0-9_-]+\.md` | 违规 | **0 命中**（已清，2026-08-27 治理收口） |
| L4 版本号叙事 | `^\s*(//\|///\|;\|#).*v0\.[0-9]+` | 违规 | **0 命中**（已清，2026-08-27 治理收口） |
| L5 裸 TODO | `(TODO\|FIXME\|HACK\|XXX)` 不跟 `issue-`/`ADR-` | 违规 | **0 命中**（已清） |
| L6 ID 可兑付 | 抽取 `ADR-[0-9]+`，逐个在 `docs/spec/adr/` 找**同编号文件** | 悬空即违规 | **无 ADR 引用**（2026-09-19 编号重置后：旧一批连同其登记表**载体已删**，引用已全仓改写为主题词） |

**文档面判据（D1–D4；域与依据见 §10）**：

| 判据 | 检测式 | 判定 | 与 L 系的差别 |
|---|---|---|---|
| D1 文档路径 | 反引号包裹的 `.md` / `.toml` 路径 | 违规 | 同 L3，但作用面是**文档正文** |
| D2 跨文件章节号 | **主题词直接跟** `§N` | 违规 | 同 L2，但**不依赖字面量 `spec`**（本仓实际写「语言规范 §N」⇒ 原 L2 正则抓不到） |
| D3 裸节号 | `§N` 不在**本文已声明节**之内 | 违规 | 比 L2 更强：改「引用 − 声明」差集，能抓无主题词的裸引 |
| D4 版本号叙事 | `v0.NN` | 违规 | 同 L4，作用面扩到文档 |

**显式豁免**（**不是漏洞**）：围栏代码块内的行（可执行指令 / 引例）；行内带反例记号 `❌` 的行；命名模式与占位符。

落地方式（注释面）：`hooks/comment-lint.sh` 已实现 L1–L6 机械检查并**转 `exit 1` block 模式**（2026-08-27）；`hooks/pre-commit` 与 `.github/workflows/linux-test.yml` 各挂一次。无 ripgrep 时自动回退 `grep -E`（模式已 POSIX 化），CI 容器零额外依赖。

⚠️ **扫描面（后缀）= `*.swift` / `*.pini` / `*.toml`**。
`.toml` 于 2026-09-20 纳入 —— 资源类 TOML（诊断资源）同样载有注释，**早先不在面内 ⇒ 其注释零门禁**
（实测：两个诊断资源各有 3 行违规，而门禁一直打印「全绿」）。
⚠️ 由此产生一条**已知边界**：后两条规则（L5 待办 / L6 ADR 兑付）**不锚定注释符**
（对 `.swift` / `.pini` 亦如此，行为未变）⇒ 它们也会看到 TOML 的**数据行**；
L1–L4 因锚定 `#` 而天然只见注释行。⇒ 若要「只看注释」，须给 L5/L6 补锚定（**尚未做**）。

落地方式（文档面）：**文档卫生检查**已实现 D1–D4 + **阳性对照**，挂 `hooks/pre-commit` 与 CI。
⚠️ 它与既有的**文档链接校验**互补：那条判「路径**是否存在**」，本条判「**该不该写路径**」——
前者在去引用之后只会**少检查**、**永不报错**，故守不住本规则。

## 8. 与现有文档的关系

- **上位治理**：语言规范的「注释规范」把本指南确立为强制工程标准（权威摘要 + DoD 在规范，细则在本文）。
- **姊妹标准**：同为规范所治的**测试规范**。二者协和：测试规范要求「写意图」，本指南要求「意图之外不叙事、不引易变外部」。
- **来源依据**：本指南 §0 总纲继承自 spec「行号=软证据、符号名+语义为权威」与「跨文件章节缩减」（证据表亦记「注释 / 编辑会系统性移动行号」）——操作化既有原则，非新增立场。

## 10. 长效文档同规（决策记录正文「零文件级引用」）

> **扩展依据（2026-09-19 裁定）**：§0 的寿命不对称是**通则**，不是「注释专用」。
> 决策记录、规范、指南、参考与注释**同属「持久、慢维护」空间** ——
> 所以「指向快变外部」的耦合在那边以**同样方式**腐化。
> 原规划把范围写成「只处理**代码注释**里的跨文件引用」，**过窄**：它把决策记录留在了门外。
> **实证**：首条决策记录在「门禁全绿」的掩护下留下 9 处会腐烂的引用 + 1 处文件头述旧况 ——
> 绿色只证明**被扫的那部分**干净。

### 10.1 适用范围（按**寿命方向**定域，不按「是不是文档」定域）

| 类 | 例 | 本条是否管 | 为什么 |
|---|---|---|---|
| **结论件** | 决策记录 | ✅ **管** | 纯结论，不含数据、不含版本史 |
| **规则载体** | 本指南 | ✅ **管** | 与结论件同理 |
| **权威源** | 语言规范、语言参考 | ⛔ 不管 | 同级互引是**职责**；登记表里的版本号是**权威数据**，删了即毁证据 |
| **记录件** | 变更记录 | ⛔ 不管 | 版本叙事**就是它的内容** |
| **工作件** | 提案、落地计划 | ⛔ 不管 | 指向过程材料是**本职** |

⇒ 判据是**寿命方向**：**长寿件里不许出现指向短命件的引用**；反向（短命件指长寿件）**合法且鼓励**。
⚠️ 定域若按「是不是文档」一刀切，会同时**误伤**上面三类（实测：全仓文档面命中数以百计，
其中绝大多数合法）并**放过**真正的病根。

### 10.2 规则

与 §2 同表，只是作用面从注释扩到长效文档正文。**判据仍只有一条**：
该引用是否随**对方**文件编辑 / 重命名 / 章节重排 / 行移动而失效？会失效 ⇒ 不许写。

⚠️ 一条**只在文档面出现**的病：**文件头述旧况** —— 正文改了而状态行没改 ⇒ **头在说谎**（已有实测）。
⇒ 改完正文，**回头核头部状态行**。

### 10.3 门禁

| 判据 | 检测式 |
|---|---|
| D1 文档路径 | 反引号包裹的 `.md` / `.toml` 路径 |
| D2 跨文件章节号 | **主题词直接跟** `§N` |
| D3 裸节号 | `§N` 不在**本文已声明节**之内（引用 − 声明 差集） |
| D4 版本号叙事 | `v0.NN` |

域 = **结论件 + 规则载体**。显式豁免见 §7「文档面判据」。

⭐ **D2 与 D3 互补，缺一即漏**（实测实证）：D2 看不见**无主题词的裸节号**；
D3 看不见**目标节号恰好也是本文一节**的跨文件引用（差集把它当成「已声明」放过）。
⇒ **必须取并集**，单独跑任一条都会漏。

⚠️ **判据必须字节安全**：CI 是 ubuntu 容器、locale 可能是 `C` 而非 UTF-8
⇒ 抽取式里**不得出现含多字节字符的字符类**。实测教训：那种写法在字节语义下按**字节数**限距，
同一份文件在本机与 CI 会得出**不同结论**。多字节只作**字面量**出现（字面量按字节比较，两端一致）。
⇒ 验收方式：同一探针在 UTF-8 与 `C` locale 下输出**逐字相同**。

⚠️ **抽取式只能证伪，不能证明**：**扫不到 ≠ 干净**。
故门禁内置**阳性对照** —— 抽取式失灵时**响亮失败**，绝不静默判过。
