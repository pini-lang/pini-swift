## A. 批 2：集合下标三通道（G48 破坏性修订）

### A.1 变更摘要

下标 `a[i]` 由「安全通道，越界返回可空 nil」改为「**安全断言通道，返回元素本身，越界 panic**」；容错与热路径各补一个显式通道。

| 通道 | 形态 | 越界 / 缺键 | 返回类型 |
|---|---|---|---|
| 安全断言 | `a[i]` | **panic**（E5-005 索引越界） | `T` |
| 安全可选 | `a.get(i)` | `Optional.none` | `Optional<T>` |
| 不安全 | `unsafe a.getUnchecked(i)` | **UB**（解释器以「UB 陷阱」E5-006 近似） | `T` |

三类型一致：**Array / Dictionary / String**；**字典缺失键与下标越界同义**。

### A.2 旧 → 新

| 旧写法 | 新写法 | 说明 |
|---|---|---|
| `print(a[i])`（依赖越界得 nil） | `print(a.get(i))` | 需要容错时改通道 2，返回 `.none` |
| `unsafe a[i]!`（剥壳取裸值） | `a[i]` | 下标已直接给元素，`!` 与 `unsafe` 都成了多余 |
| `unsafe m[0]![1]!`（嵌套） | `m[0][1]` | 嵌套下标可直接连写 |
| `match a[i]: case some(v):` | `match a.get(i): case some(v):` | 需要 Optional 参与 match 时走通道 2 |
| — | `unsafe a.getUnchecked(i)` | 新增：已证明界内的热路径 |

### A.3 不变项（不要改）

- **负索引尾部计数**：`a[-1]` 仍为末元素。
- **切片语法**：`a[i:j]` / `a[i:]` / `a[:j]` / `a[:]`、全切片 `a[:]` 与 `[:]` 字面量含义不变。
- **下标写越界**仍报错（不能经赋值扩容器）。
- **match 具名绑定** `case A(x: v):` 的 `:`（见 B 部分，批 3 明确保留）。

### A.4 迁移步骤

1. 机械替换：`]!` → `]`（本轮实测 218 处 / 13 文件，含自举源码 98 处）。
2. 若该处 `unsafe` 仅为许可强制解包而存在 → 一并删除（空 `unsafe` 消费点是**无害**的，但留着会误导）。
3. 依赖「越界得 nil」的地方 → 改 `.get(i)`；依赖 `some/none` 匹配的 → 改 `.get(i)`。
4. 跑 `pini check` + 实跑，逐处确认。

### A.5 会遇到的报错

| 报错 | 触发 | 处理 |
|---|---|---|
| `Type Error [E4-001] type mismatch: expected Optional<T>, got I32` | 容器类型可静态解析时写了 `a[i]!` | 删掉 `!`（及多余的 `unsafe`） |
| `Runtime Error [E5-006]` | 类型不可推断时写了 `a[i]!` | 同上；此路径只在运行时暴露，故必须实跑验证 |
| `Runtime Error [E5-005] index out of range` | `a[i]` 越界（新语义） | 确认是否该改 `.get(i)`；不该容错则修正索引 |

### A.6 边界与已知限制

- **LLVM 端**：通道 1 与运行时一致（`@bk_array_get` 一直 `bk_panic`）；**通道 2/3 未实现**，IR 生成报 unsupported。
- **UB 的表达限制**：解释器无法给出真正的 UB，`getUnchecked` 越界以「未定义行为陷阱」（E5-006）报错近似；调用方证明界内的义务不变。
- **空字典无字面量**：`[:]` 是全切片；用类型构造 `字典<键, 值>()` 取空字典。

## B. 批 3：括号内记法收口——值的注入用 `=`

### B.1 变更摘要（记法原则）

> **`=` = 值的注入方向**（实参标签 / 字典条目 / 元组标签 / 默认参数）
> **`：= 标注与取出方向`**（类型标注 / 块开启 / match 具名绑定）

旧记法在**注入位**被废弃并报错（带迁移提示）。

### B.2 旧 → 新

| 旧写法 | 新写法 | 位置 |
|---|---|---|
| `f(a: 1)` | `f(a = 1)` | 调用实参（含泛型构造 `Name<T>(a = 1)`） |
| `E(x: 1)` | `E(x = 1)` | 枚举具名构造 |
| `["Alice": 30]` | `["Alice" = 30]` | 字典字面量条目 |
| `(a: 1,)` | `(a = 1,)` | 标签元组字面量 |

### B.3 不变项（**不要改**，这些位置的 `:` 仍是 `:`）

- 形参声明与类型标注：`func(n: I32)`、`let y: I32 = 2`、结构体字段 `x: I32`。
- 默认参数：`n: I32 = 1`（类型部分 `:`、值部分 `=`——正是本原则的样板）。
- 块开启：`if c:`、`func() -> ():`（H-4 强制）。
- **match 具名绑定**：`case A(x: v):`（取出方向）。
- 切片分隔符：`a[i:j]`。
- 泛型约束：`func<T: 约束>`（H-2）。

### B.4 迁移步骤（**检查器驱动，勿用盲改正则**）

1. 解析器对三种旧记法报错并给出提示（实测文案）：

   ```
   invalid expression: 实参标签须用 `=`（如 `f(a = 值)`）；旧写法 `f(a: 值)` 已废弃
   invalid expression: 元组标签须用 `=`（如 `(a = 值,)`）；旧写法 `(a: 值,)` 已废弃
   invalid expression: 字典条目须用 `=`（如 `[键 = 值]`）；旧写法 `[键: 值]` 已废弃（`[:]` 为全切片）
   ```

2. 按报错给出的 `file:line:col` **逐点**把 `:` 改写为 `=`，迭代至零报错。
3. 字符串字面量里的 Pini 源码（如自举测试 `parse_expr_text("(a: 1,)")`）检查器**看不见**，须手工改。

### B.5 两个已知的坑（本轮实际踩过）

1. **字典第二条目的报错文案不同**：首个条目报「字典条目须用 `=`」，后续条目报「**字典元素必须是 键 = 值**」。自动化脚本若只认第一条文案，会在改完首条目后提前退出，留下半改文件（如 `[1= "x", 2: "y"]`）。
2. **泛型声明与构造调用文本同形**：`func<T>(x: T)`（声明）与 `Name<T>(x: v)`（构造）长得一样。盲改 sed 会把形参声明改成 `func<T>(x = T)` 而毁掉代码。→ 只改写**不含 `func` / `->`** 的行，并逐文件复核。
