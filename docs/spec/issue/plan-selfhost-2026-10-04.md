# selfhost 自举轨 · 规划总件（唯一入口）

> **本件是什么**：selfhost 自举轨**规划面的唯一入口** —— 承载「目标 · 定标 · 结构 · 路线 · 判据的分层 ·
> 现行施工面 · 止损 · 不做范围 · 待裁」的**结构**，使「我们在哪、为什么走这条路线、下一步有哪些候选」
> 可以**从一份件读到**，⛔ 不必跨四份件拼装。
>
> **本件不是什么**（三条，都是防腐坏的硬约束）：
> ① ⛔ **不记读数** —— 会漂的数（处数 / 条数 / 份数 / 行数 / 墙钟 / HEAD / 分支数）一律只留指针（§9）。
> ② ⛔ **不是判据的定义处** —— 判据正文在判据件；本件只写「有哪几条 + 右端是谁 + 达成态去哪读」。
> ③ ⛔ **不授权开工** —— 每段 / 每批仍须独立点名 + 独立判据 + 变异反证 + 留档。
>
> **承接**：本件是 2026-10-04 的**文档治理整合**产物。此前规划面分散在四份 `plan-selfhost-*` 件里，
> 四件之间以**多条「优先序」声明**互相指认（判据以 A 为准 / 批序以 B 为准 / 段施工以 C 为准 …）
> ⇒ 看整体必须跨件拼装，且**任一件单读都看不到全貌**。本件提供单一入口；
> **四件降为下钻层** —— 其正文**原样保留、不迁不删**，各自件头加一行回指本件。
>
> **读法**：先读 §0（命名）→ §1–§3（目标 / 结构 / 路线），这一遍即能定位「现在在哪」；
> 其余各节按需下钻。⚠️ 本件只写**稳定**内容 —— 你在这里看不到任何具体数字，那是**设计如此**（§10）。

## 0. ⚠️ 先读这一节：三套命名 + 四层判据，⛔ 别混读

> 本轨**同时存在三套分段命名与四层判据编号**，且**彼此不同粒层**。
> 「看不清整体脉络」的一大来源正是它们被混读 —— 尤其 `P2` / `P3` 两个字母在**两套命名里含义不同**。

### 0.1 三套命名（不同粒层，⛔ 不可互推）

| 套 | 出处 | 单位 | 取值 |
|---|---|---|---|
| **档位** | 判据件 | 「编译器对自己能做什么」的阶段 | **S** 种子 → **P1** 自产 → **P2** 自洽 → **P3** 不动点 |
| **演进阶段** | 演进件 | 一条**推进计划**的阶段切分 | **P2-0** 基线 → **P2-1** 清障与自洽 → **P3** AOT 与特性回填 |
| **施工段** | 后端件 | 演进阶段 P3 里 **「CodeGen」那一格**的施工切分 | **段 A** 地基 → **段 B** 扩面 → **段 C** 收口（**段 P** 已撤销） |

⚠️⭐ **三处必须记住的冲突**（前两处是真陷阱）：

1. **`P2` 被用两次**：档位 `P2` = **自洽**（一条判据）；演进阶段 `P2-0` / `P2-1` =
   为达成自洽所做的**前置阶段**（一条计划）。⇒ 同字母、不同粒层，⛔ 不可互推。
2. **`P3` 也被用两次，且含义不重合**：档位 `P3` = **不动点**（再编一次、输出相同）；
   演进阶段 `P3` = **AOT 与特性回填**。⇒ ⛔ **阶段 P3 达成 ≠ 档位 P3 达成**。
3. **施工段 ⊂ 演进阶段 P3**：段 A/B/C 是阶段 P3 里 **CodeGen 那一格**的展开，
   ⛔ 不是整个阶段 P3（阶段 P3 还并行着特性回填）。

### 0.2 四层判据（名字都叫「判据」，⛔ 不可跨层引用）

| 层 | 回答什么 | 定义处 | 形态 |
|---|---|---|---|
| **档位判据** | 档位达成没有 | 判据件 §2 | **M1 自产** · **M2 符合 reference** · **M3 不断链** |
| **段验收判据** | 段 C 达成没有 | 后端件 §3.3 | **C①** 整包 `.ll` 逐字节 · **C②** 整包行为等价 · **C③** 自举自编 |
| **判据形态** | 判据该怎么写 | 后端件 §4.1 | 文本等价 · 行为等价 · 覆盖面双向对账 |
| **器械判据** | **单道门禁**判了什么 | 各器械件头 | 判据① ② …⑫（⚠️ **器械内局部编号**） |

⚠️⭐ **器械判据的编号是局部的**：不同器械各自有「判据①」。
⇒ 跨器械引用**必须指名器械**（例：「**整包面器械的**判据⑧」），
⛔ 单说「判据⑧」在任何一份件之外都无从兑付 —— 这是本轨**最常见的一处指代失效**。

### 0.3 一条读法：判据**分叉**，⛔ 不可合并读
某一条达成**不等于**其余达成（档位三条尤其如此）。
⇒ ⛔ 不得把「P1 已达成」读成「其余各层可停」，也⛔ 不得读成「它们是欠账」——
那些里程碑格是通往**下一档位**的**扩展轨**，每格开工须**独立点名**。

## 1. 目标与定标

### 1.1 目标（一句）
**用 Pini 写 Pini**（自举）。⚠️ 但作业契约（元仓 L0）第一句即写明：
**自举是探针，不是目标** —— 它的价值是**暴露宿主实现（Swift 版）的缺陷**，⛔ 不是「成功运行」本身。

### 1.2 定标（四处 —— 本轨全部判据的右端都由此推出）

| 项 | 定标 | 备注 |
|---|---|---|
| **MVP 落在哪个档位** | **P1 自产** | ⛔ 不宣示 P2 自洽 / P3 不动点 |
| **后端路线** | **LLVM-乙** —— 自举自己发射 `.ll` | ⛔ C 后端已撤销（理由是**工程经济性**，⛔ 不是「做不到」） |
| **宿主发射器的角色** | 降为**规格书 + 判据右端** | ⛔ 不再是运行时的必需件 |
| **验收面** | **L1（替代编译器）** | ⛔ L2（替代运行时）是**独立量级项**，不在本路线内 |

⚠️ **如实登记一条**：L1 达成 ⇒ 产物是**编译级独立、链接级依赖**（仍链宿主运行时的动态库）
⇒ ⛔ 不得读成「零宿主」。

### 1.3 判据的右端：⛔ 不比实现，比权威
右端一律取**分面权威树**（规范 / 语言参考 / IR 契约），⛔ **宿主实现不得作右端**。
⭐ 宿主 CLI 可作**临时观察器械**（现查现取，⛔ 不落成固化期望文件）；
实测到的差异一律走**差异三分归因**（① 自举写错 ② 宿主缺陷 ③ 规范未定）。
⇒ 全文在判据件 §3（本件只记「有这条纪律」）。

⭐ **两处会把人引错文件的坑**（判据件 §3.1 已载，此处只作提醒）：
① 规范件的**形式文法**在它**自己的 §A**，⛔ 不在语言参考 —— 参考里的对应章是**递交去处**，该递交**待完成**；
② 语言参考**只收已「递交」的成熟项** ⇒ 未递交的条款仍在规范侧。

## 2. 结构与站位

### 2.1 三仓（各自独立 git）
- **元仓** = 治理层（契约 / 授权台账 / 机器读数 / 记忆）
- **宿主仓** = Swift 实现 + 语言级规范与计划载体
- **自举仓** = Pini 实现（**嵌套独立仓** ⇒ 有**自己的**门禁职责，⛔ 不在宿主仓门禁内）

⚠️ 三仓**同受**提交纪律约束（元仓 L0 C5）。

### 2.2 自举仓的层（11 层）
前端**十层**已交付（M10 收口）⇒ 缺的**只有发射器**；**第十一层 `codegen`** 即本路线新建的那一层。
⇒ ⚠️ 建该层时**推翻了自举仓两处既有裁定**（「不建 CodeGen 层」「本仓不含 LLVM 后端」）——
那是本路线的**定义性动作**，⛔ 不是副作用，须在交付报告里作为**显式变更**登记。

### 2.3 两条腿（发射器的两种形态）

| 腿 | 形态 | 状态 |
|---|---|---|
| **对齐腿** | **消费 IR 再发射** | ⭐ **本路线**的正统形态（与宿主 FE–IR–BE 架构对齐） |
| **融合式腿** | 走 AST 的同时产文本 | ⚠️ **待退役** —— 它是绕过架构对齐的产物；已裁定**不往上打补丁** |

⚠️⭐ **记「自举侧发射器」必须指名是哪条腿** —— 否则下一批会照着一个指偏的方向去找。
（此条有实测先例，代价是白付一轮。）

### 2.4 一条架构纪律
自举仓**必须**与宿主 FE–IR–BE 架构对齐 ⇒ `codegen` **消费 IR**（融合式 = 偏离）。
⚠️ 成因若落在宿主 ⇒ **修宿主**（⛔ 不另设规避）。

## 3. 路线与站位

```
P2-0 基线 ──▶ P2-1 清障与自洽 ──▶ 演进阶段 P3（AOT 与特性回填）
  ✅ 已达成      ⚠️ 未达（自洽验证）      │
                                        └─ CodeGen 那一格 ──▶ 段 A ✅ ──▶ 段 B ✅ ──▶ 段 C ⛔
```

| 站 | 内容 | 出口判据 | 达成态 |
|---|---|---|---|
| **P2-0 基线** | 速度基准 + 差距对账表固化 | 基线读数件 + 复跑可复现 | ✅ |
| **P2-1 清障与自洽** | 插值（已交付）· 扩展方法格（未做） ⇒ 自洽验证 | **P2 自洽验证**（终端判据） | ⚠️ **未达** |
| **P3 · 段 A** | 发射器地基（模块头 / 类型定义 / 序号器 / 组装骨架） | 最小模块逐字节相同 | ✅ |
| **P3 · 段 B** | 逐节点扩面（按**值的表示法**分六组） | 各组语料逐字节相同 | ✅（**单文件口径**） |
| **P3 · 段 C** | **贯通与收口**（全链入口 / 整包发射 / 对账 / 交付报告） | **C① · C② · C③** | ⛔ **未达** |

### 3.1 站位一句话
**当前站在段 C**；它的**三条验收判据一条未达**。
⚠️ 且 **P2-1 的终端判据（P2 自洽）也未达** —— 两条轨**各有一处缺口**，⛔ 不可互相顶替。

### 3.2 ⚠️⭐ 一条必须记住的读法：**单文件口径 ≠ 整包口径**
段 A / 段 B 的成就是在**单文件口径**下取得的；段 C 要的是**整包口径**。
⇒ 两者差距**不是量，是通道**（跨文件的函数表 / 类型表 / 枚举表）。
⇒ ⛔ **别把「单文件面全绿」读成「段 C 快了」** —— 它们处在**不同难度层**。
（达成态的现读读数去哪取：§9。）

### 3.3 一处结构发现：本路线与「门禁提速」互为因果
「门禁提速」卡在「自举各层两路读数一致」，而那需要**原生臂**；原生臂今天只能由**过渡通道**提供。
⇒ 本路线让自举侧**自己**能出原生码时，那件事才不再依赖宿主的语义完备性。
⚠️ 反向的一条：本路线**自身**的迭代速度受「自举侧跑得慢」限制 ⇒ **两件事共享同一个瓶颈**。

### 5.1 三条验收判据 + 四件拦路物

⛔ 与「行为是否等价」（C②）是**两本账** —— 前者转绿**不含**后者达成。

### 5.2 当前的主要推进方式：「**按族扩面**」
从**降载侧的类型推断**入手，逐族销减判据⑧ 的族。
⚠️ **如实登记代价**：它**加深**「**降载侧绕过 type 层**」这处**最大的架构偏离**；
⛔ 本方式**不是终局形态** —— 终局仍须走**消费 type 层**，且届时这些扩面支应改为**消费**它（否则成冗余）。
⚠️ 另一条路（消费 type 层）今天**不是「更大」而是「无路」**：
它须先有「**节点 → 类型**」的承载，而自举 AST 是**枚举**（无节点身份）⇒ 该承载**今天造不出来**。
