# 提案：比较运算符类型宽度扩展（FFI P2 转正式提案）

- 状态：**§1.3 ①提议 登记（2026-09-04 批 D），待影响评估与裁决**
- 提出方：AI（自 `docs/issue-ffi-module-2026-08-27.md` §三 P2 转出）
- 关联：`docs/issue-ffi-module-2026-08-27.md`（G3 比较宽度缺失）/ ADR-015（FFI 数值边界）

## 动机（指针，不重复论证）

`==` 及比较运算符族现仅支持 I32 操作数；U64 / U8 / 指针（`*T`）比较缺失，
是所有 FFI 数值断言别扭的根因（实测：ffi 场景只能以 `if` + 手工宽度转换规避）。
完整问题记录见 ffi-module 工单 §三 P2 / G3。

## 提议方向（初稿，待影响评估）

比较运算符族（`==` `!=` `<` `<=` `>` `>=`）扩展到 U64 / U8 / 指针，
或引入泛型比较能力。候选路径（②阶段展开）：

- **P-α 逐类型扩展**：`==`/`!=` 先行（等值比较无符号序问题），有序比较随宽度语义钉定；
- **P-β 泛型比较**：协议式 `Comparable` 抽象——依赖类型系统分层能力，前置重；
- **P-γ 指针等值**：仅 `==`/`!=` 对 `*T`（地址等值），无序关系（回避 UB 面）。

**约束**：

- 无符号序比较的语义（U64 与 I32 混合操作数）必须在设计期钉定，不得隐式转换；
- 指针关系比较（`<` 于地址）默认排除（v1），如需须显式裁决；
- 不得变更现有 I32 比较语义。
