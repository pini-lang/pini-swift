## 动机（指针，不重复论证）

1. **ADR-026 修订（2026-08-30）**：`append` 返回 `Array<Any>` 是 ADR-020 登记的签名契约，不是缺陷；
   语言**没有数组元素标注语法**，`var xs = []` 起步的累积器**本无元素类型可供传播**。
   9e54e27 回退的教训是「不要从用法中发明元素身份」——正确路径是**独立语言特性提案**：
   显式声明元素身份，另行排期。
2. **G-P2 清账前提**：bootstrap-gap-remediation 收口修订载明，G-P2（typed append）
   的彻底清账以本提案落地为前提；当前 `[Any]` 累积 + 消费点 match 解构为契约下的惯用法
   （自举侧登记 `MITIGATED-BY-DESIGN`）。

## 影响评估（2026-09-04 批 D，实测核验）

**解析层现状（比提案登记时的预期乐观）**：`[T]` 标注解析**已完整存在**——
`Parser.parseTypeAnnotation` 对 `[I32]` 产出 `Array<I32>`、`[K: V]` 产出 `Dictionary<K, V>`、
`{T}` 产出 `Set<T>`（三族齐备）；`var xs: [I32] = []` 现已可解析、可运行。

**语义层缺口（实测）**：元素类型**不参与**成员方法签名——

- `append` 返回**新数组**（须 `xs = xs.append(1)` 接收，实测 `[1]`）；签名恒为 `[any]`（ADR-020）；
- `pop` 返回 `(剩余数组, 弹出值)` tuple（实测空数组 `[[], null]`、`[7]` 上 `[[], 7]`）；弹出值无类型检查；
- `数组<I32>()` 泛型构造调用未实现（实测 `invalid operation: 未定义的泛型类型: 数组`）。

**记法形态对比（D-α 裁决依据）**：

| | 形态 A：`[T]` 标注（声明位） | 形态 B：`[I32]()` 构造（表达式位） |
|---|---|---|
| 解析层 | **已存在**（三族齐备，实测可运行） | 不存在 |
| 歧义 | 无（标注位 vs 值位分离） | **`[I32]` 在表达式位已是合法数组字面量**（实测报 E5-001 undefined variable 'I32'——被当单元素字面量解析） |
| 实现面 | 仅补语义检查层 | 须先解决字面量歧义（上下文消歧或换记号）+ 新造类型构造器语义 |
| 语法卫生 | 符合 | 视觉近似形式，原则性风险 |

## 裁决（2026-09-04 批 D，用户）

- **D-α 记法形态**：**形态 A（`[T]` 标注）采纳**；形态 B（`[I32]()` 构造调用）**否决**
  （与数组字面量歧义、收益与 A 重复）。
- **D-β 契约关系**：**标注仅做检查，ADR-020 签名契约不动**——`append` 返回新数组、
  `pop` 返回 tuple 的契约保持；标注约束字面量初始化 / 赋值 / `append` 参数的元素类型检查。
  特化（随标注改签名）被否决；G-P2 清账 = 「标注提供显式元素身份 + 契约惯用法保持」。
- **实施边界**：本裁决仅钉定设计；语义检查层实现另立实现批次排期。

## 提议形态（裁决后定稿）

`var xs: [I32] = []`（声明位标注，复用既有 `Array<T>` 解析）。

**约束**（承 ADR-026 修订，裁决后仍有效）：

- 元素身份必须**显式声明**，不得从用法推断（重蹈 9e54e27 / D4 覆辙即否决）；
- ADR-020 `append` 签名契约**保持**（D-β 裁决）：内建签名不随元素标注特化；
- 空字面量 `[]` 的类型推断规则不得隐式变更现有程序语义（检查失败报错，不静默改推）。
