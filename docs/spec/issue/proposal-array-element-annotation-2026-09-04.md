## 动机（指针，不重复论证）

1. **ADR-026 修订（2026-08-30）**：`append` 返回 `Array<Any>` 是 ADR-020 登记的签名契约，不是缺陷；
   语言**没有数组元素标注语法**，`var xs = []` 起步的累积器**本无元素类型可供传播**。
   9e54e27 回退的教训是「不要从用法中发明元素身份」——正确路径是**独立语言特性提案**：
   显式声明元素身份，另行排期。
2. **G-P2 清账前提**：bootstrap-gap-remediation 收口修订载明，G-P2（typed append）
   的彻底清账以本提案落地为前提；当前 `[Any]` 累积 + 消费点 match 解构为契约下的惯用法
   （自举侧登记 `MITIGATED-BY-DESIGN`）。

## 提议形态（初稿，待影响评估）

数组类型标注扩展为元素显式形态，例如 `var xs: [I32] = []` 或 `var xs = [I32]()`
（具体产生式在 ②影响评估阶段定，本提案仅登记意图与约束）。

**约束**（承 ADR-026 修订）：

- 元素身份必须**显式声明**，不得从用法推断（重蹈 9e54e27 / D4 覆辙即否决）；
- 与 ADR-020 `append` 签名契约的关系（内建签名是否随元素标注特化）须在影响评估中裁决；
- 空字面量 `[]` 的类型推断规则不得隐式变更现有程序语义。
