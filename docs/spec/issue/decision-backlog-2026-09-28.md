### 待决 1 —— 段六的判据：按「规范 §2.7 白名单」写，还是按「宿主实现实际放行」写

**① 这件事是什么**（编号先展开：段六 = 类型层七段里的第六段「FFI 与指针面」；§2.7 = 规范件
`docs/spec/pini-spec-v0.md` 的第 2.7 节「FFI 与 unsafe」）

规范 §2.7 的「FFI 类型白名单（顶层签名）」里有一列叫「**永远禁止**」，明写四样东西不得出现在
`[名称|foreign]` 块的顶层参数与返回类型上：**对象（object，含含 object 字段的复合类型）、
`String`、`Optional`、`Result`**。

而宿主实现里那个函数（`Sources/PiniCore/Type/TypeChecker.swift` 的 `checkFFITopLevelType`，
1450–1485 行）实测是**放行**的：它先判「是不是引用类型（含内建 `String` 等）」，是就 `return`
（放行，注释写「仅 shim 可承载」）；末尾对「其它已知用户类型（枚举等）与未知简单名」也 `return`。

⇒ 同一件事，规范说「禁止」、实现说「放行」。段六要写「顶层签名该不该报红」这条判据时，
**必须选一边**，两边不能都写。

**② 为什么现在要决定**：段六的**下一步就是起点实测 + 落语料**，而判据 ⑥（foreign 顶层签名白名单）
是十来条判据里**唯一**一条两侧读数相反者。晚一步决，就得先写两版语料再删一版。

**③ 各选项做什么、代价是什么**

上一批的收口记录里已写着：本批起点实测要含「**连带宿主修复的判定**」，口径是

   本轨的定式是「**阻塞才修**」（严重性 ≠ 阻塞性，实例见 `L0` D2）。
2. ⭐ **一次只推进 ≤ 3 项**（本件第一部分即如此）。其余项在**它们成为下一格的前置**时才该决，
   ⛔ 提前裁会失去届时的实测依据（本仓已多次实证：计划期的读数会被开工时的实测翻转）。
