# 草稿审计（A1–A14）成批处置方案

- 状态：**方案待认可**（2026-08-31）。承接 `issue-draft-impl-syntax-audit-2026-08-28.md`
  「处置选项（待拍板）」。
- 背景：A1–A14 单项繁多，逐项请示成本高于给一套**分类默认规则**。本文件给出规则与逐条
  落位，认可规则即等于处置全部条目；任何一條可单独改判。
- 权威序（用户指示）：**spec > 草稿意图 > 实现现状**；草稿小于 spec，但**遇困惑时应参考
  草稿意图**。冲突时按此序判定，不逐条重新发明原则。

## 一、分类默认规则

| 类别 | 判据 | 默认处置 |
|---|---|---|
| **R-a 草稿订正** | 草稿与 spec/实现冲突，且 spec/实现为**长期事实**（已成语义、改动成本高） | 订正草稿文本并记勘误；若 spec 复制了草稿错误，**连带订正 spec** |
| **R-b 特性提案** | 草稿意图明确，实现**尚未支持**，且无 spec 条款 | 登记为 **Provisional 特性提案**（不实现、不删除），随路线图排期 |
| **R-c 实现缺陷** | 实现行为**自相矛盾**或给出错误诊断（与草稿/spec 意图均不符） | 单列缺陷修复工单，不归入草稿订正 |
| **R-d 治理** | 事实源本身的管理状态问题 | 治理动作（入库/跟踪） |

补充规则：

- **草稿内部自相矛盾**时，取「与实现一致且与草稿多数表述一致」的一侧，另一侧记勘误；
- **内建清单**以宿主 `BuiltinRegistry` 为唯一事实源（ADR-020 D3/D4），草稿与 spec 均向其对齐；
- 判为 R-b 的条目**不等于废弃**——它保留草稿意图，只是排期在后。

## 二、A1–A14 逐条落位（按默认规则）

| A4 | 草稿含 `cancel`/`join`，宿主无（有 `isCancel`/`joinAll`/`joinWithin`） | R-a | 订正草稿为宿主实际内建名 |
