## 1. 设计规矩（本件自守的四条）

1. **一例一事** —— 不把「新语法 + 异步 + 跨模块」塞进一个例子；需要三件事就写三个例子。
2. **输出必须证明语义** —— 禁止 `print("运行成功")` 式占位（`examples/README.md` 明令禁止）。
   例 1 用「跨调用累积」证明单例，例 2 用「该出现的没出现」证明惰性。
3. **除新语法外，每一行都必须是今天的合法写法** —— 靠等价体实跑兑付，不靠阅读。
4. **不落 `examples/`，直到给定块有实现** —— 落点见本件末尾的待裁点。

## 2. 已裁前提（用户裁定，2026-09-19）

| # | 裁决 | 对示例的后果 |
|---|---|---|
| **D1** | 语言字段默认可变；**给定块字段不可变**（≈ `static let`）；**函数参数确定不变** | 给定块**不能自持可变状态**。队列、缓存、连接池这类「可变」全靠字段所引用的 `object` 承担 —— 字段本身只是不可变的名字 |
| **D2** | `main` 是惯例入口，**不带参数** | `main` 不能声明 `using`。取用给定块须经顶层函数，或经类型名直接访问 |
| **D3** | 给定块是**常量复合类型**，`\|own` 与 enum 扩展块的 `\|own` 一致（类型级） | 示例只演示 `\|self`（单例实例方法）；`\|own` 的取用通道另裁 |
| **D4** | 示例由本件设计 | —— |

> **D1 是本次最重的修正**。上一版草案里我写过 `self.元素 = self.元素 + 数据` 这类**直接改给定块字段**的写法，
> 按 D1 该写法**不成立**。本件所有可变状态一律收进 `object` 字段。

## 3. 示例

### 例 1 · 声明与取用（正典）— `given.pini`

```
; 演示：给定块（程序级单例）的声明、扩展与 using 取用
; 侧证：状态跨调用累积 —— 两次调用得到 1 和 2，证明是同一个实例
; 运行：pini run examples/given.pini
; 预期：1 / 2

[队列|object]
元素: [I32] = []

{{队列}}
推入|self(数据: I32,) -> ():
    self.元素 = self.元素.append(数据)
    return

[应用服务|given]
队列: 队列 = 队列()

[[应用服务]]
提交|self(数据: I32,) -> (I32,):
    self.队列.推入(数据)
    return len(self.队列.元素)

处理|func(using 应用: 应用服务, 数据: I32,) -> (I32,):
    return 应用.提交(数据)

main|func() -> ():
    print(处理(1,))
    print(处理(2,))
    return
```

**这一例演示三件事**：块头 `[名|given]`、扩展块 `[[名]]`、参数修饰符 `using 名: 类型名`。

**新语法只有三处**：`|given`、`|given` 块的字段、`using` 参数。`队列` 是普通 `object`，其余每一行都是现行写法。

**关键点**：`元素` 的可变发生在 `队列`（一个 `object`）里，**不在**给定块字段上 —— 这正是 D1 的形状。

**等价体实测**（`given` → `object`、`using` → 显式传参）：

```
[队列|object] 元素: [I32] = []
[应用服务|object] 队列: 队列 = 队列()
处理|func(应用: 应用服务, 数据: I32,) -> (I32,):
    return 应用.提交(数据)
main|func() -> ():
    let 服务 = 应用服务()
    print(处理(服务, 1,))
    print(处理(服务, 2,))
```

```
check OK
run → 1
      2
```

### 例 2 · 惰性：未访问不构造 — `given-lazy.pini`

```
; 演示：给定块在首次访问时才构造；从未访问者从不构造（无启动风暴）
; 侧证：「审计：已打开」不出现 —— 该块从未被访问
; 运行：pini run examples/given-lazy.pini
; 预期：main 结束

打开|func() -> (I32,):
    print("审计：已打开")
    return 1

[审计|given]
句柄: I32 = 打开()

main|func() -> ():
    print("main 结束")
    return
```

**输出只有一行 `main 结束`**，就是全部证据。「审计：已打开」的缺席 = 字段初始化器没被执行 = 该块没被构造。

**反向兑付**：把 `main` 改成读 `审计.句柄`，输出变成「审计：已打开」在前、`1` 在后 —— 两个方向的等价体都实跑过。

**等价体实测**：

```
未访问版 run → main 结束
已访问版 run → 审计：已打开
               1
```

### 例 3 · 给定块依赖给定块 — `given-dependency.pini`

```
; 演示：给定块字段引用另一个给定块；初始化顺序由依赖决定
; 侧证：「存储：已建连」在 42 之前出现 —— 依赖被先行构造
; 运行：pini run examples/given-dependency.pini
; 预期：存储：已建连 / 42

建连|func() -> (I32,):
    print("存储：已建连")
    return 42

[存储服务|given]
连接: I32 = 建连()

[[存储服务]]
读|self() -> (I32,):
    return self.连接

[应用服务|given]
存储: 存储服务 = 存储服务

[[应用服务]]
读|self() -> (I32,):
    return self.存储.读()

取用|func(using 应用: 应用服务,) -> (I32,):
    return 应用.读()

main|func() -> ():
    print(取用())
    return
```

**等号右边 `存储服务` 是「类型名当值」** —— 它不构造新实例，就是取那个单例。这是本例唯一的额外新机制
（`given` 版 `存储服务` ↔ `object` 版 `存储服务()`）。

**等价体实测**：

```
[应用服务|object] 存储: 存储服务 = 存储服务()
main|func() -> ():
    print(取用(应用服务()))
```

```
check OK
run → 存储：已建连
      42
```

### 例 4 · 对照：参数传染 vs 取用（对照用，**不进** `examples/`）

这一例是 ADR「为什么要有 `using`」的论证材料，不是可运行示例 —— 它演示的是**两段代码的差**，不是某个运行时行为。

```
; 不用 given —— 资源实例逐层传递：每一层签名多一个参数，每个调用点多一个实参

记账|func(服务: 应用服务, 数额: I32,) -> ():
    服务.日志.写(数额)
    return

汇总|func(服务: 应用服务,) -> ():
    记账(服务, 1,)
    记账(服务, 2,)
    return

main|func() -> ():
    汇总(应用服务())
    return
```

```
; 用 given —— 签名只声明来源，调用点不传

记账|func(using 服务: 应用服务, 数额: I32,) -> ():
    服务.日志.写(数额)
    return

汇总|func(using 服务: 应用服务,) -> ():
    记账(1,)
    记账(2,)
    return

main|func() -> ():
    汇总()
    return
```

**差别恰好是**：`服务` 从**每一层签名**里消失，且每个**调用点**不再传它。`main` 里的 `应用服务()` 也消失 —— 这是 D2
（入口不带参数）与单例取用共同的结果。

**左栏等价体实测**（右栏是左栏去掉 `服务` 参数，等价体即左栏本身）：

```
check OK
run → [app]
      [app]
```

## 4. 哪些行依赖尚不存在的机制

把示例拆开，逐行标出「今天成不成立」，免得把三样东西混成一样：

| 写法 | 出现在 | 今天的实测结果 | 性质 |
|---|---|---|---|
| `using 名: 类型名` 参数 | 例 1/3/4 | `E2-005`（与不认识的修饰符同码） | **新语法** |
| `[名\|given]` 块头 | 例 1/2/3 | `E2-005`（同上） | **新语法** |
| `[[名]]` 扩展块 | 例 1/3 | 现行合法，按类型名挂载 | 照抄 ✓ |
| `名.字段`（类型名当值） | 例 3 | `E6-004 不支持的特性` | **新机制** |
| `main\|func() -> ()` | 全部 | 现行合法 | 照抄 ✓ |
| `[名\|object]` + 字段 + `{{名}}` | 例 1/4 | 现行合法 | 照抄 ✓ |

> 补充实测：给定块的扩展块**不需要新语法**。现行扩展块按类型名挂载、**不校验目标种类** ——
> `[[句柄]]` 挂在 `[句柄|object]` 上实跑通过，且同一目标可并挂 `[[X]]` 与 `{{X}}`。
> 这同时钉住一件事：给定块的扩展块**用哪个括号**都行，选择属风格问题，不是语法问题。

## 5. 待裁点（含本轮新照出的两条）

### 5.1 类型名当值（例 3 的硬前提）

例 3 的 `存储: 存储服务 = 存储服务` 要求：**给定块名出现在表达式位时解析为该单例**。
今天不支持（`E6-004`）。而 D2 说 `main` 不带参数，于是它同时是**入口侧取用给定块最自然的通道**。

需要裁的是**范围**：类型名当值是只对给定块开放，还是对所有复合类型开放（那会牵动 enum/object 的既有语义）？

### 5.2 给定块字段不可变的强制方式（D1 的落地）

D1 已裁字段不可变，但没裁**怎么表达**。现有 `field-decl` 产生式是 `IDENT ':' 类型 ['=' 表达式]`
—— 没有 `var`/`let` 修饰位，字段语法上无标记。两种落法：

- **A · 块种类隐含**：`|given` 块内字段天然不可变，不写修饰符。代价：同一产生式在两种块里语义不同。
- **B · 显式修饰**：给定块字段写 `let 元素: ...`。代价：给字段产生式新增修饰位，语法面变宽。

⚠️ 无论取哪种，**给不可变字段赋值必须报错**（对照：`let a = 1; a = 2` 今天报 `E4-010`）。
这条负向用例是 D1 的兑付判据，示例落地时应一并写。

### 5.3 函数参数「确定不变」与实现不符（本轮新照出）

D1 说函数参数确定不变，但**实测参数可变**：

```
处理|func(x: I32,) -> (I32,):
    x = 5          ; ← 未报错
    return x

main|func() -> (): print(处理(1,))
→ check OK，run → 5
```

对照：`let a = 1; a = 2` 报 `E4-010`。⇒ 参数不可变这条规则**在实现里不存在**。
本件按 D1 的意图写示例（不重新赋值参数），但**规范与实现的这处不一致须单独记账**。

### 5.4 `|own` 在给定块的取用通道（D3 的余项）

D3 裁 `|own` 与 enum 语义一致（类型级）。但给定块只有一个实例，`|self`（实例级）与 `|own`（类型级）
指向的是同一个东西 —— 需要说明：

- 两者可访问的成员是否相同？（enum 的 `|own` 摸不到实例字段，给定块若照搬则 `|own` 方法摸不到任何字段）
- 若相同，`|own` 带来的是什么？（是「不经过单例实例」的语义，还是仅书写位置的区别）

本件示例只用了 `|self`，此点不影响示例成立。
