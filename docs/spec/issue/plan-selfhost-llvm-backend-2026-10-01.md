> **授权**：本件由 `auth-78`（元仓授权台账）点名制定；⛔ **本件不授权开工** —— 每段开工仍须独立点名 +

## 0. 一句话

**让自举编译器自己把自举 IR 发射成 `.ll`** —— 宿主发射器从「**运行时的必需件**」降为「**规格书与判据右端**」。

⭐⭐ **口径（最高优先，压过本件其余各节）**：做的是**自举 MVP 的 `.ll` 发射**，
⛔ **暂不做完整特性版本的 `.ll` 发射**。两者的差别**全在发射面**：

| | 发射面 | 节点数 |
|---|---|---|
| ⭐ **本路线（MVP）** | 自举源码**实际用到的** IR 节点 = **自举切片**（§1.3） | **40**（类型 11 + 表达式 18 + 语句 11） |
| ⛔ **不做**（完整特性版） | 契约**全量**节点面 | 21 + 46 + 17 = **84** |

⇒ **划出面**（Optional / 闭包 / object / 下标 / 字典 / 指针 / 惰性引用 / 并发 / 泛型 / 逻辑运算符）
**整体不在本路线内**（§6 第 7 条）—— 它们随**特性回填**推进，**那时才进发射面**。
⚠️ 判据因此**只需在切片上成立**；⛔ 不按契约全量节点面设判据、⛔ 不按宿主发射器的全量面设判据。

⭐ **首段**（§3.4）**不依赖**装配通道的函数表 · 不依赖宿主仓改动 · 不依赖运行时替换 ——
是一段可以立即起步、且判据右端**现成**的贯线。

## 1. 事实基础

### 1.1 改道的缘由（⭐ 按用户原话口径，⛔ 不写成「技术阻断」）

| # | 用户原话（2026-10-01） | 本件的读法 |
|---|---|---|
| ① | 「此语言的特性对于 C 后端来说过于高级，需要的工程量很大，对于自举 MVP 来说不是一个近期目标」 | **工程经济性判断**：C 路线的成本 = 一份**第三实现**（C 运行时 + C 粘合 + C 发射器）的长期维护 |
| ② | 「改道到 LLVM-乙，以**能产生二进制演进载体替代宿主**为目标」 | 目标 = 自举自己发射的 `.ll` 经 LLVM 编出**可编译下一代自举源码**的二进制 |
| ③ | 「把已落件去掉，另立 LLVM IR 后端规划」 | 本件 = 该规划的载体 |

⚠️ **必须如实登记的一条**：C 路线**不是被技术实测推翻的** —— 撤销前最后一次实测，其前置全部通过

⇒ **撤销的理由是成本与近期性，不是「做不到」**。⛔ 将来重读本件时不得把这条读反。

⚠️ **同时撤销的动作**（2026-10-01，用户同批指令）：C 后端规划件（`plan-selfhost-cbackend-*`）与其三处
指针回填已从两仓**未提交改动中撤销**，授权条目 `auth-77` 改判终止。⇒ 本件是**唯一**的后端路线载体。

**自举侧**：前端**全交付**（`common` / `lexer` / `ast` / `parser` / `desugar` / `semantic` / `type`（七段）/
`module` / `IR` / `interpreter`；M10 收口 2026-09-30）。⇒ 缺的**只有发射器**。

**甲路线**（宿主发射器吃自举 IR）：

| 项 | 读数 |
|---|---|
| 链路 | ✅ **通** —— 自举整包经宿主 `emit` → `clang` → 原生二进制；未定义符号**零缺口** |
| 三道前置 | ✅ **全清** —— B 组字符语义（`auth-74`）· 名义箱寿命（`auth-75`）· 切分分配与入口门禁（`auth-76`） |

### 1.4 规格面：宿主发射器 = **规格书 + 判据右端**

| 件 | 规模（2026-10-01 现读） | 在本路线中的角色 |
|---|---|---|
| `Sources/PiniCore/CodeGen/IREmitter.swift` | 5507 行 / **119 个函数** | ⭐ **规格书**：逐节点的发射算法（含顺序与命名） |
| `Sources/PiniCore/CodeGen/IRBuilder.swift` | 140 行 | ⭐ **逐字节稳定的关键**：temp / label **全局唯一编号源**与 padded 行格式 |

| `Sources/PiniCLI/main.swift`（`runCompileCommand` / `runLLICommand`） | — | **构建配方**（见 §1.5） |

⭐ **本路线相对 C 路线的根本差别**：那是一份要从零**设计**的产物（含自定所有权契约的运行时）；
这是一份**已存在且已在用**的发射算法 —— 工程性质是**移植**（可逐函数对照、可增量推进、每步有机械判据）。

### 1.5 运行时面与「替代宿主」的分层口径

**构建配方**（`runCompileCommand` 现读）：

```sh
clang -o <bin> -L<dir> -lPiniRuntime -Wl,-rpath,<dir> <ir.ll>     # dir = libPiniRuntime.{dylib,so} 所在目录
```

`libPiniRuntime` = `@_cdecl` 暴露 C ABI 的**动态库**（`Sources/PiniRuntime/`，76 处导出）。`.ll` 里的
`declare` 由发射器按用量**条件发出**。

| 层 | 「替代宿主」到哪 | 状态 |
|---|---|---|
| **L1 · 替代宿主的编译器** | 前端（已有）+ **发射器**（本路线）⇒ 自举自己产的 `.ll` 能编出可运行的二进制 | 本路线目标 |
| **L2 · 替代运行时** | `libPiniRuntime`（Swift 实作）换成自举链自产 | ⛔ **独立量级项**，不在本路线内（见 §6.2） |

⚠️ **L1 达成时依赖仍在**：产物是**编译级独立**（不再需要宿主编译器），但**链接级依赖** `libPiniRuntime`。
⛔ 不得把 L1 读成「零宿主」。本件**不宣告**任何一层的完成 —— 宣告权在交付报告。

### 1.6 三条对 C 路线有利、对 LLVM 路线**同样锁定**的语言面事实（承自已撤的 P 段普查）

⚠️ 该普查的载体随 C 规划件撤销 ⇒ **本件为唯一载体**。三读数与后端无关（是语言面事实）：

1. **内建面很小**：自举源码的内建用量 —— `print` 883 · `len` 180 · `readFile` 32 · `argv` 12 · `listDir` 4
   （⚠️ 后者的件内注释称「零用量」，实为 `module` 层在用 ⇒ 该注释已过期，登记不修）。
2. **字素面不触发**：178 份 `.pini` 的字符串字面量里，**组合标记（Mn/Me）= 0 · ZWJ / 格式字符 = 0**，
   非 ASCII 全是单码点汉字 ⇒ 按**码点**实现与按**字素簇**实现，在**现有语料**上等价。
   ⚠️ 这不是「字素簇语义可以不做」—— 语义由契约钉死（§2.22 等已由 `auth-74` 在 LLVM 侧对齐）；

3. **`listDir` 的注释过期**已登记（属注释卫生，非缺陷）。

## 2. 目标与定位

### 2.1 目标（一句话）

**自举编译器吃自举 IR，自己发射 `.ll`**（⚠️ **MVP 切片口径**：只覆盖自举源码用到的 **40 节点**，见 §0）；
该 `.ll` 经 LLVM 工具链编出的二进制，**能编译自举源码自身**（自举链闭合 = 「二进制演进载体」，用户裁定②的目标）。

### 2.2 为什么 LLVM-乙 可行（四条，⛔ 不是偏好）

1. **规格现成**：宿主发射器是逐函数可对照的规格书（§1.4）⇒ 工程是**移植**，不是设计。
2. **判据右端现成**：宿主 `emit` 对**同一份源**的输出即右端，**可机械比对到逐字节** ——
   ⛔ 无需另建期望文件，也⛔ 不依赖「自举各层行为一致」那类弱读数。
3. **不新增运行时**：`.ll` 引用的 `bk_*` 是**共用层**（§1.5）⇒ 与 C 路线不同，本路线**不引入第三份实现**。
4. **链路已验**：甲路线已实证「自举 IR → `.ll` → clang → 二进制 → 运行」的每一跳（§1.2）。

⚠️ **如实交代代价**：复杂度**没有消失，是搬了家** —— 从「运行时」搬到「发射器」，
且发射器的**正确性由右端（宿主）定义** ⇒ 宿主发射器的缺陷会被**一并继承**（这是**移植**的固有代价，
见 R5）。收益在于：那些缺陷在甲路线上已被逐个暴露与修复（`auth-73` / `76` 共修四处）。

### 2.3 与相邻路线的关系

| 相邻 | 关系 |
|---|---|
| **甲路线**（`auth-73`） | 它是**过渡期通道**，也是本路线的**加速器**（规格 + 右端）。⛔ 本路线不撤销它的过渡许可；⭐ 本路线达成后它可退役，但**不是立刻**（覆盖面追平前它仍是唯一能出原生码的通道） |
| **P2 装配通道** | ⭐ **共用前置**（跨文件函数表）：P2 终端判据要它，本路线的**整包发射**也要它 ⇒ 一处投入、两处受益。⛔ 首段与逐节点扩面**收单文件口径**（§3.4） |
| **自举侧内存缺陷族** | ⛔ **另一族，未修**（§1.2）⇒ 它是本路线的**地基风险**（R1），⛔ 不属本路线范围 |
| **特性回填**（插值 / 逻辑运算符 / 闭包 / 泛型 / 指针） | 覆盖面受 **IR 切片**限制（§1.3）；逐节点扩面与特性回填**并行但不同批**（避免判据混合） |
| **宿主仓语义** | ⛔ 不改。若某步证明**必须**改 ⇒ **停下登记**，照甲路线先例另立条目 |

### 2.4 风险面（本路线会撞上的五堵墙）

| # | 风险 | 为何是墙 | 本规划的处置 |
|---|---|---|---|
| **R1** | **自举侧内存缺陷（非确定性）** | 发射器**跑在自举运行时上** ⇒ 上游不稳会把「发射器写错」与「运行时抖动」混成同一种红 | 首段与逐节点扩面收**最小语料**；每批判据先跑**重复性探针**（同输入多次 ⇒ 同输出）；缺陷修**另立条目**（止损 S4） |
| **R2** | ⭐ **`E6-004` 形态敏感缺陷** | `entry-ir.pini` 件头明写：自举侧的「**事后遍历自造 IR 链表 + 字段访问**」形态在宿主上**一绿一红、不可预测**。⚠️ 而发射器**必须**构造并遍历 IR（要模块级收集类型/全局，不能纯流式） | 段 P 的**可行性预验**（§3.0 ②）：用最小探针量「发射器要用的形态」在宿主上是否可跑；⚠️ 若不可 ⇒ 停，**它是宿主缺陷**（另族） |
| **R3** | **逐字节相同的可达性** | 编号 / 命名 / 顺序 / 空白 —— 任一处差一个字符即红 | 首版**照抄**宿主算法（含 `IRBuilder` 的编号语义）；若证明某处**不可能**相同 ⇒ 停，先证明再谈降级（止损 S2） |
| **R4** | **迭代速度** | 自举侧跑在双层解释上（量大、启动固定成本高）⇒ 发射器的每次迭代都贵 | 右端（宿主 `emit`）随时可跑、**零成本**；左端迭代**收小语料**；⭐ 「门禁提速」与本路线**互为因果**（见 §2.5） |
| **R5** | **移植继承宿主缺陷** | 右端本身可能有缺陷（`auth-73`/`76` 共修四处：命名撞名 ×2 · 顺序 ×2 · 分配 ×2） | 移植**带修后的形态**（右端 = 当前树，⛔ 不是历史版本）；⚠️ 宿主侧未来若再修 ⇒ 自举侧须同步（登记为**同步义务**） |

### 2.5 ⭐ 一处结构发现：本路线与「门禁提速」互为因果

「门禁提速」卡在「自举各层两路读数一致」，而那需要**原生臂**；原生臂今天只能由**甲路线**提供。
⇒ **LLVM-乙 不是「门禁提速」的替代路径，而是它的下游**：本路线让自举侧**自己**能出原生码，
那时「门禁跑原生臂」不再依赖宿主发射器的语义完备性。

⚠️ 反向的一条：本路线**自身**的迭代速度受「自举侧跑得慢」限制（R4）⇒ **两件事共享同一个瓶颈**，
但⛔ **不得**把「修内存缺陷」写进本路线（R1 的处置已把边界划死）。

  层表 + 树形 + marker（⛔ 三处缺一即红）。
- **③ 各选项**：
  - **甲（推荐）**：自举侧 `src/codegen/` **新层**（第 11 层）。同批改：`boundaries.md` §1 层表 + §2 树形 +
