# 自举 LLVM IR 后端 · 实现规划

> **本件是什么**：把「自举编译器 → 原生码」这一跳，从「**借宿主发射器**」换成「**自举自己发射 `.ll`**」——
> 承载**目标 · 起点 · 分段 · 判据骨架 · 止损点 · 不做范围 · 待裁**。
> ⛔ 不复述语言规范、IR 契约与自举判据件的正文（那些各自有主，本件只留指针）。
>
> **出身**：① 2026-10-01 用户三项裁定（见 §1.1）② 二期件（`plan-selfhost-evolution-2026-09-30.md`）
> 的 P2 → P3 路线 ③ 同日甲路线实测（`selfhost-aot-gate-report-2026-10-01.md`）与其三道后续专项
> （`auth-74` / `75` / `76` 的交付报告）。
>
> **授权**：本件由 `auth-78`（元仓授权台账）点名制定；⛔ **本件不授权开工** —— 每段开工仍须独立点名 +
> 独立判据 + 变异反证 + 留档（与二期件、判据件同一纪律）。
>
> **分工**：路线**批序**以二期件为准；**判据**以判据件（`plan-selfhost-criteria-2026-09-30.md`）为准；
> 本件只在「LLVM IR 后端」这一段内展开施工面。冲突时按此序判。
>
> **读法**：§1 的事实为 2026-10-01 现读/实测。⚠️ **数字会漂，用前重测**（会漂的读数一律只留指针）。

## 0. 一句话

**让自举编译器自己把自举 IR 发射成 `.ll`** —— 宿主发射器从「**运行时的必需件**」降为「**规格书与判据右端**」。

⭐⭐ **口径（最高优先，压过本件其余各节）**：做的是**自举 MVP 的 `.ll` 发射**，
⛔ **暂不做完整特性版本的 `.ll` 发射**。两者的差别**全在发射面**：

| | 发射面 | 节点数 |
|---|---|---|
| ⭐ **本路线（MVP）** | 自举源码**实际用到的** IR 节点 = **自举切片**（§1.3） | **40**（类型 11 + 表达式 18 + 语句 11） |
| ⛔ **不做**（完整特性版） | 契约**全量**节点面 | 21 + 46 + 17 = **84** |

⇒ **划出面**（Optional / 闭包 / object / 下标 / 字典 / 指针 / 惰性引用 / 并发 / 泛型 / 逻辑运算符）
**整体不在本路线内**（§6 第 7 条）—— 它们随**特性回填**推进，**那时才进发射面**。
⚠️ 判据因此**只需在切片上成立**；⛔ 不按契约全量节点面设判据、⛔ 不按宿主发射器的全量面设判据。

⭐ **首段**（§3.4）**不依赖**装配通道的函数表 · 不依赖宿主仓改动 · 不依赖运行时替换 ——
是一段可以立即起步、且判据右端**现成**的贯线。

## 1. 事实基础

### 1.1 改道的缘由（⭐ 按用户原话口径，⛔ 不写成「技术阻断」）

| # | 用户原话（2026-10-01） | 本件的读法 |
|---|---|---|
| ① | 「此语言的特性对于 C 后端来说过于高级，需要的工程量很大，对于自举 MVP 来说不是一个近期目标」 | **工程经济性判断**：C 路线的成本 = 一份**第三实现**（C 运行时 + C 粘合 + C 发射器）的长期维护 |
| ② | 「改道到 LLVM-乙，以**能产生二进制演进载体替代宿主**为目标」 | 目标 = 自举自己发射的 `.ll` 经 LLVM 编出**可编译下一代自举源码**的二进制 |
| ③ | 「把已落件去掉，另立 LLVM IR 后端规划」 | 本件 = 该规划的载体 |

⚠️ **必须如实登记的一条**：C 路线**不是被技术实测推翻的** —— 撤销前最后一次实测，其前置全部通过
（C 编译器接受 UTF-8 标识符 · 语料无组合序列 ⇒ 码点实现即等价 · 内建面很小）。
⇒ **撤销的理由是成本与近期性，不是「做不到」**。⛔ 将来重读本件时不得把这条读反。

⚠️ **同时撤销的动作**（2026-10-01，用户同批指令）：C 后端规划件（`plan-selfhost-cbackend-*`）与其三处
指针回填已从两仓**未提交改动中撤销**，授权条目 `auth-77` 改判终止。⇒ 本件是**唯一**的后端路线载体。

### 1.2 起点读数（2026-10-01）

**自举侧**：前端**全交付**（`common` / `lexer` / `ast` / `parser` / `desugar` / `semantic` / `type`（七段）/
`module` / `IR` / `interpreter`；M10 收口 2026-09-30）。⇒ 缺的**只有发射器**。

**甲路线**（宿主发射器吃自举 IR）：

| 项 | 读数 |
|---|---|
| 链路 | ✅ **通** —— 自举整包经宿主 `emit` → `clang` → 原生二进制；未定义符号**零缺口** |
| 三道前置 | ✅ **全清** —— B 组字符语义（`auth-74`）· 名义箱寿命（`auth-75`）· 切分分配与入口门禁（`auth-76`） |
| 自举各层两路一致 | ⚠️ **绿 3 层**（`ast` · `common` · `type-seg7`），其余崩或错 |
| 下一个根因 | ⛔ **非确定性内存缺陷**（另一族，未修）：ASan 下 `type-seg4a` 未初始化 · `4b`/`5a` use-after-free；非 ASan 下同一二进制重复跑读数不同 |
| 门禁提速 | ⛔ **未达成** —— 原生 `module-check` 0.015 s 崩（rc=133）；解释路径下界 ≥688 s |

⭐ **对 LLVM-乙 的意义**：「绿 3 层」是**甲路线的**读数（宿主发射器 × 自举 IR）。LLVM-乙 的判据
（§4.1）**不依赖它** —— 因为本路线的右端是**宿主发射器的输出**，而不是「自举各层行为一致」。

### 1.3 发射面：自举 IR 切片 = **40 节点**

⭐ **切片已被自举侧划定**（`examples/selfhost/src/IR/ir.pini` 件头的「切片清单」，对账器械按该表三侧双向对账）：

| 面 | 契约总数 | **切片内** | 出处 |
|---|---|---|---|
| 类型（§1） | 21 | **11** | `irI32` … `irString` · `irEnumeration` · `irNominal` · `irArray` |
| 表达式（§2） | 46 | **18** | `intConst` … `printCall` · `enumConstruct` · `construct` · `fieldGet` · `stringSplit` … |
| 语句（§3） | 17 | **11** | `allocVar` … `matchStmt` · `fieldStore` · `forIn`（`returnStmt` 拆双 case） |

**划出面**（⛔ 不进切片）：Optional/Result/try · 闭包/函数值 · object/ARC · 下标 · 字典/集合 · 指针 ·
惰性引用 · `join`/`detach` · 泛型 · 逻辑运算符降载。

⭐ **这就是本路线的工程量**：**40 个节点**的发射规则，⛔ 不是宿主发射器的全量面（§1.4）。

### 1.4 规格面：宿主发射器 = **规格书 + 判据右端**

| 件 | 规模（2026-10-01 现读） | 在本路线中的角色 |
|---|---|---|
| `Sources/PiniCore/CodeGen/IREmitter.swift` | 5507 行 / **119 个函数** | ⭐ **规格书**：逐节点的发射算法（含顺序与命名） |
| `Sources/PiniCore/CodeGen/IRBuilder.swift` | 140 行 | ⭐ **逐字节稳定的关键**：temp / label **全局唯一编号源**与 padded 行格式 |
| `Sources/PiniCore/CodeGen/LLVMToolchain.swift` | 64 行 | 工具探测（`PINI_LLVM_BIN` → `llvm-config --bindir` → `PATH`） |
| `Sources/PiniCLI/main.swift`（`runCompileCommand` / `runLLICommand`） | — | **构建配方**（见 §1.5） |

⭐ **本路线相对 C 路线的根本差别**：那是一份要从零**设计**的产物（含自定所有权契约的运行时）；
这是一份**已存在且已在用**的发射算法 —— 工程性质是**移植**（可逐函数对照、可增量推进、每步有机械判据）。

### 1.5 运行时面与「替代宿主」的分层口径

**构建配方**（`runCompileCommand` 现读）：

```sh
clang -o <bin> -L<dir> -lPiniRuntime -Wl,-rpath,<dir> <ir.ll>     # dir = libPiniRuntime.{dylib,so} 所在目录
```

`libPiniRuntime` = `@_cdecl` 暴露 C ABI 的**动态库**（`Sources/PiniRuntime/`，76 处导出）。`.ll` 里的
`declare` 由发射器按用量**条件发出**。

| 层 | 「替代宿主」到哪 | 状态 |
|---|---|---|
| **L1 · 替代宿主的编译器** | 前端（已有）+ **发射器**（本路线）⇒ 自举自己产的 `.ll` 能编出可运行的二进制 | 本路线目标 |
| **L2 · 替代运行时** | `libPiniRuntime`（Swift 实作）换成自举链自产 | ⛔ **独立量级项**，不在本路线内（见 §6.2） |

⚠️ **L1 达成时依赖仍在**：产物是**编译级独立**（不再需要宿主编译器），但**链接级依赖** `libPiniRuntime`。
⛔ 不得把 L1 读成「零宿主」。本件**不宣告**任何一层的完成 —— 宣告权在交付报告。

### 1.6 三条对 C 路线有利、对 LLVM 路线**同样锁定**的语言面事实（承自已撤的 P 段普查）

⚠️ 该普查的载体随 C 规划件撤销 ⇒ **本件为唯一载体**。三读数与后端无关（是语言面事实）：

1. **内建面很小**：自举源码的内建用量 —— `print` 883 · `len` 180 · `readFile` 32 · `argv` 12 · `listDir` 4
   （⚠️ 后者的件内注释称「零用量」，实为 `module` 层在用 ⇒ 该注释已过期，登记不修）。
2. **字素面不触发**：178 份 `.pini` 的字符串字面量里，**组合标记（Mn/Me）= 0 · ZWJ / 格式字符 = 0**，
   非 ASCII 全是单码点汉字 ⇒ 按**码点**实现与按**字素簇**实现，在**现有语料**上等价。
   ⚠️ 这不是「字素簇语义可以不做」—— 语义由契约钉死（§2.22 等已由 `auth-74` 在 LLVM 侧对齐）；
   本读数说的是**夹具覆盖**可以按此排序。
3. **`listDir` 的注释过期**已登记（属注释卫生，非缺陷）。

## 2. 目标与定位

### 2.1 目标（一句话）

**自举编译器吃自举 IR，自己发射 `.ll`**（⚠️ **MVP 切片口径**：只覆盖自举源码用到的 **40 节点**，见 §0）；
该 `.ll` 经 LLVM 工具链编出的二进制，**能编译自举源码自身**（自举链闭合 = 「二进制演进载体」，用户裁定②的目标）。

### 2.2 为什么 LLVM-乙 可行（四条，⛔ 不是偏好）

1. **规格现成**：宿主发射器是逐函数可对照的规格书（§1.4）⇒ 工程是**移植**，不是设计。
2. **判据右端现成**：宿主 `emit` 对**同一份源**的输出即右端，**可机械比对到逐字节** ——
   ⛔ 无需另建期望文件，也⛔ 不依赖「自举各层行为一致」那类弱读数。
3. **不新增运行时**：`.ll` 引用的 `bk_*` 是**共用层**（§1.5）⇒ 与 C 路线不同，本路线**不引入第三份实现**。
4. **链路已验**：甲路线已实证「自举 IR → `.ll` → clang → 二进制 → 运行」的每一跳（§1.2）。

⚠️ **如实交代代价**：复杂度**没有消失，是搬了家** —— 从「运行时」搬到「发射器」，
且发射器的**正确性由右端（宿主）定义** ⇒ 宿主发射器的缺陷会被**一并继承**（这是**移植**的固有代价，
见 R5）。收益在于：那些缺陷在甲路线上已被逐个暴露与修复（`auth-73` / `76` 共修四处）。

### 2.3 与相邻路线的关系

| 相邻 | 关系 |
|---|---|
| **甲路线**（`auth-73`） | 它是**过渡期通道**，也是本路线的**加速器**（规格 + 右端）。⛔ 本路线不撤销它的过渡许可；⭐ 本路线达成后它可退役，但**不是立刻**（覆盖面追平前它仍是唯一能出原生码的通道） |
| **P2 装配通道** | ⭐ **共用前置**（跨文件函数表）：P2 终端判据要它，本路线的**整包发射**也要它 ⇒ 一处投入、两处受益。⛔ 首段与逐节点扩面**收单文件口径**（§3.4） |
| **自举侧内存缺陷族** | ⛔ **另一族，未修**（§1.2）⇒ 它是本路线的**地基风险**（R1），⛔ 不属本路线范围 |
| **特性回填**（插值 / 逻辑运算符 / 闭包 / 泛型 / 指针） | 覆盖面受 **IR 切片**限制（§1.3）；逐节点扩面与特性回填**并行但不同批**（避免判据混合） |
| **宿主仓语义** | ⛔ 不改。若某步证明**必须**改 ⇒ **停下登记**，照甲路线先例另立条目 |

### 2.4 风险面（本路线会撞上的五堵墙）

| # | 风险 | 为何是墙 | 本规划的处置 |
|---|---|---|---|
| **R1** | **自举侧内存缺陷（非确定性）** | 发射器**跑在自举运行时上** ⇒ 上游不稳会把「发射器写错」与「运行时抖动」混成同一种红 | 首段与逐节点扩面收**最小语料**；每批判据先跑**重复性探针**（同输入多次 ⇒ 同输出）；缺陷修**另立条目**（止损 S4） |
| **R2** | ⭐ **`E6-004` 形态敏感缺陷** | `entry-ir.pini` 件头明写：自举侧的「**事后遍历自造 IR 链表 + 字段访问**」形态在宿主上**一绿一红、不可预测**。⚠️ 而发射器**必须**构造并遍历 IR（要模块级收集类型/全局，不能纯流式） | 段 P 的**可行性预验**（§3.0 ②）：用最小探针量「发射器要用的形态」在宿主上是否可跑；⚠️ 若不可 ⇒ 停，**它是宿主缺陷**（另族） |
| **R3** | **逐字节相同的可达性** | 编号 / 命名 / 顺序 / 空白 —— 任一处差一个字符即红 | 首版**照抄**宿主算法（含 `IRBuilder` 的编号语义）；若证明某处**不可能**相同 ⇒ 停，先证明再谈降级（止损 S2） |
| **R4** | **迭代速度** | 自举侧跑在双层解释上（量大、启动固定成本高）⇒ 发射器的每次迭代都贵 | 右端（宿主 `emit`）随时可跑、**零成本**；左端迭代**收小语料**；⭐ 「门禁提速」与本路线**互为因果**（见 §2.5） |
| **R5** | **移植继承宿主缺陷** | 右端本身可能有缺陷（`auth-73`/`76` 共修四处：命名撞名 ×2 · 顺序 ×2 · 分配 ×2） | 移植**带修后的形态**（右端 = 当前树，⛔ 不是历史版本）；⚠️ 宿主侧未来若再修 ⇒ 自举侧须同步（登记为**同步义务**） |

### 2.5 ⭐ 一处结构发现：本路线与「门禁提速」互为因果

「门禁提速」卡在「自举各层两路读数一致」，而那需要**原生臂**；原生臂今天只能由**甲路线**提供。
⇒ **LLVM-乙 不是「门禁提速」的替代路径，而是它的下游**：本路线让自举侧**自己**能出原生码，
那时「门禁跑原生臂」不再依赖宿主发射器的语义完备性。

⚠️ 反向的一条：本路线**自身**的迭代速度受「自举侧跑得慢」限制（R4）⇒ **两件事共享同一个瓶颈**，
但⛔ **不得**把「修内存缺陷」写进本路线（R1 的处置已把边界划死）。

## 3. 阶段划分

### 3.0 前置段 P：普查与可行性预验（先量后合）—— ⛔ 零源码风险

| 项 | 内容 |
|---|---|
| **做什么** | ① **节点映射表**：40 节点（§1.3）↔ 宿主发射器分支的**双向**映射（语言面有而表无 / 表有而语言面无）；② ⭐ **可行性预验**（R2）：最小探针量「构造 + 遍历 IR 形态」在宿主上是否可跑；③ **确定性面清单**：`.ll` 中哪些量必须照抄（编号 / 命名 / 顺序 / 空白）；④ **构建配方固化**：clang 参数 + 运行时段定位 + 版本记录 |
| **为什么先做** | ② 决定**整条路线的可行性**（若该形态在宿主上跑不了，则发射器在今天的自举侧**不可实现**，须先修宿主缺陷）；③ 决定判据能否收到**逐字节**（R3） |
| **判据** | ① 清单**双向报缺口**、每条可追溯到契约条目号或「无对应」判定 ② 预验有**最小复现**与**重复性读数**（同输入多次）③ 读数落件、可复跑 |
| **变异反证** | 删一条已用的节点 ⇒ 须红在 ①；预验夹具改回「流式」形态 ⇒ 须红在 ②（反向验证探针真的在判它） |
| **风险** | 零源码风险（纯量测 + 文档）；⚠️ 但 **② 的结论可能是否决性的** |

### 3.1 段 A · 发射器地基（`.ll` 组装骨架）

| 项 | 内容 |
|---|---|
| **交付物** | ① 新层（自举侧 `codegen`；⚠️ 建层须同批改受管载体，见 §7 待裁 A）② 命名计数器（`IRBuilder` 的镜像）③ 模块头 / 类型定义 / 全局常量 / 函数序言 / 声明（`declare`）的组装 ④ 判据器械骨架（三态） |
| **判据** | A① **最小模块**（空函数体或直返）的 `.ll` 与宿主**逐字节相同**；A② 编号计数器语义与宿主一致（同名同序）；A③ 产物**确定性**（同输入多次 ⇒ 同文本，逐字节）；A④ 器械三态（前提缺失 ⇒ 2，⛔ 不并进红） |
| **变异反证** | 各一条**只打一条**：编号计数器起点偏移 ⇒ 只红 A①/A②；行格式去掉 padding ⇒ 只红 A①；引入非确定性名（如时间戳）⇒ 只红 A③ |
| **止损点** | **S1**：地基段迭代超过三轮仍不逐字节相同 ⇒ 停下重估**编号/命名口径**（R3） |

**分组的轴 = 值的表示法**（⭐ 与宿主发射器的实际结构对应，⛔ 不按契约章节）：

| **B2 字符串族** | `stringConcat` / `lenCall` / `stringContains` / `stringSubstring` / `stringSplit` / `fileRead` | ⭐ 与运行时段**强耦合**（`bk_string_*`）；`declare` 条件出现 |
| **B3 聚合与名义值** | `construct` / `fieldGet` / `fieldStore` / `enumConstruct` / `irNominal` / `irEnumeration` | ⭐ **最复杂的一组**：布局 / 释放胶水 / 值语义即时深拷贝（`auth-75` 的形态） |

② **开工顺序：先修结构性共因，⛔ 不按面序盲啃。** 首测的 14 个面里 `typeName`（283）不是独立一项，

## 4. 验证点

### 4.1 三类判据，别混读

| 类 | 形态 | 作用 | ⛔ 不得读成 |
|---|---|---|---|
| **文本等价**（本路线特有，最强） | 两侧 `.ll` **逐字节**比对 | **移植忠实**：防「自举侧自说自话」 | 「语义正确」—— 右端本身可能有缺陷（R5） |
| **行为等价** | 两腿运行输出逐字节比对 | **回归**：防两腿漂移 | 「符合 reference」—— 等价 ≠ 符合 |
| **覆盖面双向对账** | 双向报缺口 | 防「完全没实现」与「完全实现」同形 | 「已覆盖」—— 单向对账无区分力 |

⭐ **文本等价是本路线相对 C 路线的最大红利**：判据**机械、逐字节、无需期望文件**，
且右端随宿主树的修复**自动跟进**（⚠️ 同时意味着**同步义务**，见 R5）。

### 4.2 硬纪律

⭐ **判据的**「定义处是判据件的四定式」**（`plan-selfhost-criteria-2026-09-30.md`）—— 本路线**照用**，
⛔ 此处不重写。操作上只补三条本路线特有的落点：

1. **文本等价的口径须写明**：是「同一份源 → 两侧 `.ll`」还是「同一份 IR → 两侧 `.ll`」；
   ⛔ 不得混用（后者绕过了降载面）。
2. **确定性判据用「同输入多次」**，⛔ 不用「两次运行输出相同」（那是行为面，不是产物面）。
3. **拒绝面一律判「哪条规则拒的」**（取判定码），⛔ 不只看退出码。

### 4.3 变异反证

每段**每条判据配一条只打它自己**的变异（§3.0–§3.3 各列）。
⭐ 判据写完先问「**未修时它会红吗**」—— 红了再谈绿（本仓已有一例**空转判据**的教训：
`auth-76` 的判据②首版按 `hasPrefix("%")` 取临时名，而发射器写出的行**以空格起头** ⇒ 集合恒空 ⇒
「没有违规」与「判据根本没在判」外观相同）。

## 7. 待裁（三项，各带决策背景）

### 待裁 A · 发射器的**落点**与建层（决定段 A 的第一步）

  - 自举仓 `docs/boundaries.md` §4 明写 `CodeGen/`「⛔ **不建层** —— 属不做范围（后端不实现）」；
  - 自举仓 `README.md` 明写「⛔ **本仓不含**：LLVM 后端 …」。
  `check-boundaries.sh` 的 B1/B3 按 `src/` 的**子目录集合**核对层表 ⇒ 建 `codegen` 层必须**同批**改
  层表 + 树形 + marker（⛔ 三处缺一即红）。
- **③ 各选项**：
  - **甲（推荐）**：自举侧 `src/codegen/` **新层**（第 11 层）。同批改：`boundaries.md` §1 层表 + §2 树形 +
    §4 那一行（`CodeGen/` 由「不建层」改为「⇒ **建层**」）+ `README.md` 的树形与「本仓不含」那句 +
    `docs/probe-notes.md` 的层数口径。**代价**：动三份受管载体（同批改齐）；层集合门禁须重跑。
  - **乙**：不建层，代码散在 `IR` 层内。**代价**：⭐ 违反「层 = 职责」的既有分工；`IR` 层是**降载**

  - **丙**：放宿主仓。**代价**：**不推进自举**（P3 一格不动），落进「第二个主机实现」陷阱。

  改为「已从本清单移出」）· `docs/probe-notes.md` 层数口径。

### 待裁 B · 判据口径：`.ll` 逐字节是否作为**常设硬门**

- **① 是什么**：文本等价（§4.1）是**常设门禁**，还是**一次性证据**。
- **② 为何现在定**：它决定判据器械的形态与自举侧迭代成本（逐字节判据要求左端每次都能跑出来）。
- **③ 各选项**：
  - **甲（推荐）**：**常设**（进自举仓 `tools/`，手动跑，三态）。**代价**：左端慢（R4）；
    ⚠️ 且宿主侧任何改动都要重跑（同步义务 R5）。
  - **乙**：一次性证据（照甲路线 `auth-73` 的先例 —— 用户当年裁定「不要」把逐字节等价立成常设硬门）。
    **代价**：失去本路线**最强**的机械判据 ⇒ 退回到行为等价（弱）。
  - **丙**：分级 —— **地基段与标量组**常设（便宜且稳定），**聚合 / `match` 组**按批一次性。
    **代价**：口径复杂。
- **④ 建议**：**丙**，并在开工时点名哪些组常设。⚠️ 本项与 `auth-73` 当年那条「不要」**不冲突**：
  那条针对的是「**两腿行为**逐字节等价」（会被并发语料的诊断措辞噪声打红），
  而本项是「**两侧 `.ll` 文本**逐字节等价」（**输入是同一份 IR，无并发面**）—— ⚠️ 该区别须在开工时写明。
- **⇒ 已裁（2026-10-01 · 代理裁，记录见自举仓 `docs/probe-notes.md` §50.1 第 1 项）：取甲 · 常设**
  —— 进自举仓 `tools/` 的**常跑集**（器械落在 `check-*.sh` 通配内）。
  ⚠️⭐ **与本节第 ④ 条的推荐（丙 · 分级）不同，如实登记**：分级的理由（省左端代价）不成立到值得让
  **未设门的那些组没有判据**——而那正是本仓反复防的「**静默 = 与实现了同形**」。
  实测代价（单跑器械数十秒量级）已量并接受；⚠️ 由此带来的**同步义务**照 R5 执行
  （宿主发射器一改，自举侧须同批跟进，器械会红）。
  ⚠️ 第 ④ 条要求写明的「行为面 vs 文本面」区别已按原样落进器械件头（`check-codegen.sh` 的口径纪律段）。

### 待裁 C · 「替代宿主」的**分层口径**（L1 到哪、L2 何时启）

- **① 是什么**：用户目标「替代宿主」是到 L1（替代**编译器**）还是到 L2（替代**运行时**）。
- **② 为何现在定**：它决定本路线的**验收面**与「自举达成」的宣告口径。⚠️ 若按 L2 验收，本路线的量级
  会**放大数倍**（运行时替换 = 把 `libPiniRuntime` 的语义用自举链重写）。
- **③ 各选项**：
  - **甲（推荐）**：**L1 为验收面**，L2 立为**独立后续项**并带**启用条件**（如「L1 交付后，且自举侧内存缺陷族清零」）。
    **代价**：产物仍链 `libPiniRuntime`（⚠️ 须在交付报告里明写「编译级独立、链接级依赖」）。
  - **乙**：L1 + L2 同批。**代价**：量级放大数倍，且 L2 的前置（自举侧稳定性）今天**不满足**。
