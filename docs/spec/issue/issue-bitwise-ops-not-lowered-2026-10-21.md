# Issue：位运算整族不在 IR 降载面 —— 落 `ir-skip: binaryOp` 且值成 0

- 状态：**Closed（2026-10-21 销账 · 用户裁定「立刻」⇒ 按候选 A 补齐，C 取可落地形态）** —— 读数见本件末
  「销账」节与自举仓读数件 §139；⛔ 本单**未占用开放项册编号**（立案时未取，销账后亦不补）。
- 层级：**自举级**（IR 降载面缺口）。语言面已定义、解释器已能求值、**宿主发射器也已能发指令** ⇒
  ⛔ 不是语言缺口、⛔ 不是宿主缺口。
- 发现来源：2026-10-21 浮点字面量指数形态批（开放项册 `N91`）—— 为位型助手做可行性原型时，
  原型用了 `>>` 与 `&`，自举产物算出的值全是 0，由此撞出。
- 关联：IR 契约的 `binary` 条目（其文字已含位运算，见「建议」）· 自举仓读数件 `§137` ·
  兄弟族「逻辑运算符未降载」在宿主规范台账 `G81` 在案（**不同族，⛔ 不并单**）。

## 问题

五个运算符在 IR 降载的二元运算分派里**没有臂**，落 catch-all：

| 运算符 | 降载产物 | 诊断行 |
|---|---|---|
| `&` · `\|` · `^` · `<<` · `>>` | `irIntConst(value = 0, type = irI32)` | `ir-skip: binaryOp`（**响亮 · 不阻断**） |

⚠️ **危害形态**：这不是「报错停住」，而是**照常产出一个合法但错误的 0**：
`rc=0`、产物良构、执行不崩，只有数字是错的。⇒ 任何「产物非空 / 能跑完」的粗读都看不见它。

## 实测（2026-10-21 · 两腿现跑 · 探针在仓外临时目录）

语料（最小）：

```
t|func(n: I32,) -> (I32,):
    return (n >> 4) & 15
u|func(n: I32,) -> (I32,):
    return n << 2
main: print(t(1023,)) / print(u(3,))
```

| 腿 | 产物里的函数体 | 执行输出 |
|---|---|---|
| 自举（IR 腿） | `ret i32 0`（**一条指令都没有**） | `0 0` |
| 宿主（种子） | `ashr i32` + `and i32` / `shl i32` | `15 12` |

诊断面：`ir-skip: binaryOp` **2 条**，⛔ 无其它诊断、无异常退出。

## 已排除（⛔ 别再往这些方向查）

- **不是语言面缺**：词法有 `<<` / `>>` / `&=` 一族记号；解释器求值正确
  （同一份源走 `run` 得 `12 16 37`）⇒ 前端与语义都在。
- **不是宿主缺**：宿主发射器对同源发 `and i32` / `ashr i32` / `shl i32`。
- **不是兜底缺失**：兜底**在**（它印了行、给了 0）—— 缺的是**五个臂**。
- **不是承载能表达**：承载的 `[IRBinaryOp]` 只有 **11 个 case**（算术 5 + 比较 6），
  **没有**位运算与移位位 ⇒ 加臂之前必须先扩承载。

## 影响面（今天为什么不发作）

- 自举源码对五个运算符**零使用**（全仓检索零命中）⇒ 现有产物一个都不受影响。
- 但**自编自身**（C③）时，任何新增的位运算会在自产产物里**静默算成 0** ——
  这正是本批（`N91`）修法刻意绕开它的原因：位型助手改用 `/` 与 `*`，⛔ 不用 `&` / `>>`。

## 候选（含代价）

| | 做什么 | 代价 |
|---|---|---|
| **A · 补齐三腿** | 承载 `[IRBinaryOp]` 加 5 个 case · 降载 5 臂 · 发射 5 臂（`and`/`or`/`xor`/`shl`/`ashr`）· 镜像解释器 5 臂 · 新语料 · 契约对账器械与覆盖面册同步 | 动**共享承载形状** ⇒ 必须先跑「节点 case 集 ↔ 切片清单」双向对账器械；`free` 分母会涨；影响面 = 三腿 + 两册 + 器械 |
| **B · 只用算术等价** | 不补语言面，靠 `*2` / `-` 之类表达 | ⛔ 位运算**没有**算术等价（除 `<<1` ≡ `*2`）；且把改写责任摊给每个写代码的人 |
| **C · 改为 fail-loud** | 降载处把兜底从「给 0」改成**拒绝**（拒绝形态与既有划出面同规） | 最便宜（一处返回）；但会让今天「能过」的程序变红 —— 属**行为收紧**，须先裁 |

## 建议

先回答一句再排期：**这属「接线」还是「新立条目」？**
IR 契约的 `binary` 条目文字已写「算术 / 比较 / 逻辑 / **位运算**（`IRBinaryOp`）」⇒
若判为接线，则 A 是「把承载与三腿补到条目已有范围内」；若判为新立，则先走治理流程。
⚠️ ⛔ 本单不预设二者之一 —— 这条判断属口径裁决。

## 待裁（三种处置，用户已给选项）

1. **MVP 之外 · 暂不做** —— 理由面：自举源码零使用，今天不影响任何产物。
2. **延迟做** —— 排在 C③（自举自编）之前，因为那时「自举源码写位运算」才成为现实需求。
3. **立刻做** —— 若判「静默算 0」这一形态本身不可接受（属「划出面不得以看起来合法的值
   静默流进下游」那条定式），则按 C 先收紧、再按 A 补齐。

## 不做范围

- ⛔ 不动 `&&` / `||`（另一族：降载侧落 `ir-skip: logicalOp` 并返 `false`；两者同属兜底，但成因与判据不同）。
- ⛔ 不动语言语义、不动解释器、不动宿主发射器。
- ⛔ 不改任何语料 / 判据面（本单未定排期，改判据面属开工动作）。

## 销账（2026-10-21）

**结论：候选 A 成立；C 的「非零拒绝」在本层无先例，改取**同规形态**；另量出一条工单没写的坏面（融合式腿）。**

- ⭐ **开工半步把「几条腿」量清楚了** —— 同一份 `&=` `|=` `^=` `<<=` `>>=` 源，三条腿各跑一遍：

  | 腿 | 正确指令 | `add` | 诊断行 |
  |---|---|---|---|
  | 宿主（右端） | 5 | 0 | — |
  | 自举 IR 腿 | 0 | 5 | `ir-skip: binaryOp` ×5（响亮 · 值成 0） |
  | 自举融合式腿 | 0 | **10** | **0 条**（完全静默：产物良构、值全错） |

  工单只登记了 IR 腿 ⇒ **融合式腿是同一缺陷的静默那一半**（其算术语义表对未列运算符兜底返回 `add`）。
- ⭐ **第二个量出来的事实**：`n | 3` **直写形态在前端就不可解析**（Parse Error E2-006）——
  词法把竖线命名为 `pipe`，分派查的是 `bitwiseOr` ⇒ 永远不匹配；`|=` 走另一条分派因而可达。
  ⇒ `irBitOr` 曾只有 `|=` 一条入口，语料据此布局。
  ⭐ **2026-10-21 已销**（同日后续批）：宿主位运算分派补上 `.pipe` 两臂（`isBitwiseOperator` /
  `getBitwiseOperator`），语料改回直写形态并有宿主内联用例守着；读数见计划件 §10.80。
- **修法**：承载 +5 case · 标签 +5 臂（该函数无兜底，缺一即运行期中止）· 降载 +5 臂 ·
  IR 发射的 op→AST +5 臂 · 融合式腿的指令名 +5 条；并把融合式腿的静默 `add` 兜底改为
  **点名诊断**（与既有 21 个 `ir-skip` 面同规）。
- **读数**：两份新语料（IR 腿 / 融合式腿各一）两侧 **8583 = 8583** 与 **8278 = 8278** 字节、
  `diff` 0 行、skip 0 条，执行输出同为 `15 6 12 63 15 3 11 10 40 20`；
  `check-codegen-ir` 50 → **51**；`check-codegen` 11 → **12**；
  `ir-mod`（7349=7349 · 7447=7447）· `codegen-mod`（skip 面 14/3185，**新兜底零命中** ⇒ 确证不可达）·
  梯 4/4 · `ir-lower` / `ir-run` / `semantic` / `boundaries` / `codegen-arr` / 腿分区 / `seed` 全绿；
  `free` 分母不动（零新增自由函数）。
- **变异两级**（撤四处源码 · 单点把异或指令名改成 `or`）各只红本批两份语料。
- **契约对账**：器械先红（「节点集有而清单无」）—— 其**豁免集**列的是运算符子枚举，新 case 未列；
  该豁免集在**同一件里两份**（判据② / 判据⑦），**两处同改**后双绿，被对账的 52 条计数不变。
- **边界**：`|` 直写仍不可解析（前端命名缺口，未修）；`I64` 位运算的 `rtype` 与算术同规（既有缺口，
  非本批引入）；`&&` / `||` 另属一族（`ir-skip: logicalOp`）。
