# Issue：位运算整族不在 IR 降载面 —— 落 `ir-skip: binaryOp` 且值成 0

- 状态：**Open（已立案 · 未开工 · 未排期）** —— 用户 2026-10-21 点名「立案，有可能裁定为 MVP 之外而暂不做，
  或延迟做，或立刻做」⇒ 三种处置都列在「待裁」，⛔ **本单未自行占用开放项册编号**（编号是不可逆资源）。
- 层级：**自举级**（IR 降载面缺口）。语言面已定义、解释器已能求值、**宿主发射器也已能发指令** ⇒
  ⛔ 不是语言缺口、⛔ 不是宿主缺口。
- 发现来源：2026-10-21 浮点字面量指数形态批（开放项册 `N91`）—— 为位型助手做可行性原型时，
  原型用了 `>>` 与 `&`，自举产物算出的值全是 0，由此撞出。
- 关联：IR 契约的 `binary` 条目（其文字已含位运算，见「建议」）· 自举仓读数件 `§137` ·
  兄弟族「逻辑运算符未降载」在宿主规范台账 `G81` 在案（**不同族，⛔ 不并单**）。

## 问题

五个运算符在 IR 降载的二元运算分派里**没有臂**，落 catch-all：

| 运算符 | 降载产物 | 诊断行 |
|---|---|---|
| `&` · `\|` · `^` · `<<` · `>>` | `irIntConst(value = 0, type = irI32)` | `ir-skip: binaryOp`（**响亮 · 不阻断**） |

⚠️ **危害形态**：这不是「报错停住」，而是**照常产出一个合法但错误的 0**：
`rc=0`、产物良构、执行不崩，只有数字是错的。⇒ 任何「产物非空 / 能跑完」的粗读都看不见它。

## 实测（2026-10-21 · 两腿现跑 · 探针在仓外临时目录）

语料（最小）：

```
t|func(n: I32,) -> (I32,):
    return (n >> 4) & 15
u|func(n: I32,) -> (I32,):
    return n << 2
main: print(t(1023,)) / print(u(3,))
```

| 腿 | 产物里的函数体 | 执行输出 |
|---|---|---|
| 自举（IR 腿） | `ret i32 0`（**一条指令都没有**） | `0 0` |
| 宿主（种子） | `ashr i32` + `and i32` / `shl i32` | `15 12` |

诊断面：`ir-skip: binaryOp` **2 条**，⛔ 无其它诊断、无异常退出。

## 已排除（⛔ 别再往这些方向查）

- **不是语言面缺**：词法有 `<<` / `>>` / `&=` 一族记号；解释器求值正确
  （同一份源走 `run` 得 `12 16 37`）⇒ 前端与语义都在。
- **不是宿主缺**：宿主发射器对同源发 `and i32` / `ashr i32` / `shl i32`。
- **不是兜底缺失**：兜底**在**（它印了行、给了 0）—— 缺的是**五个臂**。
- **不是承载能表达**：承载的 `[IRBinaryOp]` 只有 **11 个 case**（算术 5 + 比较 6），
  **没有**位运算与移位位 ⇒ 加臂之前必须先扩承载。

## 影响面（今天为什么不发作）

- 自举源码对五个运算符**零使用**（全仓检索零命中）⇒ 现有产物一个都不受影响。
- 但**自编自身**（C③）时，任何新增的位运算会在自产产物里**静默算成 0** ——
  这正是本批（`N91`）修法刻意绕开它的原因：位型助手改用 `/` 与 `*`，⛔ 不用 `&` / `>>`。

## 候选（含代价）

| | 做什么 | 代价 |
|---|---|---|
| **A · 补齐三腿** | 承载 `[IRBinaryOp]` 加 5 个 case · 降载 5 臂 · 发射 5 臂（`and`/`or`/`xor`/`shl`/`ashr`）· 镜像解释器 5 臂 · 新语料 · 契约对账器械与覆盖面册同步 | 动**共享承载形状** ⇒ 必须先跑「节点 case 集 ↔ 切片清单」双向对账器械；`free` 分母会涨；影响面 = 三腿 + 两册 + 器械 |

## 建议

先回答一句再排期：**这属「接线」还是「新立条目」？**
IR 契约的 `binary` 条目文字已写「算术 / 比较 / 逻辑 / **位运算**（`IRBinaryOp`）」⇒
若判为接线，则 A 是「把承载与三腿补到条目已有范围内」；若判为新立，则先走治理流程。

## 待裁（三种处置，用户已给选项）

1. **MVP 之外 · 暂不做** —— 理由面：自举源码零使用，今天不影响任何产物。
2. **延迟做** —— 排在 C③（自举自编）之前，因为那时「自举源码写位运算」才成为现实需求。
3. **立刻做** —— 若判「静默算 0」这一形态本身不可接受（属「划出面不得以看起来合法的值
   静默流进下游」那条定式），则按 C 先收紧、再按 A 补齐。

- ⛔ 不动语言语义、不动解释器、不动宿主发射器。
