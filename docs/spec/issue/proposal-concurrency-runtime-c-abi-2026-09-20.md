## 3. 原语层 ABI 面（**拟定，供裁**）

命名照 `bk_*` 既有族；句柄 `void*`；长度 / 状态用 `i32`；返回值走 **out 缓冲**
（照 `bk_lazyref_value` 的「运行时分配、wrapper 写入」模式，规避返回栈地址的逃逸 UB）。

### 3.1 任务与 join

| 函数 | 签名 | 语义 |
|---|---|---|
| `bk_task_spawn` | `(wrapper, code, env, elemBytes, elemTag) -> handle` | 派发任务体。**照 §2 第 2 条的 wrapper ABI**，不新造 |

⛔⛔ **本行已订正（2026-09-20，`B-1`）**：原「照 §2 第 2 条的 wrapper ABI，不新造」**在「走乙」下不成立** ——
那条 wrapper ABI 的返回是**单个 `ptr`**，**表达不了「跑完 / 已让出」两态**，
而「两态」正是让出在乙下的全部内容（见 §3.2.1）。
⇒ ⭐ **`bk_task_spawn` 与 `bk_task_yield` 是本件仅有的两个受形状影响的符号**；
其余 8 个（`join` / `join_within` / `join_all` / `cancel` / `is_cancelled` / `detach` / `scope_close` / `capabilities`）
**形状不受影响**（已实测复核）。**新的 spawn 形状须在 `DE-3b` 的 `B-3` 段单独裁定，本件不替它定。**

⛔⛔ **上句已作废（2026-09-20，裁定 37 · 糖读法）** —— 保留原文以留历史链。
「急切派发」按糖读法即「**调用即派发**」（依据见 `proposal-scheduling-surface-2026-09-20.md` §1.14）：
**调用点就是派发点**，本符号的实参**就是**该次调用的实参 ⇒ **`spawn` 自身不需要新形状**，
故**「形状待议」这一项不存在**。
⚠️ **真正待定的收窄为「wrapper 的返回协议」**（任务体怎么告知驱动器「本次没跑完」），
且它**不再是阻塞级**、属 `B-3` **批内可定并登记的细节** —— 依据有**双重锚定**：
① 本件 §3 章首**已定**约定「长度 / 状态用 `i32`、返回值走 `out` 缓冲」⇒ 自然解与 §3 既有形态**同构**；
② 解释器腿**已解过同一问题**：`Scheduler.swift` 的 `TaskOutcome { finished(Value) | suspended }`，
其注释原文「只返回 `Value` 的签名里**没有『这次没跑完』这一格**」。
⚠️ 一处**仍未定**的真细节（属 `DE-3c`）：可恢复帧之下「**从哪一帧续**」的入口形态
（对照解释器腿的 `resumeBody` / `completeResumedRun`）是否需要**第二个入口**。
⭐ **2026-09-21（`DE-3c` 交付后）补注**：本批只落 **L0**，体**从不中途返回** ⇒ 该问题在本批
**不产生对象，故不替它定**；它随 **L1**（真让出）一起才有对象。⚠️ 不要把「本批没定它」
读成「它被裁掉了」。

✅ **2026-09-21（`DE-6a`）该问题已定案** —— 它随 L1 一起来了，故按上文所说在此定掉：
**取「新增一条符号」**，即 **`bk_task_await`**（形状见 §3.2.1 表、语义与帧的持久化见 §3.2.2）。
⚠️ 为什么不是「给 `bk_task_join` 的 status 加一个取值」：**「这次会不会让出」是编译期属性**，
而运行时刻判不出 —— 同一个 `join` 路径既服务异步体（可让出）也服务同步体的 `wait`（**永不该**让出，
且那是既有语义）。把两个契约挤进一个符号，等于让运行时代码去猜一个它拿不到的信息。
⭐ 该符号与既有的 `bk_task_yield` **分工照 §3.2.1**：查询在前（问能不能），新符号在后（据此走让出那条路）。
⛔ 上文原句一字未改 —— 它记的是**当时为真**。

⚠️ **一类连带须留意（实施时实测）**：本符号在解释器腿的对应物 `spawnAsync`
**收到的实参面**即为糖析出的落点 —— 糖的**载荷是类型**（`future(ok:)`，`DE-3a` 已交付），
调用节点不变 ⇒ 两侧的实参对应关系**可以直接照搬**，无需翻译层。

| `bk_task_join` | `(handle, out) -> status` | **阻塞** join（现行唯一形态）。`out` 写 `Result` 聚合 |
| `bk_task_join_within` | `(handle, ms, out) -> status` | 带超时阻塞 join；超时归约 `err(CancelError)`（与解释器腿 `joinWithin` 同构） |
| `bk_task_join_all` | `(handles, count, out) -> status` | 聚合，**fail-fast**：任一 `err` 即返回并取消其余 |

⭐ **`out` 的形态照 `Result` 的既有 ABI**（三槽）：**槽 0 = tag**（`ok=0` / `err=1`）·
槽 1 = ok 载荷 · 槽 2 = err 载荷（**擦除为 i64 宽度**）。
⇒ `await` / `wait` 站点解构时，**发射层已有三槽读写代码**（本仓 `match` 的 Result 分派同族），
故 `DE-3` 在这处**不需要新 ABI 概念**。

### 3.2 ⭐ 让出（本批新增的唯一原语）

> ⛔⛔ **本节已订正（2026-09-20，`B-1`）—— 读它以这一节为准，不要按旧表述实现。**
> **订正原因**：§3.2 原按「让出 = 一次无参调用**自己切走**」定形，**该形状未经机制层审查**。
> `B-1` 补做该审查（外部对照见 `proposal-scheduling-surface-2026-09-20.md` §7.6.10），
> 结论：**走乙（编译器可恢复帧）** ⇒ 让出**不能**表达为一次调用，只能表达为**体的 `return`**。
> 三条订正理由：① 与解释器腿 `DE-2b` 的「帧栈 + 驱动器」**同形**（正面符合裁定 32 的理由①）
> ② 绕开 macOS arm64 的 `ucontext` 缺口、不需逐架构汇编 ③ **WASM 腿今天只有这条路可走**。

#### 3.2.1 订正后的形状

| 项 | 旧（已废） | ⭐ **新（照此实现）** |
|---|---|---|
| 让出是什么 | `bk_task_yield()` 调用**自己切走**（换栈） | **体返回「已让出」** —— 让出是**控制流的返回**，不是一次调用 |
| 该符号的角色 | **动作**：发起让出 | ⭐ **查询**：回答「本次让出**能不能真的发生**」 |
| 返回值 | `1 = 真让出 / 0 = 降级为立即返回` | **保持 `1 / 0` 不变**，但语义从「发生了吗」改为「**能做到吗**」 |

⚠️ **这一订正让该符号与解释器腿的既有行为对齐，不是新增分歧**：
解释器腿 `yieldTask()` 的注释**已经写着**「调用它**不等于**已经让出：它回答的是
『这次让出能不能真的发生』」⇒ 它**实际早已是查询语义**。⇒ 订正后**两腿同义**。

| 函数 | 签名 | 语义（订正后） |
|---|---|---|
| `bk_task_yield` | `() -> i32` | **问后端能否让出**：`1` = 能（调用方据此把控制流交还驱动器）· `0` = **合规降级**。⛔ 它**不执行**让出；执行让出的是**体的返回** |
| ⭐ **`bk_task_await`** | `(handle, out) -> i32` | **可让出的等待**（`DE-6a` 新增）：`0` = 已决 ok · `1` = 已决 err / 已取消（两者 `out` 三槽已写，归一化同 `bk_task_join`）· **`2` = 本次会让出**（`out` **未**写；运行时已把「当前任务等待 `handle`」登记进当前任务盒子） |

⚠️ **`bk_task_await` 的三条边界**（`DE-6a` 定案）：
- ⛔ **只许在「异步体 · 语句根 · `form = awaits`」处调用** —— 该前置由**发射层**保证，运行时**不校验**。
  ⇒ 这不是「运行时多一个模式」，而是**同一处调用点按编译期事实分岔**：其余位置（含同步体的 `wait`）一律沿用 `bk_task_join`。
- ⛔ **L1 位未置时它不得返回 `2`**：按**合规降级**处理（阻塞等待后返回 `0`/`1`），与 `bk_task_yield` 的答案同源。
- ⛔ **返回 `2` 时 `out` 一个字节都不许写** —— 与 §3.1 `bk_task_spawn` 那一行的「体已让出 ⇒ `out` 不许被写」
  **是同一条约定**；调用方据此返回非 `0`，且**不得释放帧**（见 §3.2.2）。

⭐ **返回码 `1 = 能真让出 / 0 = 降级为占用`** —— 这一个位就是「本次让出是否真的会发生」的**可观测差异**，
也正是 `D`+`E` 验收所需的那条（提案 §7.5 判据 3：`await` 让出 / `wait` 占用的可观测差异）。
⛔ **不许把它写成「无线程后端语义为空」** —— 已由提案 §7.6.4 订正为「**语义保持、只降级执行策略**」
（Go 的 WASM 目标等价 `GOMAXPROCS=1`）。`0` 是**合规降级**，不是错误。

#### 3.2.2 ⭐ 续跑入口与**帧的持久化**（`DE-6a` 定案）

> 本节的来源是 §3.1 里那处**明写的留白**（「从哪一帧续」的入口形态）；它随 L1 一起才有对象，故在此定掉。

| 项 | 定案 |
|---|---|
| 续跑怎么做 | 运行时用**同一个**三元组 `(wrapper, code, env)` **再调一次** wrapper ⇒ ⭐ **不需要第二个入口函数**。依据：盒子今天已存着这三件（`spawn` 时写入），且 §3.1 的 wrapper 形态本来就以 `env` 为唯一上下文入口 |
| 体怎么知道是续跑 | 由**体自己**从帧里读续跑点 ⇒ 帧的**布局是发射层的私事**，不成为 ABI 的一部分 |
| `env` 的角色 | ⭐ **从「实参缓冲」升格为「体的持久帧」**：派发点按**体所需尺寸**（含实参）分配、体**只在真跑完时**释放。⛔ 让出时**不许**释放 |
| `out` 的角色 | 每次进入体都是**新的一块**（今天由运行时每次运行分配，见 §3.1）；⛔ 让出时不得写它 |
| 续跑跑在哪条线程 | **原语层**的事；契约上只声明「**可能不是原来那条线程**」⇒ 体不得依赖线程局部 |
| 两条连带（须实现时兑现） | ① 运行时 `_bkTaskRunBody` 那道「**体已跑过就返回**」的闸**必须让续跑通过**（今天的形态会直接吞掉续跑）；② 任务在**让出态**被取消 ⇒ 体**不会再被进入** ⇒ **帧必须由运行时释放**（否则漏） |

⚠️ **与「更省」方案的分界（登记，免被重新提出）**：曾考虑「把 `bk_task_join` 的 status 加一个取值 `2`」——
**已否**，理由见 §3.1 末尾那处 2026-09-21 补注（编译期属性 vs 运行时刻）。
⭐ **本节的帧语义与解释器腿同形**：那条腿的挂起帧也是「一个任务一个」、携带该任务的上下文快照，
续跑按帧重入 —— 两腿在这一层的**概念**一致（实现手段不同：一条是 Swift 值，一条是堆缓冲）。

### 3.5 睡眠（`DE-3c` 补入，2026-09-21）

| 函数 | 签名 | 语义 |
|---|---|---|
| `bk_sleep` | `(ms: i32) -> void` | `sleep` 的落点：**按片睡**，每片醒来看一次取消位 |

⭐⭐ **它为什么在这张表里，而不做成一条 libc 调用**：`sleep` 是并发内建里**唯一**被降载成
一条普通调用、而实现又必须由后端提供的那个（`Error` / `CancelError` 在降载层就成值，`joinAll` /
`joinWithin` / `isCancel` 由两台引擎各自按名回答）。解释器腿的对应物把长睡**拆成小片**、每片回来
查一次取消 ⇒「取消一个正在睡的任务」在**一片之内**生效。一条直通的 libc 睡眠会让两腿在
**取消时机**上分岔，而那个分岔在**只跑成功的样板里看不出来**。
⚠️ 睡眠本就属**原语层**（§4：让出 / 恢复 / 续体保存归宿主），故它的落点是运行时符号。
⚠️ **一处如实边界**：解释器腿在检查点发现取消时是**抛**（abort 体），而 C ABI 面没有异常通道
⇒ `bk_sleep` 只能**提前结束睡眠**、体随后仍会跑完；**等待侧的归约两腿同一套**（盒子已置取消
⇒ `bk_task_join` 回 `status = 1` ⇒ `err(CancelError)`）。体被真正中断要等发射层接上取消检查点。

### 3.6 让出的**可观测通道**（`DE-6a` 定案 —— ⛔ 非 ABI，但**各后端须同形**）

> ⛔ **它不是一个 ABI 函数**，故**不计入** `HIR 契约` 的 `bk_*` 权威清单（清单只数导出符号）。
> 但它**必须登记在本件里**，理由：`D`+`E` 的验收标准是「`await` 让出 / `wait` 占用的**可观测差异**」——
> 而这条差异**只能靠观测**才成立 ⇒ 观测面本身成了**后端之间的契约**。第 4 个后端若各自发明一种观测法，
> 那条验收标准就**无法跨后端复用**（本件存在的全部意义正是「让下一个后端不用重想」）。

| 项 | 定案 |
|---|---|
| 通道形态 | ⭐ **环境变量闸门 + stderr 汇总行**：运行时累计「体真让出」的次数，并在**进程退出时打一行**到 stderr |
| 落点 | 经**既有**的进程退出钩子（运行时已用它回收活动句柄），⛔ **不新起一条退出路径** |
| 闸门 | **仅在环境变量置位时**输出；⛔ **未置位 ⇒ 零输出**（不得污染任何正常程序的 stderr） |
| ⛔ 性质声明 | 它是**测试器械专用**的观测面 —— **不是** ABI、**不是**诊断通道、**不是**给用户的功能。⚠️ 本仓另有一笔**已登记的**「诊断通道」缺口，二者**不得混为一谈**（这条声明的作用就是防止有人把它当成那个缺口的补丁） |
| 为什么是汇总一行而不是逐次一行 | 逐次打点会与程序自身输出交错 ⇒ 读起来**非确定**；汇总一行**逐字节可断言**。⚠️ 代价如实说：**只有置位的运行可见** ⇒ 「不置位时也让出」这一半测不到 —— 这与本仓「**跳过必须可见**」同向（必须**显式**开闸，否则读数不可信） |

⚠️ **判据的分工**（免得把两件事当成一件）：
- **进程内单测**钉运行时的**续跑协议**（已让出的任务在等待对象决出后被续跑）—— 确定性最好；
- **闸门 + stderr 计数**钉**发射层真的在 `await` 处让出**（`await` 版计数 > 0 · `wait` 版 = 0）。
⛔ 两者**不可互相替代**：前者看不见发射层，后者看不见协议本身。

## 5. ⛔ 重入规则（**待裁**，本件不替用户定）

若策略是 Pini 值，则**调度决策是一次 Pini 函数调用，而它恰好运行在 `await` 点上** ⇒
「调度决策自身是否也能被让出」**必须显式定清**，否则这是**递归挂起**的入口。

| 解读 | 含义 | 代价 |
|---|---|---|
| **甲（我的建议）** | **调度决策不得挂起**：决策期间 `bk_task_yield` 恒返 `0`（no-op），并**响亮诊断**（若策略真去让出） | 需要一层「决策中」标志；表达力受限（策略不能自己做异步等待） |
| **乙** | **允许**调度决策挂起（重入挂起） | 需要「调度器的调度器」；**递归深度无自然上界** ⇒ 须先定义终止条件 |

**建议 `甲`**，理由两条：① 外部先例里策略层都是**同步的**（Rust `Waker` / C++ `scheduler` 的选择动作皆非异步）；
② 本批的克制口径（裁定 11）不允许为一个尚未出现的需求预置无限递归面。**但这条我不擅自定。**

### 6.1 分层（一层套一层，**不是矩阵**）

| 层 | 能力 | 依赖 | 本仓现状 |
|---|---|---|---|
| **L0 调度** | `spawn` / 阻塞 `join` | 无 | ✅ 解释器腿有；LLVM 腿 ⛔ 缺（`DE-3`） |

3. ⛔ **无合格版本则降级，不失败**（例如无线程 ⇒ L1 降为 no-op 返回 `0`，**不是报错**）
