## 1. 终端判据是什么，以及它的形状

**判据（`auth-69` 结案时转交项① · 二期件 §2）**：**自举解释器跑自举编译器全源**。
销账条件（原文）：*在自举解释器上端到端跑通全源；⚠️ 若受时长/覆盖面阻塞，
须如实登记阻塞面并另立条目。*

⭐ **它的形状与本轨其余判据不同，且必须不同**：其余判据判「**读数对不对**」，
它判「**能不能**」—— 先例是解析层判据⑫（「不终止即红」）。

**机械形式**（本批建成）：`examples/selfhost/tools/check-selfverify.sh`，三态：

| 判据 | 内容 | 本批读数 |
|---|---|---|
| ① | 全源**逐份可解析**（⛔ 不抽样） | 47/47 ✅ |
| ② | 全源**逐份降载不崩** | 47/47 ✅（本批修成） |
| ③ | **全源端到端**（装配后在自举解释器上跑通） | ⚠️ **报 2（无法判定）** |

⚠️ **③ 为什么报 2 而不是 1**：③ 的**判定手段**（模块 → IR → 解释器的装配入口）
**不存在** ⇒ 与「子集门禁在判定手段未就位时报 2」**同形**。
⛔ 这不是把红粉成灰 —— ③ 的**未达**就是本件 §2 的第一句；
且该器械已在自举仓红名单（`tools/expected-red.txt`）登记一行（**预期码 2**，
**删行条件随行写明** = 装配通道落地且端到端跑通，届时本器械应转 0）。

## 2. 阻塞面三类（第一类当场修，第二类是真墙，第三类是它的倍增器）

### 2.1 ⛔ **通道面 —— 模块 → IR → 解释器的装配通道不存在**（真墙）

- **机械证据**：`pini run . ir-run src/main.pini` ⇒ `iv-runtime-error: undefined function irRunEntry`。
  ⚠️ 注意 rc=**0**：它**降载完就停**，⛔ 不是崩溃 —— 这个形状说明问题出在**执行期的函数解析**，
  而不是前端。
- **机制**：`ir-lower` / `ir-run` 只收**单文件**；解释器的函数表 = **本文件**的函数集
  （`ivRunProgram`）⇒ 跨文件调用**无一可解析**。模块层与 IR/解释器之间**没有任何调用边**。
- **归属**：⛔ 它**不是**「自举缺特性」，是**通道缺口** —— 缺的是**装配语义**
  （跨文件的类型表 / 枚举表 / 函数表如何汇成一张）。
- ⚠️ **量级如实交代**：重建它牵动**整个前端**的装配面 ⇒ 属**量级项**，
  ⛔ 不在 `auth-71` 的 scope 内（该条明写「不重建」）⇒ **须另立条目**。

### 2.2 ⚠️ **覆盖面面 —— 全树逐份降载的划出面**（⚠️ 读数被 2.1 放大）

- 47 份逐份降载（⛔ 不抽样）共 **5034 条**划出面。⚠️⚠️ **这个数不等于「能力缺口 5034 条」**
  —— 见 §3.2 的归因：其中**至少 2740 条（54.4%）是 2.1 那面墙的产物**。
- 九类分布（`unknownType` 2761 · `matchEnumUnknown` 1516 · `member` 240 ·
  `assignTarget` 206 · `callCallee` 139 · `expr` 129 · `decl` 21 ·
  `complexTypeAnnotation` 13 · `unaryOp` 9）。
- **归属**：⛔ 逐类实现属 **IR 格 / 各特性格**（差距台账 §1 第 1–6 行即那张账），
  须**另立条目**；本批只**量**与**登记**。

### 2.3 ✅ **健壮性面 —— 降载器遇真实形态直接崩**（**本批当场修**）

- **症状**：修复前 **7/47 份 rc=1**，`E5-012 match not exhaustive`。
- **两处落点**（**同一形状复发了两处**）：`irLowerMember` 的 `match receiver:` ·
  `irLowerStmt` assign 分支的 `match baseExpr:` —— 均只列 `identifier` 一臂、**无默认臂**。
- ⚠️⭐ **要害不是「崩」，是「兜底行成了死代码」**：两处函数尾各写着一行
  `print("ir-skip: member")` / `print("ir-skip: assignTarget")` —— 那正是**划出面的记账行**；
  match 不穷尽 ⇒ 运行期中止 ⇒ **到不了那一行** ⇒ 该文件**后半**的划出面**全部数不出来**。
  ⇒ 因此 §3.2 的对照表里那条 **+365** 不是「新增了 365 个缺口」，而是**把欠计量补回来**。
- **处置依据（`L0` D2）**：①下游以它为基准 ✅（本条的终端判据与②的读数皆必经它）·
  ②工作量小 ✅（两处各补一句）⇒ **当场修**。
- **判据**：`check-ir-lower.sh` **判据④**（两处逐点覆盖 + **阴性对照**）；
  **变异反证四条**（M1/M2 各只红④；M4 只红④且**差异恰在阴性对照行**；
  ⚠️ M3 被③先抓住 ⇒ **如实登记它不是④的自证**）。

## 4. 速度：量化后的速度问题

> 本轨的速度基线是受管载体（自举仓 `tools/baseline-p2-0.tsv` + `docs/baseline-p2-0.md`），
> ⛔ 本件不复写那份账；下面只做**合读**，并补一条**本批新测**。

| 量 | 值 | 出处 |
|---|---|---|
| 宿主 `pini check .`（46 文件 / 22338 行） | **0.68 s** | P2-0 读数件 |
| 自举前端检查**自身**（`pini run . module-check`） | **> 688 s**（下界，观测被杀） | P2-0 读数件 |
| 自举前端**逐份解析+降载**全源（47 份） | **250.3 s**（逐份累计） | **本批新测**（自举仓 §46.4） |
| 层入口固定成本（23 个入口） | 2.33–3.35 s | P2-0 读数件 |

**两条可说的**：

1. ⭐ **同量级输入下 ≥1000×**：宿主整模块检查 **0.68 s** vs 自举前端检查自身 **>688 s**
   —— 输入是**同一批源码**。成因 = **双层解释**（自举前端本身跑在宿主解释器上）。
   ⇒ 这正是 **P3（AOT / CodeGen）** 的理由，⛔ 不是「优化一下就好」的量级。
2. ⭐ **单位成本里约一半是固定段**：本批量得 **250.3 s / 47 份 ≈ 5.3 s/份**，
   而 P2-0 量得的**层入口固定成本**是 **2.33–3.35 s/次**
   ⇒ 真正干活的部分 ≈2–3 s/份，其余是「种子启动 + 加载并检查整模块」。

⚠️ **口径提醒（⛔ 别把不同物相除）**：「自举前端**整模块检查**」含类型检查，
「逐份 **parse+lower**」不含 ⇒ 两者**不是同一个量**，⛔ 别拿 250.3 / 0.68 当倍数。

⚠️ **一条未取到的量，如实登记**：「全源端到端」的**墙钟**今天**取不到** ——
因为 ③ 的入口不存在（§2.1）。⇒ ⛔ 本件**不给**这个数的估计值。
