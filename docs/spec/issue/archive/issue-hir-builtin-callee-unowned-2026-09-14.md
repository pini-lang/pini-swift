# Issue：HIR 通道不解析「裸内建 callee」——`sqrt` 一类调用无归属，两夹具停在翻转阻塞槽

- 状态：**LANDED（2026-09-16 关闭；LR-4「P4-0 判据面清零」批交付并实测核验）** —— 关闭依据与残余归属见文末「关闭记录」。
- 发现渠道：G5（具名类型与字段）**开工期的范围裁决**。删除「委托解释器求值内建」这一选项后
  **实测出代价**，本单是把这个代价从「口头取舍」变成**在册的、可被后续裁决的边界**。
- 归属：**被调者解析规则（callee resolution）**，**不是节点族**。
  ⇒ **P2a 九格按节点族切分，故九格无一拥有本项** —— 这是本单存在的根本理由，
  且它不是「规划漏了一个节点」，所以**不能靠往某格加一个节点名来消化**。
- 关联：
  - `docs/issue-interpreter-hir-plan-2026-09-12.md`（LR-4 逐格实录）；
  - `docs/issue-interpreter-hir-p2-plan-2026-09-13.md` §8.5（G5 实录，本单的来源格）；
  - G7（字符串与内建）—— **候选归属**（见下方「归属候选」）；
  - P4（删除 AST 走查）—— **本单影响它的翻转门槛**：两个 `GAP_EXEC` 阻塞挂在门槛上，
    且因无归属而**不会被任何格的交付清掉**。

## 现象

内建函数调用（`sqrt` / `abs` / `argv` / 文件 IO …）在 HIR 层面**就是普通 `call` 节点**，
被调者名字**不在 HIR 的任何表里**（既不是 `functions`，也不是类型方法表）——它的语义活在
解释器内部一条 `if fv.name == …` 长链上，而那条链是**有状态的**（`processArguments`、
`outputSink`、文件 IO），无法在不做无关重构的前提下抽成静态单源。

G5 的裁决是**不委托**（不把 callee 交给一个活的 `Interpreter` 求值），
于是这类调用在 HIR 通道**按名响亮拒绝**，并把理由写进错误文本。

## 实测代价（不是估计）

| 项 | 事实 |
|---|---|
| 受影响夹具 | **2 个**：`Tests/PiniTests/CodeGen/HIRTests/HIRDifferentialTests/testDiffStructValue.pini`、`examples/struct.pini` |
| 两者共同点 | 方法体末尾调用 `sqrt`（`libc`） |
| 判定迁移 | `HIR_ENGINE_TODO` → **`GAP_EXEC`**（错误 `E5-006`），**不是**留在 pending |
| 翻转阻塞 | 全量探针 `FLIP BLOCKERS` **23 → 25** |
| 阻塞槽身份 | 逐夹具对账确认：**新增 2 个面孔**（上述两夹具），**0 个离去** |

⚠️ **代价比开工时的预测更糟**：开工时预期这两个夹具「仍停在待办列表」。
实测是**它们从待办列表向上迁移成翻转阻塞** —— 因为 `construct` 通了，夹具**走得更远**，
死在后面的 `call` 节点上。这是「每实现一个节点，这层屏蔽就薄一分」的又一实例，
但**与既有 `E7-001` 假阳性族不同**：本项是**实质失败**（`rc` 非零），不是诊断面差异。

## 为什么 G5 之前不暴露

**首缺口遮蔽**：这两个夹具在本格之前的首缺口是 `construct`，探针只报「最先撞上的那个缺口」，
于是后面的 `call` 节点**一直不可见**。G5 交付 `construct` 后，遮蔽物移走，本项才浮现。
⇒ 本单也是「**首缺口分布 ≠ 夹具覆盖**」这条既有结构性发现的又一个实证。

## 归属候选（供后续裁决，本格不预设结论）

| 选项 | 说明 | 代价 |
|---|---|---|
| **① 独立工单**（**本格已选**） | 记录为独立边界，不由任何格消化 | 阻塞数停在 25，直到有格/批接手 |
| ② 归 G7（字符串与内建） | G7 行名含「内建」，且它已含 `isAsciiDigit` / `printMulti` 等内建味节点 | G7 的清单是**节点名**，而本项是**规则** ⇒ 会重演同一类「账目口径错位」 |
| ③ 单开一格 | 结构上最诚实 | 破坏「九格」的规划口径，且 P2a 已近尾声，**扩格即扩规模** |

**本格的裁决与理由**：取 **①**。三条依据 ——
1. **结构性**：本项是规则不是节点，九格按节点族切，故**无一格天然拥有它**；
2. **可逆性**：立单是可逆的纯增量 —— 将来若裁决归 G7，**工单即交接点**，不返工；
3. **规模纪律**：P2a 中途扩格会破坏规划口径，而本项**当日零用户可见后果**
   （两夹具是语料/示例，不是用户程序）。

## 处置建议

**不排期**。优先级随两件事抬升：① **G7 开工时**（若裁决并入，则随之处理）；
② **P4（翻转）之前**（否则门槛上永久挂着两个无主阻塞）。
实现时的注意点（供接手者）：**不要**为此在 HIRExecutor 里重写一个 `sqrt`
（那会是 `sqrt` 的第二份、会漂移的定义）；正解是**把解释器那条链抽成静态可调用的单源**，
或**按裁决正式引入受限委托并同时裁齐 IO 语义**。

### 交付形态（与本单建议逐条对应）

本单「处置建议」写明：「**不要**为此在 `HIRExecutor` 里重写一个 `sqrt`（那会是 `sqrt` 的第二份、
会漂移的定义）；正解是**把解释器那条链抽成静态可调用的单源**」。交付即此 ——
`Sources/PiniCore/Interpreter/Interpreter.swift` 的 `builtinSqrt`（连同 `builtinAbs` /
`builtinMin` / `builtinMax` / `builtinSin` / `builtinCos` / `builtinTan`）为**静态单源**，
`Sources/PiniCore/Interpreter/HIRExecutor.swift` 调同一份：**HIRExecutor 里没有第二份 `sqrt`**。

同批另把 libc 预注册表提为 `Interpreter.libcShims`（8 个 shim 的单源），并在 `.call` 落点加
**declared-foreign 门**（只回答模块**自己声明过**的 foreign 名）⇒ `malloc` 一类的裸内建 callee
**也有归属**了。交付读数与变异反证见 `docs/issue-interpreter-hir-plan-2026-09-12.md` 的 P4-0 条目。

### 残余**不属本单**（避免「关闭即当无事」）

`argv` / `moduleRoot` 在 HIR 下仍不可用，但**失败面不同**：它们在**降载层**被拒
（`unsupported feature 'call to unknown function 'argv' …`），即 **lowerer 无对应节点**，
而**不是**本单的「executor 侧 callee 解析」。
⇒ 归属 = `docs/issue-hir-p4-plan-2026-09-16.md` 的 **P4-2「前置核对」** 行
（该行明写「`argv` / `moduleRoot` 在 HIR 侧无节点」），**本单不重复登记**（同一件事不要两个状态源）。
