## 2. 两个方案

### 方案 A · 维持单行（不改）

- 理由：块文法（F5）只有「缩进块 + 顶格块」两种形态，括号内换行会引入第三种「表达式内跨行」规则，钉定面变大；现语料（897 夹具 + examples + 自举）零跨行字面量使用。
- 代价：长集合字面量可读性受限；与草稿意图偏离（草稿为意图参考，非权威）。

### 方案 B · 引入跨行（括号内容忍 NEWLINE）

- 语义：`( )` / `[ ]` / `{ }` / `< >`（类型实参）内部允许换行，换行等同空白；缩进不参与（括号深度即结构）。
- 代价：F5 钉定批须增加「括号内记号流」维度；lexer 的 newline 发射策略需按括号深度抑制（lexer 改动，波及 L0 门禁语料与自举 lexer——自举 lexer 的 newline 发射须同步）；错误恢复路径需重新验证。
- 收益：大集合/结构体字面量的可读性；与 Swift/Python 等参照系一致。

## 3. 影响面实测（2026-08-31）

- 语料：全仓 .pini 无跨行字面量使用（grep 括号未配平行零命中）——方案 A 零迁移；方案 B 亦零迁移但**实现+门禁成本实付**。
- F5 钉定批依赖本裁决：A 则 F5 只钉「缩进块 + 顶格块」；B 则加第三维度。

## 4. 裁决

**采纳方案 B**（用户，2026-08-31）：括号内容忍 NEWLINE，换行等同空白，缩进不参与（括号深度即结构）。

## 6. 实施记录（LANDED，2026-09-01）

### 6.1 语料普查修正了实现落点（§5 原方案的必要细化）

Phase A 普查（全仓 `.pini` 行尾括号未配平行）命中 11 处，分两类，**「深度>0 即抑制」的字面规则不成立**：

1. **畸形错误夹具 8 行 / 3 文件**（`[Bad1|notakw` 无闭合 `]`，靠行级恢复收集多错误）→ 抑制会吞掉恢复点。迁移：补 `]` 配平。实测 E2-005 错误类型/位置/消息完全保留。
2. **括号内块体 3 处（合法在用）**：`LazyRef<I32>(func () -> (I32,):` 实参位函数字面量块体——块体语句边界依赖 newline/INDENT/DEDENT，简单抑制会杀死它。

用户裁决（路 C）：**块携带括号标记制**——依据是草稿在册的 IIFE 语法（`docs/spec/Pini草稿.md`：`(func ...:\n body\n)(实参元组,)`），块携带括号是草稿注册特性的承重结构，禁止会废掉 IIFE。设计原则（用户）：任何子块由「引导子块的关键字」开启；块体进括号 = 整个子块被圆括号包裹。

### 6.2 终版规则

- **抑制判据 = 最内层未闭合括号是普通括号**：行尾不发 newline、行首旁路缩进处理（空白照消费）。
- **块携带** = 开括号后同行紧跟 `func`（关键字边界校验；`` `func` `` 不算；前瞻不跨行）→ 内部布局完全照常（LazyRef/IIFE token 流与改前逐字节相同）。
- 已裁边界同 §2.2 新增条目（D-5/D-6/D-7 + 反引号 + 同行前瞻）。
