## 1. 处 A · `split` 的两处分配缺陷

两处都在同一个函数里（`IREmitter.emitStringSplit`），**可见性不同** —— 这是本批把判据做成两条的理由。

### A1 · 固定 1024 字节栈缓冲 + 无界 `memcpy`（**可达且致命**）

- **形态**：两次暂存拷贝各写 `alloca i8, i64 1024`，随后 `memcpy(buf, source, strlen(source))`。
  源串超过 1024 字节即**砸栈**。
- **可达性（本批测出）**：自举的 `makeScanner` 是 `s.lines = source.split("\n")` —— **源串就是整份文件文本**
  （本仓自举源码单件数十 KB）。⇒ 这不是理论缺陷，它每次都踩。
- **实测**（最小探针：40 × 70 = **2800** 字节源串）：

  | 通道 | 修前 | 修后 |
  |---|---|---|
  | 解释器（权威） | `2800` / `40`，rc=0 | 同左 |
  | 原生（`run-llvm`） | `2800` 后 **崩**（栈转储落在 `bk_array_set → _bkEnsureUnique`） | `2800` / `40`，rc=0 |
  | 原生 + ASan | **SEGV on unknown address**（写访问） | 无报告，读数同解释器 |

### A2 · token 复制按 `strlen` 分配后 `strcpy`（**无行为签名**）

- **形态**：`dupLen = strlen(token)` → `malloc(dupLen)` → `strcpy(dupBuf, fillTok)` ⇒ 终止符写到**区外一字节**。
- **实测**：ASan 报 `heap-buffer-overflow: WRITE of size 85 → 84-byte region`，栈是
  `strcpy ← makeScanner ← tokenize`（自举 `semantic` 层，0.1 s 内复现）。
- ⚠️ **它没有行为签名**：越界的那一字节通常无声。⇒ 常设判据只能判**产物结构**（见 §2 判据②），
  行为级证据由上面的 ASan 读数承担（**一次性证据，⛔ 不是常设门前**）。

### 修法（两处一起）

| 位置 | 修前 | 修后 |
|---|---|---|
| 两次暂存（`countBuf` / `fillBuf`） | `alloca i8, i64 1024` | `malloc(slen + 1)`；末尾 `free` 两处 |
| token 复制（`dupBuf`） | `malloc(strlen(token))` | `malloc(strlen(token) + 1)` |

⚠️ **两处刻意都不再用「固定常数」**，也⛔ **不在循环里留变长 `alloca`** —— 后者是本仓 `stringSubstring`
那条已登记的教训（栈按 N²/2 增长）。尺寸一律由**源串长度**算出。

## 2. 处 B · 单文件 LLVM 入口缺语义门禁（`E3-008` 覆盖面分叉）

- **症状**：同一份源 `check` / `run` 报 `E3-008`（闭包捕获须声明），而 `emit` / `compile` **照跑并产出目标码**。
- **根因**：`emit` / `compile` / `run-llvm` 走 `typeCheckThenGenerate`，它只跑 `TypeChecker`，
  **没有跑 `SemanticAnalyzer`**。而另两条入口都跑：`check`（`checkSingleFileDiagnostics`）跑，
  **模块级** `emit`（`runIRPackageEmit`）也跑。⇒ 是**单文件 LLVM 入口**这一处漏了，不是「后端分工」。
- **修法**：在 `typeCheckThenGenerate` 里补语义门禁，与另两条**同序**（语义 → 类型；语义不过即退出）。
- **修后四条入口同判**（阴性夹具 `closure-capture-undeclared`）：

  | 入口 | 修前 | 修后 |
  |---|---|---|
  | `check` | 拒 `E3-008` | 拒 `E3-008` |
  | `run` | 拒 `E3-008` | 拒 `E3-008` |
  | `emit` | ✅ **放行**（产出 237 行 IR） | 拒 `E3-008` |
  | `compile` | ✅ **放行**（印出 102） | 拒 `E3-008` |

- **对照（阳性夹具 `closure-capture-declared`，只多一行 `capture k`）**：四条入口**全部放行** ⇒
  判据不是「凡闭包必拒」。

## 3. 判据与变异反证

### 3.1 判据（两条套件、四个用例、四个夹具；全部进常跑集）

| 套件 | 用例 | 判什么 |
|---|---|---|
| `EntryParityTests` | 闭包捕获未声明：四条入口同判拒绝，判定码都是 `E3-008` | 四入口一致（阴性） |
| | 闭包捕获已声明：四条入口全部放行 | 四入口一致（阳性对照） |
| `SplitPathTests` | 长源串：LLVM 侧读数与解释器**逐字节相同** | 行为级（对 A1） |
| | 切分路径的 `malloc` 尺寸不得直接取 `strlen` 结果 | 产物结构级（对 A2） |

⚠️ 判据②的口径写明：它只判「**直接取自**」，不判算错 —— `strlen+1` 与更宽裕的常量都放行。
⚠️ 「拒绝面」一律判**哪条规则拒的**（取判定码），⛔ 不只看退出码（四条入口的退出码都能是 1）。

### 3.2 变异反证（三条，每条只打自己）

| 变异 | 期望 | 实测 |
|---|---|---|
| **M1a** 两次暂存改回固定 1024 | 行为判据红 · 结构判据绿 | ✅ 行为判据红（2 条夹具各一次）· 结构判据绿 |
| **M1b** token 复制改回 `malloc(strlen)` | 结构判据红 · 行为判据绿 | ✅ 结构判据红 · 行为判据绿 |
| **M2** 去掉 `typeCheckThenGenerate` 的语义门禁 | 阴性一致判据红 · 阳性绿 | ✅ 阴性红（`emit`/`compile` 两条）· 阳性绿 |

### 3.3 ⚠️ 一处自犯（本批最值得记的一条）

**判据②首版是空转的**（恒绿）：发射器写出的 IR 行**以空格起头**，而我的解析按 `hasPrefix("%")` 取临时名
⇒ 集合恒空 ⇒ 「没有违规」与「判据根本没在判」外观相同。
**抓出它的正是 M1b** —— 变异之后它**没有红**。修好（先 trim）之后 M1b 才红。
⇒ 定式：**判据写完先问「未修时它会红吗」，红了再谈绿**；一条从不红的判据不是判据。

## 5. 边界与未解决（本批**未**解决）

1. ⛔ **「门禁慢」未解决**（§0）：门禁仍走双层解释；原生臂未接；且原生 `module-check` 仍崩。
   ⚠️ 本批**改善了前置**：切分缺陷修掉后，ASan 配置下自举层从 **3 / 19** 升到 **16 / 19** 干净。
2. ⛔ **自举剩余缺陷是另一个族（本批只定位、未修）**：
   - ASan 配置下仍有 3 层报错：`type-seg4a`（SEGV，地址满 `0xbe` —— ASan 的未初始化填充字节）·
     `type-seg4b` / `type-seg5a`（**heap-use-after-free**）。
   - ⚠️ 非 ASan 配置下**读数不稳定**：同一二进制重复跑同一层，`semantic` 三次读数为 `rc=133 / 133 / 0`
     （rc=0 那次输出 **63 字节，与解释器逐字节相同**）⇒ 剩余缺陷是**非确定性内存缺陷**，
     其现形与否取决于分配器布局。⇒ 与切分缺陷**不同族**，须另立条目。
3. ⚠️ **语义警告面未动**：`run` / `check` 打印语义警告，`emit` / `compile` 不打印。本批只补**阻断性**检查
   （那才是「同一条规则两条路不同判」的缺陷）；警告面差异**如实登记**，未顺手改。
4. ⚠️ **ASan 是一次性证据，不是常设门前**：本仓门禁不依赖 ASan。⇒ A2 的常设判据只能是产物结构级（§3 判据②）。
5. ⚠️ **未 push · 未删分支**。
