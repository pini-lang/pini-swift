## 1. 需求原文（用户 2026-09-01）

> 括号内文法有变动：`func(a = 1, b = 2)`。概要就是：实参用等号，顺便要展开想想词典如何写。

拆解为两条：①**调用点的实参加等号**（名字 → 值的绑定记号由 `:` 改为 `=`）；②**字典字面量怎么写**需展开论证（本文 §4）。

### 2.1 `:` 当前承载的四重语义

1. 类型标注：`n: I32`、`x: I32 = 0`
2. 块开启（H-4 强制）：`if 条件:`、`func() -> ():`
3. 字典映射：`["Alice": 30]`
4. 标签：枚举具名构造 `identifier(text: "x", loc: 1,)`、带标签调用 `f(x: 1)`、标签元组 `(a: 1,)`、match 具名绑定 `case identifier(text: s, loc: l):`

## 3. 连带影响面（「实参用等号」波及的四个形态）

记法切换后，自然的界线是：**`:` = 类型标注 + 块开启；`=` = 值绑定/关联**。据此四个形态需逐个裁量：

| # | 形态 | 现写法 | 是否属「实参」 | 候选 |
|---|---|---|---|---|
| 1 | 形参声明（类型） | `n: I32` | 否（声明侧） | **不变** |
| 2 | 形参默认参数 | `n: I32 = 1`（EBNF 已在册） | 否（声明侧的值绑定） | **不变**——与「`=`=值绑定」自洽，是新记法的一个支撑点 |
| 3 | 调用点带标签实参 | `f(a: 1)` → `f(a = 1)` | **是** | 改 `=`；是否同时废弃 `:` 待裁（D-1） |
| 4 | 枚举具名构造 | `identifier(text: "x",)` | 是（构造调用） | 是否同步 `=` 待裁（D-3）；G54 已钉定，改动属破坏性 |
| 5 | 标签元组字面量 | `(a: 1,)` | 边界（字面量非调用） | 待裁（D-4） |
| 6 | match 具名绑定 | `case A(x: v):` | 否（**解构绑定方向相反**：字段 → 变量） | 建议保留 `:`，待裁（D-5） |
| 7 | 切片 `a[i:j]` | 分隔符，非关联 | 否 | **不变** |
| 8 | 字典字面量 | `["Alice": 30]` | 见 §4 | 待裁（D-2） |

冲突点记录：规则 3.15 明文禁止枚举用例括号内出现 `IDENT '='`，本需求须同步修订该条（否则新记法在枚举构造处非法）。

## 4. 字典怎么写（用户指定展开）

字典的「键 → 值」是**运行时数据关联**；调用的「参数名 → 值」是**编译期可校验的名字绑定**。二者同形不同类，故有两种正统立场：

### 立场 A · 统一用 `=`：`["Alice" = 30, 1 = "x"]`

- **理由**：①与「实参用等号」同一条原则——括号内 `=` 一律是关联记号；②EBNF 已有 `IDENT '=' expression`（默认参数）作先例，`=` = 值绑定的语义已存在；③批 1.5 后括号内 `:` 失去块开启语义，顺势把括号内的关联记号统一为 `=`，`:` 收敛为「类型标注 + 块开启」两类，记号面最干净；④键为任意值（`"Alice"` / `1` / 变量），与参数名同处 LHS 位置，句法消歧无负担（首个 `=` 出现即判为字典）。
- **代价**：46 处 / 34 文件迁移；**空字典仍无字面量**——需另定（`[:]` 已被全切片占用，见 §2）。

### 立场 B · 保留 `:`：`["Alice": 30]`

- **理由**：①Python 先例（`{"a": 1}` 映射 vs `f(a=1)` 绑定），映射与绑定分属两类语义、记号不同反而传递信息；②零迁移。
- **代价**：`:` 继续承载三类语义；混合表达式 `f(a = 1, d["k"])` 中两种记号并存需读者分辨；与「括号内统一关联记号」的收口方向相背。

### 立场 C · 用 `=>` 作映射记号：`["Alice" => 30]`
- **否决**：`=>` 已是 async 箭头（`func (…) => (…)`），复用必致歧义。

### 我的推荐

**立场 A（字典用 `=`）**。核心理由是记号面收口的净收益：`=` 专司值绑定/关联、`:` 专司类型与块，且这与默认参数 EBNF 的既有 `=` 语义同向；代价（46 处迁移）相对于全仓规模可一次性消化（批 2 刚完成 218 处迁移，工具化 sed + 复核路径已验证可行）。

**配套建议**：空字典字面量缺口应随本批补齐（候选：`[,]`？`[=]`？或走类型构造 `字典<键, 值>()`——后者更自洽，不新增记号）。此项列为 D-6。

## 7. 裁决记录（2026-09-02，用户「按你的建议来」）

### 7.1 总原则：注入 `=` / 取出与标注 `:`

> **`=` = 值的注入方向**（给名字/键绑定一个值）；**`:` = 类型与块的标注方向 + 值的取出方向**（解构绑定、类型标注、块开启）。

### 7.2 逐条裁决

| # | 裁决 | 理由 |
|---|---|---|
| D-1 | `f(a: 1)` **报错废弃**，提示改用 `f(a = 1)`；不留双记法 | Pini 既有做法是破坏性切换 + 一次性迁移（G50、H-4、批 2）；并存会留下两种实参记法。走 Provisional 窗口（§1.3） |
| D-2 | 字典字面量 → **A**：`["Alice" = 30, 1 = "x"]` | 括号内关联记号统一为 `=` |
| D-3 | 枚举具名构造 → **同步** `identifier(text = "x", loc = 1,)` | 与 `f(a = 1)` 同属实参绑定；属 G54 破坏性修订，走 §1.3 |
| D-4 | 标签元组字面量 → **同步** `(a = 1,)` | 构造侧（值 → 名字）；match 模式位保留 `:`（D-5） |
| D-5 | match 具名绑定 `case A(x: v):` **保留 `:`** | 解构方向（字段 → 变量），与「取出用 `:`」一致 |
| D-6 | 空字典**不新增记号**，走类型构造 `字典<键, 值>()` | `[:]` 已被全切片占用（须先确认 Pini 侧类型名拼写） |
| D-7 | 形参侧（`n: I32`、`n: I32 = 1`）**不变** | 声明侧；默认参数的 `=` 与「`=`=值绑定」自洽 |
| D-8 | **并入批 3**（与 F5 块文法钉定同批） | 同属「括号内文法」，一次钉死，避免钉定面返工 |

### 7.3 迁移方法（关键决策：不用盲改正则）

标签 `:` 在**模式位**与**声明位**必须保留，盲改正则必然误伤（`case A(x: v):` 与 `f(x: v)` 同形）。采用**检查器驱动的迁移**：

1. 先落地解析层改动：`=` 通过、`:` 报错（报错携带精确 file:line:col）。
2. 跑 `pini check` 收集全部报错位置，**按位置逐点改写**（非正则扫全文件）。
3. 迭代至零报错，再跑全量测试与门禁。

每个改写点都由编译器判定过上下文，不会误伤模式位与声明位。
