### 1.5 外部行为调研：Swift 的默认实例语义（2026-09-19 实测）

用户第 11 条要求「先调研 Swift 行为，不一致再问我」。四个独立编译单元的探针（`swiftc` 6.4 · macOS · arm64）：

| 问题 | 实测输出 | 与「读法一」的关系 |
|---|---|---|
| `static let` 是否惰性 | 首次访问**之前**初始化日志计数为 0；访问后才出现记录 | 支持「未访问不物化」 |
| 并发首次访问是否**恰一次** | 64 路并发取用 ⇒ 不同实例数 **1**、初始化次数 **1** | 支持「恰一次」 |
| 同模块**两个文件**是否各得一份 | 另一文件取到的 id 与本源取到的**相同** | **否证**读法二（「每个使用它的文件各自实例化一份」） |
| 跨模块 `import` 是否共享 | 访问前计数 0 → 首次访问后 **1**；引入侧**两个文件**取到的 id 相同，最终计数仍为 **1** | **支持读法一**：存放位与初始化都在**定义侧**，引入侧只引用 |
| 定义侧的文件级全局 `let` | 同样惰性、同样跨文件共享 | 文件级槽位与类型级槽位行为一致 |
| 泛型类型的 `static` **存储**属性 | ⛔ **编译错误**：`static stored properties not supported in generic types` | ⇒「每特化一份」的槽位**不能**是一处通用存储，必须由编译器**按特化合成**（§2.4） |
| 泛型类型的 `static` **计算**属性 | 可用；同特化稳定、跨特化不同 | 特化粒度与既有泛型机制自洽 |

⇒ **读法一成立**，与用户倾向一致，**无需回问**。附带一条对 P2 有用的推论：泛型给定块的槽位必须**逐特化合成**，与用户第 7 条「每特化一份且必须带默认构造」自洽。

### 1.6 `[[T]]` 的含义重叠怎么收（用户第 12 条）

两条现状实测：`[[T]]` 在解析期被钉为 `.enumExt`，而该 kind **在降载层没有任何消费者**（§1.2）；全仓 `.pini` 语料对该形态**零使用**。于是有两条落法：

| 落法 | 做什么 | 代价 |
|---|---|---|
| **① 语义按被扩展者分派**（**采用**） | `[[X]]` 保持「方括号 = 通用扩展」的原意：扩展语义由 **`X` 的类别**决定（枚举 / 给定块） | 归并处须按目标符号类别分派；「kind 由定界符决定」变为「kind 由解析结果决定」，须在规范写明 |
| ② 另立 `.givenExt` | 新增一个 kind，定界符仍取 `[[` | 定界符与 kind 不再一一对应，两种 kind 抢同一形状，更绕 |

用户第 12 条的「方括号本身应是通用的，其他扩展应是糖」= 落法 ①：`((` / `{{` / `<<` 是**按类型类别专门化的糖**，`[[` 是通用形。**另一条佐证**：声明位 `[名]` / `[名\|修饰符]`（单方括号）本来就是**声明总线**（枚举声明 + `[名称\|import]` / `[名称\|export]` 块）⇒ `[名\|given]` 落在同一分支，扩展位取 `[[` 与之一致。

⚠️ **须留痕的一处**：`.enumExt` 无消费者 ⇒「枚举扩展块」在当前 HIR 路径下**可能从未生效**（语料零使用 ⇒ 无观测，无法判「缺陷」还是「未实现」）。本件**不顺手改**（超范围），只登记为待点名项（§7）。

## 2. 默认实例的承载方案（已裁：方案 B）

### 2.1 为什么必须新建面（已不是待裁，是定案前提）

ADR §2.2 承诺四项行为：**惰性** · **恰一次** · **地址稳定** · **无启动风暴**。这四项都需要一个**存放位**（「这一份实例放在哪」）与一个**物化入口**（「谁来跑各字段初值」）。

实测表明现成的路都不通：

| 看似可用的设施 | 为什么不成立 |
|---|---|
| `LazyRef<T>` | ⛔ 用户第 4 条已裁定：它只在**字段内部**做细粒度缓冲，**不**承担默认实例的物化 |
| `HIRModule` 的四个面 | 都不是「模块级可变状态」的载体 |
| 顶层 `let` | ADR §1 背景表已列：无模块级绑定语义、无程序级唯一性、无惰性 |
| `IREmitter` 的 `global` | 仅 `@__stdinp`（外部声明），不是语言层定义的存放位 |

⇒ **「零新运行时机制」这句（ADR §4.1）在实测下不成立**，须订正为「零新**惰性**机制；默认实例的**存放位**与**物化入口**是最小的新面」。

### 2.2 候选对比（A 已排除 · C 未被选 · **B 定案**）

**方案 A（扩 `LazyRef` 元素 ABI）—— 已由用户第 4 条排除。**
补充实测证据（说明它本来就贵）：`IREmitter.lazyRefElemABI` 只认 5 种元素（`i32` / `f64` / `boolean` / `string` / `char`），其余落 `fatalError`；且 `bk_lazyref_value` 的语义是**每个 handle 一次**，而默认实例需要**每类型一份**——语义层级不同，不是加一条 case 能解决的。

**方案 B（新增最小运行时面 `bk_given_*`）—— ✅ 用户第 10 条定案**

- **读法**：用户第 11 条取**读法一**（声明所在文件发射槽位与初始化函数，其它文件 import 后引用**同一份**）⇒ 下面「跨文件/跨模块」那条落法**已定**。

- 形状：`bk_given_get(slot, init_fn, bytes) -> ptr`。内部：`*slot == null` 时加锁 → 分配 → 调 `init_fn` → 写 slot；否则直接返回 `*slot`。
- `slot` 是**发射层定义的静态全局**（`@__given_<T>`），地址天然稳定；`init_fn` 是发射层**合成的具名函数**（先例：`IREmitter.ensureLazyRefWrapper` 已在合成 wrapper）。
- once 骨架**照抄** `bk_lazyref_value`（`NSLock` + 缓存），成本约 20 行。
- 跨文件/跨模块：定义处发射 slot，使用处 `external global` 引用（**沿用 `@__stdinp` 的既有先例**），链接期可见性**随类型可见性**（用户第 6 条）。
- HIR 侧：新增**一个表达式节点**（如 `givenDefaultInstance(type:)`），语义写「取该类型的默认实例；惰性物化、恰一次、地址稳定」，三锚点齐备。

**方案 C（纯发射层：静态全局 + 一次性守卫，零新符号）—— ❌ 未被选（用户第 10 条选 B）**

- 优点：零新运行时符号。
- 代价（三条，逐条实测支撑）：
  1. **线程安全要自己写**——而一旦为此调用运行时原语，就退回方案 B。
  2. **两台引擎各写一套 once**——`HIRExecutor` 侧要独立的表 + 标志。这与 `LR-4` 的判据（「同一程序在每个后端意思相同」，手段是「单一 C-ABI 边界 + HIR 为唯一中枢」）**正面冲突**，且要额外用差分夹具去守两侧一致。
  3. **省不掉 HIR 新节点**——「此处须做一次且仅一次」这个信号在 HIR 里仍需表达，否则两台引擎只能靠约定各自猜。
- ⇒ **相对 B 只省 1–2 个符号，却多一份双实现风险。**

### 2.3 定案与理由（用户第 10 条：**选方案 B**）

**已裁 = 方案 B**。理由三条（上轮据以推荐，用户采纳）：

1. **与 `LR-4` 的方向一致**：once 逻辑只写一次（运行时），两台引擎调同一个语义。方案 C 要维护两份并额外立差分判据。
2. **用户第 6 条（文件级 + 可见性一致）在 B 里是自然结果**：slot 由**声明文件**定义、随类型可见性导出，使用文件 external 引用 —— 不需要额外的机制设计。
3. **成本已被实测锚定**：`bk_lazyref_value` 的骨架可直接照抄；`HIRTypeDecl.Field.defaultValue` 已存在；`HIRExpr.construct` 三锚点已在 —— 真正的增量只有「一个节点 + 一条契约 + 1–2 个符号」。

### 3.7 `P2a` 执行实录（2026-09-19，默认实例取用：节点面 + 运行时符号）

**一句话**：`P2a` 把「默认实例取用」从**预留位**变成**存在的节点**（契约 §2.46 + 三锚点）与
**存在的符号**（`bk_given_get`），并**刻意不改动任何语言可见行为** —— 交付后语言侧与交付前**逐字相同**，
「可见行为改变」这件事留给 `P2b`。

**用户裁定切分**（本批开工时的两条指令之一）：`P2` 的面太多（运行时 / HIR / 发射 / 引擎 / 降载），
一次做完则**中途无从验收** —— 故切为 `P2a`（地基，零可见行为）与 `P2b`（接通，语言可见）。
切分线取「节点是否存在」而不是「功能是否走通」：`P2a` 的完成态可以用契约器械**机械判定**。

| 层 | 改动 | 备注 |
|---|---|---|
| HIR 节点 | `HIRExpr.givenInstance(type:)` | **无源形态**（默认实例在源语言里由 `using` 省略实参时**隐式**取用）⇒ 打印成内部名 + 类型 |
| 三锚点 | `HIRPrinter` 打印 · `HIRExecutor` 报 `invalidOperation` · `IREmitter` **两处**（主 dispatch `fatalError` + 结果类型推导） | 起步 **fail-loud**，照 §2.45 `join` / §3.17 `detachStmt` 先例。⚠️ 落点由**编译器穷举报出** —— 共 4 处，`IREmitter` 占两处（漏第二处会让类型推导静默失配） |
| 运行时 | `bk_given_get(slot, init_fn, bytes) -> ptr` | once 骨架照抄 `bk_lazyref_value`；⚠️ 但**锁要两级**（见下） |
| 契约 | §4.3 由预留位降为**兑现记载** · §2 新增 §2.12 + **第 46 条** · §5.2 清单 **37 → 38** | ⚠️ §2 标题原写「44 条」而**实际 45**（编号 1..45 无缺号）⇒ 本批顺手订正为 46 |
| 规范 | `G71` 行四处（预留位改兑现 · 排期加 `P2a` · 引用列 · 改动点状态） | 规范侧**无**逐符号清单（契约 §5.2 是单一权威来源）⇒ 规范只引用它与数字 |

**两级锁的理由（本批唯一的非平凡设计）**：`bk_lazyref_value` 只需要**盒内锁**（盒由调用方先建好），
而默认实例的**存放位由发射层给、首调时才建盒** ⇒ 「判空 + 建盒 + 写槽」这一段也必须串行，
否则两个线程会各建一个盒，同一类型物化出**两份**实例（地址不稳定 ⇒ 违反契约写明的语义）。
⚠️ 而**建盒的锁不得跨 `init_fn` 持有**：`init_fn` 会跑各字段初值，那些初值自己可能取用**另一个**
类型的默认实例 ⇒ 持锁调用就是一次可复现的**自死锁**。故两段分开、中间放锁。

**验收读数（实测）**：

- **契约器械**：**46 expr + 17 stmt = 63 cases**，三锚点 **63/63**，`clean`（改前 62/62）。

  ⇒ 「先登记后落码」在契约面**两个方向都拦**，这不是风格偏好而是器械事实。

  | 变异 | 红集 | 说明 |
  |---|---|---|
  | M1 去掉建盒的全局锁（两级降一级） | **1 条**（并发），且 **60/60 轮全部命中** | 两级锁的必要性的直接证据 |

⛔ **本批最值钱的实测：并发判据的形态决定它能不能抓住变异。**
初版写成 `concurrentPerform(64)` **单轮** ⇒ 实测**抓不住 M1**；改为信号量栅栏 + 40 轮 ⇒ **仍然抓不住**
（竞态窗口 = 「判空 + 分配」，约 **100ns**；而信号量唤醒线程的散布是**微秒级**，比窗口宽一个量级）；
改为**自旋栅栏**（线程不挂起、停在 CPU 上等令）+ 显式队列 + 主线程也参与 ⇒ 抓住了，且 60 轮**全部**命中。
⇒ 教训：**「并发判据通过」可能只说明它没真的并发**。判据的有效性本身要拿变异去证。

**两处如实登记**：

- ⛔ **`bk_given_destroy` 未加**（§2.4 成本表原写「+ 可能」）：存放位是发射层的静态全局、盒与**进程同生命周期**
  ⇒ **不需要释放钩子**；加它反而要引入一张 live 表。故清单停在 **38**，不是 39。
- ⚠️ **M2 的表现形态不干净**：持锁调用会让全局锁被**永久持有** ⇒ 同进程内后续任何取用默认实例的测试
  都会卡住，整份套件表现为**挂死**而非失败。已在测试件里登记，不假装它是干净失败。

**遗留（不在本批）**：物化面 —— 发射层合成 `init_fn` 与存放位 · `using` 解析 · 给定块撤 fail-loud ⇒ **`P2b`**。

### 3.8 `P2b` 执行实录（2026-09-19，默认实例物化面）

**一句话**：中间态结束 —— 给定块进**类型面**，默认实例在 `using` 取用点**真的物化**。
`a`（省略实参）、`g`（方法位）、`h`（泛型给定块）三类探针由红转绿，脚本从 10 个里 9 个红变成 9 个绿。

| # | 裁定 | 落点 |

| 2 | **字段缺初值 ⇒ 降载期就对每个给定块报** | 即使该块**从未被取用**也报（**语义收紧**，见下） |

只有经**引用字段**的更深层修改才可见」。⇒ 两臂同语义，且不预裁「值 / 引用语义」（与 `P1b` 的 `isObject: false` 对齐）。

**实测否证的三处计划措辞**：

1. **「跨文件 `external`」不必要** —— 整包降载为一个 `HIRModule`、发射为一个 IR 模块（`main.swift` 两处发射入口各只调一次 `emit(module:)`）；**真·跨模块没有通路** ⇒ 不覆盖面。

3. **「`using` 解析」一句话低估了面** —— 让 `using` 可省略牵动**检查器**的实参个数校验与**降载层**的三处 arity 守卫；且 `FunctionSignature` 与 `HIRLowererSignatureInfo` 各要补一个 `usingParamIndices`（**同一口径的两份**，不同步就会「check 过了、降载报错」）。⚠️ 我一度把检查器的 4 处 `E4-005` 全算进来，实测**只有 1 处**是函数调用的 arity（另 3 处是枚举用例与 match 绑定）—— 该过度声明当场订正。
