## 1. 四个结构位（**去命名**的）

> ⚠️ **为什么必须去命名**：跨实现的 `stage N` 编号**互相冲突**
> （同一件事在一个实现里叫 `stage2`、在另一个里叫 `stage1`）⇒ 跨实现引用该词**必然错位**。

| 位 | 含义 | 与 MVP 的关系 |
|---|---|---|
| **S** | **种子** —— 非本语言实现，够编出下一版即可 | 自举的前提，⛔ 不属 MVP |
| **P1** | **自产** —— 用本语言写、由**非自身实现**编出 | ⭐ **MVP 落在这里** |
| **P2** | **自洽** —— P1 能编出它自己 | **目标**，⛔ 不属 MVP |
| **P3** | **不动点** —— 再编一次，输出相同 | **正确性证明**，⛔ 不属 MVP |

## 2. 三条判据（可判定）

| 判据 | 内容 |
|---|---|
| **M1 自产** | 自举仓源码**全部用 Pini 书写**（**自写 C 例外**见 §4）；由**非自身实现**编出**可运行**产物 |
| **M2 符合 reference** | 产物在一组既有语料上的行为**符合 reference**（conformance）。⛔ **不要求**与宿主实现**逐条 diff 一致**、⛔ **不要求**三方两两一致。⚠️ 「reference」取**分面权威树**（§3.1），⛔ **不指**宿主实现 |
| **M3 不断链** | 存量源码**始终**落在「种子能编」的子集内；种子**冻结且可重建** |

⭐ **为什么是这三条**：**P1 之前，下面这些纪律没有对象可守** —— 没有「用本语言写的编译器」，
「不断链」「受限子集」全是空话 ⇒ **M3 就是「持续扩展」的实体**。

⚠️ **三条判据是分叉的，⛔ 不得合并读**：某一条达成**不等于**其余达成
（现况读自举仓 README「当前状态」段；本件不记读数）。两条读法纪律：

- ⛔ **不得**把「P1 已达成」读成「其余各层可停」，也**不得**读成「它们是欠账」——
  里程碑格是通往**下一档位**的**扩展轨**，每格开工须**独立点名**；
- ⛔ **不得**把「收口」读成「P2 自洽 / P3 不动点已达成」—— 该轨的终端判据是
  **覆盖面推进**，**不是不动点、也不是能编译自身**。

⭐ **措辞定式**：**P1 是判据，格是路线。**

## 3. 弱对比：判据的**右端**放什么

> 依据 = 用户裁定原话：「**找出权威文件 reference，把可靠性和比对建立在弱对比上。**」
> 本节规定的是**每一条判据的右端该放什么**；⛔ 本节不新增终端判据。

### 3.1 ⭐ reference **不是一份文件，是一棵分面权威树**

| 面 | 权威载体 | 判读要点 |
|---|---|---|
| **工程与治理** | `docs/spec/pini-spec-v0.md` | **首要入口**；「不一致时以本规范为准」 |
| **语言面描述** | `docs/spec/pini-reference-v0.md` | ⚠️ **只收已「递交」的成熟项** ⇒ 未递交的条款仍在规范侧 |
| **形式文法** | ⚠️ **规范件的 §A 附录**（⛔ **不在**语言参考） | 语言参考的对应章是它的**递交去处**，该递交**待完成** |
| **IR 节点语义** | `docs/spec/ir-contract.md` | ⭐ 「任一后端都不是定义处」 |
| **诊断码映射** | 代码资源 `Diagnostics.{en,zh}.toml` | 同目录 `docs/spec/diagnostic-codes.md` 自称**派生 / 低权威** |
| **证据** | `docs/spec/evidence-table.toml` | 自标 `citable=false`；新鲜度见 §3.2 |

⭐⭐ **一处会把人引错文件的陷阱**：规范件的事实源表把它**自己的 §A** 记在「语言参考」名下，
而同件的事实源索引写「**待递交**」⇒ ⚠️ **前者描述目标态、后者记录现况**。
⇒ 照前者写判据会**把权威判给另一个文件**。

### 3.2 ⭐ 一条决定设计形态的规则：证据新鲜度 **60 分钟**

证据自 `validated_at` 起 **60 分钟**内可信；>60 分钟 → `STALE`（**不得作为依据**）；>72 小时 → 待删。

⇒ ⛔ **「验证语言架构可靠性」不能落成一次性结论**（保鲜期只有 60 分钟）。
⇒ ✅ **它只能落成「可重跑协议」**：每项 = **命令 + 判据 + 最近实测**，数字**现跑现取**。

### 3.3 四定式（**本轨全部判据据此书写**）

| # | 定式 | 依据 |
|---|---|---|
| **1** | **比权威不比实现** —— 判据**右端**只能是 §3.1 树上的载体；⛔ 宿主实现**不得**作右端。⭐ **但宿主 CLI 可作「临时观察器械」**（`pini tokens` / `pini parse`）：**现查现取**，⛔ 不落成固化期望文件 · ⛔ 不因它绿而判绿；实测到的差异一律走定式 **4** 逐条归因 | IR 契约的「任一后端都不是定义处」；规范 §A.6 的命令行即宿主 CLI ⇒ 规范自己就把宿主 CLI 当**抽查器械**，⛔ 非定义处 |
| **2** | **判别式而非全量** —— 断言「规范**钉住**的那几条**可区分**性质」，⛔ 不比完整 token 流 / AST / 逐字节 | 规范 §A.6 的形态；手则判据纪律「**判据的区分力全在语料上**」 |
| **3** | **双向报缺口** —— 要求「有 A 无 B」与「有 B 无 A」**两个方向都报** | 契约器械的既有形态；⚠️ 单方向判据对「完全没实现」与「完全实现」**同形**，无区分力 |
| **4** | ⭐ **差异三分归因** —— 凡用临时器械（定式 1）实测出的**每一条差异**，必须归入三类之一：**① 自举写错** ⇒ 判红；**② 宿主缺陷**（须引规范 §3 台账的 `G` 号）⇒ **登记，不判红**；**③ 规范未定**（该面在权威树上查无载体）⇒ **登记为待补条款，不判红** | ⭐ 它是定式 1 的**配套**：宿主只作参照 ⇒ 差分的**读数**可信，而**判读**必须逐条归因。⛔ 不归因就会把**宿主的缺陷升格成规范要求** |

### 3.4 ⛔ 为什么必须弱对比 —— 三条实测理由（不是偏好）

1. **规范自己禁止强对比**（定式 1 的依据）；
2. ⛔ **强差分器械已整体退役**：宿主的差分类测试套件「已随测试面重建整体退役」；
   其调度面提案件自记「各后端一致性**今天的守卫不在岗**」（探针根**剩一个**，靠注释断言）；
3. ⛔ **宿主不是可信 oracle**：其能力矩阵两列**跑同一条命令**却给出**相反结论**；
   台账 `G79` / `G80` 两处静默错（**无诊断 · 退出码 0**）⇒ 强对比会把**宿主的缺陷
   升格成规范要求**。

### 3.5 代价（如实登记）

本轨判据的右端原有数格写着「与宿主差分 / 对表」 ⇒ 与本节**相冲**，已**成批重写**为对权威的
判别式。✅ 一处例外：**M1 的判据本来就是弱对比形状**（对**资源表**，非对实现）。

## 4. 「自写 C」例外

- **M1 允许**自举仓自带**自写的 C**（运行时 / 粘合）；⛔ 但**每个 C 文件须登记**一句
  「**为何 Pini 自己做不了**」。
- ⭐ **该名单不是附加手续 —— 它是产出**：它正是**自举缺口清单的生产者**，与 M3 的
  「须补项」**共用同一张表**。
- ⚠️ **附带代价（如实登记）**：允许多份实现并存 ⇒ 那份 C **必须冻结并带删除计划**，
  否则它会成为**永久的第三份**。
