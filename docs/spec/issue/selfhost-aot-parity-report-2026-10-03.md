## §3 三处根因（都在**宿主侧**，逐条给实测证据）

### 3.1 `split` 的**空定界符**：`strtok` 把定界符当字符集（⇒ `common` 值全空）

**形态**：发射器旧实现对 `s.split(sep)` 发**两遍 `strtok`**（一遍计数、一遍填充）。
而 `strtok` 的语义是「按**字符集**切」，且**空字符集不匹配任何字符**。

**最小复现**（`pini run` vs `pini compile`，两路对照）：

| `"ab\ncd".split("")` | 解释（权威） | 原生（修前） |
|---|---|---|
| 元素个数 | **5**（逐字素） | **1**（整串） |

**可达性**：自举 `src/common/common.pini` 的 `textAtoms` 就是 `text.split("")`
——它是**全仓最常被调用的逐字符扫描**的承载（`splitLines` / `trim` / `equalsPos` /
`stripQuotes` 全走它）。⇒ 原生路径下**整份资源表解析成空表**（实测 `TABLE|zh|E7-001|message|`
值全空 · `CODES|zh|` 空）。这也解释了「起点比旧报告更差」：`textAtoms` 是旧报告之后
引入的形态（字符模型墙线性化批），而**原生臂不支持它**。

**修法**：`split` **整族下沉到运行时段**（新 `bk_string_split`），循环**逐条镜像**
`IRExecutor` 的 `.split` 分支 —— 空定界符 ⇒ 逐字素 · 非空 ⇒ **子串**匹配 ·
**省略空子序列**。⚠️ 顺带修掉一处当时未被发现的同类偏离：`strtok` 对**多字符定界符**
按字符集切，而解释器按**子串**切（如 `"ab".split("Xb")`：解释器得 `["ab"]`，`strtok` 得 `["a"]`）。

**读数**（判据夹具 `split-delimiter-semantics.pini`，11 组）：
修后两路**逐字节相同**；⭐ 其中 `("e"+chr(769)).split("")` 得 **1** 是**强阳性对照**
—— 字素簇语义成立（按字节/码点实现会给 2）。

### 3.2 **枚举载荷**只做裸 `store`（⇒ 引用语义的值悬垂）

**形态**：发射器 `case .enumConstruct` 对每个载荷 `emitExpr` 之后**直接 `store`** 进箱的载荷槽
—— ⛔ 没有走 `.fieldStore` 那条「别名点 retain / 结构体深拷贝」的落值路径。

**产物 IR 直证**（本批实测，`acc = c(tail = acc,)` 的循环体）：

```
%t28 = load %enum.L*, ptr %acc_slot      ; 旧箱
      store %enum.L* %t28, ptr %t29      ; ← 存进新箱的载荷：没有 retain
%t30 = load %enum.L*, ptr %acc_slot
      call void @__release_enum.L(ptr %t30)   ; ← 紧接着「写前 release 旧值」
      store %enum.L* %t24, ptr %acc_slot
```

⇒ 新箱的载荷指向一个**刚被收回**的箱。

**可达性**：自举的 `stringListAdd`（head-insert 累积）正是 `cons(head, tail = 旧表)`；
模块层目录扫描、`sectionNames`、`tyAllFuncBodyTags` 一族全走它。

**最小复现**（判据夹具 `enum-payload-alias.pini`）：解释 `CTL 1 / ACC 3 / TWO 2` · rc=0；
修前原生在第二组崩（`Pini runtime error: match value matched no case`，**非确定性**
rc=133/134/139 —— 因为「撞不撞上」取决于分配器布局）。

**修法**：载荷槽改走**与 `.fieldStore` 同一规**的落值路径（`emitValueForStorage`）。

### 3.3 **插值 / `join` 的结果是栈缓冲**（⇒ 交出栈地址）

**形态**：`emitInterpString` 与 `emitArrayJoin` 都在**本帧的 `alloca i8, i64 4096`** 上拼串，
然后把**栈地址**当字符串交出去。而结果会离开本帧 ——
自举词法层原文就是 `self.emit("int", "\(parseDecimal(wholeText))")`，
那个插值串随即被存进 Token 的 `text` 字段（**堆上的箱**）。

**症状**（lldb 断 `bk_panic` 取栈）：`parseDecimal` 的循环里，`len(text)`
（`bk_string_count`）与 `text[i]`（`bk_string_char_at`）读**同一个指针**却给出不同答案
（前者 ≥1、后者 0）⇒ `string index out of range`；而指针指向的 8 字节是
`0x10 0x85 0xdf 0x6f 0x01 0x00 0x00 0x00` —— **根本不是 C 串**，是一处**栈槽**。
⇒ 两次读之间栈被复用覆写。这正是「剩余红层**非确定性**」的真因。
解释器没有这个问题（字符串是值，帧退不掉内容）。

**修法**：交出前 `strdup` 到堆（新助手 `heapCopyOfStackString`，用于插值与 `join`）。

> ⚠️ **一处刻意不改**：`stringifyValue` 的数组/标量分支也返回栈缓冲，但它的结果
> **只在同帧内被 `strcat` 消费**（实测调用点只有两处，都在拼串链上）⇒ 不动它，
> 避免制造无谓的堆分配。⛔ 概括要准：「栈串逃逸」的是插值与 `join` 两处，不是「一切拼串」。

## §4 ⭐ 一处**判据级**缺陷：`compile` / `run-llvm` 把子进程退出码**丢掉**

**实测**：一个 `abort()` 掉的程序，`pini compile` 报 **rc=0**（手工编跑同一份是 134）。

```swift
try run.run(); run.waitUntilExit()      // ← 状态到此为止，函数返回，CLI exit(0)
```

**为什么它比上面三处更要紧**：本仓的门禁形态正是「看退出码」（三态 0/1/2）
⇒ **任何**建在 `compile` / `run-llvm` 上的判据都会**恒绿**。
实测既有 `SplitPathTests` 里那条 `compiled.status == 0` 断言就是**恒真**的
（「跑通了」与「根本没跑起来」外观相同）—— 那正是本仓明令禁止的「一条从不红的判据」。

**修法**：两处都改用 `exit(childExitStatus(of:))`，并按 shell 惯例归一
（被信号杀死 ⇒ `128 + 信号`，即 `abort()` ⇒ **134**，而不是裸信号号 6）。

⚠️ 这是**用户可见变化**（同族的还有 emit/compile 的单文件语义门禁，见 `auth-76`）。

## §5 判据与变异反证

### 5.1 判据（新增 5 条，全进常跑集）

| 套件 | 用例 | 判什么 |
|---|---|---|
| `OwnershipLifetimeTests`（新） | `enum-payload-alias` | 载荷占用自己那一份份额（行为级 · 两路逐字节） |
| | `string-escapes-interp` | 插值串活过产出它的帧（行为级 · 判据内含 `burn` 压栈） |
| | `string-escapes-join` | `join` 结果活过产出它的帧（同上） |
| | `stackBuiltStringsAreCopiedToTheHeap` | **产物结构级**：栈上拼串的**交出点**必须经 `@strdup` |
| `SplitPathTests` | `splitDelimiterSemanticsMatchInterpreter` | 空定界符 ⇒ 逐字素 · 多字符 ⇒ 子串匹配 |

⚠️⭐ **行为级判据不够（本批实测，已写进用例注释）**：把堆复制撤掉之后，
两条**行为级**字符串判据**仍全绿** —— 因为夹具里那支 `burn` 没覆写到产出帧的那片栈
（栈复用是**碰运气**的，这正是本缺陷长期被读成「非确定性」的原因）。
⇒ 补**产物结构级**那条，它把该变异**打红**。**这条弱点是判据的实测属性，须随判据一起记。**

### 5.2 变异反证（两级，每条只打自己）

| 变异 | 改什么 | 实测 |
|---|---|---|
| **M1** | 枚举载荷退回裸 `store` | ⛔ **只**打红 `enum-payload-alias`；其余 5 条全绿 ✅ |
| **M2** | `heapCopyOfStackString` 直接返回栈缓冲 | ⛔ 打红**结构级**那条（2 处）；两条行为级**仍绿**（见上 ⚠️） |

两次变异都**先备份、后强制重建**（`rm` 产物 + 重建 + 行为探针），还原后校验 sha256 一致。

### 5.3 判据②的非退化锚点换过一处

`SplitPathTests` 的「`malloc` 尺寸不得直接取 `strlen`」那条，原来用 `@strtok` 当
「切分路径真的被发射过」的锚点；切分委派给运行时段之后，`@strtok` 只剩**头部的无条件声明**
⇒ 那个锚点从此**恒真**、判据退化。已换为认**调用**的 `@bk_string_split`。

## §7 门禁原生臂（`auth-73` scope ⑦）+ 比值（scope ⑥）

### 7.1 接手

`tools/check-module-b2.sh` 件头曾把「**改由原生臂执行自检**」列为恢复常跑面的条件②，
并注明「该路径本仓**尚未接过**，且本仓**没有**可兑现的读数支撑它」
⇒ 本批的层表读数（22/22）**就是那条支撑**。

**落法**：

1. **新器械** `tools/build-selfhost-native.sh`：`emit` + `clang` ⇒
   `<自举仓>/.build-native/selfhost-native`（产物目录已进 `.gitignore`）；
2. 判据④ 的执行侧改为 **原生优先 · 回落可见**：
   - 原生二进制在场（`PINI_SELFHOST_NATIVE` 或默认路径）⇒ 走原生，并打印 `④ 臂：**原生**（<路径>）`；
   - 不在场 ⇒ 回落解释路径，且打印**可见的回落行**（⛔ 不静默 —— 静默回落会让
     「走了哪条臂」在读数上不可知，而那正是「拿错读数当门禁」的老路）；
3. ⛔ **判据本体一字未改**：`U1/U2/U3/U4/U5/U7` 断言两条臂同一套 —— **换臂不换判据**；
4. ⛔ 判据④ **仍在按需面**（`PINI_MODULE_SELFCHECK=1`）—— 常跑面的恢复是**另一件事**，
   须连着量到的比值一起裁，本器械**不自行**更改常跑面集合。

### 7.2 比值（口径）

   **宿主侧发射器**，而**自举侧自己的发射器**（P3 那一格）**没有同步** ⇒ 凡夹具用到这些形态者，
   「宿主发射器 ⇄ 自举发射器产物**逐字节相同**」那几条判据会**红**（实测两道：整包 codegen 的
   `prog3` 只差一行 `declare ptr @bk_string_split`；泛型注解族的装置差整片字符串垫层 declare
   与那处 `call`）。⚠️ **自举仓 `src/` 本批未动** —— 同步这件事在甲路线的授权范围之外，
   要动须另行点名（本条授权原文即要求「若必须改自举源码才能过 ⇒ **停下登记**，⛔ 不顺手改」）。
   ⭐ **销它的条件** = 自举发射器同样实现这三处；⛔ 「宿主侧改了 ⇒ 自举发射器欠一笔」是**结构性**的。
   ⚠️ 同族有一处**已就地修掉**：本条最初把 `declare ptr @strdup(ptr)` 写进**无条件头部**，
   而自举侧那份头部清单里没有它 ⇒ 逐字节门禁当场红；改成**按需发出**后恢复绿。
