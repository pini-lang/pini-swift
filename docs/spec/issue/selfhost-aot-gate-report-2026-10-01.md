# 甲路线（宿主 AOT 编自举前端）第一次实测报告（2026-10-01）

> **本件是什么**：授权条目 **`auth-73`**（门禁提速 · 甲路线）的交付与判读件。
> 用户 2026-10-01 三答钉死路线：①「**只走甲**」②「**不要**」（不把逐字节等价立成常设硬门）
> ③「**借宿主 LLVM 后端吃自举 IR…在自举侧把 LLVM 后端搭建起来之前，要吃**」。
>
> ⭐ **结论一句话**：**链路打通了，语义没打通。**
> 自举编译器**已能编成原生二进制并运行**（symbol 零缺口、框架级正确：`ast` 层与解释路径
> **逐字节相同**），但**绝大多数层与解释路径分歧**——而分歧的成因已收敛到**一个已知类别**：
> **IR 契约在案的 B 组字符语义偏离（5 项）**。⇒ ⛔ **本件不宣示甲路线达成**，
> ⛔ **不把门禁接到原生路径上**（接上去就是拿错读数当门禁）。
>
> ⛔ **授权**：本件产出属 `auth-73`；⛔ 本件不授权任何后续施工。

## 2. 本批交付（三处宿主缺陷 + 六个运行时段）

### 2.1 发射器：局部名两族撞源码名（scope ②）

| 现象 | 真因 | 处置 |
|---|---|---|
| `%span_slot` 在 `render` 里二次 `alloca` | 形参槽**手工拼** `%<名字>_slot`、绕过 `freshSlot` 的计数器；同函数内 `var span = span`（自举 `common.pini:471`）再取同名 | 形参槽改走 `freshSlot`（不相撞时计数为 0 ⇒ **逐字节不变**） |
| 形参 `%t1,%t2` 撞发射器临时名 | `typeFieldRows\|func(n1,t1,n2,t2)`（自举 `type/entry-seg1.pini:26`）的形参名落进 `%t<数字>` 族 | 新增 `parameterSSANames`：**只在名字落进发射器自有命名族时**改名（`<原名>.p<序号>`） |

⚠️ 两处**都不是自举仓的缺陷** —— 是宿主发射器的命名纪律缺口。

### 2.2 LLVM 路径缺失的运行时段（scope ③）

自举整包 IR 里**被调用但既无 declare 也无 define** 的符号共 **6 个**（全量静态扫描，⛔ 非抽样）：
`argv`(3) · `chars`(2) · `ord`(2) · `listDir`(2) · `is_letter`(1) · `is_number`(1)。
它们在**解释器侧早有实现**，缺的只是 LLVM 侧 ⇒ 新增运行时段 `bk_argv` / `bk_chars` / `bk_chr` /
`bk_ord` / `bk_is_letter` / `bk_is_number` / `bk_list_dir`，并在发射器接上（`declare` 条件出现）。
⚠️ 谓词**不**用 C 的 `_Bool` 返回（那在 C ABI 里是零扩展 i8，与语言的 `i1` 对不上）——
运行时段一律回 `i32`，收敛到 `i1` 由调用点显式做掉。

### 2.3 ⭐ 三处**语义**缺陷（本批的主要发现；均在宿主侧）

| # | 缺陷 | 实证 | 性质 |
|---|---|---|---|
| **A** | `stringSubstring` 按 **length** 读第 2 参数（契约裁的是 **end**），且旧形状在**调用点** `alloca` 变长缓冲 —— 循环里的 `alloca` 不到函数返回不回收 ⇒ 栈按 **N²/2** 增长 | 最小复现：`"abcd".substring(1,2)` 解释器 `b` / 原生 `bc`；自举 `splitLines` 撞栈保护页（`KERN_PROTECTION_FAILURE`，帧落 `_platform_memmove`） | **契约 §2.9 第 38 条已登记的 B 组缺陷** + 一处**与之独立**的分配缺陷 |
| **B** | `return <局部容器>` 交出的是**已回收**的悬垂句柄 —— 发射器把 `emitReleases` 排在**求值之前** | `splitLines` 生成 `call void @bk_array_destroy(...)` 紧接 `ret %bk_array*`；调用方第一次 `len()` 就撞（`KERN_INVALID_ADDRESS`，帧落 `bk_array_len`） | 宿主发射器缺陷（所有权契约：返回值是**转移**出去的那一份） |
| **C** | `var x = <expr>` 的初始化式在**新绑定已生效之后**求值 ⇒ `var span = span` 读到的是**自己刚分配、还没写过的槽** | `render` 生成「`load` 未初始化槽 → 存回同一槽」；后续 `span.startLine` 空指针崩溃 | 宿主机射器缺陷（解释器语义：初始化式在**旧**作用域求值） |

**处置**：A 改为运行时段 `bk_substring`（语义**逐条镜像** `IRExecutor.stringSubstring`：字素 · 负值尾计数 ·
双端夹取 · `hi<=lo` 得空串），分配一并交给运行时；B/C 各改**顺序**（求值 → 保留别名 → 释放 → ret；
先求值 → 再登记绑定 → 再存）。

⭐ A/B/C **同属一族**：都不是「算错」，而是**顺序/位置**错——遮蔽名字时谁先谁后、
变长分配该落在哪一层。判据形态也一样：**最小复现 + 两路对照**，而不是读代码猜。

## 3. 量测（scope ⑤⑥）

### 3.1 链路与规模

### 3.2 ⭐ 两路对照（**非常设硬门**，用户裁定②；一次性证据）

**仓内语料（`examples/*.pini`，51 份）**：**44 份逐字节相同**；7 份不同——
⚠️ **全部是 `concurrency-*` 且两路 rc 都 = 1**，**本批改动前后同一条基线**（改前同为 44/51）。
⇒ **无回归**。

**自举各层（`pini run . <层>` vs 原生二进制）**：

| 层 | 结果 |
|---|---|
| `ast` · `type-seg7` | ✅ **逐字节相同** |
| `common` | ⚠️ 行数同（36/36）但**取值全空** |
| `lexer` · `parser` · `parser-decl` · `desugar` · `semantic` · `type-seg2…seg6` · `ir-lower` · `ir-run` | ⛔ rc=139（段错误） |
| `module` · `module-check` | ⛔ rc=134（`match value matched no case`） |
| `type-seg1` | ⛔ rc=134（同上） |

> ⚠️ **2026-10-01 同日订正（两行 rc=134 的归因）**：本表记录时把它读作「`match` 的代码生成在自举代码上
> 语义不符」。**该读法已被实测推翻** —— 同日的最小探针给出：**同帧的枚举 `match` 两路一致**
> （`D-ctl 2.0`），而**同一枚举一旦跨帧返回**就报**同一句** `match value matched no case`
> （`D`，夹具 `examples/selfhost/tools/.fixtures/aggregate-escape-D-enum.pini`）。
> ⇒ 它是**名义箱跨帧外逃**（枚举盒随创建帧一起失效、标签被覆盖）的症状，**不是 `match` 的缺陷**。
> ⇒ 本表的读数值照旧有效，**归因以后一条为准**（载体：`docs/spec/issue/survey-aggregate-return-2026-10-01.md` §9）。

⚠️ **`module-check` 的墙钟有两道假读数，如实登记**：原生侧 **0 s 即 rc=134**（跑错了，不是跑快了）；
解释侧 rc=**142** 是**我方 150 s 闹钟截断**，⛔ 不是被测程序的结果。
⇒ 门禁时长**本批未取得可比值**，照旧只有 P2-0 的 **≥688 s 下界**。

### 3.3 ⭐ 归因：分歧的成因是一个**已知类别**

`common` 的「取值全空」追到底是：**资源全文读进来是对的，`splitLines` 切错了行**
（`CODES|zh|` 一行：原生 24 字节 vs 解释 548 字节）。机制：

- `len(s)` 走「数非续字节」⇒ **码点计数**（契约 §2.9 **第 22 条 B 组缺陷**：契约 = 字素簇）；
- `s[i]` 走**字节寻址**（契约 §2.9 **第 23 条 B 组缺陷**：契约 = 字素簇）；
- 二者在**非 ASCII 文本**上彼此不一致 ⇒ 切点落进多字节序列内部。

叠加 §2.9 **第 37 条**（`contains` 字节 vs 字素），**B 组 5 项里有 3 项直打自举的高频形态**。

> ⭐⭐ **结论**：甲路线的剩余阻塞面 = **IR 契约在案的 B 组字符语义偏离**。
> 契约 §6 对它的处置原文是「**实现缺陷，修实现对齐 `字符模型 = Grapheme Cluster`**」
> ⇒ 修完它 = **一个成规模的专项**（`String` 的 `len`/下标/切片/`contains` 四条通道 +
> 字符模型对齐 + 随之而来的夹具与判据重建），**不是本条的余量**。

| 三处修复的最小复现 | 各有一条**两路对照**的定向探针（§2.3 表内） |

⚠️ **A 改的是 LLVM 腿的既有语义**（`substring` 从 length 改回 end）。它**不是**「为让器械变绿而改」——
契约第 38 条明文写着「注册表与**测试已裁** `(start, end)`；LLVM 侧现为 `(start, length)`，**偏离**」
⇒ 本批是**把实现对齐到已裁语义**，方向与契约一致。
