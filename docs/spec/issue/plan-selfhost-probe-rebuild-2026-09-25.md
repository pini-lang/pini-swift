## 2. 目标与 MVP 判据

### 2.1 四个结构位（**去命名**的 —— 因各实现对「`stage N`」的编号互相冲突）

| 位 | 含义 | 与 MVP 的关系 |
|---|---|---|
| **S** | **种子** —— 非本语言实现，够编出下一版即可 | 自举的前提，⛔ 不属 MVP |
| **P1** | **自产** —— 用本语言写、由**非自身实现**编出 | ⭐ **MVP 落在这里** |
| **P2** | **自洽** —— P1 能编出它自己 | **目标**，⛔ 不属 MVP |
| **P3** | **不动点** —— 再编一次，输出相同 | **正确性证明**，⛔ 不属 MVP |

⚠️ **为什么必须去命名**：跨实现的 `stage N` **编号互相冲突**（同一件事在一个实现里叫
`stage2`、在另一个里叫 `stage1`）⇒ 跨实现引用该词**必然错位**。

### 2.2 MVP 判据（可判定）

**档位 = P1**：存在一个自举仓库，其源码**全部用 Pini 书写**，被**非自身实现**编出**可运行的**编译产物。

| 判据 | 内容 | 对应用户原话 |
|---|---|---|
| **M1 自产** | 自举仓源码**全部为 Pini**（**自写 C 例外**见 §2.3）；由**非自身实现**编出**可运行**产物 | 「能构建」 |
| **M2 符合 reference** | 该产物在一组既有语料上的行为**符合 reference** —— ⛔ **不要求**与宿主实现**逐条 diff 一致**、⛔ **不要求**三方两两一致。⚠️ 「reference」取**语言参考 / 规范**（**conformance** 判据），⛔ **不指**宿主实现。**它具体指哪些载体，见 §2.5.1** | 「能构建」里「可用」那一半 |
| **M3 不断链** | 仓库**存量**源码**始终**落在「种子能编」的子集内；种子**冻结且可重建** | 「**能持续扩展**」 |

⭐ **为什么是这三条**：**P1 之前，下面这些纪律没有对象可守** —— 没有「用本语言写的编译器」，
「不断链」「受限子集」全是空话 ⇒ **M3 就是「持续扩展」的实体**。

#### 2.5.1 reference **不是一份文件，是一棵分面权威树**

规范件的「事实源层级与权威关系」一节自己就否掉了「单一权威」这个设定：

| 面 | 权威载体 | 判读要点 |
|---|---|---|
| **工程与治理** | 规范件 | **首要入口**；「不一致时以本规范为准」 |
| **语言面描述** | 语言参考 | ⚠️ **只收已「递交」的成熟项** ⇒ 未递交的条款仍在规范侧 |
| **形式文法** | ⚠️ **规范件的 §A 附录**（⛔ **不在**语言参考） | 语言参考的第 13 章是它的**递交去处**，而该递交**尚待完成**（规范的语言细则索引自记「待递交」） |
| **IR 节点语义** | IR 契约件 | ⭐ 其权威次序第 3 条明写「**任一后端都不是定义处**」 |
| **诊断码映射** | `Sources/PiniCore/Resources/Diagnostics.{en,zh}.toml`（**代码资源**） | 同目录的 `docs/spec/diagnostic-codes.md` 自称**派生 / 低权威** |
| **证据** | `docs/spec/evidence-table.toml` | 自标 `citable=false`；❗**新鲜度 60 分钟**（见 §2.5.2） |

⭐⭐ **一处会把人引错文件的陷阱**：规范件的事实源表把它**自己的 §A** 记在「语言参考」名下，
而同件的事实源索引写「**待递交**」⇒ ⚠️ **前者描述目标态、后者记录现况**。
⇒ 照前者写判据会**把权威判给另一个文件**。

#### 2.5.2 ⭐ 一条决定设计形态的规则：证据新鲜度 **60 分钟**

规范件规定：证据自 `validated_at` 起 **60 分钟**内可信；>60 分钟 → `STALE`（**不得作为依据**）；
>72 小时 → 待删。

⇒ ⛔ **「验证语言架构可靠性」不能落成一次性结论**（它的保鲜期只有 60 分钟）。
⇒ ✅ **它只能落成「可重跑协议」**：每项 = **命令 + 判据 + 最近实测**，数字**现跑现取**。

⭐ 这不是新发明 —— 规范件的 §A.6「**验证记录（可重跑协议）**」就是它的现成范本，
它自己写着「本节为**可重跑验证协议**，**不是历史快照**」。
⚠️ 该节的**探针载体已删**（其路径在件内已标「载体已删」）⇒ **这正是「探针重建」的对象**。

#### 2.5.3 三定式（本件全部判据据此书写）

| # | 定式 | 依据 |
|---|---|---|
| **1** | **比权威不比实现** —— 判据右端只能是 §2.5.1 树上的载体；⛔ 宿主实现**不得**出现在右端 | IR 契约的「任一后端都不是定义处」 |
| **2** | **判别式而非全量** —— 断言「规范**钉住**的那几条**可区分**性质」，⛔ 不比完整 token 流 / AST / 逐字节 | 规范 §A.6.1 的形态（`<=` 必须**是一个 token**、`0x1F` → `int 31`、缩进栈必须出现 `indent → / dedent ←` 序列）；合手则判据纪律「**判据的区分力全在语料上**」 |
| **3** | **双向报缺口** —— 要求「有 A 无 B」与「有 B 无 A」**两个方向都报** | `tools/ir-contract-check.py` 的既有形态；⚠️ 单方向判据对「完全没实现」与「完全实现」**同形**，无区分力 |

#### 2.5.4 ⛔ 为什么必须弱对比 —— 三条实测理由（不是偏好）

1. **规范自己禁止强对比**（定式 1 的依据）。
2. ⛔ **强差分器械已整体退役**：宿主的差分类测试套件「**已随测试面重建整体退役**」；
   其调度面提案件自记「各后端一致性**今天的守卫不在岗**：69 条测试**零条**跑 LLVM 后端 ·
   探针 6 个根剩 1 个 ⇒ **靠注释断言**」。
3. ⛔ **宿主不是可信 oracle**：其能力矩阵的 `emit` 与 `ir` 两列**跑同一条命令**却 11/59 行结论相反；
   台账 `G79` / `G80` 两处静默错（**无诊断 · 退出码 0**）⇒ 强对比会把**宿主的缺陷升格成规范要求**。

#### 2.5.5 代价（如实登记）

§3 的退出判据列原有 **6 格**写着「与宿主差分 / 对表」（M2 · M4 · M5 · M6 · M7 · M9）
⇒ 与本节的弱对比**相冲**，本批**已成批重写**为对权威的判别式。
✅ 一处例外：**M1 的判据本来就是弱对比形状**（「与宿主**资源表**对表」= 对 TOML 权威，非对实现）——
本批只把它写得更明确。
