## 2. 目标与 MVP 判据

### 2.1 四个结构位（**去命名**的 —— 因各实现对「`stage N`」的编号互相冲突）

| 位 | 含义 | 与 MVP 的关系 |
|---|---|---|
| **S** | **种子** —— 非本语言实现，够编出下一版即可 | 自举的前提，⛔ 不属 MVP |
| **P1** | **自产** —— 用本语言写、由**非自身实现**编出 | ⭐ **MVP 落在这里** |
| **P2** | **自洽** —— P1 能编出它自己 | **目标**，⛔ 不属 MVP |
| **P3** | **不动点** —— 再编一次，输出相同 | **正确性证明**，⛔ 不属 MVP |

⚠️ **为什么必须去命名**：跨实现的 `stage N` **编号互相冲突**（同一件事在一个实现里叫
`stage2`、在另一个里叫 `stage1`）⇒ 跨实现引用该词**必然错位**。

### 2.2 MVP 判据（可判定）

**档位 = P1**：存在一个自举仓库，其源码**全部用 Pini 书写**，被**非自身实现**编出**可运行的**编译产物。

#### 2.5.1 reference **不是一份文件，是一棵分面权威树**

规范件的「事实源层级与权威关系」一节自己就否掉了「单一权威」这个设定：

| 面 | 权威载体 | 判读要点 |
|---|---|---|

#### 2.5.2 ⭐ 一条决定设计形态的规则：证据新鲜度 **60 分钟**

规范件规定：证据自 `validated_at` 起 **60 分钟**内可信；>60 分钟 → `STALE`（**不得作为依据**）；
>72 小时 → 待删。

⇒ ⛔ **「验证语言架构可靠性」不能落成一次性结论**（它的保鲜期只有 60 分钟）。
⇒ ✅ **它只能落成「可重跑协议」**：每项 = **命令 + 判据 + 最近实测**，数字**现跑现取**。

⭐ 这不是新发明 —— 规范件的 §A.6「**验证记录（可重跑协议）**」就是它的现成范本，
