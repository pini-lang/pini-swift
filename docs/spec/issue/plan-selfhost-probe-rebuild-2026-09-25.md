## 2. 目标与 MVP 判据（2026-09-25 重写）

> **重写说明**：本节原定的终端判据是「**覆盖面推进**」（探针定位）。用户 2026-09-25 给出 **MVP 判据**
> ⇒ 本节**按 MVP 重写**。⚠️ 原有的**探针价值**（暴露宿主缺陷）**保留**，但**不再充当终端判据**。

### 2.1 四个结构位（**去命名**的 —— 因各实现对「`stage N`」的编号互相冲突）

| 位 | 含义 | 与 MVP 的关系 |
|---|---|---|
| **S** | **种子** —— 非本语言实现，够编出下一版即可 | 自举的前提，⛔ 不属 MVP |
| **P1** | **自产** —— 用本语言写、由**非自身实现**编出 | ⭐ **MVP 落在这里** |
| **P2** | **自洽** —— P1 能编出它自己 | **目标**，⛔ 不属 MVP |
| **P3** | **不动点** —— 再编一次，输出相同 | **正确性证明**，⛔ 不属 MVP |

⚠️ **为什么必须去命名**：跨实现的 `stage N` **编号互相冲突**（同一件事在一个实现里叫 `stage2`、
在另一个里叫 `stage1`）⇒ 跨实现引用该词**必然错位**。故本件只用上表的**结构位**。

### 2.2 MVP 判据（可判定）

**档位 = P1**：存在一个自举仓库，其源码**全部用 Pini 书写**，被**非自身实现**编出**可运行的**编译产物。

| 判据 | 内容 | 对应用户原话 |
|---|---|---|
| **M1 自产** | 自举仓源码**全部为 Pini**（**自写 C 例外**见 §2.3）；由**非自身实现**（Swift 宿主或自写 C 运行时）编出**可运行**产物 | 「能构建」 |
| **M2 符合 reference** | 该产物在一组既有语料上的行为**符合 reference** —— ⛔ **不要求**与宿主实现**逐条 diff 一致**、⛔ **不要求**三方两两一致。⚠️ 此处「reference」取**语言参考 / 规范**（即 **conformance** 判据），⛔ **不指**宿主实现 | 「能构建」里「可用」那一半 |
| **M3 不断链** | 仓库**存量**源码**始终**落在「种子能编」的子集内；种子**冻结且可重建** | 「**能持续扩展**」 |

⭐ **为什么是这三条**：**P1 之前，下面这些纪律没有对象可守** —— 没有「用本语言写的编译器」，
「不断链」「受限子集」全是空话 ⇒ **M3 就是「持续扩展」的实体**。

### 2.3 「自写 C」例外（用户 2026-09-25 裁定）

- **M1 允许**自举仓自带**自写的 C**（运行时 / 粘合）；⛔ 但**每个 C 文件须登记**一句
  「**为何 Pini 自己做不了**」。
- ⭐ **该名单不是附加手续 —— 它是产出**：它正是**自举缺口清单的生产者**，与 M3 的「须补项」**共用同一张表**。
- ⚠️ **附带代价（如实登记）**：允许多份实现并存 ⇒ 那份 C **必须冻结并带删除计划**，
  否则它会成为**永久的第三份**。

### 2.4 附带价值（⛔ 不作判据）

- **探针价值仍在**：跑不起来 = **暴露宿主缺陷** ⇒ 该价值**如实保留**，
  但**它不再充当终端判据**（原判据「覆盖面推进」**由此作废**，见 §6-3）。

**依赖栏取值**：`—` = 无依赖、可立即开工 · `M<n>` = 层内依赖 ·
`语义收敛` = 原门控（**现况：已解除**，见 §1.4）。

| 格 | 目标 | 退出判据 | 依赖 |

**每格通用纪律**：① 每格**重新实测**夹具面（⛔ 不拿上一格的清单做加减）→ ② 夹具最小化 →
③ 实现（**镜像宿主，不造第二份语义源**）→ ④ 验证（本层绿 + 全量回归 + 契约核验）→
