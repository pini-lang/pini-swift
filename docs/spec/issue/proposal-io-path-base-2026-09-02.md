## 1. 动机（根因分析结论，2026-09-02 已查证）

1. **双基准不对称**：`import` 按模块根解析（`ModuleDependencyLoader.LoadedModule.rootPath`），而 `readFile` / `writeFile` 按进程 CWD 解析（`String(contentsOfFile:)` / `content.write(toFile:)`）。同一程序两条路径基准。
2. **可复现性缺失**：相对路径的语义随调用目录变化。自举 `corpus_tests.pini` 的 5 个测试从仓根直跑即假失败（症状）；批 5 清单工具、批 6 远程抓取等 CLI 程序都会踩。
3. **F6 耦合**：CLI 不向 main 透传 argv（F6 宿主缺口）。未来 argv 落地后，用户在 shell 传入的路径（CWD 视角）与程序内资源路径（程序视角）必然共用 `readFile`——**基准规则必须先定义，否则 F6 无法立项**。

## 2. 现状取证（2026-09-02 实测）

| 事实 | 证据 |
|---|---|
| IO 内建 = `readFile` / `writeFile` / `readLine`（后者无路径） | `BuiltinRegistry.swift:110-114`（group: .io） |
| 解释器：路径字面量直传系统调用（CWD 基准） | `Interpreter.swift:3087` / `:3104` |
| **LLVM 端 IO 已实现**（修正早前「解释器专属」的误判） | `BuiltinsEmitter.swift:4,171,192`；`IRExecutionTests/testWriteReadFileViaLLI` |
| 模块根判定已存在（R1：`pini.toml`） | `ModuleDependencyLoader.swift:55-58`；但**解释器运行时不保存根路径**（grep `rootPath` 仅 1 处，用于 SourceLocation） |
| 使用面（全仓）：`examples/io.pini` 用**绝对路径** `/tmp/...`；IOTests 用 `__PATH__` 注入**绝对临时路径**；IR 测试用 `/tmp/x` | grep 实测；**无一处 CWD 相对路径的现存用法** |
| 自举测试假失败 | `corpus_tests.pini` 5 处 `readFile("examples/…")`（模块根相对意图，被 CWD 解析） |
| 单文件模式无模块根 | `pini run <file>`（无 `pini.toml`）时 R1 不适用 |

**迁移面结论：≈零**——现存全部 IO 用法均为绝对路径或注入路径，**没有任何一处会被基准变更破坏**（G14 Provisional 窗口期，时机最佳）。

## 3. 方案空间

### 方案 A（推荐）· 按路径形态区分基准

| 路径形态 | 基准 | 视角 |
|---|---|---|
| 绝对路径（`/` 开头） | 原样 | — |
| `./` 或 `../` 开头 | **运行时 CWD** | 用户 / shell 视角（argv 传入的用户路径天然正确） |
| 其余相对路径 | **程序基准**：模块根（有 `pini.toml`）/ 入口文件所在目录（单文件） | 程序 / 资源视角（可复现、可测） |

- **优点**：①程序资源路径可复现——自举 5 个假失败**零改动修复**（无前缀 → 模块根）；②`./` 给 shell 互操作，为 F6（argv）铺路——用户在 shell 敲的路径按惯例带 `./` 或绝对；③双后端可对齐（见 D-4）；④记号面零新增。
- **代价**：「无前缀相对路径」的语义是 Pini 特有约定（主流语言全部 CWD），需 spec 钉清 + 迁移说明。

### 方案 B · 维持 CWD + 暴露 `moduleRoot()` 查询内建

- **优点**：与 Python/Node/Swift CLI 主流一致；零破坏。
- **代价**：可复现性推给每个程序自行拼接 `moduleRoot() + "/examples/…"`——自举测试要改写、工具程序要自觉；「程序资源放哪儿都能跑」的保证不存在。

### 方案 C · 运行时切 CWD 到模块根

- **优点**：单一基准。
- **代价**：吞掉用户 CWD（`./` 不再是用户视角）；对进程全局状态做隐式变更，工具程序反而困惑。**否决倾向**。

### 方案 D · 维持现状 + 文档约束「必须从模块根运行」

- **优点**：零改动。
- **代价**：隐患保留（批 5/6 必踩）；「约定优于机制」与本仓「机制钉定」哲学相背。**否决倾向**。

**推荐：方案 A**。它是唯一同时满足「程序资源可复现 + shell 互操作 + 双后端可对齐 + 自举测试零改动修复」的方案；语义的独特性以 spec 钉清 + 迁移说明消化。

## 4. 影响评估（§1.3 第 2 步）

| 受影响构造 | 稳定性 | 性质 |
|---|---|---|
| G14 `readFile` / `writeFile` | Provisional | **破坏性**（无前缀相对路径：CWD → 程序基准）；**现存用例迁移面 ≈ 0**（全部绝对/注入路径） |

| F6（argv 透传） | 未立项 | **被本提案解锁**：`./` 语义就位后 argv 用户路径无歧义 |
| 自举探针 | — | 5 个假失败随 A 自动修复（根因验证点） |
| A13（冲突登记册「字符串按路径规则解析」待定义） | — | 本提案即其定义，落地后 A13 出账 |

**破坏性升级评审结论**：破坏面为「源码内无前缀相对路径」——**现存为零**；G14 从未 Stable；建议按 Provisional 窗口期直接切换，配迁移说明。
