## 1. 现状定位（立项实测，2026-09-30）

### 1.1 速度：双层解释是根因

- 自举编译器（src 十格 **22120** 行 + main 218 行 Pini）跑在**宿主 Swift 解释器**上；
  自举解释器又是**树遍历式 IR 求值**——两层解释叠加。
- 已量化的代价：门禁里的 module-check 占总时长的大头（全量门禁 17–19 分钟）；
  缺陷乙修法实测「56K 字符 >45s vs 内建 `split` 11s」**被性能否决**（先量后合定式的
  首个实例）。
- ⛔ **本件立项时无墙钟基线** ⇒ 阶段 0 第一件事就是把基线量出来（见 §3）。

### 1.2 特性：与 Swift 版的差距是明账

| 面 | 宿主参照 | 自举现状 | 备注 |
|---|---|---|---|
| IR 契约条目 | 46 | 40（切片对账） | 差 6：逻辑/位运算符、tuple、arrayLiteral、指针族、join/detach 等（G81 划出等） |
| 插值 `\(expr)` | 有 | **表达式段零产出**（parser 死代码） | M4 格缺口；int→string 唯一路径被门住 |
| 扩展块方法 | 有（mangle `方法__类型`） | 划出 | 宿主亦无现量语料 ⇒ 需宿主先补现量 |
| 闭包 / 函数值 | 有（fat pointer） | 划出 | 宿主 `IRNode.swift` 344 行形态可参照 |
| 指针 / FFI | 有（type 段六只交付声明面） | 划出 | 契约 §2.29 pointerLoad 符号扩展语义待裁项 |
| 泛型 | 有 | 划出 | 宿主 genericConstruct / 泛型枚举构造先例 |
| **CodeGen（LLVM）** | **5159 行** | **目录占位**（裁决 1） | P3 的必要件；⭐ 宿主 LLVM 侧带在案 B 组偏离（substring 按 length 读等） |

> ⭐ **本表已升格为受管载体**（P2-0 判据③）：**活载体 = 差距台账** `docs/spec/issue/selfhost-gap-ledger-2026-09-30.md`
> —— 销账以那里为准，⛔ 本表只作**立项快照**留存。⚠️ 升格时改动了一处口径：原写「差 6」
> 是**两套账相减**（契约条目总账 vs 自举切片对账账），台账已改为**按条目号逐项列举**。

## 2. 三阶段总览

| 阶段 | 内容 | 产出物 | 风险性质 |
|---|---|---|---|
| **P2-0 · 基线** | 速度基准量测（模块检查墙钟分段 · 代表性语料执行墙钟分位）+ 特性差距对账表固化（§1.2 升格为受管对账表） | 基线读数件 + 对账表 | **零源码风险**（纯量测） |
| **P2-1 · 清障与自洽** | 两小格（插值表达式段 · 扩展方法格）→ U5 清零 → **P2 自洽验证**：自举解释器跑自举编译器全源 | 两格交付 + U5=0 读数 + 自洽验证报告（含完整量化后的速度问题） | 形态风险（解析面回归） |
| **P3 · AOT 与特性回填** | CodeGen 格立项分段（首段 = IR→`.ll` 线性发射最小循环）+ 特性回填并行序列（§4） | `.ll` 发射器 + clang 链路判据 + 逐格回填 | **量级风险**（宿主 5159 行参照）+ 语义风险（B 组偏离不镜像的对账成本） |

⭐ **速度的正解是 C 路线（AOT CodeGen）**，但它的前置就是 P2 自洽（自举编译器全源可跑）
—— 依赖关系决定批序，⛔ 不跳步。两条被否的捷径：**借宿主 LLVM 后端吃自举 IR**（继承在案
B 组偏离，违背弱对比口径）与**字节码 VM**（仍是解释执行，且 VM 本身加重双层解释负担）。

⚠️⭐ **2026-10-01 追记（用户枢裁，改写上段的一项政策）**：上段那条「借宿主 LLVM 后端」的**否决被松绑** ——
用户原话「**无论如何，自举的解释器侧已经初步可行，那么借宿主 LLVM 后端吃自举 IR 可能松动，
在自举侧把 LLVM 后端搭建起来之前，要吃**」（`auth-73`）。
⇒ ⭐ **松绑的准确范围**：在**自举侧自建 LLVM 后端（P3 原目标）落地之前**，**许可**借宿主 LLVM 后端
产出原生码 —— 它是一条**过渡期通道**，⛔ **不替代** P3 那一格，也⛔ 不豁免「按契约钉语义」。
⚠️ **代价已实测并在册**：宿主后端带着**在案的 B 组字符语义偏离**，用它编自举前端会把这些偏离
**带进自举的读数**；实测结论见 `docs/spec/issue/selfhost-aot-gate-report-2026-10-01.md`
（链路通、语义未通；剩余阻塞面 = B 组 4 项）。

⚠️⭐ **2026-10-01 第二次追记（同日 · 路线收敛）**：当日曾另立「**C 后端**」提案（发射 C 而非 `.ll`，
带独立规划件与授权条目）—— **同日撤销**（用户裁定：「此语言的特性对于 C 后端来说过于高级，
需要的工程量很大，对于自举 MVP 来说不是一个近期目标」）⇒ ⭐ **本件 §2 表内 P3 的原文口径
（「IR→`.ll` 线性发射」）恢复为唯一路线**，施工面见
`docs/spec/issue/plan-selfhost-llvm-backend-2026-10-01.md`（`auth-78`）。
⚠️ §4 依赖图的「CodeGen 首段」那一格**不变**，只是发射目标确定为 `.ll`。

⚠️⭐ **P2-1 的第三项产出物（自洽验证报告）已于 2026-10-01 首次落地，结论 = 终端判据未达**
（本件 §2 表内 P2-1 那一行的产出物因此**只兑现了第一项**，后两项见下）：
⇒ 报告 = `docs/spec/issue/selfhost-selfverify-report-2026-10-01.md`（`auth-71`）。
⇒ ⛔ **本表的批序不因此改变，但依赖关系被量清了**：挡住 P2 自洽的不是「某个特性缺」，
而是 **模块 → IR → 解释器的装配通道不存在**（⚠️ **量级项**）—— 它同时把覆盖面读数**放大**了
（全局划出面里至少 54.4% 是它的产物）。⇒ 该通道的重建**须另立条目**，
且它正是 §4 那条依赖图里「扩展方法 → P2 自洽验证」之前**未画出的一格**。
⚠️ 本件**不复述读数**（数字在报告与自举仓读数件里）。

## 3. P2-0 基线批的判据骨架（首批，待点名）

1. **模块检查墙钟分段**：module-check 内部按层计时（common→module 九段各占多少）——
   定位热点层；
2. **代表性语料执行墙钟**：prog1–7 各跑 N 次取分位（⭐ 这批语料已经是判据程序集，
   基线免费拿）；
3. **对账表固化**：§1.2 的差距表升格为受管载体（每行带契约条目号与宿主参照位）——
   后续每格回填以此为销账单位；
   ✅ **已落（P2-0）**：`docs/spec/issue/selfhost-gap-ledger-2026-09-30.md`（⚠️ 该数口径问题见 §1.2 表下的注）。
4. 判据 = 基线读数件落盘 + 复跑可复现（分位差 < 10%）；变异反证 = 读数件数字手工改错
   后器械须红（防「写了没生效」）。

## 4. 特性回填序列（依赖排序，逐格点名）

```
插值（M4）──┐
扩展方法 ───┴→ P2 自洽验证 ─→ CodeGen 首段（.ll 线性发射）
                                  ├→ 特性回填（并行排）：
逻辑运算符（G81，最小）────────→  │
Collections 完整面 ────────────→  │
闭包 / 函数值 ─────────────────→  │
泛型 ──────────────────────────→  │
指针 / FFI ────────────────────→  ┘
```

⭐ CodeGen 语义纪律：**按契约钉语义，与宿主 LLVM 的在案 B 组偏离逐条对账、⛔ 不镜像**
（弱对比方法论的红利：自举从零写，天然可以写「正确语义」那一份）。
