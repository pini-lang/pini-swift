# 影响评估：给定块（`given`）与取用参数（`using`）

> **性质**：`../pini-spec-v0.md` §1.3 变更治理流程**第 2 步**的交付物。
> **配套 ADR**：`../adr/adr-001-given-blocks-and-using-parameters.md`
> **稳定性**：**Experimental**（用户裁定）· **实现状态**：未落地 · **日期**：2026-09-19
> **决策过程与实测记录**：`proposal-given-using-examples-2026-09-19.md`（本件只做影响面判定，不重复推演）

---

## 1. 结论摘要

1. **不触及 Stable** ⇒ **不需升级评审**（§1.3 第 2 步的触发条件未满足）。
2. **已定部分无破坏性变更**：`|given` 与 `using 名: 类型` 都是**新拼写**，不改变任何既有合法程序的含义。
3. ⚠️ **唯一的破坏性风险在待决项里**：`using` **入关键字表**会使它从合法标识符变为保留字。本件按「待决」标注，不计入已定部分。
4. **稳定性定 Experimental** ⇒ 按 §1.3 第 4 步条件①，**不递交语言参考**。

## 2. 受影响的构造及其稳定性级别

> 级别取自 `../pini-spec-v0.md` §2.4.1 构造级索引与 §3 缺口台账（**现状值，非本决定的定级**）。

| 受影响构造 | 现级别 | 影响方式 | 破坏性？ |
|---|---|---|---|
| 类型声明定界符 `( ) { } [ ] < >` | **Provisional** | 块修饰符集**加一项** `given`（现有：`object` / `enum` / `import` / `export` / `foreign`） | ❌ 纯新增 |
| `func` 函数声明 | **Provisional** | 参数产生式**加修饰位** `using` | ❌ 纯新增（该位置今天无合法解析） |
| 扩展块 `((T))`/`{{T}}`/`[[T]]`/`<<T>>` | **Provisional** | 给定块的扩展块**不需要新语法**（按类型名挂载）；**用哪套括号待决** | ❌ |
| 特征块 `<名称>` | **Provisional** | 给定块可实现特征；特征签名**无需** `using`（默认实现走 `self`） | ❌ |
| 方法 `\|self` | **Provisional** | 无改动（给定块的 `self` = 接收者实例） | ❌ |
| `LazyRef<T>`（缺口台账 `G40`） | **Provisional** | **被复用**（字段级惰性），语义不变 | ❌ |
| 行首消歧规则 | Provisional | **不需要新行** —— 行首记号仍是 `[`，已在表内；`\|given` 属块修饰符位 | ❌ |
| 诊断码映射 | Provisional | **不需要新码段** —— 不认识修饰符走既有码（实测 `[名\|given]` 与 `[名\|zzz]` **同码**） | ❌ |
| 泛型 `<T>` + 运行时单态化 | **Experimental / Provisional** | 泛型给定块**设计上成立**；⚠️ 既有实现边界会挡住其实测 | ❌ 设计层无冲突 |
| 异步 `=>` 派发 + `await`/`wait` | ⭐ **Stable**（阻塞语义） | ⚠️ **见下节** | ❌ **不改它** |

## 3. 是否触及 Stable —— **否**

`../pini-spec-v0.md` 中定级 **Stable** 的构造**只有一处**：**异步 `=>` 派发 + `await`/`wait` 的阻塞语义与结构化并发契约**（缺口台账 `G12`）。

本决定**不修改**它的任何条款：`given` / `using` 是**声明与取用**机制，与 `=>` 的派发语义、`await`/`wait` 的 join 语义不相交。

⚠️ **但有一处须显式记账**：草案把「**急切派发**」列为卖点，而它**依赖「异步方法调用产出 Future」**这一形态 ——
该形态**尚未落地**（实测：异步**方法**调用不产出 Future，与自由函数不同）。⇒ 这属**该卖点的前提未验证**，
**不是**对本决定的 Stable 面的影响，也**不是**对 `G12` 条款的修改。已列入 `../adr/adr-001-given-blocks-and-using-parameters.md` 的改述项。

## 4. 破坏性判定

| 部分 | 判定 | 依据 |
|---|---|---|
| `\|given` 块修饰符 | **非破坏** | 新拼写；既有程序不含它 |
| `using 名: 类型` 参数 | **非破坏** | 实测该位置**今天无合法解析**（`E2-001`）⇒ 不抢占任何现有含义 |
| 字段取值默认急切 | **非破坏**（对新构造而言） | 与语言中每种复合类型同规 |
| 默认实例惰性物化 | **非破坏** | 纯新增能力；`LazyRef` 已有同类先例 |
| ⚠️ **`using` 入关键字表** | ⚠️ **破坏性** | `using` **今天是合法标识符**（可作变量名 / 参数名）⇒ 入表会使既有合法程序变非法。**属待决项，未计入本决定的已定部分** |
| ⚠️ **`\|own` 不得触实例** | ⚠️ **若实施则破坏** | 实测 `object` / `struct` / `enum` 三类扩展块的 `\|own` **今天都能用 `self` 触实例** ⇒ 收严会拒掉既有写法。⚠️ **但这是既有缺陷，不属本决定** ⇒ 已移入提案 X 组，另行立案 |

⇒ **已定部分的破坏性 = 无**；⇒ **不触发「跨 minor 破坏性 ⇒ 升级评审」**。

## 5. 语法面影响（逐处）

### 5.1 块修饰符集

`|given` 加入既有修饰符集（全为关键字）。**形态一致**：现有块修饰符 `object` / `enum` / `import` / `export` / `foreign` **全是关键字** ⇒ `given` 入关键字表是**形态一致性要求**，不是随意选择。

### 5.2 参数产生式

新增 `using` 修饰位。实测：`取|func(using x: I32,)` 今天报 **`E2-001`**（解析失败）⇒ **该槽位是空的**，加修饰符**不产生新的消歧负担**。

### 5.3 行首消歧

**不需要新行。** 行首记号仍是 `[`（已在表内）；`|given` 落在块修饰符位，归既有消歧规则。
⇒ 草案曾计划「行首消歧表加一行」，经核**可省**。

### 5.4 关键字表（⚠️ 待决）

`given` 与 `using` **今天都是合法标识符** ⇒ 入表是**破坏性变更**。逃生舱 = 反引号转义（实测可用）。
⚠️ **本项属待决**（`../adr/adr-001-given-blocks-and-using-parameters.md` §7 未决 1）；
若采用**前瞻式消歧**（既有先例：裸函数声明判定）可**不入表**，从而消除破坏性。

### 5.5 诊断码

**不需要新码段**：未知块修饰符走既有码。
⛔ 但有一处**须注意方向**：`|own` 不得触实例所**需要**的诊断语义与既有「无此成员」不同（那是「成员不存在」，这里是「此上下文不可触实例」）—— ⚠️ **该需求属既有缺陷（提案 X 组）**，不在本决定的诊断影响内。

## 6. 语义面影响

| 面 | 影响 |
|---|---|
| 名字解析 | `using` 解析**按类型**，编译期完成；**无运行时查找、无 vtable** |
| 初始化时机 | **新增一种**：默认实例的惰性物化（恰一次）。⚠️ **不改变**既有任何构造的初始化时机 |
| 字段求值 | **不改变** —— 默认急切，与既有复合类型同规；字段级惰性走 `LazyRef` |
| 参数可变性 | **不改变**（该议题不属本决定） |
| 依赖可见性 | **新增强制**：值位引用给定块类型 ⇒ 签名须声明。⚠️ 这是**新约束**，但只作用于**含该引用的函数**，不影响既有代码 |
| `main` 入口 | **不改变**（惯例入口不带参数） |

## 7. 运行时面影响 —— **复用既有设施**

| 需求 | 既有设施 | 结论 |
|---|---|---|
| 惰性 + 恰一次 + 线程安全 + 地址稳定 | `LazyRef`（`G40`，Provisional，已转正） | ⭐ **复用** —— 草案曾把「新增运行时机制：惰性初始化 once」列为代价，**该代价不成立** |
| 跨后端可用性 | `bk_lazyref_*` C-ABI 面 | ✅ LLVM 后端现成可用 |
| 集合 / COW | `bk_array_*` / `bk_dict_*` / `bk_set_*`（`G34`） | 无改动 |

⇒ **本决定不新增任何运行时机制**；唯一新增的是**编译期**行为（按类型解析默认实例 + 依赖检查）。

## 8. 自举可用性评估（`../pini-spec-v0.md` §3 第 2 条与执行指引要求）

> 规范明文判据：「以 Pini 写的 Pini 编译器能否用它表达宿主实现需求」。

**成本可当场量出**：自举编译器的 AST 用**枚举**描述语言构造（`examples/selfhost/src/ast/ast.pini` 的 `[decl]` 列出全部声明种类，全是用例）。加入给定块只需**一个枚举用例**：

```
given_decl(name: String, fields: Any, loc: src_loc,)
```

- 与既有 `struct_decl(… fields: Any …)` **同构**；
- 字段载荷**复用**既有 `[field_decl]`；
- ⇒ **一个用例 + parser / semantic 分支**，成本可数、无新表示。

⚠️ **跨仓约束**：自举仓是**嵌套独立仓** ⇒ 改动须走**自举仓自己的分支 + `--no-ff` 合并**，属**另一条授权线**。
