## 1. Motivation

**表内 ID 一直在被外部载体引用，而本表是滚动表。** `tools/evidence_sweep.py` 按新鲜度自动清扫
（≤1h `FRESH` / ≤72h `STALE` / >72h `PENDING_DELETE` → 下一轮删除），所以任何写进规范正文、ADR、
工单、计划、CHANGELOG 或源码注释的编号，**必然在某次清扫后指向空**。改型前的实测读数：表内 15 条，
而表外有 97 处编号出现、分布在 26 个文件里。

上游机制（`docs/spec/issue/archive/issue-evidence-table-sweep-2026-09-03.md`）对悬空债务的处置是「**记进表里**
（`meta.dangling_ids`）、由人工处置」，并把「归档件 / 已关闭工单 / ADR / spec 历史登记行允许引用已清理
ID」写成口径。该口径的两处代价在 2026-09-15 暴露：

1. **它是按载体分类的规则**——每新增一类载体就要重判一次，而真正的结构事实是「引用必然悬空」。
2. **债务是可见但不被处理的**——`dangling_ids` 改型前已积到 37 个编号，没有任何动作会迫使它们结算；
   同一时期另一处实测（`E-151（源已删除）`被一张 Open 工单引用而条目已删）正是这种「记在表里也没人看」的实例。

另一条独立动因来自用户对 ID 可读性的判断：旧编号（含内部批次代号，如 `p2b` / `g1` 一类命名）**读表的人
看不懂**，而「看不懂的 ID 又偏偏被到处引用」正是上面那条债务的来源。

## 2. Evidence（改型前实测，2026-09-15）

测量方式：全树 `rglob` 扫描（跳过 `.git` / `.build` / `__pycache__` / `DerivedData`，跳过二进制，
按文件名排除表本体），正则 `\bE-\d{3}\b` 带词边界。

| 事实 | 值 |
|---|---|
| 表内条目 | **15**（computed：`FRESH` 1 / `STALE` 9 / `PENDING_DELETE` 5） |
| 表外编号出现 | **97 处 / 61 行 / 26 文件** |
| 其中引用**已删**编号 | 46 行（涉及 37 个已删编号） |
| 其中引用**表内现存**编号 | 23 行（如 `docs/spec/hir-contract.md`、`docs/CHANGELOG.md` 的活断言） |
| `meta.dangling_ids` 存量 | **37** 个编号 |
| 编号史实核查 | `git log -p -- docs/spec/evidence-table.toml`（该文件被改 **78** 次）去重后**首号到末号连续无缺号**（覆盖全部 170 个历史编号）⇒ 37 个悬空编号**每一个都真实存在过** |

`\bE-?\d{3}\b` 曾把 `IEEE-754` 误判为编号（缺词边界）——该次假阳性是本件判据**必须带词边界**的直接来源。
另实测：全仓**不存在**不带连字符的 `E` + 三位数字形态（0 处），故器械的编号正则收紧到**必带 `-`**。

## 3. Decisions（用户裁定，2026-09-15）

| # | 议题 | 裁定 | 被否方案与理由 |
|---|---|---|---|
| D-1 | 表内 ID 形态 | **日期前缀 + 中文自描述短语**（含空格），旧编号在**表内彻底退役**；每条加 `citable = false` | 曾提「时间戳 + 主题短语」但含内部批次代号 ⇒ 用户否：「主题依然没人看得懂，很快就会出现一些乱七八糟的计划编码和 p2 之类的碰撞到一起」 |
| D-2 | 引用**已删**编号的 46 行 | **保留编号 + 加注「（源已删除）」** | 用途是**说明它为什么悬空**（表已清空，查不到），故不改成摘要 |
| D-3 | 引用**表内现存**编号的 23 行 | **改成简短摘要**（不指向别处） | 这些条目「迟早会清空」；且它们**没被删、只是改名**，标「源已删除」是造假 |
| D-4 | 执行顺序 | **分两批**：先修字符串（已收口），再做本批 | — |
| D-5 | 规则源头 | 改写 spec §1.4 的「ID 空间」与「被引用条目照删」两条；替换 `meta.dangling_policy` | — |
| D-6 | 器械 | 新增「表外出现编号而无标注 ⇒ 报错」，接入 `pre-commit`，**须做变异反证** | 即用户裁定的「丙」＝甲（改型）＋乙（逐条标注）＋让检查程序报错 |

**核心立场（一句话）**：**这个证据表的 ID 不应该被引用**；与其给不同载体分类开口子，不如让器械拦下。
