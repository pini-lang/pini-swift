## 1. 动机（实测，不是推断）

**现象**：原生臂跑自举发射器的整包面时，内存**加速**上涨 —— 62 s 内 0.21 GB → **4.2 GB** 且仍在涨。

**隔离读数**（同一份源 · 两条路径 · 量峰值 RSS）：

| 形态 | N 扫描 | 原生臂峰值 | 解释路径峰值 | 判读 |
|---|---|---|---|---|
| 缓冲累积（`emitLine` 的 `self.buf = self.buf + 行 + "\n"`） | 500 → 4000 | 8.9 → **206.2 MB** | 9.5 → 11.1 MB | **二次方**（吻合 Σ(单行长度×i)）⇒ **内存**缺陷 |
| 别名往返写入（`ixPut` 的「别名 → 写 → 回存」） | 100 → 6400 | 6.8 → 7.3 MB | 16.2 → 20.1 MB | **不泄漏** ⇒ 那是**时间**缺陷（另一条，已裁暂不修） |

**归因**：爆炸期栈采样（1644 样本中 960 个落在同一条链）指向 `emitStmt → emitStringConst`，
即**字符串拼接**。机理 = native 字符串是裸 `char*`、**运行时段不导出任何释放入口**、
而发射出来的拼接是内联 `strlen` 两次 + `malloc` + `strcpy` + `strcat`
（实测产物里 `malloc` 1 处 · **`free` 0 处**）⇒ 被覆盖或被丢弃的旧串**无人回收**。

**后果（要紧）**：自举发射器整篇是「累积拼接」形态 ⇒ 整包原生臂**必被杀** ⇒
发射器族的**13 处**门禁调用点因此不能接臂。⚠️ 同一入口在**小模块**上 0.08 s 干净跑完
（10.8 MB）⇒ 与规模强相关，⛔ 不是入口本身坏。

## 2. 影响面

### 2.1 这不是语言面语义变更（这一节决定走哪条流程）

| 事实 | 出处 |
|---|---|
| `String` 是**值类型**且**不可变** | 语言规范的类型层 / 语言参考的类型表 |
| 语言参考自陈「**无所有权、无借用**」 | 语言参考（设计原则节） |
| ARC 只覆盖 `object`（引用类型） | 语言参考（引用计数节） |
| IR 契约把 `string` / `char` 的表示钉为 `i8*` | `docs/spec/ir-contract.md`（表示表） |
| IR 契约的 `stringConcat` 条目明写「两侧结果一致，**仅分配方式不同**」 | `docs/spec/ir-contract.md`（表达式条目） |

⇒ **缺陷性质 = 实现质量缺陷（泄漏）**，而它在语言层**不可观测**
（字符串不可变 ⇒ 「共享」与「复制」不可区分；泄漏不改任何可观察行为）。
⇒ 因此「更新规范章节 / 递交语言参考」这两步**不适用**；
本件的落点候选 = **运行时段 ABI + 两个发射器**（⛔ 不是规范正文）。

### 2.2 触面清单（逐面）

| 面 | 现状 | 本方案要动什么 |
|---|---|---|
| 运行时段分配入口 | `strdup` **23 处**；导出入口 **75 个** | 全部改道一个带头的分配器；新增 `retain` / `release` 入口 |
| 运行时段分配契约文本 | 多处注释写「`strdup`，**调用方释放**」 | 改为引用计数语义（属运行时段自身文档） |
| 数组元素槽 | `.str`（tag 3）是**裸指针**，`deepCopy` **只对 `.handle` retain** | 元素槽的 `.str` 也要配对 retain/release（⛔ 只碰所有权一处） |
| 宿主发射器 | 产物里 `free` 仅 1 处（打印临时） | 在四个点插 retain/release；该 `free` 改 `bk_str_release` |
| 自举对齐腿 | 同上 | **镜像同一序列**（见 §7） |
| ⛔ 不动 | 数组 COW 的**时间**缺陷（每写全量深拷） | **不碰** —— 用户已裁「暂不修」 |

### 2.3 影响面的规模提示

运行时段是**共享面**：本方案改的是**所有**字符串产生点与**所有**持有字符串的槽，
故它**不是**一个可局部收窄的补丁 —— 但切分见 §6（可逐片独立验收）。

## 3. 是否破坏性

| 面 | 破坏性 | 理由 |
|---|---|---|
| 语言层 | **否** | 不可观测（不可变 ⇒ 共享与复制不可区分） |
| IR 契约 | **否** | `i8*` 表示不变；分配策略本就不在契约内 |
| 运行时段 ABI | **是** | `bk_*` 的分配契约由「调用方 free」改为引用计数；`free` 站点改 `bk_str_release` |
| 既有产物 | **是** | 旧 `.ll` 与新运行时段混链会错放 ⇒ 须**一次性同批**切换 |

⚠️ 裁源已明示「**不把 ABI 稳定性当选路约束**」⇒ 上表两处「是」**不构成反对理由**，
只作为**切换纪律**（同批切、别混链）登记。

## 4. 目标要写成两句，⛔ 别压成一句

| # | 目标 | 只做所有权能否达成 |
|---|---|---|
| **T1** | 原生臂的**内存**不再二次方滞留（整包跑得动） | ✅ 能 —— 中间串被及时回收 ⇒ 峰值回落到「最大单串」量级 |
| **T2** | 原生臂的**时间**不再是 O(N²) | ❌ **不能** —— 拼接本身要复制整段累积，回收不改变这一点 |

⚠️ 但 T2 的**绝对量可接受**：整包约 6.7 万次拼接 × 平均累计 3.3 MB ≈ 2×10¹¹ 字节复制
（按 10 GB/s 记忆体带宽 ⇒ 约 20–60 s），而解释路径今天是 **13–21 分钟**
⇒ **T1 达成即已解锁那道被卡的判据**。T2 若要，另点一条（见 §5 候选 C）。

## 5. 候选与代价

| | 机制 | 表示 / 契约 | 失败形态 | 改动面 | 判定 |
|---|---|---|---|---|---|
| **A** | **引用计数串**：计数头放在指针**之前**，新增 `bk_str_retain` / `bk_str_release` | `i8*` **不变** ⇒ IR 契约**零改动** | 漏放 ⇒ **泄漏**（fail-safe） | 运行时段（分配点 23 · 导出 75）· 两个发射器插四个点 · 元素槽的 `.str` 配对 | ⭐ **建议** |
| B | 帧级回收：`bk_frame_push` / `bk_frame_pop` + 逃逸提升 | `i8*` 不变 | 过早弹帧 ⇒ **悬垂 / 踩内存**（fail-dangerous） | 函数边界少，但「存入堆」处仍须提升 | ⛔ 不建议 |
| C | 发射器改可增缓冲（只改自举发射器的累积写法） | 无改动 | 无 | 只动 `emit.pini` 的累积 | ⛔ 只解 T2；**不解语言面泄漏**（`s = s + "x"` 循环实测仍 1.4 GB） |

### 5.1 为什么 A 不必做精确别名分析（这是它可行性的关键）

字符串**不可变**且语言层**不可观测** ⇒ **保守的 retain/release 恒安全**
（多留一份只是慢，⛔ 不改变任何可观察行为）⇒ 插入点是**机械**的，共四类：

1. **产出点**：`bk_*` 返回的串已 +1（调用方接管）；
2. **覆盖点**：字符串槽被写入时 release 旧值；
3. **退出点**：作用域 / 函数退出时 release 其局部字符串槽；
4. **逃逸点**：`return` · 存入数组元素 · 存入名义字段 · 交给 `foreign` 时 retain。

⇒ ⛔ 不需要「谁拥有这份引用」的精确分析 —— 这是 A 相对 B 的**决定性优势**。

| 片 | 内容 | 验收 |

| 3 | 自举对齐腿：**镜像同一序列** | 「两侧逐字节相同」那族门禁（见 §7，**这两片必须同批**） |

## 7. ⚠️ 本方案会**加重**开放项册 `N51`（必须先说清）

那族门禁的判据是**两条腿的产物逐字节相等** ⇒ 插入 retain/release 后，
**两个发射器必须发出完全相同的序列** ⇒ 此后每一次所有权规则的调整都要**两侧同批**改。
⇒ 建议：§6 的片 2 与片 3 **合成一个同步批**做；⛔ 只改一侧会让门禁长期红在「两侧不等」上。

## 8. 验收判据与反证

- **T1**：复用 §1 的两路径探针（同一份源 · 两路径 · 峰值 RSS）⇒ 缓冲累积形态在 N=4000 处
  从 **206 MB** 降到「最大单串」量级；**阴性对照** = 解释路径读数**不动**。
- **T2**：同一探针量**墙钟**。⚠️ 预期「仍随 N 超线性」—— 那是**正确**的（拼接本身没变），
  ⛔ 不得读成失败。
- **不回归**：`s = s + "x"` 循环（n=50000）两路径对照，从 **1403 MB** 降到与解释路径同量级。
- **变异反证**：撤掉第 3 类点（退出释放）⇒ 应见**峰值回升**而**行为输出不变** ——
  这条同时证明判据量的是「回收」、不是「值」。
