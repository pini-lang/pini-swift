## 四、勘误（2026-09-05 批③ 复测订正）

1. **row 9 `|path` 系误读链**：草稿原文 `[路径枚举|关键字]`（§[名称|import] 一带）说的是**把包路径绑定到用例标识符的 import 全导入/export 例外表**——即 P4 已实现的 import/export 块，**不是**一个 `path` 关键字。误读源头为归档审计 `docs/spec/issue/archive/issue-draft-audit-disposition-2026-08-31.md` A13（「path 关键字未实现」），本工单 row 9 与探针 p18 逐级传染。订正：本行改判；p18 探针重写为草稿本意形态（`p18_import_draft_form.pini`）；A13 归档文件加勘误注。用户 2026-09-05 裁决：path 关键字（误读产物）通过治理流程移除——因实现/spec EBNF 本就不存在该形态，移除对象为上述文档记载。
2. **import/export 不是超售（原判「全形态 REJ 零语料」为假阴性）**：复测 `[自识名|import]` / `[自识名|export]` 单文件解析 PASS（初测假阴性原因：探针块头名违反 D-1 自识性规则——文件名带连字符或头名与文件名不符）；测试语料在库（ImportExportTests / ModuleSystemTests / GrammarConsistencyTests.testProductionsImportExport）。spec L263「P4 落地」与 G52 批 1 记载属实。
3. **参数默认值从来不是 spec 超售**：spec 明写「无默认值」（§A.2.2 注）与「声明位不接受 `=`（默认值另议）」（规则 3.15）——宿主拒绝与 spec 一致。该意图只存在于草稿（审计 A6），已在提案池，无需处置。原「三大超售」实为**一项**（`<<T>>`）。

**教训入档**：本轮两项假阴性均源于**探针自身语法错误**（文件名含连字符破坏 D-1 自识名、自造不存在的记号）——「实现拒绝」结论必须先用能通过词法/自识校验的最小正确样例复测一次，方可入账。
