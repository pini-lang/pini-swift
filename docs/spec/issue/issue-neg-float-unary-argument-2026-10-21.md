# Issue：一元负号的浮点表达式做实参 ⇒ 自产产物是**非法 .ll**（clang 直接拒编）

- 状态：**Open（已立案 · 未开工 · 未排期）** —— 用户 2026-10-21 点名「立案，有可能裁定为 MVP 之外而暂不做，
  或延迟做，或立刻做」⇒ 三种处置见「待裁」；⛔ **本单未自行占用开放项册编号**。
- 层级：**自举级**（IR 降载/发射的**实参类型**面）。语言面已定义一元负号、宿主发射器也正确。
- 发现来源：2026-10-21 浮点字面量指数形态批（`N91`）—— 该批把位型助手搬进自举源码时，
  原型里的 `f(-1.5)` 让自举产物**编不过**，由此撞出。
- 关联：宿主规范台账 `N73`（宿主侧常量折叠遍 · 自举侧没有）—— 本条与它**相邻但不同**：
  `N73` 解释「为什么两侧形态不同」，本条解释「为什么自举那一侧是**非法**的」· 自举仓读数件 `§137`。

## 问题

一元负号作用于浮点表达式、且该表达式出现在**实参位置**时，自举发射的实参类型是 `i32`，
而值是 `double` ⇒ **类型不符的调用**：

```
 %t2 = fneg double %t1
 %t3 = call i32 @negArm(i32 %t2)      ← 实参声明 i32，值是 double
```

⚠️ **危害形态**：不是错值，是**产物无法链接** —— clang 报
`error: '%t2' defined with type 'double' but expected 'i32'`。
⇒ 这条**不会静默**（比错值好），但它把「这段源码不可编译」这一事实推迟到**链接期**才暴露，
而 IR 腿的逐字节判据只比文本、不编译 ⇒ **判据面看不见**（见「实测」的第三行）。

## 实测（2026-10-21 · 两腿现跑 · 探针在仓外临时目录）

三份最小源，同一个 `negArm(x: F64) -> I32`：

| 实参写法 | 自举发射 | 宿主发射 | 自举产物 | 宿主产物 |
|---|---|---|---|---|
| `-1.5`（字面量） | `fneg double 1.5` → `call @negArm(i32 %t1)` | `call @negArm(double -1.5)`（折成字面量） | ❌ 编不过 | ✅ 输出 `0` |
| `-v`（局部变量） | `fneg double %t1` → `call @negArm(i32 %t2)` | `call @negArm(double %t2)` | ❌ 编不过 | ✅ 输出 `0` |
| `0.0 - v`（二元减法，**对照**） | `fsub double 0x0, %t1` → `call @negArm(double %t2)` | **逐字节同** | ✅ | ✅ |

⇒ 边界清楚：**一元负号**在实参位置出事；**二元减法**正常。
⇒ 与字面量无关（变量形式同样红），⛔ 不是「负字面量」这一族专有。

## 已排除（⛔ 别再往这些方向查）

- **不是 `fneg` 本身错**：指令是对的（`fneg double %t1`），错的是**调用点声明的实参类型**。
- **不是字面量解析错**：变量形式同样红（`-v`）。
- **不是 `0.0` 的常量文本问题**：对照那行的 `fsub double 0x0, %t1` 两侧**逐字节相同**。
- **不是逐字节判据能看见的**：现有语料里没有「一元负号做实参」的形态 ⇒ 判据面一直是绿的。

## 影响面

- 自举源码**零使用**（无 `f(-x)` 形态）⇒ 今天的自产产物不受影响。
- 但它是**语言可用性**的硬缺口：写「取负后传参」这种最普通的算术就会得到编不过的产物。
- 与 `N73` 叠加时读数会**说不清是谁的**：宿主把 `-1.5` 折成字面量（形态差），
  自举不折（`fneg`）**且**传错类型 —— 一个红里两个成因 ⇒ 语料要分开写。

## 建议

**A**：`irUnary` 节点自己就有 `type`（承载里已存在），说明**类型信息在**、只是实参位置没读它 ⇒
这是「接线」而不是「补能力」。开工时**先量一次**「实参位置取类型的代码有几种形态」
（字面量 / 一元 / 二元 / 调用 / 字段读），确认不是只修一元那一支。
