# 在案开放项册（Open Items Register）

> **本件是什么**：全轨**开放项**（未交付 / 未裁 / 未修 / 未量）的**单一收拢处**。
> ⛔ **它不是新权威** —— 每条都指认自己的权威载体，本册只做三件事：
> ① 把散落六处的开放项**收成一张表**；② **归并同源项**（同一堵墙的不同说法）；③ **销账已解消项**（带证据）。
> ⇒ 判据「一条项只能有一个主人」：本册管**索引与收拢**，语义仍归各自治载体。

**为什么建（本件的立项依据，逐字取自载体）**：原「待裁清单」载体的那一行写着 ——
「原 `decision-backlog-2026-09-28.md` **载体已删** ⇒ 存量待裁项散在各载体，收拢须另行点名」。
本件即那次收拢（2026-10-02 · 元仓授权条目按用户当轮指令登记，见 `L0 授权台账`）。
⚠️ 同批还有一处**反向依据**：授权台账里**多个条目自带 `still_open` 字段**，而主简报同期只记
「仍开 11 项」⇒ 两者**差数倍**，正是分散的直接代价。
⭐ **那两组数只作「建册时（2026-10-02）实测」，⛔ 本册不复述**（台账每批都在变，写死即成谎）——
要现值请**现读**台账的 `still_open` 字段；本册的职责是**收拢**，⛔ 不是记账。

**它管的范围**：**开放项**。⛔ 不管已结案的历史、⛔ 不复述读数（那些在自举仓读数件与探针记录里）。

**状态栏三态**（⛔ 别混读）：
- `开` = **真开放**，须**点名**才动（多数项的原载体已如此声明）；
- `条件` = 现在不是开放项，**触发条件成立时**才转开（例如判据退化、某前置落地）；
- `已销` = 本批或此前**已解消**，附证据摘要，⛔ 不再计入开放数。
  ⚠️ **`已销` 的项⛔ 不占 §1 / §4 的开放位** —— 它们**逐条列在 §5.1 的归并记录里**（那是本册唯一列出「已销」条目的地方）；
  ⇒ 读法是：**§1 与 §4 的行 = 当前开放面**，**§5.1 = 已结部分**，⛔ 别把两处的条数相加当「总项数」。
  ⚠️ **编号不回收**：一项被销账后，该编号**只在 §5.1 出现** ⇒ 主表（§1 / §4）**允许出现编号缺口**
  （2026-10-02 首例 = `N39`）⇒ **缺口不是漏登**。

| **N62** | ⭐ **IR 切片里没有「浮点字面量」节点** ⇒ `F64` 的初值在承载里落回 `irIntConst(0, irI32)` | `开` | 实测（对齐腿控制流/枚举批）：`var x: F64 = 1.5` 经降载后类型正确（`irF64`）但**值丢失** ⇒ 本腿发 `store double 0` 而宿主发 `store double 1.5`。后果：`irBinary` 的 `fcmp` 臂与浮点算术臂**今天没有任何语料能走到**（`ir-bin-ops` 因此刻意不含浮点）。**解除条件**：给 IR 切片补一个浮点字面量节点（属 IR 格），随后补浮点语料 ⇒ 那两条臂才有见证 |
| **N63** | ⭐ **`irCall.returnType` 对普通（带实参的）调用恒为 `irI32`** | `开` | 降载侧构造 `irCall` 时硬写 `returnType = irI32`（只有零参内建 `argv` 那一支带了真类型）。⇒ **返回 `F64` / 名义值 / 枚举值的用户函数调用**在承载上类型错，发射器照它发即写错。本批因此**不收**该形态进语料（`ir-enm-match` 首版正是被它挡下）。⚠️ 与 `N56`（void/i32 不可分）**不同处**：那条是「两态同形」，本条是「一律 i32」。**解除条件**：令降载侧带真返回类型，或让承载附带一张「按名查签名」的表 |
| **N64** | ⭐ **`for` 的迭代物取「变量」时承载类型落 `irI32`** | `开` | 实测：`var a = argv()` 后 `for (x,) in a:` ⇒ 变量声明的类型落 `irI32`（降载侧的**初值类型推断**不认 `argv` / `split` 这两个内建的返回）⇒ 发射器发 `bitcast i32` 而非 `%bk_array*`。**直接调用**形态（`in argv():`）**已覆盖**且逐字节同。⚠️ 与 `N63` 同族（都是「承载的类型信息不足」）。**解除条件**：扩初值类型推断（认这两个内建），或让承载带推断结果 |
| **N65** | ⭐ **枚举值的 `print` 渲染面未接** | `开` | 宿主为 `print(枚举变量)` 烘一串 `fmt.enum.*` 臂（按 tag 分派到各用例的字面段）与若干字面常量；对齐腿**未接** ⇒ 该形态逐字节红（`ir-enm-ctor` 首版正是被它挡下的）。⚠️ 属**渲染面**，与枚举的构造/分派/释放**不同面**。**解除条件**：点名一条「渲染面」片（含 `fmt.enum.*` 的臂形态与串表次序），或明示该形态不在 MVP 切片内 |
| **N66** | ⚠️ **具名构造写错字段标签时，`pini check .` 拦不住** —— 只有 IRGen 才炸 | `开` | 实测（本批自身踩到）：把 `caseName` 写成 `cname` ⇒ `pini check .` **照样通过**（语法/结构层），`run` 到 IRGen 才报 `E6-004` + `unsupported feature 'case 'X' has no associated value labeled 'Y''`。⚠️⭐ 这同时是 **`E6-004` 的一个新失败形态**（既有四处文档指认的是「member access outside the slice」那一支）。**可操作纪律**：凡改动**具名构造 / 具名解构**，必须跑一次真实执行（哪怕最小语料）⇒ 已写进对齐腿件头。**解除条件**：把「标签名不存在」提到语法/结构层拦（或给 `E6-004` 补一条更准的诊断） |
