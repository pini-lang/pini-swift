# 在案开放项册（Open Items Register）

> **本件是什么**：全轨**开放项**（未交付 / 未裁 / 未修 / 未量）的**单一收拢处**。
> ⛔ **它不是新权威** —— 每条都指认自己的权威载体，本册只做三件事：
> ① 把散落六处的开放项**收成一张表**；② **归并同源项**（同一堵墙的不同说法）；③ **销账已解消项**（带证据）。
> ⇒ 判据「一条项只能有一个主人」：本册管**索引与收拢**，语义仍归各自治载体。

**为什么建（本件的立项依据，逐字取自载体）**：原「待裁清单」载体的那一行写着 ——
「原 `decision-backlog-2026-09-28.md` **载体已删** ⇒ 存量待裁项散在各载体，收拢须另行点名」。
本件即那次收拢（2026-10-02 · 元仓授权条目按用户当轮指令登记，见 `L0 授权台账`）。
⚠️ 同批还有一处**反向依据**：授权台账里**多个条目自带 `still_open` 字段**，而主简报同期只记
「仍开 11 项」⇒ 两者**差数倍**，正是分散的直接代价。
⭐ **那两组数只作「建册时（2026-10-02）实测」，⛔ 本册不复述**（台账每批都在变，写死即成谎）——
要现值请**现读**台账的 `still_open` 字段；本册的职责是**收拢**，⛔ 不是记账。

**它管的范围**：**开放项**。⛔ 不管已结案的历史、⛔ 不复述读数（那些在自举仓读数件与探针记录里）。

**状态栏三态**（⛔ 别混读）：
- `开` = **真开放**，须**点名**才动（多数项的原载体已如此声明）；
- `条件` = 现在不是开放项，**触发条件成立时**才转开（例如判据退化、某前置落地）；
- `已销` = 本批或此前**已解消**，附证据摘要，⛔ 不再计入开放数。
  ⚠️ **`已销` 的项⛔ 不占 §1 / §4 的开放位** —— 它们**逐条列在 §5.1 的归并记录里**（那是本册唯一列出「已销」条目的地方）；
  ⇒ 读法是：**§1 与 §4 的行 = 当前开放面**，**§5.1 = 已结部分**，⛔ 别把两处的条数相加当「总项数」。
  ⚠️ **编号不回收**：一项被销账后，该编号**只在 §5.1 出现** ⇒ 主表（§1 / §4）**允许出现编号缺口**
  （2026-10-02 首例 = `N39`）⇒ **缺口不是漏登**。
