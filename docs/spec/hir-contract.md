# HIR 节点语义契约（HIR Node Semantic Contract）

- 性质：**宿主级规范**。HIR 节点语义的**唯一权威载体**。
- 依据：本契约自身为语义权威（原依据件已随旧决策记录退役；现行治理见 `pini-spec-v0.md` §1.3 与 §3 台账）。
- 版本：v1（2026-09-12，随 P0b 首次落地）。
- 变更：走 `pini-spec-v0.md` §1.3 五步治理；条目一经落地**不得随实现漂移**（冻结纪律照搬 bk_* 范本）。

## 0. 定位与判读规则

### 0.1 权威次序（HIR 契约是语义权威）

1. **语言面语义**（用户可见行为）以 `pini-spec-v0.md` 为准 —— 本契约**不得与之冲突**；
2. **HIR 节点语义**（后端间契约）以**本契约**为准；
3. 各后端实现（解释器 / LLVM / 未来 WASM）**与本契约一致**；**任一后端都不是定义处**。

### 0.2 本契约的表述纪律（强制）

- **语义列**只写后端无关的行为约定。**不得**出现 `bk_*`、`alloca`、`fgets`、`strtok`、
  `memcpy`、GEP、refcount 布局、fat pointer 形状等实现细节；
- 实现细节只能出现在**「LLVM 侧实现注记」**列，且其地位是「一种实现」，不是语义；
- **禁止**以 `bk_*` 行为定义语义 —— 否则等于把某一后端的实现选择升格为全体后端的义务
  （HIR 契约是语义权威、WASM 约束）。

> **反例（本契约立此存照）**：`HIRNode.swift` 原注释写 `fileRead`「fread into a 64 KiB
> stack buffer」——把缓冲尺寸写成了节点语义。本契约的表述为「读取整文件内容；上限见
> §2.8 注记」，尺寸降为实现注记。

### 0.3 三方对照核验（P1 脚本化的对象）

```
本契约条目  ↔  HIRNode.swift 的节点集  ↔  各后端实现锚点
```

核验须能双向报缺口：**有节点无契约条目** / **有契约条目无实现锚点**（计划 §8 第 2 层判据）。

## 1. 类型层（HIRType，21 case）

| 类型 | 语义（后端无关） | LLVM 侧实现注记 |
|---|---|---|
| `i32` / `i64` | 32 / 64 位有符号整数 | `i32` / `i64` |
| `u64` / `u8` | 64 / 8 位无符号整数 | 与 `i64` / `i8` 同拼写，符号性由运算承载 |
| `i8` | 8 位有符号整数 | `i8`；算术在发射期拓宽到 `i32` |
| `f64` | 64 位 IEEE-754 浮点 | `double` |
| `boolean` | 布尔 | `i1` |
| `string` | 字节串值 | `i8*` |
| `char` | **一个字素簇**（extended grapheme cluster，用户感知的「一个字符」）—— **不是**码点、**不是**字节；表示**与 `string` 同构**（`Char 表示与 String 同构` 方案 A），「恰含 1 个字素」的不变式**由类型系统承担**、表示层不设防 | `i8*`（与 `string` 同拼写；**零新 ABI**） |
| `result(ok:)` | `Result<ok, E>`；**错误槽类型擦除** | `{ i64, ok, i64 }` — 三槽是**布局约定** |
| `future(ok:)` | `Future<ok, E>`：**运行中的进程句柄** —— 与 `result` **不可互换**（后者是已结算的值，本条是还没结算的句柄）。**一次等待、结果恰一次**是语义 | 不透明句柄 `ptr`（与 `array` / `dict` / `lazyRef` 同族）；**句柄形状是后端约定** |
| `array(element:)` | 有序、可重复、值语义集合 | 不透明句柄（`%bk_array*`） |
| `optional(wrapped:)` | 有/无二态容器 | `{ i64, T }` 带 tag（**tag 取值是布局约定**） |
| `nominal(name:isObject:)` | 用户具名类型；`isObject=true` 为**引用语义**、`false` 为**值语义** | `%object.*` / `%struct.*`；**refcount 头是实现** |
| `enumeration(name:)` | 用户枚举（带关联值的 tagged union） | `%enum.*`；**tag 位置与槽宽是实现** |
| `dict(key:value:)` | 键到值的映射；**键唯一** | 不透明句柄（`%bk_dict*`） |
| `set(element:)` | 唯一元素集合 | 不透明句柄（`%bk_set*`） |
| `lazyRef(element:)` | **一次求值**、共享（引用）拷贝语义的惰性引用 | 不透明句柄（`%bk_lazyref*`） |
| `tuple(labels:fieldTypes:)` | 带位置与可选标签的异质定长组 | 聚合值；**按标签序取成员** |
| `function(params:returnType:)`（＋**取用下标集合**） | 函数是一等值；取用下标集合标出「哪些参数位可取用」（ADR-001 §2.6）—— **由推断产生、用户写不出、不参与类型等价** | fat pointer `{ptr, ptr}`；**首参恒为 env 是调用协议**；⚠️ 取用位**不进**运行时表示 |
| `pointer(element:)` | `*T` 原始指针（FFI） | 不透明 `ptr`；**load/store 按元素类型解码**（半语义，见 §2.29） |

> **乙类纪律**（甲类裁决统一到 LLVM 侧 E 组）：上表「布局约定」字样者为**后端约定**，WASM 端可另择
> 表示；标「语义」者为**必须实现的行为**。半语义两项见 §2.17（`optionalGet` 的 panic 面）
> 与 §2.29（`pointerLoad` 的符号扩展）。

- 契约条目一经落地，**变更须走 §1.3**；不得为迁就某后端实现而漂移；
- `bk_*` 是 **LLVM 后端的实现面，不是语义定义处**；其 ABI 冻结（`LLVM 后端重写` 约束 4）继续有效；
- **每个后端须能自备 shim** —— 既有的「shim 边界必须是 C ABI」MUST 得到强化
  （`pini-spec-v0.md` §3.2），因为多后端下每个后端都需要自己的值层实现面。

⭐ **上一版的处置留档（`DE-6a`，2026-09-21 —— 现已兑现，保留以说明当时的理由）**：
本清单的**口径是导出符号数**（即 `@_cdecl` 的匹配数，见本节上方「量具口径」注）⇒ 形状定案但
源码没有时把它加进合计就是**让这份清单说谎**，故当时明标「不计入」并约定实现落地时再计入。
⭐ 这条处置的依据是本仓既定纪律：**改动面不许超出**，且**读数要能与实现对上**。

⭐ **`bk_sleep` 的来历**（`DE-3c`，2026-09-21）：`sleep` 是并发内建里**唯一**被降载成一条普通调用、
而落点又必须由后端提供的那个。它此前在 LLVM 腿上是**未定义符号**（`@sleep`），于是**任何**含
`sleep` 的并发程序都跑不起来 —— 这掩盖在「发射层还没接线」这条更大缺口下面。
⛔ **不做成 libc 的睡眠**：解释器腿的对应物按**片**睡、每片查一次取消，取消因此在一片之内生效；
一条直通的 libc 睡眠会让两腿在**取消时机**上分岔。睡眠本就属**原语层**（`DE-1` §4：让出 / 恢复 /
续体保存归宿主），故它的落点是运行时符号。
⚠️ **一处如实边界**：解释器腿在检查点发现取消时是**抛**（abort 体），而 C ABI 面没有异常通道
⇒ `bk_sleep` 只能**提前结束睡眠**，体随后仍会跑完；**等待侧的归约是同一套**（盒子已置取消 ⇒
`bk_task_join` 回 `status = 1` ⇒ `err(CancelError)`）。体被真正中断要等发射层接上取消检查点。

#### 5.2.1 任务 / 并发族的**两处定案**（`DE-1` 留了空，`B-2` 补全）

⛔ 这两处在 `DE-1` §3 里**只写了签名、没写值**，而实现必须定 ⇒ 在此登记，免得被读成「实现自作主张」。
两处都是**补全**，**不改** `DE-1` 任何一个符号的签名。

1. **`status` 的取值**（三个 `-> status` 的符号共用）：
   `0` = `out` 已写（任务的 `Result` / 聚合结果）· `1` = **未取得 `Result`**：任务被取消或超时归约，
   调用方按 `err(CancelError)` 处置。非法用法（空句柄 / 越界）**不走 `status`**，一律 `bk_panic`
   —— 与既有 `bk_array_get` / `bk_dict_get` 同一通道。
2. **「运行时自己产生的 err」其载荷在 C ABI 面构造不出来** —— 这一层**没有值构造器、也没有 stringify**。
   `B-2` 的处置：取消 / 超时的身份由 `status` 承载；`bk_scope_close` 的聚合只写 **leaked 计数**。
   ⚠️ **原标为「待 `DE-3c` 换真实值」，2026-09-21 订正其归属**：`DE-3c` 接的是
   **派发 / 阻塞等待 / 剪枝**三个调用点，**不含**取消族与聚合 join ⇒ 这两处**没有**在本批被换。
   换它们的时机是**发射层接上取消族与聚合 join 的那一批**（`cancel` / `isCancelled` 的调用点、
   `joinAll` 的聚合载荷）—— 换的时候这两处（`status = 1` 与聚合载荷）要**一起**改。

#### 5.2.2 任务体的 **wrapper 返回协议**（`B-3` 定案）

⛔ `DE-1` §3.1 只写了「照 §2 第 2 条的 wrapper ABI，不新造」，而 `B-1` 实测判定**该条在走乙下不成立**：
那条统一 ABI（`ptr (ptr, ptr, ptr) -> ptr`）的返回是**单个 `ptr`**，**表达不了「跑完 / 已让出」两态**，
而两态正是让出在走乙之下的**全部内容**。故本族**必须**与 LazyRef / 给定块那一族不同形：

| 项 | 定案 |
|---|---|
| 形态 | `i32 (ptr code, ptr env, ptr out) -> i32` —— **状态走返回值、值走 `out`**，与 §5.2.1 第 1 条**同一约定**（该条已定「状态用 `i32`、值走 out 缓冲」） |
| 返回 `0` | 体**跑到底** ⇒ 三槽已写，由运行时决出该任务的 `Result` |
| 返回非 `0` | 体**已让出** ⇒ `out` **不许被写**，`future` **保持未决**，由**续跑方**决出（✅ **续跑入口已由 `DE-6a` 定案、`DE-6b` 落地**，见 §5.2.3） |
| 线程归属 | 体在**一条新 OS 线程**上开始（`bk_task_spawn` 内起线程）⇒ 这是本腿**原语层**的事（`DE-1` §4）。⚠️ **不作策略**：队列 / 优先级 / **选择下一个任务**仍归策略层（Pini 值经 HIR，裁定 28） |
| `bk_task_yield` | **查询**语义（`B-1` 订正）：`1` = 能真让出 · `0` = 合规降级。⭐ 答案**取自 L1 位** —— 与解释器腿 `capabilities.supports(.yield) ? 1 : 0` **同一条规则**，故两腿不会各说各话 |

#### 5.2.3 续跑入口与帧的持久化（`DE-6a` 定案，2026-09-21）

> §5.2.2 原写「续跑入口属 `DE-3c`，本契约不替它定」；`DE-3c` 只落 L0、体从不中途返回
> ⇒ 那处留白当时不产生对象。**它随 L1（真让出）一起才有对象**，故在此定掉。⛔ 上文原句未改。

| 项 | 定案 |
|---|---|
| 续跑怎么做 | 运行时用**同一个** `(wrapper, code, env)` 再调一次 wrapper ⇒ **不需要第二个入口函数** |
| 体怎么知道是续跑 | 由**体自己**从帧里读续跑点 ⇒ **帧的布局是发射层的私事，不是 ABI** |
| 等待对象怎么登记 | 走**新增符号** `bk_task_await`（形状见 §5.2 那行，语义见 `DE-1` 件的 §3.2.1）—— 它在返回「会让出」之前把「当前任务等待哪个句柄」登记进**当前任务盒子**（运行时经线程局部知道当前任务） |
| `env` 的角色 | ⭐ **从「实参缓冲」升格为「体的持久帧」**：派发点按体所需尺寸分配，体**只在真跑完时**释放；⛔ **让出时不许释放** |
| `out` 的角色 | 每次进入体都是**新的一块**；⛔ 让出时不得写 |
| 续跑跑在哪条线程 | **原语层**的事；契约上只声明「**可能不是原来那条线程**」⇒ 体不得依赖线程局部 |
| 两条连带（实现时须兑现） | ① 运行时那道「体**已跑过**就返回」的闸必须让续跑通过；② 任务在**让出态**被取消 ⇒ 体不会再被进入 ⇒ **帧由运行时释放**（否则漏） |

⭐ **分岔落在符号上、不落在运行时的判断上**：`bk_task_await` 只许在「异步体 · 语句根 · `form = awaits`」
处发射，其余（含同步体的 `wait`）一律沿用 `bk_task_join` —— 因为「这次会不会让出」是**编译期**属性。

⚠️ 判据在 `Tests/PiniTests/ConcurrencyRuntimeABITests.swift`（三条：`yield` 的关系式 · `spawn` 不阻塞调用方且体在**另一条线程** · **让出态保持未决**）。
⭐ **本族 10 个到齐 ✓** 说的是**已实现**的那 10 个；`bk_task_await` 是**第 11 个**（`DE-6b` 已落它）。
但这**仍不等于 `DE-3b` 完成**：发射层接线属 `DE-3c`。

#### 5.2.4 让出落地后的三处**实现事实**（`DE-6b` 立 · `DE-6c` 补形态，2026-09-21）

> 本节记的是**实现选定了哪一条路**，不是新契约 —— 契约（形状）在 §5.2.2 / §5.2.3 已定。
> ⛔ 记它们的理由：这三件都**改不了**（一经发射即进 ABI 或进帧布局），日后要改须先知道现状。

| 项 | `DE-6b` 的落地 |
|---|---|
| **体怎么把「我让出了」告诉 wrapper** | ⭐ **走帧，不走返回值** —— 体的返回类型是 `Result` 聚合、**没有空位**。发射层把续跑点写进**帧头那 8 字节**，而入口每次进入都先读它、再**清零** ⇒ wrapper 只看「跑完之后它是不是 0」即得两态。⭐ 由此 `@<mangled>` 的**签名零变化**：函数值 adapter 与 `=> ()` 的直呼路径都因而不受影响（`DE-6b` 的用户裁定选的就是这条） |
| **帧的内存归谁** | 运行时 —— 由它经 `bk_task_frame` 分配、由它在**真跑完**或**让出态被取消**时交还。⛔ 由此**取消了一处旧分工**：`env` 原先由体 wrapper 在跑完后 `free`，那条已删（两处都释放就是 double free）。⚠️ 只释放**登记过的**帧：调用方直接给的 `env`（进程内单测就是这么做的）不归运行时管，无条件释放会当场崩 |
| **局部变量怎么跨让出** | ⭐ **异步体的局部槽一律落帧**（不是只落「跨让出的那些」）：让出等于**从栈返回**，而做活跃性分析去找「哪些槽跨让出」会把简单的事做复杂。⚠️ 帧槽由 `bk_task_slot` **按需取自运行时**、**可重放**（同一体第 n 次进入的第 k 次调用必得同一地址），取槽代码**全部排在入口块**、顺序 = 声明顺序 —— 那是续跑能拿回上次那些槽的**唯一**依据。⚠️ **限外两条如实登记**：帧槽对齐按 **8 字节**（超 8 对齐的类型无通道）；循环体内声明的局部槽**随迭代复用同一帧槽**（与今日 `alloca` 在循环内的实际行为同向，差别只在「取局部变量地址且地址逃逸」那种形态可观测） |

⭐ **让出点已覆盖四条语句根**（`DE-6c`，2026-09-21）：`await f()` 独占一行（`S1`，结果按语言语义
**丢弃**）· `var x = await f(...)`（`S2`）· `try await f() else …`（`S4`）· `match await f():`（`S3`）。
后两条与前两条**共用同一条让出序列**，只差一个**产出档位**（帧槽 / 丢弃）；⭐ 而 `S3` 与 `S4` 的
**产出**（判别式 / `try` 的操作数）一律落**帧槽**、由紧随其后的**分派**从槽读回 —— 与 `S2` 存变量槽
**同一个理由**：续跑的跳转只跳得回入口能支配的块，而让出点那块里的 SSA 值不支配它。
⭐ 这四条正是降载层的位置报文**自己列出**的那四个位置 ⇒ 本节记的是「发射层追平了那条承诺」。

⛔ **仍拒：嵌在 `if` / `match` 的 case 体 / 循环体里的让出点**。理由是续跑的跳转只跳得回顶层那一块 ——
嵌套的让出点其所在块依赖外层块先算出的值，而那些值**不支配**续跑块。⛔ 拒绝而不静默阻塞：
`await` 的承诺是让出，静默按占用处理就是**把承诺打折而不出声**。

⚠️ **一处两层口径差（如实登记，未处置）**：降载层允许 `await` 出现在**任意嵌套深度**的「一条语句的
根部」（它判的是**句法形态**），发射层按**嵌套深度**拒 ⇒ 嵌套块里的 `var x = await f(...)` 今天被
**降载层放行、发射层拒绝**。两层的判定依据不同（形态 vs 位置），处置须另行点名。
⚠️ 另有**一条**与本批**无关但同区**的边界：`.result` 异步体若被**绕过派发**进入（函数值 adapter），
入口会在帧为空时**响亮拒绝**；`=> ()` 的直呼**不在**帧式之内、其既有行为不受影响（那是已登记的
另一笔缺陷）。


#### 5.2.5 推进一次的**跨腿契约**（`Q-1` 定案，2026-09-23）

> 本节给「推进一次」这个动作一个**跨腿的名字**。⛔ 它**不新定行为** —— 发射腿那一侧的形状在
> §5.2.2 / §5.2.3 已定，解释器腿那一侧按同一语义运行；本节把两腿共有的语义写成**一处**，
> 免得它只住在工作件里。⚠️ 契约定的是**语义**，⛔ **不固定两腿的入口形状**（照 §0.2 的表述纪律）。

| 项 | 契约 |
|---|---|
| **单位** | **整个异步体** —— 推进到下一个**未决**的 `await` 点，或跑到体的末尾 |
| **输入** | **一个任务**。⛔ **不带值** —— 「等到的值」怎么送进续体是**各腿的实现私事** |
| **输出** | **该任务的结算**：跑到末尾 ⇒ 任务**决出**（带结果）；停在未决的 `await` 点 ⇒ 任务**留在等待态**。⚠️ 「输出」写成**结算**而非返回值，是**如实描述现况**：两腿今天都**就地结算**，⛔ 不是把结果**返回**给调用方 |
| **谁调它** | **驱动器的挑选循环** —— ⚠️ 今天**不存在**：策略层尚无对象可挑（该缺口登记在语言规范的台账，见 `G75`）|
| ⛔ **它不做什么** | 不**挑选**（归策略层）· 不**入就绪集合**（归策略层）· **不分配也不释放帧**（帧归运行时，见 §5.2.3）· 不判**公平性** |
| **两腿的对应物**（实现面，⛔ 不是语义） | 发射腿 = §5.2.2 的 wrapper 返回协议 + §5.2.3 的续跑入口；解释器腿 = 其驱动器 |
| ⚠️ **一处如实登记的不对称**（⛔ 本节**不消除**它） | 发射腿是**单入口**（同一入口兼任首跑与续跑，见 §5.2.3）；解释器腿是**两条路径**（首跑与续跑的入口形态不同，且**输出形态亦不同**：一条返回两态、一条就地结算）。⇒ 「同一契约」指**上表的语义**，⛔ 不指两腿入口形状相同；收敛该不对称归主题词「调度驱动面」的后续段 |

⭐ **与 §5.2.2 那条跨腿对齐同族**：那里记的是「让出能否发生」两腿由**同一条规则**决定，
本节记的是「推进一次」两腿共有的**语义** —— 两处都把跨腿一致性**写在一处**，而不是各腿各写一份
（后者的失效方式是两个副本各自漂移，而外观上谁也看不出）。

#### 5.2.6 调度驱动面的两个符号（`Q-4` 定案，2026-09-23）

> 「结果决出 ⇒ 交给策略层的队列 ⇒ 由它挑下一个」这条改道在两个后端上落地之后，本族多了两个符号。
> ⛔ 本节记的是**形状与调用约定** —— 形如落笔即成承诺，而调用约定**必须**有一处成文
> （裁定 57 的明文要求）。

| 符号 | 签名 | 语义 |
|---|---|---|
| `bk_task_bind_sched` | `(handle, binding) -> i32` | 把一个**策略绑定**交给运行时。`binding` 指向下面那条记录；⭐ **传空即解绑**。`0` = 已接受（或已解绑） |
| `bk_task_state` | `(handle) -> i32` | 观察态：`0` 未起 · `1` 可跑 · `2` 等待中 · `3` 已决 |

**绑定记录的布局（即 ABI）**：三个机器字，按序为
**策略实例** · **「收下」的入口** · **「选择下一个任务」的入口**。
两个入口的调用约定是「**第一实参是策略实例**」：

```
accept(策略实例, 任务句柄) -> ()          // 入队
pick(策略实例)             -> 任务句柄     // 挑选；空指针 = 队列空
```

⛔ 运行时**不解释**第一个字是什么（它是默认实例的盒指针），只把它原样回传给那两个入口。

**为什么由发射层交出「怎么调」**：策略是 Pini 值、它的方法体是编译产物，而运行时那一层是纯
C ABI ⇒ **它自己不可能调到策略**。由发射层在派发点构造这三个字，是这条改道在发射腿上唯一
可行的交接形态（裁定 57 取甲）。

**两处如实登记的边界**（⛔ 都不在本节消除）：

- **句柄承载两腿不同**：发射腿上策略接口的句柄本就是 `*U8`，而运行时的任务句柄本来就是一个
  不透明指针 ⇒ 两处**直接同形、零映射表**；解释器腿的任务是宿主对象、塞不进 `*U8` ⇒ 那条腿
  用**整数句柄 + 一张映射表**。⚠️ 这与 §5.2.5 的明文一致：契约定的是**语义**，
  ⛔ 不固定两腿的入口形状。
- **策略缺方法时两腿的拒绝形态不同**：解释器腿在**运行期**抛「策略没有这个方法」；
  发射腿的对应形态是**链接期**的未定义符号（发射层照发对那两个方法符号的引用）——
  收敛它须另行点名。

⭐ **一条实施事实（发射腿专属）**：派发点取的是**默认实例的盒指针**，⛔ 不是它的一份值拷贝。
理由是策略层的方法会**写它自己的字段**（入队 / 出队），而调用方栈上那份副本随帧消失 ——
把副本的地址交出去，挑选循环拿到的就是**悬垂指针**，且症状是随机错乱而非立即崩溃。
⚠️ 这与「取用点拿的是实参的副本」**不冲突**：那是取用的语义，这是驱动面的语义，
两者不可互推。

⚠️ **`bk_task_state` 的三处空洞** —— 四态表比现实粗，如实登记，⛔ 不自行扩表：
`3` 把「已取消」并进「已决」（与 `join` 的归一一致）；`1` 同时覆盖「在队列里等挑」与
「正在被推进」（四态表没有后者那一格）；`2` 只覆盖「体交出控制流、等某个未来」。
