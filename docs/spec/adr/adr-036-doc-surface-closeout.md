# ADR-036: 文档面收口——路线图退役与项目规范并入
（Document Surface Closeout: Roadmap Retirement and Project Spec Absorption）

## Status

**Accepted（2026-09-16）** —— D1–D3 裁决，随本次文档治理落地。

## Context

### 1. 为什么是现在

设计者（2026-09-16）对两份语言级文档提出处置要求：

> 「pini-roadmap-next.md 作为路线图已经过时，可能要移除（探讨一下过时了多少）……工程级的权威里，
> 下游还有 pini-project-spec.md 也已过时，pini-project-spec 承担的责任应当移交 pini-spec。」

### 3. 裁决

| # | 议题 | 裁决 |
|---|---|---|
| **D1** | 路线图 | **抽取仍有效内容后移除**（「我们不缺少计划」——排期由工单与计划件承担，不设「路线图」载体） |
| **D2** | 项目规范 | **分拣后部分移交**：工具链实际读取的内容移交规范；纯指引内容不随迁 |
| **D3** | 移交落点 | 规范新增一节「项目布局与清单 schema」（工程面，与测试 / 注释规范同层） |

## Decision

### D1 → 路线图退役

- **抽取**：§2.5 的「执行指引」3 条，以及该节记录的 T14 FFI 现状（该节已记「解释器优先部分落地」，
  而规范当时仍写「尚未实现」——规范侧已过时），并入规范的「运行时 shim 与长期愿景」一节。
- **移除**：整份移入 `../issue/archive/`，加 ARCHIVED 标记（含退役理由、去向与「不得作为当前行为依据」声明）。
- **引用面**：规范 §3 的「计划版本」读法、§5 的下游声明、缺口台账 G39–G42 的关联列、迁移说明、
  两处 README 清单——全部改指或改述。**ADR-024 的引用按「路径跟随、位置不回改」处理**：文件路径随
  归档更新（否则引用失效且文档链接门禁会拦下），其记载的章节号 / 条款位置保持原样。
- **归档件内部引用**：两份归档件自身的相对引用随移动订正（同目录 → `../../`）——只改路径前缀，
  不动内容语义。

### D2 → 项目规范分拣

| 内容 | 去向 |
|---|---|
| 必需 / 可扩展 / 预留目录三分类 | 规范新节（含 `.pini/baseline` 定义） |
| `.gitignore` 基线 | 规范新节 |
| 清单 schema（字段表 / 稳定性分级 / 版本约束语法 / `spec` 字段语义） | 规范新节 |
| 脚手架校验规则 | 规范新节 |
| 验收 DoD | 规范新节 |
| 设计原则的最佳实践对照（Cargo / SwiftPM 逐条） | **不随迁**——属指引；规范只保留「宿主布局 vs 语言布局」的层级区分 |
| 「与既有资产的映射」表 | **不随迁**——其「关联路线图」列引用已退役的阶段编号体系 |
| 脚手架的文件内容样例 | **不随迁**——`examples/` 有真实项目可参照 |

### D3 → 落点与纪律

- 新节置为规范第 8 节（注释规范之后、形式文法附录之前）。
- 该节**不含阶段编号**：原载体的「关联路线图」列所用的编号体系随 D1 退役；预留项的激活时机由
  对应能力的设计载体决定，规范不臆造编号。
- 依赖两通道的**语义判据**仍单点在规范的访问控制 / 模块系统节，第 8 节只给**书写形态**并回指，
  避免双写。

## 后果

- **文档面收敛为**：规范（工程与治理 + 项目布局与清单 schema）· 语言参考（语言面）·
  工程标准细则（测试 / 注释，外部文档）· 诊断码派生视图 · ADR 与工单。
  不再有独立的「路线图」与「项目规范」载体。
- **规范变厚**（约 +220 行）：这是 D3 的代价——项目布局与清单 schema 属工程面，与治理条款分节共处。
- **跨仓影响（登记为待办）**：自举仓 `examples/selfhost` 有两处引用项目规范（清单注释与入口文件注释）。
  该仓是嵌套独立仓，须在其内单独提交——**不在本仓改动**，落地状态记于集成计划载体。
- **阶段编号混用风险显式化**：路线图的阶段编号与 LR-4 各阶段的编号是**两套不同体系**，
  此前规范曾以「以路线图的 P 阶段为准」表述排期，现已解除依赖；归档件内保留该提醒。
