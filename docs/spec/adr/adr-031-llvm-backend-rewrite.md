# ADR-031：LLVM 后端重写与假测试先行清除

- 状态：Accepted（2026-09-07）
- 关联：集合后端运行时（`bk_*` C ABI 由来）、`docs/issue-gated-stale-fixtures-2026-09-05.md`
- 影响面：`Sources/PiniCore/CodeGen`（5677 行）、`Tests/PiniTests`（测试资产）

> 本 ADR 记**约束与判据**，不记操作细节。论证部分全部为实测值，可复现；
> 执行细节（目录名、类名、分格顺序等）由执行者在各阶段自行填充并回填。

---

## 1. 约束（本 ADR 改变了什么）

1. **LLVM 后端由「演进」改为「重写」**：新增实现须独立于既有 `CodeGen`，
   通过 CLI 后端开关切换；既有 `CodeGen` 在切换完成前保持可构建，但**不再接受功能新增**。
2. **Emitter 不得做类型决策**：类型一律来自上游显式类型字段。
   违反即等于重建影子类型系统。
3. **能力检查单点化**：不允许在发射路径中途散落 `unsupported` 抛点。
4. **`bk_*` C ABI 冻结**：35 个导出符号与语义不变；`PiniRuntime` 不在重写范围内。
5. **测试不得静默跳过**：门控缺失时须显式失败并标注原因，禁止 `XCTSkip` 静默。
6. **锁死实现细节的断言不被承认为回归保护**：断言 IR 文本形态的测试，
   在后端行为变更时不构成回滚理由。

---

## 2. 必要性（不做会怎样）

以下均为 2026-09-07 @ `2433789` 实测值，可复现。

| 事实 | 实测值 |
|---|---|
| CodeGen 体量 | 5677 行 / 9 文件，全部 `extension IRGenerator` |
| `unsupported` 抛点 | **100 处**（平均每 57 行一个） |
| 影子类型表 | 6 张 `*ByVar` / 90 处引用 |
| 捕获分析重复实现 | 12 个同名函数（CodeGen 6 + TypeInference 6） |
| 端到端测试的 skip 点 | `IRExecutionTests` 82 test / **85 skip** |
| 门关态实测跳过率 | IRExecution 73/82、IRPrintGolden 2/2、RuntimeBackend 37/51 |
| 锁死 IR 文本的断言 | `IRGeneratorTests` 内 **149 处** `ir.contains` |

**必要性论证**：

- **N-1 后端不是"一个大模块"，而是"一百个未完成的分支"**。100 处抛点意味着
  每新增一个语言特性，都要在字符串拼接层重新做一次类型决策。这是工程量膨胀的
  直接来源，不是编码风格问题，无法靠局部重构消除。
- **N-2 测试资产结构倒挂**：锁死实现的（149 处文本断言）恒跑，验证行为的
  （82 个端到端）恒跳过。结果是「重构被枷锁捆住，同时脚下没有网」——
  任一次重构的回归信号都不可信。
- **N-3 门后腐烂已被实证**：`issue-gated-stale-fixtures` 记录门一开即炸 4 处，
  均为长期 skip 期间夹具/语义演进未同步。skip 的测试不是资产，是负债。
- **N-4 增量路径已被否决**：先做「前端归位 + 类型注入」可消除 N-1 的部分症状，
  但无法消除 100 处抛点与 god class 结构，且会在 N-2 的枷锁下进行，
  回归成本不可控。

## 3. 充分性（做完这些为什么够）

重写成功的判据不是"代码更漂亮"，而是以下四条同时成立：

- **S-1 行为等价可判定**：存在一条不依赖 LLVM 文本形态的验收路径
  —— 同一源码在解释器与 LLVM 后端的输出逐字节一致。
  `examples/` 下 1010 个 `.pini` 提供语料，无需新写夹具。
- **S-2 决策上移可判定**：新 Emitter 中不存在类型推断、捕获分析、单态化任一项；
  能力检查出现在单一位置。以 grep 可机械核验。
- **S-3 覆盖面可增量**：功能面按能力清单分格，每格独立验收；
  任一分格失败不影响已完成分格——避免大爆炸式切换。
- **S-4 旧实现可退役**：新旧并存由 CLI 开关控制，差分全绿后才切换默认，
  切换前任一时刻都可回退。

**充分性论证**：N-1～N-4 的每一条都被 S-1～S-4 中的某条直接消解
（100 处抛点 → S-2；结构倒挂 → S-1；门后腐烂 → 约束 5；不可控回归 → S-3/S-4）。
四条判据全部可机械核验，不依赖主观评价。

## 4. 核心步骤（执行时自行填充细节）

> ADR 不规定目录名、类名、分格顺序。执行者按下列骨架填充细节，并回填到本 ADR 的
> 落地记录章节。

1. **清除假测试**（已完成，见 §6）：删除恒跳过的端到端测试、恒跑但锁死 IR 文本的
   断言测试，及其孤儿夹具。保留恒跑且验证错误路径的 `IRGenError` 断言。
2. **立契约**：实测后端在 `examples/` 语料上的真实通过率；把 100 处抛点分类为
   核心必支持 / 可延后 / 永久不支持；冻结 `bk_*` ABI；写能力清单。
3. **建差分网**：先建立「解释器 vs LLVM」逐字节差分通道，并使其在旧后端上全绿
   —— 网必须先于拆除而存在。
4. **垂直切片**：新实现独立于旧 `CodeGen`，先打通最小可执行子集并出差分绿。
5. **分格扩张**：按能力清单逐格推进，每格一次提交 + 一次差分验证。
6. **切换与退役**：差分全绿 → 切默认 → 观察 → 删除旧实现。

**止损判据**（任一成立，立即停止增量、转入全量重写并回到步骤 4）：

| # | 判据 | 阈值 |
|---|---|---|
| S-1 | 影子类型表不减反增 | ≥ 7 张 |
| S-2 | 回归规模与定位成本 | > 5 个测试 且 > 1 小时 |
| S-3 | 单次收敛的扩散面 | > 4 个 emitter 未收敛 |
| S-4 | 单项核心能力的实现代价 | 需改动 > 3 个 emitter |

## 5. 执行者需自行填充的细节（非穷举）

- 新实现的模块名与目录位置；CLI 后端开关的名称与默认值。
- HIR/中间层的具体形态（是否引入、类型表示、控制流表示）。
- 能力清单的分格与顺序；每格的验收程序清单。
- 差分通道的执行方式（JIT / AOT）与 `lli` 可用性的保障手段
  （约束 5 要求：不可用即失败，不得 skip）。
- 旧实现退役的具体时点与删除范围。
