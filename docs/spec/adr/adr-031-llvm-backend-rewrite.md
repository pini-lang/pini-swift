# ADR-031：LLVM 后端重写（含门控测试的环境判据）

- 状态：Accepted（2026-09-07；**同日就地修订**：初版包含基于错误测量的「假测试先行清除」，
  该部分已撤回并从历史中删除，详见 §6 与 §2.3）
- 关联：集合后端运行时（`bk_*` C ABI 由来）、`docs/issue-gated-stale-fixtures-2026-09-05.md`
- 影响面：`Sources/PiniCore/CodeGen`（5677 行）、`Tests/PiniTests`（测试资产）

> 本 ADR 记**约束与判据**，不记操作细节。论证部分全部为实测值，可复现；
> 执行细节（目录名、类名、分格顺序等）由执行者在各阶段自行填充并回填。

---

## 1. 约束（本 ADR 改变了什么）

### 后端重写

1. **LLVM 后端由「演进」改为「重写」**：新增实现须独立于既有 `CodeGen`，
   **直接替换，无任何 CLI 兼容开关**（LR-5，2026-09-07 用户裁决：已有解释器后端、
   项目未进 1.0.0 不考虑兼容；回退手段 = 提交边界 git revert）；既有 `CodeGen`
   在新管线差分绿前保持服务，但**不再接受功能新增**。
2. **Emitter 不得做类型决策**：类型一律来自上游显式类型字段。
   违反即等于重建影子类型系统。
3. **能力检查单点化**：不允许在发射路径中途散落 `unsupported` 抛点。
4. **`bk_*` C ABI 冻结**：35 个导出符号与语义不变；`PiniRuntime` 不在重写范围内。

### 测试资产的处置判据

5. **测试不得静默跳过**：门控缺失时须显式失败并标注原因，禁止 `XCTSkip` 静默。
6. **门控结论的环境判据**：凡以「某个外部命令是否可用」为前提的测试结论
   （跳过率、失败数、通过基线），必须在**完整登录 shell 环境**下实测。
   判据：执行 `source ~/.zshrc` 后 `command -v <tool>` 有输出，才算该工具存在。
   自动化/代理环境的默认 PATH 不得作为依据。
7. **「恒跳过」不构成删除理由**：删除测试前，须证明它在完整环境下仍然跳过；
   举证责任在删除方。工作树（`git worktree`）与自定义 `--scratch-path` 下的测量
   一律不作判据——运行时 dylib 由仓内 `.build/debug` 定位，两者都会使其失效。
8. **锁死实现细节的断言不得先行删除**：断言 IR 文本形态的测试在旧实现退役前
   是唯一的回归信号；只允许在与「旧实现删除」同批提交中移除。

## 2. 必要性（不做会怎样）

### 2.1 结构事实（2026-09-07 @ `2433789` 实测，可复现）

| 事实 | 实测值 |
|---|---|
| CodeGen 体量 | 5677 行 / 9 文件，全部 `extension IRGenerator` |
| `unsupported` 抛点 | **100 处**（平均每 57 行一个） |
| 影子类型表 | 6 张 `*ByVar` / 90 处引用 |
| 捕获分析重复实现 | 12 个同名函数（CodeGen 6 + TypeInference 6） |
| 锁死 IR 文本的断言 | `IRGeneratorTests` 内 **149 处** `ir.contains` |
| 运行时 ABI | 35 个 `bk_*` C 符号 / 699 行（冻结，不可改） |

### 2.2 论证

- **N-1 后端不是"一个大模块"，而是"一百个未完成的分支"**。100 处抛点意味着
  每新增一个语言特性，都要在字符串拼接层重新做一次类型决策。这是工程量膨胀的
  直接来源，不是编码风格问题，无法靠局部重构消除。
- **N-2 类型决策散落在发射层**。6 张影子类型表与 12 个重复的捕获分析函数，
  使「类型的唯一真相」不存在：前端改一处，后端有 6 处可能不同步。
- **N-3 增量路径代价不可控**。既然后端是 9 个 `extension IRGenerator` 共享
  40+ 可变状态的 god class，任何增量改动都要在该状态下推理；
  100 处抛点中的每一处都可能是一个独立的类型决策点。

### 2.3 已撤回的论证（初版错误，记录以备复核）

初版曾以「测试资产结构倒挂」「门后腐烂已实证」为由，判定 225 个 LLVM 测试为
「假测试」并删除（commit `49aae31`）。**该判定错误，已回退**。

| 对象 | 初版记载（残缺环境） | 完整环境实测 |
|---|---|---|
| 全量 | 1214 / 114 skip | **1214 / 0 skip / 0 failure** |
| `IRExecutionTests` | 73/82 skip | 82/82 通过 |
| `IRPrintGoldenTests` | 2/2 skip（工作树下 8 处失败） | 2/2 通过 |
| `RuntimeBackendTests` | 37/51 skip（工作树下 38/51） | 51/51 通过 |
| `OptionalTests` | 2/20 skip | 20/20 通过 |

错误由两层环境假象共同造成，均已被约束 6、7 覆盖：

- **假象一（PATH 残缺）**：测量环境 PATH 不含 `/opt/homebrew/bin`，`lli` 因此
  "不存在"；完整环境下存在（LLVM 22.1.8）。
- **假象二（dylib 路径失效）**：`locateRuntimeDylib()` 只找仓内 `.build/debug`，
  在 `git worktree` 下必然失败，额外伪造 38 个跳过与 8 处 golden 失败。

**结论修正**：本项目的 LLVM 行为级保护网**本来就存在**（`IRExecutionTests` 82 +
`RuntimeBackendTests` 51 = 133 个端到端/契约测试，完整环境下全绿）。
重写的必要性只由 N-1～N-3 支撑，与测试资产无关；「先建网再拆旧」的前置动作
因此**不再是新建，而是加固**（见 §4 步骤 1）。

## 3. 充分性（做完这些为什么够）

重写成功的判据不是"代码更漂亮"，而是以下四条同时成立：

- **S-1 行为等价可判定**：同一源码在解释器与 LLVM 后端的输出逐字节一致。
  既有 133 个端到端/契约测试已提供语料与通道，`examples/` 下 1010 个 `.pini`
  可作增量语料，无需新建差分设施。
- **S-2 决策上移可判定**：新 Emitter 中不存在类型推断、捕获分析、单态化任一项；
  能力检查出现在单一位置。以 grep 可机械核验。
- **S-3 覆盖面可增量**：功能面按能力清单分格，每格独立验收；
  任一分格失败不影响已完成分格——避免大爆炸式切换。
- **S-4 旧实现可退役**：新旧并存仅以提交边界隔离（无运行时开关），差分全绿后
  一次性翻转（删旧接新同批），翻转前任一时刻可经 git revert 回退。

N-1～N-3 分别被 S-2（抛点单点化）、S-2（类型决策上移）、S-3/S-4（增量与可回退）
直接消解；四条判据全部可机械核验，不依赖主观评价。

## 4. 核心步骤（执行时自行填充细节）

> ADR 不规定目录名、类名、分格顺序。执行者按下列骨架填充细节，并回填到 §6。

1. **加固既有网**（不是新建）：把门控从「静默 skip」改为「显式失败」（约束 5）；
   把环境判据（约束 6）写入测试文档。判据：在不满足环境的机器上跑，
   必须**失败并报明原因**，不得绿。
2. **能力清单**：实测后端在 `examples/` 语料上的真实通过率；把 100 处抛点分类为
   核心必支持 / 可延后 / 永久不支持；冻结 `bk_*` ABI。
3. **决策门**：按能力清单结果判定路线——
   「核心必支持」占比低 → 走增量（前端归位 + 类型注入，消除影子表与重复捕获分析）；
   占比高 → 走重写（步骤 4 起）。**本步骤是分叉点，须记录判定依据。**
4. **垂直切片**（仅重写路线）：新实现独立于旧 `CodeGen`，
   先打通最小可执行子集并出差分绿。
5. **分格扩张**：按能力清单逐格推进，每格一次提交 + 一次差分验证。
6. **切换与退役**：差分全绿 → 一次性翻转（CLI 接新管线 + 删除旧实现 +
   删除 IR 文本断言同批）→ 观察；`IRGeneratorTests` 的 149 处文本断言在
   **同批**提交中删除（约束 8）。

**止损判据**（任一成立，立即停止当前路线并回到步骤 3 重新判定）：

| # | 判据 | 阈值 |
|---|---|---|
| S-1 | 影子类型表不减反增 | ≥ 7 张 |
| S-2 | 回归规模与定位成本 | > 5 个测试 且 > 1 小时 |
| S-3 | 单次收敛的扩散面 | > 4 个 emitter 未收敛 |
| S-4 | 单项核心能力的实现代价 | 需改动 > 3 个 emitter |

## 5. 执行者需自行填充的细节（非穷举）

- 新实现的模块名与目录位置：已定案 `HIR/` 顶层（LR-2/LR-3 类型化树）+
  `CodeGen/` 原址重建；CLI 后端开关不再需要（LR-5 无兼容开关）。
- HIR/中间层的具体形态（是否引入、类型表示、控制流表示）。
- 能力清单的分格与顺序；每格的验收程序清单。
- 差分通道的执行方式（JIT / AOT）与 `lli` 可用性的保障手段
  （约束 5：不可用即失败，不得 skip）。
- 旧实现退役的具体时点与删除范围。
