# ADR-029: 括号内记法收口——值的注入用 `=`（含 G54 破坏性修订）

## Status

Accepted（2026-09-01 用户需求提出；2026-09-02 D-1~D-8 裁决并落地）

> **补登记说明**：与 ADR-028 同源于 2026-09-02 的治理债清偿——当时跳过了 spec §1.3 第 2 步（破坏性升级评审）与第 3 步（ADR 记录决策理由）。理由见路线图 §8.3。

**修订对象**：spec §2.2（集合与表达式位置）、规则 **3.15**（枚举关联参数）；**触及 ADR 具名关联值决议 / G54（2026-08-29 已钉定且已实现）的构造位**。

---

## Context

**用户需求（2026-09-01）**：「括号内文法有变动：`func(a = 1, b = 2)`。实参用等号，顺便要展开想想词典如何写。」

**取证（`docs/spec/issue/archive/proposal-paren-equals-binding-2026-09-01.md` §2）**：

1. **这不是纯新增**：`f(a: 1)` 带标签调用**当前可用**（实测输出 3）；`f(a = 1)` 当前是 **E2-001 解析错误**。→ 是**记法切换**。
2. **`=` 在 Pini 里已是「值绑定」记号**：spec §A 产生式 `IDENT '=' expression; (* 默认参数 *)`。
3. **规则 3.15 明文禁止枚举用例括号内出现 `IDENT '='`** → 本变更必须同步修订该约束，否则新记法在构造位非法。
4. **空字典至今无字面量**：`[:]` 被全切片 `a[:]` 占用（`var e = [:]` 实测 E2-006）。
5. **批 1.5 创造的收口窗口**：括号内布局抑制后，括号内的 `:` 已不可能是块开启 → `:` 在括号内只余「映射 / 标签」二义。

**`:` 改前承载四重语义**：①类型标注 `n: I32`；②块开启（H-4 强制）；③字典映射 `["a": 30]`；④标签（枚举具名构造、带标签调用、标签元组、match 具名绑定）。

---

## Decision

**总原则（已写入 spec §2.2）**：

> **`=` = 值的注入方向**（实参标签 / 字典条目 / 元组标签 / 默认参数）
> **`：= 标注与取出方向`**（类型标注 / 块开启 / match 具名绑定）

**逐条裁决（D-1~D-8）**：

| # | 裁决 | 理由 |
|---|---|---|
| D-1 | `f(a: 1)` **报错废弃**并给迁移提示；不留双记法 | Pini 既有做法是破坏性切换 + 一次性迁移（G50 / H-4 / 批 2）；并存会留下两种实参记法 |
| D-2 | 字典字面量统一 `=`：`["Alice" = 30]` | 括号内关联记号统一；与默认参数 EBNF 的 `=` 同向 |
| D-3 | 枚举具名构造**同步**：`E(text = "x", loc = 1,)` | 与 `f(a = 1)` 同属实参绑定。**属 G54 破坏性修订**（见影响评估） |
| D-4 | 标签元组**同步**：`(a = 1,)` | 构造侧（值 → 名字） |
| D-5 | match 具名绑定**保留 `:`**：`case A(x: v):` | 方向为解构（字段 → 变量），与「取出用 `:`」一致 |
| D-6 | 空字典**不新增记号**，走类型构造 `字典<键, 值>()` | `[:]` 已被全切片占用 |
| D-7 | 形参侧（`n: I32`、`n: I32 = 1`）**不变** | 声明侧；默认参数的 `=` 恰与「`=`=值绑定」自洽 |
| D-8 | 并入批 3（与 F5 同属「括号内文法」） | 一次钉死，避免钉定面返工 |

**实现落点（4 处改 + 1 处不动）**：调用实参、泛型构造实参、`parseTupleOrParen` 标签元素、`parseCollectionLiteral` 字典条目改用 `=`；**match 具名绑定保持 `:`**。

**迁移方法（关键决策）**：不用盲改正则——`case A(x: v):`（模式位）与 `func<T>(x: T)`（声明位）在文本上与构造/调用同形。采用**检查器驱动**：解析器报错携带精确 `file:line:col`，按位置逐点改写并迭代至零报错；每个改写点都由编译器判定过上下文。

## Consequences

**正**
- `:` 从四重语义收敛为两类（标注 + 取出），`=` 专司注入——记号面可解释、可教学。
- 与默认参数 EBNF 的既有 `=` 语义同向，不是新造记号。
- 迁移由编译器定位，模式位/声明位零误伤（实测：无一处 `case`/形参被改）。

**负 / 代价**
- **破坏性**：旧记法全部报错；触及 **G54 已钉定面**（构造位）。
- **迁移面**：529 + 24 + 14 + 2 处（含自举源码与其测试内字符串源码 2 处——检查器看不见，须手工）。
- **两次迁移翻车（记录为教训）**：①过滤器漏掉字典第二条目文案「字典元素必须是 键 = 值」，循环提前退出留下半改文件 `[1= "x", 2: "y"]`；②泛型声明 `func<T>(x: T)` 与构造 `Name<T>(x: v)` **文本同形**，盲改 sed 毁掉形参声明（已回退重做，改为跳过含 `func`/`->` 的行）。

**验证（实测）**：宿主 1116/0（+11 `ParenEqualsTests`）；gate 五关 GREEN（L0 508、parse 222+94、check 15 文件、自举 70/0、audit GREEN）；自举 parser 同步后 parse 差分重新 MATCH。

**提交**：宿主 `ad10773` / `cbeec25` / `831b3db`；自举 `d96c996`；基线第十四次重标定。

## 影响评估（§1.3 第 2 步，破坏性 —— 升级评审）

| 受影响构造 | 稳定性 | 变更性质 |
|---|---|---|
| 实参标签记法 | Provisional | `:` → `=`（**破坏性**：旧记法报错） |
| 字典字面量条目 | Provisional | `:` → `=`（**破坏性**） |
| 标签元组字面量 | Provisional | `:` → `=`（**破坏性**） |
| 枚举具名**构造**实参 | **G54 已钉定（2026-08-29）** | `:` → `=`（**破坏性修订已钉定面**） |
| match 具名绑定 | **G54 已钉定** | **不变**（D-5 明确保留 `:`） |
| 形参声明 / 类型标注 / 块开启 | Pinned / Provisional | **不变** |
| 切片 `a[i:j]` | Provisional | **不变**（`;` 是分隔符非关联） |

**评审结论**：破坏性集中在 Provisional 面，但**有一项触及已钉定面（G54 的构造位）**——按路线图 §8.4 规则属「计划修正案」，已登记为 **AM-2** 并经用户批准（2026-09-02）。G54 的解构位（match 绑定）保持不动，故 G54 的核心能力（具名关联值 + 按名对位 + 具名解构）**完整保留**，仅构造实参的书写记号变更。未触及 §2 Pinned Core。
