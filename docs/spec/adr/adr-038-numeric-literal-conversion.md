# ADR-038: 数值字面量的转换与 `abs` 的定义域

> **状态**：**active**（2026-09-16 用户裁决）｜**类别**：语言级
> **本件范围**：**只登记**。内建表、降载层与夹具的实现改动**另立批次**（本件的落地项见「后果」节）。
> **触发**：`P4-γ` 的子批 `G-2R` 里有三条失败用例，成因不是实现缺失，而是**语言的数值规则没写下来**。

## 1. 提议（要解决什么）

`G-2R` 原本把这三条当「零散小件」修，实测后发现它们问的是同一类问题：**整数与小数之间，语言允许什么**。

- `Tests/PiniTests/StdlibTests/testMathAbs.pini` 要 `abs` 能吃小数；
- `Tests/PiniTests/ParenEqualsTests/testEnumNamedConstructionUsesEquals.pini` 把整数字面量写在小数的位置上（函数声明返回小数却 `return 0`、枚举字段是小数却写 `圆(半径 = 2)`）；
- 两条都要求语言先回答「可以还是不可以」，实现才能跟。

## 2. 现状实测（同一个 `abs` 在仓里有三种说法）

| 面 | 出处 | 说法 |
|---|---|---|
| **内建函数登记表** | `Sources/PiniCore/Common/BuiltinRegistry.swift` 的 `abs` 条目 | 收 **`I32`**、返回 **`I32`**（只认整数） |
| **旧引擎（AST 走查）运行期** | `Sources/PiniCore/Interpreter/Interpreter.swift` 的 `if fv.name == "abs"` | **任意数字都行**（整数与小数各自保型） |
| **新引擎（HIR）降载层** | `Sources/PiniCore/HIR/HIRLowerer.swift` 的 `abs` 分支 | 结果类型**硬写成 `I32`** |
| **测试断言** | `testMathAbs.pini` 断言输出 `5` 与 `2.5` | 要**小数也行** |

⇒ 表与降载层说「只整数」，旧引擎与测试说「小数也行」。**没有任何一处写下了规则**，所以无从判断谁对。

另一面：`testEnumNamedConstructionUsesEquals` 被类型检查拒了三处，理由一律是 `expected F64, got I32`
（「要小数，给的是整数」）—— 即**今天不允许**整数字面量隐式当小数用，但这条**同样没有写在规范里**。

## 3. 影响评估（本批实测的实数）

**D1（`abs` 放宽到小数）的触及面**：

| 项 | 实数 |
|---|---|
| 代码点 | **2 处**：内建登记表的 `abs` 条目、HIR 降载层把结果硬写成 `I32` 的那一行 |
| 全仓把小数喂给 `abs` 的地方 | **1 处**，就是 `testMathAbs.pini` |
| 把整数喂给 `abs` 的地方 | 4 处（`examples/stdlib.pini`、`testBuiltinMathIntegersViaLLI.pini`、`testDiffStdlib.pini`、`testMathAbs.pini`）—— 全部仍合法，不受影响 |
| LLVM 后端 | ⚠️ 有一条用例名就叫 `testBuiltinMathIntegersViaLLI`（**Integers**）⇒ LLVM 侧的 `abs` 现状是**整数面**。本决定生效后，LLVM 侧要么跟上，要么**响亮拒绝**；不得静默产出引用未定义符号的产物（`G-2a` 的 `is_letter` 即此型） |

⇒ **放开的爆炸半径很小**（无任何既有夹具依赖「`abs` 拒绝小数」）。

**D2（整数字面量不隐式转小数）的触及面**：

| 项 | 实数 |
|---|---|
| 与今天的差异 | **没有差异** —— 类型检查**今天就已经拒**。本条是把现状**写成明文规则**，不是改变行为 |
| 真正的行为变更 | 发生在**两引擎之间**，且**已登记**：旧引擎不跑类型检查，所以这类程序今天「能跑」；翻转后一律被拒。这是既有的 `E4` 族（见 `docs/issue-hir-p4-plan-2026-09-16.md` 的 `D-P4-15`：「带类型错误的程序由可运行变被拒」按**用户可见语义变更**登记） |
| 需改的夹具 | `testEnumNamedConstructionUsesEquals.pini` 的 **3 处**（`return 0` ×2、`圆(半径 = 2)`）⇒ 改成 `0.0` / `2.0` |
| 全量语料普查 | **本件未做**（归实现批）——普查的是「有多少既有 `.pini` 源把整数字面量写在小数位」，它决定迁移说明的篇幅 |

## 4. 决定

### D1 —— `abs` 接受整数与小数（**用户裁决：甲**）

`abs` 的定义域放宽到**数值类型**：整数进整数出、小数进小数出，各自保型。
理由：测试的断言原话是「abs 应返回绝对值并**保持数值类型**」，旧引擎的实现就是这个语义；
把小数收敛掉是**用户可见的能力回退**，而放宽只是让登记表追上既有实现。

### D2 —— 整数字面量**不**隐式转为小数（**用户裁决：乙**）

需要小数的位置必须写小数字面量（`0.0` / `2.0`）。
理由：这条规则把类型面钉成**单一可判**的形态；代价是旧引擎时代写下的程序翻转后会被拒，
因此**必须**在迁移说明里明写，不得只靠报错让用户自己猜。

## 5. 后果与破坏性

- **D1 是放宽**，不破坏既有程序（普查见 §3）。
- **D2 是「现状明文化 + 一次跨引擎行为变更的明示」** ⇒ 迁移说明落 `docs/spec/migration-2026-09.md` 新增一节。
- **两面的实现都未落地**（本件只登记）。落地项：
  1. 内建登记表 `abs` 的签名（`Sources/PiniCore/Common/BuiltinRegistry.swift`）；
  2. HIR 降载层 `abs` 分支的结果类型（`Sources/PiniCore/HIR/HIRLowerer.swift`）；
  3. 类型检查对 `abs` 实参的接受面；
  4. LLVM 侧 `abs` 的处置（实现或响亮拒绝）；
  5. 夹具 `testEnumNamedConstructionUsesEquals.pini` 的 3 处改写；
  6. 全量语料的整数→小数普查。
