# ADR-027: 反引号关键字转义（自举探针批次 2）

## Status

Accepted（2026-08-30，D5 双段落地：spec §A.1.1 与实现同期；自举探针 G-P5，用户提案）

## Context

自举 parser 阶段（S2）实测：构造/关联参数标签与关键字共享命名空间——`member(object: ...)` / `while_stmt(step: ...)` 因 `object`/`step` 是关键字而解析失败（E2 类，自举探针 G-P5，`examples/selfhost/docs/host-gaps.md`）。spec 未约束标签与关键字的策略，宿主侧无解法，迫使自举侧改名绕行（`base`/`step_block`）。

用户裁决（2026-08-30）：采 Swift 风格**反引号转义**——通用解，惠及一切关键字/标识符碰撞，不引入标签专属命名空间规则。

## Decision

### D1 反引号转义产生式

`'`' ESCAPED_NAME '`'` 整体产出 **IDENT token**（跳过关键字分类），故关键字可在一切标识符位作标识符：变量、参数、构造/关联参数标签、声明名。转义仅是词法层的拼写选择，不改变语义（转义名与同名普通标识符完全等价）。

### D2 未闭合回退（与 ADR-021 同层）

转义**行内闭合且非空**时按 D1 产出转义 IDENT；未闭合（行尾/EOF）或空内容**回退 ADR-021 兜底**（单字符 IDENT，文本 = 反引号本身）——词法器零错误契约不变，畸形转义的诊断后移到解析/语义阶段。依据：L0 差分语料的裸反引号用例（第 95 行）钉定了兜底行为，为保 L0 门禁而收敛于此。

## Consequences

- **变容易**：任何关键字/标识符碰撞有了通用出路；自举侧 G-P5 改名（`base`/`step_block` 等）成为可回退清理项。
- **挂账（G-P10，自举批次 2 探针连带发现）**：带标签的类型构造调用当前无限递归（E5-006 护栏拦截）、标签为 `step` 的函数调用同样递归、位置形式类型构造实参被静默忽略——反引号在**函数标签**位已可用，在类型构造标签位的实际启用待 G-P10 修复。
