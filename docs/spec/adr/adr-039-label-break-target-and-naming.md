# ADR-039: 标签 `break` 的定向范围与标签命名规则

> **状态**：**active**（2026-09-17 用户裁决）｜**类别**：语言级
> **本件范围**：**§1.3 第 1–3 步（提议 / 影响评估 / 登记）**。第 4 步「落地」与实现**同批后续段**完成，
> 落点见「后果」节 —— 本件不是「只登记」型 ADR，而是同批先登记、后落地的第一段。
> **触发**：`P4-γ` 期补**第 3 层「spec 断言层」**的「标签语义」面时，用例面照出一个
> **三处文档都没写、两个引擎行为相反**的形态。

## 1. 提议（要解决什么）

补第 3 层用例要写「标签落在各种控制流上」的期望值，于是必须先回答：**`break 标签` 能指向什么**。
一查之下发现三个问题同源，都由「给 `if` 打标签」这个**被明文允许、却没有配套语义**的形态引出：

| # | 问题 | 现状 |
|---|---|---|
| **D1** | `break 标签` 指向一个 **`if` 标签**时该做什么 | **文档沉默**，两引擎相反（见 §2） |
| **D2** | 嵌套**同名**标签时，`break 同名` 定向到哪一个 | **无条款**；三通道一致（内层） |
| **D3** | 标签与**变量同名**时是否互相遮蔽 | **无条款**；三通道一致（不遮蔽） |

D1 不是「实现 bug」：它是**语义从未被定义**，两侧各自成立了一套解释。

## 2. 现状实测（提出方向前先量）

### 2.1 D1：`break` 指向 `if` 标签（最小复现）

```pini
main|func() -> ():
    var k = 0
    outer|if k == 0:
        print("before")
        break outer
        print("never")
    print("after")
    return
```

| 通道 | 实测 |
|---|---|
| `interp-ast` | `rc=0`，输出 `before` / `after` ⇒ **跳出该 `if` 块、继续执行** |
| `interp-hir` | `rc=1`，**`E5-006`** ＋ `break outside loop` ⇒ 运行期 panic（`before` 已印出） |
| `llvm-hir` | **panic**（`bk_panic` → `lli` 崩溃栈）；退出码不可辨（`run-llvm` 丢弃 `lli` 状态，**已立案**） |

⇒ **`hir` 与 `llvm` 同源 panic，`ast` 是少数派。** 同源的原因不是巧合：
`HIRLowerer` 是**两个 HIR 后端共用的前端**，`panicStmt` 由它在降载期产生。

**同一份文本被三处写成「正确」**，而实测与之不符：

| 处 | 原文 | 实测 |
|---|---|---|
| 契约节点 11 | 「不可解析目标 → 降级为 `panicStmt`」（**fail-loud 对齐**，非静默跳过） | 解释器**不** fail-loud ⇒ 「对齐」不成立 |
| `HIRLowerer` 注释 | 「fail-loud at run time, **exactly like the interpreter**」 | 同上 |
| `IREmitter` 注释 | 「the interpreter errors when a break escapes to the top level (probe-verified)」 | 仅当**无任何带标签结构可接**时才成立 |

⇒ 三处的前提是「解释器会 fail-loud」，而解释器把 `if` 标签**正常解析**为「跳出该块」。
**根因是「标签 break 能指向什么」这条语义从未被定义。**

### 2.2 D2 / D3：三通道一致，但**无条款**

| 形态 | 最小复现要点 | 三通道实测 |
|---|---|---|
| 内层同名标签遮蔽 | `same\|while` 内再套 `same\|while`，内层 `break same` | 全一致 `0` / `0` ⇒ **内层**（最近匹配） |
| 标签与变量独立命名空间 | `var outer = 5` ＋ `outer\|while`，体内 `print(outer)` | 全一致 `5` / `5` ⇒ **独立**，标签不遮变量 |

**依据是「实现共识」，不是规范** —— 因此**不能据以手写第 3 层期望值**：
照抄实现输出写 `.expected`，第 3 层会从「对照规范」**退化成「对照自己」**
（`Tests/PiniTests/SpecAssertionTests/PROVENANCE.md` 对此有明文禁令）。

### 2.3 文本依据：EBNF 的两条注释**不对称**，且不对称是有意义的

```
break-stmt      ::= 'break' [IDENT];                   (* 不携带值 *)
continue-stmt   ::= 'continue' [IDENT];                (* 仅循环标签有效 *)
if-stmt         ::= [IDENT '|'] 'if' expression control-block …
```

- `continue` 明写「**仅循环标签有效**」；`break` **没有**这条限制。
- 而 `if-stmt` 的产生式**允许**标签（`[IDENT '|']`），§2.4.1 亦明写「标签落在 **if**/while/for 上」。

⇒ 反向阅读：**对 `continue` 设限、对 `break` 不设限** —— 这正是一条可用的文本依据，
而实测的 `continue`→`if` 标签行为（`ast` 与 `hir` **都拒**）与该限制**一致**。

## 3. 影响评估（触及契约节点 ⇒ 依硬停条件走 §1.3）

**本件触及契约节点 3 个**：节点 3 `ifStmt`（须承载标签）、节点 11 `breakStmt`、节点 12 `continueStmt`
（语义表述须改）。`P4-γ` 的硬停条件写明「若须动契约那 60 个节点 ⇒ 停下走 §1.3」⇒ 本件即该流程的入口。

### 3.1 代码面实数（实测，按符号计）

| 层 | 现状 | 证据（符号） |
|---|---|---|
| AST 语法 | **已支持** —— `ifStatement` **已带** `label: String?` | `Sources/PiniCore/AST/Statements/Statement.swift` |
| AST 执行 | **已支持** —— `executeIf(…, label:)` 捕获匹配标签的 `breakSignal` 并向外抛（跳出块） | `Interpreter.executeIf` |
| HIR 表示 | **无标签** —— `HIRStmt.ifStmt(condition:thenBody:elseBody:)` | `Sources/PiniCore/HIR/HIRNode.swift` |
| HIR 降载 | **丢弃标签** —— 模式解构写成 `_, _`；`resolveLoopDepth` 只扫**循环**标签栈 | `HIRLowerer` 的 `case .ifStatement(…)` / `resolveLoopDepth` |
| HIR 执行 | 信号按**深度**承载（`breakSignal(depth:)`），接收者只有循环帧 | `Sources/PiniCore/Interpreter/HIRExecutor.swift` |
| LLVM | `ifStmt` 无标签；`loopStack` 是**循环**帧栈，越界即 `bk_panic` | `emitBreak` / `emitContinue` / `loopStack` |
| AST 挂起路径 | 按**标签名**匹配（`l == frame.label`），与 D2 的「最近匹配」同形 | `Sources/PiniCore/Interpreter/SuspendEvaluator.swift` |

**符号计数（`Sources/` 全树）**：

| 符号 | 处数 | 文件数 |
|---|---|---|
| `ifStmt` | 8 | 5 |
| `breakStmt` | 8 | 5 |
| `continueStmt` | 6 | 5 |
| `loopLabels` | 8 | 1 |
| `loopStack` | 29 | 2 |
| `resolveLoopDepth` | 3 | 1 |
| `breakSignal` | 22 | 4 |
| `emitBreak` / `emitContinue` | 3 / 2 | 1 / 1 |

⇒ 触及 `Sources/` **至少 5 个文件**：`HIRNode` · `HIRLowerer` · `HIRExecutor` · `IREmitter` · `HIRPrinter`。
⚠️ `HIRPrinter` 是**穷尽 switch** ⇒ 改 `ifStmt` 形状会**编译失败**（这是保护，不是缺陷）；
它的消费方是两项宿主级断言与契约核验的 `printer` 锚点 ⇒ 打印文本须同步。

### 3.2 表示差异（这是实现方向的关键）

两侧的**承载方式不同**，不是同一件事的两种写法：

| 侧 | 承载 | 匹配方式 |
|---|---|---|
| AST（含挂起路径） | `label: String?` | **按标签名**沿帧栈向上找最近匹配 |
| HIR / LLVM | `depth: Int` | **按层数**从最内层往外数 |

⇒ 要让 `if` 块可被 `break` 定向，HIR 侧需要把「**循环帧栈**」泛化为「**可中断帧栈**」
（`if` 也压帧，但其 `continueTarget` 为空）。**这一步是本 ADR 的实现主线**，见「后果」节。

### 3.3 爆炸半径

| 项 | 实数 |
|---|---|
| 既有语料是否依赖「`break` 拒不指向 `if` 标签」 | **未发现** —— 全仓用例面未见该形态（本批实测面 = 第 3 层 12 例 + 差分语料，均不含） |
| 既有 `examples/` 是否用到 | 否（`examples/control-while.pini` / `for.pini` / `step.pini` 均为循环标签） |
| 与 LLVM 侧的一致性 | 该分歧**来自共用降载层** ⇒ 改降载层**同时**修好两条 HIR 后端；LLVM 侧另需「`if` 块出口标签 + 释放路径」 |

## 4. 决定

### D1 —— `break 标签` 可定向**任意带标签结构**（含 `if` 块）（**用户裁决：S1 保留 ast 行为**）

`break 标签` 跳出标签所指的那一层；标签落在 `if`/`while`/`for` 上均有效。
**`continue 标签` 仍仅循环标签有效**（EBNF 明文；实测两解释器臂已一致拒绝）。

理由：① 文本方向一致（对 `continue` 明设限、对 `break` 不设限）；② 改动落在**存留实现**上
（`ast` 侧已实现，是待删的那一支）；③ 判它非法要改**即将被删的代码**、并**收回用户今天能跑的形态**。

### D2 —— 内层同名标签**遮蔽**外层（**用户裁决：B 先补规范再写断言**）

`break 同名` / `continue 同名` 定向到**离它最近**的那个同名标签。
依据：三通道已有一致行为，且 `ast` 挂起路径的 `l == frame.label` 沿栈向上找最近匹配即此语义。

### D3 —— 标签与变量**独立命名空间**（**用户裁决：B 先补规范再写断言**）

标签不参与变量作用域，同名互不遮蔽。

> **D2/D3 的登记理由（用户裁决）**：这两条今天靠「实现共识」维持，而实现共识正是**翻转之后最难守住**的东西
> —— 参照臂一删，就没人再交叉验证。走 §1.3 写入语言参考后，它们才**有规范依据且有第 3 层断言保护**。
> 另一条被否决的路是「生成期望值 + 盖 `GENERATED` 戳」：它把这种隐性依赖**固化**成「只证没变」，
> 方向与绞杀（逐步让旧实现可退役）相反。

## 5. 后果与破坏性

### 5.1 破坏性判定：**非破坏**

| 侧 | 今天 | 本决定生效后 | 判定 |
|---|---|---|---|
| `ast` | 已可跑（跳出块） | 不变 | 无变更 |
| `hir` | **拒绝**（`E5-006` panic） | 可跑 | **放宽**（拒 → 接受） |
| `llvm` | **拒绝**（panic） | 可跑 | **放宽** |

⇒ 无任何**既有可运行程序**变为被拒；变化只有「原本被拒的形态转为可运行」。

### 5.2 一处**收敛**（如实记账，不是「无变更」）

`break 同名` 在「**外层循环**与**内层 `if`** 共用同名标签」时会换靶：
今天 `hir` 只扫循环标签 ⇒ 命中**外层循环**；本决定生效后按 D2 取**最近匹配** ⇒ 命中**内层 `if`**。
这是 `hir` 向 `ast`（冻结参照）**收敛**，也是该形态此前**无定义**的直接后果。
形态罕见（同名标签跨种类嵌套），但**不写进迁移说明就是隐瞒** ⇒ 落 `docs/spec/migration-2026-09.md`。

### 5.3 落地项（同批后续段，顺序不可拆）

1. **登记**（本件）→ **用例作红规格**（第 3 层「标签语义」面）→ **实现** → **转绿** → **证据**（§1.3 第 5 步）；
2. **规范**：§2.4.1 标签行 + §3 台账 G61；**语言参考**：标签节 + 跳转节（D1/D2/D3 三条）；
3. **契约**：节点 3 `ifStmt` 加标签；节点 11/12 的「fail-loud 对齐」表述**按实测订正**；
4. **实现**：`HIRNode` · `HIRLowerer`（可中断帧栈）· `HIRExecutor` · `IREmitter`（`if` 块出口标签 + 释放路径）· `HIRPrinter`；
5. **迁移说明**：§5.2 的收敛项。

⚠️ **规范与实现不可拆开登记**：若规范先写「`break` 可跳出带标签的 `if` 块」而实现做不到，
规范就描述了**不存在的东西** ⇒ 撞「锚点须可兑付」。这是本批把 §1.3 与实现放在同一批的实质理由。

## 6. 不在范围

- **不改**「`continue` 仅循环标签有效」这条限制（本件是**加固**它，不是放宽）。
- **不裁决**「未定义标签」与「标签重复声明于同一层」的处置（前者两解释器臂已一致拒绝、后者无实例）。
- **不动** `run-llvm` 丢弃 `lli` 退出码的既有缺陷（**已立案**，与本件无关）。
- **不引入**标签作为一等值（不可传参、不可返回）。
