# ADR-001：给定块（`given`）与取用参数（`using`）

> **状态**：已接受（设计定稿；实现未落地）
> **决策日期**：2026-09-19
> **稳定性**：**Experimental**（用户裁定：暂时放到实验级）
> **⭐ 编号规则**：**只增不改** —— 本编号不复用；**内容不受此限**（可后续修订）。
> **上级载体**：本仓语言规范 §1.3（语言级变更流程）。
> **记录范围**：只记**结论与依据**，不复制推演过程。

## 1. 背景

Pini 禁止全局可变状态。但有一类东西是程序级、可变、且被多模块共用：调度器、队列、连接池、缓存。
它们**不是**全局变量的语义，但**今天没有承载它的机制**：

| 既有机制 | 为什么承载不了 |
|---|---|
| 顶层 `let` | 无模块级绑定语义，无程序级唯一性，无惰性 |
| `object` | 是类型；能实例化任意多个，实例之间不共享 |
| `enum` | 用例是编译期值或显式构造 |
| `import` / `export` | 只是符号可见性，不创造运行时值 |
| 参数传递 | 可行，但**逐层传染** —— 中间每一层都要多加一个参数 |

⇒ 三条出路都不可接受：**显式传参（传染）**、**藏到宿主语言（语言层失去推理能力）**、**放弃急切派发（失去直觉）**。

## 2. 决策

### 2.1 给定块是**一种复合类型**

```
[应用服务|given]
队列: 队列类型 = 创建队列()
调度器: 调度器类型 = 协作式调度器()
```

| 面 | 规格 |
|---|---|
| 块头 | `[类型名\|given]` —— 块头名是**类型名**，不是文件名 |
| 字段 | `名: 类型 = 表达式`（沿用 `field-decl`，**不新增产生式**） |
| 身份 | **普通复合类型**：可作类型标注、可实现特征、**实例数任意** |
| 构造 | ✅ **允许**，与其它复合类型同规（`应用服务()` 合法） |
| 字段可变性 | ✅ **可写**。写语义问题归 **COW 等优化**；本决定不规定任何字段级不可变约束 |
| 值 / 引用语义 | **由类型自身决定**，本决定不作统一规定（`self` 不分值 / 引用语义） |
| 唯一保留的不可变 | **enum 用例不可修改**（既有规则，非本决定引入） |

### 2.2 默认实例与惰性（本决定的**唯一新机制**）

⭐ **各字段初值合起来，就是编译器为该类型提供的「默认实例」**：

| 条目 | 规格 |
|---|---|
| 什么被物化 | 把全部字段初值求值后得到的**一个实例** |
| 时机 | **惰性** —— 首次需要时才物化 |
| 次数 | **恰一次**（每类型实例化一份） |
| 取用 | `using` 参数 ⇒ 绑定**该实例本身**（不是副本、不是模板） |
| 字段不齐 | 缺初值 ⇒ 无完整默认值 ⇒ **`using` 无从物化**。⭐ **实现口径（2026-09-19 用户裁定）**：**降载期就对每个给定块报** —— **即使该块从未被取用**也报（比「用到了才报」严）。⇒ 代价：`[配置\|given]` 里留一个无初值字段、打算以后只显式构造，这种写法**不再合法**（要它就写显式初值） |
| 地址 | **稳定** —— 全程序共用同一个默认实例，故其身份稳定 |

⇒ **「未访问的给定块从不物化」**，所以无启动风暴：不用的数据库、日志、缓存不会建连接、开文件、分内存。

### 2.3 `using` 是**参数修饰符**

```
处理|func(using 应用: 应用服务, 数据: [I32],) -> (I32,):
    return 应用.提交(数据)
```

| 面 | 规格 |
|---|---|
| 形态 | `using 名: 类型`，位于**函数参数列表**内（不是子句，不是第二个块） |
| 解析 | **编译期**按**类型**找到默认实例；**无运行时查找、无 vtable** |
| 调用点 | 实参由**编译器插入**，调用点不传 |
| 显式提供 | ✅ **允许** —— 它是个真参数，调用点可以自己给 |
| 强制 | ✅ **依赖不得隐藏**：值位引用了给定块类型，签名就必须声明对应 `using`（或改为普通参数） |
| 作用域收窄 | 强制规则的判据是「**体内**值位引用」⇒ **抽象签名（无体）豁免** |
| 扩展块方法 | ✅ 允许声明 `using`（与自由函数同规） |
| 入口 | `main` 无调用点 ⇒ 无需声明（惯例入口不带参数） |

### 2.4 惰性分三层 —— **默认急切，惰性要明写**

> 用户裁决：「字段级的懒构造是**非默认行为**，字段上允许通过 `LazyRef` 来处理。」

| 层 | 行为 | 依据 |
|---|---|---|
| **块级**（默认实例何时物化） | 惰性 + 恰一次 | 本决定 §2.2（招牌卖点） |
| **字段级**（实例内字段初值） | ⭐ **急切** —— 构造实例时求值 | 与语言中每种复合类型同规 |
| **字段要惰性时** | 显式写 `LazyRef<T>` | 既有能力（缺口台账 `G40`，v0.42.0 转正） |

⇒ **`LazyRef` 已可作字段类型，无需任何新能力**；本决定只需写明「哪一层默认是什么」。

### 2.5 程序级共享从哪来 —— **诚实登记**

```
[队列|object]                       ; 可变的共享状态在这里
元素: [I32] = []

[应用服务|given]
队列: 队列 = 队列()                  ; 字段指向那个 object
```

| 写法 | 拿到的是 |
|---|---|
| `处理(1,)`（声明了 `using`） | ⭐ **同一个默认实例**（非副本）⇒ 与所有其它 `using` 取用共享**同一对象** |
| `处理(应用服务(), 1,)`（自己构造后传入） | **你自己的新实例** ⇒ **不共享，且语言不报错** |

⇒ ⚠️ 「程序级」**不是类型的保证，是用法的性质**。ADR 只能承诺「**同一类型的所有 `using` 取用共享同一个默认实例**」，
**不能**承诺唯一性。
⇒ ⚠️ 配套规则：**可变共享状态必须放进引用字段**（放值字段则随实例各一份，共享**静默失效**）。

### 2.6 取用位与函数类型 —— **声明位与调用位配对**

```
取名|func(using 配: 配置,) -> (String,):
    return 配.名称

main|func() -> ():
    var f = 取名
    print(f())            ; ✅ 省略生效（取用位由推断携带在函数类型上）
    return
```

| 面 | 规格 |
|---|---|
| 取用位住在哪 | **函数类型**上的一组下标（「哪些参数位可取用」）—— 与 §2.3 不冲突：**声明位**决定它，**类型**承载它 |
| 谁填它 | **类型推断**（由声明的参数表推出），不是书写 |
| 用户能写吗 | ⛔ **不能** —— 类型标注位写 `using` 落无效类型（解析期天然拒绝；实测字段位与局部标注位同形） |
| 参与类型等价吗 | ⛔ **不参与** —— 赋值 / 传参无摩擦，既有语料零影响 |
| 能力边界 | **取用位会丢失的地方**：显式标注裸函数类型 / 作实参传入 / 存进对象字段 ⇒ 省略实参落「参数数量不匹配」 |
| 依据 | 「本语言向来不在字段位置做细致修饰」⇒ **声明位置与调用位置配对**（用户 2026-09-19 裁定） |

⇒ 一句话：**取用位是「声明 ↔ 调用」的配对信息，不是类型恒等的一部分。**

⇒ **代价（有意采纳）**：函数值经字段 / 参数传递后**失去**省略能力 —— 用户已明确接受
（「经过字段位置上的类型标注禁止 `using` 修饰，因此采纳『保存到字段上失去此能力』」）。

⇒ **收益**：`check` 与 `run` 的报法**收敛** —— 要么省略生效、要么「参数数量不匹配」；
此前「赋给局部变量后调用」是 `check` 通过、`run` 报 IRGen 层「未声明变量」同族的中间态。

⇒ ⚠️ **不进运行时表示**：取用位是**编译期**事实，函数值在运行时不携带它 ——
以维持 §2.3「无运行时查找、无 vtable」。

## 3. 理由

**为什么不直接用 `object`**：`object` 能实例化任意多个，且没有「程序级默认实例」这个概念 ⇒ `using` 无从解析。

**为什么不放 `export` 块**：`export` 是符号可见性操作。加入值声明会杂糅两种语义，`=` 的含义分裂。

**为什么 `using` 是参数修饰符而不是第二个块**：`given` 已经用了块形式，再给 `using` 一个块是**重复的清单** ——
块里的名字与参数表里的名字是同一批事实的两份副本，而副本必然漂移。参数修饰符保持**「函数的全部输入都写在同一个参数表里」**这条不变式：
普通参数从调用点传入，`using` 参数由编译器插入 —— 位置同一个，**来源被标出来**。

**为什么强制而不是自愿**：自愿的话，函数体内可直接写 `应用服务.提交(...)` 绕过 `using` ⇒ 依赖仍可隐藏。
而本决定的前提修正（「无隐式、不可控、**不可推理**的全局可变状态」）要成立，需要的恰恰是**不可绕过**。
⇒ 这正是「必要的噪音」的实质：**传染没有消除，只是从实参位搬到了签名位**。

**为什么惰性不用显式初始化**：显式初始化易漏、易错、顺序要手工维护；惰性自动、安全、无启动风暴。

## 4. 后果

### 4.1 正面

- 程序级资源有了**显式声明位**，且语言层可推理（无运行时查找、无 vtable）
- 依赖在**签名里可读**（`using` 强制），入口侧**无传染**
- **无启动风暴**：未访问的给定块从不物化
- 默认实例**地址稳定**；值语义不施于给定块（值 / 引用由类型自决）
- 复用既有设施：块文法、扩展块、字段产生式；惰性 / 恰一次 / 线程安全 / 地址稳定四项复用既有
  **`LazyRef`（`G40`）的实现骨架**。⚠️ **订正（2026-09-19）**：`LazyRef` **本身不承担**默认实例的物化 ——
  用户裁定它只作**字段内**的细粒度缓冲 ⇒ 原文「零新运行时机制」当读作「零新**惰性**机制」；
  **新增面** = 程序级存放位 + 取用节点 + 一个运行时取用符号（见 §4.2 代价 7）

### 4.2 代价（诚实登记，不藏）

| # | 代价 |
|---|---|
| 1 | **「程序级」是用法约定而非类型保证** —— 自行构造的实例不共享，而语言**不报错**（§2.5） |
| 2 | **可变共享状态必须放进引用字段**，否则共享**静默失效**（§2.5） |
| 3 | **签名面被占用** —— 每层都得声明 `using`（「无传染」应改述为「**无实参传染**」） |
| 4 | **关键字表可能增加**（`using` 入表是**破坏性**：它今天是合法标识符）—— 见 §7 未决 |
| 5 | **字段初值的求值时机容易被误读** —— `连接数据库()` 读起来像只跑一次，实为**每次构造都跑**（§2.4） |
| 6 | **语言层承认程序级状态** ⇒ 前提须修正为「无**隐式、不可控、不可推理**的全局可变状态」 |
| 7 | **非「零新面」**（2026-09-19 订正 §4.1）：默认实例的物化需要一个**程序级存放位** + 一个**取用节点**（`HIR 契约` §4.3 预留位）+ 一个**运行时取用符号** ⇒「零新运行时机制」不再成立，正确表述是「零新**惰性**机制」（惰性四项复用既有实现骨架） |

### 4.3 不承诺（明确的非目标）

- ⛔ **不是依赖注入**：解析在编译期、按类型 ⇒ **不可替换、不可 mock**
- ⛔ **不提供终结语义**：语言不定义给定块的销毁与清理（见 §7 第 5 项 —— **已裁：只登记、不改码**，不对称显式保留）
- ⛔ **不保证唯一性**：允许多实例（§2.1）
- ⛔ **不支持 FFI 传递给定块本身**：`*T` 禁 `object` ⇒ 能传的是它**持有的 `*T` 字段**（见 §7）

## 5. 与既有决定的关系

| 事项 | 关系 |
|---|---|
| 块修饰符集 | 新增 `\|given` 一项（既有：`object` / `enum` / `import` / `export` / `foreign`） |
| 扩展块 | **不需要新语法** —— 扩展块按类型名挂载；给定块的扩展块括号**已裁** = **`[[T]]` 通用形**（方括号为通用形，`((` / `{{` / `<<` 为按类别专门化的糖；**已落地**，批 `P1a`） |
| `LazyRef`（`G40`，Provisional） | **被复用**，语义不变 |
| 函数参数「确定不变」 | 本决定**不改变**参数可变性现状（该议题不属本决定，另行处理） |
| 特征块（trait） | 给定块可实现特征；特征签名**无需**声明 `using`（默认实现走 `self`） |

| 「惰性初始化 once」列为新增运行时机制 | ⚖️ **部分成立（2026-09-19 订正）** —— 惰性 / 恰一次 / 线程安全 / 地址稳定四项**复用既有 `LazyRef`（`G40`）实现骨架**；但**默认实例的物化本身是新面**（存放位 + 取用节点 + 一个运行时符号，见 §4.2 代价 7）⇒ 「不成立」只对**惰性那四项**成立，对**物化面**不成立 |
| 「急切派发」列为卖点 | ⚠️ **前提未验证** —— 它依赖「异步方法调用产出 Future」，该形态须先落地 |
| 仅写「首次访问才初始化」 | 须**补明三层**（§2.4） |
| 「生命周期」区初始化 5+ 项、终结零字 | 立「**寿命与清理**」为与「**惰性构造**」**并列的一节** |
| 「类型名 `_` 前缀私有」 | ⛔ **两点订正**：① 跨模块共享**须 `public`**（只有 `public` 能跨模块）；② `private` 在本仓定义为**当前类型内部** ⇒ 对顶层类型不成立 |
