# ADR-035: 语言参考纳入事实源——分面权威与递交流程
（Language Reference as a Source: Faceted Authority and the Handover Flow）

## Status

**Accepted（2026-09-16）** —— D1–D4 全部裁决，随本次文档治理落地。

本 ADR 是「语言面描述的权威归属」的规范载体。此前语言面描述的唯一权威载体是规范
`../pini-spec-v0.md`（其自我声明为单一事实源）；设计者新建的语言参考
`docs/spec/pini-reference-v0.md`（4203 行 / 14 章）自称「取代旧规范，成为单一事实源」。
两者正面冲突：同一时刻两份文件都自称唯一权威（见 Context §2）。

## Context

### 1. 为什么是现在（设计者裁决，2026-09-16）

> 「reference 作为 spec 的补充说明，相当于细化的语言参考，但是其中集成了一些 spec 的描述，
> 必须重新整理 spec，并把 reference 纳入事实源。」
>
> 「先迁移，spec 必须是首要入口，它承载改动，然后把成熟的改动成果递交到
> （今后相当稳定的）reference。」

⇒ 事实源在**分面**后不再单一；必须把「谁是入口、谁承接成果、冲突时听谁」显式化为规则，
否则两份文件各自自述权威，漂移不可判。

### 3. 裁决

| # | 议题 | 裁决 |
|---|---|---|
| **D1** | 权威分层 | **以规范为基础**；语言参考作为**外部引用文件**纳入事实源，地位**同等或低于规范**。承认单一事实源在分面后不再成立。 |
| **D2** | 参考里的工程内容 | **语言参考不应包含工程内容**（诊断码判为工程内容，一并出列）。 |
| **D3** | 规范侧整理方向 | **规范专注工程，语言参考专注描述语言**；两者必须挂钩；语言参考此后相当稳定。 |
| **D4** | 引用纪律 | **跨文件引用不得引用到章节**，一律用主题词。 |

## Decision

### D1 → 分面权威 + 权威次序（落规范 §0）

| 面 | 权威载体 | 覆盖 |
|---|---|---|
| 工程与治理 | 规范 | 事实源层级与权威次序、版本演进、稳定性分级、证据协议、缺口台账、破坏性变更政策、测试规范、注释规范 |
| 语言面 | 语言参考 | 词法、类型、声明、表达式、语句、内存模型、并发模型、FFI 与 unsafe、模块系统、错误模型、运行时与执行、形式文法 |

**权威次序**（三条）：

1. **规范是首要入口**——语言面与工程面的一切改动**先在规范发生**；
2. **成熟成果递交语言参考**沉积——语言参考因此偏向稳定、变更频率低；
3. **不一致时以规范为准**（规范是上游、是入口）。**已完成递交的条款**，其语言面表述以语言参考为准；尚未递交的仍以规范为准。

### D2 → 工程内容出列（落语言参考章首）

语言参考删除第 14 章全部工程内容（诊断码 / 稳定性分级定义 / 变更治理 / 证据协议 /
缺口登记 / 证据表 / 取代声明）；章首改述「性质与依据」：性质、在事实源层级中的位置、
不含内容、变更方式、与设计意图稿的关系。工程条款的权威保持单点，只在规范。

### D3 → 挂钩与递交流程

- **挂钩**：规范新增「语言细则索引」，逐条登记「规范条款 → 语言参考位置 → **递交状态**」。
  该节是两者的**唯一挂钩点**，同时是递交批次的进度台账。
- **递交（Handover）**：作为规范变更治理第 4 步「落地」的固定子步骤——**步数不变**，
  故下游「五步治理」提法不受影响。
  - **条件（三条全中）**：① 该构造已定级 Provisional 或 Stable（Experimental 不递交）；
    ② 实现侧有证据（缺口台账状态为「已定义且已实现」或等价）；③ 无未裁决张力。
  - **动作（顺序固定「先补后删」）**：① 细化连同**判据与 ADR 溯源**先写入语言参考
    （信息量只增不减）；② 规范该条收缩为「钉住声明 + 指向」；③ 缺口台账该条「关联」列改指；
    ④ 同步引用该条的下游载体。
  - **回写**：语言参考侧若发现判据缺口，按治理流程回到第 1 步——**不得**只在参考侧改。

### D4 → 引用纪律（落规范 §0 文档引用约定）

跨文件指向一律用**主题词**（章 / 节名），不引章节号。豁免仅两处：机器元数据字段与
历史归档快照；以及规范「语言细则索引」自身——该节不带小节号即无法定位到细则。

## 后果

- **单向流向**：改动入口唯一（规范），语言参考是沉降层 ⇒ 结构上不会双向漂移。
- **下游锚点分流**：引用工程面条款的载体不变；引用语言面条款的**活载体**（工单 / 计划 /
  README / 契约）在**该条递交时同批**改指语言参考——不早于递交，避免指向尚未接收的位置。
  **只增不改的历史载体区别对待**：ADR 的**章节号 / 条款位置**不回改（记录决策当时的位置，如 ADR-029
  指向规范的「集合与表达式位置」条，属决策快照）；但其**文件路径**随归档 / 移动跟随更新——否则引用
  失效，且文档链接门禁会当场拦下。
- **器械约束**：第 3 层断言层锚点绑定规范的「值展示语义」条，故该条递交须与该层锚点改写同批，
  否则第 3 层静默降级为第 1 层（只证明实现自洽）。
- **代价记账**：分面后，两文件对同一构造仍可能短期并存（未递交的条款 ⇒ 规范仍有细则），
  故「不一致以规范为准」这条兜底规则须保留，直到该条的递交完成。
- **不做**：不合并两文件；不改两个文件名；不动工程面章节；不在本次清理形式上一致但语义
  更细的既有内容（形式文法两处的注释溯源补齐属后续批次）。
