# ADR-041：错误发现的层次 —— 静态层优先

> **状态**：Accepted（2026-09-17）｜**级别**：语言级
> **依据**：用户裁决（2026-09-17，阻塞队列乙组 `D2` 取 **①**）—— 「写明『编译期拒』；
> 通过测试方法断言维持验证」。
> **上游**：`docs/issue-hir-blocker-queue-2026-09-17.md` §2 `D2` ·
> `docs/issue-hir-static-rejection-vs-runtime-error-2026-09-16.md`（现象与实测清单）。
> **走 `spec §1.3`**：提议 / 影响评估 / 登记 / 落地 / 证据 —— 五步的落位见本文末表。

## 1. 上下文

`LR-4` 把「已解析语义」的唯一权威交给 HIR，而 HIR 是**静态降载层**：它在一份程序被接受之后、
在运行之前，就把整棵树降载成节点。这个性质与「AST 走查是唯一引擎」的时代**天然不同**：

同一批负向用例（喂一个**非法程序**、断言抛某类**运行期**错误）在两条通道上的结局是：

| 通道 | 结局 |
|---|---|
| AST 走查（旧） | 程序跑起来 → 在运行期撞上 → 抛 `RuntimeError` / `invalidOperation` / `typeMismatch` |
| HIR（新） | 降载期**已经看出**它不合法 → **更早、以另一种错误种类**拒绝（`E4-xxx` 类型检查 / `E6-004` 降载） |

⇒ **语义（程序该被拒）一致，判据的形状（在哪个阶段拒、报什么码）不一致**。
这不是回归，也不是 HIR 的功能缺口 —— 该单 §2 把它定性为「**语言规范说运行期 trap，
而静态层提前拒了，这件事本身是否可接受**」。

⚠️ 该单同时写明一条纪律，本条遵循它：**不能靠改测试结案** ——
「把断言从 `RuntimeError` 改成『编译期报错』，等于用实现去定义规范」。
⇒ **先裁规范，再改用例。** 本 ADR 就是那次裁决。

## 2. 决策

### D1 · 拒绝的**层次**不是语言的语义承诺，而是实现的性质；规范明确「静态层优先」

**规范承诺的是「这个程序会被拒」，不是「它在哪一毫秒被拒」。**
但当某一情形**在静态层可判定**时，规范要求它**在静态层被拒** —— 理由不是审美，而是：

- 静态层拒错**不产生任何输出**，不依赖运行时状态，可复现；
- 它把错误绑到**源码位置**，而不是绑到「跑到第几步才发现」；
- 它是 HIR 作为「唯一已解析语义表示」这一定位的直接推论（ADR-034）。

⇒ 因此下列**分工**成为规范的一部分（落 §2.4.5）：

| 错误形态 | 在哪一层被发现 |
|---|---|
| 类型不符、可见性越界、泛型/元组形态错、`Result` 上下文缺失 | **静态层**（类型检查 `E4-*` / 降载 `E6-004`） |
| 越界读、IO 失败、除零、断言失败、取消、用户 `err(...)` 的传播 | **运行期**（`E5-*`）；这些**静态不可判定**，静态层**不得**抢报 |

### D2 · 判据的绑定方法：负向夹具**不删**，改以**测试方法断言**「编译期拒 + 具体错误码」

用户原话「通过测试方法断言维持验证」。落地含义（本 ADR 钉死）：

1. 每条受影响的负向夹具**保留**，**不删**、不减；
2. 它的期望值改为断言**两件事**：① 该程序**被拒**（rc ≠ 0、零 stdout）；
   ② 拒绝**发生在静态层**，且**错误码是哪一个**（如 `E4-012`）；
3. ⚠️ **不得**放宽成「只要不是运行期就通过」这类无内容的断言 ——
   那正是本仓已付过代价的「判据被掏空」形态（`D-P4-21` 同族）。

### D3 · 本条的**未做部分**：13 条用例的断言改写属 `G-4·G-5`

本 ADR 只**定规范**与**定方法**，不动任何测试。改写清单与实施见
`docs/issue-hir-p4-plan-2026-09-16.md` 的 `G-4·G-5` 批 —— 它是 `G-6` 的前置。

### D4 · `D2` 的另一半（诊断通道奇偶，20 条）**不在本条**

「两条解释器臂发 `E7-001` 语义警告、而 LLVM 臂从不转发」属**诊断通道**问题，
不属「拒绝层次」；归**在册工单** `docs/issue-diagnostic-channel-parity-2026-09-12.md`（其 A/B/C 仍未裁）。
⇒ 本条**不顺手改 LLVM 行为**。

## 3. 后果

- **规范侧**：新增 §2.4.5；§3 登记 **G63**（残余：13 条用例的断言待改写、以及「哪些情形属静态可判定」的边界清单待随批补齐）。
- **判据侧**：负向夹具的期望从「运行期错误种类」改指「静态层拒绝 + 错误码」——**判据仍能失败**（改错码即红）。
- **实现侧**：**零改动**。HIR 现状**已经**是静态层优先；本条把它从「实现的性质」升格为「规范的要求」。
- **语言参考**：**本批不递交**（§1.3 第 4 步的条件之一「实现侧有证据」目前**只对 HIR 一侧成立**，
  而 AST 通道仍在、且用具的期望值尚未改写）⇒ 待 `G-4·G-5` 交付后随该批递交。
- **迁移**：不构成破坏性变更（无程序因此从合法变非法；已有程序的**可运行性**不变）。
