# ADR-037: 泛型枚举用例构造的形态与类型实参挂点
（Generic Enum Case Construction: Form and Type-Argument Attachment）

## Status

**Accepted（2026-09-16）** —— 用户裁决形态取 **C**（限定为准 · 裸名为糖），并在三个候选拼写中选定
**实参挂枚举名** 一种；随 `G-2d` 的 `S0`（语言面登记）落地。

## Context

### 1. 为什么是现在

`G-2d`（`P4-γ` 子批）**开工前勘测**发现：语言面从未定义「泛型枚举用例的**显式类型实参**挂在哪」。
触发点 = 待转绿的差分夹具用裸名形态 `ok<I32, String>(42)`，而该形态在语言参考里**无对应表述**——
语言参考只定义了泛型枚举的**声明**（`[可选<T>] 有(T,) 无`）与非泛型枚举的**构造**。

⇒ 若直接进实现（`S1`），即「**实现即规范**」。本项目已因该形态栽过一次
（见 `ADR-023` 的流程越界记录：具名关联值当初是「实现先于 spec 修订、事后追认」）⇒
本批**先登记、后实现**。

### 2. 现状实测（2026-09-16）

**① 文法已覆盖，语义未定义**：

```
primary-atom     ::= IDENT [generic-construct]
generic-construct ::= '<' type-annotation {',' type-annotation} '>' ('(' … ')' | '.')
```

两条产生式合计**已允许** `枚举名<实参…>.用例(载荷…)`；消歧规则 3.3 亦把「`>` 后跟 `(` / `.`」
判为泛型构造（否则回退为比较）。⇒ **本 ADR 不改文法，只钉语义。**

**② 三种候选拼写的解析代价**（读码实测；用户裁决取第一种）：

| 拼写 | 解析产出 | 是否需改解析器 |
|---|---|---|
| `枚举名<实参…>.用例(载荷…)` | 成员访问挂在**无参** `genericConstruct` 上 | ❌ 产生式与消歧规则已覆盖 |
| `枚举名.用例<实参…>(载荷…)` | 需「成员名带类型实参」 | ✅ 需扩产生式 |
| `.用例<实参…>(载荷…)` | `.` `IDENT` 节点的变体**只带名字** | ✅ 需扩节点字段 + 改全部消费点 |

**③ 两层实现现状**：

- **类型层已具备解析能力**：泛型枚举模板注册与按实参替换载荷类型（`defineGenericEnum` /
  `genericEnumParamCount` / `lookupSpecializedEnumCase`），且 `TypeChecker` 在**构造点**与
  **match 绑定**两处**已在调用**；
- **降载层未实现**：泛型构造分派只认三条路——内建 `LazyRef`、泛型**函数**模板、泛型**结构体**特化
  ⇒ 枚举名走不到任何一路。这是 `G-2d` 的 `S1` 对象。

### 3. 影响面与破坏性

| 项 | 值 |
|---|---|
| 受影响的构造 | 泛型枚举用例构造（带载荷与零载荷用例） |
| 稳定性级别 | **Experimental**（沿枚举与「泛型运行时单态化」的现状——后者在规范里正是 Experimental 的范例） |
| 是否破坏性 | **否**：裸名形态维持既有解析规则（`ADR-026` D1 三档），既有程序零影响 |

## Decision

### D1 两种形态与它们的等价关系

- **限定形态（为准）**：`枚举名<实参…>.用例(载荷…)`
  - 父枚举与类型实参**均由书写给出**，不依赖任何推断；
  - 类型实参个数 = 该枚举声明的泛型形参个数 ⇒ **可在类型层静态校验**
    （类型层已有按**枚举名**的实参个数校验）。
- **裸名形态（为糖）**：`用例<实参…>(载荷…)`
  - **定义性等价**：先按 `ADR-026` D1 三档解析出父枚举（期望类型命中 → 模块唯一 → 歧义则报错
    要求改写为限定形态），再用该枚举的泛型形参**逐位绑定**实参；此后与限定形态**同一语义**。
  - ⚠️ **已知代价（显式登记）**：该形态下**实参个数校验落在运行期**——类型层现有校验按**枚举名**查，
    而此形态给出的是**用例名** ⇒ 校验不触发。这是「为准 vs 为糖」的真实差别，不是遗漏。

### D2 稳定性与递交

- 定级 **Experimental**。
- **本轮不递交语言参考**，两条**独立**理由（任一成立即不可递交）：
  1. 递交流程的条件之一是「该构造已定级 **Provisional 或 Stable**」（**Experimental 不递交**）；
  2. 另一条件是「**实现侧有证据**」——而实现发生在 `S1`，本批只有登记。

### D3 明确不在本 ADR 范围

- 不带类型实参的限定形态（`枚举名.用例(载荷…)`）与其实参推断规则；
- 非泛型枚举的构造形态（既有规则不变）；
- `match` 模式位的限定 / 点号形态；
- 内建 `Optional` / `Result` 的构造（走各自既有通道）。

## 后果

- **文法零改动、契约节点计数零改动**；本批新增的是一处**语义注记**（§A）与一条**台账行**（§3 `G59`）。
- **`S1` 的落点被收窄**：只需在降载层补三站（用例名→父枚举 · 产出特化枚举体 · 注册进两张表），
  **不改解析器**。
- **代价记账**：裸名形态的实参个数校验留在运行期。该代价**不是阻塞项**（裸名形态本就是糖），
  待该形态被收窄或校验下沉时再裁。
- **等待链**：本构造的语言面递交要等 `S1` 交付 **且** 定级升至 Provisional，或用户另行裁决。
- **与既有 ADR 的关系**：**不撤销** `ADR-026`（D1 三档解析规则继续有效，本 ADR 只是给它挂上
  「类型实参从哪来」）；**不撤销** `ADR-023`（具名关联值决议不变）。
