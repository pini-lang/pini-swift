# Pini 自举扩张评估（Feature Expansion Assessment）

> **本件是什么**：以**自举仓为视角**，把「特性索引里自举尚未实现的特性」逐簇评估成一句话 ——
> **要实现它，自举 MVP 必须先扩张什么**。
>
> **与特性索引的分工**：`pini-feature-index-v0.md` 回答「**有哪些**特性」（名录）；
> 本件回答「**要补它得先长什么**」（依赖与动作）。两者同属派生视图、同低权威。
>
> ⛔ **本件不是权威**：特性是否存在、语义为何，以参考件为准；路线与销账以规划件为准。
> ⛔ **本件不是施工图**：粒度到「簇」，不列节点级改动。
> ⛔ **本件不代裁**：§7 的待裁项须另行点名。
>
> **本件的实测只到解析层 / 面册层**：凡写「实测」处，指该结论由可复跑的探针或册给出；
> 凡写「推定」处，指尚未实测。两者在文中分别标记，⛔ 不可混读。

## 0. 三分钟读法

### 0.1 ⭐ 右端口径：**不是宿主**

用户 2026-10-04 的提示纠正了此前的一个默认假设：**宿主的 Swift 实现并不等于参考件的实现**。
本批实测给出了三处硬证据（§1），其中三项是**参考件有明文、而两侧前端都不接受**的构造
（`if let` · 单返回糖 · 默认参数）。

⇒ 因此本件按以下口径定右端：

| 用途 | 右端 |
|---|---|
| **「这个特性存在吗、语义是什么」** | **参考件**（唯一权威） |
| **「这个特性在自举侧补上了吗」** | **契约件 / 面册**（可机械对账） |
| **「这个特性补对了没有」** | 宿主**仅当宿主自己也实现时**才可作逐字节右端；⚠️ 宿主未实现的项**无右端**（§6） |

⚠️ **推论**：自举侧的待补集合**不等于**「参考件 − 宿主」——
它是「参考件 − 自举」，而**其中一部分宿主也缺**。那部分是「无右端项」，风险最高（§6）。

### 0.2 ⭐ 两把尺子：特性扩张 ⇄ 能力扩张

「补一个特性」在自举侧从来不是单点动作。实测出的分层模型是 **5–6 处**：

```
契约 → 承载(ir.pini) → 降载(lower.pini) → 发射(emit-ir.pini) → 执行腿(interpreter) → 运行时段(bk_*)
```

而**比这更前置**的是第二把尺子 —— **能力扩张**：自举编译器自身在降载期的
**类型/名字解析能力**。它是当前**近端最大堵点**，且它不是参考件里的任何一条特性（见本件 2.0 节）。

### 0.3 量级档（口径写死，便于复核）

| 档 | 判据 |
|---|---|
| **小** | 动 **1–2 处**，无新机制，无前置 |
| **中** | 动 **3 处**，或有前置但前置已具备 |
| **大** | 动 **4 处**且需**新承载族**（3+ 节点），或需**新机制**但机制面窄 |
| **特大** | 动 **5–6 处**且需**族级新机制**（分析 / 胶水 / 状态机），或带**硬前置**（§4） |

⛔ 档位是**动作面**的度量，**不是工期**。本件一律不换算工期。

## 1. 实测：前端覆盖对照（宿主 ⇄ 自举）

**探针**：46 份最小语料，每份两侧各跑一次（宿主 `pini parse` · 自举 `pini run . parser-decl`）。
**判据**：宿主以退出码；自举以输出里有无 `parseError:` 行。

### 1.1 两侧一致 · **都通过**（自举前端已覆盖）

| 构造 | 出处 |
|---|---|
| 数组类型 `[T]` / 数组字面量 / 下标读 | §3.7 · §5.8 · §5.6 |
| 字典类型 `[K:V]` / 字典字面量 / 字典下标 | §3.7 · §5.8 |
| 集合类型 `{T}` / 集合字面量 | §3.7 · §5.8 |
| 可选类型 `?T` / `nil` / `.some(42)` / `p!` | §3.8 |
| Result 类型 `^T` / `.ok` / `.err` | §3.9 · §11.1 |
| 函数字面量（带括号返回）/ 闭包 `capture` | §5.9 |
| 泛型结构 `(盒<T>)` / 泛型函数调用 `f<I32>(…)` | §3.11 · §4.3 |
| 下标 `a.get(i)` / `unsafe a.getUnchecked(i)` / 切片 `a[i:j]` / 负索引 | §5.6 |
| 复合赋值 `+=` / 逻辑 `&&` / 位 `&` | §5.3 · §6.2 |
| `defer` / `pass` | §6.5 · §6.7 |
| 控制流标签 `标签\|for` | §6.3 |
| 元组类型与解构 | §3.6 · §5.7 |
| object 声明 `{计数器}` | §4.4 |
| 扩展块 `((点))` + 方法（带括号返回） | §4.7 |
| 指针类型 `*T` / 取地址 `&a` | §3.2 · §9.1 |
| 字符串插值 `"…\(x)…"` | §2.8 · §5.1 |
| 标签实参 `f(名 = 值)` | §5.4 |
| 异步函数 `=> …` / `await` / `detach` | §5.11 · §8.2 |
| IIFE `(func …)(42)` | §5.4 |

⭐ **这一列本身就是一条结论**：自举前端**已经能解析**上表全部构造 ——
包括那些**承载侧划出**的（可选 / Result / 闭包 / 泛型 / object / 指针 / 下标 / 切片 / 元组）。
⇒ **「前端缺」与「IRC/发射缺」是两件事，⛔ 别把后者的工作量算到前者头上。**

### 1.2 两侧一致 · **都拒绝** ⇒ ⚠️ 参考件有明文、两侧都没实现

| 构造 | 出处 | 两侧报错（逐字相同） |
|---|---|---|
| `if let 值 = 可选值:` | §3.8 | `invalid expression: 无效的表达式`（都在 `let` 处） |
| 单返回糖 `-> I32` | §3.10 · §4.8 | `expected (, got I32` |
| 默认参数 `b: I32 = 2,` | §4.8 | `expected ), got =` / `expected a name` |

⭐⭐ **这是本批最重要的发现**：这三项**参考件都写了**，而**两侧前端共用同一套文法规则、
且那套规则都不含它们** ⇒ 它们是**实现落后于参考件**的实例，不是「自举没用到的功能」。

### 1.3 两侧不一致 ⇒ ⭐ 自举前端的**真缺口**

| 构造 | 出处 | 宿主 | 自举 |
|---|---|---|---|
| `try 表达式 else err: 控制流语句`（语句位 / 表达式位） | §5.10 · §6.4 · §11.2 | ✅ 过 | ❌ `parseError: invalid expression` |

⚠️ 注意 `try` 是**唯一**的「宿主有而自举无」项。⇒ 自举前端与宿主的差距**只有这一格**。

### 1.4 一处「参考件写法与实现偏离」

| 项 | 参考件写法 | 两侧实测 |
|---|---|---|
| 集合类型 | `{T,}`（带尾逗号） | `{T}` 过、`{T,}` **两侧都拒** |

## 2. 自举未实现特性的**总账**（按性质分两类）

### 2.0 ⭐ 第一类：**能力缺口**（不是任何一条 reference 特性）

| 项 | 自举现状（实测读数） | 说明 |
|---|---|---|
| **降载期的类型/名字解析** | 融合式腿**整包面** 14 个 skip 面 / 2,688 条中，`typeName` **1706** · `expr` 298 · `fieldStoreReceiver` **246** · `member` 130 · `inferType` **113** · `memberReceiver` 96 · `inferMember` **24** | 大头全落在「**这个名字/表达式是什么类型**」上 |
| **语义** | 自举源码里 `for (x,) in a:`（迭代物是**变量**）不支持，因为该变量的类型落回 `irI32`（降载侧不认 `argv()` / `split()` 的返回类型） | 已登记在册 |
| **前端** | 46 项实测：自举前端与宿主差距**仅 `try` 一格** | 见 §1 |

⭐⭐ **这一条决定了整个评估的重心**：自举仓当前最大的堵点**不是**「缺某个语言特性」，
而是「**降载侧答不出类型与名字**」。⇒ 特性补得再多，若这条不补，
**它们在自举源码量级上仍然跑不出产物**（14 面不会因为补了「字典」而变绿）。

### 2.1 第二类：**特性缺口**（参考件里有、自举承载/降载/发射未做）

逐簇见 §3。

## 4. ⭐ 扩张的**依赖序**（哪些是前置）

实测与承载形状给出的硬依赖（⛔ 不能任意顺序补）：

```
                    ┌─────────────────────────────┐
   值语义基础（已有：构造 / 字段读写 / 释放胶水 / 拷贝胶水）
                    └──────────────┬──────────────┘
                                   │
        ┌──────────────────────────┼──────────────────────────┐
        ▼                          ▼                          ▼
   AC 降载期类型解析          Q 泛型/单态化              V 闭包/函数值
        │                          │                          │
        │                          ▼                          │
        │                    R 容器（字典/集合）               │
        │                          │                          │
        │                          ▼                          │
        │                    Y COW（需 R + W）                │
        │                          ▲                          │
        ▼                          │                          ▼
   （所有簇的公共前置）        W object/ARC ────────────►  X 弱/无主/惰性引用
                                   │
                                   ▼
                             Z 并发（需 V 的续体）
```

**三条读法**：

1. **AC 是公共前置**：它不是特性，但**所有特性在自举源码量级上跑通**都要它。
2. **Q（泛型）是容器的前置**：字典/集合是泛型容器 ⇒ 先有单态化才谈得上容器。
3. **W（引用语义）是 COW / 弱引用 / 惰性引用 / 并发任务树的前置**。

## 5. 两个目标的**分界**（渐进替代宿主的路径）

| | **目标 A · 自举链闭合** | **目标 B · 特征追平参考件** |
|---|---|---|
| 判据 | 自举源码能被自举发射的 `.ll` 编出 | 参考件里「进产物」的特性都能编 |
| 必需 | 近端缺口（插值 · `arrayLiteral` · `subscriptStore`）+ **AC** | A ＋ §3 全部簇 |
| 是否需 AG（运行时自举） | **不需要** | **不需要**（AG 属「零宿主」第三目标） |
| 是否需 AE/AF（驱动面） | **不需要** | 不需要（正交） |
| 现状 | 未达成（面册 14 面未清） | 未达成 |

⚠️⭐ **与规划件口径一致**：规划件把 A 定为**验收位**是刻意的；B 不在 MVP 定义里。
⇒ 「补特性」与「自举达成」是**两条轴**，⛔ 别把 B 的进度算成 A 的进度。

## 6. ⚠️ 无右端项（宿主与参考件也不一致的项）

**风险形态**：这些项**没有可用的逐字节右端** —— 自举侧补上后，判据只能靠
「契约一致性 + 行为自洽」，**不能用「与宿主逐字相同」**。

| 项 | 为何无右端 |
|---|---|
| `if let` | 两侧都拒（§1.2） |
| 单返回糖 | 两侧都拒（§1.2） |
| 默认参数 | 两侧都拒（§1.2） |
| 引用件写法的 `{T,}` | 两侧都拒（§1.4） —— ⚠️ 须先裁「改参考件还是补实现」 |
| FFI 面 | 宿主 §12.3 显式 unsupported |
| `.get` / `.getUnchecked` | 宿主 §12.3 登记未实现（⚠️ 实测**前端能解析**，缺口在承载） |
| 跨模块 IR 后端 | 宿主不支持（⚠️ 自举侧**已越过**：整包面已跑通） |

## 8. 边界

- ⛔ **本件不是权威 · 不是施工图 · 不代裁**（同本件 0.1 节口径）。
- ⛔ **本件不记会漂的读数**：凡出现条数处均标明来源与日期，且**以来源件为准**。
- ⚠️ **本件的实测边界**：§1 是**解析层**实测（可复跑）；§3 的「自举现状」来自面册与件头自陈；
  §3 的「需先扩张什么」是**分层的推定**（依据 = 该簇在宿主侧的实现位置），⛔ 不是逐条实测。
- ⚠️ **维护纪律**：本件随「簇」演进 —— 某簇落地后**同批**把该行改为「已交付」并从 §3 移除；
  参考件新增特性时，特性索引跟行，本件**同批判定它属哪个簇**。
