# IR 节点语义契约

- 性质：**宿主级规范**。IR 节点语义的**唯一权威载体**。
- 适用范围：所有消费 `IRModule` 的执行通道（解释器、LLVM，以及将来的任何后端）。
  **任一后端都不是定义处。**
- 变更：条目一经落地不得随实现漂移。新增或修改节点语义先改本件，再改代码。

## 0. 定位与判读规则

### 0.1 权威次序

1. **语言面语义**（用户可见行为）以 `pini-reference-v0.md` 为准 —— 本契约不得与之冲突；
2. **IR 节点语义**（后端间的契约）以**本契约**为准；
3. 各后端实现与本契约一致 —— 其中包括第 5 节列出的五条义务与第 7 节的资源归属约定。

### 0.2 表述纪律

- **语义列只写后端无关的行为约定**。不得出现 `bk_*`、`alloca`、`fgets`、GEP、
  引用计数布局、fat pointer 形状这类实现细节。
- 实现细节只出现在「注记」列，其地位是**一种实现**，不是语义。
- 禁止以某个运行时段的行为定义语义 —— 那等于把一条通道的实现选择升格为全体后端的义务。

> 反例（立此存照）：`fileRead` 的早期注释写「读进 64 KiB 栈缓冲」，把缓冲尺寸写成了节点语义；
> 那个数后来真的成了两侧共用的上限，并静默丢弃越限部分。一条把实现选择写成语义的注释，
> 是那条上限的源头。

### 0.3 三方对照核验

```
本契约条目  ↔  IRNode.swift 的节点集  ↔  各后端实现锚点
```

核验须能双向报缺口：**有节点无契约条目** / **有契约条目无实现锚点**。
器械是 `tools/ir-contract-check.py`，它同时检查条目编号是否为无缺口的一段连续整数。

### 0.4 计数基线

**55 个表达式节点 + 17 个语句节点 = 72**。表内编号即条目号，与节点数严格相等。
语句位的两个指针（`tryStmt`、`matchStmt`）不占表达式编号。

## 1. 类型层（IRType，23 case）

| 类型 | 语义（后端无关） | 实现注记 |
|---|---|---|
| `i32` / `i64` | 32 / 64 位有符号整数 | 原生标量 |
| `u64` / `u8` | 64 / 8 位无符号整数 | 与 `i64` / `i8` 同拼写，符号性由运算承载 |
| `i8` | 8 位有符号整数 | 算术在发射期拓宽到 `i32` |
| `f64` | 64 位 IEEE-754 浮点 | 原生双精度 |
| `boolean` | 布尔 | 一位或一字节，由后端定 |
| `string` | 字节串值 | 指针 |
| `char` | **一个字素簇**（用户感知的「一个字符」），不是码点、不是字节；表示与 `string` 同构，「恰含一个字素」由类型系统承担 | 与 `string` 同拼写，零新 ABI |
| `result(ok:)` | `Result<ok, E>`；**错误槽类型擦除** | 三槽 `{ tag, ok, err }`，槽序是布局约定 |
| `future(ok:)` | `Future<ok, E>`：运行中的任务句柄。与 `result` 不可互换 —— 后者是已结算的值，本条是未结算的句柄。**一次等待、结果恰一次**是语义 | 不透明句柄 |
| `array(element:)` | 有序、可重复、值语义集合 | 不透明句柄（`bk_array_*` 族） |
| `optional(wrapped:)` | 有 / 无二态容器 | 带 tag 的按值聚合；tag 0 = some、1 = none 是布局约定 |
| `nominal(name:isObject:)` | 用户具名类型。`isObject=true` 为引用语义；`false` 为值语义，四个存储点即时深拷贝（见 1.1） | 头四格之后是字段；值类型与对象同形 |
| `enumeration(name:)` | 用户枚举（带关联值的 tagged union），引用语义 | 头四格之后是用例标签，载荷按最大元数定型 |
| `dict(key:value:)` | 键到值的映射，键唯一 | 不透明句柄（`bk_dict_*` 族） |
| `set(element:)` | 唯一元素集合 | 不透明句柄（`bk_set_*` 族） |
| `lazyRef(element:)` | 一次求值、引用拷贝语义的惰性引用 | 不透明句柄（`bk_lazyref_*` 族） |
| `tuple(labels:fieldTypes:)` | 带位置与可选标签的异质定长组 | 按值聚合；标签序即字段序 |
| `function(params:returnType:usingIndices:)` | 函数是一等值；取用下标集合标出哪些参数位由给定块填。类型标注写不出它，它也不参与类型等价 —— 但随函数值保留，标注不得把它抹掉 | fat pointer `{code, env}`；首参恒为 env 是调用协议；取用位不进运行时表示 |
| `pointer(element:)` | `*T` 原始指针（FFI） | 不透明指针；load / store 按元素类型解码 |
| `cFunction(params:returnType:)` | C 函数指针：可交给 C 调用的一个地址。与 `function` 不可互换 —— 后者是 `{code, env}`，调用先传 env | 裸指针；不参与 Pini 的计数与取用位 |
| `stringHandle` | C 边界上的字符串句柄：一份运行时段持有的拷贝。不是字节地址，也不能当计数串用 —— 计数归 C 侧那一份 | 不透明指针；创建即复制，读写只经运行时段入口 |

> 注意 **布局约定与语义的分界**：标「布局约定」者为后端可选表示；标「语义」者为必须实现的行为。

### 1.1 名义值类型的值语义：绑定即即时深拷贝

`isObject=false` 的结构体在**四个存储点**取**即时深拷贝**（不是写时复制）：

| 点 | 形态 | 规则 |
|---|---|---|
| 绑定 | `var b = a` | 新箱 + 递归拷贝 |
| 赋值 | `d = c` | 同上；顺序是先让新值站住，再释放旧值，最后写槽 |
| 字段存 | `h.p = expr` | 同上，顺序同赋值 |
| 返回 | `return 局部` | 拷贝交出，原局部随作用域释放 |

递归规则：结构体字段递归拷贝；对象与枚举字段原样共享并留一份份额；容器字段共享，
写时复制由容器自己管；标量与字符串直接复制。

注意 **形参是共享**（被调方改形参、调用方看得见）—— 这是已裁定的可观察行为，与「绑定即拷贝」
并存：拷贝只发生在上表四处，不在形参入口。也正因它是可观察行为，写时复制被排除。

## 3. 语句节点（17 条）

| # | 节点 | 语义 | 注记 |
|---|---|---|---|
| 1 | `allocVar(name:type:mutable:initializer:adopt:)` | 声明变量槽；有初值则在分配后立即存入，`adopt` 是初值的接收动作 | 可变性是语言约束，不靠后端 |
| 2 | `storeVar(name:type:value:adopt:releaseOld:)` | 向既有变量写值；`releaseOld` 说槽里旧值要不要还 | — |
| 3 | `ifStmt(label:condition:thenBody:elseBody:)` | 条件分支。`label` 非空时本节点是可中断帧，`break` 可定向到它 | 条件为布尔；`label` 运行时不读，只有解析好的深度随信号走；`if` 帧不是 `continue` 目标 |
| 4 | `whileStmt(condition:body:step:)` | `while` 循环；`step` 块每轮体后执行一次 —— 正常完成与无标签 `continue` 时均执行，`break` 跳过 | 带标签且深度大于 1 的 `continue` 跳到循环头，该臂不执行 `step`，属已知偏离 |
| 5 | `forInStmt(pattern:elementTypes:kind:iterable:body:step:)` | `for` 遍历；`kind` 决定元素读取方式；`_` 占位仍占槽位并带类型 | 同一处偏离在此更重：深度大于 1 的 `continue` 跳过索引自增 |
| 6 | `returnStmt(value:adopt:)` | 返回值；`nil` 表示空返回；`adopt` 是返回值的接收动作 | — |
| 7 | `exprStmt(IRExpr)` | 表达式求值并丢弃结果 | — |
| 8 | `deferStmt(body:)` | 语句块离开作用域时按 LIFO 执行，含每轮循环结束 | 与局部释放共栈，次序见 7.4；与 `break` / `return` 的交互尚无门控面 |
| 9 | `tryStmt(operand:errorVar:handler:okTarget:type:)` | `try e else err: ...`；操作数为 `result(ok:)`；错误路径把类型擦除的错误字绑定到 `errorVar` 并运行 handler；表达式位把 ok 载荷存入 `okTarget` | `okTarget` 为 `nil` 表示语句位 |
| 10 | `subscriptStore(container:index:value:elementType:adopt:)` | 下标写 `c[i] = v`；可嵌套；复合赋值降级为读改写 | 越界写报错，不得经赋值扩容 |
| 11 | `breakStmt(depth:)` | 跳出第 `depth` 个可中断帧；帧 = 循环 + 带标签的 `if` | 目标不可解析时降级为 `panicStmt`，fail-loud |
| 12 | `continueStmt(depth:)` | 继续第 `depth` 个帧 | 目标只能是循环帧，不能是 `if` 帧 |
| 13 | `panicStmt(message:)` | 无条件运行时陷阱，固定消息，块终止 | 用于解释器仅在运行时才发现的逃逸 |
| 14 | `matchStmt(scrutinee:cases:scrutineeType:)` | `match` 分派；可分派于枚举、Optional 与裸值字面量 | 枚举 / Optional 未匹配即 panic；裸值字面量未匹配且无通配时静默落到 match 之后 |
| 15 | `fieldStore(base:field:value:fieldType:adopt:releaseOld:)` | 具名字段写；字段是持有者，`releaseOld` 管旧值 | 对象需越过引用头 |
| 16 | `captureMarker(name:)` | 闭包体内的 `capture` 标记；捕获在闭包创建点解析，本节点降级为无操作 | 存在意义是让该语句种类在闭包体内被接受 |
| 17 | `detachStmt(inner:)` | 求值操作数（须为 `Future`），把它从父任务剪枝，父返回时不再取消它 | 剪枝在各后端都没有可观测的输出差异，判据只能是结构级 |

## 4. 待办与已知偏离

| 项 | 状态 | 类型 |
|---|---|---|
| `whileStmt` / `forInStmt` 的深层 `continue` 跳过 `step` | 未修 | 偏离，后端与解释器相反 |
| `addressOfVar` 的解释器快照语义 | 未修 | 偏离，已裁「统一到真引用」 |
| `deferStmt` 与 `break` / `return` 的交互 | 未门控 | 覆盖缺口 |
| `pointerLoad` 窄元素的扩展规则 | 未裁 | 半语义，须上提为语义或标为约定 |
| `optionalGet` 的边界检查方式 | 未裁 | 半语义，同上 |
| `readLine` 的 256 字节上限 | 已裁保留 | 语言级尺寸语义，`IOLimits` 为单一源 |
| 警告通道的跨通道一致性 | 缺口 | 诊断面 |
| 闭包环境与捕获槽不释放 | 未修 | 缺口：逃逸闭包持有捕获，但闭包值无销毁路径，捕获值的 `deinit` 不触发 |
| `LazyRef` 句柄不释放 | 已修 | 保留走通用句柄入口，释放走 `bk_lazyref_destroy`；别名点与退出两侧成对 |
| 异步析构与同步清理的相对次序 | 未裁 | 半语义：参考 7.7 只定调度点，未定它与清理栈的先后 |

## 5. 后端义务

本节不新增节点、不改任何一条节点语义，计数基线因此不变。它约束的是**读者**：凡把 `IRModule` 翻成
目标表示的通道都受下面五条约束。解释器是执行型通道，不产出目标表示 ——「布局归位」与「资源归位」
对它没有对象，其余三条照办。

五条一律以否定式书写：说清后端**不得**自行决定什么，不说它该怎么做。换目标表示、换实现语言，
五条一字不改。判据全部落在后端源码的形状上，不落在 IR 上 —— 所以删掉本节不改变任何产物。

节点表说「每个节点是什么意思」，本节说「后端不得越过哪些线」。前者讲内容，后者讲读法，两者不重叠。

### 5.1 类型定型

降载之后类型已经定型，节点上写的类型就是它要翻译的类型。后端不得从值的形状、用法或上下文再推一次，
也不得在推不出时回落到默认类型。

需要新的类型信息就改本节与降载，不在后端补推。后端每多一处推导，就多一处与另一条通道分叉的机会；
这类分叉不报错，只让同一个程序在两条通道上得到不同结果。

注意 判定看源码形状：后端里出现「依值的运行形状决定类型」的分支即为违反，无须等它出错。

### 5.2 布局归位

布局是 IR 携带的事实，不是后端的推导结果。值占多大、字段落在哪、带标签的值怎么区分，后端只读不算。

后端若为某类值另算一套布局，它与另一条通道的字节视图就会分叉。后果不是编译错误，而是同一程序在
两侧读写到不同位置；这类缺陷只在特定数据下显形，且极难归因。

注意 判定看源码形状：后端出现偏移、槽数、对齐的字面量或计算即为违反。

### 5.3 资源归位

这里管的是份额的接手与归还：值的存活与释放由 IR 里已写明的动作决定（见第 7 节）。后端只翻译这些
动作，不得自行决定「这里该复制」「这里该释放」「这一次可以省掉」。

后端自己合成资源动作，等于把生命周期规则写了两遍。两遍之间没有仲裁者：一致时无人知道，不一致时
也没有判据，只能等某次崩溃或泄漏来指出哪一遍错了。

注意 判定看源码形状：后端存在「按节点自行插入资源动作」的路径即为违反。

### 5.4 单层 IR

中端只在同一套 IR 上做 IR→IR 改写。后端不得要求一个「更适合自己」的中间表示，也不得在内部另立一套
与 IR 平行的节点体系。

新增能力走节点与本节，不走旁路。旁路一开就会长成第二份节点表，而第二份表不受计数基线检查 ——
它漂移的那天，没有任何一道门禁会响。

### 5.5 清单唯一

内建的名字与签名只有一份清单。实现可以有多份 —— 执行一份、运行时段一份 —— 但「有哪些内建、签名是
什么」必须同源。

后端不得私藏清单，也不得接受清单之外的名字。多一份清单就多一处漂移点，其形态是「某通道认一个别的
通道不认的名字」，用户看到的是跨通道不一致，而任何一侧都不会报错。

五条的共同点只有一句：**每一条都在阻止同一件事被决定两次。** 两次决定之间没有仲裁者，漂移就发生在
没人看的地方。

### 5.6 通道接入

一个通道接进 CLI 只付两笔：实现 `PiniBackend`（名字 · 能力声明 · 一个产出入口），在注册表里加
一行。除此之外不改既有文件 —— 若某通道需要动别处，说明接缝漏了一种需求，补在接缝上，不在那一条
通道里打补丁。

能力声明按**节点族**给，不按节点逐个给。族名与第 2 节的十三个小节同名，另加「控制流」一档收语句
节点。逐个节点表态会变成第二份节点表，而第二份表不受计数基线检查 —— 它漂移的那天没有门禁会响。

注意 声明「支持」不等于「产目标码」。一个只做结构转储的通道可以对全部族表态支持：它证明节点集
被完整消费，只是选择不产出可执行表示。产出档次单列，不与能力混为一谈。

### 5.7 内建清单

后端调用运行时段，只经一份清单登记：符号名 · 签名 · 族 · 降级点。符号名与签名各写一次 ——
调用点按名取声明，不在两处各抄一遍。签名属目标表示，故清单随后端放，不进本契约。

注意 清单是**编译器能力**的边界，不是运行时符号面的副本：运行时导出全集由运行时契约持有，
编译器只登记它能发出的部分，其余在该契约的零调用点表里逐条说明。两侧互补，不得有第三种状态。

### 5.8 结构不变量

节点表说每个节点是什么，5.1 至 5.7 说后端不得越过哪些线；本节说这些线由谁持守。

`IRValidator` 是唯一持守处：它在任何后端读取 `IRModule` 之前走一遍整棵树，把「后端假定成立、
IR 自己从未检查过」的事实逐条核出，以 `E6-011` 报告并附源码位置。后端的 `fatalError` 由此退为
兜底 —— 它不该再被触发，触发即说明验证器漏了一条规则。

新增节点、或改动既有节点的形状时，同一笔改动里补一条规则。只加节点不补规则，等于把那条不变量
重新交回给记忆，而记忆没有门禁。判据分两面：语料巡检（`examples/` 全量降载零违约）证明真程序
不被误伤，每条规则的阴性夹具证明它真的会响。只有前一面时，把规则全删掉也是绿的。

注意 判定看源码形状：后端里出现「假定某个 IR 事实成立」的分支，而验证器没有对应规则，即为缺口。

## 6. 布局约定

本节承载**布局事实**：值由几个槽组成、每个槽放什么。它不属节点语义，故单列一节 —— 写进节点语义列
会把实现选择升格为语义（前例见 0.2 的反例）。

槽是布局的单位，不是字节。每槽取多宽、怎么对齐、聚合叫什么名字，都属目标表示，由后端决定；
本节只说「有几个槽、第几个槽放什么」。后端可以选自己的表示，但不得另算槽位。

注意 本节不新增节点，计数基线不变。

| 事实 | 约定 |
|---|---|
| 名义箱头 | 四槽，依次为强计数 · 弱计数 · 类型标识 · 弱引用旁表 |
| 名义字段 | 第 i 个字段（按声明序，从 0 起）落在第 4 + i 槽 |
| 枚举 | 用例标签在第 4 槽；载荷从第 5 槽起，按该用例关联值的声明序 |
| `Result` | 三槽：标签 · ok 载荷 · 错误字 |
| `Optional` | 两槽：标签 · 载荷 |

三族名义箱（结构体 · 对象 · 枚举）共用一个头，故字段与标签的槽位基准只有一个数；改头只改这一处，
否则三族会各自漂移，而漂移的形态是「某个字段读到别处」，不是崩溃。

注意 **逐类型的字节尺寸不属本节**。它是目标表示，后端用自己知道的方式算（LLVM 后端取类型的 sizeof），
搬进 IR 就等于让 IR 认识目标机器。

## 7. 资源归属与归还（RAII）

本节承载**资源事实**：谁握有一份份额、何时移交、退出时按什么次序归还 —— 即 RAII 的归还面，
每份申请有唯一责任方，责任方在确定的位置交还。与第 6 节同规，它不属节点语义，故单列。
第 5.3 节说后端**不得**自行决定；本节说 IR **携带**什么，两者不重叠。

注意 下文只用两个词：**份额**是一份计数的单位，**持有**是某个位置对它的归还责任。与 Rust 无关 ——
没有所有权类型、没有借用标注、没有生命周期参数，编译器也不据此拒绝任何程序。参考 1.1 的核心前提
仍是「无所有权、无借用」：7.1 的三态只在编译器内部使用，不出现在源程序里，也不构成检查 —— 今天能
编过的程序，带上这些动作之后仍能编过。

本节不新增节点，计数基线不变。第 2、3 节的签名在资源动作落到节点上时同批更新。

### 7.1 状态

一个值在任一程序点处于三态之一：

| 状态 | 含义 | 落进存储点前 |
|---|---|---|
| 持有 | 当前求值握有一份份额 | 直接移交 |
| 借用 | 不握份额，只保证使用期间有效 | 先拷贝或保留 |
| 别名 | 别处已握一份，本处是第二持有者 | 先拷贝或保留 |

### 7.2 动作

| 动作 | 语义 | 典型位置 |
|---|---|---|
| 移交 | 份额从来源转给目标，来源不再负责 | 临时值落进存储点、容器唯一化写回 |
| 拷贝 | 值语义深拷贝，产生独立的一份 | 结构体别名落进存储点 |
| 保留 | 计数族加一份，来源仍负责 | 对象 / 枚举 / 容器 / 字符串别名落进存储点 |
| 释放 | 计数族减一份，归零即触发 `deinit` | 覆盖、作用域退出、临时值用完 |

注意 动作由中端决定，后端只翻译。后端不得因为「这里看起来可以省」而删掉一次保留或释放。

### 7.3 存储位 · 消费位 · 求值效果

一个值只能落在三类位置之一，三类穷尽。

| 位置 | 有哪些 | 接收方做什么 |
|---|---|---|
| 存储位 | 声明变量 · 赋值 · 字段写 · 下标写 · 返回 · 容器元素 | 按 7.2 的四种动作之一接收 |
| 消费位 | 调用实参 · 打印实参 · 拼接操作数 · 内建的操作数 | 借用：求值方在读完它之后归还 |
| 观测位 | 条件 · 迭代源 · 被匹配值 | 借用：求值方在用完之后归还 |

注意 「穷尽」是这条约定的全部力量：每个产值节点都必然落进其中一类，没有第四类去处。
补一类位置必须同时说明它的接收动作，否则新位置上的临时值就地泄漏。

拼接的自赋值（`s = s + x`）是消费位的一个变体：左操作数就是即将被覆盖的那个槽，故它按**持有**而非
借用处理 —— 中端照旧标「释放旧值」，后端把这次归还敛进拼接内核（就地追加则引用转移，否则复制后释放）。
份额数目不变，换的只是执行者；把这次归并当成「可以省一次释放」而删掉，旧串就永远留着。

接收动作由**求值效果**决定，不另设第二套判据：

| 效果 | 含义 | 落进存储位 |
|---|---|---|
| 新份额 | 本次求值造出一份 | 移交 |
| 借用 | 份额在别处，只保证使用期间有效 | 拷贝（值语义）或保留（计数族） |
| 不参与 | 标量 · 外部指针 · 整块聚合 | 无 |

`call` 与 `indirectCall` 的返回按**新份额**：`return` 的接收动作已在被调方安排好 —— 交临时值即
移交，交别名先保留 —— 故调用方接手的一定是干净的一份。判不准时按借用，因为漏一份是保守方向。

### 7.4 清理栈

同一作用域内，`defer` 体与局部值的释放**共用一条清理栈**：按登记顺序入栈，退出时逆序执行。

注意 这不是「所有 `defer` 先于所有释放」。`defer` 只能引用它之前声明的局部值，那些值在它之前
登记、故在它之后释放；`defer` 之后声明的局部值在它之前释放。次序是语言事实，不是实现选择。

`deinit` 在释放使计数归零时触发（`pini-reference-v0.md` 7.7），因此清理栈的次序就是 `deinit`
的可观察次序。异步析构由结构化作用域退出调度，不在本节定义其次序。

### 7.5 容器唯一化

容器的唯一化动作**消费**当前句柄、产出新句柄：原句柄的那份份额转给新句柄，写回存储点是移交，
不得再插一次释放。唯一化本身由运行时完成；本节只约定份额的方向。

### 7.6 闭包捕获

逃逸闭包**持有**它的捕获：捕获值随闭包存活，闭包销毁时释放。非逃逸闭包只借用，不产生持有。
Pini 的闭包是一等值，默认按逃逸处理。

注意 当前实现尚未提供闭包销毁路径，捕获槽与闭包环境不释放 —— 这是已知偏离，记在第 4 节，
不是本节允许的第二种语义。

### 7.7 任务实参

任务实参按求值效果分流：借用的实参留一份份额，由任务体在完成时归还，让出期间不归还；临时的
实参移交份额，调用方不再归还。派发与归还是运行时协议，但其方向由本节决定。

### 7.8 执行型通道

解释器不产出目标表示；第 7.1–7.7 节的动作对它是无操作。它必须接受携带这些动作的节点，不得
据此改变求值结果。

### 7.9 类型分类

每种类型在存储点上只有一条接收规则，由类别决定。四类：

| 类别 | 含义 | 落槽动作 | 类型 |
|---|---|---|---|
| 不参与 | 不握份额 | 无 | 标量 · 外部指针 · 任务句柄 |
| 整块 | 寄存器聚合，按值搬移 | 无（内部计数成员尚未单独保留，见第 4 节） | `Result` · `Optional` · 元组 · 函数值 |
| 值语义 | 堆上带计数头，写入即独立 | 拷贝 | 名义结构体 |
| 计数 | 按份共享 | 保留 · 释放 | `String` · `Char` · 数组 · 字典 · 集合 · 对象 · 枚举 · `LazyRef` |

对应的 IR 类型是 `IRType.shareClass`，四类依次为 `inert` · `aggregate` · `valueBox` ·
`retained(IRShareKind)`；求值侧另有一张 `IRExpr.shareEffect`（`fresh` · `borrowed` · `inert`），
7.3 的三行就是它。

注意 类别是 IR 事实，后端据此选符号与动作；LLVM 拼写是后端的表示，不得反过来参与判定 ——
换表示时拼写会变，而分类一变，失效的形态是某一族悄悄不再释放。

`LazyRef` 与本表同规：保留走通用句柄入口（它与容器共用同一个计数头），释放走自己的销毁符号。
