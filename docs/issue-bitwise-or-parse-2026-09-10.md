# Issue：单竖线 `|` 位或表达式无解析通道（规范内部自相矛盾）

- 状态：**Open（2026-09-10 立案；需 spec §1.3 决策，未决策前不动源码）**
- 发现来源：LLVM 重写 M5 G15 格（compound-assign 语料差分 fixture 编写时踩中，
  原记录为「宿主级解析器缺陷」）
- 关联：spec §A.1.2（词法记号表）/ §A.2.5（表达式层 5）/ §A.4 规则 3.13；
  同族工单 `docs/spec/issue/archive/issue-binop-dead-cases-2026-09-04.md`（运算符面收敛）

## 复现（实测，2026-09-10）

| 探针 | 结果 |
|---|---|
| `print(a \| b)` | ❌ Parse Error [E2-001] `expected ), got \|`（列位指向 `\|`） |
| `a \| 3`（语句位） | ❌ Parse Error [E2-006] `invalid expression: 无效的表达式` |
| `a \|= 3` | ✅ 正常（a=12, b=3 → 15；LLVM 与解释器一致） |
| `t \|\| f` | ✅ 正常 |
| `a & b` / `a ^ b` / `a << 1` / `a >> 1` | ✅ 正常 |

`pini tokens` 实测：`|` 恒词法化为 `pipe`（例：`1:5 pipe |`）——无独立位或记号。

## 根因（符号级）

1. `Token` 枚举**无** `bitwiseOr` case：`Sources/PiniCore/Lexer/Token.swift` 中
   `logicalOr` = `||`、`pipe` = `|`、`orAssign` = `|=`；而 `BinaryOperator.bitwiseOr`
   存在于 `Sources/PiniCore/AST/Expressions/BinaryExpr.swift`。
2. `Parser.isBitwiseOperator()` / `Parser.getBitwiseOperator()`（层 5）只列
   `bitwiseAnd` / `bitwiseXor` / `leftShift` / `rightShift`——**位或缺位**，
   故表达式中缀位无入口。
3. `Parser` 已有 `.orAssign → .bitwiseOr` 映射，故复合赋值可用；`pipe` 记号被
   声明位修饰独占消费（`main|func`、`|test`、`|unsafe`、标签 `标签|while`）。

## 规范侧现状（本工单的真正动因：spec 自相矛盾）

| 位置 | 内容 | 与实现 |
|---|---|---|
| §A.2.5 `bitwise-expr ::= term { ('&' \| '\|' \| '^' \| '<<' \| '>>') term }` | 位或**在**产生式内 | 超售 |
| §A.1.2 记号表 `'\|' : 按位或（表达式） / 声明修饰分隔符（行首/声明）` | 双义并陈 | 超售 |
| §A.1.2 记号转换表 | 只列 `'&'→bitwiseAnd '^'→bitwiseXor '<<'->leftShift '>>'->rightShift`——**无 `'\|'` 行** | 与上一行自相矛盾 |
| 同节已记事句「bitwise-or 仅经复合赋值 `\|=` 去糖得到（去糖后 opText 为 bitwiseOr）」 | 承认缺位 | 与产生式矛盾 |
| §A.4 规则 3.13 | 「若 `'\|'` 后是其他 token → 回退为按位或表达式」 | 实现走报错，未回退 |

即：spec 的**产生式与消歧规则**承认 `a | b`，**记号表与实现**只有 `|=`。
属语言级欠定义，不是单纯实现缺陷。

## 影响

- 表达式中缀位或不可用；`|=` 可用而 `|` 不可用，形态极不对称（用户可见行为缺口）。
- 自举 parser 语料与 G15 差分 fixture 均须绕开（fixture 已就地注记）。
- `&` 已用语法位置消歧先例（前缀取地址 `unsafe &x` vs 中缀按位与，`Parser.parseUnary`
  已实现）——单竖线的「声明分隔符 vs 位或」同型消歧有现成范式可循。

## 处置请求（待裁决，先决策后实施）

决策点二选一，两者都必须过 spec §1.3 治理序（提议 → 影响评估 → 登记 → 落地 → 证据）：

- **B（收敛规范）**：维持现状（`|=` 为唯一通道），spec 删 `bitwise-expr` 产生式中的

## 补充（2026-09-17：第二次独立发现，第三条自相矛盾处，以及一处判据空档）

**状态不变：仍 Open，A/B 未裁。** 本节只补证据，不改处置请求。

### 1. 第二条独立的发现路径

本批为第 3 层「spec 断言层」补**标签语义**面时，为「`IDENT '|'` 后跟 `if`」这条消歧
写了一条断言（`Tests/PiniTests/SpecAssertionTests/labelNotBitwiseOr.pini`：
`run|while` 在语句位必须解析为**带标签语句**，打印 `3`）。该断言默认了
「回退为按位或」那一支存在且可达 —— 一查之下发现**它不可达**，于是与 2026-09-10 的 M5 G15 格
**各自独立**地撞到同一处欠定义。两条路径互不依赖，这提高了「这是真缺口、不是个案」的置信度。

⚠️ 该面**无法**为本单建判据：第 3 层的载体要求 `rc == 0`，表达不了「应当被拒」的负向用例。
⇒ 本单将来即便修好，**第 3 层不会自动检出**（修复与回归都需要另建判据）。
该结论已如实记在 `Tests/PiniTests/SpecAssertionTests/PROVENANCE.md` 的「面外发现」节。

### 2. 自相矛盾处的**完整**清点（六处规范面，4 : 2）

原「规范侧现状」表点了四处。补齐后是**六处**，且方向分布并不对称：

| # | 位置 | 原文要点 | 说的是 |
|---|---|---|---|
| 1 | §A.2.5 `bitwise-expr`（约 :1278） | `term { ('&' \| '\|' \| '^' \| '<<' \| '>>') term }` | **有** |
| 2 | §A.1.2「多重角色」注记（约 :1023） | `'\|' : 按位或（表达式） / 声明修饰分隔符（行首/声明）` | **有** |
| 3 | §A.3 优先级注记（约 :1440） | `位运算四则同级（& \| ^ << >> 无分层）` | **有** |
| 4 | §A.4 规则 3.13（约 :1467） | 「若 `'\|'` 后是其他 token → **回退为按位或表达式**」 | **有** |
| 5 | §A.1.2 opText 投影表 + 紧随其后的注意句（约 :1305–1309） | 「**`\|` 没有二元或形态** —— `\|` 是定界符…bitwise-or 仅经复合赋值 `\|=` 去糖得到」 | **没有** |
| 6 | §2.4.1 位运算行（约 :187） | 算子列写作 `& ^ ~ << >>` | **没有** |

⇒ **4 处说有、2 处说没有**。而最尖锐的一点：第 2 处与第 5 处**同属 §A.1.2，相隔约 280 行，互相矛盾**。
所以本单不是「规范没定」，而是「**规范在同一个附录里定了两次、方向相反**」。

### 3. `'|'` 的「没有」那一侧是**一条已被做出的决定**，不是遗漏

第 5 处那句话不是随手写的，它带三件东西：

- 一张**二元 opText 投影表**（17 项，逐项列出 `'&'→bitwiseAnd`、`'^'→bitwiseXor`、`'<<'→leftShift`、`'>>'→rightShift`，**无 `'|'`**）；
- 明确的范围声明「自举 parser 已按此表对齐，**差分门禁以之为权威参考**」；
- 一句**给出理由的结论**：「`|` 是定界符（修饰符/标签/联合类型分隔符），故 bitwise-or 仅经 `|=` 去糖」。

⇒ 这与 §2.4.1（正文的位运算行）**一致**。也就是说：`'|'` 无二元形态是**已决**的，
缺的只是把这个决定**传播到另外四处**（产生式 · 多重角色注记 · 优先级注记 · 规则 3.13 的回退分支）。

**本单 A/B 应在此光线下重读**（本件不代为裁决）：

- **B 的代价**从「删一条没人走的规则」变成「把一条**已决**的规则在四处补齐」——
  不动 `Sources/` 一行，且与 §2.4.1 和 opText 表两处**已有**表述同向。
- **A 的代价**相应变大：它要把第 5 处那张「权威参考」表推翻（表内加 `'|'` 行），
  并推翻「`|` 是定界符」这条理由 —— 而 `'|'` 确实还在承担修饰符/标签/联合类型三职。

### 4. 「不可达」应读作结构性不可达，不只是「实现走报错」

原「根因」节第 2 条已指出 `Parser.getBitwiseOperator()` 缺 `bitwiseOr` 分支。
补充其后果的准确措辞：规则 3.13 的回退分支**不是被实现绕过，而是没有下游可走** ——
回退要把 `'|'` 造成一个中缀位或节点，而该节点在层 5 没有入口。
⇒ 这不是「实现尚未实现」，而是**该分支在当前文法下不可兑现**。
这与上面第 3 节合起来，使 B 成为「把已决事项补齐」，而非「降级一个功能」。
